## 摘要
现代语言模型智能体越来越多地在长时程、多步轨迹中与外部环境交互，而累积的交互历史会很快超出实际可用的上下文预算。为确保可靠性，智能体必须在长时程中保持事实信息、记住执行错误与纠正反馈，并跟踪跨动作的进展。已有若干方法可在无需在上下文中保留完整执行历史的情况下实现这一点，例如利用推理与动作历史、通过覆写机制学习维护固定大小记忆，以及周期性摘要。尽管覆写式记忆原则上可以保留仅追加式记忆所能保留的任何内容，但它必须学会在每一次后续重写中传递每个事实，而这很难从稀疏的结果奖励中学习；对于网页智能体等交互式应用，我们发现训练后的覆写式记忆会删除轨迹所需的关键信息，以及从环境收到的纠正反馈。我们提出 AMBER（Append-only Memory Bank for Evidence Retention，证据保留的仅追加记忆库）——一个简单且可扩展的框架，其中智能体联合学习推理、行动和写入自由形式记忆，而仅追加规则从构造上保证信息保留。这使得 AMBER 可以通过结果奖励的强化学习进行端到端训练，而无需大量精心整理的 SFT 数据。在 WebArena Lite 上，AMBER 相比基于覆写式记忆的方法将平均成功率提高 4.09 个百分点，将五次重复运行中解决任务的比例提高 4.8 个百分点，并匹配了使用昂贵得多的精选监督训练的覆写基线。AMBER 在保持实用 token 预算的同时实现了这些改进，在上下文效率、任务性能和可靠的长时程执行之间提供了良好平衡。

## Abstract
Modern language-model agents increasingly interact with external environments over long-horizon, multi-step trajectories, where the accumulated interaction history can quickly exceed practical context budgets. To ensure reliability, agents must maintain factual information over long horizons, remember execution errors and corrective feedback, and track progress across actions. Several approaches have been proposed to achieve this without the need for maintaining the entire execution history in context, such as using the reasoning and action history, learning to maintain a fixed-size memory through an overwrite mechanism, and periodic summarization. Although overwrite memory can in principle retain anything an append-only memory can, it must learn to carry each fact through every subsequent rewrite, which is difficult to learn from sparse outcome rewards; for interactive applications like web agents, we find that trained overwrite memories delete key information required by the trajectory, as well as corrective feedback received from the environment. We introduce AMBER (Append-only Memory Bank for Evidence Retention) - a simple and scalable framework where an agent jointly learns to reason, act, and write free-form memory, while an append-only rule guarantees retention by construction. This allows AMBER to be trained end-to-end with reinforcement learning from outcome rewards without the need for extensive curated SFT data. On WebArena Lite, AMBER improves average success over overwrite-based memory by 4.09 percentage points, increases the fraction of tasks solved in five repeated runs by 4.8 percentage points, and matches an overwrite baseline trained on substantially more expensive curated supervision. AMBER achieves these improvements while maintaining a practical token budget, providing a strong balance between context efficiency, task performance, and reliable long-horizon execution.

## 1. 核心问题与研究背景

- **背景**：语言模型智能体在网页导航、深度研究、工具调用等长时程、多步任务中，交互历史（观察、推理、动作）会快速累积并超出模型上下文预算；同时网页观察本身冗长，直接保留完整历史不可行。
- **核心问题**：一旦智能体识别出值得记住的信息，**应如何在后续交互中保留这些信息**？即上下文管理机制需要同时决定“写什么、保留什么、呈现什么”。
- **现有方案及其缺陷**：
  - **推理+动作历史**（如 WebAgent-R1、Go-Browse）：丢弃观察，只保留推理与动作，信息量不足。
  - **覆写式记忆**（如 MemAgent、MemSearcher、MEM1）：学习一个在每一步被递归重写的紧凑记忆。理论上容量可覆盖仅追加记忆，但**每个事实必须在每次重写中被策略显式携带**，在稀疏结果奖励下极难学习。
  - **外部记忆/摘要**（如 ReSum、Memory-R1）：引入更多可学习操作，进一步扩大策略学习负担。
- **关键发现（动机）**：作者发现，经结果奖励训练的覆写记忆会**删除轨迹所需的关键事实**以及**环境返回的纠正反馈**，导致智能体重复犯错、无法作答。这被归因于**可学习性问题**，而非容量问题。

## 2. 方法论：AMBER（Append-only Memory Bank for Evidence Retention）

### 2.1 核心思想

- **将“写什么”与“保留什么”解耦**：
  - **写什么**：由策略学习（生成自由形式自然语言记忆条目）。
  - **保留什么**：由确定性的**仅追加规则**保证（已写入条目不可修改或删除），从而**从构造上保证持久性**。
- 每一步只将记忆条目跨步传递，先前的观察、推理、动作及步内对话全部丢弃。

### 2.2 技术细节

- **两步对话式记忆生成**（每个环境步）：
  1. 第一轮：策略接收任务 $x$、当前观察 $o_t$、记忆库 $C_t$，生成推理 $r_t$ 与动作 $a_t$：$(r_t,a_t)\sim\pi_\theta(\cdot\mid x,o_t,C_t)$。
  2. 第二轮：在同一对话中追加指令，策略基于步内已有内容生成自由形式记忆 $m_t$：$m_t\sim\pi_\theta(\cdot\mid x,o_t,C_t,r_t,a_t)$。
  - 注意：**记忆在动作执行前、观察到动作结果前生成**，因此可记录当前观察、执行状态与进度，但不应断言动作结果。
- **仅追加更新规则**：$C_{t+1}=C_t\parallel[m_t]$，$C_0$ 为空；无学习参数，保证已写记忆不可被改写或删除。
- **端到端 RL 训练（GRPO）**：
  - 先做**最小化 SFT**（用离线轨迹初始化），再以 SFT 策略为参考策略进行 RL；采用**异步 RL**。
  - 每个任务生成 $G$ 条多步 rollout，每条仅得终端二值奖励 $R_g\in\{0,1\}$；组相对优势 $A_g=\frac{R_g-\text{mean}(R)}{\text{std}(R)+\delta}$，同一条 rollout 的所有步共享该优势。
  - 每一步包含推理、动作、记忆的全部 assistant token，模板与用户消息 token 被 mask；采用 token 级重要性采样比与 PPO 式裁剪，并加 KL 正则约束到 SFT 参考策略。
  - **无记忆专用奖励**：记忆写入行为完全由任务结果奖励驱动而涌现。

### 2.3 大规模 Rollout 基础设施

- 将**模型推理（SGLang）、浏览器执行、网站服务**解耦为可独立扩展的组件。
- 每个 rollout 拥有独立 **Ray actor + BrowserGym 浏览器会话**，避免 cookie/状态泄漏；修改网站状态的任务分配独立网站容器（VM 隔离）。
- **步级异步执行**：浏览器执行与模型推理跨 rollout 重叠，减少 GPU 空闲；WebArena 任务最多修改两个可变服务，每台网站主机支持 8 个并发隔离 rollout 槽位。

## 6. 主要结论与发现

- **成功率**：AMBER 在 9B 上平均成功率 **36.85%**，较 MemAgent（32.76%）提升 **4.09 个百分点**；27B 上 **48.82%** vs 46.77%（+2.05），并超过 Haiku 4.5（46.72%）。
- **可靠性**：9B 在全部五个阈值上领先；27B 在 ≥2/5、≥3/5、5/5 上领先。最严格的 5/5 阈值下，AMBER 达 **20.5%（9B）/ 35.4%（27B）**，均优于两个基线。作者指出 AMBER 的优势主要体现在**跨重复运行的一致性**，而非单次多解几个任务。
- **显式记忆优于仅推理历史**：MemAgent 较 WebAgent-R1 提升 4.41 个百分点，说明显式训练记忆写入有益。
- **上下文效率**：第 30 步时 AMBER 约 **7.4k token**，MemAgent 约 4k，WebAgent-R1 约 9k，Full Context 约 **90k**；虽线性增长但仍在实用范围内。
- **可学习性而非容量**：精炼监督可将 MemAgent 从 32.76% 提升到 35.59%，接近但仍略低于 AMBER（36.85%），且需昂贵数据管线；说明仅追加先验让持久记忆更易从弱结果监督中学到。
- **失败模式分析**：
  - **错误反馈丢失**：环境反馈在覆写记忆中约 4 步后基本丢失（表 5：k=4 时仅 4.5%，k=5 时 0.8%）。
  - **重复无效动作**：AMBER 每个首次拒绝事件平均重发 **1.29 次**，MemAgent 为 **1.95 次**；MemAgent 有 15.4% 的事件重复 6 次以上，AMBER 仅 3.3%。
  - **递归压缩损失**：覆写记忆会在后续重写中丢掉已正确记录的证据（如 Task 23 丢失 Rachel、Task 202 丢失订单 #136）。

## 7. 优点

- **方法极简且可扩展**：仅追加规则无参数、无需额外奖励设计，策略只需学习“写什么”，大幅降低学习负担。
- **从构造上保证持久性**：避免覆写式记忆的递归压缩损失与错误反馈遗忘，直接针对长时程可靠性的核心痛点。
- **训练成本友好**：无需大量精选 SFT 数据即可端到端 RL；与需要昂贵 generate–judge–revise 管线的精炼监督基线性能相当。
- **实验设计严谨**：控制变量（仅改变保留上下文轴）、多随机种子、多模型规模、成功率与重复运行可靠性双指标、上下文长度实测。
- **工程贡献明确**：给出可扩展的异步 rollout 架构（Ray + FastAPI + SGLang + 隔离浏览器/网站容器），对社区复现有实用价值。
- **失败分析深入**：用具体轨迹和半定量统计揭示覆写记忆的两类失效机制，增强了结论的说服力。

## 8. 不足与局限

- **上下文线性增长**：仅追加意味着 $C_t$ 随步数线性增长；在远超本文评估范围的长时程任务中可能触及上下文上限，届时仍需引入选择或合并机制，而如何在不丢失远期有用信息的前提下做到这一点仍是开放问题。

- **记忆幻觉**：在仅用结果奖励的 RL 下，模型生成记忆时有时会写入**未经环境验证的断言**，例如对页面状态的错误推断，或对动作结果的提前预期；而仅追加规则意味着这些错误条目**既不能被改写也不能被删除**，会在后续步骤中持续污染上下文，甚至与环境返回的纠正反馈形成冲突。这构成仅追加设计的对称代价：它以牺牲“可纠错性”换取“不丢失性”，而论文并未提出显式的幻觉检测或记忆失效标注机制。
- **记忆冗余与缺乏合并**：由于没有去重、抽象或合并操作，语义相近的条目会被反复写入（尤其在重复访问同类页面时），进一步放大上下文线性增长的问题。作者虽在效率分析中表明第 30 步约为 7.4k token，但这是在该 benchmark 步数上限内测得的结果，冗余累积的长期后果未被量化。
- **写入时机的一步延迟**：记忆在动作执行前生成，因此动作的实际结果只能在下一步的记忆写入中补记。对于“动作→结果”耦合紧密的任务（如提交表单、下单），这会造成证据记录的时序错位，甚至可能因中间页面跳转而**永久丢失结果证据**。
- **基线覆盖的缺口**：对比集中在“仅推理历史”“覆写式记忆”“完整上下文”三类，**缺少检索式记忆基线**（如对历史做 embedding 检索、只回填相关片段）这一在实践中常用的中间路线，因而无法判断“仅追加 + 全量呈现”相对于“选择性检索”的优势边界。
- **统计严谨性有限**：成功率以五个随机种子平均报告，但未给出方差、置信区间或显著性检验；在 9B 上 +4.09 个百分点的差距是否稳健，读者难以独立判断。重复运行可靠性指标部分缓解了这一问题，但它是同一批种子的另一种切分，并非独立证据。
- **训练规模与泛化性**：RL 仅 100 步、group size 6、单一 benchmark、单一模型族（Qwen 3.5），且 27B 使用了不同硬件（B300 vs H200），跨规模结论的可比性存在一定混淆。方法在更小模型、更强模型或非网页环境（工具调用、代码库导航、多智能体协作）上的表现尚未验证。
- **任务集裁剪**：排除 GitLab 虽出于工程稳定性考虑，但 GitLab 恰是长流程、多分支、状态依赖最强的站点之一，其缺失可能使结论对“高复杂度长时程任务”的适用性被高估。

## 9. 启示与可迁移价值

- **设计范式层面**：论文提出的“**学习写什么、确定性保证保留什么**”这一解耦思路，具有很强的可迁移性。它把长时程记忆问题从“策略需要学会一个难以学习的递归压缩算子”，转化为“策略只需学会一次性的信息筛选”，从而把学习难度从“序列级信用分配”降为“单步写入质量”，这对稀疏结果奖励下的 agentic RL 是一条通用减负路径。
- **对记忆机制研究的启示**：结果说明，在弱监督条件下，**结构性先验（不可删除）比容量扩张更重要**——覆写式记忆在理论上容量更大，却因可学习性差而失效。这一“容量不是瓶颈、可学习性才是”的判断，可推广到摘要式、图结构式等其它记忆架构的设计取舍中。
- **对训练管线的启示**：AMBER 无需记忆专用奖励、无需昂贵的 generate–judge–revise 数据管线即可逼近精炼监督基线的性能，说明**良好的结构约束可以部分替代监督强度**，这对算力/标注预算受限的研究者具有直接的实践价值。
- **工程层面**：将模型推理、浏览器执行与网站服务解耦，并以 Ray actor + 独立浏览器会话 + 隔离网站容器实现大规模并行 rollout 的架构，可直接复用于其它需要状态隔离的交互式环境训练。

## 10. 总体评价

AMBER 是一篇**问题定位精准、方法极简、论证链条完整**的工作。其核心贡献不在于引入新模块，而在于通过一个几乎零成本的结构约束（仅追加），纠正了当前覆写式记忆范式在稀疏结果奖励下的系统性失效，并用“成功率—重复可靠性—上下文效率—可学习性对照—失败模式轨迹”五重证据支撑这一判断。方法的价值在于其**诊断性**：它把长时程智能体的记忆瓶颈从“容量不足”重新表述为“保留不可靠”，这一视角对后续记忆架构设计具有指导意义。

其主要遗留问题也恰由这一设计选择派生：**持久性以可纠错性和上下文经济性为代价**。因此，最自然的后续方向是在仅追加骨架之上，引入**可验证的写入过滤**（抑制幻觉条目）、**非破坏性的分层抽象**（在保留原始条目的前提下生成摘要视图），以及**面向长时程的检索式呈现**（从只增不减的记忆库中选择性回填），从而在“不丢失”与“不膨胀、可纠错”之间取得平衡。若能补充检索式基线与统计显著性检验，并扩展至 GitLab 类高复杂度任务及其它交互环境，该结论的说服力还将进一步提升。
