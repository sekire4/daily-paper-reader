## 摘要
长期记忆使 LLM 智能体能够复用过往经验，但检索到相关记忆并不一定能为回答查询提供充分证据。关键信息可能仍分散在多个记忆记录中，被抽象化所掩盖，或与推理所需的关系脱节。我们识别出这种相关性—充分性差距，并提出 QEMem 框架，将记忆利用重新表述为构建查询特定的证据集，把关注点从单个检索结果的相关性转向集体证据支持。QEMem 集成了三种互补机制：查询引导的发现跨多个记忆粒度检索证据；基于来源的具体化将其组织为结构化的 ViewCards，并具有明确的证据角色和来源引用；充分性引导的精炼则有选择地恢复缺失信息。QEMem 在现有记忆存储上运行且无需修改记忆形成过程，在 LoCoMo 上使用 Claude Opus 4.5 达到 91.43% 的 LLM 评判准确率，在共享记忆存储下比最强评估基线 MemR$^3$ 高出 7.6 个百分点，比 NEMORI 高出 10.7 个百分点。进一步分析表明，其证据覆盖率有所提升，并在需要跨会话证据整合的问题上表现强劲。

## Abstract
Long-term memory enables LLM agents to reuse past experiences, yet retrieving relevant memories does not necessarily provide sufficient evidence for answering a query. Essential information may remain fragmented across memory records, obscured by abstraction, or disconnected from the relations required for reasoning. We identify this relevance-sufficiency gap and propose QEMem, a framework that reformulates memory utilization as the construction of query-specific evidence sets, shifting the focus from individual retrieval relevance to collective evidential support. QEMem integrates three complementary mechanisms: query-guided discovery retrieves evidence across multiple memory granularities; source-grounded reification organizes it into structured ViewCards with explicit evidential roles and source references; and sufficiency-guided refinement selectively recovers missing information. Operating on existing memory stores without modifying memory formation, QEMem achieves 91.43% LLM-judge accuracy on LoCoMo with Claude Opus 4.5, outperforming the strongest evaluated baseline, MemR$^3$, by 7.6 percentage points and NEMORI by 10.7 points under a shared memory store. Further analyses demonstrate improved evidence coverage and strong performance on questions requiring cross-session evidence integration.

## 1. 核心问题与研究动机

- **背景**：长期记忆使 LLM 智能体能够跨会话复用经验。MemGPT、Mem0、A-Mem、Zep、NEMORI、SimpleMem、MemGAS 等系统在记忆的**存储、组织、压缩与检索**上已取得显著进展。
- **核心问题**：论文指出，**检索到“相关”记忆并不等于获得“充分”证据**。回答一个查询所需的关键信息往往：
  - 碎片化地散落在多条记忆记录中；
  - 被记忆抽象（episode 摘要、语义事实）所掩盖；
  - 缺乏连接各条事实所需的**关系**，因而无法支撑多跳或聚合推理。
- 作者将这一脱节命名为 **relevance–sufficiency gap（相关性—充分性鸿沟）**，并提出根本性问题：*智能体如何构建一个来源可溯、能集体满足查询信息需求的证据集？*
- **诊断性证据**（LoCoMo，NEMORI 记忆库）：
  - NEMORI 几乎保留了全部原始交互记录，但其检索到的 episode 仅在 **68.8%** 的问题上覆盖全部标注支撑证据的来源轮次；
  - 在来源覆盖完整的问题上，回答准确率约 **93%**；
  - 说明即便对强 LLM 而言，**证据可获取性仍是主要瓶颈**，而非推理能力。
- **整体含义**：论文把记忆利用的基本单位从“单条记忆记录”上移到“**查询特定证据集**（query-specific evidence set）”，评价标准从“个体相关性”转为“**集体证据支持**”。

## 2. 方法论：QEMem 框架

### 2.1 问题形式化

- 记忆空间 $\mathcal{M}=\{M_E, M_S, M_U\}$：情景记忆（事件摘要）、语义事实、原始对话轮次（通过来源引用保留）。
- 目标：$\mathcal{E}^*_q=\arg\max_{\mathcal{E}\subseteq\mathcal{C}(q,\mathcal{M})}\mathrm{Suff}(q,\mathcal{E})$，约束为 **Traceable**（可溯源到记忆库）与 **Cost ≤ B**（检索/推理预算）。
- 该目标不直接优化，而是通过三个互补机制**渐进式构造**证据集，且**不修改记忆形成过程**（即插即用于既有记忆库）。

### 2.2 机制一：查询引导的证据发现（Query-Guided Evidence Discovery）

- **查询条件化检索规划**：规划器输出结构化信息需求 $P(q)=(\eta_q, a_q, \alpha_q, \tau_q, Q_q)$——信息需求、期望答案类型、是否需要跨记忆聚合、是否需要时序推理，以及 4–6 条补充检索查询（语义改写、中间事实子问题、关键实体查询）。这使检索超越与原始查询的表面语义相似度。
- **多粒度检索**：在三种粒度 $g\in\{E,S,U\}$ 上同时做稠密检索与稀疏检索（BM25），用 **reciprocal rank fusion** 融合：$R_g(m|q)=\sum_{q_j}\sum_h \mathbb{I}[m\in L^h_{j,g}]/(k+\mathrm{rank})$。
- **来源链接调整**：利用语义事实与其来源 episode 之间的 provenance 链接修正 episode 排序。
- **候选池**：$\mathcal{C}^{(0)}_q=\mathrm{Ctx}_U(\bigcup_g \mathrm{Top}_{b_g(q)}(M_g;\tilde R_g))$，预算 $b_g(q)$ 随聚合需求自适应；$\mathrm{Ctx}_U$ 为检索到的原始轮次补充局部对话上下文。

### 2.3 机制二：来源锚定的证据具体化（Source-Grounded Reification）

- 证据构造器同时产出初始证据集与证据缺口评估：$(\mathcal{E}^{(0)}_q, f^{(0)}_q)=\mathcal{R}(q,\eta_q,\mathcal{C}^{(0)}_q;\varnothing)$。
- 每条证据表示为结构化 **ViewCard**：$v_i=(\gamma_i, r_i, \pi_i, \xi_i, t_i)$
  - $\gamma_i$：与查询相关的 claim；$r_i$：证据角色（答案候选、中间事实、时序约束、推理支撑、与其他卡矛盾等）；$\pi_i$：来源 ID；$\xi_i$：**逐字引文**；$t_i$：时间信息。
- **引文保真校验**：$\kappa_i=\max_{m\in\mathrm{Src}(\pi_i)}\mathrm{Match}(\xi_i,x_m)$，$\nu_i=\mathbb{I}[\kappa_i\ge\delta]$。注意这验证的是**引文保真度而非逻辑蕴含**；未通过校验的卡**保留但标记 UNVERIFIED**，冲突观察也保留供下游推理。
- **时间对齐**：相对时间表达依据来源会话时间戳归一化（如 "yesterday" → 绝对日期；"last Friday" → "the Friday before <日期>"）。

### 2.4 机制三：充分性引导的证据精炼（Sufficiency-Guided Refinement）

- 反馈三元组 $f^{(t)}_q=(\hat s^{(t)}_q, d^{(t)}_q, Q^{(t)}_{q,\text{gap}})$，$\hat s\in\{0,1\}$ 为估计的证据充分性，与 ViewCard 在**同一次 LLM 调用中联合生成**（非单独训练充分性模型）。
- 不足时定向补检：$\Delta\mathcal{C}^{(t+1)}_q=\mathrm{Retrieve}(Q^{(t)}_{q,\text{gap}},\mathcal{M})\setminus\mathcal{C}^{(t)}_q$，并**条件于已有 ViewCard** 增量构造：$\mathcal{E}^{(t+1)}_q=\mathcal{E}^{(t)}_q\cup\Delta\mathcal{E}^{(t+1)}_q$。
- **终止条件**：判定充分 / 无新候选 / 检索预算耗尽。

### 2.5 证据锚定答案生成

- $\hat y=F_\theta(q,\mathrm{Assemble}(\mathcal{E}^{(T)}_q,\mathcal{C}^{(T)}_q))$，冻结 LLM 接收 ViewCard + 引用源上下文 + 其余检索记忆；prompt 中含时序解析规则、列表去重计数规则、以及一次“禁止拒答”的 abstention retry。

## 3. 实验设计

- **数据集/场景**：**LoCoMo**（10 段多会话超长对话，长期对话记忆基准），1,540 题（排除对抗性问题），四类：Multi-hop 282、Temporal 321、Open-domain 96、Single-hop 841；其中 1,531 题具有可完整映射的支撑证据标注。
- **评测指标**：LLM-judge 准确率（固定 Opus 4.5 评判、全方法同一评判 prompt）；辅以证据覆盖率、源可见性、溯源解析率、引文保真度、输出级 groundedness、查询时成本。
- **Backbone**：Claude **Haiku 4.5** 与 **Opus 4.5**（Amazon Bedrock）；记忆库由 Opus 4.5 **一次性构建后跨 backbone 复用**。
- **对比方法（7 个）**：NEMORI、Mem0、A-Mem、LightMem、SimpleMem、MemR³、MemGAS。关键控制：**QEMem 与 NEMORI 共享完全相同的预构建记忆库**，从而隔离“查询时记忆利用机制”的差异。
- **实现细节**：Qwen3-Embedding-4B 作嵌入模型，dense + BM25 + RRF；temperature=0；标注证据**仅在事后分析使用，推理时从不暴露**。
- **实验组（RQ1–RQ6 + 附录）**：
  - RQ1 总体性能（两 backbone × 四类题）；RQ2 证据覆盖与准确率条件分析；
  - RQ3 消融：Matched-Budget Retrieval / Query-Guided Retrieval / w/o Refinement / Full QEMem，并匹配最终答案上下文 token 预算；
  - RQ4 溯源与可靠性：10,121（Haiku）/10,213（Opus）张 ViewCard 的溯源与引文保真；288 个分层样本的 claim–来源语义一致性审计；时间锚定审计（9,541/9,598 个时间字段）；240 题分层输出级 groundedness（另 68 题 Haiku 子集）；
  - RQ5 复杂证据：≥3 支撑轮、跨会话、跨会话 list/count；
  - RQ6 源轮预算下的覆盖（10–120 轮；另做 300–3,600 token 预算）；
  - 附录：时间跨度（同日/1–30/31–180/>180 天）、复杂度 Δgap + 按对话聚类 bootstrap + leave-one-conversation-out、准确率–成本 Pareto、prompt 模板。
