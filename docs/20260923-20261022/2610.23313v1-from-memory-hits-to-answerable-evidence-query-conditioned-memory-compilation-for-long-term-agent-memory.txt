## From Memory Hits to Answerable Evidence: Query-Conditioned Memory Compilation for Long-Term Agent Memory 

Shangze Li 1, Yanyu Yao 1, Derong Xu 1, Zhi Zheng 1, Tong Xu 1

1State Key Laboratory of Cognitive Intelligence, University of Science and Technology of China, Hefei, China

Abstract 

Long-term agent memory requires recover-ing answer-relevant evidence dispersed across turns and sessions. Existing systems increas-ingly use structured memories and adaptive re-trieval, yet often pass retrieved or expanded units directly to the reader, coupling mem-ory addressing with evidence presentation and leaving the final context redundant or incom-plete. To address this gap, we propose Mem-Compile, a query-conditioned evidence com-pilation framework for long-term conversa-tional memory. Given a query, the Address Plane locates relevant support through compact source-linked descriptors and capacity-aware Cells, while a normalization boundary resolves heterogeneous retrieval hits to stable Sour-cePacket identities. Its Evidence Plane then allocates a bounded evidence budget across complementary packets, admits limited addi-tional support, and renders the retained claims associated with each selected packet into an answer-ready context. MemCompile achieves 80.52% Judge Accuracy on LoCoMo and ex-tends the empirical quality–cost Pareto frontier to a higher-quality regime. Its strong perfor-mance on LongMemEval-S further suggests that the benefits of query-conditioned compila-tion generalize across long-term conversational-memory benchmarks. The implementation code is publicly available at https://github. com/MINE-USTC/MemCompile

Persistent interaction therefore depends not only on retaining past information, but also on making the relevant parts of an accumulated history accessible when needed. Foundational long-term memory systems ad-dressed this need by extracting and retrieving salient records, including persistent memories and atomic conversational facts (Zhong et al., 2023; Chhikara et al., 2025). Subsequent work improved access by compressing dialogue into facts, notes, summaries, profiles, and events, and by organizing these representations in graphs or hierarchies (Xu et al., 2025; Rasmussen et al., 2025; Liu et al., 2026; Yao et al., 2026). As retrieval representations be-came increasingly compact and structured, recent work began to distinguish the units used to locate 1arXiv:2610.23313v1 [cs.AI] 16 Oct 2026 memory from the evidence exposed to the reader. AnchorMem reconstructs immutable contexts from retrieved fact anchors, xMemory adaptively dis-closes segments or raw messages from a hierarchy, and MemIR projects heterogeneous retrieval cues into provenance-scoped claim bundles (Shen et al., 2026; Hu et al., 2026; Jin et al., 2026). Together, these developments move long-term memory sys-tems from improving addressability toward separat-ing memory location from evidence presentation. However, this separation remains incomplete: the retrieved representation, or the expansion at-tached to it, still largely determines the context presented to the reader. Existing systems therefore do not fully separate two decisions: which under-lying conversation sources should receive the lim-ited evidence budget, and how evidence from those sources should be represented for answer genera-tion. This coupling is problematic because the two decisions favor different properties. Address repre-sentations should be compact, discriminative, and broad enough to support reliable recall, whereas reader evidence should preserve relevant qualifica-tions, connect complementary facts, and avoid un-necessary context. When a single unit serves both purposes, the system must accept a fixed trade-off. As illustrated in Figure 1, an atomic claim may be easy to retrieve but may omit causal relationships or sibling facts from the same source. A raw turn preserves such details but may reintroduce noise, such as greetings and irrelevant dialogue, whereas a hierarchy node can provide an effective navigation unit without matching the granularity required for answer generation. Moreover, without an explicit source-level boundary, multiple claims or retrieval channels may allocate context budget repeatedly to the same underlying source. This coupling not only creates avoidable quality loss after successful retrieval, but also makes it difficult to distinguish failures of source recovery from failures of evi-dence presentation. In this paper, we propose MemCompile, asource-normalized evidence compiler for long-term conversational memory. Its central principle is to locate relevant information through compact representations and allocate the evidence budget at the level of original dialogue turns while gen-erating from a separately compiled reader view. MemCompile realizes this principle through an Address–Evidence two-plane architecture. The Address Plane organizes source-linked atomic de-scriptors into capacity-bounded Cells and combines diminishing-benefit Cell routing with lexical re-trieval to construct primary source candidates while a broader dense packet pool supplies proposals for bounded semantic refinement. An explicit normal-ization boundary resolves these heterogeneous re-sults to stable SourcePacket identities, ensuring that one underlying source occupies one evidence unit regardless of how many descriptors or chan-nels locate it. The Evidence Plane then selects complementary packet identities, preserves the ini-tial anchors while admitting bounded additional support, completes evidence within each selected packet, and compiles the result into a reader-facing view. By separating packet selection from textual rendering, MemCompile can optimize and evalu-ate source recovery and evidence presentation as distinct decisions. Our main contributions are summarized as fol-lows: • We formulate long-term memory serving as query-conditioned evidence compilation, dis-tinguishing two decisions that are commonly coupled: which underlying sources receive the evidence budget and how evidence from those sources is represented to the reader. • We introduce MemCompile, an Ad-dress–Evidence two-plane architecture that addresses memory through compact derived views, allocates evidence budget at the level of immutable SourcePackets, and generates from a separately compiled reader view. • Comprehensive evaluations on long-term memory benchmarks demonstrate that Mem-Compile consistently outperforms state-of-the-art baselines while extending the empir-ical quality–cost Pareto frontier. On the Lo-CoMo benchmark, packet-scoped compilation improves F1 by 15.26 points and Judge Accu-racy by 23.51 points over representative-claim rendering. 

2 Related Work 

Structured long-term memory for LLM agents 

Early long-term memory systems store and retrieve salient interaction records to support persistent per-sonalization and multi-session reasoning. Mem-oryBank combines retrieval with time-dependent forgetting and memory reinforcement, while Mem0 extracts and consolidates conversational facts into vector- and graph-based stores (Zhong et al., 2023; 2Chhikara et al., 2025). Subsequent systems con-struct richer memory organizations. A-MEM cre-ates dynamically linked notes whose attributes and relations evolve as new experiences arrive while Zep represents evolving conversational knowledge in a temporal graph (Xu et al., 2025; Rasmussen et al., 2025). Other approaches improve informa-tion density or associative access through semantic compression, atomic facts, profiles, events, and higher-level memory scenes (Liu et al., 2026; Yao et al., 2026). 

Reconstructive and adaptive memory access 

Recent systems recognize that a representation use-ful for locating memory need not be self-contained answer evidence. AnchorMem retrieves atomic facts as anchors and reconstructs their associated raw contexts and events (Shen et al., 2026). xMem-ory organizes intact memory units into a revisable hierarchy and adaptively discloses episodes or raw messages when additional detail reduces reader un-certainty (Hu et al., 2026). MemIR takes a typed approach, separating raw evidence, retrieval cues, and truth-bearing claims, and projecting heteroge-neous hits into provenance-scoped claim bundles exposed through a normalized fact interface (Jin et al., 2026). MemCompile builds on the shared insight that retrieval representations and answer evidence serve different purposes, but places its architectural boundary at a different level. Mem-Compile instead resolves derived address results to immutable SourcePacket identities before evi-dence selection. This source-normalized boundary makes it possible to vary and evaluate reader rep-resentation while holding the selected source set fixed. 

3 Methodology 

3.1 Problem Formulation 

Let a conversational history be H = ( P, ≺), where 

P = {p1, . . . , p N } contains the original dialogue turns and ≺ denotes their temporal order. Each turn pi includes its speaker, session, interaction time, and content. Given a query q, the task is to construct an ordered and bounded reader context 

Xq grounded in H. The context should contain suf-ficient and complementary support for answering q,preserve traceability to the original dialogue turns, and limit irrelevant or redundant content. 

3.2 Address Plane 

MemCompile instantiates each original turn pi ∈P as an immutable SourcePacket that stores its speaker, session, interaction time, raw content, and stable identifier. The Address Plane builds compact source-linked descriptors and organizes them for complementary retrieval. Its objective is to pre-serve source coverage under fixed limits on opened Cells and sparse and dense candidate pools.

3.2.3 Diminishing-Benefit Cell Routing 

For a query q, we calculate the query relevance 

u(c, q ) for each cell based on the normalized query term set of q and the person set. Given the set of memory units Ot opened before round t, the marginal benefit of candidate memory cell c is denoted as g(c | O t, q ):

g(c | O t, q ) = u(c, q ) [1 − λRJ(Mc, M Ot )] −κopen 

(5) Here, u(c, q ) combines keyword, person, time, and density signals and J(A, B ) denotes Jaccard similarity between two sets. The implementation sets λR = 0 .45 and defines κopen as an opening cost that increases with the number of opened Cells plus a token-proportional reading cost. 3.4 Evidence Plane 

The Evidence Plane converts the normalized packet candidates into a bounded and coherent context. We organize it around the two decisions: how to compile a selected packet, and when to supplement the selected packet set.

A closed-pool listwise scheduler receives q and Uq

and selects K0 = 10 complementary SourcePack-ets, 

A0(q) = Schedule K0 (q, Uq), (11) where A0(q) is the baseline evidence anchor set. Each candidate is rendered with an opaque label, di-alogue identifier, speaker, recorded date, and source content. The scheduler is instructed to rank di-rect answer-bearing packets first while retaining complementary packets for relational, temporal, comparative, and list questions. It returns exactly 

K0 distinct labels in descending usefulness; labels are validated against the closed pool and resolved back to SourcePacket identities. 4 Experiments 

Our experiments are designed to answer four cen-tral research questions: RQ1 Does MemCom-pile deliver meaningful performance improvements 5over long-term-memory baselines under the same evaluation protocol? RQ2 Does bounded Cell placement improve fixed-budget source recovery, and how does it complement the Evidence Plane? 

RQ3 Does budgeting by SourcePacket reduce source aliasing and distinguish source-recovery failures from evidence-presentation failures? RQ4 

Given the same recovered SourcePackets, how does reader-view granularity affect answer quality? 

4.1 Experimental Settings Datasets We evaluate MemCompile on LoCoMo (Maharana et al., 2024) and LongMemEval (Wu et al., 2025) benchmarks. LoCoMo evaluates long-term conversational memory over extended, multi-session dialogues which contains ten conversations, each comprising roughly 600 dialogue turns and 16K tokens on average. LongMemEval-s evaluates the ability of chat assistants to retain and use infor-mation across sustained user-assistant interactions, which contains 500 questions, each embedded in a history of approximately 115K tokens. 

Baselines and Metrics We compare against rep-resentative long-term memory systems spanning flat, atomic, graph, and hierarchical designs includ-ing MemoryBank (Zhong et al., 2023), A-Mem (Xu et al., 2025), Mem0 (Chhikara et al., 2025), Memo-ryOS (Kang et al., 2025), LightMem (Fang et al., 2026) , AnchorMem (Shen et al., 2026), xMemory (Hu et al., 2026) , SimpleMem (Liu et al., 2026), AtomMem (Yao et al., 2026). We report token-level F1, BLEU-1 (Papineni et al., 2002) and Judge accuracy (Zheng et al., 2023). We report token cost through memory construction and query-time retrieval/generation. For Open-Domain questions, we do not use F1 or BLEU-1 for cross-method comparisons due to this category require combin-ing conversational evidence with commonsense or world knowledge and may admit multiple lexically divergent yet semantically valid answers. 

Experimental Details Unless otherwise spec-ified, all generative components of MemCom-pile use gpt-4o-mini with temperature 0 and default top-p, and set the maximum output length to 2,048 tokens. Dense retrieval uses 

text-embedding-3-small without task-specific fine-tuning or dimensionality reduction. The LLM-as-a-Judge metric employs gpt-5-nano with a rig-orous evaluation prompt to assess semantic correct-ness.

4.3 RQ2: Analysis of Cell Placement 

We first compare five placement layouts that orga-nize the same memory items under a fixed can-didate budget. Detailed layouts definitions are provided in Appendix B.4. Figure 5 shows that structured placement improves candidate recovery across complementary query types. Bounded Cell produces the largest gains on single-hop and multi-hop questions, increasing recall by 5.13 percentage points (pp) and 3.42 pp, respectively. It also im-proves temporal recall by 1.71 pp and open-domain recall by 2.78 pp. The upstream coverage improvement carries into the Evidence Plane. Removing Cell-routed can-didates while keeping the downstream scheduler and evidence compilation pipeline fixed reduces final recall to 81.54%, a decrease of 3.96 percent-age points, F1 to 52.31, BLEU-1 to 45.14, and Judge to 77.53%. Cell placement expands the set of answer-relevant addresses available to the Evi-dence Plane, and the downstream pipeline converts this additional source coverage into measurable answer-quality gains.

4.5 RQ4: Analysis of Reader Evidence Granularity 

Table 4 isolates evidence presentation by holding the final SourcePacket exactly constant. Compress-ing each selected packet to a single representative claim reduces Judge from 80.52% to 57.01% in-dicating that aggressive compression can discard answer-bearing relations, temporal qualifiers, and other context needed to interpret an otherwise cor-rect source. Presenting the raw SourcePacket recovers much of this loss, reaching 75.32% Judge, but remains significantly below the complete claim bundle. The compiled bundle preserves the relations and qual-ifications lost by single-claim compression while filtering the conversational noise retained by raw dialogue. This fixed-source comparison isolates evidence presentation as a separate design problem from source recovery.

5 Conclusion 

We introduced MemCompile, an Address-Evidence dual-plane architecture that separates memory loca-tion from reader-facing compilation. The Address Plane improves addressing and memory placement through organizing source-linked atomic descrip-tors in bounded Cells. Source normalization then releases duplicate address slot by resolving cross-channel hits to its SourcePacket key; the Evidence Plane schedules complementary sources, preserves initial anchors during bounded expansion, and com-piles packet-scoped claims. Experiments on the LoCoMo benchmark confirm that MemCompile achieves state-of-the-art performance while the re-sult on LongMemEval-S demonstrates strong cross-benchmark performance. Ultimately, MemCom-pile offers a source-normalized and cost-effective evidence-compilation framework for deploying intelligent agents capable of sustaining reliable, evidence-grounded long-term interactions. 8Limitations 

Evaluation is limited to two conversational-memory benchmarks and proprietary LLMs; broader domains and open-model replications remain future work. Although MemCompile achieves a favorable quality-cost trade-off, its over-all token consumption could be further optimized.

A End-to-End Algorithm and Complexity 

A.1 Serving Pipeline 

Algorithm 1 specifies the complete serving path. The construction stage creates one immutable Sour-cePacket per dialogue turn, extracts an ordered set of atomic descriptors, records a foreign key from each descriptor to its packet, and places the descrip-tors into bounded Cells. At query time, query-only intent fields augment the lexical query. Cell routing and BM25 produce atomic candidates, which are collapsed by SourcePacket identity before listwise scheduling. The semantic frontier operates over a separate packet index and can only append pack-ets to the scheduled anchors. Finally, the reader view is materialized without changing the selected packet sequence. 

A.2 Source Normalization and Scheduler Validation 

Atomic candidates are grouped by their stored 

source_packet_id . Within each group, the de-scriptor with the largest retrieval score becomes the representative address; ties retain the earliest candidate. Packet ordering is then descending by the representative score, followed by first candi-date position and packet identifier. This operation changes the selection state from claims to sources without adding any source absent from the closed candidate pool. For listwise scheduling, candidate packets are assigned opaque labels C001 , C002 , and so forth. The request displays each label with the packet’s dialogue identifier, speaker, recorded date, and con-tent. The requested cardinality is min( K, |U q|). A valid response must contain exactly that many dis-tinct labels, all drawn from the request. Invalid re-sponses are retried up to three times with a schema correction; after the final attempt, the parser retains only valid, unique labels in response order. If fewer than K labels survive, the remaining closed candi-date pool is submitted in a subsequent round until the target cardinality is reached. Then output only the minimum text that fully answers that slot. Rules: - Reuse the most direct and specific wording from the evidence whenever possible. - For one value, give one short phrase rather than a sentence. - For a list, merge all and only the explicitly supported requested items into a concise comma-separated list.
