## 摘要
具备长期记忆的对话式 AI 助手会从用户消息中抽取事实，存入一个供后续对话查询的存储库。用户陈述的计划可能作为事实进入该存储库：一个可能搬到西雅图的用户，可能被记录为已经居住在那里。我们将这种错误称为推测污染。最终状态记忆基准会漏掉这一错误，因为它们不探查中间状态，且包含的未解决推测很少。我们提出 AgentMemGate，一种用于画像存储记忆的写入时门控机制，它将抽取出的陈述分类为推测、已完成事件、更正或其他。推测会留在记忆之外，并由条件控制其后续提升或删除。我们还贡献了一个多会话对话数据集，其中的计划会被确认、放弃或保持未解决。在我们的 147 个对话的留出集上，Mem0 和 Graphiti 分别将 35.2% 和 27.3% 的待定计划断言为当前状态。在核心基准上，相对于相同的无门控流程，AgentMemGate 消除了所有观察到的污染（对于最易暴露的抽取方式，从 87.5% 降至零），并将任务准确率从 65% 提高到 95%。在更难的留出集上，门控后的污染率为 3.4% 至 5.7%，任务准确率提高 9 至 13 个百分点。我们的分析指出，字段匹配是剩余的主要瓶颈：现实中的推测常常不匹配任何画像字段，因而从未到达门控。我们发布数据集、提示词和评估代码。

## Abstract
Conversational AI assistants with long-term memory extract facts from user messages into a store consulted in later conversations. A stated plan can enter that store as fact: a user who might move to Seattle may be recorded as already living there. We call this speculation contamination. Final-state memory benchmarks miss this error because they do not probe intermediate state and include few unresolved speculations. We present AgentMemGate, a write-time gate for profile-store memory that classifies extracted statements as speculation, completed event, correction, or other. Speculations remain outside memory, with conditions governing later promotion or deletion. We also contribute a dataset of multi-session conversations in which plans are confirmed, abandoned, or left unresolved. On our 147-conversation held-out set, Mem0 and Graphiti assert unresolved plans as current state for 35.2% and 27.3% of pending plans. On the core benchmark, AgentMemGate eliminates all observed contamination relative to the identical ungated pipeline (87.5% to zero for the most exposed extraction style) and raises task accuracy from 65% to 95%. On the harder held-out set, gated contamination is 3.4% to 5.7% and task accuracy rises by 9 to 13 percentage points. Our analysis identifies field matching as the main remaining bottleneck: realistic speculations often match no profile field and never reach the gate. We release our datasets, prompts, and evaluation code.

# AgentMemGate 论文结构化总结

## 1. 核心问题与研究动机

- **问题定义**：具备长期记忆的对话助手会把用户消息抽取为“事实”写入画像存储。当用户只是表达一个尚未实现的计划（如“可能在考虑搬去西雅图”），系统却将其记录为当前事实（`current_city = Seattle`），作者称之为**推测污染（speculation contamination）**。
- **为何重要**：这种错误会让助手基于从未发生的变化行动（如按“已搬家”推荐本地服务），且污染可能在后续多轮对话中持续存在。
- **现有评测的盲区**：LongMemEval、LoCoMo 等终态基准只在结果出现后打分，不检查“计划已提出、结果未知”的中间窗口；且自然对话中未解决的推测很少，难以暴露该问题。
- **现有方法的不足**：Mem0、Graphiti 等改进了抽取、去重和时间结构，但**不会延迟写入以等待后续证据**；写入时过滤方法（MemRouter、ConsistencyGate）也只决定“是否写入”，不处理“事实尚未成真、应暂存待定”的情况。
- **核心洞察**：推测不是“无依据的抽取错误”，而是“一个尚不成立的事实”。因此应**延迟（defer）而非过滤（filter）**：暂存、附上解决条件，确认后晋升，放弃后删除。

## 2. 方法论：AgentMemGate

### 2.1 存储与流程抽象

- **画像存储** \(P\)：键 \(k=(e,a)\in K=E\times A\) 映射到值 \(v\in V\)。每个键保存当前值及带有效区间 \([t_{begin}, t_{end})\) 的历史值；更正会将旧值标记为“从未有效”。
- **流水线阶段**：抽取 → 字段匹配 → 证据类型分类 → 路由（写入/暂存）→ 后续解决（晋升/丢弃）。

### 2.2 关键组件

- **抽取**：对每个用户轮次 \(u_t\) 及上下文 \(C_t\)，抽取器输出三元组 \((e,a,v)\)，不标注语句类型，也不跟踪结果。
- **字段匹配**：固定字段集 \(F\)，模型调用 `Match((e,a,v), F)` 返回匹配字段或 `none`；未匹配的候选既不会写入也不会暂存。
- **分类（门控核心）**：独立分类器查看语句来源片段及最多两轮前文，输出四类证据类型的分布：
  - `speculation`：可能的、计划的、尚未实现的未来变化；
  - `completed_event`：已发生的变化，立即提交；
  - `explicit_correction`：明确纠正此前错误，提交并使旧区间失效；
  - `other`：偏好、观察、问题等非修订性内容，立即提交。
- **路由**：按 argmax 分类。门控关闭时所有匹配元组直接提交；门控开启时，仅 `speculation` 被移出存储，进入暂存区 \(H\)。
- **暂存与解决**：暂存项 \(\sigma=(k,v,\phi)\) 在暂存时生成两条自然语言谓词：
  - \(\phi_{confirm}(u_t)\)：确认条件满足则晋升到 \(P(k)\)；
  - \(\phi_{abandon}(u_t)\)：放弃条件满足则丢弃。
  - 暂存期间对读取不可见；每轮后续用户消息由独立 checker 模型调用检查条件。
- **计划框架重试（仅谨慎抽取配置）**：用正则移除 `grocery_plan` 等计划性短语后重新提交匹配（如 `grocery_plan → grocery → grocery_store`），原始推测语句仍会进入分类器被暂存。消融显示该重试本身不是门控在起作用。
- **算法流程（文字版）**：对每轮用户输入，先抽取元组；逐个匹配字段，失败则按配置重试，仍失败则丢弃；随后分类，若非推测或门控关闭则直接提交，否则暂存；最后遍历暂存区，检查确认/放弃条件并晋升或删除。

### 2.3 设计取舍

- 作者强调**分离“抽取”和“写入路由”**，使错误可归因、存储策略可测试；分类器基于“证据类型”而非直接问“事实是否为真/是否应存储”，在验证中 AUROC 更高。
- 暂存保留计划信息但不对回答暴露，避免“提前写入”与“完全丢失”两个极端。

## 3. 实验设计

### 3.1 数据集与场景

- **自建 plan-to-outcome 数据集**，三个划分共享结构：2–3 个带日期的会话，用户先陈述当前值，再以对冲语气提出切换计划，之后返回；每个计划标注为“成真 / 放弃 / 仍未解决”。
  - **核心基准**：60 个对话，三种结果各 20 个。
  - **留出集**：147 个对话，含 88 个风险计划、44 个成真计划、15 个“已完成变化”控制；会话更短、值为长自由文本，难度更高。
  - **控制难度划分**：179 个对话，单因素变化——5 档计划措辞（强对冲、弱对冲、无日期确信计划、有日期计划、已完成变化控制）和 4 档确认措辞（逐字、改写、间接、情境暗示）。
- **辅助评测**：LongMemEval 与 LoCoMo 中 161 个依赖“对话中变化事实”的问题；240 次含显式更正的运行；15 个已完成变化控制。
- **产品级黑盒评测**：Mem0 与 Zep Graphiti 在 147 个留出对话上逐会话摄入并查询当前值。

### 3.2 评测指标

- **待定窗口污染率**：计划尚未有结果期间，被存为字段当前值的风险计划比例。
- **终态污染率**：对话结束时同样统计。
- **任务准确率**：每对话一个探针问题（“用户当前使用什么？”），从最终存储回答，由固定等价 judge 评分。
- 比例报告 95% Wilson 置信区间；配对差异使用聚类 bootstrap。

### 3.3 对比方法与控制

- **四种流水线配置**：两种抽取风格（literal 直接记录陈述值；cautious 将计划记录为计划）× 门控开/关。提示词分别改编自 Graphiti 与 Mem0 的公开抽取提示。
- **仅提示基线**：cautious + 无门控，检验“把计划说成计划”是否足够。
- **计划类型提交基线**：立即写入但标记为 plan，读取时屏蔽，检验“读时屏蔽”能否替代暂存与解决。
- **控制实验**：已完成变化应立即提交；显式更正应正确应用；另测过度暂存率。
- **模型**：主实验所有组件使用固定模型 `gpt-5.5-2026-04-23`；另用 `claude-opus-4-8` 做第二模型家族复现。

## 4. 资源与算力

- **论文未报告 GPU 型号、数量、训练时长或总 token 消耗**。该系统是推理型流水线，不涉及模型训练；所有组件均为固定提示下的单次 LLM 调用，路由与存储为确定性逻辑。

- 因此无法从文中评估总计算成本或碳足迹，这是复现成本透明度上的一个缺口。

- **优点**：

  - 控制难度划分做到“一次只变一个因素”，能定位污染随措辞变化的趋势；
  - judge 与分类器均做了异家族模型复判和人工盲审，并报告了置信区间与重复运行稳定性；

  - 每个控制单元仅 \(n=20\)，置信区间很宽（如 0% 的 Wilson 上界为 16.1%），小样本下的“零污染”不能理解为绝对为零；

  - 每个对话只注册一个字段、匹配为接受/拒绝二选一，未覆盖大字段集中的字段选择问题。

## 6. 主要结论与发现

- **污染普遍且被终态指标掩盖**：147 个留出对话上，Mem0 对 35.2%（31/88）、Graphiti 对 27.3%（24/88）的待定计划曾断言为当前状态；Mem0 最终问题准确率仍有 78.9%，说明“最终答案正确”与“中间状态正确”是两种能力。
- **门控显著降低污染**：核心基准上，literal 无门控的待定窗口污染为 87.5%，门控后为 0%（上界 8.8%）；cautious 无门控为 2.5%，门控后为 0%。留出集终态污染：cautious 由 10.2% 降至 5.7%，literal 由 23.9% 降至 3.4%。
- **门控不以准确率为代价，反而提升准确率**：核心基准 literal 由 65% 升至 95%；留出集两种抽取风格分别提升 12.9 与 9.5 个百分点；LongMemEval/LoCoMo 变化事实问题上 literal 提升 9.9 点，cautious 为 0.0 点（区间跨零）。
- **仅靠提示词不稳定**：cautious 抽取在强/弱对冲时污染为 0，但在“确信计划”和“有日期计划”时升至 10% 与 20%，说明其保护依赖措辞而非证据状态。
- **字段匹配是剩余主瓶颈**：大量推测被抽取为偏好、兴趣、条件等，匹配不到任何画像字段，因而从未到达门控；cautious 配置在确认措辞划分中仅 23/80 进入暂存，但一旦暂存，晋升率为 82.6%。计划框架重试可扩大覆盖，但只能部分恢复（核心基准 22/60，留出集仅 11/132）。
- **确认越隐晦，晋升越不可靠**：情境暗示确认下，门控 literal 仅答对 13/20，低于无门控的 19/20；无门控的高分部分来自“提前写入”的偶然正确。
- **分类器表现**：在 163 条自然语句上，推测类精确率 92.5%、召回 88.1%；对“是否应更新画像”的排序 AUROC 为 0.93，优于直接问“现在是否为真”（0.69）和“是否应存储”（0.62）；主要错误是过度提交（将 `other` 误判为 `completed_event`），更正类因样本极少表现最弱。
- **控制成本可控**：显式更正结果与无门控一致；已完成变化控制的过度暂存率为 6.7%（15 个中 1 个）。
- **读时屏蔽的替代方案不完整**：计划类型提交基线污染低，但对话结束时 85–90% 的计划条目仍未解决；在严格读取解释下，literal 成真计划终态正确率仅 5.0%。
