## 摘要
记忆使大语言模型（LLM）智能体在响应请求时能够利用过去经验，这些经验通常以文本记录的形式存储。对于控制机器人的具身智能体而言，视觉与空间观测引入了更广泛的记忆模态选择，既影响后续任务可用的信息，也影响构建和使用记忆的模型推理成本。我们提出 MeMoREval，一个通过受控的经验—请求协议来研究该问题的基准。智能体首先在不知道后续任务的情况下经历一系列事件，随后在不接收新观测的情况下利用记忆来响应信息请求和动作请求。该基准包含跨四个模拟室内环境的 53 个任务，并在测量任务成功率的同时测量记忆构建与使用的推理成本。我们的参考评估表明，对于主模型而言，存储帧在更低的写入时推理成本下优于存储生成的描述；而存储帧并结合场景图则在所有被测模型上取得最高的总体任务成功率。对累积经验、选择性帧保留以及向记忆写入器提供视觉输入的扩展，展示了该基准如何支持进一步的记忆设计研究。两个实体机器人演示验证了将其协议应用于仿真之外场景的可行性。

## Abstract
Memory allows large language model (LLM) agents to use past experience, often stored as textual records, when responding to requests. For embodied agents that control robots, visual and spatial observations introduce a broader choice of memory modalities, affecting both the information available for subsequent tasks and the model inference costs of constructing and using memory. We introduce MeMoREval, a benchmark for studying this problem through a controlled experience-request protocol. Agents first experience a sequence of events without knowing the subsequent tasks, and subsequently they use memory to respond to information and action requests without receiving new observations. The benchmark comprises 53 tasks across four simulated indoor environments and measures task success alongside the inference costs of memory construction and use. Our reference evaluations reveal that storing frames outperforms storing generated descriptions at lower write-time inference cost for the primary model, while storing frames with scene graphs achieves the highest aggregate task success for every tested model. Extensions to accumulated experience, selective frame retention, and visual input to memory writers demonstrate how the benchmark accommodates further memory-design investigations. Two physical-robot demonstrations establish the feasibility of applying its protocol beyond simulation.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体普遍依赖外部记忆来复用过去经验，现有记忆系统（MemGPT、Mem0、A-MEM、Reflexion 等）与记忆基准（LoCoMo、LongMemEval、MemLens、MemEye）多以**文本或对话**为载体，主要考察长程回忆。
- **具身场景的特殊性**：控制机器人的智能体除文本外，还可保留**相机帧、场景图/空间记录**等多种证据形式；记忆模态的选择同时决定“后续任务能取回什么信息”和“构建/使用记忆的推理开销”。
- **核心痛点一：信息在写入时就被丢弃**。生成描述必须在**尚不知道未来请求**的情况下决定“写什么”，任务相关细节（如颜色）可能被提前省略；而存帧把解释推迟到请求到来之后。
- **核心痛点二：遗忘的代价是物理的**。代码智能体可通过重读代码库恢复信息，代价只是算力与延迟；机器人则需重新导航、开柜、操作物体，记忆失败表现为重复搜索与多余动作，且环境变化（物体被移动/移除）可能使信息**不可恢复**。
- **研究问题**：RQ1 记忆模态如何影响信息请求与动作请求的成功率（跨任务类别与模型）；RQ2 模态如何在成功率与写入/读取推理成本之间权衡；RQ3 该基准如何指导实际部署中的记忆设计。
- **关键概念区分**：**记忆模态（modality）**＝保留证据的形式（文本、帧、描述、场景图及其组合）；**记忆后端（backend）**＝证据的组织与检索方式（滚动 transcript、wiki 页面、A-MEM、Mem0、ObsMem）。论文主张把二者解耦，让模态成为受控主变量。

## 2. 方法论

### 2.1 核心思想：受控的“经验—请求”两阶段协议

- **经验阶段（Experience）**：机器人执行**脚本化**的动作序列（巡游、物体被移动、容器被打开、用户表达偏好等），记忆模块同步记录观测与动作结果。智能体此时**不知道**后续请求，因此必须“先存后知”。
- **请求阶段（Request）**：智能体从**全新上下文**开始，不含任何经验阶段的观测，只能通过记忆模块取回信息。请求分两类：
  - **信息请求**：回答事实性问题（如“哪个柜子里有杯子”）。
  - **动作请求**：提交**完整技能调用计划**，由机器人**开环执行**，执行中不返回新观测、不允许修改计划。
- **设计要点**：开环执行是防止智能体“靠现场探索补偿记忆缺失”的关键，否则评测的是探索能力而非记忆能力；同一任务内信息请求先于动作请求，从而把“记得住”与“会使用”分开度量。
- **堆叠任务（Stacked）**：把多个任务的经历阶段串接成长历史，再依次发出全部信息请求与动作请求；每个动作请求前将仿真器复位到合并经验结束时的状态，保证各计划从同一物理状态评估，组件任务沿用原评分标准。

### 2.2 观测流与记忆写入

- 基准提供三种观测流：
  - **文本**：用户消息、技能反馈、当前检测到的物体（类别、开合状态、支撑/包含关系），**刻意不含颜色与纹理**。
  - **视觉**：带边界框与整数物体 ID 的相机帧（ID 也用于工具调用中指代物体）。
  - **空间**：场景图快照，节点存物体 ID 与世界坐标 3D 位置，边存支撑/包含关系，**不含外观属性**，也不显式编码序数或视角相关关系。
- **写入器（writer）**：可选的 LLM 角色，把观测加工为记忆条目；**读取器（reader）**即使用记忆的智能体。二者可为同一模型。帧、描述、场景图快照可**绕过 writer 直接归档**，按经验步号索引，智能体通过步号调用检索工具取回。

### 2.3 记忆条件（模态）

- 六种主条件共享同一份由公共观测构建的文本记忆：
  - `text`：仅文本记忆。
  - `desc@64 / @256 / @1024`：额外归档**生成的帧描述**，按 64/256/1024 token 预算，由与 writer、agent 相同的模型基于“标注帧＋同步文本观测”生成，逐字存储、不经 writer。
  - `frames`：额外归档标注相机帧。
  - `frames+graph`：再额外归档场景图快照。
- **检索约束**：每个请求最多 5 次检索调用；每轮最多 20,000 字符文本记忆渲染进上下文；检索到的帧/描述/场景图记录不计入该上限。

### 2.4 后端

- 五个后端共享同一接口、上下文上限与检索机制：`transcript`（无 LLM writer 的滚动历史）、`wiki`（命名页面的 append/rewrite）、以及适配的 `A-MEM`、`Mem0`、`ObsMem`。所有 writer 接收相同观测与“记什么”的指令。

### 2.5 成本度量（无训练，纯推理成本）

- 采用**加权 token**：`T_in × (P_in / P_out) + T_out`，其中输入含图像 token、输出含推理 token；该量等于“成本 ÷ 输出 token 单价”，故**仅可在同一模型内跨条件比较**。
- **写入成本**：经验阶段 writer 更新与描述生成，按“每经验步”报告。
- **读取成本**：请求阶段全部模型调用，按“每请求”和“每成功请求”报告（后者把失败尝试也计入）。
- 同时报告工具调用次数与推理 token 数，用于解释成本差异来源。

- **机器人**：Dexmate Vega 1 双臂移动操作平台，通过技能工具控制（导航、开/关家具、抓取、放置），抓取与放置用碰撞检测运动规划，导航用规划器验证的路径；请求阶段用 `answer`、`submit_plan`、`done` 三类接口。
- **任务规模**：53 个任务，覆盖 7 类被记忆信息：物体位置(11)、空间构型(11)、外观绑定(10)、集合聚合(8)、用户偏好(5)、遮挡状态(4)、技能结果(4)；分布为 office 12、studio 14、home 14、clinic 13。每个环境另构造由 10–11 个组件任务组成的堆叠复合任务。
- **评分**：完全确定性。信息请求对照指定类型的参考答案（区域、物体、计数、集合）；动作请求对照任务特定的仿真终态谓词（如目标物体是否被持有或置于指定表面）。
