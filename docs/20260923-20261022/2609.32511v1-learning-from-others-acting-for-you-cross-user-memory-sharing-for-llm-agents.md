## 摘要
服务于不同用户的大语言模型（LLM）智能体常常解决相关任务，但彼此分离的用户历史会使可复用经验无法被其他智能体获取。汇聚记忆可扩大可访问范围，但存在将接收用户需求相冲突的偏好迁移过来的风险。我们提出ShareMem，一种记忆架构，在共享可复用经验的同时，将其应用建立在接收用户自身偏好之上。共享经验指示如何行动以及应查询哪些偏好；接收用户的记忆则提供其具体取值。两阶段整合先在本地精炼经验，再将获接受的编辑并入共享池。在执行阶段，范围优先检索在统一的条目预算下联合选择本地与共享经验，而用户绑定通道支持初始偏好检索与由智能体发起的偏好检索。我们在网页导航（Mind2Web）、在线个性化交互（VitaBench~2.0）和多会话编程（MemoryCode）三类任务上，使用四个骨干模型对ShareMem进行评估。在所有四个模型上，相较匹配的用户本地记忆，它分别提升了步骤成功率、平均任务成功率和对话宏平均编程得分。消融实验表明，两阶段整合在更小的共享池、更低的归纳token用量以及更好的下游性能方面更具优势，并支持经验指导与主动偏好检索之间的互补性。进一步分析表明，当相关本地经验稀缺时共享收益最大，而来源质量与跨用户偏好干扰会限制有效迁移。

## Abstract
Large language model (LLM) agents serving different users often solve related tasks, yet separate user histories can leave reusable experience inaccessible to other agents. Pooling memories expands access but risks transferring preferences that conflict with the receiving user's requirements. We introduce ShareMem, a memory architecture that shares reusable experience while grounding its application in the receiving user's own preferences. Shared experiences indicate how to act and which preferences to consult; the receiving user's memory supplies their concrete values. Two-stage consolidation refines experience locally before integrating accepted edits into a shared pool. During execution, scope-first retrieval jointly selects local and shared experiences under a common entry budget, while a user-bound channel supports initial and agent-initiated preference retrieval. We evaluate ShareMem across web navigation (Mind2Web), online personalized interaction (VitaBench~2.0), and multi-session coding (MemoryCode) with four backbone models. It improves step success, average task success, and dialogue-macro coding scores, respectively, over matched user-local memory across all four models. Ablations favor two-stage consolidation for smaller shared pools, lower induction token usage, and better downstream performance, and support complementarity between experience guidance and active preference retrieval. Further analyses show that sharing helps most when relevant local experience is scarce, while source quality and cross-user preference interference limit useful transfer.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已具备长期记忆能力，可复用历史经验并实现个性化服务。在多用户部署场景（如企业内部共享智能体平台）中，不同用户常处理相似任务，但各自的历史记忆彼此隔离。
- **核心瓶颈——经验可达性瓶颈（experience-reachability bottleneck）**：用户 A 已获得的可用流程/经验，用户 B 的智能体无法访问，导致重复摸索。
- **直接汇聚记忆的风险**：若把所有用户历史放入公共池，虽扩大访问范围，却可能把贡献者的个人偏好（如命名习惯、口味、舱位偏好）错误迁移给接收用户，与其实际需求冲突。
- **关键区分**：论文强调“可访问（accessible）”不等于“可适用（applicable）”。访问权限只决定能否检索，成功个性化还要求把**可复用程序**与**用户特定偏好**分离。
- **核心研究问题**：智能体如何复用他人的经验，同时仍按**接收用户自己的偏好**来执行？

## 2. 方法论：ShareMem 架构

### 2.1 核心思想
- 共享经验只回答“**如何行动**”以及“**应查询哪些偏好维度**”，不携带具体偏好值；具体偏好值由接收用户自己的本地记忆提供。
- 每个用户 \(u\) 拥有智能体实例 \(A_u\)、交互历史 \(H_u\)、本地记忆 \(M_u\)（偏好 \(P_u\) + 按适用范围 \(s\) 组织的经验 \(E_{u,s}\)）；共享记忆 \(S\) 存放跨用户经验集合 \(R_s\)。
- 偏好与经验**分开维护**；共享经验可跨用户访问，但偏好通道严格绑定当前用户。

### 2.2 两阶段经验整合（Two-stage consolidation）
1. **本地更新**：对轨迹/会话 \(\tau\)，由适配器分配范围 \(s=\sigma(\tau)\)；本地检索器取最多 \(k_w=5\) 个相关邻居 \(N_{u,s}\)；LLM 更新算子 \(U_{\text{local}}\) 基于证据与邻域对本地经验集合做增/替/删/不变操作，得到更新后的 \(E'_{u,s}\) 与被接受的编辑集 \(\Delta_{u,s}\)。
2. **共享整合**：对每个被接受的编辑 \(\delta\in\Delta_{u,s}\)，从共享池检索最多 \(k_w\) 个邻居，取并集 \(N^{\text{shared}}_s\)，再由共享更新算子 \(U_{\text{shared}}\) 独立决定共享池如何修改。
- 关键设计：本地替换/删除**不会**被机械重放到共享池；没有本地被接受的编辑时，共享池不变。这样可避免冗余贡献挤占有限检索槽位。

### 2.3 范围优先的联合经验检索（Scope-first retrieval）
- 为任务 \(x\) 构造 \(J\) 个范围组 \(G(x)=(G_0,\dots,G_{J-1})\)，从直接匹配到更宽泛回退，优先级依次降低。
- 每组候选为本地与共享经验的并集：
  \[
  C_j=\bigcup_{s\in G_j}\big[R(x,E_{u,s};K_c)\cup R(x,R_s;K_c)\big],\quad K_c=25
  \]
- 最终指导集：
  \[
  H_x=\text{ScopeTopK}\big(x,(C_0,\dots,C_{J-1}),K\big),\quad K=5
  \]
- 在同一组内，本地与共享候选**不设配额**，按相关性联合重排，共享统一 \(K=5\) 条目预算；低优先级组只填补剩余槽位，不能挤掉高优先级已选条目。

### 2.4 用户绑定的主动偏好检索
- 初始召回：\(B^0_u=R_{\text{pref}}(x,P_u;k_p)\)，\(k_p=10\)，与任务输入和经验指导一起进入上下文 \(h_0\)。
- 执行时策略 \(\pi_\theta\) 在动作空间 \(A_{\text{env}}\cup A_{\text{pref}}\cup A_{\text{out}}\) 中选择动作；若发起偏好查询 \(q_t\)，返回观测 \(o_t=R_{\text{pref}}(q_t,P_u;k_p)\)，并追加到上下文：
  \[
  h_{t+1}=h_t\parallel(a_t,o_t)
  \]
- 环境固定当前用户 \(u\)，**禁止跨用户偏好访问**；经验只指导“该查什么偏好”，不会自动触发检索。

### 2.5 范围实例化
- Mind2Web：按网站存储，匹配优先级为网站 → 子域 → 域 → 其他站点。
- VitaBench 2.0：按任务域组织，同域优先，再回退其他域。
- MemoryCode：单一编程范围，无回退层级。
