## 摘要
智能体在读取输入、推理并调用工具时，其记忆会不断增长。更长的历史会增加推理成本，并最终超出上下文窗口。基于大语言模型（LLM）的摘要可缩短该历史，但会增加延迟，且未对信息损失给出显式界限。我们提出 LAM，一种有损智能体记忆系统，包含三个组件：一种确定性的去重规则，带有对检索分数的替换界——这是对分数扰动的界，而非排序保持不变的证明；一个保留缓存前缀并将压缩与推理重叠执行的记忆管理器；以及一个可在部署前估计压缩成本的性能模型。在 600 条智能体轨迹上，LAM 移除了 22.47% 的观测 token，同时保留了 99.984% 的测量到的 gold-patch 证据。在固定删除集下，性能模型预测：在预填充之前移除记录，而不是从已预填充的上下文中删除它们，可获得 71.4 倍至 91.6 倍的端到端加速。该收益来自调度安排而非规则本身，并适用于任何保持前缀的测试。

## Abstract
Agent memory grows as agents read inputs, reason, and call tools. Longer histories increase inference cost and eventually exceed the context window. LLM-based summarization reduces this history but adds latency and provides no explicit bound on information loss. We propose LAM, a Lossy Agent Memory system with three components: a deterministic deduplication rule with a substitution bound on retrieval scores - a bound on score perturbation, not a certificate of unchanged ranking; a memory manager that preserves the cached prefix and overlaps compaction with inference; and a performance model that estimates compaction costs before deployment. On 600 agent trajectories, LAM removes 22.47% of observation tokens while retaining 99.984% of the measured gold-patch evidence. At a fixed deletion set, the performance model predicts a 71.4x-91.6x end-to-end speedup from removing records before prefill instead of deleting them from a prefilled context. That benefit comes from the schedule rather than the rule and applies to any prefix-preserving test.

- **背景**：AI 智能体在执行任务时会持续积累文件读取、命令执行与工具输出等历史记录。历史越长，推理成本越高，最终会超出上下文窗口，因此必须进行记忆压缩（compaction）。
- **现有方法的缺口**：
  - 基于 LLM 的摘要/学习式压缩器（Gisting、ICAE、xRAG、LLMLingua-2、Mem0 等）需要额外模型推理，增加延迟，且**不对信息损失给出显式界限**，可复现性依赖权重与执行配置。
  - SemDeDup 用 k-means 聚类嵌入，结果随初始化波动；观察掩码（observation masking）只保留最近 k 条观测。
  - 这些方法暴露 token 预算、聚类数或窗口大小，但**没有一个参数能约束删除所导致的检索分数损失**。
- **关键观察**：智能体工具输出高度重复（重读文件、重跑测试、重复列目录），但精确哈希只能捕捉逐字节相同的副本，漏掉仅有细微差异的输出。
- **论文主张**：提出 LAM（Lossy Agent Memory），用**查询无关的替换误差界**约束删除造成的检索分数扰动，并通过**在预填充之前完成去重**来保留 KV 缓存前缀，从而把收益来源明确归因于“调度”而非“删除规则”。

## 2. 方法论

### 2.1 核心思想

- 将每条到达记录与已保留记录做**单位化嵌入空间中的 ℓ2 距离检验**：若存在保留记录满足 $\|a-b\|_2 \le \delta$，则用引用桩（stub）替换该到达记录。
- 由于对单位向量有 $\|a-b\|_2^2 = 2-2\cos(a,b)$，合并阈值 $t$ 与替换半径 $\delta$ 一一对应：$\delta=\sqrt{2-2t}$（默认 $t=0.95 \Rightarrow \delta=0.316$）。
- **关键性质**：检验发生在记录被预填充**之前**，因此已缓存前缀不被破坏；决策不可回溯，索引只含保留记录。

### 2.2 三层设计（L0 / L1 / L2）

- **L1（近重复层，先运行）**：对坐标做量化 $Q_\varepsilon(x)=\mathrm{round}(x/2\varepsilon)$，分 band 哈希生成候选，再用**全精度 ℓ2** 验证；只有通过 $\delta$ 检验才合并。哈希为 $O(N)$，验证成本随候选数增长；候选漏检只影响移除率，**不影响已接受合并的替换界**。
- **L0（字节精确层，后运行）**：沿用 vLLM 式前缀缓存思想，用 xxHash3 对**单行**做精确哈希（实验表明行粒度移除 18.14%，远高于整记录 1.61%、512-token 块 2.61%）。先跑 L0 会打碎 L1 可匹配的块，故顺序为 **L1 → L0**（在 $\cos\ge0.95$ 下顺序差异 2.45 个百分点，0.90 下 4.08 个百分点）。
- **L2（字节压缩层）**：用 cuSZp 对**保留的嵌入**做有相对误差界的压缩，与去重相乘降低索引存储；它不减少上下文文本，因此不进入 token 移除指标。

### 2.3 替换界（理论核心）

- **定义 1（δ-替换）**：$R\subseteq S$，映射 $\pi:S\to R$ 且 $\pi|_R=\mathrm{id}$，对一切 $x$ 有 $\|x-\pi(x)\|_2\le\delta$。
- **定理 1（分数亏空）**：对任意单位查询 $q$，$0 \le \max_{x\in S} q\cdot x - \max_{z\in R} q\cdot z \le \delta$，且两端常数都紧（用 Cauchy–Schwarz 证明，取 $q=(a-b)/\delta$ 可达）。
- **代表选择**：采用贪心“首次出现”规则，每个被删记录选**索引最低**的合格保留代表；因近邻关系**不满足传递性**，不能用连通分量（DSU）合并（DSU 会超出所声明的界，实测 $\hat\delta/\delta$ 达 2.5）。
- **实测界**：每次运行报告实际最大替换距离 $\hat\delta$（默认配置下 0.268 vs 配置值 0.316），定理以 $\hat\delta$ 替代 $\delta$ 仍成立。
- **推论**：Corollary 1（top-k δ-覆盖）、Proposition 1（逐名次亏空）、Corollary 2（对任意源分布的 rate–distortion 上界 $R_P(\delta)\le H(\pi(X))\le\log_2|R|$）、Corollary 3（用半径 $\delta$ 与 $2\delta$ 两次贪心 pass 夹逼 $\delta$-熵）、Theorem 2（移除上限 $\rho^*(\delta)\le\rho_{\text{greedy}}(2\delta)$，可一趟额外计算）。
- **作者明确界定作用范围**：该界只约束**分数扰动**，**不保证排序不变或任务成功**；在 LoCoMo 上 $\delta=0.316$ 是中位 top-1 margin（0.0185）的 17 倍，默认阈值下没有任何查询的 top-k 可证不变。

### 2.4 调度与性能模型

- **调度洞察**：从已预填充的上下文中删除记录会使后续位置的 KV 条目失效，需要重新预填充；先检验后预填充则前缀存活。模型预测：重预填充 360K 上下文约 538 s，而该轮推理约 12 s；原地删除把 98.6% 的运行时间花在压缩+重预填充上，LAM 仅 0.1%。
- **成本模型**：把一轮拆成随上下文长度 $C$ 缩放的部分（解码 KV 读取、到达 token 的预填充）与不随 $C$ 缩放的部分（权重流式读取），设 $\varphi$ 为前者占比，Amdahl 上限 $1/(1-\varphi)$；端到端时间 = 服务项 + 压缩项 + 指示函数控制的重预填充项。$\varphi$ 在 batch 1 / 32K 下为 21.6%（上限 1.28×），batch 32 下为 76.6%（上限 4.28×）。
- **放置策略**：检验跑在主机 CPU 上，与 GPU 推理重叠；编码成本单独计账（编码占压缩耗时 99.989%）。
