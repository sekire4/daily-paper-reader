## 摘要
长期智能体不仅需要记住关于用户的真实信息，还需要随着共享历史的演变，记住特定智能体应如何与该用户协同工作。现有基准主要监督用户事实与偏好，或可在用户间复用的经验，使这种关系特定的智能体记忆仍处于隐含状态。此外，大多数先前工作仅通过长交互历史上的最终答案问答来评估模型，使评估仍不完整且不可靠。为此，我们提出 DyadMem，并给出新定义：用户条件化的关系型智能体记忆（User-conditioned Relational Agent Memory, URAM）。DyadMem 沿相同的多会话轨迹联合标注用户侧记忆与 URAM，形成 6 类记忆类别。总之，它包含 3,065 个 episode、50,961 个会话和 61,210 个问答实例，并提供大量会话级 Capture 与 Update 金标准标注、查询级 Recall 支持，以及两种问答设置：Gold-Memory 和 Full-Pipeline。在 16 个开放权重模型和 4 个专有模型上，Gold-Memory 问答表现始终较强，但 Full-Pipeline 问答显著下降。这一差距明确支持了我们细粒度评估设计。此外，若干定量结果进一步揭示了即使是前沿大语言模型也存在 Capture 召回率低、Recall 不完整以及不安全删除等问题。我们进一步开展了一项严谨实验以验证 URAM 的有效性，并观察到其对全部 20 个模型均有正向效果。总之，DyadMem 是一个双领域、全流程的记忆基准，并投入了大量标注工作，以推动该领域的发展。

## Abstract
Long-term agents must remember not only what is true about a user, but also how a particular agent should work with that user as their shared history evolves. Existing benchmarks primarily supervise user facts and preferences or experience reusable across users, leaving this relationship-specific agent memory implicit. Additionally, most prior works measure the model solely with final-answer QA over long interaction histories, making the assessment still incomplete and unreliable. To this end, we introduce DyadMem with the proposed new definition User-conditioned Relational Agent Memory (URAM). DyadMem jointly annotates user-side memory and URAM along the same multi-session trajectories, resulting in 6 memory categories. To summarize, it includes 3,065 episodes, 50,961 sessions, and 61,210 QA instances, with extensive session-level Capture and Update gold annotations, query-level Recall support, and two QA settings: Gold-Memory and Full-Pipeline. Across 16 open-weight and 4 proprietary models, Gold-Memory QA is consistently strong, yet Full-Pipeline QA drops sharply. Such a gap explicitly supports our fine-grained evaluation design. Additionally, several quantitative results further reveal low Capture recall, incomplete Recall, and unsafe-deletion issues arising from even the frontier LLMs. We further conduct a rigorous experiment to validate the effectiveness of our URAM and observe the positive effects for all 20 models. In summary, DyadMem is a dual-domain, full-pipeline memory benchmark with extensive annotation efforts for advancing the domain's development.

# DyadMem 论文结构化总结

## 1. 核心问题与研究动机

- **背景缺口一：记忆对象不完整。** 长期交互智能体不仅要记住“用户是谁、用户有什么事实与偏好”，还要随共享历史演变，学会“**这个特定智能体应如何与这个特定用户协同工作**”。现有基准分两条线：用户记忆基准（LoCoMo、LongMemEval、PerLTQA、ConvoMem、PersonaMem、Memora、STALE）只监督用户侧信息；经验型智能体记忆（Agent Workflow Memory、Memp、LongMemEval-V2 等）只提取可跨用户迁移的工作流与失败模式。二者之间的**关系特定智能体记忆**长期处于隐含状态。
- **背景缺口二：评估方式不完整。** 多数基准仅用长历史最终答案 QA 衡量，把“构建正确记忆、随变化维护、检索完整支持、用支持作答”四类能力混在一起。结果是：正确答案可能掩盖不完整或不安全的记忆库；错误答案无法定位失败环节。
- **核心概念：URAM（User-conditioned Relational Agent Memory）。** 它不是对用户的另一份描述——两个智能体服务同一用户，可能因交互历史不同而需要不同的未来行为。URAM 记录的是“该智能体对该用户应做什么不同的事”。
- **整体含义：** 论文主张长期记忆应同时表示**用户侧记忆**与**用户条件化的智能体侧记忆**，并在同一交互轨迹上对记忆全生命周期（Capture → Update → Recall → QA）逐阶段监督与评测。

## 2. 方法论

### 2.1 核心思想
- **双域 + 全流程：** 在同一多会话轨迹上联合标注用户侧记忆、URAM 与共享 episodic 记忆；分别评测记忆构建、维护、检索与使用，使失败可定位，而非只通过最终答案可见。
- **对话优先构建（dialogue-first）：** 先生成并验证完整多会话对话，再从已实现的交互中重建记忆及其变化，保证每条标注可追溯到对话证据；生成计划只规定“应发生何种记忆变化、何时发生”，不规定最终记忆条目。

### 2.2 任务形式化
- 一个 episode = 按时间排序的会话序列 + QA 集。会话 *t* 含：时间锚点 τ_t、完整对话 D_t、gold Capture 条目 C*_t、gold Update 操作（删除集 L*_t、

删除集 \(L^*_t\)、新增/修改集 \(U^*_t\) 等）、以及 gold 共享 episodic 记忆 \(E^*_t\)。QA 集则按能力分层，分别对应 Capture、Update、Recall 与 QA 四个阶段，并要求每个答案给出可追溯的记忆证据链。
- **双域记忆表示：** 用户侧记忆刻画用户事实、偏好、目标与状态；URAM 刻画“针对该用户，智能体应遵循的协作策略、沟通方式、边界条件与历史教训”；episodic 记忆保留双方共同经历的关键事件，作为前两者的证据来源与上下文桥梁。
- **阶段解耦：** 将传统“端到端长历史问答”拆为四个可独立评分的能力环节——记忆捕获（是否抽全、抽准）、记忆更新（是否随新信息正确增删改、避免污染与过时）、记忆检索（是否召回完整且必要的支持集合）、记忆使用（是否忠实依据检索结果作答），从而定位失败来源。

### 2.3 数据构建流程
- **对话优先生成：** 先由计划层规定多会话交互中“应发生哪些记忆变化、在何时发生”，再生成完整、自然、时间一致的多轮对话；记忆标注从已实现对话中反向重建，确保每条记忆均有对话证据支撑，而非凭空设定。
- **记忆重建与对齐：** 对每个会话逐步重建用户侧记忆、URAM 与 episodic 记忆，并显式记录更新操作及其触发证据；对同一记忆条目的跨会话演化保留版本链，便于评测“维护”而非仅“最终状态”。
- **分层 QA 构造：** 针对四阶段分别构造问题：Capture 问“应从本段对话获得什么记忆”；Update 问“新信息如何改变既有记忆”；Recall 问“回答某问题需要哪些记忆条目”；QA 问“基于给定记忆应如何作答”。同时加入干扰项、时间冲突与近似重复信息，检验抗污染与抗过时能力。
- **质量控制：** 通过自动检查（时间一致性、证据可追溯性、记忆与对话蕴含关系）加人工/模型复核，过滤无证据记忆、矛盾标注与不可回答问题；并对 URAM 标注强调“用户条件化”，避免退化为普通用户画像。

### 2.4 评测设置与指标
- **Capture：** 以条目级匹配衡量召回率、精确率与 F1，区分用户侧、URAM 与 episodic 三类记忆。
- **Update：** 衡量增删改操作的准确率与完整性，并单独考察“过时信息是否被正确失效”“冲突信息是否被正确处理”“无关信息是否被误写入”。
- **Recall：** 在给定查询下评估召回记忆集合与 gold 支持集合的一致性，常用 Recall@k、支持覆盖率与噪声率。
- **QA：** 在标准答案准确率之外，评估答案是否由检索到的记忆支持（证据忠实度），以及当记忆缺失或冲突时模型是否表现出恰当的不确定性。
- **诊断性分析：** 通过阶段间关联分析判断最终错误主要来自捕获缺失、更新错误、检索不全还是使用不忠实，形成可解释的错误归因。

## 3. 实验与主要发现

- **基线覆盖：** 对比无长期记忆、纯用户记忆、纯经验/工作流记忆以及统一长上下文或 RAG 式记忆系统，检验双域记忆与全流程监督各自带来的增益。
- **总体趋势：** 仅优化最终 QA 的系统在阶段指标上暴露明显短板——即使答案偶发正确，记忆库仍可能存在遗漏、过时或污染；加入 URAM 与阶段监督后，Recall 支持覆盖率与 QA 证据忠实度同步提升。
- **阶段瓶颈：** 更新环节通常比捕获更困难，尤其在信息冲突、时间演化与近似重复场景下；检索环节的主要问题不是“召回不到”，而是“召回不完整或混入无关条目”；使用环节则表现为有支持记忆但作答偏离证据。
- **双域消融：** 去掉 URAM 后，涉及协作策略、沟通边界与历史教训的问题显著退化，说明用户侧记忆无法替代关系特定智能体记忆；去掉 episodic 证据桥接后，跨会话追溯与更新判断同样受损。
- **错误归因价值：** 分阶段评测使“答案错”可进一步定位为捕获遗漏、更新失败、检索缺失或使用不忠实，验证了基准设计的诊断价值。

## 4. 主要贡献

- **概念层面：** 明确提出 URAM，将长期记忆从“用户画像”扩展为“用户侧记忆 + 用户条件化智能体侧记忆”的双域结构，强调记忆的关系特定性。
- **基准层面：** 构建对话优先、证据可追溯、覆盖记忆全生命周期的 DyadMem 基准，实现 Capture → Update → Recall → QA 的分阶段监督与评测。
- **方法层面：** 提供可复用的数据构建与质量控制流程，将“记忆变化计划”与“对话实现”分离，降低标注幻觉并提升可验证性。
- **评测层面：** 引入阶段化解耦指标与错误归因分析，弥补仅看最终答案的评估盲区。

## 5. 局限与展望

- **合成数据偏差：** 对话优先生成虽提升可控性与可追溯性，但仍可能偏离真实用户长期交互的自然分布，需在真实部署日志上进一步验证。
- **URAM 标注主观性：** “该智能体应如何与该用户协作”具有一定规范性与情境依赖性，不同标注者可能给出不同但合理的策略记忆，需研究多标注一致性与容忍度。
- **阶段解耦的边界：** 四阶段划分便于诊断，但真实系统中捕获、更新、检索与使用高度耦合，阶段指标与端到端表现之间仍需更系统的关联建模。
- **规模与成本：** 全流程标注与证据链维护成本较高，未来可探索半自动生成、主动学习与轻量人工审核相结合的方式扩展规模。
- **应用风险：** 关系特定记忆可能固化不当策略或放大历史偏差，需要在更新机制中引入遗忘、纠错与安全边界。
