## 摘要
大型语言模型（LLMs）难以回答跨越长交互历史的问题，其中相关证据可能分散在相隔遥远的会话中。现有记忆系统通常在观察到用户查询之前离线构建和维护复杂的记忆表示，这带来大量开销，并限制其根据查询特定信息需求调整记忆构建的能力。本文提出T²Mem，一个测试时记忆构建框架，将记忆构建推迟到推理阶段，并沿推理过程逐步构建记忆。具体而言，T²Mem离线提取轻量级的片段级元数据，以捕获关键事件和时间关联作为检索线索，同时保留指向原始交互的链接，以便重建跨片段的依赖关系。在测试时，LLM自适应地检索和组织元数据与原始交互，随着推理展开逐步构建查询特定的记忆。在LoCoMo和LongMemEval上的实验表明，T²Mem在不同骨干LLM上持续优于强基线，同时大幅降低记忆构建开销，证明了其有效性。进一步分析表明，将记忆构建推迟到推理阶段使记忆构建过程能够动态适应单个查询的信息需求。所有代码见https://github.com/OpenBMB/T2Mem。

## Abstract
Large Language Models (LLMs) struggle to answer questions over long interaction histories, where relevant evidence may be scattered across distant sessions. Existing memory systems typically construct and maintain sophisticated memory representations offline, before user queries are observed, incurring substantial overhead and limiting their ability to adapt memory construction to query-specific information needs. In this paper, we propose T$^2$Mem, a Test-Time Memory construction framework that defers memory construction to inference and progressively builds memory along the reasoning process. Specifically, T$^2$Mem extracts lightweight episode-level metadata offline to capture key events and temporal associations as retrieval cues, while retaining links to the original interactions to facilitate the reconstruction of dependencies across episodes. At test time, the LLM adaptively retrieves and organizes metadata and raw interactions, progressively constructing query-specific memory as reasoning unfolds. Experiments on LoCoMo and LongMemEval show the effectiveness of T$^2$Mem by consistently outperforming strong baselines across different backbone LLMs while substantially reducing the overhead of memory construction. Further analysis demonstrates that deferring memory construction to inference enables the memory construction process to dynamically adapt to the information needs of individual queries. All code is available at https://github.com/OpenBMB/T2Mem.

## 一、核心问题与研究动机

- **背景痛点**：LLM 在面对跨越很长交互历史的问题时表现受限——上下文窗口有限，且相关证据常常分散在相隔遥远的多个会话中（"lost in the middle" 问题）。
- **现有方案一（RAG）的缺陷**：以 chunk 为单位检索，把历史交互视为孤立片段，破坏时间上下文与跨轮次依赖关系，难以利用长历史中相互关联的信息。
- **现有方案二（离线记忆系统）的缺陷**：MemGPT/MemoryOS/LightMem/HiMem/EverMemOS/xMemory/AnchorMem 等在**查询到来之前**就构建、维护复杂的记忆表示（分层、图结构、主题聚合等）。由于构建是 query-agnostic 的，必须"预判"未来所有查询并尽量完整保留信息，导致**离线预处理与维护开销巨大**，且难以按具体查询的信息需求调整记忆形态。
- **现有方案三（已有 test-time 方法）的缺陷**：LazyMem、DeferMem 等把记忆构建推迟到推理时，但通常是"先一次性检索一批候选事实、再重组"，检索过程**刚性、单次**，无法获取"初始未检索到、但随着记忆构建推进才显现为必要"的证据。
- **论文的整体含义**：受 test-time scaling 与人类"联想式回忆（associative recall）"启发，论文主张**记忆不应是离线固定的表示，而应是推理过程中逐步演化的状态**——让 LLM 在推理中动态决定"下一步该激活并组织哪段历史信息"。

## 二、方法论：T²Mem 框架

### 1. 核心思想
将"记忆编排（memory orchestration）"从离线预处理**解耦**并推迟到测试时：离线只抽取**轻量片段级元数据**作为检索线索，保留回指原始会话的链接；推理时 LLM 在"推理—检索—蒸馏—再推理"的闭环中**渐进构建查询特定记忆**。

### 2. 关键技术细节

- **离线阶段：片段级元数据抽取**
  - 对每个会话 $s_k$ 用 LLM $\pi_{meta}$ 抽取半结构化元数据 $i_k$，形式化写作 $I=\pi_{meta}(s_1,\dots,s_n)$。
  - 元数据字段包括：`summary`（2–3 句概述）、`event_core`、`atomic_facts`（8–15 条原子事实）、`entities`、`temporal_clues`、`resolved_temporal_facts`（相对时间被锚定为显式日期）、`ongoing_threads`。
  - 每个条目保留源链接 $L(i_k)=s_k$，保证可回溯到原始对话（traceability）。
  - 与"摘要"或"图结构"表示相比，这种半结构化元数据同时提供结构线索（时间戳、事件）与语义线索。

- **测试时阶段：动态记忆构建（迭代轨迹）**
  - 推理轨迹 $\tau=\{(r_1,m_1,a_1),\dots,(r_T,m_T,a_T)\}$，其中 $r_t$ 为推理痕迹、$m_t$ 为新构建的记忆缓存、$a_t$ 为动作。
  - 每步：$(r_t,m_t,a_t)=\mathrm{LLM}(q, M_{t-1}, o_{t-1}, \mathcal{T})$，即输入查询、累积记忆、上一步观察与工具集，联合产出推理、记忆蒸馏与下一步动作。
  - 记忆累积：$M_t = M_{t-1}\oplus m_t$（拼接），初始 $M_0=\varnothing$；最终 $M_T=m_1\oplus\cdots\oplus m_T$，答案 $y=\mathrm{LLM}(q, M_T)$。
  - **初始观察**：$o_0=\mathrm{Top\text{-}k}(q,I)$，主实验 $k=5$。

- **工具集 $\mathcal{T}=\{\text{SearchMeta},\text{ReadRaw}\}$（自适应检索）**
  - `SearchMeta(q)`：从**未见过**的元数据中检索，$\mathrm{Top\text{-}k}(q, I\setminus I_{seen})$，每次 $k=1$；维护 $I_{seen}$ 避免重复读取。
  - `ReadRaw(k)`：沿源链接取回原始会话 $L(i_k)=s_k$，用于元数据不足以提供细粒度证据时。
  - 终止条件：LLM 判断记忆已满足信息需求并输出 `Answer`，或达到最大步数 $T_{max}=5$。

- **机制解读**：元数据负责"定位与关联"（跨片段依赖、时间线索），原始会话负责"细粒度证据恢复"，两者互补；每一步新激活的证据都会改变后续推理与检索方向，形成**闭环式按需构建**。

## 六、主要结论与发现

- **整体性能领先**：LoCoMo 平均 71.69（Qwen）/ 71.30（Gemma），优于最强基线 LazyMem（69.84 / 70.49）；LongMemEval 平均 84.80 / 85.20，显著优于 LightMem（77.40 / 77.60）。跨骨干一致提升，说明鲁棒性与可迁移性。
- **难点题型收益最大**：Multi-Hop（59.22）、Temporal（75.70）、LongMemEval 的 Temporal-Reasoning（84.96/85.71）提升明显——这类问题证据跨多会话分布，单次检索难以覆盖。
- **开销更低**：LoCoMo 上 T²Mem 约 8.77M tokens，低于 AnchorMem（10.94M）与 HiMem（11.06M），却取得更高准确率（71.69 vs 67.45 / 65.34）；说明"离线轻量元数据 + 测试时按需计算"的计算分配策略更高效。
- **记忆质量更高**：五个维度（尤其 Detail Preservation 与 Factual Correctness）均优于 LightMem、Search-o1，说明迭代构建能保留更细粒度证据并提升与标准答案的一致性。
- **测试时缩放有效**：随 token 预算增加，T²Mem 持续提升；Search-o1 缩放趋势较弱；Naive RAG 甚至随预算增加而下降——**关键不是加大算力，而是把算力转化为"有用的证据"**。
- **构建步数存在收益递减**：Single-Hop 在 1→3 步即饱和；Temporal / Open-Domain 可受益至 7 步；更深则收益减弱。
- **消融结论**：半结构化元数据 > 纯摘要 > 图结构；元数据与原始会话**互补**（去掉任一方均下降）；去掉 rollout 构建虽省 token（5,177 vs 8,765），但准确率明显下降（65.45 vs 71.69）。
- **定性发现（显著性分析）**：LightMem 检索到的记忆虽"高显著度且相关"，但只保留"her home country"这类未解析指代，无法回答具体国家；T²Mem 通过按查询需求累积事实，得到"Sweden"这类可回答的显式关联——说明**相关 ≠ 充分**，记忆需围绕查询的证据需求组织。

- **对元数据抽取质量高度敏感**：整个流程的检索入口是离线 LLM 抽取的半结构化元数据；若 `atomic_facts`、`resolved_temporal_facts` 等字段抽取不全或出错，后续测试时构建将建立在有偏的线索之上，且论文未系统评估抽取错误率的传播影响。
- **多步 agentic 推理带来延迟与工程复杂度**：每题最多 $T_{max}=5$ 步，每步均涉及 LLM 推理与工具调用，实际墙钟延迟可能显著高于单次 RAG；论文仅报告 token 消耗，未给出 latency、吞吐或成本数据，难以判断其在实际服务场景中的可用性。
- **离线预处理成本未完全消除**：虽然元数据“轻量”，但仍需对全量历史会话逐条调用 LLM 抽取，历史规模很大时，预处理开销与存储开销仍不可忽视；论文未与“完全不预处理”的纯在线方法做成本对照。
- **终止条件依赖 LLM 自判断**：以 LLM 判断“记忆已满足信息需求”作为终止信号，存在过早终止（漏检证据）或过晚终止（浪费预算）的风险；论文未分析终止判断的准确率或与 oracle 终止的差距。
- **评测覆盖有限**：仅两个 benchmark、两个骨干模型，且均为同族或相近规模模型；对更小模型（如 7B 级）、更大模型或非指令微调模型的表现未知，泛化性证据仍不充分。
- **LLM-as-judge 的潜在偏差**：全部采用 Qwen3.5-Plus 评判，且与 Qwen3.5-27B 骨干同族，可能存在系统性偏好；缺乏人工评测或双 judge 一致性检验，绝对分数的可信度需谨慎看待。
- **基线调优透明度不足**：离线记忆系统基线涉及大量超参（分层粒度、图构建阈值、更新策略等），论文未说明是否对每个基线做同等强度的调优，部分基线（如 LightMem 在 LongMemEval 子类上的极端低分）可能反映实现适配问题而非方法上限。
- **对噪声与冲突信息的处理讨论不足**：长历史中常存在过时信息、矛盾陈述与知识更新；论文虽在 LongMemEval 的 Knowledge-Update 类别上有结果，但未深入分析 T²Mem 如何在迭代构建中识别并消解冲突。
- **元数据字段设计的敏感性未验证**：`summary`、`event_core`、`atomic_facts` 等字段的数量与粒度（如 8–15 条原子事实）是否为最优，论文未做字段级消融或敏感性分析。
- **可复现性细节欠缺**：prompt 模板、元数据 schema 的完整定义、工具调用的具体格式等关键实现细节在总结所及范围内未充分展开，可能影响独立复现。

## 九、启示与展望

- **“记忆即过程”的范式价值**：T²Mem 的核心贡献不只是某个模块，而是把记忆构建从“预处理产物”重新定义为“推理轨迹的一部分”。这一视角可迁移到其他需要长上下文聚合的任务（如多文档问答、长程对话代理、代码库理解），提示我们重新审视“离线索引 vs 在线计算”的成本分配。
- **计算分配的再平衡**：论文表明，在总 token 预算可比甚至更低的情况下，将计算从离线预处理转移到测试时按需构建，能获得更高准确率。这为资源受限场景提供了一条务实路径：与其维护昂贵的全局记忆结构，不如保留轻量线索、把重计算留给真正需要的查询。
- **检索与推理的深度耦合**：`SearchMeta` 与 `ReadRaw` 的分工、$I_{seen}$ 去重、基于记忆状态的下一步决策，构成一个可终止的闭环。未来可探索用强化学习或偏好优化来学习“何时检索、检索什么、何时停止”的策略，替代当前基于提示的自判断。
- **表示形式的混合设计**：消融显示半结构化元数据优于纯摘要与图结构，说明“结构线索+语义线索”的混合表示在检索定位与证据恢复之间取得了较好平衡。后续可研究自适应表示——根据查询类型动态选择元数据粒度或切换表示形式。
- **成本-精度权衡的精细化**：论文的 token 预算缩放实验提示存在收益递减与任务依赖的最优步数。未来可引入显式的预算感知机制（budget-aware stopping），针对不同题型动态分配构建步数，而非统一 $T_{max}$。
- **评测方法的改进空间**：记忆系统的评测亟需更细粒度、更抗偏差的协议，例如人工校验子集、多 judge 交叉验证、以及针对“证据充分性”而非仅“答案正确性”的指标，以更准确地区分“检索到相关片段”与“构建出可回答的记忆”。

## 十、总体评价

T²Mem 是一篇问题定位清晰、方法设计自洽、实验较为扎实的论文。其最大贡献在于提出并验证了“测试时按需构建记忆”这一范式：通过离线轻量元数据保留可回溯线索，在线以闭环 agentic 流程逐步累积查询特定记忆，在 LoCoMo 与 LongMemEval 上以更低或可比的开销取得领先性能，并通过表示形式、信息源、构建机制三组消融与多维分析支撑了设计合理性。其主要不足在于对元数据抽取质量的依赖、多步推理的延迟与工程成本未量化、评测覆盖与 judge 偏差风险，以及部分实现细节的透明度不足。总体而言，该工作为长历史记忆管理提供了一个有前景的方向，其“相关≠充分”“计算应转化为有用证据”的洞察对后续研究具有启发意义。
