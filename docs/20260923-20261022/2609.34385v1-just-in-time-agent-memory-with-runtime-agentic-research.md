## 摘要
记忆对AI智能体至关重要。许多现有智能体记忆系统采用提前（Ahead-of-Time，AOT）设计，在特定请求到达之前构建记忆。虽然这降低了在线服务成本，但这种与请求无关的记忆构建可能会丢弃后续变得重要的细粒度信息。为解决这一局限，我们提出即时智能体记忆（Just-In-Time Agent Memory，JAM），一个可在运行时进行查询条件化上下文构建的可训练框架。记忆器（Memorizer）将完整原始历史保存在带有紧凑导航摘要的分层页面存储中，而研究器（Researcher）则针对每个请求迭代地检索、检查和整合证据。为训练这些记忆使用行为，我们引入Memory-Gym，一个基于证据的数据合成流水线，覆盖六个领域中的九种任务类型，并通过经过验证的轨迹监督微调，随后采用提示引导的组相对策略优化（Hint-guided Group Relative Policy Optimization）来优化研究器。我们在智能体记忆和长上下文处理的多种基准上验证了JAM的有效性，其任务性能优于AOT式记忆系统，同时比先前训练过的智能体记忆方法显著更高效。为支持可复现性和未来研究，我们在https://github.com/VectorSpaceLab/general-agentic-memory发布了匿名化源代码。

## Abstract
Memory is critical for AI agents. Many existing agent-memory systems follow an Ahead-of-Time (AOT) design, constructing memory before a specific request arrives. While this reduces online serving cost, such request-agnostic memory construction can discard fine-grained information that later becomes important. To address this limitation, we propose Just-In-Time Agent Memory (JAM), a trainable framework for query-conditioned context construction at runtime. A Memorizer preserves complete raw histories in a hierarchical page-store with compact navigational summaries, while a Researcher iteratively retrieves, inspects, and integrates evidence for each request. To train these memory-use behaviors, we introduce Memory-Gym, an evidence-grounded data synthesis pipeline covering nine task types across six domains, and optimize the Researcher through verified-trajectory supervised fine-tuning followed by Hint-guided Group Relative Policy Optimization. We demonstrate the effectiveness of JAM across a variety of benchmarks on agent memory and long-context processing, where it achieves stronger task performance than AOT-style memory systems while remaining substantially more efficient than prior trained agentic memory approaches. To support reproducibility and future research, we release our anonymized source code at https://github.com/VectorSpaceLab/general-agentic-memory.

## 1. 核心问题与研究动机

- **背景**：AI Agent 在深度研究、软件工程等长流程任务中会持续产生大量观察、推理轨迹与交互记录，历史呈"长、演化、跨会话依赖"的特点，记忆系统因此成为构建下游上下文的关键组件。
- **现有范式的问题**：主流 Agent 记忆系统采用 **Ahead-of-Time（AOT）** 设计，即在具体请求到达前就把历史压缩/组织成摘要、记忆笔记或分层存储。这种做法虽然降低了在线服务成本，但属于**请求无关（request-agnostic）** 的预处理：
  - 会丢弃后续才变得重要的细粒度信息与跨会话依赖；
  - 当证据分散在庞大且随时间演化的历史中时，固定的检索或摘要管线难以拼装出查询特定的上下文。
- **核心主张**：记忆不应只被视为"存储过去信息"，而应被视为**在运行时构建与查询相关的上下文**。论文据此提出 **Just-In-Time（JIT）** 范式，将离线记忆组织与在线记忆构建解耦。
- **整体含义**：JAM 把"记忆使用"显式建模为一个可追踪、可训练的智能体研究过程（思考—工具调用—充分性判断），从而在效果与效率之间取得新的平衡点。

## 2. 方法论

### 2.1 核心思想

- 双组件框架：
  - **Memorizer（离线）**：完整保留原始历史，构建带导航摘要的分层页面库（hierarchical workspace）；
  - **Researcher（在线）**：针对每个请求迭代检索、检查、整合证据，产出查询条件化的精简上下文。
- 设计原则：**原始证据不丢失 + 轻量导航不膨胀 + 运行时按需深挖**。

### 2.2 问题形式化

- 历史表示为按时间排序的会话序列 \(H=\{s_1,\dots,s_T\}\)，记忆系统对请求 \(q\) 输出上下文 \(c^* \leftarrow \text{Memory}(q,H)\)。
- 优化目标为"先保证下游性能最优、再在其中取最小上下文"：
  - \(C^*(q,H)=\arg\max_{c\in C(H)} \text{Perf}_A(q,c)\)，再 \(c^*=\arg\min_{c\in C^*(q,H)} |c|\)。
- AOT 用请求无关的预压缩近似 \(c^*\)，JIT 则在运行时以 \(q\) 为条件构造 \(c^*\)。

### 2.3 Memorizer：分层工作区构建

- 两个轻量操作：
  - **memorize**：\(\text{memorize}(s_i, W_{<i}) \to \mu_i\)，为每个会话生成简洁 memo，作为导航描述符；
  - **write**：\(\text{write}(s_i,\mu_i,W_{<i}) \to W_{\le i}\)，把原始会话存为源文件，并依据 memo 将语义相关会话归入一致目录。
- 每个目录维护由子文件/子目录 memo 汇总而成的 **README**，形成该区域的紧凑导航摘要。
- 支持批量构建与新增会话的增量更新；原始文件保持完整、路径可追溯。

### 2.4 Researcher：运行时智能体研究

- 工具空间 \(T=\{\text{open}(p),\ \text{search}(\kappa),\ \text{browse}(p,\kappa)\}\)：
  - open 读取目录 README 与列表；
  - search 用 **BM25 + 稠密向量** 做混合检索；
  - browse 读取指定文件并抽取与查询相关的信息。
- 迭代"思考—探索—反思"流程：
  - 第 \(i\) 步依据 \(q\) 与轨迹 \(h_{i-1}\) 采样动作集 \(A_i=\{a_i^1,\dots,a_i^{K_i}\}\sim\pi_\theta(\cdot\mid q,h_{i-1})\)；
  - 执行得到观测 \(O_i=\text{Exec}(A_i,W)\)，更新 \(h_i=h_{i-1}\oplus(A_i,O_i)\)；
  - **Reflect** 隐式判断信息是否充分 \(y_i=\text{Reflect}_\theta(q,h_i)\)，充分或达到动作预算即停止；
  - **Finalize** 生成最终上下文 \(c^*=\text{Finalize}_\theta(q,h_T)\)，保留请求相关信息与来源出处；预算耗尽时对已收集证据做尽力而为的总结。

### 2.5 Memory-Gym：证据锚定的数据合成管线

- **任务分类（3 族 9 类）**：
  - 单跳定位：属性抽取、概念解释、条件定位；
  - 多跳连接：比较、溯源追踪、交集选择；
  - 多会话摘要：状态演化、集合枚举、聚合摘要。
