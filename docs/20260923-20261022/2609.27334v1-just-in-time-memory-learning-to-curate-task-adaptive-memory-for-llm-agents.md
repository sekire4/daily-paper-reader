## 摘要
智能体记忆系统会复用过去经验以提升未来表现，但大多数现有设计在写入时整理记忆：一旦任务完成，其轨迹就被蒸馏为一个固定产物，例如反思、工作流、技能或推理策略，之后通过相似度进行检索。这迫使系统在尚不知道未来查询的情况下决定什么值得记住，从而不可逆地丢弃信息，并生成一个必须服务于许多潜在下游任务的、与查询无关的摘要。学习这样的写入时整理器也很困难，因为某个存储决策的价值可能只有在相关查询到来时才会显现，而该查询可能在许多任务之后才出现，这构成了长时程信用分配问题。我们则保留原始轨迹，并将整理推迟到读取时，即当前任务已知时。给定检索到的轨迹和新任务，记忆整理器会合成一个紧凑、任务自适应且针对即时需求定制的内容。由于该内容在同一任务上被消费，整理器可以直接根据即时任务成功进行训练，从而避免延迟效用信号，也无需人为地将相关任务分组。在 ALFWorld、WebShop 和 τ^2-bench 上，我们的即时记忆（JitMem）始终优于无记忆智能体以及启发式和学习式写入时记忆方法，分别比最强基线提升了 16.2、16.3 和 3.9 个绝对成功率百分点。值得注意的是，即使未经训练的整理器也已能与这些基线相当或超过它们，表明任务自适应的读取时整理本身就是主要增益来源；进一步训练整理器会叠加提升效果。

## Abstract
Agentic memory systems reuse past experience to improve future performance, yet most existing designs curate memory at write time: once a task is completed, its trajectory is distilled into a fixed artifact, such as a reflection, workflow, skill, or reasoning strategy, that is later retrieved by similarity. This forces the system to decide what is worth remembering before the future query is known, irreversibly discarding information and producing a query-independent summary that must serve many possible downstream tasks. Learning such a write-time curator is also difficult because the value of a storage decision may only become apparent when a relevant query arrives, potentially many tasks later, creating a long-horizon credit-assignment problem. We instead retain raw trajectories and defer curation until read time, when the current task is known. Given the retrieved traces and the new task, a memory curator synthesizes a compact, task-adaptive payload tailored to the immediate need. Because this payload is consumed on the same task, the curator can be trained directly from immediate task success, avoiding delayed utility signals and the need to artificially group related tasks. Across ALFWorld, WebShop, and $τ^2$-bench, our Just-in-Time Memory (JitMem) consistently outperforms no-memory agents as well as heuristic and learned write-time memory methods, improving over the strongest baseline by 16.2, 16.3, and 3.9 absolute success-rate points, respectively. Notably, even an untrained curator is already competitive with or surpasses these baselines, showing that task-adaptive read-time curation itself is a major source of the gain; training the curator further compounds the improvement.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地需要连续解决一系列任务，而非孤立问题；复用自身过往经验（agentic memory）是提升长期表现的关键资源。
- **现有主流范式的共同缺陷——写入时整理（write-time curation）**：任务完成后立即将轨迹蒸馏为固定产物（反思、洞察、工作流、可执行技能、推理策略等），推理时按相似度检索。这带来两个结构性代价：
  - **信息丢失过早且不可逆**：一旦细节被丢弃，后续依赖该细节的任务无法恢复。
  - **查询无关的单一摘要**：同一轨迹对不同下游任务可能有不同用途（如“状态转移”模式 vs “物体放置”策略），但写入时只能押注一种框架。
- **学习层面的困难**：写入决策的价值只有在未来相关查询到来时才显现，可能相隔许多任务，构成**长时程信用分配问题**；已有工作（如 SkillOS）不得不人为将相关任务分组以制造延迟学习信号。
- **核心主张**：将整理推迟到**读取时（read time）**，即当前任务已知时，“即时（just-in-time）”地从原始轨迹中合成任务自适应记忆载荷。这同时解决了信息损失与信用分配两个问题。

## 2. 方法论

### 2.1 核心思想
- 记忆库只存储**未经抽象的原始轨迹**，写入时不丢弃任何信息；读取时由**记忆策展器（curator）** 联合阅读“当前任务 + 检索到的原始轨迹”，生成紧凑、任务条件化的自然语言载荷注入执行器上下文。
- 同一轨迹可为不同任务产出不同载荷——这是写入时方法无法提供的性质。作者将其类比认知科学中“情节记忆是重构性的而非重放的”（Schacter & Addis, 2007）。

### 2.2 系统组成（四个组件，仅策展器可训练）
1. **记忆库 M**：每条记录为完整轨迹 ξ=(x, o₁, a₁, …, oₙ, aₙ)，不做摘要/反思/技能抽象。
2. **检索器 R**：BM25，仅对**任务描述**（而非轨迹内容）做检索，取 top-k（主实验 k=3），与轨迹长度解耦、轻量且不训练。
3. **记忆策展器 π_φ**：输入为“当前任务 xₜ + k 条原始轨迹”的结构化提示，输出紧凑载荷 pₜ（识别最相关经验、抽取有效策略、给出针对本任务的具体指导）。载荷是**临时的**，不写回记忆库。
4. **冻结执行器 π_L**：预训练 LLM，训练全程不更新；载荷前置到提示中，执行器从策展载荷而非原始轨迹获取指导。

### 2.3 记忆写入与质量门控
- 部署时无真实成功标签，故用**执行器自身作为 LLM-as-judge** 判断任务是否成功，仅将判定成功的轨迹追加进库（保持检索到的示范为正例）。
- 消融对比了“存储全部轨迹并标注成功/失败”的做法。

### 2.4 训练流程（GRPO）
- 对每个采样训练任务 xₜ：检索轨迹 ξ̂ₜ → 策展器生成 G=8 个候选载荷 → 冻结执行器逐一尝试 → 返回**真实任务奖励** rₜ（ALFWorld/τ²-bench 为二元成功，WebShop 为连续分数）。

- 损失：L_GRPO = −(1/G) Σ Âᵢ · log π_φ(pᵢ | xₜ, ξ̂ₜ)，无价值网络。
- **关键性质**：奖励是同一任务所生成载荷的直接函数，**策展动作与奖励的时间间隔为零**，信用分配退化为单步，无需任务分组或延迟回报机制。
- **固定训练库**：用基座执行器（无策展器）在训练集跑一遍，按真实标签保留成功轨迹并全程固定，以保证训练稳定可复现（代价是与测试时“在线增长的库”存在轻微分布偏移）。

### 2.5 评测协议
- 测试时记忆库默认**从空开始**，随任务解决在线增长，存在自然冷启动效应；不继承训练库。
- 为效率采用**批量流式协议**：同批任务共享同一记忆库状态，批后更新；任务顺序与批组成会影响结果，故报告多种随机顺序下的均值±标准差。
- 任务成功由 benchmark 真实校验器判定；记忆入库判定用 LLM judge，避免真实标签泄漏进库。

## 6. 主要结论与发现

1. **读取时策展优于写入时策展（同零样本策展器下）**：如 ALFWorld + Qwen3-8B，JitMem-base 60.5 vs ReasoningBank 55.7、SkillOS-base 53.1；WebShop + Gemini 61.0 vs 40.2/41.0。
2. **学习式读取时策展显著优于学习式写入时策展**：ALFWorld 77.4 vs 61.2（+16.2），WebShop 32.8 vs 16.5（+16.3）；Gemini 执行器下 +6.0 / +9.2；τ²-bench 宏平均 +3.0、微平均 +3.9（Telecom 域 +11.0）。
3. **增益主要来自读取时任务自适应，而非策展器模型强度**：JitMem-base（Qwen3-8B 策展）在 ALFWorld + GPT-5.4 上 79.3，已超过使用 GPT-5.4 策展的 ReasoningBank（77.9）与 SkillOS-gpt（70.0）。
4. **训练可跨执行器迁移**：仅用 Qwen3-8B 执行器训练的策展器迁移到 GPT-5.4 后，与直接用 GPT-5.4 训练仅差 1.4 SR，说明学到的是通用策展策略而非执行器特异模式。
5. **更紧凑高效**：相对写入时方法，输入 token 减少 50.3%–56.3%，执行步数减少 28.4%–31.4%；JitMem-base 仅比无记忆多 1.9K 输入 token（ReasoningBank 10.7K、SkillOS-base 13.4K）。
6. **消融结论**：
   - 任务条件化是核心（训练后去掉它掉 11.4/10.4 SR）；
   - 成功轨迹过滤优于“全存 + 标注”（掉 1.5–3.4）；
   - 写入时蒸馏损伤最大（WebShop 掉 6.8–8.2）；
   - **强制检索为空时性能大幅下降（−14.8 / −15.2）**，证明 RL 学到的是“蒸馏检索经验”，而非仅靠参数知识；
   - 分阶段库刷新增益有限（最多 +2.8），测试库热启动几乎无效——说明默认设置已足够。
7. **定性发现**：同一轨迹在“把热土豆放冰箱”与“把报纸放沙发”两个任务中被策展成不同重点；RL 训练后策展器能自发产出**环境特定的程序性语义**（如“先移动到台灯，再用台灯检查碗”），而这些并未写在提示中。
8. **适用边界**：τ²-bench 的 Airline/Retail 域上所有记忆方法均未显著超越无记忆，说明读取时策展在需要**综合程序性指导**（如 Telecom 多步策略核验）时价值最大，而非简单事实检索。

## 7. 优点

- **概念层面的清晰重构**：把“何时整理记忆”提炼为一个独立且可检验的设计维度，论证链条（信息损失 + 信用分配）简洁有力。
- **训练信号设计优雅**：读取时策展使奖励与动作同任务、零时间差，直接消除任务分组、延迟回报、内容质量辅助奖励等脚手架，训练更简单且稳定。
- **策展器与执行器解耦**：单一策展器可服务多执行器且无需重训，具备实际部署价值；也使记忆模块可被隔离评测。
- **无损存储 + 质量门控**的组合经消融验证各自独立贡献。
- **效率收益明确**：不仅更准，还更省 token、更少步数，具备实用说服力。
- **实验严谨性细节到位**：基线复现校准（刻意偏保守）、多随机顺序、同检索器、-base 变体控制容量、检索数量敏感性、训练曲线。
- **定性证据有说服力**：用同输入不同任务的载荷对比，直接可视化“任务自适应”这一核心主张。

## 8. 不足与局限

- **检索器过简**：BM25 仅基于任务描述，库规模增大、任务多样时可能成为瓶颈；作者亦承认此点，未探索学习式/稠密检索。
- **额外开销**：每个任务多一次 LLM 策展调用，带来延迟与成本；论文未报告端到端 wall-clock 与 API 成本对比。
- **载荷格式手工设计且按 benchmark 定制**：三套策展提示与执行提示各自不同，泛化到新领域需人工重设计，削弱“通用框架”的说服力。
- **τ²-bench 缺训练验证**：

- **τ²-bench 缺训练验证**：由于缺少标准训练集，该场景只评测了免训练变体（JitMem-base 与提示式策展器），因此“学习式读取时策展”在多轮工具调用对话上的收益尚未被直接验证；表 2 中的增益只能说明“读取时整理”这一结构性优势，不能说明 RL 训练带来的额外提升。
- **训练与测试的记忆状态不一致**：训练时使用由基座执行器一次性生成、全程固定的成功轨迹库，测试时则是从空库开始在线增长的库。作者用“热启动”消融说明影响有限，但严格说，策展器在训练中见到的检索上下文分布与部署时并不相同，尤其在冷启动早期（库中轨迹少、质量参差）时，策展器的行为缺少直接证据。
- **评测协议偏离严格在线**：批量流式协议让同批任务共享同一库状态，批后才更新，任务顺序与批组成会引入方差；论文以多次随机顺序的均值±标准差缓解，但未做显著性检验，3–4 次重复下部分结论（如 τ²-bench Airline/Retail 上各方法差距很小）的稳健性存疑。
- **成功判定缺少校验**：入库门控依赖执行器自身作 LLM-as-judge，与执行器同源，存在自我偏好与系统性误判风险；论文未报告 judge 的判定准确率、与真实校验器的一致性，也未做人工抽检，因此“成功过滤优于全存+标注”这一消融结论的机制解释仍不够充分。
- **记忆库只增不减**：没有遗忘、去重、冲突消解或时效性衰减机制。库规模长期增长后，BM25 基于任务描述的检索精度、以及 k=3 的固定截断是否仍然合适，论文只在 k∈{3,5} 上做了小范围敏感性分析，未模拟大规模长期运行。
- **策展器需按场景分别训练**：ALFWorld 与 WebShop 各自训练一个策展器，跨 benchmark 的迁移未验证（只验证了跨执行器迁移）。加上载荷格式与提示按 benchmark 手工定制，方法的“通用性”目前是框架层面的，而非开箱即用的。
- **成本报告不完整**：只给出训练时长，未报告推理阶段每任务的额外策展调用延迟、端到端 wall-clock，以及使用 GPT-5.4 / Gemini-2.5-Pro 作策展器时的 API 成本，削弱了效率优势的实践说服力（token 与步数收益是明确的，但延迟与费用未量化）。
- **基线对等性存在残余不确定性**：SkillOS 原文依赖任务分组与复合奖励，作者以自复现版本对比；各基线的最优超参是否被充分搜索、提示是否被公平调优，论文仅以“固定检索器 + 同基座 -base 变体”作控制，仍不能完全排除基线欠调的可能（尽管其保守校准方向降低了这一风险）。

## 9. 可借鉴之处

- **把“何时整理”显式化为设计维度**：将记忆系统的设计空间拆为“写什么 / 何时写 / 何时读 / 读什么”，并给出可检验的对照，这种问题重构方式本身可迁移到工具学习、提示优化、经验回放等方向。
- **零时间差信用分配**：让可训练模块的输出直接作用于同一任务的奖励，从而把长时程问题退化为单步 bandit 问题，是绕开延迟回报的通用技巧，适用于任何“中间产物影响下游表现”的场景（如检索器、规划器、摘要器）。
- **无损存储 + 读取时压缩**：以“原始轨迹全量保留、按需合成”替代“写入时蒸馏”，在存储成本可接受时是提升信息利用率的一种低成本改造，可直接叠加在现有 RAG 式记忆系统上。
- **策展器与执行器解耦**：模块化设计使记忆策略可独立训练、跨模型复用，也为记忆模块的隔离评测提供了可行接口。
- **保守的基线校准实践**：刻意把 no-memory 基线调到等于或低于原文报告值，使增益被低估而非高估，是值得效仿的实验伦理做法。

## 10. 总体评价

这是一篇问题定位清晰、论证链条简洁的实证型论文。其核心贡献不在于新模型或新架构，而在于提出并验证了一个被忽视的设计维度——记忆整理应放在读取时而非写入时，并用“信息损失 + 信用分配”两条理由给出了机制解释，再以跨 3 个 benchmark、3 个执行器、多类基线的实验支撑。方法本身足够简单（BM25 检索 + 冻结执行器 + GRPO 训练的小策展器），却在同条件下稳定优于写入时基线，并附带 token 与步数上的效率收益，工程可复现性较好。

其局限也较明确：检索器过简、载荷格式手工定制、τ²-bench 缺训练验证、库无遗忘机制、成本报告不完整，以及评测协议的在线性与统计严谨性仍有提升空间。因此更准确的定位是：**它确立了一个有价值的设计原则并给出了可信的首个系统性证据，而非一个已可直接部署的完备记忆系统**。后续工作若要推进，较自然的方向包括学习式检索与库管理、跨场景统一的策展器、载荷的结构化与冲突消解，以及在严格在线协议下的大规模长期评测。
