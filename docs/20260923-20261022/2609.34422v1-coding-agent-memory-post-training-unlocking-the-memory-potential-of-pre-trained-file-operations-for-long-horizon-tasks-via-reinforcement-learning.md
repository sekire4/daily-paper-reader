## 摘要
语言模型智能体越来越多地处理长时程任务，其交互历史超出模型的活跃上下文。近期工作开始使用强化学习将记忆控制纳入策略的一部分，通常依赖相对短时程的领域特定训练环境中的预定义记忆工具。这种设置将学到的记忆行为绑定到基础模型预训练之外的环境特定接口，必须从头学习，因此即使经过后训练，智能体在长时程任务中也难以使用记忆。为解决这些限制，我们引入编码智能体记忆 Gym（CAMG），一套涵盖 Shop、Coding、DeepResearch 和 AutoResearch 的长时程智能体强化学习环境。除每个环境的原生任务接口外，CAMG 提供可执行 shell 访问和回合持久工作区，使智能体能够在整个回合中创建、修改、搜索和复用文件作为记忆。我们还引入 CAMG-RL，它使用全异步 PPO 在所有四个环境中联合训练单一策略，直接从下游任务奖励中学习这种基于文件的记忆行为，并且我们从匹配规模的 Qwen3.5 模型训练了 CAMG-RL-4B 和 CAMG-RL-9B。在 SWE-bench Verified 和 MLE-bench Lite 上，CAMG-RL-4B 和 CAMG-RL-9B 分别与 Qwen3.5-35B-A3B 和 Qwen3.5-122B-A10B 具有竞争力。

## Abstract
Language-model agents increasingly tackle long-horizon tasks whose interaction histories exceed the model's active context. Recent work has begun to use reinforcement learning to make memory control part of the policy, often relying on predefined memory tools within domain-specific training environments of relatively short horizons. This setup ties learned memory behavior to environment-specific interfaces that lie outside the base model's pre-training and must be learned from scratch, so even after post-training, agents struggle to use memory in long-horizon tasks. To address these limitations, we introduce Coding Agent Memory Gym (CAMG), a suite of long-horizon agentic-RL environments spanning Shop, Coding, DeepResearch, and AutoResearch. Alongside each environment's native task interface, CAMG provides executable shell access and an episode-persistent workspace, enabling agents to create, revise, search, and reuse files as memory throughout an episode. We also introduce CAMG-RL, which trains a single policy jointly across all four environments with fully asynchronous PPO, learning this file-based memory behavior directly from downstream task reward, and we train CAMG-RL-4B and CAMG-RL-9B from Qwen3.5 models of matching size. On SWE-bench Verified and MLE-bench Lite, CAMG-RL-4B and CAMG-RL-9B are competitive with Qwen3.5-35B-A3B and Qwen3.5-122B-A10B, respectively.

## 1. 核心问题与研究动机

- **背景**：语言模型智能体越来越多地处理长时程任务（多轮工具调用、环境交互），交互历史不断累积，早期关键信息会滑出模型活跃上下文。例如编码智能体需要回忆"此前某次修复为何被拒绝"，但该对话已不在 prompt 中。
- **现有做法及缺陷**：近期工作用强化学习把"记忆控制"纳入策略，但通常：
  - 依赖**预定义的专用记忆工具**（如 LTM/STM 工具、外部存储操作）；
  - 训练环境**领域单一、时程较短**。
  - 结果是记忆行为被绑定在基础模型预训练分布之外的"环境特定接口"上，必须从零学起；即使后训练后，智能体在长时程任务中仍难以用好记忆。
- **核心开放问题**：能否在**代码预训练**的基础上，通过强化学习直接激发编码智能体"保留并复用超出上下文的信息"的能力？
- **整体含义**：论文主张不引入新记忆工具，而是把智能体**本来就熟悉的文件系统操作**（创建、修改、搜索、读取文件）当作记忆载体，用下游任务奖励端到端训练，从而"解锁"预训练中已有的文件操作先验。

## 2. 方法论

### 2.1 CAMG：四类长时程 RL 环境

- 覆盖四个任务族：
  - **Shop**：6 次关联购物会话，会话间清空对话记录，后续购买依赖此前偏好/约束（720 个 WebShop 产品）。
  - **Coding**：SWE-smith 仓库修复任务，诊断、改码、测试证据可跨多个上下文（11,218 任务 / 93 仓库）。
  - **DeepResearch**：LiteResearcher 的 Search–Visit–Answer，需跨上下文累积证据（26,597 任务）。
  - **AutoResearch**：OpenMLE 任务包，迭代开发 ML 方案并提交（931 任务 / 804 家族）。
- **统一接口**：每个环境保留原生任务接口，同时提供：
  - 单一 `shell_command` 可执行文件系统动作（遵循 mini-swe-agent 的极简 shell 接口）；
  - **回合持久工作区**（episode-persistent workspace），跨上下文替换保持挂载；
  - 只有 `.agent_memory/` 下的普通文件计为"策略记忆"。
  - 动作空间：`A_d = A_d^task ∪ A_fs`，一次 shell 命令可同时产生任务效果与文件效果。

### 2.2 上下文替换机制（关键设计）

- 环境在上下文压力或子回合边界触发替换，并提示策略用一次普通文件动作写入 `.agent_memory/CONTINUATION.md`（上限 8,192 字节）。
- **是否合规由策略自行决定**；环境从不代写或清空该文件。
- 只有验证该文件被策略动作改为非空普通文件后，环境才替换活跃消息历史；替换后**不自动注入文件内容**，策略需通过后续普通文件读取自行恢复状态。
- 写检查点本身消耗一个动作槽，并作为一个正常 RL 步骤被采样与训练。

### 2.3 CAMG-RL：训练算法

- **核心思想**：把任务交互与文件系统操作放在**同一条动作轨迹**上，用下游任务奖励经 GAE 传播，对包括策略生成的文件内容在内的所有 token 做 PPO 优化。
- **联合目标**：四个环境均匀采样，`J_CAMG-RL(θ) = (1/|D|) Σ_{d∈D} J_d(θ)`，`|D|=4`。
- **双粒度 PPO**：
  - **响应级优势估计**（每个完整响应一个 advantage，稳定）；
  - **token 级比率裁剪**（每个 token 一个 ratio，更新细粒度）。
  - 对比：Turn-PPO 全 turn 级（粗）、SAO 全 token 级（高方差）。
- **信用分配**：
  - 对响应步做 GAE：`δ_t = r_{d,t} + γ(1-e_t) V̄_{t+1} − V̄_t`，`Â_t = δ_t + γλ(1-e_t) Â_{t+1}`，取 `γ=λ=1`；
  - 同一响应的所有 token 共享同一响应级优势；
  - 优势按环境做 token 数加权与掩码标准化；critic 只看到策略可见上下文（不偷看隐藏状态或未读文件）。
- **完全异步 PPO**：
  - rollout worker 持续采样，完成 episode 入持久队列；learner 按最早派发顺序取 64 个 episode 更新一次 actor/critic，并发布新权重；
  - 队列吸收变长 episode 的完成时间差异，避免等待最慢 episode；
  - 每个 episode 最多用于一次学习更新；记录 policy-version lag、clip fraction 等优化健康指标。
- **奖励设计**：稀疏、基于成功。Shop 分段奖励（末次购买权重更高，错误 −0.01）；Coding 仅隐藏测试通过 +1（检查点写失败 −0.1）；DeepResearch 语义判官接受 +1（无效动作 −0.02）；AutoResearch 方向归一化分数 +0.1 首次提交里程碑，另有首次成功执行 +0.05、首次验证指标 +0.1。

## 6. 主要结论与发现

- **CAMG 测试集**：CAMG-RL 平均成功率 **54.4%**，高于 CompactionRL（48.0%）、AgeMem（25.3%）、Mem0（19.7%）、Letta Code（17.8%）和冻结基座（17.4%）；优势主要来自 Coding 与 AutoResearch，Shop 两者接近饱和（97.1 vs 97.5），DeepResearch 未显著分离。
- **外部迁移**：
  - SWE-bench Verified：CAMG-RL-4B **15.8%**（≈ Qwen3.5-35B-A3B 的 15.6%），CAMG-RL-9B **27.6%**（超过冻结 122B-A10B 的 22.0%）；
  - MLE-bench Lite：4.5% 与 9.1%，分别匹配 9B/27B/35B-A3B 与 122B-A10B。
- **预训练先验是关键**：冻结基座对文件记忆动作的 surprisal 仅 0.076–1.193 nats/token，而 AgeMem 六个专用工具在每个意图上都更"意外"；改名 nonce 控制、native 调用格式控制、删除 shell 文档控制均表明**先验偏向文件动作本身，而非工具名或调用格式**。
- **训练是"激活"而非"重造"**：训练后完整记忆链从首季度 8.0% 升至 20.9%，而策略相对基座的 KL 仅 0.094 nats/token、权重相对变化 0.22%，说明小幅策略移动即把既有偏好转化为可用记忆行为；AgeMem 在 261,941 个响应中仅 53 次尝试、0 次完整链。
- **记忆内容具因果作用**：清空记忆内容平均降 14.1 点，移植错配内容降 11.5 点，四个环境均下降。
- **消融结论**：去掉 memory-action 梯度平均降至 21.1%（接近冻结基座）；仅保留 continuation 文件重训为 41.8%；token 级估计控制降至 50.1%；单 `apply_patch` 工具变体降至 48.6% 且解析失败率升至 11.7%。
- **Coding 失败

- **Coding 失败**主要不是"不会改代码"，而是**记忆链在跨上下文边界处断裂**：典型模式包括（i）上下文替换前未写出可用检查点，导致后续回合丢失已诊断的根因与已尝试的补丁；（ii）检查点写出但内容过于笼统（只记录"正在修复 X"而缺少文件路径、失败测试名、已排除的假设），恢复后无法据此继续；（iii）恢复阶段未主动读取 `.agent_memory/`，或读取后未把旧证据与新观察合并，重复走已失败的路径；（iv）修复本身未通过隐藏测试，属于纯代码能力上限而非记忆问题。论文的训练动态分析显示，CAMG-RL 主要提升的是"store–retrieve–use"完整链的比例，说明其收益集中在把已有代码能力**跨上下文接续**起来，而非提升单回合内的代码生成质量；这也解释了为何 Coding 与 AutoResearch 获益最大——二者都需要跨多个上下文累积诊断证据，而 Shop 的任务结构更接近单会话内可完成，DeepResearch 则受限于语义判官的判定噪声与检索质量，记忆增益被其他瓶颈掩盖。

## 7. 局限性

- **基座与规模单一**：正式训练集中于 Qwen3.5-4B，另有 9B 规模验证，但未覆盖其他模型家族（如 Llama、Gemma 系列）或 MoE 架构的系统对比。因此"文件系统接口先验可被 RL 激活"这一核心论断的**普适性仍待验证**——若某基座在预训练中文件操作暴露不足，该方法的优势可能显著缩水。
- **训练预算有限**：200 次 learner 更新、12,800 episodes、约 120–140 GPU-hours，属于"小规模验证"量级。曲线是否在更长训练下继续上升、是否会出现记忆行为的过拟合或退化（例如退化为"总是写检查点"的形式化行为），论文未给出长程训练证据。
- **测试集为自建**：CAMG 测试集虽做了产品/仓库/问题组/任务家族的隔离划分，但任务构造方式与训练环境同源，存在**分布同质性**风险；两个外部 benchmark 缓解了这一问题，但 SWE-bench Verified 与 MLE-bench Lite 的样本量（500 / 22）导致单次评估的置信区间较宽，迁移结论的精度有限。
- **DeepResearch 未显著分离**：四个环境中有一个未能显示统计显著优势，说明方法并非在所有长时程形态上都有效；论文对此的解释（判官噪声、检索瓶颈）合理但缺少直接实验分离这两种因素。
- **Shop 接近饱和**：97.1 vs 97.5 的对比已无区分度，该环境实际上主要作为"不损害原有能力"的对照组，而非能力证明。
- **记忆容量与格式约束**：检查点文件上限 8,192 字节，且不自动注入、需策略自行读回。这一设计刻意贴近真实工程实践，但也意味着**信息压缩损失**是性能天花板之一；论文未系统扫描该上限（如 2K/8K/32K）对成功率的影响。
- **异步 PPO 的 off-policy 性**：完全异步采样带来 policy-version lag，论文虽报告了 lag 与 clip fraction 等健康指标，但未量化 lag 对最终性能的因果影响（如与同步 PPO 的受控对比）。
- **基线的公平性张力**：Mem0 / Letta Code 使用冻结 4B，能力上限受基座限制；AgeMem 在统一协议下训练可能偏离其原始设计（论文以原 recipe 复现作为补丁，排序不变，但仍非完全对等）。
- **安全与鲁棒性未讨论**：记忆文件是策略可自由写入的持久状态，存在被污染、被注入错误结论并在后续回合被无条件信任的风险；论文的记忆内容干预实验证明了内容的因果作用，但未讨论对抗性场景或错误记忆的自纠机制。

## 8. 启示与实践意义

- **接口选择即先验选择**：本文最有价值的洞见不是某个算法细节，而是"**记忆接口应当落在基座预训练分布之内**"。用 NLL/surprisal 定量探测候选接口的先验强度（文件动作 0.076–1.193 nats/token vs 专用工具显著更高），并把 nonce 改名、调用格式、文档删除作为控制变量，是一套可复用的**接口评估方法论**，可推广到其他智能体能力（如浏览器操作、API 调用）的工具设计。
- **"激活"范式**：KL 仅 0.094 nats/token、权重相对变化 0.22%，却带来记忆链比例从 8.0% 到 20.9% 的提升，说明后训练的杠杆点在于**把已有先验接到正确的信用分配通路上**，而非教授新技能。这为"小预算后训练"提供了乐观证据，也提示应优先排查"能力是否已存在但未被激励"。
- **环境设计范式**：回合持久工作区 + 单一 shell 动作空间 + 策略自主决定是否写检查点 + 环境不代写不注入，这一组合使"记忆"成为可被 RL 直接优化的**行为变量**而非硬编码流程，同时保持了与真实开发环境的一致性，便于向生产系统迁移。
- **双粒度 PPO 的工程价值**：响应级优势 + token 级裁剪，在变长、多回合、动作与自然语言混合的轨迹上兼顾了稳定性与细粒度，可作为长时程 agent RL 的默认配置参考。
- **可复现性**：论文报告了完整超参、GPU 小时、随机种子、5 次重复实验的均值±标准差、10,000 次分层配对 bootstrap 的置信区间，以及多项控制实验（token 级 GAE 控制、单工具变体、AgeMem 原 recipe），复现信息密度较高；代码与数据的具体发布状态需以原文附录或补充材料为准。

## 9. 总体评价

本文提出的是一个**观点清晰、证据链完整**的工作：核心主张（用文件系统作为记忆载体、以 RL 激活预训练先验）简洁且具有工程可迁移性；方法层面（统一 shell 接口、上下文替换协议、双粒度异步 PPO）设计自洽；实验层面在四个差异显著的任务域上做了域内评测，并通过两个外部 benchmark 与多项机理分析（surprisal 探测、记忆链统计、内容干预、KL/权重距离）回答了"为什么有效"，而不仅是"是否有效"。主要不足在于基座与规模覆盖有限、训练预算偏小、一个环境未显著分离，以及记忆状态的安全性与长程训练动态尚未探讨。总体而言，该工作把"智能体记忆"从**外部工具工程问题**重新表述为**策略行为学习问题**，并给出了可操作的接口设计原则与训练配方，对后续长时程 agent 的后训练研究具有明确的参考价值。
