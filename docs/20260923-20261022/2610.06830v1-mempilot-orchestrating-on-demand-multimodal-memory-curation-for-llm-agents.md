## 摘要
记忆已成为LLM智能体生态不可或缺的一部分，支持跨交互的信息保留与复用。然而，现有大多数智能体记忆系统以与查询无关的方式构建记忆，这会造成不必要的预处理开销，并丢弃后续可能至关重要的细节。近期研究开始将记忆处理转向运行时自适应，但通常专注于特定操作或固定处理方案，对性能、成本和延迟的灵活控制仍尚未得到充分探索。为应对这一挑战，我们提出MemPilot，一个灵活的框架，可在不同性能—成本—延迟偏好下编排按需记忆整理。具体而言，我们通过强化学习优化一个多步LLM策略，以迭代地在从与查询无关的记忆中检索，以及将针对查询的原始多模态历史整理委托给异构LLM和VLM之间进行选择。该策略联合控制证据数量、整理指令、模型选择和视觉访问，从而实现运行时计算的细粒度分配。为在相互竞争的目标下优化该策略，我们采用按目标优势解耦，即在聚合之前分别估计每个目标的优势。此外，我们引入基于前缀的边际效用估计，用于跨多步rollout的细粒度信用分配。在五个多模态智能体记忆基准上的实验表明，在不同优化偏好下均能实现有利的性能—成本—延迟权衡，且偏好扫描所得前沿比现有权衡感知基线更广。

## Abstract
Memory has become integral to the LLM agent ecosystem, supporting information retention and reuse across interactions. However, most existing agent memory systems construct memory in a query-agnostic manner, which can incur unnecessary preprocessing cost and discard details that later prove essential. Recent studies have begun shifting memory processing toward runtime adaptation, but typically specialize in particular operations or fixed processing schemes, leaving flexible control over performance, cost, and latency largely underexplored. To address this challenge, we present \textbf{MemPilot}, a flexible framework that orchestrates on-demand memory curation under different performance--cost--latency preferences. Specifically, we optimize a multi-step LLM policy via reinforcement learning to iteratively choose between retrieving from query-agnostic memory and delegating query-specific curation of raw multimodal history to heterogeneous LLMs and VLMs. The policy jointly controls evidence amount, curation instructions, model selection, and visual access, enabling fine-grained allocation of runtime computation. To optimize this policy under competing objectives, we adapt objective-wise advantage decoupling by separately estimating each objective's advantage before aggregation. Moreover, we introduce prefix-based marginal utility estimation for fine-grained credit assignment across multi-step rollouts. Experiments on five multimodal agent-memory benchmarks demonstrate favorable performance--cost--latency trade-offs across optimization preferences, with preference sweeps yielding broader frontiers than existing trade-off-aware baselines.

## 1. 核心问题与整体含义

- **背景**：随着 LLM 智能体走向长程、持久化交互，记忆机制成为保留与复用历史经验的核心组件。但现有智能体记忆系统大多以**与查询无关（query-agnostic）** 的方式在查询到来前构建记忆，既产生不必要的预处理开销，又可能丢弃后续查询真正需要的细节。
- **已有转向**：近期工作开始将记忆处理迁移到运行时（如 GAM、BudgetMem、Mem-Gen、AdaMEM、MemRL、DeferMem 等），但普遍存在三点局限：
  1. **运行时控制结构僵化**：依赖手工设计的操作、固定流水线、预算档位或启发式规则，缺乏查询级自适应自由度；
  2. **权衡优化不完整**：多只关注 token 用量或金钱成本，用户可感知的**延迟**很少被作为显式优化目标；
  3. **处理后端固定**：默认单一模型完成运行时整理，忽视异构 LLM/VLM 在质量、成本、延迟上的巨大差异，限制了可达的权衡空间。
- **核心问题**：如何在运行时对多模态记忆整理进行**自适应编排**，并在性能、成本、延迟之间实现**可控权衡**？
- **整体含义**：论文主张智能体记忆应从“性能单一导向”转向“资源感知的运行时自适应”，把记忆整理视为一种可调度的计算资源分配问题，类似商业 LLM 服务提供的多档位能力—成本—延迟选择。

## 2. 方法论

### 2.1 核心思想

- **双视图记忆表示**：
  - 查询无关记忆库 **M**：可由任意现成记忆系统（如 LLMLingua-2 压缩、A-MEM、SimpleMem）初始化，用于高效访问；
  - 原始多模态历史 **H**：按约 256 token 分块，保留原始文本与图像上下文，供查询特定的运行时整理。
- **设计原则**：保留高效但可能有损的记忆库，同时保留原始历史以支持按需精加工，二者互补。
- **多步决策编排**：由文本型 orchestrator 策略 π_θ 在每一步选择 `Retrieve`（检索 M）或 `Curate`（委派异构 LLM/VLM 处理 H），累积证据后给出最终答案。

### 2.2 关键技术细节

- **序贯决策形式化**：
  - 状态 `s_t = (q, a_<t, o_<t)`，动作 `a_t = (z_t, φ_t)`，`z_t ∈ {Retrieve, Curate}`；
  - 观测：`Retrieve` 返回语义检索结果 `RM(φ_t)`；`Curate` 返回外部模型整理结果 `CH(φ_t)`；
  - 轨迹 `τ = (q, a_1, o_1, ..., a_T, o_T, y)`，`T ≤ T_max`（实验最多 6 轮、最多 2 个并行调用）。
- **因子化动作参数**：
  - `Retrieve`：`(r_t, k_t)` —— 检索查询与证据条数；
  - `Curate`：`(r_t, k_t, i_t, m_t, v_t)` —— 额外包含整理指令、外部模型选择、是否包含原始图像；
  - 关键设计：**将“检索什么”(r_t) 与“如何整理”(i_t) 解耦**，避免语义混淆。
- **异构模型委派**：模型池含 6 个纯文本 LLM（Llama-3.2-3B 至 Qwen3-235B-A22B）与 6 个 VLM（Qwen3-VL 系列、Gemini-2.5-Flash-Lite、Claude-Haiku-4.5、GPT-5.6-Luna）；orchestrator 仅见匿名模型 ID 与轻量画像（参数量、支持模态），自身不直接处理图像像素。
- **资源感知 GRPO 训练**：
  - 三目标奖励：`r_Q = Q(τ)`（F1/LLM-judge）、`r_C = -C(τ)`（orchestrator + 外部调用 token 成本）、`r_L = -L(τ)`（代理延迟估计）；
  - **目标级优势解耦**：对每个目标在 rollout 组内独立归一化得 `A_j`，再按偏好 `λ = (λ_Q, λ_C, λ_L)` 加权聚合并做 batch 级再归一化，最后代入带 KL 正则的 clipped GRPO 损失；
  - **前缀边际效用**：对每个整理阶段 t 截断后续操作、贪心生成短答案，得到 `u_{i,t} = Q(ŷ_{i,t})`，边际效用 `Δu_{i,t} = u_{i,t} - u_{i,t-1}`，以权重 η 加到该阶段对应策略 token 的优势上（`Ã = A_λ + ηΔu`），实现细粒度信用分配；仅用于质量目标以避免重复计入资源惩罚。
- **格式门控**：格式不合规轨迹奖励固定为 -1，且其资源优势置零，防止“无工具/低资源”轨迹因低成本获得不当奖励。
- **延迟代理模型**：`L̂ = b + a_in·n_in + a_out·n_out (+ a_img·n_img)`，并行调用取最大值、顺序阶段求和；系数通过受控的 OpenRouter 请求标定，以避免网络与服务波动带来的训练不稳定。

## 6. 主要结论与发现

- **可控的多档位权衡**：MemPilot-Perf 在 5 个基准、2 个答案模型下均取得最佳 LLM-judge 分数；MemPilot-Bal 以显著更低成本提供中间档位；MemPilot-Cost 达到与文本中心系统相当的低成本区间。
- **前沿优势**：偏好扫描得到的性能—成本与性能—延迟前沿**明显包络** LightMem、BudgetMem、OmniSimpleMem 等权衡感知基线；多数传统记忆系统只暴露单一工作点。
- **计算分配具有协同性**：随成本/延迟偏好收紧，策略会**同时**减少步数、Curate 频率、图像访问、输出 token 与模型规模，而非单一维度收缩；证据数变化非单调，说明是“重配置”而非“简单少取”。
- **模型路由是关键机制**：高资源设置偏向大模型与强 VLM，最低成本点五个基准均只路由到 <70B 的纯文本 LLM。
- **消融结论**：移除 LLM/VLM 委派（37.40 → 14.58）、边际效用（→14.82）、检索—指令解耦（→15.35）、目标级优势解耦（→21.94）均导致大幅质量下降；虽成本降低，但权衡明显劣化。
- **记忆库兼容性**：替换为 SimpleMem 或 A-MEM 记忆库后无需重训即可保持前沿形态，仅整体成本区间平移，证明框架与上游记忆构建解耦。

## 7. 优点

- **问题建模清晰**：将运行时记忆管理统一形式化为**偏好条件化的多目标序贯决策**，把检索、整理、模型路由、模态访问纳入同一动作空间，概念上简洁且覆盖面广。
- **双视图 + 可替换记忆库**的设计兼顾效率与信息保真，且与现有记忆系统正交兼容，工程落地性好。
- **训练方法有针对性创新**：目标级优势解耦解决多目标奖励归一化相互掩盖的问题；前缀边际效用以低开销（短答案 + KV 前缀复用）实现步级信用分配，思路巧妙。
- **实验分析维度丰富**：不仅报告主指标，还给出前沿曲线、逐基准行为分解、模型选择份额、记忆库敏感性，解释性较强。
- **公平性设计到位**：统一数据协议、统一检索上限、OOD 隔离、策略—答案模型解耦、格式门控防止“钻空子”。
- **案例分析直观**：三个案例清楚展示了“何时直接检索、何时委派文本模型、何时启用图像”的决策逻辑。

## 8. 不足与局限

- **延迟建模为代理估计**：使用仿射代理而非真实 wall-clock，虽提升训练稳定性，但与实际部署延迟可能存在系统性偏差；作者亦将其列为未来工作。
- **隐私与安全风险**：运行时整理会把检索到的交互历史发送给外部模型，对敏感记忆存在泄露风险，论文仅将其列为未来方向，未提供机制性缓解。
- **偏好需人工设定**：λ 系数需预先指定，缺乏从高层部署需求到奖励系数的自动映射，实际使用门槛较高。
- **算力与复现信息缺失**：未报告 GPU 型号/数量/训练时长，复现成本不透明。
- **评估覆盖有限**：
  - 每偏好仅单条确定性轨迹，未报告方差或多次采样稳定性；
  - 未与 MemRL 等端到端 RL 记忆方法直接对比；
  - 外部模型池与定价为特定快照，结论的时效性与可迁移性受限；
  - judge 依赖 GPT-4o-mini，存在评分偏差可能。
- **训练数据规模偏小**（约 3.7K 训练 QA），策略在更大规模、更多领域记忆分布上的泛化性尚未验证。
- **成本口径局限**：仅计 token 计费，未纳入本地 orchestrator 的真实硬件成本、缓存命中率波动等部署因素。
- **格式门控较严格**：格式不合规即奖励 -1，可能导致训练早期探索受限，论文未讨论其对收敛的影响。
