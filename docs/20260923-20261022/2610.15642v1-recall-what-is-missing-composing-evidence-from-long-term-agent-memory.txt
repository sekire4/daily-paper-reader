## ABSTRACT 

Under a limited context budget, a long-term agent must recall not merely mem-ories that are individually relevant, but evidence that is collectively sufficient for the current query. Conventional memory access retrieves, scores, and trun-cates memories, often spending multiple context slots on redundant facts while leaving complementary evidence behind. We cast the read phase of long-term memory as query-conditioned evidence composition : each memory is valued by what it adds beyond the evidence already selected. We instantiate this opera-tion with M EM PURSUIT , a training-free mechanism that uses the residual of a sparse convex query reconstruction as a representation-space proxy for what the current memory set is missing. By reusing the query and candidate embeddings already available from retrieval, M EM PURSUIT progressively composes nested evidence contexts without invoking a language model or cross-encoder to score each query–memory pair. The effectiveness of our method is verified on 3 pop-ular benchmarks in comparison to strong baselines. In fixed-budget LoCoMo experiments, M EM PURSUIT improves end-to-end accuracy by 7.2 percentage points at Top-10 and 5.5 percentage points at Top-20, with consistent gains across multiple memory frameworks, while achieving a 32.9 × speedup in median rerank-ing latency over fully batched BGE-v2-m3. Our implementation is available at 

https://github.com/FengQi-HITSZ/MemPursuit .

## 1 INTRODUCTION 

Long-lived language-model agents accumulate far more interaction history than can be placed in the prompt of every future query. External memory systems address this mismatch by extracting, organizing, and retrieving persistent records of past interactions (Zhong et al., 2024; Chhikara et al., 2025; Kang et al., 2025; Xu et al., 2025). Yet storage alone does not determine whether an agent remembers successfully. At answer time, a memory system must assemble a limited context from its growing store of records. We refer to this process as memory reading. Hierarchical and graph-based architectures exploit the organization of stored memories to guide retrieval (Kang et al., 2025; Gutiérrez et al., 2024; Rasmussen et al., 2025). A common memory-read policy selects records according to their individual relevance to the query, using dense semantic similarity, sparse lexical matching, or hybrid retrieval (Zhong et al., 2024; Pan et al., 2025; Fang et al., 2026), optionally followed by a relevance reranker (Li et al., 2026). For the dominant pointwise memory-read, the final context consists of the K highest individual scores, implicitly treating the usefulness of a memory as independent of the other selected memories (Sun et al., 2026). In long histories, independently relevant memories often repeat the same event, preference, or conversational fact (Hu et al., 2026). A multi-hop query can consequently receive several paraphrases of one hop while missing a less similar fact required to complete the evidence chain. Figure 1 shows this pattern: the standard read repeats memories about Deborah’s father while omitting her friend Karlie, whereas M EM PURSUIT selects complementary records about her father, mother, and Karlie to complete the answer. Increasing K only partially addresses this failure:

The key decision is not just which memories match the query, but which memory adds what the current context still lacks. We formulate this read-time decision as query-conditioned evidence composition : assembling a compact context by valuing each memory according to what it adds to the evidence already se-lected. Graph-based systems already support cross-memory retrieval through explicit relational structures (Gutiérrez et al., 2024; Rasmussen et al., 2025). However, building and maintaining these structures requires additional operations, with graph-wide consolidation identified as a substantial source of overhead as memory grows (Zhou et al., 2026). We introduce M EM PURSUIT , a training-free reader that implements this principle through sparse convex query reconstruction. Its central idea is to represent the query using the selected memory embeddings and use the remaining residual to guide further recall. Starting with the strongest semantic match, M EM PURSUIT alternates between selecting a memory aligned with the residual and refitting the weights of all selected memories. The residual discounts query directions already represented in the context, directing subsequent selections toward complementary content. A single pursuit path yields nested evidence sets across context budgets. By operating directly on existing query and memory embeddings, M EM PURSUIT makes these conditional choices through matrix and vector operations, without additional language-model or cross-encoder scoring. In controlled comparisons on LoCoMo, with the memory store, candidate pool, and downstream evaluation fixed, M EM PURSUIT improves Top-10 accuracy by 7.2 percentage points, including a 12.8-point gain on multi-hop questions. It improves gold-session coverage and reaches 85.1% accuracy with 20 memories, outperforming hybrid retrieval with 50. At Top-20, it comes within 0.5 points of BGE-large with 32.7 × lower median selection latency. These benefits transfer across four memory frameworks, and its end-to-end pipeline achieves the highest aggregate scores among the evaluated systems on LoCoMo, LongMemEval-S, and BEAM with both answerers. These results establish residual-guided composition as an effective, efficient, and reusable operation for long-term agent memory. Our contributions are threefold: • Residual-guided evidence composition. We introduce M EM PURSUIT , a training-free memory reader that turns query reconstruction into a set-conditioned selection rule. Residual scoring and fully corrective simplex refitting adapt each choice to the evidence already selected. 2Preprint • More complete evidence under limited budgets. Controlled comparisons show higher answer accuracy with fewer memories and improve complete gold-session coverage from 77.1% to 84.5% at Top-10. Reconstruction analysis connects these evidence gains to the geometric selection signal. • Reusable and efficient memory reading. Experiments span three benchmarks and two answerers, with accuracy gains in all eight framework–budget configurations in cross-framework comparisons. Reranker comparisons demonstrate competitive answer quality at a fraction of the selection cost. 

## 2 PRELIMINARIES 

2.1 WRITING MEMORIES , READING EVIDENCE 

An agent memory system performs two complementary operations. Writing constructs and updates a persistent memory store M = {mi}Ni=1 from past interactions. Reading assembles stored information into the answer model’s context for a query q. The writer determines what the agent retains. The reader chooses which memories to use together for the current answer. For each query, the underlying memory system supplies a candidate pool CP (q) ⊆ M of P memories. A read policy π selects an evidence set SK (q) = π(q, CP (q), K ) ⊆ C P (q) with |SK (q)| ≤ K. The selected memory texts are passed to the answer model together with q. The budget counts memory entries in the form supplied by the backbone. We study this final selection step, which determines how the available evidence is assembled into the answer context. The backbone handles memory writing, store organization, and candidate generation. To isolate the effect of memory selection, our controlled comparisons hold the store, candidate pool, budget, answerer, and evaluation protocol fixed. 2.2 MEMORY READING AS BUDGETED SET SELECTION 

Let U (q, S ) denote the utility of memory set S for answering query q with a fixed answer model. Memory reading seeks a set that maximizes this utility within the available budget:

We use query reconstruction to measure how well a combination of memories represents the query and to guide the choice of that combination.

The greedy pursuit produces an ordered sequence of memories with nested selected sets S1 ⊂ S2 ⊂· · · . For a fixed budget K, M EM PURSUIT performs K selection–refit steps and uses the texts of the first K selected memories as the answer context. A single pursuit path also supplies contexts for smaller budgets through its prefixes. Composition weights guide the search, while all selected entries remain in the context even if their fitted weights later become zero. This incremental construction also allows context size to adapt to the query. Instead of always using the full budget, M EM PURSUIT can terminate when further selections make little progress in query reconstruction. Under a fact-cluster model that groups memories supplying the same fact, it then gives conditions for selecting all required facts before repeating any of them.

We compare M EM PURSUIT with nine baselines across three benchmarks using two answerers, and evaluate its integration into four memory frameworks. Further analyses examine evidence coverage, performance across question types and memory budgets, and quality–efficiency trade-offs with neural rerankers. 4.1 EXPERIMENTAL SETUP

## 5 RELATED WORK 

Long-term memory for language-model agents. Agent memory systems improve retention and access through persistent memory management (Zhong et al., 2024; Chhikara et al., 2025), seg-mentation and compression (Pan et al., 2025; Fang et al., 2026; Liu et al., 2026), and linked or graph-structured organization (Xu et al., 2025; Gutiérrez et al., 2024; Rasmussen et al., 2025). Mem-oryOS and MemOS develop broader memory-management architectures (Kang et al., 2025; Li et al., 2025), while Hindsight distinguishes factual evidence, experiences, and beliefs (Latimer et al., 2025). Memory-R1 learns memory management and utilization through reinforcement learning (Yan et al., 2025b). These systems shape what agents retain and how they access it. M EM PURSUIT focuses on composing the final answer context from a supplied candidate pool, providing a reusable read operation across memory architectures. 

From relevance ranking to evidence composition. Dense retrieval such as DPR (Karpukhin et al., 2020) and pointwise rerankers such as MemReranker (Li et al., 2026) estimate individual relevance, whereas RankGPT and ListT5 use listwise comparisons to produce rankings (Sun et al., 2023; Yoon et al., 2024). Set-dependent selection has a longer history in MMR (Carbonell & Goldstein, 1998), xQuAD (Santos et al., 2010), submodular optimization (Lin & Bilmes, 2011), and determinantal point processes (Kulesza & Taskar, 2012), which promote novelty, aspect coverage, or diversity. More recent approaches target evidence utility directly (Deng et al., 2025; Singh & Vadlamani, 2026). For instance, SetR uses LLM reasoning to select passages satisfying query requirements (Lee et al., 2025). M EM PURSUIT instead evaluates the selected set through query reconstruction. Jointly refitted weights determine the residual guiding each addition, making selection sensitive to what the current set already represents without a separately trained utility model or LLM-based selection. 9Preprint 

Dynamic retrieval and residual pursuit. MemR 3 and GAM interleave retrieval with reflection or research (Du et al., 2025; Yan et al., 2025a), while MRAgent uses LLM reasoning to prune memory-graph paths (Ji et al., 2026). xMemory combines hierarchical organization with uncertainty-guided expansion (Hu et al., 2026). These approaches make retrieval responsive to accumulated evidence. MEM PURSUIT implements this adaptation geometrically within the candidate pool. Drawing on orthogonal matching pursuit (Tropp & Gilbert, 2007), Frank–Wolfe optimization (Jaggi, 2013), and generalized matching pursuit (Locatello et al., 2017), it alternates residual-guided selection with fully corrective simplex refitting. This connects sparse approximation to agent-memory composition, yielding nested contexts through inexpensive operations on existing embeddings. 

## 6 CONCLUSION 

A long-term memory system must compose a limited answer context from complementary evidence. MemPursuit implements this operation through simplex-constrained residual pursuit: selected memo-ries jointly reconstruct the query, and the remaining residual guides subsequent recall. The method is training-free, reuses existing embeddings, and produces nested contexts without additional neural scoring. Experiments show consistent accuracy gains across memory frameworks, while comparisons with neural rerankers demonstrate competitive answer quality at a fraction of their selection cost. However, MemPursuit relies on the structure of the semantic embedding space and cannot explicitly reason about contextual relationships between memories and the query.

LoCoMo — Answer generation 

You are answering a question using retrieved memories from past conversations. Follow these reasoning steps IN ORDER. ## Step 1: SCAN ALL MEMORIES Read EVERY memory below from first to last. For each one that contains information relevant to the question, note it. Do NOT stop after finding the first relevant memory — important details are often scattered across many memories, including ones far down the list. Give equal weight to ALL memories regardless of position — a memory near the end is just as likely to contain the answer as one near the beginning. In these memories, "User" refers to the main person whose memories these are. ## Step 2: ENTITY VERIFICATION Confirm each relevant memory is about the correct person/entity. If the question asks "What does Person A like?" and a memory says "Person B likes X", do NOT use that memory to answer about Person A. In two-person conversations, both speakers' actions are relevant — if the question asks about person A and a memory attributes an action to person B (the other speaker), that information is still valid evidence from their shared conversations, but always check the attribution is correct. ## Step 3: COMBINE AND CROSS-REFERENCE - COMBINE facts from multiple memories about the same topic. If one memory says "won first place" and another says "performed a piece titled X," those describe the same event — connect them. - For listing/counting questions, extract EVERY distinct item from ALL memories. A single memory may contain multiple items. Think about what CATEGORIES of answers the question could have, then re-scan specifically for each category. - For counting questions ("how many times", "how many X"), enumerate each distinct instance explicitly with its date or context BEFORE giving a final count. Do not estimate — list them out, then count the list. - DECOMPOSE complex sentences: "an immersive X with Y, enjoys Z" contains multiple distinct facts. Each could be the answer. - Connect related facts across memories: if one says "nearby lake" and another says "Lake Tahoe is great for kayaking", the nearby lake IS Lake Tahoe. If one says "bought X in Paris", infer the country is France. ## Step 4: SELECT THE BEST ANSWER - Do NOT assume the highest-ranked memory is correct. Multiple memories may describe different events for the same topic. Compare each candidate's relevance to the SPECIFIC question, not its retrieval score. A lower-ranked memory that directly answers the question beats a higher-ranked one that is only tangentially related. - ALWAYS choose the MOST SPECIFIC detail available. A proper name, title, or number beats a generic description. Rate each candidate as HIGH specificity (name, title, number, specific activity) or LOW (generic description), and prefer HIGH.

C.5 COMPARISON WITH MAXIMAL MARGINAL RELEVANCE 

We compare M EM PURSUIT with maximal marginal relevance (MMR) (Carbonell & Goldstein, 1998), which balances query relevance against the maximum similarity to an already selected item. While MMR explicitly penalizes pairwise redundancy, M EM PURSUIT optimizes a joint query-reconstruction objective over the selected set. Residual scoring and joint refitting work together to select memories that improve this reconstruction. This comparison tests whether reconstruction-driven composition improves on explicit redundancy penalization. We use the same LoCoMo memory store and per-question candidate pool of P = 200 memories, with GPT-4o-mini as both answerer and judge, and vary only the memory selection strategy. MMR uses a fixed relevance–diversity coefficient λMMR = 0 .5. Each budget K ∈ { 10 , 20 , 50 , 200 } is evaluated on 1,540 questions.
