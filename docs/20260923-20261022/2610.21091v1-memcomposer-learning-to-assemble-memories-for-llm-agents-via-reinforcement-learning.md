## 摘要
智能体记忆使大语言模型（LLM）智能体无需更新参数即可复用过往经验。然而，仅凭语义相似度并不能保证记忆有用：下游性能取决于记忆如何被选择并呈现给智能体。我们提出MemComposer，一种记忆组装器，它联合考察当前查询与检索到的候选记忆，以决定纳入哪些经验、选择多少条以及如何排序。我们使用经验策略优化（Experience Policy Optimization, ExPO）训练该组装器；ExPO是一个基于GRPO的框架，通过完整的智能体交互评估组装后的记忆上下文，并利用任务成功反馈优化组装策略。在τ²-bench的三个领域、两种冻结执行器设置下，MemComposer在每个执行器上均优于最强基线，同时将平均记忆token用量分别降低16.9%和4.9%。学习到的策略还可迁移到未见过的领域、执行器和记忆库，并且无需进一步训练即可受益于更强模型生成的记忆。这些结果证明了利用下游任务反馈学习查询特定记忆组装的价值。

## Abstract
Agent memory enables large language model (LLM) agents to reuse past experiences without updating their parameters. However, semantic similarity alone does not guarantee memory usefulness: downstream performance depends on how memories are selected and presented to the agent. We propose MemComposer, a memory composer that jointly examines the current query and retrieved candidates to decide which experiences to include, how many to select, and how to order them. We train the composer using Experience Policy Optimization (ExPO), a GRPO-based framework that evaluates assembled memory contexts through complete agent interactions and uses task-success feedback to optimize the assembly policy. Across three $τ^2$-bench domains with two frozen executors, MemComposer outperforms the strongest baseline for each executor while reducing average memory-token usage by 16.9% and 4.9%, respectively. The learned policy also transfers to unseen domains, executors, and memory banks, and benefits from memories generated by stronger models without further training. These results demonstrate the value of learning query-specific memory assembly using downstream task feedback.

  - **如何排序**：同一记忆集合仅改变顺序，逐任务结果即发生变化（相似度序、逆序、长度升降序、随机均无普适最优），与 in-context learning 的顺序敏感性一致。

## 2. 方法论

### 2.1 问题形式化
- 组装器策略 πθ、执行器 πe。给定查询 q，相似度检索返回 top-n 候选 M(q)={m₁,…,mₙ}。
- 组装器采样**有序子集** S=(m_{i₁},…,m_{i_k})，0 ≤ k ≤ n（k 可为 0，即不用记忆），同时决定成员与顺序。
- 执行器在 (q, S) 条件下与环境多轮交互，返回二元成功奖励 r；目标是最大化 E_q E_{S~πθ}[R(q,S)]，即执行器使用该记忆序列的期望成功率。

### 2.2 自生成记忆库（固定，不参与训练）
- 每个域 × 每个执行器骨干：对每个训练任务用冻结执行器采 N=8 条独立轨迹，记录结果 r。
- **同模型事后自评**：失败轨迹定位“第一个出错的 agent 轮次 + 本应怎么做”（若有同任务成功轨迹则作为对比样例）；成功轨迹审计是否含关键错误（如误报信息、声称未执行的动作）。
- **标签三分类**：clean pass / fake pass（通过但过程有关键错误）/ failure；**原始奖励永不修改**。
- **确定性一致性检查**：引用的轮次必须存在且属于 agent、结论须与环境奖励一致、格式合规，否则整条丢弃。
- **Curation**：每训练任务最多保留 2 条（一条 pass + 一条 failure），控制规模与平衡。
- **双表示**：digest（首条用户消息 + 结果标签 + 摘要 + 反思，约 1.0–1.4K tokens，给组装器看）；full（完整轨迹 + 反思，被选中后交给执行器）。
- 以用户首条消息为索引，用 Qwen3-Embedding-8B 检索，top-10 候选池对所有方法共享。

### 2.3 MemComposer 组装器
- 输入：任务指令 + 10 条候选 digest + 用户开场请求 + 格式要求（候选按检索序编号 [1]–[10]）。
- 输出：`<reasoning>` 简述取舍理由 + `<answer>` 中的**有序索引列表**（可空列表表示无记忆执行）。
- 选择条数 k 与顺序均由策略动态生成，**不设固定预算**。

### 2.4 Experience Policy Optimization（ExPO，基于 GRPO）
- **任务奖励**：每条采样序列 S_g 用冻结执行器跑 **J=8 次试验**（仅随机种子不同，记忆与顺序固定；基础设施错误重采样），取平均成功率 r_task = (1/J)Σ r_{g,j}。相同序列共享试验以省算力。
- **最终奖励**：r_ExPO = r_task − p_len(k_g) − p_fmt(S_g)。
  - 格式惩罚：缺 reasoning 段罚 λ_fmt=0.05；无效输出（无闭合 answer、无列表、索引越界）直接记 0 分且不送入执行器。
  - 规模惩罚：仅在 k > K_max 时生效，p_len = λ_len·max(0, k−K_max)；Telecom 用 λ_len=0.02、K_max=7，Retail/Airline 用 λ_len=0.01、K_max=0。
  - **设计约束**：惩罚上界 0.1 < 单次成功增量 1/8=0.125，因此不会逆转任务结果不同的序列排序，只在结果持平时偏好更短的选择。
- **动态采样（DAPO 式）**：丢弃任务奖励全同的组并继续采样，保证被保留的组一定在**任务结果**上有差异，使惩罚项无法单独“制造信息量”。
- **优势**：A_g = r_ExPO − 组内均值（**不除以标准差**，避免近同结果组的噪声放大）。
- **优化**：GRPO 裁剪代理目标（ε=0.2、dual-clip 3.0），token 级平均；**无 KL 惩罚**，无参考策略；仅更新组装器，执行器、检索器、记忆库全程冻结。
- **训练数据构造**：官方 train split；因首条消息是固定问候，从用户模拟器采 4 个开场变体作为同任务的 4 个查询；排除同任务来源记忆、每源任务最多 2 条；top-20 切成两个 10 窗口并重新编号 1–10，防止模型识别窗口位置。
- **实现**：LoRA（rank 64 / scaling 128），30 次策略更新，lr 2×10⁻⁵（Qwen3-4B）/ 1×10⁻⁵（Ministral），verl 框架，bfloat16。
