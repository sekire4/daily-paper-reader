## 摘要
持久记忆将先前的交互转化为持久的智能体状态，但现有系统对以下两方面控制有限：该状态是否仍然有效，以及它是否应影响后续查询。我们认为，可靠的记忆需要对状态形成和查询时影响都进行治理。我们引入 PLACE，这是一种分解式治理层，为记忆后端增加了写侧状态认证和读侧授权。基于 Mem0 并使用 Qwen2.5-3B 与 Qwen2.5-7B 的析因评估分离了每种机制的贡献。结果表明，写侧治理显著提升了生命周期状态正确性，而读侧治理在状态正确的设置下消除了由不合格记忆造成的可测量因果泄漏。二者结合在保持查询相关支持的同时实现了最强的联合性能。这些发现表明，可靠的持久记忆需要对所维护状态和查询时信息影响进行显式控制。

## Abstract
Persistent memory turns prior interactions into durable agent state, but existing systems provide limited control over whether that state remains valid and whether it should influence a later query. We argue that reliable memory requires governance over both state formation and query-time influence. We introduce PLACE, a factorized governance layer that adds write-side state certification and read-side authorization to a memory backend. A factorial evaluation on Mem0 with Qwen2.5-3B and Qwen2.5-7B isolates the contribution of each mechanism. Results show that write-side governance substantially improves lifecycle state correctness, while read-side governance eliminates measured causal leakage from ineligible memory in the state-correct setting. Their combination achieves the strongest joint performance while preserving query-relevant support. These findings show that reliable persistent memory requires explicit control over both maintained state and query-time information influence.

## 1. 核心问题与整体含义

- **研究动机**：持久记忆使智能体能够跨会话保留用户与任务状态，但现有记忆增强系统（Mem0、MemGPT、MemoryBank、A-MEM、Zep 等）主要改进“如何构建、更新、检索”记忆，缺乏对两个关键问题的显式控制：
  - 记忆后端中保存的状态**是否仍是当前有效的语义状态**；
  - 该状态**是否有资格影响**当前这一次查询。
- **核心洞察**：最终答案正确并不等于记忆正确。智能体可能从邻近上下文“碰巧答对”，而持久记忆中仍残留过期信息；也可能状态本身正确，却在回答时把不应暴露的记忆（过期值、越权信息）喂给了模型。因此，仅用存储质量或答案准确率都无法定位错误来源。
- **问题分解**：论文把可靠记忆拆成两个正交要求：
  - **状态正确性（State Correctness）**：写入侧，记忆须随交互历史演化维护当前有效语义状态；
  - **影响正确性（Influence Correctness）**：读取侧，只有对当前查询“有资格”的记忆才能影响回答，同时保留相关且被授权的记忆。
- **研究问题**：
  - RQ1：写入侧治理能否提升记忆更新过程中的生命周期状态一致性？
  - RQ2：读取侧治理能否阻止不合格记忆影响回答，同时保留查询相关记忆的效用？
- **整体含义**：论文主张“可靠持久记忆 = 状态形成治理 + 查询时影响治理”，并提出可分解、可归因的治理层 PLACE 作为实现路径。

## 2. 方法论

### 2.1 核心思想
- **PLACE**（Persistent-memory Lifecycle Alignment and Contextual Eligibility）是一个**因子化治理层**，在既有记忆后端与回答模型**之外**增加两个边界控制，**不修改后端与答案模型本身**：
  - **CSS（Certifying Write-Side State）**：写入侧状态认证，负责“状态形成”；
  - **QASC**：读取侧授权，负责“查询时影响”。
- 两个机制针对互补的失败模式：CSS 防止过期/冲突状态驻留，QASC 防止不合格记忆进入回答上下文。

### 2.2 问题形式化
- 设 $X_t$ 为第 $t$ 步后的物理记忆后端，其评估侧语义读回为 $S^{phys}_t = \beta(X_t)$，其中 $\beta$ 只把**物理上有证据的记录**映射为语义事实，不能引入无支持的值。
- 参考状态 $S^\star_t$ 仅用于评估，运行时不暴露。
- **写入正确性**：$S^{phys}_t$ 是否与 $S^\star_t$ 持续一致（缺失替换、过期值、矛盾均计为状态错误）。
- **读取正确性**：给定物理记忆视图 $R_t$ 与查询的可信解释 $\tau_t$，授权支持定义为
  $$Q_t = \{m \in R_t \mid E(m, q_t, \tau_t) = 1\}$$
  其中 $E$ 为资格规则，$Q_t$ 是唯一暴露给答案模型的记忆支持。由于 $Q_t \subseteq R_t$，读取治理**只能过滤、不能重建**物理记忆中不存在的事实。

### 2.3 CSS：写入侧状态认证
- 输入上一治理状态 $G_{t-1}$ 与**可信用户级事件** $e_t$，计算
  $$G_t = F_{CSS}(G_{t-1}, e_t)$$
- 事件只编码用户级更新意图（目标事实、取值、作用域、来源），**不包含**结果生命周期状态或内部转移逻辑。
- CSS 自行推导所需状态变化，通过后端操作将 $G_t$ 落地，再用式 (1) 的**物理读回**验证实际存储状态是否与预期一致。

### 2.4 QASC：读取侧授权
- 资格规则 $E$ 综合考虑**请求的实体与谓词**，以及相关的作用域、时间与生命周期约束；只有满足式 (2) 的条目进入模型可见支持。
- QASC **只读**、以物理存储为依据，不能修改持久状态，也不能恢复后端缺失的信息。
- **授权先于上下文预算截断**：避免不合格条目仅因检索排名高而挤入答案模型。

### 2.5 示例（论文图 1）
- 用户先说“东京出发 9 点”，后说“改到 11 点”。CSS 把 `departure_time` 更新为 11:00 并认证落地；QASC 在查询“当前出发时间是几点、为什么”时，只放行 11:00 与改签原因，过滤掉已废弃的 9:00。

## 3. 实验设计

- **实现栈**：记忆后端 Mem0；回答与原生更新模型为 Qwen2.5-3B 与 Qwen2.5-7B（经 Ollama）；向量存储 Qdrant；嵌入 Nomic。CSS 与 QASC 为**确定性规则**，无需训练。
- **因子设计**：写入（Native / CSS）× 读取（Native / QASC）→ 四个条件：**Native、CSS、QASC、PLACE**。Native 与 QASC 共享 Native 产生的状态，CSS 与 PLACE 共享 CSS 产生的状态；每个 producer 在每个更新步只写一次，以隔离读取侧效应。
- **主评估场景（自建 benchmark，非公开数据集）**：
  - 一条**预指定的 302 轮轨迹**，横跨 4 个对话，会话重置但持久记忆保留；
  - 含 **105 个状态检查点**与 **48 个查询**，覆盖 **6 个治理族**（论文未展开各族细节）；
  - 使用可信用户级事件与查询语义，不向系统暴露结果生命周期状态、CSS 内部转移或授权支持。
- **因果泄漏隔离**：48 个**因果对**，固定查询与授权状态，仅变化无关历史，比较两世界答案是否不一致。
- **诊断实验**：
  - **Utility**：72 个探针，测 NeededSupport、ExposureRate、ConflictHarm；
  - **Closed Loop**：保留先前助手回答作为非权威对话上下文，重复因子设置。
- **对比方法**：本质是四个治理组合的消融式对比（Native 基线、仅 CSS、仅 QASC、CSS+QASC），而非与外部记忆系统的横向对比。
- **指标**：
  - StateCorrectness = 105 个检查点上 $F_1(S^{phys}_c, S^\star_c)$ 的均值；
  - LeakageRate：仅在两世界授权状态相同且参考正确时，统计答案结果不一致的概率；
  - AnswerCorrectness：生成答案的确定性语义 F1；
  - JointSuccess：更严格，要求持久状态正确、授权支持正确、所需支持仍可用、无治理违规且最终答案正确；
  - 用 JointSuccess 上的因子**双重差分**衡量 CSS×QASC 交互。
- **统计处理**：纵向结果作描述性报告并用对话块敏感区间；48 个独立因果对用 4000 次 pair-level bootstrap；3B/7B 视为模型规模重复。

## 7. 批判性评估

### 7.1 优点
- **问题分解清晰且有理论价值**：把“记忆可靠性”拆成状态正确性与影响正确性两个正交维度，并给出可操作的形式化（$S^{phys}_t$、$Q_t \subseteq R_t$），使“答案对但记忆错”这类此前被混淆的现象变得可诊断。
- **治理层与后端解耦**：PLACE 不修改 Mem0 与答案模型，只在其外增加边界控制，工程上易插拔，也便于在其它后端上复用。
- **因子设计支持归因**：2×2 设计 + factorization check，使写入侧与读取侧的贡献可分别识别，避免“混合改进无法归因”的常见问题。
- **因果对设计有方法论亮点**：把“泄漏”从相关性指标提升为可干预的因果测量，并配套 bootstrap，思路严谨。
- **防伪改进的 Utility 诊断**：显式区分“治理”与“压制”，是对记忆系统评测的重要补充。
- **确定性规则、无需训练**：降低复现门槛，也使失败模式更易解释。

### 7.2 不足与风险
- **外部效度有限**：单一自建 302 轮轨迹、单一后端（Mem0）、单一嵌入（Nomic）、两个同系列小模型（Qwen2.5-3B/7B），结论能否推广到其它后端、更大模型、多用户真实负载存疑。
- **统计效力不足**：纵向检查点非独立单元，作者自认只能描述性报告；48 个因果对与 72 个探针的样本量偏小，交互效应的双重差分估计对噪声敏感。
- **规则化治理的泛化边界未讨论**：CSS/QASC 为确定性规则，其资格规则 $E$ 依赖实体、谓词、作用域、时间与生命周期约束的手工编码；面对开放域谓词、模糊指代、多跳推理时规则覆盖不足的风险未被系统评估。
- **“只过滤不重建”的下界**：QASC 无法恢复物理记忆中缺失的事实，因此读取侧收益上界受写入侧质量约束；论文虽以因子设计刻画这一点，但对“写入侧失败时读取侧能否缓解”的边界情形讨论不足。
- **缺少与强基线对比**：未与时间感知检索、冲突消解写入、置信度门控等替代治理策略比较，难以判断 PLACE 的相对优势来源是机制本身还是实现细节。
- **成本未量化**：CSS 的物理读回验证与 QASC 的逐条资格判定会带来额外延迟与调用开销，论文未报告其对端到端时延/吞吐的影响。
- **评测指标的主观性**：AnswerCorrectness 用“确定性语义 F1”，其判定器与标注一致性未充分说明，可能影响可复现性。

## 8. 局限与未来方向

- **规模与多样性**：扩展到多轨迹、多领域、多后端的评测，并引入公开或半公开的记忆基准以支持横向比较。
- **统计设计**：将检查点聚合为独立对话级单元，或采用分层/混合效应模型，提高交互效应估计的稳健性。
- **规则到学习的过渡**：探索以少量标注学习资格规则 $E$ 或状态转移 $F_{CSS}$，在保持可解释性的同时提升开放域覆盖。
- **成本-收益权衡**：系统测量治理层带来的延迟与 token 开销，研究“按需治理”（仅在冲突或高风险查询时触发）的调度策略。
- **安全性延伸**：把“影响正确性”从过期/冲突扩展到越权、隐私与注入攻击场景，检验 QASC 的授权语义能否承载访问控制。
- **人机交互**：当治理层过滤掉用户认为相关的记忆时，如何向用户解释与申诉，是实际部署中不可回避的问题。

## 9. 对领域的启示

- **评测范式**：记忆系统评测应从“答案准确率”转向“状态正确性 + 影响正确性 + 联合成功”的多层指标体系，并引入因果对与防伪诊断，避免把“碰巧答对”误判为记忆可靠。
- **架构范式**：把记忆治理实现为后端与模型之间的**可插拔边界层**，比把治理逻辑耦合进后端更利于复用与审计。
- **设计原则**：“授权先于预算截断”是一条值得推广的工程原则——检索排名不应凌驾于资格判定之上。
- **研究议程**：状态形成与影响治理应作为两个独立可研究的子问题，各自有独立的失败模式、指标与改进路径。

## 10. 可复现性说明

- **可复现的部分**：后端（Mem0）、向量库（Qdrant）、嵌入（Nomic）、模型（Qwen2.5-3B/7B via Ollama）均为公开组件；CSS/QASC 为确定性规则，理论上可精确重放。
- **不可复现或难复现的部分**：自建 302 轮轨迹与 105 个检查点、48 个查询、48 个因果对、72 个探针若未公开，则核心结果无法独立验证；语义 F1 的判定器实现、6 个治理族的具体定义、bootstrap 的随机种子与重采样细节均需作者补充。
- **建议**：公开轨迹、检查点、查询与资格标注，以及 CSS/QASC 的规则实现与判定脚本，是提升该工作影响力的关键。

## 11. 一句话总结

PLACE 把“可靠持久记忆”重构为**写入侧状态认证（CSS）与读取侧资格授权（QASC）两个可分离、可归因的治理边界**，并以因子设计、因果对与防伪诊断支撑其主张；其概念贡献与评测方法论价值突出，但受限于单轨迹、小样本与规则化实现的泛化边界，尚需更大规模与更强基线的检验。
