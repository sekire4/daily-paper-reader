## 摘要
长期记忆已被广泛用于基于大语言模型（LLM）的智能体中，以支持持续交互和个性化辅助。然而，长期多方交互会积累显著更细粒度的信息，决策被反复更新，状态在参与者与交互阶段之间不断演化。因此，时间结构对于追踪此类记忆至关重要：相关信息常常密集出现在短时间间隔内，而不同状态之间的转换则由严格的时间顺序锚定。现有的时间感知记忆框架主要将时间存储为元数据，或利用时间信号指导在预构建记忆结构上的检索，而未利用时间结构同时恢复局部集中的证据并重建其完整事件进程。为解决这些局限，我们提出 T-Mem，一种基于时间结构的记忆框架，它保留交互信息，并通过两种时间机制组织与查询相关的证据。时间证据发现利用相关消息的局部集中性来恢复被忽视的证据，而时间记忆结构化则对随时间变化的状态转换与支撑关系进行建模，并在所得森林中压缩低信息量片段。证据森林线性化随后将结构化证据序列化，用于答案生成。在两个长期多方记忆基准上的实验表明，T-Mem 在不同 LLM、参数设置、领域和查询类型上均持续优于有竞争力的记忆框架。

## Abstract
Long-term memory has been widely adopted in LLM-based agents to support persistent interaction and personalized assistance. Long-term multi-party interactions, however, accumulate substantially more detailed information, with decisions repeatedly updated and states evolving across participants and interaction stages. Temporal structure is therefore crucial for tracing such memories: relevant information often appears densely within short intervals, while transitions among different states are anchored by a strict temporal order. Existing temporally aware memory frameworks primarily store time as metadata or use temporal signals to guide retrieval over preconstructed memory structures, without using temporal structure to both recover locally concentrated evidence and reconstruct its complete event progression. To address these limitations, we propose T-Mem, a temporal-structure-based memory framework that preserves interactions and organizes query-relevant evidence through two temporal mechanisms. Temporal Evidence Discovery exploits the local concentration of related messages to recover overlooked evidence, while Temporal Memory Structuring models state transitions and supporting relations over time and compresses low-information spans within the resulting forest. Evidence Forest Linearization then serializes the structured evidence for answer generation. Experiments on two long-term multi-party memory benchmarks demonstrate that T-Mem consistently outperforms competitive memory frameworks across LLMs, parameter settings, domains, and query types.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体无法把全部历史放入上下文，因此依赖外部记忆系统（段落、摘要、结构化记录）在生成前检索紧凑证据。长期多方对话（群聊、协作对话）比普通长对话更复杂：多个发言者、角色、话题和并行演进的决策交织在一起。
- **核心痛点**：语义相似的消息可能描述**互相冲突的状态**（早期提案 vs. 后续修订），而决定最终答案的**关键更新**却可能与查询只有很少的词面重叠。现有记忆框架（图结构、持久记忆网络、多粒度关联、选择性整合）多以语义关联、实体结构或预查询整合为中心；时间信息即使被保留，也仅作为元数据或检索信号，**没有同时用于“定位相关事件片段”和“重建事件内部状态演化”**。
- **两个互补的时间属性**：
  - **时间局部性（Temporal Locality）**：同一事件的相关消息往往密集集中在某个讨论片段内，即使单条消息与查询表面重叠很低。简单增大 Top-k 会引入无关话题和竞争性片段。
  - **时间演化（Temporal Evolution）**：片段内消息并非可互换的观察，而是“提案—质疑—修订—确认—实施”的状态轨迹。相似度排序的扁平列表无法说明哪条代表当前状态。
- **整体含义**：论文主张把**时间结构作为记忆的核心表示**，而非辅助属性；仅“证据完整”不够，还必须显式区分状态变更与支撑性说明，否则早期被取代的状态会与最终决策竞争。

## 2. 方法论（T-Mem）

### 2.1 总体框架
- 不改变原始存储的对话，查询到来时构建**查询条件证据森林** \(F_q=(V_q,E_q)\)，节点为原始消息；答案模型只看到查询与森林的线性化序列，从不接触参考答案。
- 三阶段：**时间证据发现 → 时间记忆结构化（含压缩）→ 证据森林线性化**。

### 2.2 时间证据发现（Temporal Evidence Discovery）
- **种子检索**：用轻量检索器（BM25）对“文本 + channel/phase/topic/author/role”元数据扩展后的消息检索 \(k=36\) 个粗锚点 \(R_k(q)\)。
- **按话题的时间聚类**：对每个话题 \(\theta\) 的种子集 \(A_\theta\)，按时间戳邻近性聚类（实现用 DBSCAN，\(\epsilon=12\) 小时，MinPts=2）。
- **种子密度**：
  \[
  \rho(C_j)=\frac{|C_j|}{\max(\Delta t_j,\delta)},\quad \delta=2\text{h}
  \]
  密度超过阈值 \(\mu=0.25\) 锚点/小时的簇被认定为候选证据区间，并向两侧各填充 12 小时以纳入附近的确认、纠正与后续更新。
- **证据效用选择**：区间内用 embedding 排序取 Top-100，再由 LLM 将消息标注为 **KEY / SUPPORT / IRRELEVANT**；仅接受对查询有证据效用的消息，避免因关键词或话题相同就整段复制讨论。最终 \(R'(q)=R_k(q)\cup\bigcup_j K_j\)。

### 2.3 时间记忆结构化（Temporal Memory Structuring）
- **父节点约束**：候选父节点必须时间更早、同话题、且对话阶段顺序不逆：
  \[
  P_j=\{m_i\mid t_i<t_j,\ \text{topic}_i=\text{topic}_j,\ O_i\preceq O_j\}
  \]
  其中 \(O_i=(\text{stage}_i,\text{phaseOrder}_i,\text{phaseProgress}_i)\) 按字典序比较。
- **关系分类**：查询条件分类器为每对候选打标签：
  - **UPDATE**：子节点推进或改变父节点状态；
  - **EXPAND**：子节点回答、解释或直接支撑父节点；
  - **ROOT**：无正当直接语义父节点。
  置信度最高的非 ROOT 候选成为父节点，否则另起新树。时间、话题、阶段约束共同阻止逆向、跨话题、阶段倒退的连边。
- **预算内压缩**：不删节点、不改边，只压缩节点文本跨度。对叶节点跨度 \(s\) 与父节点 \(p\)，定义信息量
  \[
  G_q(s|p)=\sum_{u\in U(s)\cap U(q)}\Big(\log\tfrac{N+1}{df(u)+1}+1\Big)+\sum_{u\in U(s)\setminus U(p)}\Big(\log\tfrac{N+1}{df(u)+1}+1\Big)
  \]
  即奖励查询相关内容和父节点未覆盖的新信息；按长度归一化得 \(g_q(s|p)=G_q(s|p)/\ell(s)\)。包含查询实体、时间戳、数值、UPDATE 状态变化内容的跨度受保护；其余按密度升序删除直至满足 \(B=8192\) token，必要时从叶向父节点迭代压缩；每个节点至少保留一个文本跨度及元数据。

### 2.4 证据森林线性化（Evidence Forest Linearization）
- 树按根时间戳排序，树内按前序遍历、兄弟按时间排序。
- 每个节点序列化为 \((i,\pi_i,r_i,d_i,t_i,a_i,x_i)\)：节点序号、父节点序号、关系标签、深度、时间戳、作者、保留文本。根节点 \(\pi_i=0,\ r_i=\text{ROOT}\)。
- 答案模型据 \(q\) 与 \(\mathcal{L}(F_q)\) 生成回答。答案提示中明确说明 ROOT/UPDATE/EXPAND 语义，并指示沿 UPDATE 链识别当前或最终状态。

## 3. 实验设计

### 3.1 数据集 / Benchmark
- **GroupMemBench**：4 个领域（金融、科技、医疗、制造），共 12 万条消息；745 道题，覆盖多跳、知识更新、时间推理、用户隐式、术语歧义、拒答 6 类能力。
- **EverMemBench**：2400 道题，三个一级维度：细粒度召回、记忆意识、画像理解（各含 3 个子任务）。
- 均沿用官方数据与评测协议，报告答案准确率。

### 3.2 对比方法
- **简单检索**：BM25（含元数据扩展）、Qwen3.7-text-embedding 稠密检索。
- **结构化/智能体记忆**：A-Mem、HippoRAG2、Hindsight、StructMem、MemGAS。

## 6. 主要结论与发现

- **时间结构是有效且必要的记忆表示**：T-Mem 在两个长期多方记忆基准、两个 LLM 骨干上均取得最高总体准确率，且优势在领域、参数设置、查询类型间一致。
- **时间局部性确实带来召回增益**：Top-36 时关键证据召回从 BM25(Expand) 的 56.6%、HippoRAG2 的 61.5% 提升到 72.8%；受控实验（固定 36 条输出）下，时间定位仍比全局同话题搜索高约 8 个百分点（72.3% vs 64.2%），说明收益来自“改变搜索位置”而非扩大候选集。
- **组织本身就有价值**：同一检索集下，森林结构在 Top-48 比扁平列表高 7.60 个百分点；扁平列表在 Top-36 后开始退化，说明更多证据带来“关系干扰”，显式 UPDATE/EXPAND 关系让额外证据更可用。
- **关系语义有增量贡献**：无类型森林已优于扁平列表，恢复 UPDATE/EXPAND 标签后进一步提升（Top-36：58.79% vs 58.39% vs 54.36%）。
- **消融贡献排序**：时间证据发现贡献最大（−6.04/−6.31 点），其次时间结构化（−4.17/−5.23 点），元数据扩展与压缩贡献较小但一致为正。
- **鲁棒性**：注入修订—回滚噪声后准确率从 47.66% 缓降至 41.12%/38.32% 而非崩溃，完整链召回更强、仅检索到中间状态的比例更低；移除 topic/phase 后仅下降 0.80–2.28 点，仍比 HippoRAG2 高 5.77 点，说明优势来自时间机制本身而非基准特有元数据。
- **效率**：查询条件式时间处理避免了全局构建与反复整合记忆的高成本，Token 与成本显著低于主流结构化记忆基线。

- **写作与可复现性较好**：三阶段流程、超参（\(k=36\)、\(\epsilon=12\)h、\(\delta=2\)h、\(\mu=0.25\)、填充 12h、Top-100、\(B=8192\)）均明确给出，提示模板与线性化字段格式在正文中可追踪。

## 8. 局限与可质疑之处

- **元数据依赖仍是隐性前提**：方法的核心约束（同话题、阶段字典序 \(O_i\preceq O_j\)）依赖 topic / phase / phaseOrder 等结构化元数据。虽然 Exp-6 显示移除后仅下降 0.80–2.28 点，但这是在**基准本身自带较干净元数据**的前提下测得的；在真实群聊、邮件列表、工单系统中，话题边界与阶段标签往往需要额外推断，噪声元数据对父节点约束的影响未被系统评估。
- **时间戳即语义的假设**：时间局部性以“相关消息在时间上密集”为前提。对于异步协作（跨天回复、长期挂起的议题）、时区混用、或同一事件被多次间歇性重提的场景，密度阈值 \(\mu\) 与 12 小时填充窗口可能不成立；论文未给出对时间尺度（小时/天/周）的敏感性分析。
- **阶段顺序的可逆性**：真实讨论常出现回退（重新讨论已被否决的提案、需求反复）。父节点约束禁止阶段倒退，可能把合法的“回滚后重启”错误地切分为新树；Exp-5 只注入了“修订—回滚”噪声来测鲁棒性，但没有检验回滚本身是否被正确表示。
- **LLM 标注引入的不确定性**：KEY/SUPPORT/IRRELEVANT 标注与 UPDATE/EXPAND/ROOT 分类均由 LLM 完成，论文未报告标注一致性（如人工抽检一致率或多模型一致性），也未分析分类错误如何沿树传播——一个错误的父节点可能使整条 UPDATE 链的当前状态判断偏移。
- **单父节点假设**：每节点仅保留一个父节点，牺牲了“一条消息同时更新两个并行议题”的多父情形；这类交叉更新在多方协作中并不罕见，当前设计会将其压缩为单链，可能丢失并行状态。
- **压缩的信息损失未量化**：压缩按 \(g_q(s|p)\) 密度删跨度，虽有保护规则，但没有测量“被删跨度中实际包含答案证据”的比例，也没有与“不压缩但截断”的朴素基线对比，因此压缩的正贡献（消融中小幅为正）缺少机制层面的解释。
- **评测层面的通用问题**：LLM-as-judge 的评分随机性、基线为作者自行适配（StructMem、MemGAS 为改编实现）、成本按 GPT-5.5 等价价格估算（StructMem/MemGAS 为分阶段推算），这些都会削弱跨方法比较的绝对可比性；论文报告的是单次准确率，未给出多次运行的方差或置信区间。
- **基准构造的潜在偏置**：GroupMemBench 与 EverMemBench 均以“存在明确最终状态/可判定答案”为出题前提，天然有利于“沿 UPDATE 链找当前状态”的设计；对开放式、无唯一结论的讨论（如头脑风暴）适用性未知。
- **规模与延迟**：每问 42.39K token 的处理量意味着多次 LLM 调用（标注 + 分类），论文只报告了 token/成本，未报告端到端延迟与并发下的吞吐，对交互式智能体的实际可用性缺乏数据。

## 9. 对领域的启示

- **“检索什么”与“如何组织”应解耦评估**：论文用 Exp-2（证据恢复）与 Exp-3（固定检索集的组织对比）分离两类增益，这一实验范式值得被后续记忆系统工作沿用——否则“结构更好”很容易被“检索到更多”所混淆。
- **时间是低成本的结构先验**：相比构建全局知识图谱或持久记忆网络，时间戳几乎是免费信号；论文表明仅用时间局部性 + 时间演化就能在成本远低于图结构基线的情况下取得更好效果，提示“轻结构 + 强归纳偏置”可能优于“重结构 + 弱先验”。
- **记忆系统的瓶颈正在从“容量”转向“状态判定”**：长期多方对话的核心困难不是找不到相关文本，而是判断哪条文本代表**当前有效状态**。UPDATE/EXPAND 这种最小关系集，为“状态追踪”提供了一个可操作的中间表示，可迁移到代码评审、需求管理、临床病程记录等强演化场景。
- **压缩应以“关系”而非“长度”为单位**：在森林中按父节点未覆盖的新信息量分配预算，比均匀截断更符合“证据冗余度不均”的实际分布，这一思路可用于其他结构化上下文的预算分配。

## 10. 总体评价

论文把一个常被当作辅助特征的维度（时间）提升为记忆的核心表示，问题刻画（局部性 + 演化）与机制设计（发现 + 结构化 + 线性化）之间对应紧密，且以**免训练、查询条件式、低 token 成本**的方式实现，工程可行性高。实验在跨数据集、跨骨干、固定预算受控对比、噪声与元数据缺失鲁棒性、理论分析等维度覆盖较完整，主要结论（时间定位带来召回增益、结构组织带来可用性增益、关系语义带来增量）均有独立证据支撑。

主要不足在于：对元数据质量与时间尺度假设的敏感性缺乏系统检验，单父节点与禁止阶段倒退的约束在真实回滚/并行议题场景下可能过强，LLM 标注的一致性未报告，压缩收益缺少机制解释，以及 LLM-as-judge 与自适配基线带来的可比性折扣。总体而言，这是一篇**动机清晰、机制简洁、归因严谨**的工作，其“以时间结构组织证据、显式区分状态更新与支撑说明”的核心主张，对长期多方对话记忆系统具有较好的参考价值与可复用性。
