## 摘要
LLM智能体的记忆选择通常使用基于记录相关性或个体影响的检索排序。在证据冗余或联合必要的情况下，此类排序无法识别充分子集。我们研究逐决策记忆充分性：选择一个能保持全记忆行为的小子集。为区分搜索误差与模型误差，我们引入JointCoreBench——一个包含九种交互族、六个工作流领域、自然语言决策和精确充分集预言机的基准，以及JointCore——一种按相关性成本排序的组删除基线，它在测试单条记录之前先测试块。在6,912个精确条件下，按成本排序的JointCore在100.0%的情况下恢复最小成本充分集，将子集评估次数从30.00降至11.13（62.9%），并实现87.8%的活跃记忆节省。在四个12B-70B模型系列、每个模型432个任务上，其未加权平均为10.28次对16.00次模型查询，以及50.6%对43.1%的最小成本恢复率（相对于成本感知的单例删除）。在确定性主接口下，两种方法均保持全记忆行为。使用物理删除、UNKNOWN掩码、PENDING哨兵、反事实值和替代标签的测试识别出接口相关行为。JointCore是一个高效的基准基线；本研究并未确立可部署的记忆压缩。

## Abstract
LLM-agent memory selection often uses retrieval rankings based on record relevance or individual influence. Such rankings cannot identify sufficient subsets under redundant or jointly necessary evidence. We study per-decision memory sufficiency: selecting a small subset that preserves full-memory behavior. To separate search error from model error, we introduce JointCoreBench, a benchmark with nine interaction families, six workflow domains, natural-language decisions, and exact sufficient-set oracles, and JointCore, a relevance cost-ordered group-deletion baseline that tests blocks before individual records. On 6,912 exact conditions, cost-ordered JointCore recovers a minimum-cost sufficient set in 100.0% of cases, reduces subset evaluations from 30.00 to 11.13 (62.9%), and achieves 87.8% active-memory savings. Across four 12B-70B model families and 432 tasks per model, its unweighted mean is 10.28 versus 16.00 model queries and 50.6% versus 43.1% minimum-cost recovery relative to cost aware singleton deletion. Both methods preserve full-memory behavior under the deterministic primary interface. Tests with physical deletion, UNKNOWN masks, PENDING sentinels, counterfactual values, and alternative labels identify interface dependent behavior. JointCore is an efficient benchmark baseline; the study does not establish deployment-ready memory compression.

## 一、核心问题与研究动机

- **背景**：长时运行的 LLM 智能体不断积累观测、工具输出、约束与决策记录，记忆不能无限增长。LongMemEval、MemoryAgentBench 等基准表明，智能体在检索、跨会话更新、选择性遗忘上仍不可靠。
- **核心缺陷**：现有记忆选择方法大多基于**记录级相关性排序**或**个体影响力**（如逐条 leave-one-out）。这类"边际影响"视角在两类关键交互下失效：
  - **冗余证据（Redundant OR）**：多条记录各自都足以支持同一决策，单独删除任一条决策不变，逐条检测会误判所有记录都"不必要"，从而丢弃全部充分证据（论文 Proposition 1 给出构造性证明：k≥2 时每个 Δᵢ=0，但空集不充分）。
  - **联合必要证据（Synergistic AND）**：需要多条记录同时在场才成立，单独评分时每条都显得无用。
- **研究目标**：转向**逐决策记忆充分性（per-decision memory sufficiency）**——寻找一个小子集 S，使得 F(S)=F(V)，即**行为充分（behavioral sufficiency）**；并进一步追求**最小成本充分集**（注册成本最低）。
- **方法论难点**：真实智能体历史不暴露"哪个子集充分"，仅凭观测决策无法评估搜索方法。因此需要带**精确充分集 oracle** 的受控基准，以**分离搜索误差与模型判断误差**。

## 二、方法论

### 2.1 问题形式化

- 记忆记录集合 V={1,…,n}，每条记录有注册成本 cᵢ；F(S) 为保留子集 S 后的决策轨迹，F(V) 为全记忆参考。
- **行为充分**：F(S)=F(V)；**逻辑充分** G(S) 由任务规则定义；**最小成本充分集** C⋆ 为成本最低的逻辑充分解。
- 区分三类集合性质：inclusion-minimal（无充分真子集）、1-minimal（删任一条即不充分）、minimum-cost（成本最小）——前两者均不蕴含最小成本。
- 报告指标分离：behavioral retention、logical sufficiency、minimum-cost recovery、retained payload cost、selection cost。
- **Proposition 1**：对任意 k≥2，存在 k 条各自充分的记录，其全集中每条记录的 singleton effect Δᵢ=1[F(V\{i})≠F(V)] 全为 0，而空集不充分。

### 2.2 JointCore 算法（核心贡献之一）

- **核心思想**：把 delta debugging（Zeller & Hildebrandt, 2002）的思想迁移到"类型化记忆 + 决策保持"场景，**先整块测试、再二分细化**，用组删除替代逐条删除。
- **算法流程**：
  1. 初始化 S=V，将全部有序记录作为根组入 FIFO 队列；
  2. 出队组 G，比较 F(S\G) 与 F(V)；
  3. 若一致 → 从 S 中删除 G，**剪枝其所有后代组**；
  4. 若不一致 → 当 |G|>1 时二分入队，当 |G|=1 时保留该记录；
  5. 队列空或预算 Q 耗尽即停止；无效模型响应按"不一致"处理。
- **关键不变量**：对确定性评估器，F(S)=F(V) 在初始化时成立，且 S 仅在匹配评估后才改变，因此**返回集在预算耗尽时仍保证行为充分**（但不保证逻辑充分、最小成本或跨记忆表示的鲁棒性）。
- **复杂度**：二分定义一棵 n 叶、至多 2n−1 节点的二叉树，每节点至多评估一次，故 NJC(n,Q) ≤ min{Q, 2n−1}。注册预算 Q=256（精确阶段）、Q=64（模型阶段），分别超过 n=64 时的 127 与 n=16 时的 31 上界。最坏情况（每次非单例删除都改变决策）接近条件式单例删除的两倍开销。
- **搜索顺序**：固定开发规则 B=4，将语义 top-B 之外的记录置于连续低相关性前缀，top-B 记录按 payload 成本降序排列；前缀便于整块删除，降序固定后缀细化顺序。排序完全确定性、无学习成分。
