## 摘要
对于持久且个性化的对话智能体，记忆系统通过存储过去交互并检索相关信息，使其能够记住、更新并推理长历史。现有记忆系统通常遵循两种范式：扁平结构记忆和基于图的记忆。前者轻量，但将事件关系与状态更新留作隐式；后者显式建模记忆结构，但会带来额外构建成本，并在长历史中引入无关关系。为解决这些局限，我们提出 QGMem，一种受人类记忆启发的新型记忆构建与激活框架，其中经验被组织为事件，与查询相关的事件通过图建模为工作记忆。QGMem 将长对话历史转换为事件索引的原子记忆单元，以保留个体经验，并将相关单元整合为动态记忆痕迹，以保留状态轨迹和当前状态。当查询到来时，混合记忆检索收集互补的候选记忆，查询感知重排序激活最相关的单元作为紧凑工作记忆。为揭示工作记忆中的关系依赖并支持冲突感知推理，QGMem 将工作记忆组织为局部图，随后将其编码为图 token，并与文本工作记忆一起提供给 LLM，以提升答案生成过程中的证据利用。跨六个基准的实验验证了该框架，并在检索、多跳证据组合、冲突解决和超长对话推理方面表现出持续收益，且上下文紧凑、推理成本适中。

## Abstract
For persistent and personalized conversational agents, memory systems can enable them to remember, update, and reason over long histories by storing past interactions and retrieving relevant information. Existing memory systems typically follow two paradigms: flat-structured memory and graph-based memory. The former is lightweight but leaves event relations and state updates implicit, while the latter explicitly models memory structure but incurs additional construction cost and introduces irrelevant relations over long histories. To address these limitations, we propose QGMem, a novel memory construction and activation framework motivated by human memory, in which experience is organized into events and query-relevant events are modeled by graph as working memory. QGMem converts long dialogue histories into event-indexed atomic memory units that preserve individual experiences and consolidates related units into dynamic memory traces that retain state trajectories and current states. When a query arrives, hybrid memory retrieval gathers complementary candidate memories, and query-aware reranking activates the most relevant units as a compact working memory. To expose relational dependencies in the working memory and support conflict-aware reasoning, QGMem organizes the working memory as a local graph, which is then encoded as a graph token and provided to the LLM together with the textual working memory to improve evidence utilization during answer generation. Experiments across six benchmarks validate the framework and show consistent gains in retrieval, multi-hop evidence composition, conflict resolution, and ultra-long dialogue reasoning with compact contexts and moderate inference cost.

## 1. 核心问题与研究背景

- **应用背景**：个性化助手、陪伴式对话系统、任务型智能体需要在跨多轮、多会话的长期交互中记住用户偏好、人际关系、日程安排及其后续更新。这些信息无法全部放入 LLM 上下文，因此需要外部长期记忆机制：存储历史、跟踪状态演化、检索相关信息、并组织关系供生成使用。
- **现有两条技术路线的两难**：
  - **扁平结构记忆**（MemGPT、MemoryBank、FACT、Mem0、LightMem 等）：以轮次、会话、摘要或事实为单元，轻量易维护，可直接喂给 LLM；但**事件之间的关系与状态更新是隐式的**，难以区分“当前有效事实”与“已被取代的旧事实”。
  - **图结构记忆**（A-MEM、Associa、Zep、SG-Mem、EMem-G、LiCoMemory、GAM、HyperMem、APEX-MEM、MemORAI 等）：显式建模实体、事件、状态及其关系，支持关系推理；但**要在不断增长的全量历史上做关系抽取、对齐与维护**，构建成本高，且长历史中易引入大量与查询无关的关系；检索行为与全局图的构建方式强耦合。
- **另一层问题（生成侧）**：图记忆通常被序列化为三元组、路径或子图文本，拓扑被线性化，LLM 需从 token 中重建结构依赖，既消耗上下文又损失结构信号。
- **核心洞察与目标**：借鉴认知心理学的事件认知理论（人将连续经验切分为事件、在工作记忆中更新当前事件、从长时记忆中提取相关过往事件），提出**“持久存储 + 查询时关系组织”分离**的架构：长期记忆保存事件及其演化状态，工作记忆只对“查询相关事件”构建关系结构。目标是同时兼顾三点：**可验证的历史证据、显式暴露查询相关关系、保持紧凑的生成上下文**。

## 2. 方法论：QGMem 框架

整体由三个模块构成：事件中心记忆构建 → 查询感知工作记忆激活 → 图增强生成。

### 2.1 事件中心记忆构建（离线、一次性）

- **原子记忆单元（Atomic Memory Unit）**：按会话边界切分，会话内用**固定大小滑动窗口**（默认 6 轮、重叠 2 轮、步长 4 轮）扫描；重叠轮仅作代词/指代消解的背景，不允许从中抽取单元。每个单元表示**一个可独立检索的事件或状态**，若一个候选含多个可独立检索的关系，则拆分为多个单元（每个单元锚定一条完整结构化事实）。
  - 单元表示：`m = (c_m, d_m, E_m, P_m, T^f_m, T^u_m, f_m)`，即上下文无关摘要、源对话片段、实体集、地点集、**事实时间**、**话语时间**、结构化事实。
  - 两个设计要点：①**多视角事件匹配**——实体/地点/事实时间属性可从互补角度区分“话题相似但实体/时间不符”的记忆；②**双时间表示**——区分事实时间与话语时间（例：1 月 20 日说“昨天去了医院”，话语时间为 1/20，事实时间归一化为 1/19），支持时间敏感与冲突场景下的有效性判定。
- **动态记忆痕迹（Dynamic Memory Trace）**：把同一主体—关系的相关单元整合为状态轨迹。
  - 事实写作 `f_m = (a_m, p_m, o_m)`（主语、谓词、宾语）。用文本编码器分别算事实级、主语级、谓词级余弦相似度，取**三者最小值**作为关系分：`S_rel = min{s_f, s_a, s_p}`。取 min 的理由是“错误合并会污染整条轨迹，而未合并的单元仍可独立检索”——偏保守的设计。
  - 每个单元只检查其 **20 个最近的事实级邻居**（避免全量两两比较）；簇内要求任意两两关系分 ≥ `τ_r = 0.80`。
  - 由 LLM 整合器按时间排序、合并重复/等价状态，并区分三类关系：后出现的**不兼容值=更新（update）**、兼容细化=补充（supplement）、相互兼容=共存状态。痕迹表示为 `r_h = (ψ_h, H_h, s_h)`（代表关系、有序状态轨迹、最新有效状态）。
  - 查询时每个被检索单元仍链接其痕迹：痕迹向重排器与生成器提供状态轨迹，最新成员充当“当前状态代表”，从而**在保留源级粒度可验证性的同时连接远距离更新**。

### 2.2 查询感知工作记忆激活（两阶段）

- **混合检索（三通道互补）**：
  - 词法通道：BM25，保留姓名、日期、地点等精确线索；
  - 语义通道：稠密向量，覆盖别名与改写表达；
  - 事件属性通道：由解析器 `φ(q, t_q)` 抽取实体/地点/时间约束集，SemMatch 比对实体与地点，TimeMatch 比对 `(T^f, T^u)`，对非空约束取平均得 `S_ELT`。
  - 三路各取 top-n，用 **RRF（κ=60）** 按名次融合（无需跨通道分数校准），得到候选池 `C0`（n=100）。
- **查询感知重排**：为每个候选构造结构化“重排文档”（事实摘要、源对话、实体、地点、事实时间、话语时间、以及关联痕迹的状态轨迹），用 **Qwen3-Reranker-8B** 联合打分，在预算 k（最优 k=10）下取最高分者构成工作记忆 `M_q`；其排序同时用于图构建与答案生成。
- 效果：第一阶段保覆盖率，第二阶段把“完整、当前、与答案相关”的记忆集中到高名次，且上下文规模受控。

### 2.3 图增强生成

- **局部记忆图构建**：对 `M_q` 中每条事实 `(u, ρ, v)`，建主语实体节点、宾语值节点、以谓词为标签的有向边；经 `ν_ent(·)`、`ν_val(·)` 归一化使重复出现共享节点，得到 `G_q = (V_q, A_q)`。由于由固定预算的工作记忆诱导，**至多 k 条边、2k 个节点**（去重前），规模不随历史增长。
- **关系感知图编码**：节点用与语义检索共享的句向量（BGE-base-en-v1.5）初始化，谓词也用嵌入表示；堆叠 **L=4 层 TransformerConv**（H=4 头），注意力权重同时依赖邻居节点状态与**边谓词嵌入**，从而在消息传递中传播内容与类型化关系；L 层后做全局均值池化得 `g_q`，再经**两层非线性投影（768→2048→4096）**映射为 LLM 嵌入空间中的**图 token `z_q`**。
- **图文融合**：将 `z_q` 与序列化工作记忆的文本 token 序列 `h_t` 拼接为 `[z_q, h_t]`，连同查询送入**冻结的 LLM**，自回归生成答案；文本分支保留可读、可溯源的证据与时间/状态有效性信息，图分支补充结构信号。
- **训练目标**：只训练图编码器与投影器参数 ω（句编码器与 LLM 全部冻结，不使用 LoRA），以教师强制的 token 级负对数似然为目标；答案监督促使图表示保留对生成有用的关系信息。
- **骨干适配**：开源权重模型走“嵌入级图 token 注入”；API 型模型（如 GPT-4o-mini）嵌入空间不可得，则把工作记忆与局部图**序列化为文本**，接口层适配而保持构建/激活/图组织流程不变。
- **复杂度**：原子构建按轮数线性增长且可并行、跨查询摊销；痕迹整合每单元只查 20 邻居；查询时局部图构建与编码为 **O(k)**，与全量历史无关。

## 3. 实验设计

- **数据集/场景（六个基准，覆盖四类能力）**：
  - 精确检索：**LoCoMo**（N=1540，多会话对话的证据检索与组合）、**LongMemEval-S**（N=500，持久召回、推理与更新）；
  - 冲突解决：MemoryAgentBench 的 **FactConsolidation-SH**（N=400，单跳）与 **Fact-MH**（N=400，多跳）冲突事实选择；
  - 超长可扩展性：**BEAM-100K**（N=400）、**BEAM-500K**（N=700），并扩展到 **1M 与 10M token**。
- **对比方法（7 个）**：RAG（检索增强基线）；扁平记忆 Mem0、LightMem；图记忆 EMem-G、LiCoMemory、MR-Agent、AriadneMem。同一基准下使用相同问题与相同骨干。
- **评价指标**：
  - 答案质量：**LLM-as-judge 得分**（重复判定 10 次，报均值±标准差；BEAM 按其官方协议，9 项 nugget 能力 + Event Ordering 的归一化 Kendall τb，再宏平均）；**AlignScore-large 语义覆盖**（10,000 次 bootstrap 估计不确定性）。
  - 检索质量：R@10、P@10、**Sufficiency@10**（检索集合整体是否足以支撑答案，区别于“命中任一相关项”）、nDCG@10；由 GPT-4o-mini 判官标注覆盖/相关子集，金标证据对所有系统不可见。
- **骨干模型**：Qwen3-8B（主实验）、Llama3.1-8B-Instruct、GPT-4o-mini（闭源、走文本序列化接口）。
- **训练数据**：来自 ConvoMem 的三类确定性答案样本（user_evidence、assistant_facts_evidence、changing_evidence，按 5:3:4 采样），1,200 个 case / 2,138 个 QA；跑完整管线后仅保留最终答案正确的 **1,634** 条图接地 QA 作为监督；声明未使用 LoCoMo 或 LongMemEval-S 样本，按 train/val/test 划分，仅用验证集选 checkpoint。
