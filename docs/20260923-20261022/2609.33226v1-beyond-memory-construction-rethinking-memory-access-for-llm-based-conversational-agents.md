## 摘要
记忆是对话智能体的核心组件，使其能够在长程交互中保持连贯且具备上下文感知的行为。近期方法通常依赖基于LLM的记忆构建，即将原始交互改写为结构化记忆单元，随后通过RAG流水线进行检索。尽管在受控环境中有效，我们表明该范式在长时程、高熵对话中会失效：随着上下文长度和信息复杂度增长，记忆构建变得日益有损且不稳定，并且由于重复调用LLM而带来高昂成本。为解决这些局限，我们提出Threader，一种将重点从记忆构建转向对原始交互进行高效、结构感知访问的记忆系统。Threader不再改写交互，而是将其保留为一等记忆，通过轻量级增量分割将其组织为主题连贯的片段，并通过多视图表示实现准确检索。在查询时，它执行多信号检索，将片段级访问与局部证据匹配相结合，从而确保完整性与连贯性。大量实验表明，Threader持续提升答案准确率和证据召回率，同时显著降低记忆构建开销。

## Abstract
Memory is a core component of conversational agents, enabling coherent and context-aware behavior over long interactions. Recent approaches commonly rely on LLM-based memory construction, where raw interactions are rewritten into structured memory units and later retrieved via a RAG pipeline. While effective in controlled settings, we show that this paradigm breaks down in long-horizon, high-entropy conversations: memory construction becomes increasingly lossy and unstable as context length and information complexity grow, and incurs prohibitive cost due to repeated LLM invocation. To address these limitations, we propose Threader, a memory system that shifts the focus from memory construction to efficient, structure-aware access over raw interactions. Instead of rewriting interactions, Threader preserves them as first-class memory, organizes them into topic-coherent segments via lightweight incremental segmentation, and enables accurate retrieval through multi-view representation. At query time, it performs multi-signal retrieval that combines segment-level access with localized evidence matching, ensuring both completeness and coherence. Extensive experiments demonstrate that Threader consistently improves answer accuracy and evidence recall, while significantly reducing the memory construction overhead.

## 1. 核心问题与研究动机

- **背景**：基于 LLM 的对话智能体需要长期记忆来维持连贯、个性化、上下文感知的行为。当前主流范式是"外部记忆 + RAG"：先用 LLM 把原始交互**重写/摘要/抽取**为结构化记忆单元，再在回答新问题时检索。
- **核心问题**：作者通过实证指出，这种"**构建期抽象（construction-time abstraction）**"在**长时程、高熵**真实对话中会失效，表现为两大缺陷：
  - **记忆构建有损且不稳定**：随着会话变长、信息纠缠加剧，构建出的记忆单元数量和总 token 量反而下降（Mem0 在 1→8 个会话拼接后准确率从 55.00% 跌至 5.00%），大量查询相关证据被"部分保留"或"完全丢失"。
  - **构建成本高昂**：为 100K token 的交互构建记忆时，Mem0/MemU/EverMemOS/A-Mem 的 LLM 输入 token 分别膨胀到原始的 **2×、9×、13×、21×**。
- **整体含义**：问题根源不在检索环节，而在"构建期抽象"本身。论文主张**范式转移**：不再把交互"转写"为记忆，而是将**原始交互作为一等记忆（first-class memory）**，把重点放到**查询时的高效、结构感知访问**上。由此引出关键挑战：如何在长且混杂的历史中，**精确定位完整**的查询相关证据？

## 2. 方法论：Threader

**核心思想**：以"保留原始交互 + 结构化组织 + 多信号检索"替代 LLM 重写，实现无损、低成本、可流式处理的记忆访问。系统由三个组件构成。

### 2.1 增量主题连贯分割（Incremental Topic-Coherent Segmentation）

- 将对话按会话组织为 `C = {S1,...,Sn}`，每个会话为有序轮次序列；目标是切成连续、主题一致的片段 `sk`。
- 把分割建模为**逐轮二元决策问题**：维护当前片段 `s′`，对到来的轮次 `t′`，输入 `x = Concat(s′, [SEP], t′)`，预测 **CONTINUE**（追加）或 **SEGMENT**（结束当前片段、以 `t′` 开新片段）。
- 该形式**完全在线、无需回看历史**，满足"轻量 + 增量"两个要求。
- **实现**：用轻量 BERT 编码器 + 线性分类头，交叉熵训练。训练标签来自两类信号：
  - **硬标签**：LongMemEval 的会话边界（粗粒度结构锚点）；
  - **软标签**：GPT-4.1-mini 标注的会话内细粒度主题边界。
- 训练样本按 CONTINUE 样例（同片段内前文 + 下一轮，标签 0）与 SEGMENT 样例（当前片段 + 下一片段首轮，标签 1）构造，最终得到 **15,260 条边界决策样本（约 13M WordPiece token）**，原始类别比约 **4:1**。

### 2.2 多视图片段表示（Multi-View Segment Representation）

- 动机：证据异质——用户话语常含稀疏但关键的持久事实，助手回复冗长且生成性强；单一 embedding 会让助手内容"淹没"弱但关键的用户信号。
- 对每个片段 `si` 构造三个视图并用**共享编码器** `fenc` 编码：
  - **用户视图** `x(u)`：拼接所有用户发言；
  - **助手视图** `x(a)`：拼接所有助手发言；
  - **完整视图** `x(f)`：按原始顺序拼接完整交互。
- 得到 `e(v) = fenc(x(v)), v ∈ {u,a,f}`，实现证据解耦与互补。

### 2.3 多信号证据检索（Multi-Signal Evidence Retrieval）

采用"粗到细"两阶段 + 三类互补信号：

- **稠密语义信号**：对三视图相似度加权求和
  `score(e)_i(q) = Σ_{v∈{u,a,f}} wv · cos(z(q), e(v)_i)`，且 `Σwv = 1`。
- **词法信号**：`score(b)_i(q) = BM25(q, si)`。
- **交叉编码器信号**：`score(r)_i(q) = Rerank(q, si)`。

**Stage I 高召回片段召回**：取稠密 Top-K1 与 BM25 Top-K1 的**并集**构成候选池 `C`，兼顾语义覆盖与词法匹配。

**Stage II 证据级精化**：

- 将稠密匹配从片段级下探到**消息级**：对候选片段内每条用户/助手消息计算与查询的余弦相似度，取 Top-K2 求平均得到精化稠密分 `score~(e)_i`；
- 与 BM25 融合：`score(h)_i = score~(e)_i + β·score(b)_i`（融合前做 min-max 归一化）；
- 再与交叉编码器分数融合：`score_i = α·score(h)_i + (1−α)·score(r)_i`；
- 最终按 `score_i` 选 Top-K。**注意**：打分是消息级细粒度，但**检索单元仍是片段级**，以保证下游推理的篇章连贯性与时间一致性。

## 3. 实验设计

- **数据集 / Benchmark**：
  - **LongMemEval**：500 个 QA，平均每会话约 2,160 token，覆盖单会话用户信息回忆、单会话助手信息回忆、单会话偏好、多会话推理、知识更新、时间推理六类；用 **LLM-as-a-Judge**（GPT-4.1-mini，严格四分类：correct / partially_correct / incorrect / insufficient，仅 correct 计对）。
  - **PersonaMem**：589 个 QA，平均每会话约 **26,165 token**，侧重长程个性化，覆盖泛化到新场景、偏好对齐推荐、回忆用户共享事实、回忆用户提及事实、回忆更新原因、建议新想法、追踪偏好演化七类；用 **exact match**。
  - 未采用 LoCoMo，理由是其会话过短（约 586 token）且为模拟双人对话，与目标场景不符。

- **公平性控制**：所有基于 LLM 构建的方法共享同一构建模型（GPT-4.1-mini），所有方法共享同一响应模型；基线尽量沿用官方实现与默认配置。

## 6. 主要结论与发现

- **准确率全面领先**：
  - LongMemEval：Threader 达 **80.60（GPT-5-nano，↑3.33%）** 与 **90.60（GPT-5-mini，↑6.84%）**，均为最优；
  - PersonaMem：达 **63.16（↑4.50%）** 与 **69.95（↑7.29%）**，均为最优。
- **证据密集型任务增益最大**：Temporal-Reasoning 提升 6.94%（nano）/11.02%（mini），Knowledge-Update 提升 5.80%（mini）；PersonaMem 上 Generalize-New-Scenario 提升 25.00%/17.07%，User-Shared 提升 2.27%/8.33%。
- **在需要抽象聚合的任务上不占优**：Single-Session-Preference、Preference-Evolution、New-Ideas、Update-Reason 等出现负增益，说明"证据保留"与"偏好抽象"之间存在互补权衡。
- **成本大幅下降**：构建 100K token 仅需 **18.33 s**、**0 次

LLM 调用（构建阶段无需 LLM 参与），而 Mem0/MemU/EverMemOS/A-Mem 在同等规模下分别产生约 2×/9×/13×/21× 的输入 token 膨胀；查询阶段延迟与单次查询费用亦显著低于 LLM 构建型基线，且随历史长度增长近似线性、无构建期二次膨胀。

- **分割器轻量且可迁移**：仅用 BERT 级编码器 + 线性头即可在线逐轮决策；仅在 LongMemEval 上训练、零样本迁移到 PersonaMem（会话长度约为前者 12 倍）仍有效，说明"主题连贯边界"信号具有跨域泛化性。骨干对比（BERT/RoBERTa/ModernBERT）与阈值扫描显示性能对骨干不敏感，主要收益来自"是否分割"而非"用哪个编码器"。

- **消融结论**：
  - **分割**是必要条件：无分割或固定窗口切分（Chunk-300～2K）均明显劣于主题连贯分割，固定窗口越大越易把无关内容混入同一检索单元，越小则割裂证据；
  - **多视图**中用户视图权重最高（`wu=0.5`），去掉用户视图或退化为单一完整视图均有稳定下降，验证"助手冗长内容淹没稀疏用户信号"的假设；
  - **检索信号**三者互补：去掉 BM25 或 Rerank 的降幅大于去掉稠密 embedding，两两组合消融显示 BM25 对精确实体/时间线索、Rerank 对语义近似干扰项的区分尤为关键；去掉消息级稠密精化（w/o Msg.-Emb.）亦有可测下降；
  - **检索粒度**：以片段为检索单元、以消息为打分单元的组合优于纯消息级检索，说明"细粒度打分 + 篇章级返回"兼顾精度与下游推理连贯性。

- **超参数稳健性**：Top-K 在合理区间内性能变化平缓（LongMemEval 约 10–16、PersonaMem 约 6–10 为较优平台区）；视图权重与融合权重 β/α 的热力图显示存在较宽的高性能区域，而非尖峰，说明方法对调参不敏感。

- **抽象类任务的诊断结论**：证据审计显示，在 Single-Session-Preference 等任务上，Threader 的证据召回率可达 100%（即相关原始证据确实被检索到），但准确率仍为 96.67%（接近但未超越最优基线），说明瓶颈已从"检索不到"转移到"响应模型能否从原始证据中完成归纳抽象"。换用更强响应模型（GPT-5.6-sol）的受控对比进一步表明，此类任务的差距随响应模型能力提升而收窄，佐证"保留原始交互 + 强推理模型"路线的可行性。

- **总体论断**：记忆系统的瓶颈应从"构建期如何压缩"转向"访问期如何精准定位"；原始交互作为一等记忆，配合结构化组织与多信号检索，可在**准确性、成本、可流式部署**三方面同时占优，代价是对需要抽象聚合的任务需依赖更强的下游推理能力（或与轻量抽象层互补）。

## 7. 局限与不足

- **抽象类任务非最优**：在偏好抽象、偏好演化追踪、新想法生成、更新原因回忆等任务上出现负增益，说明"无损保留"并不天然等价于"更好用"，缺乏显式的归纳/抽象机制。
- **依赖下游模型能力**：证据已召回但答案仍可能出错，性能上限部分由响应模型决定，方法本身不解决"从证据到结论"的推理问题。
- **检索侧条件不完全对等**：基线保留各自默认嵌入模型，Threader 使用轻量多语 MiniLM，跨方法比较中嵌入能力差异未被完全控制。
- **成本比较不完整**：MemOS 因黑盒接口未纳入成本归因；全实验的总算力/总费用未披露。
- **分割监督依赖标注**：软标签由 GPT-4.1-mini 生成，存在教师模型偏差；硬标签依赖数据集的会话边界，对无边界信息的场景需另行设计。
- **数据集覆盖有限**：仅两个 benchmark，且均为英文；多语、多模态、多人协作对话等场景未验证。

## 8. 对领域的启示

- **范式层面**：为"记忆构建 vs 记忆访问"的权衡提供了系统性实证，指出构建期有损压缩在长时程高熵对话中的结构性缺陷，主张把研究重心转向访问侧。
- **工程层面**：给出可流式、低成本、无需 LLM 构建的完整方案（在线分割 + 多视图 + 粗到细多信号检索），对实际部署友好。
- **评估层面**：采用四分类 LLM-as-Judge 降低假阳性、统一构建/响应模型、补充成本与延迟指标，为记忆系统评测提供了较可复用的协议参考。
- **开放问题**：如何在不牺牲证据完整性的前提下引入轻量抽象层以补齐偏好归纳类任务；如何在多语/多模态/多人场景下保持分割与检索的有效性；如何将"访问侧优化"与"构建侧压缩"做自适应组合。
