## 摘要
关于智能体历史的问题往往需要聚合事件，而仅靠检索无法解决。我们将保留来源的证据访问与可执行聚合相结合。轨迹记忆（TM）保留原始轨迹，并在提问时构建可按来源寻址的阅读视图。TallyMem 通过可复用的事件账本、模型生成的事件规范以及确定性执行对其加以增强。在来自99个留出MINTEval仓库的776个问题上进行针对具体提交的适配后，TallyMem将Qwen3-32B的精确匹配率从35.2%提升到49.0%，相较TM提升13.8个百分点；在三个读取器上的增益为12.8–13.9个百分点。一项受控探测使用从原始日志中独立解析出的事件集，在无路由情况下取得11.0个百分点的增益，从82.8%提升到93.8%。在完整的AMA-Bench上，带路由的系统仅带来较小的1.3个百分点增益，从69.8%提升到71.1%。这些结果支持在需要组合事件的任务上采用可执行聚合，其收益取决于任务和事件规范，而事件规范是我们诊断分析中最大的残余系统错误类别。

## Abstract
Questions about an agent's history often require aggregating events, which retrieval alone does not resolve. We combine source-preserving evidence access with executable aggregation. Trajectory Memory (TM) retains the original trajectory and constructs a source-addressable reading view at question time. TallyMem augments it with a reusable event ledger, model-generated event specifications and deterministic execution. With a commit-specific adaptation on 776 questions from 99 held-out MINTEval repositories, TallyMem raises Qwen3-32B exact match from 35.2% to 49.0%, a 13.8-point gain over TM; gains span 12.8-13.9 points across three readers. A controlled probe with event sets parsed independently from raw logs shows an 11.0-point gain, from 82.8% to 93.8%, without routing. On full AMA-Bench, the routed system yields a smaller 1.3-point gain, from 69.8% to 71.1%. These results support executable aggregation on tasks that require combining events, with benefits dependent on the task and event specification, the largest residual system-error category in our diagnostic analysis.

- **核心问题**：作者将智能体记忆问答拆成两个彼此独立、但常被混为一谈的需求：
  - **证据访问（Access）**：决定答案的原始步骤必须“原样、按序”进入阅读上下文，保留动作、观察结果和位置。
  - **事件聚合（Aggregation）**：当答案需要组合大量事件时，必须正确选择事件并对其计数、分组、排序或列举。
- **关键诊断**：常见记忆系统通过摘要、抽取事实、嵌入检索或知识图谱来“改写/压缩”历史，容易丢失客观信息和因果顺序；而即使把完整历史交给长上下文模型，模型仍会在高聚合负载下大量数错。例如论文示例中，Qwen3-32B 在 150 步轨迹上对 8 类动作有 5 类计数错误。

## 2. 方法论

### 2.1 总体思想

论文提出两个互补组件，共享同一份原始历史：

- **Trajectory Memory（TM）**：坚持“延迟证据选择”，写入时不改写轨迹，提问时才根据问题构建有预算、保序、可溯源的阅读视图。
- **TallyMem**：在 TM 之上增加可复用事件账本、模型生成的事件规范（查询计划）和确定性执行器，把聚合结果及支持步骤 ID 附加到阅读视图中。

形式化地，问题答案可写为对事件集合的聚合：

- 事件集合 \(S^\star(q)=\{i\in I_H\cap I_q:\phi_q(a_i,o_i)=1\}\)，其中 \(I_q\) 是问题指定的步骤范围，\(\phi_q\) 是事件谓词；
- 答案为 \(g(S^\star(q))\)，\(g\) 可为计数、分组、排序或列举；
- 聚合负载定义为 \(|S^\star(q)|\)，即答案需要组合的事件数量。

最终上下文为 \(C_q=R_q\oplus D_q\)：\(R_q\) 是 TM 的阅读视图，\(D_q\) 是 TallyMem 的计算证据。

### 2.2 Trajectory Memory（TM）

- **无损写入**：归档 \(A=\mathrm{Archive}(H)\) 逐字保存每个非空步骤及原始步骤 ID。源引用 \(r=(i,f,[u,v))\) 指向第 \(i\) 步字段 \(f\)（action 或 observation）的字符区间，满足 \(\mathrm{text}(r)=A[i,f][u:v]\)，保证展示片段可回溯到原始记录。
- **文件事件索引**：对编辑器工具调用解析 `str_replace_editor` 等动作，以精确路径建立文件节点，将 read/write 事件与文件节点连接；只有观察中出现工具回执才确认操作成功，不支持或不确定的调用仍保留在原始归档中。
- **提问时锚定选择**：
  - 构造锚点集合 \(A_q=E_q\cup \mathrm{supp}(\mathrm{top}_k s(\cdot,q))\)，其中 \(E_q\) 是问题显式命名的步骤，评分 \(s(x,q)=|T(q)\cap T(x)|+\beta(x,q)\)，\(\beta\) 奖励显式命名的步骤和实体。
  - 在预算 \(B=26k\) tokens 内贪心接纳步骤：先命名步骤，再按到最近锚点的距离排序；锚点附近字段保留更宽字符上限（4,000 字符），远处步骤 1,200 字符。
  - 按时间顺序渲染，标记被省略步骤和截断字段。TM 构建与检索均**不调用模型**。
- **固定计数器**：TM 还包含一个关键词触发的动作计数器（如“how many times”），这是其唯一的固定聚合，也是后续消融和诊断的对象。

### 2.3 TallyMem：账本 + 类型化事件规范 + 确定性执行

- **事件账本**：写入时把归档转为关系 \(L=\Phi(A)\)，每步一行，字段包括步骤 ID、工具、规范化动作、原始动作、目标、结果、状态变化和参数差分 \(\Delta\)。
  - 机械字段由程序抽取；目标、结果和变化由模型在**不看问题**的情况下分块标注。
  - 结果标注必须包含观察中可验证的引文；变化要求步骤成功；不确定标注不会删除行。
- **类型化查询语言**：一个计划 \(\pi=(p_1,\dots,p_k)\) 最多包含 4 个子查询，每个 \(p=(I,\phi,\omega)\)：
  - \(I=[lo,hi]\) 为步骤范围，可有开边界；
  - \(\phi(e)=\bigwedge_{f\in F}\bigvee_{t\in T_f}[t\sqsubseteq e.f]\)，即字段上的字面量合取/析取，采用大小写不敏感子串匹配（结果字段用相等匹配）；
  - 操作包括 `count`、`list`、`first/last`、`group_f`（分组计数）和 `timeline`。
- **编译**：除共享答案模型外，TallyMem 在提问时额外调用一次模型，将问题编译为计划 \(\pi=\mathrm{Compile}(q,\mathrm{catalog}(L))\)；catalog 汇总工具、目标和变化属性，使过滤器使用账本自身词表。范围仅来自问题中的显式边界，否则默认全轨迹。
- **有据执行**：
  - 执行前检查每个过滤词是否在对应字段中出现、匹配集是否非空；失败子查询被丢弃，有效兄弟查询保留。
  - 执行器在全部账本行上计算，线性时间；结果包含操作、过滤条件、匹配步骤数、计算值和支持步骤 ID，渲染预算 6,000 字符。
  - 对无匹配的 list/timeline 查询可放宽一次并标记为 relaxed。
- **回答与路由**：
  - 若有非空计算证据，则 \( \hat y=F_\theta(q,R_q\oplus D_q)\)；否则退化为 TM 回答。
  - 路由器不增加模型调用：AMA 使用负载阈值 \(\gamma_{\text{load}}=\mathbf 1[\ell(q,H)>15]\)；MINTEval 使用 \(\gamma_{\text{cov}}=\mathbf 1[\ell>15\lor c(q,H)=0]\)，其中 \(c\) 表示计算证据涉及的步骤是否全部被 TM 无截断展示。

## 3. 实验设计

### 3.1 数据集与场景

- **受控聚合探针**：从 AMA-Bench 的 30 条具身和 36 条软件轨迹生成 645 个问题，覆盖 16 个模板、6 种操作、3 个步骤边界和两种措辞。答案和事件集 \(S^\star\) 完全从原始日志解析，不使用账本、编译器或模型。
- **诊断集**：630 个规则选定的常见问题，用于五读者比较、负载分层和误差分析；438 个问题有可定义负载。

- **长上下文阅读**：直接读取原始轨迹，超预算时截断。

- **TM**：保留源证据的检索视图。
- **TallyMem**：主系统及无路由、TallyMem-lite（零生成账本）、计划自一致性、改进编译器、规则路由等变体。
- **其他读者**：Qwen3-32B、gpt-oss-120b、Qwen3-8B、Qwen3.6-27B、Qwen3-235B-A22B-2507。
