## 摘要
当前，智能体在不同任务之间大多仍处于无状态，这限制了它们从先前交互中持续改进的能力，也使记忆对于长程智能体行为至关重要。现有记忆方法试图复用过往经验，但大多数依赖单一记忆表示（例如轨迹、反思、技能、结构化知识），其有效性会随任务分布而变化。重新审视这一设计空间，我们评估了13种记忆方法，发现没有单一方法能够在各基准上普遍适用，这揭示了管理异构记忆提供者的潜力。我们将智能体记忆建模为一个路由问题：由记忆智能体决定从哪个记忆提供者检索、是否注入短期记忆，以及哪些提供者应存储产生的经验。基于这一视角，我们提出MemAgent，其具有内容感知的路由架构和训练数据合成流水线。该路由架构结合了检索前的内容感知探测、执行期间的短期记忆门控以及选择性多提供者存储，而训练流水线则为路由决策合成阶段特定的监督信号。在GAIA、WebWalkerQA和xBench-DS上，MemAgent将平均准确率提高了10.0%，并在所有三个基准上优于每一种单一记忆方法。这些增益仅带来不到0.3%的路由开销，并使平均任务步数减少12%。

## Abstract
Current agents remain largely stateless across tasks, limiting their ability to continually improve from prior interactions and making memory essential for long-horizon agentic behavior. Existing memory methods seek to reuse past experience, but most rely on a single memory representation (e.g., trajectories, reflections, skills, structured knowledge) whose effectiveness varies across task distributions. Rethinking this design space, we evaluate 13 memory methods and find that no single method generalizes across benchmarks, revealing the potential of managing heterogeneous memory providers. We formulate agent memory as a routing problem in which a memory agent decides which memory provider to retrieve from, whether to inject short-term memory, and which providers should store the resulting experience. Based on this perspective, we propose MemAgent, featuring a content-aware routing architecture and a training-data synthesis pipeline. The routing architecture combines content-aware probing before retrieval, short-term memory gating during execution, and selective multi-provider storage, while the training pipeline synthesizes phase-specific supervision for routing decisions. Across GAIA, WebWalkerQA, and xBench-DS, MemAgent improves average accuracy by 10.0% and outperforms every individual memory method across all three benchmarks. These gains come with less than 0.3% routing overhead and a 12% reduction in average task steps.

## 一、核心问题与研究动机

- **背景**：LLM 智能体已从单轮问答扩展到长程任务（网页研究、多模态推理、工具调用），但绝大多数智能体**跨任务无状态**——每次调用都从零开始，无法复用过往经验，这是"持续改进"的根本障碍。
- **现状**：现有记忆增强方法（轨迹摘要、反思洞察、结构化知识、工作流模板、过程脚本、可执行技能等）各自只承诺**单一记忆表示**，且多在各自的"主场"基准上单独评测。
- **关键实证发现**：作者将 13 种代表性记忆方法统一为"记忆提供者"接口，在 GAIA / WebWalkerQA / xBench-DS 上逐一评测，发现**没有任何一种方法能在多个基准上同时最优**（如 AWM 在 GAIA +6.1% 但在 WebWalkerQA −0.6%；ExpeL 在 WebWalkerQA +7.6% 但在 GAIA 仅中游）。
- **机会量化**：一个"事后 Oracle"（只要任一提供者解出即算成功）平均准确率达 **89.6%**，远超最佳单一提供者 **71.0%**；13 个提供者中有 10 个各自独解过至少一个任务。
- **研究重述**：因此智能体记忆的关键问题，与其说是"找到一种最优记忆格式"，不如说是**在异构记忆提供者池上做路由决策**；且路由应基于"实际检索到的内容 + 各提供者的迁移偏好"，而非任务表层相似度。

## 二、方法论

### 2.1 核心思想

引入一个独立的**记忆智能体 A_M**，在任务智能体 A_T 的记忆生命周期中做三类决策，把"记忆表示之争"转化为"推理时的路由策略学习"问题。

### 2.2 问题形式化

- 任务 τ 执行轨迹 ξ_τ = (s₀,a₀,o₀,…,s_T,a_T)，二值结果 y_τ ∈ {0,1}。
- 三阶段决策（策略 A_M(d|c)，目标为最大化 E_τ[y_τ]）：
  - **BEGIN**：执行前从提供者池 P 中选择一个长期提供者 p，检索跨任务经验并注入 A_T 的 system prompt；
  - **IN**：每一步 t 决定是否注入结构化**短期工作记忆**（QUERY / NO_OP）；
  - **END**：任务结束后选择子集 S ⊆ P 存储轨迹 ξ_τ。
- 提供者池含 K 个异构提供者，统一 `retrieve` / `store` 接口（路由策略与提供者内部实现解耦）；作者另贡献两个提供者：图结构长期记忆 **InsightGraph**（洞察节点 + 同任务边/相似概念边，混合 TF-IDF+语义检索后做图扩展，边权用贝叶斯成功率自适应调整）与**规则式短期记忆提供者**（抽取已验证事实/URL 历史/搜索历史，带容量与显示阈值）。

### 2.3 内容感知路由架构（三阶段）

- **BEGIN：内容感知探测（probe）**——先对所有提供者并行发起轻量检索，得到"片段预览"；**刻意剥离检索分数**（各提供者分数量纲不可比，保留会诱导模型走"选最高分"的捷径），并对候选提供者**随机打乱**以消除位置偏置。
- **IN：短期记忆门控**——上下文含任务 q、步序 t、短期记忆摘要、最近工具调用与观测，判断注入是否有实质帮助（避免过度查询）。
- **END：选择性多提供者存储**——上下文含轨迹摘要、任务成败、各提供者的"存储契约"描述（含 success-only / all-outcome 门控标注），通常选择 3–8 个提供者。

### 2.4 训练数据合成流水线（无金标准路由标签）

- **强制探索**：对每个训练任务，强制轮流路由到每个提供者，并变化 IN 动作（QUERY / NO_OP），仅覆盖记忆路由、A_T 正常执行，得到 Ξ = {ξ_τ^(p,a)} 及对应结果 y，从而在控制任务难度的前提下做提供者间比较。
- **逐决策奖励（三路互补信号）**：
  1. **任务正确性（BEGIN）**：路由到 p ∈ P⁺_τ（成功提供者集合）得正奖励；并按"可区分性"加权——仅当 P⁺_τ 是 P 的**非空真子集**时信号最强。
  2. **LLM-as-Judge 因果归因（BEGIN / IN）**：对每次决策的上下文与后续动作打分，按维度加权聚合 r_d = Σ w_i·ŝ_i，ŝ_i 对正向维度取 s_i/s_max、负向维度取 1−s_i/s_max，权重位于单纯形上（BEGIN：Utilization 0.6 / Relevance 0.4；IN-QUERY：Helpfulness 0.4 / Progress 0.4 / Noise 0.2↓；IN-NOOP：Appropriateness 0.5 / Progress 0.3 / Missed Opportunity 0.2↓，均为 0–5 分）。
  3. **下游复用奖励（END）**：r_end = ½·min(1, |T_{>τ}^(p)|/H) + ½·下游成功率，H=5 为饱和常数，衡量"存下的记忆是否真的被后续任务检索并促成成功"。
- **奖励过滤式 SFT 数据构造**：
  - BEGIN：若 P⁺ 为真非空子集→保留所有成功路由；若全部成功→按 judge 奖励取 top-k；若全部失败→丢弃；r_d=0（空/无关检索）丢弃。
  - IN：r_d ≥ ε_IN 保留；END：r_end ≥ ε_END（0.5）保留。
- **SFT 训练**：LoRA 微调，仅在结构化决策 token 上计算交叉熵（prompt token 掩码），并按**任务级划分**训练/验证集，防止同一任务的多阶段决策跨集泄漏。

### 2.5 推理流程（Algorithm 1）

并行探测全部提供者 → A_M 选 p* 并注入检索结果 → 每步更新短期记忆并由 A_M 决定 QUERY/NO_OP → 任务结束由 A_M 选择提供者子集写入。
