Abstract. Conversational Query Rewriting (CQR) turns a context de-pendent user turn into a standalone query for a retriever, and most meth-ods do this in a single step from the dialogue history before retrieving once. The rewrite is therefore fixed before any corpus evidence is available to correct its reference resolution or its vocabulary. We recast CQR as a sequential retrieval problem: an agent rewrites the current turn, retrieves, and conditions its next rewrite on the returned passages. The agent acts in a typed space of three rewriting operations, resolving conversa-tional intent into a standalone query, generating lexical reformulations, or synthesizing pseudo-documents for document-to-document matching, together with a stop action that ends the episode. We train the policy with supervised fine-tuning followed by reinforcement learning against a single retrieval-quality reward, using no human rewrite annotations. Across TopiOCQA and QReCC, the agent outperforms several retrieval-aligned baselines, while remaining effective across retrieval backends and generalizing to the CAsT benchmarks without additional training. Fur-ther analysis shows that, through retrieval-reward optimization alone, the learned policy develops a behavior of grounding pseudo-documents in passages retrieved by earlier steps, substantially improving retrieval. 

Keywords: Query Rewriting · Retrieval Feedback · LLM Agents 

## 1 Introduction 

Conversational search systems must handle queries whose meaning depends on prior turns [36,57]. A question such as “when was it released?” cannot be re-solved without the entities and topics established earlier in the conversation. Conversational Query Rewriting (CQR) transforms the current turn into a self-contained query that an existing retriever can process, and it is the standard interface between conversational systems and retrieval infrastructure [2,7,45,55]. Most CQR methods produce a single rewrite from the conversational his-tory and issue it directly to the retriever. This includes both supervised rewrit-ers trained on human annotations [25,45,55], and recent reinforcement learning

methods that optimize rewriting from retrieval rewards. ConvSearch-R1 [61], for example, learns to rewrite using retrieval feedback but still makes a single rewriting decision before seeing any retrieved documents. Consequently, these methods cannot adapt the query to the language and entities used in the tar-get corpus. Using retrieval results to inform a subsequent query is, however, a long-standing idea in information retrieval. Pseudo-relevance feedback methods use terms from top-ranked documents to expand the initial query for a subse-quent retrieval [11,40,20]. This principle has also been applied to conversational search, where retrieved documents are used to expand or refine conversational queries [26,38]. Such approaches typically rely on predefined feedback mecha-nisms, fixing how information from retrieved documents is incorporated into the subsequent query rather than learning this process from retrieval outcomes. Recent agentic search systems extend this iterative paradigm by alternating between search and reasoning until enough evidence is gathered to answer a question [15,44]. They are typically trained and evaluated for end-to-end question answering, where retrieval is an intermediate step. How a conversational query should be reformulated after observing retrieved evidence, and how successive retrievals can progressively refine it, remains comparatively unexplored. In this work, we formulate conversational query rewriting as a sequential re-trieval problem. An agent repeatedly reformulates the current turn, issues each reformulation to the retriever, and uses the returned passages as feedback for its next decision. It chooses among three typed rewriting operations: (i) resolving conversational intent into a self-contained query, (ii) generating lexical refor-mulations, and (iii) synthesizing pseudo-documents for document-to-document matching [9]; it can also issue a stop action that ends the episode. We train the policy with supervised fine-tuning followed by reinforcement learning, using retrieval quality as the only objective and no human rewrite annotations. We first evaluate results in the standard in-domain setting, training and eval-uating on TopiOCQA and QReCC with BM25, and comparing against existing retrieval-aligned CQR methods under the same setup. We then test general-ization across retrieval backends, by replacing BM25 with a dense retriever at inference time. Finally, we test zero-shot transfer by evaluating the TopiOCQA-and QReCC-trained models on TREC CAsT without further training. Across these settings, the multi-step agent improves over multiple baselines, with further analysis showing that retrieval-reward optimization alone leads the learned pol-icy to progressively ground its reformulations in corpus evidence: it first resolves the query intent, optionally refines its lexical formulation, and finally generates pseudo-documents conditioned on passages retrieved by earlier steps. 

## 2 Related Work 

Conversational Query Rewriting. Conversational search requires resolving the context dependence of user turns before retrieval [36,57]. One line of work trains conversational dense retrievers that encode the full dialogue history into a query representation [24,30,32,56], which couples context resolution to a retriever that Multi-Step Query Rewriting via Corpus Feedback 3

must itself be trained. Conversational query rewriting instead produces a stan-dalone query that any off-the-shelf retriever can consume, which is the setting we adopt. Early rewriters learned from human rewrites collected in datasets such as CANARD, QReCC, and CAsT [2,5,7], either as sequence-to-sequence generators [25,45,55] or as term selectors [46]. Since human rewrites are written for readability rather than retrieval, subsequent work aligns the rewriter with the retriever through retrieval-based rewards [49], preference- or ranking-based optimization over candidate rewrites [19,53,58], retrieval-guided iterative data refinement [12], or by augmenting the rewrite with generated answers [37] or LLM-enhanced conversation history [35]. With LLMs, prompted rewriting became competitive without fine-tuning the rewriter [18,31,52], and ConvSearch-R1 [61] removes external rewrite supervi-sion by optimizing an LLM rewriter with reinforcement learning against a rank-shaped retrieval reward. ICR [3] departs from single-step generation by alternat-ing self-posed clarification questions with progressively refined rewrites, learned from retrieval-filtered trajectories through supervised and preference training, and fusing the rankings of all intermediate rewrites. Its refinement, however, operates on the query and dialogue alone: no step observes retrieved passages. Across these methods, retrieval signals, when used, enter only at training time, while the rewrites issued at inference are produced without observing the corpus. We retain annotation-free, retrieval-aligned training, but condition each rewrite on the passages returned by the previous ones. 

Pseudo-Relevance Feedback. Using the top of an initial ranking to refine a sub-sequent query is a long-standing idea in IR, from Rocchio’s vector-space up-date [40] to relevance models such as RM3 [11,20], and has been carried over to dense retrieval, either by training a query encoder on feedback passages [54] or by expanding the query with embeddings drawn from them [48]. LLMs shifted ex-pansion towards generation, synthesizing pseudo-documents or answers that are matched against the collection [9,10,29,47]. Because such text is produced from parametric knowledge, it can diverge from the facts and vocabulary of the target corpus, which motivates conditioning generation on retrieved passages [21,42]. Feedback has likewise been applied to conversational search, expanding the current turn with history terms selected by their behavior on the collection [26] or with keywords and expected answers extracted from initially retrieved pas-sages [38]. In these approaches the feedback mechanism is fixed a priori, i.e., the number of rounds, what is extracted from the passages, and how it is merged into the query are all hand-designed. We instead propose that an agent learns from retrieval reward which reformulation to apply at each step and when to stop. Pseudo-document generation is one of the agent’s actions, grounded in passages retrieved at earlier steps rather than generated zero-shot. 

Reinforcement Learning for Search Agents. Reinforcement learning has been used to train query rewriters against retrieval or answer rewards [13,28,33], typically emitting a single rewrite per input. In parallel, agentic search sys-tems interleave reasoning with repeated calls to a search engine, first through 4 Coelho et al. 

prompting [22,39,44,51] and more recently through reinforcement learning, e.g., with GRPO [4,15,41,43,60]. These agents are trained for end-to-end question an-swering, where retrieval is an intermediate step. Even approaches that train the searcher separately from the generator reward it through downstream answer quality [14], so query reformulation is rarely studied on its own. ChatR1 [27] and ConvAgent [34] bring this paradigm to conversational ques-tion answering, interleaving search and reasoning within each turn and densify-ing the answer reward with intermediate signals, namely intent-aware turn-level rewards on search queries and the coverage of the gold answer by retrieved pas-sages, respectively, the latter alongside a reward for mixed-initiative actions. Both remain optimized primarily for answer quality and require reference an-swers for training. We differ in objective and action space. Our policy is re-warded solely on the ranking induced by the final reformulation, requiring only passage relevance labels, with neither answers nor rewrite annotations. It also acts through a typed set of reformulation operations, which lets us analyze how reformulation strategies are sequenced in response to corpus feedback. 

## 3 Methodology 

This section formalizes the task (§3.1), defines the agent and its typed action space (§3.2), and describes the the training pipeline (§3.3). 

3.1 Task Formulation 

A conversational search session is a sequence of user queries and system answers. At turn t, the user issues a query qt that may contain ellipsis or topic shifts rela-tive to the conversation history Ct−1 = {(q1, a 1), . . . , (qt−1, a t−1)}. The retrieval objective is to rank the relevant passages for qt as high as possible in a collection 

D, using a retriever R(·) that scores passages against a query string. Single-shot CQR instantiates this as learning a function rt = f (qt, C t−1) and issuing rt to R once. We instead formulate the problem as an episode: given (qt, C t−1), an agent interacts with R over multiple steps, issuing intermediate rewrites and observing their retrieval results, before committing to a final re-trieval state. The episode is internal to resolving turn t, and it is distinct from the conversational turns themselves. 

3.2 Agent Design 

At each step s of the episode, the agent observes the conversational history, the current query, and the retrieval results of all previous steps. Then, it issues one of the following actions: 

– <intent> : produce a self-contained reformulation of qt, resolving references and ellipsis against Ct−1. This action targets the gap between the surface query and the underlying information need. Multi-Step Query Rewriting via Corpus Feedback 5

– <rephrase> : produce a lexical variant of the current formulation, targeting vocabulary mismatch between the query and the relevant passages. 

– <hyde> : produce a pseudo-document that may answer the resolved query, enabling document-to-document matching [9]. 

– <stop> : terminate the episode. Each of the first three actions emits a tag followed by a rewrite, which is issued to R, and the top-k passages are appended to the context. Each subsequent action is therefore conditioned on corpus feedback, i.e. the evidence retrieved by earlier rewrites, rather than on the conversation alone. The episode ends when the agent emits <stop> or reaches a step budget of T steps. The actions differ in how much they can exploit corpus evidence. While intent resolution can operate on the conversation alone, rephrasing and pseudo-document generation can draw on the vocabulary observed in retrieved passages. The system prompt specifies no order among the actions, and the agent may issue any action at any step. 

3.3 Training 

We train the agent in two stages, namely using a supervised fine-tuning stage that instills the action format, followed by a reinforcement learning stage that optimizes rewrite quality against the retriever. 

Supervised Fine-Tuning. Following common practice in RL-based agent train-ing [16,61], we precede reinforcement learning with a supervised fine-tuning stage that addresses a cold-start problem where the small base model that has never emitted the action format produces mostly invalid trajectories, leaving GRPO without gradient signal. Since we train small models, we distill trajectories from a larger model of the same family running the agent harness described in Section 3.2, and retain trajectories that follow the action format. The resulting check-point reliably emits typed actions but is not yet aligned with the retriever; that alignment is the role of the RL stage. 

Reinforcement Learning. We train the SFT checkpoint with GRPO [41]. Given a conversational turn instance x = ( qt, C t−1), the behavior policy produces a group of K trajectories G(x) = {o1, . . . , o K }, where each trajectory is a full episode of interleaved actions, rewrites, and retrieval results. Retrieval Reward. Using retrieval metrics such as nDCG@ k directly as rewards yields sparse signal, since most rewrites leave the gold passage outside the metric cutoff. We adopt Rank-Incentive Reward Shaping (RIRS), also used by ConvSearch-R1 [61], which converts the rank of the gold passage into a dense piecewise reward: ranks 1 through 10 map linearly onto [1 , 2], ranks 11 through 100 map onto [0 , 1], and ranks beyond 100 receive zero. The reward is computed from the top-100 ranking produced by the final rewrite issued before <stop> , or from the last issued query if the step budget is exhausted without stopping. Al-though the agent observes only the top-k passages returned at each step, reward computation uses the retriever’s top-100 ranking. Trajectories that violate the action format receive zero reward. 

## 4 Experiments 

This section evaluates our multi-step query rewriting agent. We describe the experimental setup (§4.1), report in-domain results (§4.2), analyze the learned trajectories (§4.3), test generalization to unseen benchmarks and retrieval back-ends (§4.4), and quantify the cost of sequential interaction (§4.5). 

4.1 Experimental Setup 

Datasets. We evaluate on three conversational search benchmarks. QReCC [2] covers query rewriting over a large collection, and we use its standard training (29,596 queries) and testing (8,209 queries) splits. TopiOCQA [1] is built around topic switches, with longer conversations that span several topics, which makes it harder for query reformulation than QReCC [1,37]. We use its standard training set (45,450 queries) and development set (2,514 queries). Training uses half the queries for SFT, and the remaining half for RL. TREC CAsT [5,6] is used ex-clusively for zero-shot evaluation, i.e., models trained on QReCC or TopiOCQA are evaluated on CAsT without further training. 

Retrievers. Following prior work [53,61], we use BM25 ( k1=0 .90, b=0 .40 for TopioCQA; k1=0 .82, b=0 .68 for QReCC) as our sparse retriever through Py-serini [23]. For generalization experiments, we leverage ANCE [50] and Qwen3-Embedding-0.6B [59] as dense retrievers through FAISS [17]. No retriever is trained or adapted in any of our experiments. Baselines. We compare against the raw conversational query and five trained rewriters: CHIQ-Fusion [35], AdaQR [58], ADACQR [19], RETPO [53], and ConvSearch-R1 [61], the strongest prior method and our primary point of com-parison. All baseline numbers are taken from ConvSearch-R1’s evaluation, which shares our evaluation splits, retriever, and metrics. We re-ran ConvSearch-R1’s released inference code and weights and reproduced its reported scores. We also apply RM3 [20] to our agent’s first rewriting step, contrasting a fixed single-round feedback mechanism with the agent’s learned multi-step feedback. 

System Configurations. We compare three configurations of our system, each trained with the same procedure and differing only in what the policy is allowed to do. The single-step, single-action configuration emits one free-form rewrite and issues it once, reproducing the ConvSearch-R1 setting within our harness and isolating the contribution of the backbone from that of the method. The 

single-step, multi-action configuration selects one action from the typed space and issues it once, isolating the value of typed rewriting from that of iteration. The multi-step, multi-action configuration is the full agent, selecting a typed action at each step and conditioning on the passages retrieved so far. For each configuration, we report the untrained Qwen3-4B and Qwen3-32B backbones under the same prompt and harness, the checkpoint after supervised fine-tuning, and the checkpoint after reinforcement learning. We use Qwen3-4B as the backbone for every trained configuration. The agent runs for at most T = 5 steps, and each search appends the top 5 passages to the context, each truncated to 128 tokens. At each step, the agent can generate up to 512 tokens, with a total trajectory budget of 8192 tokens covering both agent generations and retrieved passages. SFT trajectories are distilled from the agent running with Qwen3-32B as the backbone, with a separate SFT checkpoint per configuration, since the configurations differ in action space. Reinforcement learning uses GRPO with group size K = 8 and the rank-incentive reward that was described in Section 3.3. Additional details are shown on Appendix A.

4.3 Analysis and Ablations 

Interaction Budget. Figure 1 truncates the 5-step agent at inference without retraining, so every point uses the same policy and differs only in how many reformulations it may issue. Retrieval quality rises steeply over the first three steps and then flattens. Truncated to a single step, the agent scores below the reinforcement-learned baselines in Table 1, suggesting that the improvement depends substantially on sequential interaction rather than on the backbone or typed rewriting actions alone. 10 Coelho et al. 

Learned Action Order. The policy converges to a consistent order that neither the prompt nor the reward enforces (Figure 2). Intent resolution takes the first step of every trajectory on both datasets, and pseudo-document generation dom-inates the final one. SFT alone does not enforce this behavior. Rollouts from the SFT checkpoints average 1.7 search steps, and only 60% open with intent reso-lution, the rest opening with a rephrase or a pseudo-document. Under RL these alternative openings disappear and episodes lengthen to 4.9 search steps on Top-iOCQA and 2.9 on QReCC. Since the reward scores only the ranking of the final rewrite and encodes no preference over order or length, the ordering appears to emerge from retrieval-reward optimization rather than inherited from distilla-tion. A single-step agent restricted to (ungrounded) pseudo-documents, trained with the same procedure, reaches 30.3 nDCG@3 on TopiOCQA, below both the free-form single-step rewriter (32.5) and the full agent (40.6). Pseudo-documents therefore help most when conditioned on passages retrieved by earlier steps. The policy’s transition to pseudo-document generation drives the perfor-mance gains observed in Figure 1, marking the sharpest retrieval improvements in the episode (i.e., step three on TopiOCQA and step two on QReCC). A po-tential issue is that this operation might reduce to trivial re-ranking, i.e., the agent could copy one of the lower-ranked passages among the top-5 results and reissue it verbatim, which, since a passage submitted as a query should retrieve itself at rank one, would promote it without any genuine reformulation. To rule this out, for each pseudo-document we measure 8-gram containment, i.e. the fraction of its 8-word spans occurring verbatim in a passage, maximized over all passages in the agent’s context, and the median was 0. The generation is nonetheless grounded in retrieved evidence, since unigram Jaccard between each pseudo-document and the passages (excluding stop-words) in its context gives a mean of 0.137, against 0.014 for passages drawn from an unrelated query’s context, roughly an order of magnitude higher. Thus, the model incorporates vocabulary from the retrieved passages without simply copying them. Consis-tent with this, replacing the contextual passages at inference with those from an unrelated query reduces nDCG@3 on TopiOCQA from 40.6 to 25.3.

The resulting cost is dataset-dependent. On TopiOCQA, 93% of trajectories issue a fifth rewrite, making the later interactions the main source of additional gen-eration cost, whereas on QReCC only 4% issue a fifth rewrite. Thus, although individual rewriting actions are inexpensive, their cumulative cost depends on how long the learned policy continues interacting with the corpus. 

## 5 Conclusions and Future Work 

In this paper we studied conversational query rewriting as a sequential retrieval process driven by feedback from intermediate search results. We trained a multi-step agent with reinforcement learning and no human rewrite annotations. Re-warded solely on retrieval quality, the policy converges to a consistent action order: it first resolves conversational intent, optionally refines the lexical formu-lation, and then generates pseudo-documents grounded in the passages retrieved by earlier steps. This formulation achieves the strongest ranking precision among the compared methods on TopiOCQA and QReCC, transfers zero-shot to TREC CAsT, and remains effective under dense retrievers. Several directions extend from this sequential framework. While we leveraged the RIRS reward directly for better comparison with prior studies, incorporating step penalties or latency costs into the reward objective could yield cost-aware policies that adaptively terminate early when low conversational ambiguity per-mits. Also, the agent could issue multiple reformulations in parallel at each step and be rewarded on their fused ranking, encouraging complementary rewrites that broaden recall while shortening the sequential loop. System prompt: multi-step, multi-action rewriting 

You are a query rewriting assistant for conversational search. You help resolve ambiguous, context-dependent conversational queries into effective standalone search queries. You will receive a conversational query line in the following format: 

– The string contains the most recent user query first , followed by zero or more [SEP] -separated snippets representing dialogue history (earlier turns, which may include prior questions and/or short answers or facts). 

– Format: CURRENT_QUERY [SEP] HISTORY_ITEM_1 [SEP] HISTORY_ITEM_2 [SEP] ... 

– History is ordered from most recent to oldest as you move right. Your job is to rewrite the current (leftmost) query only , using the dialogue history purely for disambiguation and reference resolution. 

# Workflow 

At each step you will: 1. Think about what the user is looking for and what gaps remain in the current results. 2. Choose exactly one action from the four below. 

# Actions 

You have four actions. Each submits a single query to the search engine and returns results. 1. Intent query — a focused standalone query capturing the user’s underlying information need. Resolve all coreferences and ellipsis. 

<think> . . . </think> <intent> focused standalone query </intent> 

2. Rephrase query — the same information need expressed with alternative terminology, synonyms, or different phrasings. Think about how this topic might appear in encyclopedic or reference text. 

<think> . . . </think> <rephrase> alternative phrasing of the query </rephrase> 

3. HyDE query — a short hypothetical passage that would correctly answer the question, written using your own knowledge. This introduces answer-side vocabulary that helps the retriever match relevant documents. 

<think> . . . </think> <hyde> short hypothetical answer passage </hyde> 

4. Stop — submit the current retrieved results if they look relevant, or if further rewriting is unlikely to help. 

<think> . . . </think> <stop></stop> 

# Guidelines 

– Resolve coreferences: replace pronouns (“he”, “it”, “they”) with the actual entities from conversation history. 

– Resolve ellipsis: fill in omitted information from context. 

– Handle topic shifts: if the conversation has shifted topics, focus on the current topic. 

– Gap-bridging : after seeing retrieved passages, identify what’s missing and choose the action type most likely to bridge the gap. 

– Adopt corpus vocabulary : if the retrieved passages use specific terminology (names, dates, technical terms), incorporate those exact terms. 

– Stop early if results look relevant. Don’t rewrite unnecessarily.
