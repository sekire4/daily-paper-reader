## 摘要
基于LLM的智能体日益依赖可复用技能。然而，技能库规模扩大使得高效且准确地使用技能变得困难。完整加载技能会带来高昂的token和运行时开销。相比之下，扁平语义检索将技能视为独立的文本条目，忽略了依赖关系、执行顺序、状态转换和数据流约束。我们提出SPEM，一种轻量级、结构感知的程序性记忆框架，用于LLM智能体中的高效技能使用。SPEM维护用于单个技能的原子技能记忆（Atomic Skill Memory）和用于从成功执行中提炼出的可复用组合的技能DAG记忆（Skill-DAG Memory）。对于新任务，SPEM在可用时复用高置信度的技能DAG模板。否则，它检索原子技能并调用Skill-GNN进行状态感知和结构感知的技能选择。成功执行会被写回为新的技能DAG，使程序性记忆能够随时间累积。在ALFWorld和SkillsBench上的实验表明，SPEM取得了最佳的整体效果—效率权衡，在降低token和运行时成本的同时，相比强基线达到87.1%的ALFWorld成功率和38.38%的SkillsBench奖励。

## Abstract
LLM-based agents increasingly rely on reusable skills. However, scaling skill libraries makes efficient and accurate skill use difficult. Full skill loading incurs high token and runtime overhead. In contrast, flat semantic retrieval treats skills as independent text entries, ignoring dependencies, execution order, state transitions, and data flow constraints. We propose SPEM, a lightweight structure-aware procedural memory framework for efficient skill use in LLM-based agents. SPEM maintains Atomic Skill Memory for individual skills and Skill-DAG Memory for reusable compositions derived from successful executions. For a new task, SPEM reuses high-confidence Skill-DAG templates when available. Otherwise, it retrieves atomic skills and invokes Skill-GNN for state- and structure-aware skill selection. Successful executions are written back as new Skill-DAGs, allowing procedural memory to accumulate over time. Experiments on ALFWorld and SkillsBench show that SPEM achieves the best overall effectiveness--efficiency trade-off, reaching 87.1% ALFWorld success and 38.38% SkillsBench reward while reducing token and runtime costs against strong baselines.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地依赖可复用技能（文件解析、数据预处理、API 调用等）完成软件工程、数据分析、网页自动化与具身任务。当技能库扩展到数百至数千项时，核心矛盾从“是否存在有用技能”转变为“如何高效检索、组织并复用技能”。
- **现有方法的四点局限**：
  - **全量加载不可行**：token 成本高、上下文膨胀、运行时开销大，且关键信息易在长上下文中丢失。
  - **扁平语义检索**：将技能视为独立文本条目，只优化语义相关性，忽略前置条件、执行顺序、状态转移与数据流等结构依赖。
  - **成功经验未沉淀**：依赖感知的计划在执行后即被丢弃，智能体需反复重新推导相似工作流。
  - **效率未受重视**：检索、规划、重组的重复模型调用带来额外 token、延迟与算力开销。
- **研究目标**：在提升任务成功率的同时，降低 token 成本、运行时开销与重复技能组织，构建可随执行积累的程序性记忆。

## 2. 方法论

### 2.1 核心思想：双层程序性记忆

- **原子技能记忆（Atomic Skill Memory）**：每个技能表示为可执行单元 \(s_i=(d_i,e_i,\sigma_i)\)，其中 \(d_i\) 为元数据、\(e_i\) 为语义嵌入、\(\sigma_i\) 为轻量执行反馈（使用频率、成功率、执行成本），使检索兼顾语义相关性与历史执行证据。
- **技能 DAG 记忆（Skill-DAG Memory）**：存储从成功执行中提炼的可复用流程模板 \(G_j=(V_j,E_j,e_j,m_j)\)，包含程序节点、有向依赖边、任务嵌入与执行元数据，用于直接复用已验证的执行结构。

### 2.2 检索与模板复用流程

- 给定任务 \(q\)，先按相似度阈值 \(\tau\) 在 DAG 记忆中匹配模板：\(\mathrm{Cd}(q)=\{G_j\mid \mathrm{sim}(e_q,e_j)\ge\tau\}\)。
- **命中**：注入得分最高的 Skill-DAG 作为结构化程序指导。
- **未命中**：检索有界数量的原子技能候选 \(\mathrm{Ca}(q)=\mathrm{TopK}\,\mathrm{sim}(e_q,e_i)\)，再交由 Skill-GNN 做结构感知选择。
- 该策略避免全库加载，同时保留“模板直接复用”与“原子技能灵活组织”两种互补模式。

### 2.3 Skill-GNN：状态与结构感知的技能选择

- **候选图构建**：基于任务、检索候选与当前执行上下文构造任务条件图 \(G_q=(V_q,E_q,R)\)；节点包括任务、上下文与候选技能，边为类型化关系（任务–技能、上下文–技能、技能–技能），编码相关性、状态兼容性、语义关联与依赖线索。
- **关系感知消息传递**：节点表示按关系类型聚合邻居信息，使用关系特定变换矩阵 \(W_r^{(\ell)}\) 与消息权重 \(\alpha_{rij}\)，经 \(L\) 层更新后为每个候选技能打分 \(p_i=f_\theta(h_i^{(L)})\)。
- **输出**：排序靠前的技能及紧凑依赖线索作为结构化指导注入 LLM 执行器。
- **冷启动部署**：
  - 有目标域轨迹时，用“轨迹前缀监督”训练（前缀为当前程序状态，下一执行技能为目标）。
  - 轨迹稀缺时，仅用技能库构造库级热启动：由技能元数据生成伪查询 \((\tilde q_i,s_i)\)，并以语义相似度、共享工具/标签/schema 兼容性构造弱技能关系 \((\tilde s_i,r,\tilde s_j)\)，**不使用任务结果、验证器奖励或评估轨迹**。
  - 早期以原子检索与已有模板为主，Skill-GNN 仅做有界重排；随成功执行积累逐步转向状态感知的图选择。由于对动态候选图具有归纳性，可泛化到未见任务、未见技能组合与新提取的 DAG 变体。

### 2.4 轨迹-DAG 提取（记忆写回）

- 从成功轨迹构建执行图 \(G_\tau\)，节点为执行步骤与任务相关状态，边编码时序、实体依赖、状态转移与终态可达性。
- 从成功终节点 \(v_{succ}\) 执行**反向切片**，保留可到达成功终态的节点 \(V_\tau^*\)，剔除失败分支、冗余探索与非贡献操作。
- 对剩余节点按时间与依赖约束排序、修复，形成紧凑 Skill-DAG \(G_\tau^*=(V_\tau^*,E_\tau^*)\) 并写回记忆。
- **更新策略**：成功的非模板执行引入新模板；成功的模板引导执行强化或精炼已有模板；失败的模板执行仅更新可靠性统计。

## 3. 实验设计

- **数据集/场景**：
  - **ALFWorld**：交互式文本具身环境，考察长程依赖、状态转移与程序复用；使用 dev split 的 140 个 episode，最大 30 步，统一 37 个 `alfworld-*` 技能。
  - **SkillsBench**：大规模技能库下的技术任务，考察有限上下文预算下的技能检索与应用；采用 Docker 环境、Harbor 执行、官方验证器评估，最多 2 次尝试、2 并发，保留 67 个有效任务，统一 `skills_200` 技能库。
- **评价指标**：
  - ALFWorld：成功率↑、平均环境步数↓、平均 token 消耗↓、agent-only 运行时↓。
  - SkillsBench：验证器奖励 \(R\)↑、平均输入 token \(T\)↓、agent-only 运行时 \(S\)↓。
- **对比基线**（构成从“更多上下文”到“结构感知”的递进）：
  - **Vanilla Skills**：全量加载技能库。
  - **Vector Skills**：基于嵌入相似度的 top-k 扁平检索。
  - **GoS**：基于预构建技能图的静态图检索。
  - **SkillDAG**：依赖感知、自演化图结构的近期 SOTA 基线。
  - **SPEM**：双层记忆 + 轨迹-DAG 提取 + 按需 Skill-GNN 重排。
- **骨干模型**：MiniMax-M2.7（较弱）与 GPT-5.2-Codex（较强），覆盖强弱两种模型设定。
- **公平性控制**：所有方法共享相同数据划分、技能库、智能体接口、执行环境与验证协议；训练与评估实例不相交；SkillsBench 中因基础设施故障重试后仍失败的任务被排除而非计为模型失败。
