Abstract 

Explicit memory systems transform conversation history into persistent representations intended to improve future access, often at substantial construction cost. Yet it remains unclear whether this added complexity yields better answer accuracy than retrieving directly from raw history. This study compares six state-of-the-art explicit memory systems with raw-history RAG on LongMemEval-S and BEAM-100K under original and controlled retrieval settings. We find only localized gains for particular question types and tight run-time context budgets, with no consistent advantage over strong raw-history RAG baselines. Oracle retrieval shows that some systems fail to preserve answer-supporting information during explicit memory construction, while others preserve it but fail to retrieve it effectively, despite construction costs reaching hours per conversation. Our findings suggest that while many existing memory systems for AI agents emphasize increasingly elaborate explicit memory construction, they are often evaluated without strong controlled comparisons to raw-history RAG and may underemphasize retrieval. Retrieval remains a major bottleneck when useful information is preserved, suggesting that improving access to existing information may be at least as important as constructing richer explicit memory. 

Keywords: LLM agent memory; conversational agents; retrieval-augmented generation; long-term memory evaluation 

1 Introduction 

AI agents that interact with users over long periods need to recover relevant information from a growing conversation history. Recent memory systems address this challenge by transforming past user–assistant interactions into persistent representations, such as summaries, extracted facts, and linked notes, that can later be retrieved when needed (Chhikara et al., 2025; Fang et al., 2026; Liu et al., 2026; Xu et al., 2026; Yue et al., 2026; Zhong et al., 2024). We refer to these approaches as “explicit memory systems ”, and to the resulting representations as “ explicit memory ”. Constructing and maintaining such memory, however, can require substantial additional computation, including repeated LLM calls for extraction, summarization, consolidation, linking, or reflection. A natural alternative is to avoid this construction stage altogether and retrieve relevant evidence directly from the original conversation history. We refer to this alternative as raw-history retrieval-augmented generation (RAG) . This raises a fundamental question: does explicit memory construction provide enough benefit to justify its additional cost over raw-history RAG? 

Evaluating this trade-off is not straightforward. The effectiveness of an explicit memory system depends not only on what is constructed, but also on how the memory is retrieved, how much retrieved memory is supplied to the answer model, and how much computation is required throughout

Consequently, end-to-end comparisons between systems cannot determine whether observed gains come from explicit memory construction itself, from differences in retrieval and context budget, or from additional computation. In this study, we examine this trade-off through a controlled evaluation of six state-of-the-art explicit memory systems against raw-history RAG. We ask: (1) whether explicit memory improves answer accuracy over raw-history RAG; (2) whether its limitations arise from explicit memory construction or retrieval; and (3) whether any resulting gains justify the additional computation required to construct and use explicit memory. Beyond evaluating each system under its original configuration, we hold its constructed explicit memory fixed and systematically vary the retriever and context budget under a unified answering setup. We further use oracle retrieval to separate limitations in explicit memory construction from those in retrieval, and measure both construction and query-time cost. Our results show that the evaluated explicit memory systems provide no consistent overall advantage over raw-history RAG. This pattern persists when retrieval and context budgets are controlled, although explicit memory provides localized gains for some question types and under tight context budgets. Oracle retrieval reveals two distinct bottlenecks: some systems preserve useful information but fail to retrieve it effectively, whereas others appear to lose useful information during explicit memory construction. Moreover, the additional construction and query-time computation required by explicit memory does not consistently translate into higher answer accuracy. Our findings suggest that improving conversational memory may require shifting attention from increasingly elaborate memory construction toward retrieval. Across the evaluated systems, explicit memory construction yields limited and inconsistent gains, while retrieval remains a major bottleneck even when useful information is preserved. This suggests that better access to existing information may be at least as important as constructing richer memory representations. 

2 Background and Motivation 

Long-term conversational memory systems differ widely in how they construct and retrieve memory. Early agent architectures such as Generative Agents and MemGPT explored persistent memory and selective retrieval (Packer et al., 2023; Park et al., 2023), while more recent work increasingly constructs explicit memory from conversation history. MemoryBank combines conversation content 

2Preprint. Under review. 

with summaries; Mem0 and LightMem extract compact memory units; A-Mem constructs linked notes; SimpleMem combines structured memory with query-aware retrieval; and HyperMem organizes memory hierarchically using a hypergraph (Chhikara et al., 2025; Fang et al., 2026; Liu et al., 2026; Xu et al., 2026; Yue et al., 2026; Zhong et al., 2024). We focus on these six explicit memory systems because they construct persistent explicit memory and use a retrieval stage that can be studied separately from construction. Their different construction and retrieval procedures make end-to-end results difficult to interpret. A system that performs better may construct more useful explicit memory, retrieve from it more effectively, provide more relevant information to the answer model, or simply use more computation. Conversely, a system that performs poorly may be limited by explicit memory construction, retrieval, or both. These ambiguities reveal four gaps in current evaluation practice. 

Gap 1: End-to-end comparisons do not isolate the value of explicit memory construction. 

Recent explicit memory systems are typically evaluated as complete pipelines, though some recent work has begun to separate memory construction from retrieval (Hu et al., 2026; Zhou et al., 2026). A-Mem, SimpleMem, and HyperMem, for example, jointly change both the constructed explicit memory and retrieval (Liu et al., 2026; Xu et al., 2026; Yue et al., 2026). Mem0 and LightMem include simpler RAG-style baselines (Chhikara et al., 2025; Fang et al., 2026), but the compared systems still differ in retrieval procedure, context budget, or answering setup. An end-to-end gain therefore does not establish that explicit memory construction itself is responsible for the improvement. 

Gap 2: Retrieval is rarely controlled across explicit memory systems. The evaluated systems use very different retrieval procedures, ranging from dense retrieval to link expansion, query planning, hybrid search, and hierarchical retrieval. Because retrieval determines which preserved information reaches the answer model, it can materially change performance even when the constructed explicit memory is fixed. A controlled comparison must therefore evaluate explicit memory systems under matched retriever and context-budget settings. 

Gap 3: End-to-end accuracy cannot distinguish retrieval failure from information lost during explicit memory construction. A poor answer can arise because relevant information was discarded during explicit memory construction, or because it remains in explicit memory but is not retrieved. These failures have different causes and require different solutions, but standard end-to-end evaluation cannot distinguish them. We use oracle retrieval to measure the answer accuracy supported by each system’s explicit memory when retrieval is bypassed. 

Gap 4: Answer accuracy alone does not capture the cost of explicit memory. Explicit memory systems may require substantial LLM computation for extraction, summarization, consolida-tion, linking, query planning, or reflection. Several recent systems explicitly optimize for efficiency (Fang et al., 2026; Liu et al., 2026), but the relevant comparison is also against raw-history RAG, which requires no explicit memory construction. We therefore evaluate construction and query-time cost together with answer quality. 

3 Experimental Framework 

To address the evaluation gaps in Section 2, we place all systems within a common three-stage pipeline: construction, retrieval, and answering. The central principle is to separate explicit memory construction from downstream retrieval and answering. Constructed explicit memory remains fixed, while the retriever, context budget, and answering setup are varied according to the research question. Figure 1 summarizes the framework. 3.2 Systems and Baselines 

We evaluate the six explicit memory systems introduced in Section 2: MemoryBank (Zhong et al., 2024), A-Mem (Xu et al., 2026), Mem0 (Chhikara et al., 2025), LightMem (Fang et al., 2026), SimpleMem (Liu et al., 2026), and HyperMem (Yue et al., 2026). Table 4 in Appendix A.1 summarizes their construction, retrieval, and answering components. As controls without explicit memory construction, we evaluate raw-history RAG with three retrieval-unit definitions: all-turns , containing all conversation turns; user-turns , containing user turns only; and pair-turns , containing user–assistant turn pairs. These baselines use the same conversation histories while varying speaker coverage and retrieval granularity. We also include a 

full-context baseline that bypasses retrieval and supplies raw conversation history directly to the answer generator. The history is capped at 100K tokens 1; if it exceeds this limit, we retain the most recent content that fits.

4 RQ1: Do Explicit Memory Systems Outperform Raw-History RAG? 

We first ask if explicit memory systems outperform raw-history RAG under their original configu-rations. This provides an end-to-end comparison before separating the effects of explicit memory construction, retrieval, and context budget. 

Settings. We compare the six explicit memory systems with the raw-history RAG baselines and full-context reference described in Section 3 on LongMemEval-S and BEAM-100K. For each explicit memory system, we preserve its original construction procedure and retrieval pipeline (Appendix B). A-Mem, LightMem, SimpleMem, and HyperMem also retain their system-specific answer prompts, while MemoryBank and Mem0 use the unified answer prompt because their evaluated implementa-tions do not define a distinct downstream answering procedure. For raw-history RAG, we evaluate three retrieval-unit definitions, all-turns , user-turns , and 

pair-turns , with two dense retrievers: all-MiniLM-L6-v2 (Sentence Transformers, 2021) and Qwen3-Embedding-0.6B (Zhang et al., 2025). We include all-MiniLM-L6-v2 to match the retriever used by several evaluated explicit memory systems. We also include Qwen3-Embedding-0.6B, which is used by SimpleMem, to test whether a stronger raw-history retrieval baseline changes the comparison. Each configuration retrieves the top 10 retrieval units and uses the unified answer prompt.  

> Finding 1: Under original configurations, no explicit memory system outperforms the strongest raw-history RAG baseline.

The strongest raw-history RAG baseline leads on both benchmarks, although the margin is much larger on LongMemEval-S than on BEAM-100K (Table 1). In contrast, the full-context baseline performs substantially worse, suggesting that the advantage of raw history depends on selecting relevant content rather than providing more of it. The importance of retrieval is further reflected in retriever choice. On LongMemEval-S, replacing all-MiniLM-L6-v2 with Qwen3-Embedding-0.6B improves all-turns RAG by 14.8 percentage points and reverses its comparison with LightMem. An apparent advantage of explicit memory under a weaker raw-history baseline can therefore disappear when retrieval is strengthened, highlighting the importance of retrieval when assessing the value added by explicit memory construction. To answer RQ1, none of the evaluated explicit memory systems outperforms the strongest raw-history RAG baseline under their original configurations. However, the comparison is sensitive to retriever choice, so these end-to-end results do not isolate the effect of explicit memory construction. A controlled retrieval comparison is therefore needed to determine whether the raw-history RAG advantage persists when retrieval conditions are aligned.

The question-type analysis shows that the raw-history advantage is not driven by a single class of questions (Table 2). 6 RQ3: Is Explicit Memory Limited by Construction or Retrieval? 

Even under the controlled retrieval settings in RQ2, explicit memory systems can remain behind raw-history RAG. However, this comparison does not reveal where the limitation arises. A system may underperform because explicit memory construction does not preserve the information needed for answering, or because the information is preserved but the retrieval pipeline fails to return it. We therefore use oracle retrieval to distinguish these two sources of limitation.

We conduct this analysis on BEAM-100K because its annotations identify the conversation turns supporting each question. 7 RQ4: Does Explicit Memory Justify Its Additional Computational Cost? 

So far, we have focused on answer accuracy, but explicit memory systems can also introduce substantial computation during explicit memory construction and at query time. Construction is an upfront cost, whereas query-time cost recurs for every question, so the value of an explicit memory system depends on both its computational cost and resulting answer accuracy. RQ4 therefore asks whether the additional computation required to construct and use explicit memory is justified by its downstream benefits.

Settings. We measure computational cost at three stages: explicit memory construction, retrieval, and answer generation. Each explicit memory system uses its original configuration, as in RQ1. > Finding 7: Explicit memory construction can incur substantial upfront cost.

Explicit memory construction can require substantial computation before any questions are answered. On LongMemEval-S, even LightMem, the fastest system to construct, requires 6.2 minutes per conversation, while A-Mem requires approximately 35 times longer. Raw-history RAG avoids this LLM-based construction stage entirely. The large variation across systems shows that construction cost depends strongly on the explicit memory construction procedure. Evaluating only query-time cost therefore misses part of the computational cost of explicit memory systems.  

> Finding 8: Additional computation does not consistently translate into higher answer accuracy.

Across systems, higher computational cost does not consistently correspond to higher answer accuracy. Several explicit memory systems incur substantial construction cost and higher query-time cost than raw-history RAG while still achieving lower accuracy. Additional computation during explicit memory construction and retrieval therefore does not consistently translate into better downstream performance. Lower query-time cost is possible, but it does not necessarily offset the accuracy trade-off. For example, LightMem uses fewer query-time LLM tokens than all-turns RAG on LongMemEval-S but is 14.0 percentage points less accurate. Moreover, query-time savings do not require explicit memory construction: on BEAM-100K, user-turns achieves nearly the same accuracy as all-turns while using substantially fewer query-time LLM tokens and requiring no LLM-based memory construction. Thus, lower query-time cost is neither unique to explicit memory nor sufficient by itself to establish an efficiency advantage. To answer RQ4, the evaluated explicit memory systems do not consistently convert their addi-tional computation into higher answer accuracy. Some reduce query-time cost, but these savings must be considered together with their accuracy trade-offs and upfront construction cost. Whether construction cost is worthwhile also depends on how many future queries it can be amortized over, but within the evaluated settings, explicit memory does not show a consistent cost–accuracy advantage over raw-history RAG. 

8 Discussion and Conclusion 

In this study, we asked whether explicit memory construction provides enough benefit to justify its additional cost over raw-history RAG. Across six state-of-the-art explicit memory systems, we find no consistent overall advantage in answer accuracy over strong raw-history RAG baselines, with gains limited to particular question types and tight run-time context budgets. Oracle retrieval reveals two distinct limitations: some systems fail to preserve enough answer-supporting information 

> 13 Preprint. Under review.

during construction, while others preserve useful information that practical retrieval fails to access. These limited gains are further offset by substantial construction and, in some cases, query-time computation that does not consistently improve answer accuracy. These results suggest that long-term conversational memory should not be viewed only and primarily as a problem of constructing increasingly elaborate explicit memory. Conversation history already provides a persistent source of information, and the value of explicit memory construction depends on whether it preserves answer-supporting information and makes that information easier to retrieve within the run-time context budget. Construction and retrieval must therefore be considered jointly: better retrieval cannot recover information unavailable after construction, while richer explicit memory provides little benefit if its useful information cannot be retrieved. Looking forward, raw-history RAG should serve as a strong reference point rather than merely a simple baseline. A promising direction is to retain raw history while using explicit memory con-struction selectively when abstraction, consolidation, or structure provides measurable downstream value. Future work should therefore focus not only on how to construct richer explicit memory, but on when such construction is useful, what information should be transformed, and whether its gains in answer accuracy or information access justify the additional computational cost.
