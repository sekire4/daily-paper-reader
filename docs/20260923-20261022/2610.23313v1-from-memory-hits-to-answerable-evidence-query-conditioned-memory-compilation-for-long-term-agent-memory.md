## 摘要
长期智能体记忆需要恢复分散于多轮对话和多次会话中的与答案相关的证据。现有系统越来越多地使用结构化记忆和自适应检索，但往往将检索到或扩展后的单元直接传递给阅读器，使记忆寻址与证据呈现相互耦合，导致最终上下文冗余或不完整。为解决这一缺口，我们提出 MemCompile，一种面向长期对话记忆的查询条件化证据编译框架。给定一个查询，Address Plane 通过紧凑的源链接描述符和容量感知 Cells 定位相关支撑信息，同时由归一化边界将异构检索命中解析为稳定的 SourcePacket 标识。随后，其 Evidence Plane 在互补数据包之间分配有界证据预算，接纳有限的额外支撑信息，并将与每个选定数据包相关联的保留主张渲染为可直接用于回答的上下文。MemCompile 在 LoCoMo 上达到 80.52% 的 Judge Accuracy，并将经验质量-成本帕累托前沿扩展到更高质量区间。其在 LongMemEval-S 上的强劲表现进一步表明，查询条件化编译的收益可泛化到长期对话记忆基准。

## Abstract
Long-term agent memory requires recovering answer-relevant evidence dispersed across turns and sessions. Existing systems increasingly use structured memories and adaptive retrieval, yet often pass retrieved or expanded units directly to the reader, coupling memory addressing with evidence presentation and leaving the final context redundant or incomplete. To address this gap, we propose MemCompile, a query-conditioned evidence compilation framework for long-term conversational memory. Given a query, the Address Plane locates relevant support through compact source-linked descriptors and capacity-aware Cells, while a normalization boundary resolves heterogeneous retrieval hits to stable SourcePacket identities. Its Evidence Plane then allocates a bounded evidence budget across complementary packets, admits limited additional support, and renders the retained claims associated with each selected packet into an answer-ready context. MemCompile achieves 80.52% Judge Accuracy on LoCoMo and extends the empirical quality-cost Pareto frontier to a higher-quality regime. Its strong performance on LongMemEval-S further suggests that the benefits of query-conditioned compilation generalize across long-term conversational-memory benchmarks.

- **背景**：长期智能体记忆需要在跨轮次、跨会话的对话历史中，恢复分散且可能被后续交互修正的“与答案相关的证据”。现有系统已从原始对话检索逐步发展到原子事实、摘要、画像、事件、图结构、层次结构等结构化记忆。
- **关键矛盾**：近期工作开始意识到“用于定位记忆的表示”与“呈现给阅读器的证据”应有所区别（如 AnchorMem、xMemory、MemIR），但这种分离仍不彻底——检索到的表示或其扩展结果，依然在很大程度上直接决定最终送入阅读器的上下文。
- **两个被耦合的决策**：
  1. **哪些底层对话来源应获得有限的证据预算**；
  2. **这些来源的证据应如何表示为答案生成上下文**。
- **耦合的代价**：
  - 原子事实易检索，但可能丢失因果关系或同源兄弟事实；
  - 原始对话轮保留细节，却重新引入问候语等噪声；
  - 层次节点适合导航，但粒度与答案生成不匹配；
  - 缺乏显式来源边界时，多条主张或多个检索通道会反复为同一底层来源分配预算，造成上下文冗余。

## 2. 方法论：MemCompile 的地址—证据双平面架构

### 2.1 核心思想

- 用**紧凑的派生表示**定位相关记忆（Address Plane）；
- 用**不可变的原始对话轮 SourcePacket**作为证据预算的分配单位；
- 用**单独编译的读者视图**（源范围主张包）生成答案；
- 通过**源归一化边界**把多对多的检索命中折叠为稳定的来源身份。

### 2.2 问题形式化

- 对话历史 \(H=(P,\prec)\)，\(P=\{p_1,\dots,p_N\}\) 为原始对话轮，含说话人、会话、时间、内容。
- 给定查询 \(q\)，构造有界、有序、可追溯到原始对话轮的读者上下文 \(X_q\)，要求支撑充分且互补、限制冗余。

### 2.3 Address Plane（地址平面）

- **不可变 SourcePacket**：每个原始对话轮实例化为一个 SourcePacket，存储说话人、会话、交互时间、原始内容与稳定标识。
- **源链接原子描述符**：
  - 用 LLM 从每个 SourcePacket 抽取独立事实主张，并利用前一轮消解局部指代；
  - 每个描述符 \(x_i=(f_i,d_i,s_i,j_i,t_i,Per_i,Key_i,\tau_i,\bar\tau_i,n_i,\pi_i)\)，其中 \(\pi_i\) 为指向所属 SourcePacket 的外键；
  - 描述符既提供稀疏/语义检索键，又保留回到原始证据的路径。
- **有界 Cell 放置**：
  - Cell 是容量受限的路由结构，需满足 token 容量 \(B_C=360\) 与条目容量 \(M_C=12\)；
  - 放置得分由元数据局部性、关键词—人物—时间一致性、极性冲突惩罚、容量/熵压力组成；
  - 新建 Cell 作为额外候选，带扩张压力 \(0.65+n_i/B_C\)；
  - 按对话与主张顺序串行放置，查询服务前形成固定布局。
- **递减收益 Cell 路由**：
  - 对查询计算 Cell 相关性 \(u(c,q)\)，边际收益为  
    \(g(c|O_t,q)=u(c,q)[1-\lambda_R J(M_c,M_{O_t})]-\kappa_{open}\)；
  - 其中 \(\lambda_R=0.45\)，\(\kappa_{open}\) 随已打开 Cell 数与 token 阅读成本增加；
  - 贪心打开 Cell，直到边际收益为负、相对效用低于阈值、累计效用达 90% 或达到 6 个 Cell 上限。
- **多通道候选并集**：
  - BM25 Top-96 作为词汇通道，其前 8 条同时作为 Cell 路由种子；
  - 候选池 \(K_q=\bigcup_{c\in C_q}\text{claims}(c)\cup\text{BM25}(q)\)；
  - 候选得分融合查询—主张词项、关键词、人物、时间匹配与 BM25 分数；
  - 另设稠密语义通道，对完整包集合取 Top-40 作为补充提议。

### 2.4 源归一化边界

- 所有候选主张通过 \(\rho(x_i)=\pi_i\) 解析到所属 SourcePacket；
- 同一来源的多个主张、多个通道命中被折叠为一个证据候选；
- 包得分取同源候选的最大检索分 \(s(p,q)=\max_{x_i:\rho(x_i)=p} r_i\)；
- 关键作用：**检索键的多重性不再等同于证据预算的多重性**，避免重复命中挤占预算。

### 2.5 Evidence Plane（证据平面）

- **互补包调度**：闭池 listwise 调度器从归一化候选池中选出 \(K_0=10\) 个互补 SourcePacket，优先直接承载答案的包，同时保留关系、时间、比较、列表问题所需的互补包；输出标签需经闭池校验。
- **锚点保持的有界前沿**：
  - 前沿池 \(W_q=A_0(q)\cup D_q\)；
  - listwise 重排后，在前 \(K_R=5\) 个位置中最多接纳 \(K_\Delta=2\) 个此前未选中的包；
  - 最终证据集 \(E_q=A_0(q)\cup\Delta(q)\)，保留初始锚点、限制证据变化幅度。
- **读者视图编译**：
  - 对每个选中包 \(p\)，构造源范围主张包 \(B_p=\langle x\in X|\pi(x)=p\rangle\)；
  - 按包调度顺序拼接带时间戳的证据块，形成最终读者上下文 \(X_q\)；
  - 该编译对保留描述符集合是完整的，而非原始文本的重建。

### 2.6 算法流程概要

1. 按对话顺序注册 SourcePacket；
2. 抽取独立事实与元数据，构造描述符并写入有界 Cell；
3. 查询时抽取查询意图（人物、关键词、时间）；
4. Cell 路由 + BM25 形成候选并集；
5. 按 SourcePacket 身份折叠候选；
6. listwise 调度 10 个锚点包；
7. 稠密语义 Top-40 与锚点合并，重排后最多追加 2 个包；
8. 按调度顺序编译每个包的主张包，输出读者上下文。

## 6. 主要结论与发现

- **LoCoMo 总体最优**：MemCompile 取得 F1 55.94、BLEU-1 48.65、Judge 80.52%，在 Single-Hop、Multi-Hop、Temporal 三类均排名第一；相比最强基线，Multi-Hop 与 Temporal 的 Judge 分别提升 8.69 和 7.79 个百分点。
- **质量—成本前沿**：相比 Mem0，Judge 提升 14.35 个百分点，同时 token 减少 51.7%（26.72M vs 55.30M）；相比 AtomMem，仅多用 8.8% token，却提升 10.01 个百分点 Judge，将经验帕累托前沿推进到更高质量区间。
- **源归一化有效但有限**：源归一化本身带来 Gold Recall +3.35 个百分点；真正的大幅提升来自互补调度，Gold Recall 从 51.91% 升至 80.84%（+28.93 个百分点），且唯一来源数保持 9.988、DBR 降为 0。
- **重复命中问题严重**：Top-20 检索平均仅覆盖 14.60 个不同来源，同源命中占用 27.02% 的名义预算，影响 97.27% 的问题；说明增加命中数或通道数并不自动转化为更广的证据覆盖。
- **Cell 放置提升上游覆盖**：相比 Flat，Bounded Cell 在 Single-Hop 和 Multi-Hop 上分别提升召回 5.13 和 3.42 个百分点；移除 Cell 路由使最终召回下降 3.96 个百分点、Judge 降至 77.53%。
- **读者视图至关重要**：在固定包召回率下，单条代表主张仅 57.01% Judge，原始包 75.32%，完整主张包 80.52%；说明激进的单主张压缩会丢失答案所需的关系与时间限定。
- **跨基准泛化**：LongMemEval-S 上，MemCompile 在六类中的五类取得最佳 Judge，其中单会话助手 94.64%、单会话用户 91.43%、知识更新 78.21%、时间推理 72.18%；但多会话类别（54.14%）低于 Mem0（65.41%），显示跨会话聚合仍是薄弱环节。

- **问题刻画清晰**：明确区分“记忆寻址”与“证据呈现”两个决策，指出二者对表示性质的不同要求，具有较强的概念贡献。

- **工程可落地性较强**：SourcePacket 不可变、Cell 布局离线固定、查询时仅做路由与调度，整体符合长期记忆系统“冷构建、热服务”的部署形态。

## 8. 进一步局限与方法层面的风险

- **对 LLM 抽取与调度的依赖较深**：源链接原子描述符、查询意图抽取、listwise 调度器和前沿重排均依赖 LLM。抽取错误会沿“描述符—Cell—候选—证据包”链路传播，而论文未系统报告抽取噪声或调度器失败案例的影响。
- **来源粒度仍以原始对话轮为不可分单位**：SourcePacket 解决了“同源重复预算”问题，但若单轮内容很长、包含多个主题或答案仅需其中一句，按整轮分配预算仍可能引入噪声或浪费 token。轮内片段级来源边界是潜在改进方向。
- **Cell 布局是离线固定结构**：查询服务前形成固定布局，能降低在线成本，但当查询分布、话题漂移或新会话持续写入时，Cell 的容量与路由结构可能需要重建；论文未充分讨论增量更新与长期演化下的布局稳定性。
- **证据编译仍偏向命题化表达**：完整主张包优于单条代表主张，说明关系与时间限定很重要；但主张包是否保留原始语气、指代链、表格/列表结构、否定范围等非命题信息，仍缺少细粒度分析。
- **跨会话聚合仍是薄弱环节**：LongMemEval-S 多会话类别低于 Mem0，表明当前“来源恢复—互补调度”在需要跨多个会话合并用户状态或偏好演化时仍不充分，可能与包级调度和固定前沿窗口有关。
- **在线调度成本偏高**：包调度器与前沿重排器占在线成本 83.4%、总成本 39.5%，说明质量提升伴随显著推理开销；论文虽给出成本核算，但未系统探索小模型调度、缓存或规则化替代方案。
- **实验泛化性有限**：仅覆盖 LoCoMo 与 LongMemEval-S 两个对话记忆基准，且全部依赖 GPT 系列专有模型；未验证开源骨干、不同嵌入模型、不同语言与领域下的稳定性，也未报告多随机种子方差。
- **评测偏差与可复现性风险**：LLM-as-Judge 虽采用统一提示，但仍可能存在位置偏差、长度偏好或对主张包风格的偏好；论文未报告人工一致性校验或 Judge 与人工评分的相关性。
- **Open-Domain 未纳入跨方法比较**：这一处理合理，但也意味着系统在需要外部世界知识的问题上缺乏与其他方法的可比证据；同时论文未讨论记忆系统中的隐私、敏感信息过滤与错误记忆删除机制。

## 9. 启示与可延伸方向

- **把“来源身份”作为一等预算单位**：MemCompile 的核心启示是，长期记忆的稀缺资源不是“命中数”或“token 数”，而是“可追溯的独立来源数”。未来系统可在检索、重排、压缩各阶段显式维护来源覆盖约束。
- **寻址表示与证据表示应解耦**：原子事实、摘要、图节点适合做索引，却不一定适合直接作为答案上下文；更合理的架构是“轻量索引定位来源，原始/半原始证据按查询编译呈现”。
- **需要发展轮内细粒度来源边界**：在 SourcePacket 基础上引入句子级、片段级或事件级来源锚点，可在不破坏可追溯性的前提下降低长轮次噪声。
- **跨会话聚合需要专门机制**：可考虑会话级状态摘要、时间线对齐、冲突检测与偏好演化建模，以弥补当前包级调度在多会话问题上的不足。
- **成本感知调度值得研究**：用小型模型、蒸馏调度器、缓存路由决策或规则+模型混合策略替代高成本 LLM 调度，可能进一步推进质量—成本帕累托前沿。
- **评测应常规报告重复预算指标**：DBR、唯一来源数、来源级召回等指标能揭示“检索命中很多但证据覆盖很少”的隐蔽问题，建议纳入长期记忆 benchmark 的标准诊断集。

## 10. 总体评价

MemCompile 的概念贡献大于单纯的性能增量：它把长期记忆从“检索表示直接喂给阅读器”推进到“先恢复来源、再编译证据”的两阶段框架，并用源归一化边界解决了多通道重复占用预算这一实际问题。实验上，LoCoMo 总体领先、质量—成本前沿改善、读者视图与互补调度的消融均提供了较强证据；但跨会话聚合、在线调度成本、LLM 依赖与评测泛化仍是明显短板。总体而言，这是一项问题刻画清晰、架构完整、诊断意识较强的系统工作，若能在来源粒度、增量布局、低成本调度与多骨干验证上继续推进，将更具通用性与部署价值。
