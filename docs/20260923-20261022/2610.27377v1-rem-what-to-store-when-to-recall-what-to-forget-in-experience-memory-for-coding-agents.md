## 摘要
大语言模型（LLM）智能体现在能够通过数百个“思考—行动”步骤自主完成长时程任务，例如仓库级编程，但每次运行产生的经验很少在下次被复用。此前的记忆系统集中于检索，即找到最相关的历史轨迹。检索无法观察正在运行的智能体，因此无法决定智能体是否需要某段经验、在何时需要，以及需要多久。我们提出 REM（Reusable Experience Memory，可复用经验记忆），一个从智能体“思考—行动”循环内部管理记忆生命周期的框架，通过三项明确决策实现。存储什么：每条完成的轨迹被整合为一份按阶段组织的文档，其规模比原轨迹小两个数量级。何时回忆：该文档在任务开始时注入；成本更高的实现记录则暂不提供，直到循环内的门控机制检测到智能体陷入困难。遗忘什么：该记录在单次曝光后被淘汰。在仓库级缺陷修复任务（SWE-ContextBench Lite）上，REM 检索相关轨迹的准确率高于所有最先进的记忆系统（match@1 为 68.7% 对 55.6%），并在每次重复实验中都以低 17% 的成本提升最终任务解决率（27.6% 对 24.9%）。将相同经验以摘要或原始轨迹形式注入，即使通过 oracle 检索获得，也无法取得同样效果。消融三项决策中的任意一项都会降低解决率。总之，这些结果表明，经验复用中的瓶颈并非检索保真度，而是经验在其生命周期中如何被存储与治理，这为智能体记忆开辟了控制论视角。

## Abstract
Large language model (LLM) agents now autonomously complete long-horizon tasks, such as repository-level coding, through hundreds of think-act steps, yet the experience each run produces is rarely reused on the next. Prior memory systems concentrate on retrieval, finding the most relevant past trajectory. Retrieval cannot observe the running agent, so it cannot decide whether the agent needs an experience, at which point, or for how long. We introduce REM (Reusable Experience Memory), a framework that manages the memory lifecycle from inside the agent's think-act loop through three explicit decisions. What to store: each completed trajectory is consolidated into a phase-structured document, two orders of magnitude smaller than the trajectory. When to recall: the document is injected at the start of the task; the costlier implementation record is withheld until an in-loop gate detects the agent struggling. What to forget: the record is evicted after a single exposure. On repository-level bug fixing (SWE-ContextBench Lite), REM retrieves the related trajectory more accurately than every state-of-the-art memory system (68.7% vs. 55.6% match@1) and improves, in every replicate, end-task resolution (27.6% vs. 24.9%) at 17% lower cost. Injecting the same experience as a summary or raw trajectory, even when oracle-retrieved, does not. Ablating any of the three decisions reduces resolution. Altogether, these results demonstrate that the bottleneck in experience reuse is not retrieval fidelity but how experience is stored and governed across its lifecycle, opening a control-theoretic perspective on agent memory.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体已能通过数百个 think-act 步骤自主完成仓库级编程等长时程任务，每次运行都会产生包含探索、死路与最终解的详细轨迹；但每次运行产生的经验很少被下一次运行复用。
- **现有工作的偏差**：主流记忆系统把精力集中在生命周期的中段——**检索最相关的历史轨迹**（Mem0、LangMem、Supermemory、OpenViking 等），或存储反思、技能、工作流（Reflexion、ExpeL、Voyager 等）。
- **作者的核心论点**：检索无法观察正在运行的智能体，因此无法决定三件事——智能体**是否需要**某段经验、**在哪个时刻**需要、**需要多久**。经验复用的瓶颈不是检索保真度，而是**经验以什么形式存储、以及在注入后如何被治理**。
- **关键经验证据**：
  - 智能体只使用所收到上下文的一小部分，且需主动解释所给内容；
  - 无关或位置不当的上下文会降低性能（模型易分心、长上下文按位置利用不均）；
  - 抽象经验的迁移效果优于细节轨迹，详细轨迹甚至在困难案例上产生负迁移。
- **问题重述**：把智能体经验记忆从“查找问题”重构为“**控制问题**”——一个关于“存什么、何时召回、遗忘什么”的策略问题，每个决策都可独立度量、定价与替换。

## 2. 方法论

### 2.1 核心思想

REM（Reusable Experience Memory）在智能体的 think-act 循环**内部**管理记忆生命周期，用三个显式决策对应三个可替换的策略槽：

| 决策 | 机制 |
|---|---|
| **存什么**（Write path） | 将完整轨迹整合为一份四阶段结构化文档 |
| **何时召回**（Read path + in-loop node） | 任务开始时注入文档；实现记录仅在检测到“挣扎”信号时注入 |
| **遗忘什么**（Eviction） | 实现记录单次曝光后即驱逐；文档全程保留 |

整体流水线适用于任何遵循 **localize → understand → fix → verify** 四阶段的工作（调试代码、text-to-SQL 修复、事件响应等）；领域差异只通过一个可替换的**抽取字段模块**进入。

### 2.2 写路径（What to Store）

- 每条轨迹为 55K–170K token 的对话记录。
- **扁平化**：保留用户文本、助手文本、工具调用输入，丢弃工具结果，约缩小 15 倍且不截断。
- **一次 LLM 调用**抽取带类型的字段模式（编程领域：文件、函数、根因、修复思路、测试）。
- **确定性渲染器**将其排布为四阶段文档，平均约 **270 token**，比原轨迹小**两个数量级**。
- 记忆理论视角：这是从**情景记忆（episodic trace）到语义记忆（semantic memory）**的巩固——保留解的结构，丢弃产生它的搜索噪声。

### 2.3 读路径（When to Recall，任务开始时）

- 用现成文本嵌入模型对经验池与新任务的问题陈述做嵌入；
- 取余弦相似度最近的 **5 个**文档，送入**一次 LLM 重排调用**；
- 注入选中的文档；重排器**从不弃权**，解析失败时回退到余弦 top-1。
- 设计刻意简单：作者假设“**存什么的结构比怎么搜更重要**”。

### 2.4 循环内召回节点（两层级 + 挣扎门控 + 单次驱逐）

- **第一层**：约 270 token 的阶段化文档在运行开始时注入，用于定向。
- **第二层（实现记录）**：同一轨迹的原始编辑与验证，上限 12K 字符，**仅在按需时注入**——首次“验证失败”时触发（对测试文件的编辑被过滤，避免自写测试误触发）。
- **驱逐**：记录曝光一次后即从上下文中移除，不进入缓存前缀；文档则全程保留。
- 算法流程（Algorithm 1 的文字版）：
  - 写：对池中每条轨迹 τ，计算 `d ← RENDER(EXTRACT(FLATTEN(τ)))`、`r ← RECORD(τ)`，存入 `(d, EMBED(d), r)`；
  - 读：`C ← TOPK cos(EMBED(q), e)`，`(d*, r*) ← RERANK(q, C)`；
  - 循环：若未门控且观察到挣扎信号 `S(o_{1:t-1})`，则 `ρ ← r*` 并置门控为真；否则 `ρ ← ∅`；上下文 `c_t ← q ⊕ d* ⊕ h_{t-1} ⊕ ρ`，其中 `d*` 持续存在、`ρ` 不持续。

### 2.5 自动模式发现

- 抽取模式是记忆唯一的领域特定产物，用一个**元循环**从少量示例轨迹（9 条，均非评估任务）自动学习：
  1. LLM 写候选结构化提示（6–10 个带类型字段、精确命名规则、JSON 模板）；
  2. LLM 评审按 **覆盖度、特异性、可区分性、简洁性、结构一致性** 五个维度打 1–5 分；
  3. 针对弱维度修订，最多 **5 轮**。
- 编程领域首轮即收敛（各维度均值 4.00–4.75），得到 8 字段模式；text-to-SQL 同样首轮收敛得到 10 字段模式，证明领域迁移只需示例轨迹而非提示工程。

### 2.6 测量与统计

- **利用率探针**：从实际注入文本中抽取标识符（文件路径、≥4 字符的 CamelCase/snake_case 名称，去停用词），记录哪些出现在智能体自身文本或工具调用输入中（排除工具结果，并扣除配对无记忆运行已出现的标识符）；报告**覆盖率**（被引用注入标识符占比）。
- 统计：解决率按任务配对，用双侧精确 McNemar 检验并跨重复合并；每任务解决计数的 Wilcoxon 符号秩检验结论一致；利用率用 Cohen's d 与双侧 Mann-Whitney 检验。
