ABSTRACT 

Agentic memory allows LLM agents to reuse past experience, yet retrieved mem-ories can also distort inference even when they are benign, correctly stored, and appropriately retrieved. We study this failure mode, which we call memory over-reliance . Across benchmarks and memory architectures, we find that memory is useful when past experience transfers to the current task, but can become mislead-ing when only part of the evidence transfers. Failures are strongest under partial query-memory overlap, a pattern further confirmed by controlled experiments that vary the amount of overlapping evidence. Motivated by this finding, we propose MEM TRIM , a plug-and-play framework that indexes memory evidence at write time and controls its reuse at read time. M EM TRIM removes repeated or conflict-ing evidence while preserving useful memory-specific information, requires no retraining, and applies to both embedding-based and structured memory systems. Experiments show that M EM TRIM reduces memory overreliance while preserving the benefits of useful memory across models and memory settings. 

1 INTRODUCTION 

Memory allows LLM agents to carry information across interactions and reuse past experience on future tasks. This capability is increasingly important for agents that operate over long horizons, where solving each request in isolation would discard useful experience accumulated from previous interactions (Xiong et al., 2026; Park et al., 2023; Zhong et al., 2024; Shinn et al., 2023; Zhao et al., 2024). However, memory can misguide inference even when the memory itself is benign. A memory may be correctly formed and appropriately retrieved during normal user-agent interactions, yet contain information that does not fully transfer to the current task (Yoran et al., 2024; Yu et al., 2024; Kim & Lee, 2024). Once placed in the inference context, such memory can exert undue influence on the model’s reasoning. We refer to this phenomenon as memory overreliance : excessive reliance on benign memory that harms inference on the current task. 

Our Work. We study this issue in three steps. We first establish when memory overreliance occurs and investigate its cause. We then develop a mitigation method. Finally, we test whether the method reduces overreliance while preserving the benefits of useful memory. We begin with a three-level empirical analysis of memory overreliance. ❶ First, we ask whether overreliance arises under ordinary memory use . Across multiple benchmarks (Cohen et al., 2024; Joishy et al., 2025; Jin et al., 2023) and memory architectures (Chhikara et al., 2025; Xu et al., 2026; Packer et al., 2023; Rasmussen et al., 2025), we find a clear contrast: memory improves inference when the stored interaction remains applicable, but can reduce accuracy when the current task shares substantial evidence with the memory while requiring a different conclusion. ❷ Subsequently, we examine where these failures occur . We compare query-memory overlap between successful and failed cases and find a statistically significant difference. Successful cases appear more often near the two extremes of the overlap range, while failures concentrate under partial overlap. In this regime, enough evidence is shared to make the memory influential, yet some answer-relevant information still differs. ❸ Furthermore, we test this relationship directly through controlled experiments that vary the amount of overlapping evidence while holding the remaining memory content fixed. Collectively, these results indicate that partial evidence overlap is a key reason in which ordinary memory use can become misleading at inference time. These findings motivate M EM TRIM 1, a plug-and-play framework that controls how overlapping memory evidence enters inference. At write time, M EM TRIM decomposes each memory into evidence units and indexes them in a trie (Bodon & Rónyai, 2003). Identical evidence maps to shared trie nodes, while different values of the same evidence branch separately. At read time, the current query is mapped into the same evidence space and compared with the retrieved memories. M EM TRIM 

removes evidence already present in the query, drops conflicting memory evidence, and retains useful information found only in memory. It also removes a previous answer when the evidence it relied on has changed, or preserves it only as contextual evidence when the current query asks a different question. Since M EM TRIM operates only when memory is written and read, it can be added to existing embedding-based and structured memory systems without retraining the underlying LLM. We evaluate whether this design reduces overreliance without weakening useful memory. Across benchmarks, LLMs, and memory architectures, M EM TRIM reduces memory-induced errors on task-divergent cases while preserving the benefit of memory when the stored interaction remains applicable. Component ablations show that removing repeated and conflicting evidence, handling previous answers when relevant evidence changes, and distinguishing task changes each contribute in the settings they are designed for. We further test M EM TRIM under deliberate memory attacks and find that its performance degrades more gradually as misleading memories increase. Finally, MEM TRIM introduces only small changes in inference time across the evaluated memory systems. To summarize, our contributions are as follows: • We identify memory overreliance as an inference-time failure of benign agentic memory and show that failures concentrate under partial evidence overlap between the current query and retrieved memory. • We propose M EM TRIM , a plug-and-play framework that indexes memory at the evidence level and controls how repeated, conflicting, and memory-specific information is reused during inference. • We evaluate M EM TRIM across benchmarks, LLMs, and memory architectures, including component ablations, memory-attack stress tests, and runtime analysis.

2 AN EMPIRICAL STUDY OF MEMORY OVERRELIANCE 

We study memory overreliance through three questions. RQ1 asks whether benign memory can hurt inference under normal memory use. RQ2 examines where these failures occur along the query-memory overlap range. RQ3 then controls the amount of overlapping evidence to test whether the same pattern persists when the overlap is varied directly. 

Benchmarks and Models. We evaluate on RippleEdits (Cohen et al., 2024), CounterLogic (Joishy et al., 2025), and CLADDER-Derived (Jin et al., 2023) using Qwen3.8-27B and GPT-5.6 Luna. For each benchmark, memories are built from earlier interactions with valid stored answers and evaluated on separate queries. 

Memory systems. We evaluate four memory systems with different architectures: Mem0 (Chhikara et al., 2025) stores extracted memory entries in a retrieval index; A-Mem (Xu et al., 2026) creates structured notes and dynamically links related memories; MemGPT (Packer et al., 2023) separates active and archival memory; and Graphiti (Rasmussen et al., 2025) represents memory as a relational graph. 

Cases and metrics. We divide queries into task-aligned (TA) and task-divergent with overlapping evidence (TD-Dup) cases. In TA cases, the current query asks the same task as the stored interaction and preserves the answer-relevant evidence, so the retrieved memory is useful. In TD-Dup cases, the query still shares substantial evidence with the stored interaction, but the task or answer-relevant information differs (outdated, conflicting, or irrelevant), so the stored conclusion should not be directly reused. We report task accuracy for both groups. On TD-Dup cases, we additionally track predictions that change from correct to wrong ( ✓ →✗) and from wrong to correct ( ✗ →✓) after memory is introduced, separating errors caused by memory from cases where memory improves the prediction. 

RQ1: Can ordinary memory use degrade inference? 

We first compare each model with and without memory. Because every stored interaction was correct when written, this experiment isolates whether ordinary memory reuse can have negative impacts once the current memory storage no longer supports the same query task. 

Observations: Table 1 reveals a clear difference between task-aligned (TA) and task-divergent with overlapping evidence (TD-Dup) cases. In TA cases, retrieved memory is consistently useful across datasets and memory architectures because the stored interaction remains applicable to the current task. In TD-Dup cases, the same memory can instead reduce accuracy. At the example level, memory-induced regressions occur much more often than memory-induced corrections. 

Insights: This contrast suggests that the problem is not that memory is generally noisy or unhelpful. The same memory mechanism benefits inference when the stored experience transfers to the current task, yet becomes misguiding when only part of that experience transfers. Memory overreliance therefore arises from how partially overlapping evidence is reused during inference.

We next examine which TD-Dup cases are the most vulnerable. We call a case successful when it remains correct after memory is added and failed when memory changes a correct prediction into an incorrect one. For each case, we compute the content-word Jaccard overlap between the current query and retrieved memory, excluding the stored answer. We refer to this quantity as query-memory overlap and compare its distribution between the two groups. 

Observations: Figure 2 shows that successful and failed cases occupy different parts of the overlap range. Successful cases occur more often near the two extremes: very little overlap gives memory limited influence, while very high overlap indicates that the current task closely resembles the stored interaction. Failed cases instead concentrate under partial overlap, with a statistically significant separation across all four memory systems. 

Insights: This pattern suggests that overlap plays two roles. Increasing overlap makes retrieved memory more influential but does not guaranty that the evidence supporting its conclusion also transfers to the current task. Partial overlap is therefore particularly vulnerable: enough evidence is overlapped to make the memory dominant, while some answer-relevant information can still diverge. The exact distribution varies across memory architectures, but this pattern remains consistent. More results are provided in Appendix B. 

RQ3: How does overreliance change with overlapping evidence? 

RQ2 examines TD-Dup cases as they naturally occur, where factors beyond overlap may also distinguish successful from failed cases. To isolate the role of overlap, we construct a controlled setting in which each memory is decomposed into evidence units and vary the fraction repeated in the current query while keeping the remaining content fixed. As overlap increases, the answer-relevant evidence is gradually restored and the interaction moves toward the TA setting. At each level, we measure the memory effect as ∆Acc = Acc mem − Acc no -mem and test the non-monotonic trend with a quadratic term and the two-lines test (Simonsohn, 2018). 

Observations: Figure 3 shows a consistent non-monotonic trend across models and memory systems. With little overlapping evidence, memory has limited influence. As overlap increases, its harmful effect grows and is strongest at intermediate overlap. The effect then reverses as the current query becomes more aligned with the stored interaction.

3 METHOD 

Our empirical study shows that memory overreliance is most influential when a retrieved memory partially overlaps with the current query. This motivates a simple mitigation principle: explicitly identify replicated evidence and control how it enters inference. We develop M EM TRIM to implement this principle. Figure 4 gives an overview. We next describe the evidence representation (§3.1), write-time indexing (§3.2), and read-time memory use (§3.3). 3.1 OVERVIEW AND EVIDENCE REPRESENTATION 

MEM TRIM is a plug-and-play layer around an existing memory system. The underlying system continues to store complete memories and retrieve relevant entries using its original mechanism. MEM TRIM adds an evidence index when a memory is written and processes retrieved memories before they are passed to the LLM. It therefore requires neither model retraining nor replacement of the original memory architecture. Consider a stored interaction m = ( xm, y m), where xm contains the query and its context and ym is the resulting answer. We parse xm into a set of atomic evidence units Em. Each unit is represented as a key-value pair e = ( k, v ), where k identifies an attribute or relation and v gives its value. We further extract a task signature τm that specifies what the interaction asks the model to determine. The stored answer is represented as a typed outcome om = ( τm, y m) and associated with a support set Hm ⊆ Em, which contains the evidence on which that outcome depends. Thus, a memory is represented as m = ( Em, τ m, H m, o m). The same parser is applied to a current query q, producing 

Eq and τq . For free-text memory, we obtain these fields with a fixed instruction-based parser. If the underlying memory already contains structured metadata (e.g., graph-based memory (Rasmussen et al., 2025)), they can be mapped directly into the same representation. Details of implementations (e.g., evidence parsing and alignment) are provided in Appendix A.1. Preprint.

3.2 MEMORY WRITE : T RIE -B ACKED EVIDENCE INDEX 

At write time, M EM TRIM inserts each evidence unit into a global trie T . Evidence units are indexed independently, so one memory can be linked to multiple trie nodes. For an evidence unit e = ( k, v ),the trie first follows its canonical key k and then its value v. The corresponding node records the memories that contain this evidence and whether the unit belongs to their support sets Hm. Complete memories remain in the original memory store; M EM TRIM maintains only this evidence-level index. The trie makes shared and changed evidence directly distinguishable. Memories containing the same key-value unit point to the same node, whereas different values of the same key occupy different branches. For example, founded_in=2016 and founded_in=2017 share the same relation key but diverge at the value level.

At inference time, the underlying memory system first retrieves its usual candidate set R(q).MEM TRIM parses the current query into Eq and looks up its evidence units independently in the trie. For each retrieved memory m, the resulting matches divide its evidence into three sets: (i) shared evidence Sm(q), whose key and value also appear in the query; (ii) conflicting evidence 

Dm(q), whose key appears in the query with a different value; and (iii) memory-only evidence Um(q),which does not appear in the query. Since matching is performed independently for each unit, shared evidence can occur anywhere in the memory. MEM TRIM then constructs the memory context given to the LLM. Shared evidence is removed from the retrieved memory because it is already stated in the query, avoiding repeated support for the same information. Conflicting evidence is also removed because the current query supplies the value for the current inference. Memory-only evidence is retained when it provides additional information absent from the query. The stored outcome om is handled separately. If any supporting evidence conflicts with the current query, i.e., Dm(q) ∩ Hm̸ = ∅, M EM TRIM suppresses the previous outcome. Otherwise, its use depends on the task. When τm = τq , the outcome can be retained as a previous answer to the same task. When τm̸ = τq , M EM TRIM converts it into an evidence statement labeled by its original task. For example, a previous answer “2016” to a founding-year query can be represented as 

(founded_in , 2016) when a later query asks who founded the same organization. The earlier result can then remain available as contextual evidence without being presented as the answer to the new question. The transformed context from one memory is

4 EVALUATION 

We evaluate whether M EM TRIM reduces memory overreliance while preserving the benefit of useful memory. We detail settings and evaluations as below: 

Evaluation settings. To make M EM TRIM directly comparable with the previous results. We use the same benchmarks, backbone LLMs, memory systems, and metrics as in §2.

5 RELATED WORK 

Memory in LLM agents. Memory systems let an agent keep and reuse past experience. One line of works build the storage: long-term memory across sessions (Park et al., 2023; Zhong et al., 2024), context hierarchies (Packer et al., 2023), associative indexes (Gutiérrez et al., 2024), and self-organized memory (Xu et al., 2026). Other works turn past trajectories into reusable knowledge such as reflections, lessons, and workflows (Shinn et al., 2023; Zhao et al., 2024; Wang et al., 2024), and recent benchmarks evaluate these systems in multi-turn interaction (Hu et al., 2026). All of these designs leverage retrieved relevant memory to help the current reasoning tasks. 

Failures and attacks on memory reuse. Memory can also hurt. Agents copy retrieved experiences with similar inputs, so past errors spread (Xiong et al., 2026). Memories are applied where they no longer fit (Pulipaka et al., 2026; Piehl et al., 2026), turn faulty under repeated updates (Zhang et al., 2026a; Meng et al., 2026), or look similar to the query while being wrong for the task (Tang et al., 2026b; Zhang et al., 2026b). Memory is also an attack surface: adversaries poison memory banks (Chen et al., 2024), retrieval corpora (Zou et al., 2025), or self-evolving experiences (Wang et al., 2026), and defenses curate data against such samples (Liu et al., 2024). In all these cases, the failure comes from a flawed memory, a flawed retrieval, or an attacker. However, memory overreliance needs none of them: a correct, well-retrieved memory fails simply because its answer-relevant condition has changed. 

Reasoning under varying conditions. Knowledge editing asks how models handle updated facts and their ripple effects (Meng et al., 2022; Cohen et al., 2024). Counterfactual reasoning asks how models handle changed premises, with benchmarks on causal interventions (Yang et al., 2026; Jin et al., 2023), alternative story questions (Ashida & Sugawara, 2022), and knowledge-conflicting logic (Joishy et al., 2025), and with analyses of where LLMs fail (Tang et al., 2026a; Youssef et al., 2024; Yang et al., 2026). Such changes are routine in practice: in cyber threat intelligence, the landscape shifts fast enough that stored assessments go stale (Meng et al., 2025a;b; Tang et al., 2025). Prior work treats a changed condition as a reasoning challenge for the model. We show that memory makes it worse: the stored answer anchors the model to the old condition, and our framework removes this anchor at read time. Preprint. 

6 CONCLUSION 

We study memory overreliance, where benign and appropriately retrieved memory can misguide inference when only part of the stored experience transfers to the current task. Our experiments identify partial evidence overlap as the most vulnerable regime and motivate M EM TRIM , which controls repeated and conflicting memory evidence before inference while preserving useful memory-specific information. Across models and memory architectures, M EM TRIM reduces harmful memory reuse while retaining the benefits of applicable memory, with small runtime changes and added resistance under memory attacks.

A COMPLEMENTARY TECHNICAL DETAILS OF MEM TRIM 

A.1 IMPLEMENTATION DETAILS 

This part provides implementation details omitted from §3. We focus on how free-text interactions are converted into stable evidence units, how answer-support sets and task signatures are constructed, and how evidence from multiple retrieved memories is combined at read time. 

Canonicalizing evidence units. The same fact can be expressed in many ways, so M EM TRIM 

does not index raw text directly. For each interaction, we use a fixed parser prompt to extract typed evidence records. We retain the notation e = ( k, v ) from §3.1, but internally the key k contains the entity being described, its attribute or relation, and its value type. For example, “Highway 5 is closed,” “Route 5 has been shut,” and “Highway 5 is not open” can all map to (Highway5_status , closed ).In contrast, the word “open” in “the restaurant is open” is assigned a different key because it refers to a different entity and attribute. This prevents surface similarity alone from merging evidence with different meanings. When a new unit is parsed, M EM TRIM first checks for an exact canonical key in the trie. If none exists, it retrieves a small set of existing keys with the same entity and value type and asks the parser whether the new key is semantically equivalent to any of them. Equivalent keys are merged; otherwise a new key is created. Values are aligned only after their keys match. Boolean, categorical, numeric, and temporal values are normalized into a fixed form; free-text values use the same equivalence check. When equivalence is unclear, M EM TRIM keeps the units separate. This conservative rule avoids merging two pieces of evidence only because they share similar wording. Each parsed unit also keeps a pointer to the text span from which it was extracted. We use this span to verify that every indexed unit is grounded in the original interaction. A parsed unit that cannot be traced to the input is discarded before insertion into the trie.              

> Canonical Evidence Alignment
> Suppose one memory states “Highway 5 is closed today” , while another states “Route 5 has been shut for the day.” Both are normalized to (Highway5_status ,closed )and therefore share one trie node. If a third memory states “Highway 5 is open” , it shares the same key but follows a different value branch,
> Highway5_status=open .The word open may also occur in an unrelated sentence such as “the visitor center is open.” This evidence is indexed under a different key, e.g., (VisitorCenter_status ,open ), and is never merged with the highway-status evidence.

Extracting task signatures and answer support. The parser also produces the task signature τm

and support set Hm. A task signature records both the requested operation and its target. For example, “Which route should I take?” and “Recommend a route to City B” map to the same route_planning Preprint. signature, whereas “How long will the trip take?” maps to travel_time . We canonicalize task signatures with the same procedure used for evidence keys. If two task descriptions cannot be confidently aligned, we treat them as different tasks; this prevents an earlier answer from being reused under an uncertain task match. To construct Hm, the parser marks which evidence units directly support the stored outcome om. For the route-planning example, the answer “Take Highway 5” may depend on (Highway5_status , open )

and (destination , B ), while an unrelated fact such as the weather need not belong to Hm. We use a conservative policy for uncertain cases: evidence is included in Hm when the parser cannot determine whether the stored outcome depends on it. This can suppress reuse more often, but avoids keeping an outcome after potentially important support has changed. When τm̸ = τq , M EM TRIM converts a previous outcome into evidence only when it can be expressed as a factual key-value unit without changing its meaning. For example, “Take Highway 5” can be converted to (recommended_route , Highway5 ) when a later query asks about travel time. Outputs that are inherently procedural, subjective, or cannot be represented faithfully as evidence are omitted under a task change. 

Combining multiple retrieved memories. The trie is used only to process memories already returned by the underlying retriever. Given R(q), M EM TRIM restricts all trie matches to the memory identifiers in this set; it does not use the trie as an additional retrieval system. After each retrieved memory is transformed as described in §3.3, M EM TRIM merges the retained evidence using its canonical trie identifiers. Identical memory-only evidence from several memories is emitted once. If several retrieved memories provide different values for the same key and the current query does not resolve the conflict, M EM TRIM does not select a value based only on retrieval similarity. By default, all unresolved values for that key are withheld from the final context. If the base memory system provides an explicit ordering signal such as a trusted timestamp, that metadata can be used to resolve the conflict before this step. The current query always takes precedence when it provides a value for the same key. Thus, if the stored memory contains Highway5_status=open while the current query contains 

Highway5_status=closed , the stored value is removed regardless of the memory’s retrieval score. 

Parsing failures and runtime cost. Memory evidence is parsed once when the memory is written, and its structured representation is cached with the trie index. At inference time, M EM TRIM only parses the current query once; retrieved memories reuse their cached evidence units, task signatures, and support sets. Trie matching therefore consists of key-value lookups over the evidence units in Eq

and the retrieved memory identifiers. We use constrained structured output and deterministic decoding for the parser. Each result is checked for valid fields, grounded source spans, and well-formed key-value types. If parsing fails, we retry once with the same interaction and the validation error. If a valid representation still cannot be produced, the raw memory remains in the base memory store but its stored outcome is not reused through M EM TRIM . This keeps parser failures from introducing an unchecked answer into the inference context.

C CONSTRUCTION OF TASK -A LIGNED AND TASK -D IVERGENT MEMORY 

PAIRS 

The source benchmarks were not designed for agentic memory evaluation and do not directly provide a stored interaction paired with a later query. We derive such pairs from the released benchmark annotations. A task-aligned (TA) pair uses a stored answer that remains valid for the current query. A 

task-divergent with duplicated evidence (TD-Dup) pair preserves substantial information from the stored interaction but changes the task or answer-relevant information, so the stored answer no longer applies. No LLM is used to generate examples, assign TA/TD-Dup labels, or determine gold answers. Labels come from the original benchmark annotations or fixed rules described below. Sentence encoders are used only to identify related candidate examples when an explicit pair is not provided by the benchmark. Preprint.

RippleEdits (Cohen et al., 2024) represents factual changes as subject-relation-object edits and provides both the original and updated values for modification examples. We use the RANDOM and POPULAR subsets and exclude RECENT, which contains fact insertions without the corresponding old value. For each edit, we keep the entity, relation, and current query fixed. The TA memory stores the updated value, while the TD-Dup memory stores the original value. Thus, both memories refer to the same fact but differ in the value that determines the answer. We use Subject Aliasing queries because they preserve the underlying subject-relation pair while varying only how the subject is mentioned. We remove examples when either target is missing or when the original and updated targets become indistinguishable after alias normalization. From the 2,000 RANDOM and POPULAR edits, we sample at most 500 source queries with random seed 42. Each retained query contributes one TA and one TD-Dup condition. C.2 COUNTER LOGIC 

CounterLogic (Joishy et al., 2025) provides each set of premises and conclusion with two judgments: logical validity and agreement with real-world knowledge. This lets us change the question while keeping the underlying evidence fixed. For each instance, the stored interaction asks whether the conclusion is logically valid, while the current interaction asks whether it agrees with real-world knowledge. We use fixed templates for both questions and copy the premises and conclusion directly from the benchmark. An instance is TA when the validity and knowledge-alignment labels agree, and TD-Dup when they differ. The pair type therefore comes entirely from the two benchmark labels. To form plausible retrieval groups, we encode the premises and conclusion with 

sentence-transformers/all-mpnet-base-v2 , excluding the task instruction, gold label, and any answer-revealing fields. We use agglomerative clustering with average linkage and cosine distance, a distance threshold of 0.20, and a minimum cluster size of five. Clustering only limits which memories can be retrieved; it does not determine whether an example is TA or TD-Dup. We use all 1,800 CounterLogic instances and sample at most 500 TA and 500 TD-Dup examples with random seed 42. C.3 CLADDER-D ERIVED PREMISE -C HANGE PAIRS 

CLADDER (Jin et al., 2023) provides natural-language causal questions, structured metadata, and gold answers. We derive premise-change pairs from the official balanced release while keeping the original question text and gold labels. We first group examples that have the same story_id , graph_id , query_type , and rung .This keeps the causal scenario and question type fixed. Within each group, we replace all numerical values with a common <NUM> token and encode the remaining text with 

sentence-transformers/all-mpnet-base-v2 . Candidate pairs must have cosine similarity of at least 0.85. We then verify that the pair also overlaps at the evidence level using the structured causal quantities provided by CLADDER. Each numerical statement is converted to a key-value entry. We retain pairs Preprint. whose evidence keys have Jaccard similarity of at least 0.80, contain at least one unchanged value and at least one changed value, and have at least one changed value that appears in the benchmark-provided reasoning for the queried causal quantity. These checks ensure that the two examples share most of the same causal setup while differing in information that can affect the answer. The original CLADDER answers determine the pair type: a pair is TA when the two gold answers agree and TD-Dup when they differ. The sentence encoder and evidence-overlap checks are used only to decide whether two examples are similar enough to form a pair. For each source interaction, we select one TA and one TD-Dup candidate with similar semantic similarity and evidence overlap. When several candidates are available, we choose the pair with the smallest combined difference in these two quantities and break ties by example identifier. Source interactions without suitable candidates for both conditions are removed. From the 10,112 questions in the official release, we sample at most 500 TA and 500 TD-Dup pairs with random seed 42. C.4 CONSTRUCTION CHECKS 

We apply the same checks across all three datasets. Every stored interaction must be correct in the setting where it was written, and every current query must have a gold answer supplied by the benchmark or its formal reasoning procedure. Model predictions are never used as labels. We remove duplicate memory-query pairs and keep examples derived from the same source unit in the same data split. We also compare query-memory similarity, evidence overlap when available, and input length between TA and TD-Dup after construction. If the two groups differ substantially on these properties, we apply additional matching before evaluation. Task alignment only describes whether the stored answer remains valid for the current query. It does not require memory to be necessary for solving the query.
