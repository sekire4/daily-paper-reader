## 摘要
持久记忆使语言模型智能体无需更新模型权重即可改进提示词和技能。我们表明，使检索范围与认证范围相匹配，可使这些编辑支持在反复出现的任务族上实现可靠的重复适应。我们在 ProcStream-RSI（一个 12 轮代码修复流）上研究冻结模型智能体，使用正交回归控制（ORC）——一种面向持久技能编辑的、基于执行的门控机制。在一项保持提案和门控决策不变的干预中，仅将每个被接受的技能检索用于其原始任务族，使平均隐藏轨迹效用从全局记忆下的 0.713 提高到 0.816，并将有害部署从 8 次中的 6 次降至 0 次。在 27 个配对随机顺序流中，Scoped-ORC 相比 Global-ORC 将平均轨迹效用提高 0.063 [0.037, 0.094]，接受 63 次而非 12 次更新，并在 19/27 个流中产生多次被接受的更新，且有害接受为 0/63。全局对照达到 0.713，低于静态智能体的 0.775，因为局部有效的编辑可能干扰无关任务族。这些结果确立了范围匹配作为持久智能体记忆的一种补充性控制：认证决定一项编辑是否得到支持，而检索范围决定该证据在何处授权其使用。

## Abstract
Persistent memory lets language-model agents improve prompts and skills without updating model weights. We show that matching retrieval scope to certification scope enables these edits to support reliable repeated adaptation across recurring task families. We study frozen-model agents on ProcStream-RSI, a 12-round code-repair stream, using Orthogonal Regression Control (ORC), an execution-grounded gate for persistent skill edits. In an intervention that holds proposals and gate decisions fixed, retrieving each accepted skill only for its originating family raises mean hidden trajectory utility from 0.713 under global memory to 0.816 and changes harmful deployments from six of eight to none. In 27 paired randomized-order streams, Scoped-ORC improves mean trajectory utility by 0.063 [0.037, 0.094] over Global-ORC, accepts 63 rather than 12 updates, and produces multiple accepted updates in 19/27 streams, with 0/63 harmful acceptances. The global control reaches 0.713, below the static agent's 0.775, because locally valid edits can interfere with unrelated families. These results establish scope matching as a complementary control for persistent agent memory: certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：大语言模型智能体可以在不更新模型权重的前提下，通过持久化的提示词/技能（skill）编辑实现"自我改进"。以 G¨odel Agent、Darwin G¨odel Machine 为代表的自我指涉系统让冻结模型的外部脚手架持续演化。
- **核心问题**：现有工作多关注"提案质量"和"门控准确率"，即**一项编辑是否被证据支持**；但忽略了第二个决策——**该编辑应在何处被检索/部署**。
- **关键洞察（跨任务族干扰，cross-family interference）**：在某一任务族（family）内部局部有效的编辑，一旦被压缩进单一全局技能并全局部署，就会影响无关任务族，造成有害部署。全局持久记忆甚至可能**低于静态智能体**（0.713 vs 0.775）。
- **研究主张**：持久化智能体记忆需要两个对齐的决策——认证（certification）决定编辑是否被支持，检索作用域（retrieval scope）决定该证据在何处授权使用；二者匹配才能实现"持续适应"（continual adaptation）。
- **形式化动机**：作者给出命题 1——当 $\pi\alpha G > (1-\pi)\beta L$ 时期望部署变化为正；若多证据通道的误接受事件高度相关，叠加通道并不能降低 $\beta$。该命题只覆盖门控证据中已表示的结果，**无法保护未出现任务族上的无作用域全局编辑**。

## 2. 方法论：核心思想与关键技术细节

### 2.1 总体框架（部署视角的持续自我改进）

- 冻结 actor $\pi_\theta$ + 持久自然语言技能 $K_t$（固定 360 字符预算）；冻结 editor 根据发现批 $D_t$ 提出 $K'_t$；门控 $G_t$ 在配对探针任务上决定是否部署：
  $$K_{t+1} = K'_t \text{ if } G_t(K'_t, K_t)=1,\ \text{else } K_t$$
- 报告指标：末端效用、平均轨迹效用（MTU）、平均后向迁移（BWT）、最差族保持率、最终 bank 分数；**不使用 archive-best 作为主结论**。

### 2.2 正交回归控制（ORC）——执行落地的门控

- 每个任务设三条在线证据通道：4 个公开样例（pub）、4 个私有精确输出测试（priv，不进 actor/editor 提示）、≥6 个无答案变形检查（meta）。
- 探针实例划分为"当前族"和"每个历史族"的组；对每个（组, 通道）计算**单侧 95% 配对 bootstrap 下界** $L_{g,c}$（样本 ≤50,000 精确枚举，否则 2,000 次种子抽样；每组 ≥4 任务）。
- 部署条件（$\delta_{new}=0,\ \delta_{reg}=0.02$）：
  - 当前族：$L_{current,pub} \ge -\delta_{reg}$，$L_{current,priv} > \delta_{new}$，$L_{current,meta} \ge -\delta_{reg}$；
  - 所有历史族与通道：$L_{g,c} \ge -\delta_{reg}$；
  - 且私有/变形评估不得报告不安全程序。
- 合取（AND）设计防止某通道的增益"平均掉"另一通道的退化；被拒提案留在 trace 中但不影响后续提示。

### 2.3 族作用域检索（Scoped-ORC）——核心补救

- 接受候选存入**当前族的槽位**；任务来自族 $f$ 时，actor 收到：
  $$K_t(f) = K'_t(f) \text{ 若 } f \text{ 存在已接受槽位，否则 } K_0$$
- 活跃策略仍严格为 360 字符——只改变"检索哪个策略"，不改变提示预算；提案生成与门控逻辑完全不变，从而**隔离"跨族暴露"这一机制**。

## 3. 实验设计

### 3.1 基准与场景

- **ProcStream-RSI v3.1**：12 轮代码修复流，9 个循环出现的任务族（boundary, rotation, ordering, normalization, nested, missing, prefix, chunk, tie-breaking），每族有种子派生的不透明协议 token。
  - 每轮 4 个发现任务 + 4 个探针任务；固定 bank 含每族 1 个 checkpoint + 2 个 final 任务，**每条流 123 个任务**。
  - 公开/私有/隐藏输入两两不相交；隐藏案例对在线智能体不可见，仅由无模型审计器加载。
  - 作者明确承认：任务语义与族顺序固定、程序化实例化"熟悉的契约"，**并非适应随机化的新语义**。

### 3.2 对比方法（7 种配对）

1. **Static**（从不更新）；2. **Frozen-compute**（同样的编辑/门控/评估调用但从不部署）；3. **Latest-only**（部署每个格式正确的提案）；4. **Self-judge**（actor 自评正确率）；5. **Replay**（当前公开增益 + 历史公开不退化）；6. **ORC**（全通道门控）；7. **Batch-ORC**（累积证据一次性更新，仅最终提案可部署）。

### 3.3 实验层次

- **主实验**：8 条未见过种子的完整 12 轮流。
- **固定完成干预**：8 条主流上保持提案/门控决策不变，仅改变检索作用域。
- **平衡随机入口扩展**：18 条流（每个可能首族 2 条），每流 1 个更新轮，Global 与 Scoped 配对共享提案与决策。
- **完整随机顺序扩展**：27 条流（每首族恰好 3 条），12 轮全流程，Global 与 Scoped 逐流配对。
- **外部迁移诊断**：32 个 HumanEval+ 任务（固定 SHA-256 排序预选）；GPT-OSS-120B 在 18 任务 sealed final bank 上仅 actor 推理。
- **路由器分析**：字符 3–5-gram 多项式朴素贝叶斯的 leave-one-seed-out 路由器，与 oracle 路由对比。

### 3.4 统计方法

- 以完整流为独立单元；种子级 bootstrap 95% 区间；双侧配对 sign-flip 检验；三项主要对比做 Holm 校正；路由器用 fallback-on-miss 曲线建模保守回退。
