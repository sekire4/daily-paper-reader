## 摘要
个性化大语言模型助手必须在复杂度各异的查询中，从长对话历史中恢复稀疏证据。我们提出 APDMem（Agent-controlled Progressive Disclosure Memory，智能体控制的渐进式披露记忆），一种将渐进式披露应用于记忆检索的分层长期记忆架构。该架构不依赖扁平记忆存储或固定检索粒度，而是将对话历史表示为四个逐步细化的层级：主题摘要、个性化关键事实、轮次级证据笔记和原始消息。推理时，控制器对记忆层级应用渐进式披露：先读取高层摘要，仅在需要时深入更细粒度证据。这形成了一种自适应的成本—保真度权衡：简单查询可提前终止，而复杂的时间、多跳或精确证据查询会触发更深层检查。笔记合成器将检索到的证据转换为面向查询的结构，在最终答案生成前整合事实、排序事件并标记矛盾。在 LongMemEval 上的实验表明，APDMem 在仅访问总对话 8% 的情况下，在长上下文记忆推理方面取得了强劲性能。

## Abstract
Personalized LLM assistants must recover sparse evidence from long conversation histories across queries of varying complexity. We introduce APDMem (Agent-controlled Progressive Disclosure Memory), a hierarchical long-term memory architecture that applies progressive disclosure to memory retrieval. Rather than relying on a flat memory store or fixed retrieval granularity, APDMem represents conversation history as four progressively detailed layers: thematic summaries, personalized key facts, turn-level evidence notes, and raw messages. At inference time, a controller applies progressive disclosure to the memory hierarchy: it first reads high-level summaries and drills into finer evidence only when needed. This creates an adaptive cost-fidelity trade-off: simple queries can terminate early, while complex temporal, multi-hop, or exact-evidence queries trigger deeper inspection. A note synthesizer converts retrieved evidence into a query-focused structure that consolidates facts, orders events, and flags contradictions before final answer generation. Experiments on LongMemEval show that APDMem achieves strong performance for long-context memory reasoning while accessing only 8% of the total conversations.

## 1. 核心问题与研究动机

- **背景**：个性化 LLM 助手需要在长期、多会话的交互中保持记忆连续性，避免“上下文失忆”（contextual amnesia）——忘记用户偏好、事实细节、时间顺序或跨会话关联。
- **核心问题**：相关证据在长对话历史中高度稀疏，且查询复杂度差异巨大。简单查询只需高层信息，而时间推理、多跳、精确措辞类查询需要细粒度证据。
- **现有方法的局限**：
  - 扁平记忆存储或固定检索粒度无法同时兼顾“简单查询的低成本”与“复杂查询的高保真”。
  - MemoryBank、MemGPT、A-MEM、Zep 等需将对话转化为专用记忆对象、图节点或演化网络；LightMem、SimpleMem 等依赖压缩或语义记忆。这些方案虽降低成本，但引入了额外的记忆机制，且存在压缩导致细节丢失的风险。
- **整体含义**：论文将长期记忆访问重新表述为**查询自适应的“披露”问题**——不仅决定“哪些会话相关”，还决定“应暴露多少细节”，并以渐进式披露（progressive disclosure）作为显式架构原则。

## 2. 方法论

### 2.1 核心思想
- 将对话历史组织为**由粗到细的四层记忆**，推理时由智能体控制器先读高层摘要，仅在证据不足时逐层下钻，形成自适应的成本—保真度权衡。
- 系统由三部分组成：多分辨率记忆基底、渐进式披露控制器、组织笔记合成器。

### 2.2 多分辨率记忆基底（Multi-Resolution Memory Substrate）
- 对话历史划分为 N 个会话 $S=\{S_1,\dots,S_N\}$，每个会话表示为四元组 $S_i=(L_0,L_1,L_2,L_3)$：
  - **L0 主题摘要**：每轮一句话摘要（≤30 词）+ 5–8 个关键词 + 3–5 个标签；代词消解、相对日期按会话时间戳归一化为绝对日期；作为主索引层。
  - **L1 个性化关键事实**：会话级 5–25 条自包含要点，覆盖用户信息、推荐、计划、偏好、约束。
  - **L2 轮次级证据笔记**：按轮次组织的原子事实条目，保留时间顺序，不合并多个事实。
  - **L3 原始消息**：逐字保留的用户—助手消息，用于精确证据恢复。
- **惰性物化（lazy materialization）**：仅 L0 与 L3 在摄取时生成，L1/L2 在控制器首次请求时按需生成并缓存，降低写入成本。

### 2.3 渐进式披露控制器（Progressive Disclosure Controller）
- 动作空间：$\mathcal{A}=\{\text{search, read\_facts, read\_turns, read\_raw, interpret\_dates, decompose, reflect}\}$。
- 成本与保真度随层级单调递增：$c(L_0)<c(L_1)<c(L_2)<c(L_3)$，$f(L_0)<f(L_1)<f(L_2)<f(L_3)$。
- 优化目标（式 1）：
  $$\min_{a_1,\dots,a_T}\sum_{t=1}^{T}c(a_t)\quad \text{s.t.}\ \text{sufficient}(V_T,q)=1$$
  即用最小访问代价收集足够证据，充分性由反思机制估计。
- **工作流程三阶段**：
  1. **查询准备**：`interpret_dates` 将“去年夏天”等相对时间按提问时间戳归一化；`decompose` 将多跳/复合查询拆为子查询。
  2. **渐进披露**：`search` 在 L0 上做混合检索取 top-K 会话；`auto-drill` 选最有希望的未探索会话，`read_facts` 读取 L1；不足则 `read_turns` 读 L2，再 `read_raw` 限定在最相关轮次读 L3。检索结果累积到证据集 $V$。
  3. **反思与起草**：`reflect` 总结 $V$、识别缺失证据、判断继续检索是否有益并生成后续查询；收敛后由控制器产出草稿答案 $a_{\text{draft}}$。
- **收敛控制**：当（1）反思未发现新证据（$|V_t|=|V_{t-1}|$）或（2）达到步数预算 $T_{\max}$（实验设为 20）时终止。

### 2.4 组织笔记合成器（Organized Notes Synthesizer）
- 受 Chain-of-Note 启发，将查询 $q$、证据集 $V$ 与草稿 $a_{\text{draft}}$ 转化为结构化笔记，包含：相关事实（按相关性排序、标注来源会话与日期）、时间排序、矛盾/更新（最新日期为当前真相）、枚举去重、答案提示。
- 最终答案生成器同时接收组织笔记与草稿，可独立校验并纠正控制器的遗漏或错误，形成“先综合、再生成”的两段式设计。

### 2.5 混合检索器
- **词法索引**：带词干化的 BM25，摘要与关键词字段分开索引。
- **稠密索引**：Nomic-v1.5（768 维），L2 归一化后点积检索。
- **RRF 融合**（$k=60$，等权）；会话得分取最佳匹配轮次；额外加关键词字段精确匹配 boost $\alpha\cdot s_{\max}\cdot n_i$；多查询时取各子查询得分的最大值，返回 top-K=20。
