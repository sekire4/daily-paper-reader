Abstract 

Long-term memory for multimodal agents remains challenging, as it must preserve fine-grained visual evidence while tracking entity evolution across sessions. Existing abstraction-based memories compress images into text, often discarding visually discriminative details, whereas pixel-preserving memories retain raw observations but struggle to reliably associate diverse observations with persistent entity identities and track their evolving states. To address these limitations, we propose MHG-Mem , a multimodal hy-pergraph memory that jointly organizes entity identity, state evolution, and provenance to visual evidence. Specifically, MHG-Mem represents dis-tinct entity mentions and their observed facts as individual nodes, grouping identity-consistent mentions and facts through occurrence hyperedges. It then synthesizes aspect-specific evolution states from these grouped obser-vations and links them to supporting entities, facts, and source evidence through evolutionary and evidential hyperedges. To navigate this struc-tured memory, we introduce hypergraph-based agentic search, which adap-tively selects an entry layer, traverses typed hyperedges across memory levels, and inspects source observations when fine-grained verification is required. These designs support both detailed visual verification and rea-soning over cross-session state changes. Extensive experiments across three benchmarks demonstrate the effectiveness of MHG-Mem, improving per-formance by 8.20–9.98% over the strongest baseline. 

1 Introduction 

Long-term memory enables large language model (LLM) agents to reuse past experience beyond their context windows (Packer et al., 2023; Xu et al., 2025). As agents increasingly browse websites and interact with users through images, multimodal memory becomes es-sential for understanding user needs and providing personalized assistance (Guo et al., 2026; Liu et al., 2026a). As shown in Fig. 1(a), a web agent encounters several backpacks across sessions, with varying page layouts, product views, prices, and availability. Subsequent queries require inspecting the main zipper of the purchased backpack (Q1) or determining whether an earlier offer for the same backpack was both cheaper and in stock (Q2). Answer-ing these queries remains challenging. Memory must preserve fine-grained visual evidence while tracking the entity’s state across sessions despite variations in its visual observation. Existing multimodal memories address these requirements only partially. As illustrated in Fig. 1(b), abstraction-based memory converts visual observations into textual descrip-tions or structured records for subsequent consolidation and retrieval (Wang & Chen, 2025; Feng et al., 2026). Pixel-preserving memory retains original images, allow-ing relevant observations to be retrieved and inspected at query time (Lu et al., 2026). Yet the retrieved images remain isolated observations. Nothing records that the product photo in one session and the listing page in another show the same backpack, or how its price and availability evolved. Without reliable associations, an agent may confuse similar entities or incorrectly combine attributes in different observations. These raise the question: How can multimodal memory organize visually diverse observations of the same entity into coherent state histories while keeping each state traceable to its supporting evidence? 

Addressing this question requires preserving individual observations while explicitly orga-nizing how they relate across sessions. The underlying memory structure is inherently 

higher-order : the same entity may be observed differently across sessions, with each ob-servation jointly associating several entity mentions, facts, and visual evidence, while its evolutions must integrate these observations into coherent state histories. These relation-ships therefore extend beyond isolated entities or facts and naturally form structured groups at different semantic levels. Motivated by this, we propose MHG-Mem , a multimodal hy-pergraph memory that uses typed hyperedges to explicitly organize these higher-order rela-tionships while preserving each observation separately. Specifically, occurrence hyperedges group identity-consistent entity mentions and their associated facts across sessions, evolution nodes summarize aspect-specific state changes from temporally ordered observations, and evolutionary and evidential hyperedges connect each evolution to the participating entity mentions and its supporting facts, respectively. Because these facts retain provenance to the original dialogue and images, each inferred state remains traceable to its source evidence. This structured memory naturally exposes evidence at multiple granularities, but different queries require different retrieval paths. Q1 ultimately requires inspecting a particular source image, whereas Q2 requires first locating the backpack’s state history and then verifying the facts underlying the relevant price and availability states. A fixed retrieval strategy therefore cannot serve both effectively. To this end, we introduce Hypergraph-based Agentic Search , which adaptively selects an entry layer, traverses typed hyperedges across entity, evolution, and fact-level memory, and follows provenance links to inspect source observations when necessary. In this way, compact evolution records guide cross-session reasoning, while grounded facts and images provide fine-grained, verifiable evidence. Our contributions are summarized as follows: 2Preprint. • We propose MHG-Mem , a multimodal hypergraph memory framework that organizes cross-session observations into coherent entity evolution histories through typed hyper-edges, while preserving visual evidence and state-specific provenance. • We introduce Hypergraph-based Agentic Search , which adaptively accesses entity groups, state histories, and their supporting observations to assemble query-relevant evi-dence across granularities. • Experiments across three benchmarks and three backbones demonstrate MHG-Mem’s effectiveness, improving average performance by 8.20–9.98% over the strongest baseline. 

2 Related Work 

Long-Term Multimodal Agent Memory. As agents increasingly interact with the physical and digital world, long-term memory research has expanded beyond text-centric systems (Packer et al., 2023; Xu et al., 2025; Kang et al., 2025; Chhikara et al., 2025; Zhong et al., 2024; Yuan et al., 2026) to multimodal retrieval (Chen et al., 2022; Yeo et al., 2026; Tang et al., 2026), episodic video memory (Jeong et al., 2025; Fan et al., 2025), and multimodal conversational memory (Bei et al., 2026; Maharana et al., 2024). Recent bench-marks further examine whether agents can retain action trajectories, and visually evolving states across long-horizon interactions (Liu et al., 2026a; Guo et al., 2026). Existing sys-tems address important aspects of this problem by compressing observations into semantic abstractions (Wang & Chen, 2025; Feng et al., 2026; Jain et al., 2025), organizing experi-ences around entities or events for cross-session reasoning (Long et al., 2025; Chen et al., 2026; Nguyen et al., 2026; Liu et al., 2026b), and retrieving evidence across modalities or memory stores (Kang et al., 2026; Lu et al., 2026; Tian et al., 2026). Yet these capabilities remain difficult to reconcile: semantic abstraction improves memory organization but may discard visual cues needed to distinguish similar observations, while preserving raw pixels alone does not establish which observations refer to the same entity or how their attributes evolve over time. MHG-Mem jointly addresses these challenges by preserving multimodal occurrences, associating them with persistent entity identities, synthesizing aspect-specific state histories, and grounding each state in supporting facts and source images within a typed hypergraph, enabling agentic search to traverse between compact abstractions and verifiable evidence. 

Hypergraph-based Agent Memory. Graph memory has evolved from knowledge graphs (Rasmussen et al., 2025; Gutierrez et al., 2024), toward entity-centered graph such as M3-Agent (Long et al., 2025) and query-aware evidence expansion in GraphMemix (Li et al., 2026). Hypergraph methods then make higher-order membership explicit: Hyper-GraphRAG (Luo et al., 2025b) represents n-ary facts for corpus-level RAG, HGMEM (Zhou et al., 2025) uses hypergraph working memory for multi-step reasoning, and HyperMem (Yue et al., 2026) organizes long conversations as topic–episode–fact hypergraphs with coarse-to-fine retrieval. Despite their effectiveness, these approaches remain largely confined to text-centric memory organization, limiting their applicability to information-dense and dynami-cally evolving multimodal agent interactions. In contrast, MHG-Mem uses typed hyperedges to jointly organize persistent multimodal occurrences, entity-specific aspect evolutions and provenance, enabling identity-aware state tracking and fine-grained visual verification within a unified long-term memory framework. 

3 Methodology 

To track entity states across sessions while preserving their supporting evidence, we propose MHG-Mem, a multimodal hypergraph memory framework. Typed hyperedges organize en-tity mentions, facts, and state evolutions into reusable histories while retaining observation-specific visual evidence and links from individual states to their sources. Hypergraph-based agentic search then adapts retrieval to the query, navigating these histories and inspecting the underlying evidence as needed. 3.1 Problem Formulation 

Let D≤T = ( d1, . . . , d T ) denote an agent’s ordered multimodal interaction history across sessions , where each round dt = ( xt, It, δ t) comprises dialogue text xt, images It, and a recorded date δt. A memory construction operator W maps this history to persistent memory MT = W(D≤T ) before subsequent queries are known. Given a query q = ( xq , Iq )with optional visual input Iq , a retrieval operator S selects relevant evidence from MT . A multimodal agent then generates an answer conditioned on the query and retrieved evidence: 

Eq = S(q, MT ), ˆy ∼ pθ ( · | q, E q ), (1) where Eq denotes the retrieved evidence and θ denotes fixed model parameters. The objec-tive is to design W and S to support accurate answering of multimodal agent. 

3.2 Multimodal Hypergraph Memory Structure 

MHG-Mem represents multimodal memory using three node types and three types of n-ary hyperedges. Nodes encode memory units at different levels of granularity, while hyperedges capture cross-level associations and provenance, allowing high-level memory to be traced back to their supporting evidence. We formalize this memory as an attributed hypergraph: 

H = ( V, E, ι, τ V , τ E ), V = F ˙∪ U ˙∪ Z , E = Eocc ˙∪ E evo ˙∪ E evd , ι : E → 2V (2) where ι(e) denotes the set of nodes incident to hyperedge e, while τV and τE specify the node and hyperedge types, respectively. The contribution of nodes and hyperedges is de-fined as follows: ❶ FactNodes store atomic multimodal observations. ❷ EntityNodes store individual textual or visual entity mentions. We denote EntityNodes linked to the same underlying entity as a referent group r. ❸ EvolutionNodes store state changes in an en-tity attribute or relation. ❹ Occurrence hyperedges bind a referent’s EntityNodes to its associated FactNodes. ❺ Evolutionary hyperedges connect EvolutionNodes to its associ-ated EntityNodes. ❻ Evidential hyperedges connect EvolutionNodes to the supporting FactNodes used for verification. The complete node, hyperedge, and incidence definitions are given in Appendix B.1. The no-tation is summarized in Appendix A. Conclusion 

We presented MHG-Mem, a multimodal hypergraph memory framework that organizes visually diverse observations of the same entity into coherent state histories while preserv-ing fine-grained visual evidence. Typed n-ary hyperedges connect entity mentions, atomic facts, and evolution records, keeping individual states traceable to their supporting obser-vations. Hypergraph-based agentic search adaptively navigates these memory levels, using state histories to guide retrieval and original dialogue and images to verify evidence. Abla-tions demonstrate the contributions of entity associations, explicit state histories, evidence grounding, and adaptive retrieval. These findings support the joint design of memory orga-nization and evidence access for reasoning over evolving multimodal experience.

B.1 Detailed Hypergraph Memory Schema

C.3 Baselines 

A-Mem. A-Mem (Xu et al., 2025) organizes textual memories as interconnected notes inspired by the Zettelkasten method. It enriches each note with contextual descriptions and indexing attributes, establishes links to related notes, and updates existing memories as new observations arrive. 

MemoryOS. MemoryOS (Kang et al., 2025) maintains short-term, mid-term, and long-term memory. Storage, updating, retrieval, and generation modules coordinate the transfer and consolidation of conversational information across these tiers to support persistent user knowledge and preferences. 22 Preprint. 

SimpleMem. SimpleMem (Liu et al., 2026c) compresses interactions into compact, self-contained textual memory units. Its pipeline combines semantic structured compression, online semantic synthesis, and intent-aware retrieval planning to reduce redundancy and assemble query-relevant context. The unimodal category refers to textual memory repre-sentations. 

HyperMem. HyperMem (Yue et al., 2026) organizes long-term conversations into topic, episode, and fact levels. Hyperedges group associated episodes and facts, while hybrid lexical–semantic indexing and coarse-to-fine retrieval recover related information across these levels. 

M2A. M2A (Feng et al., 2026) combines an immutable raw-message store with a semantic-memory store of higher-level observations. A conversational agent and a memory manager coordinate memory updates and iterative retrieval, retaining links between semantic mem-ories and their original multimodal evidence. 

MMA. MMA (Lu et al., 2026) is a confidence-aware multimodal memory agent. It com-bines semantic relevance with memory reliability, estimated from source credibility, temporal decay, and conflict-aware consensus, to reduce reliance on stale or conflicting observations. 

SRAG. SRAG denotes the multimodal Semantic RAG baseline in MemEye (Guo et al., 2026). It ranks historical records by combining text and image embedding similarities and supplies retrieved text and associated original images to the answer model. It provides a direct retrieval comparison to methods that construct additional memory abstractions or relational structures. 

UniversalRAG. UniversalRAG (Yeo et al., 2026) routes queries to corpora organized by modality and granularity. Modality-aware routing selects the appropriate evidence source, while retrieval at different granularities supplies context for answer generation.

D.3 Memory Quality and Fine-grained Analysis on More Backbones 

Figure 7 and 8 extend the memory quality and task-level analysis to Qwen3-VL-8B and GPT-4.1-mini, respectively. Across both backbones, MHG-Mem achieves the highest mem-ory correctness and update handling, with retrieval coverage among the best. These results show that effective state maintenance coexists with accurate memory retention and strong evidence coverage, consistent with our objective of organizing evolving observations while keeping their supporting evidence accessible. The most consistent task-level advantages concern visual evidence use and state evolution. On WorldMemArena-S, MHG-Mem outperforms all compared baselines in cross-modal rea-soning, temporal reasoning, dynamic updates, and visual updates with both backbones. In particular, cross-modal reasoning improves over the strongest baseline by 20% and 6% with Qwen3-VL-8B and GPT-4.1-mini, respectively. On Mem-Gallery, visual-centric reasoning improves by 4% and 6%, while knowledge resolution improves by 5% under both backbones; conflict detection also benefits in both settings. These recurring gains align with the two requirements motivating MHG-Mem: accessing relevant visual observations and integrating changes across interaction histories. They are consistent with the intended role of entity histories and state-specific evidence links in supporting comparison and verification across observations. The improvements nevertheless depend on the task and backbone. For example, Mem-Gallery temporal reasoning improves by 3% with Qwen3-VL-8B but remains 6% below the strongest baseline with GPT-4.1-mini. MHG-Mem also trails the strongest factual-recall baseline on both benchmarks under both backbones. Thus, the memory-quality improve-ments do not translate uniformly into every downstream capability: visual evidence use and state updates show reproducible benefits, while factual recall remain areas for improvement.

E.1 Atomic fact construction 

Converts the current round into standalone facts while retaining temporal and visual details. 

01 Atomic fact construction 

You convert ONE conversation round into a set of ATOMIC MEMORIES — short, standalone facts that a separate answerer will later retrieve to answer questions. You are given the round’s dialogue text, its image caption(s), and its REAL image(s). You may also see up to three EARLIER rounds of the same conversation as read-only context (their text and image captions only — no earlier pictures), and a list of EXISTING MEMORIES already stored from past rounds. Write memories ONLY for the CURRENT round; use the earlier rounds and the current image(s) just to understand the round and to resolve references. Read BOTH the caption AND the real pixels of the current round. The caption often spells a detail out in words (card names, on-screen text, dashboard labels, message transcripts); the pixels carry details the caption omits (colors, counts, spatial layout, what is actually shown). Capture from both. 

## ADD-ONLY against EXISTING MEMORIES 

If an `## EXISTING MEMORIES` list is given, treat it as memories that are ALREADY STORED. Your job is ADDITIVE: output the facts from the CURRENT round that are NOT already represented there. Do not restate, paraphrase, or lightly reword an existing memory. Never create a memory from the existing list alone — every memory you output must be supported by the CURRENT round. - Default to WRITING a fact. Suppress a candidate ONLY when it is the SAME fact about the SAME moment as an existing memory. When in doubt, WRITE it — a missed fact can never be recovered, a near-duplicate is cheap. - The mere presence of the same entity, brand, game, route, dashboard, or template in an existing memory does NOT make the current round a duplicate. A new event, a new state, a changed value, a different date/session, a new opinion or conclusion the user draws, or any new detail is ALWAYS a new memory — write it. Write each memory to this STANDARD: - ATOMIC & self-contained: one fact per memory — a single event, state, attribute, or relationship — understandable on its own. Begin from the concrete named subject. - ABSOLUTE time: anchor every time reference to the Observation Date given. Convert "today / tomorrow / yesterday / last week / this Monday" to an explicit calendar date (YYYY-MM-DD). Never store a bare relative time or weekday. - DESCRIBE the state, do NOT compute the answer. Record what is shown or said — list the cards in a hand, the panels on a dashboard and their values, the people in a chat and who said what. Do NOT add totals, counts across rounds, winners, comparisons, or any conclusion the data merely implies. Faithful state, never a frozen verdict. - CAPTURE what a later question could ask: numbers, colors, spatial relations (left / right / above / below / lower-left / behind / beside / under), in-image text, per-item attributes, who did what, and any change from the earlier context. - Only return an empty list when the CURRENT round genuinely contains NOTHING beyond what is already stored (e.g. a bare "ok", "thanks", "correct" with no new content of its own). Return ONLY JSON: {"atomic_facts":["<one standalone memory>","<another standalone memory>"]} If the round carries nothing new worth remembering, return {"atomic_facts":[]}.

E.2 Multimodal entity extraction 

Extracts nameable entities and grounds visual or multimodal mentions in image regions. 

02 Multimodal entity extraction 

You extract MULTIMODAL ENTITIES from ONE conversation round (its dialogue text AND its image, if any). An ENTITY is a persistent, nameable THING that could be asked about later — for example: a brand, logo, product. This list is illustrative, not exhaustive — extract any concrete, nameable thing a later question could point at Give each entity ONE modality, decided by WHERE you learned about it: - `visual`: something you can SEE in the image. This is the DEFAULT for anything in the picture — objects, people, places, logos, products, signs, on-screen panels. Give it a short specific name (e.g. "red delivery truck", "Coca-Cola logo"). bbox required. - `multimodal`: visible in the image AND also named in the dialogue text. Name it from the dialogue; the box is on the region that shows it. bbox required. - `text`: named in the dialogue text (what the USER or ASSISTANT actually typed) but NOT visible in the image. bbox is null. This is RARE — use it ONLY for things mentioned in the conversation that you cannot see. For every `visual` and `multimodal` entity, bbox is absolute pixels `[x0,y0,x1,y1]` in the image’s pixel frame, tight around the thing. Return ONLY JSON: {"entities":[{"name":"...","type":"<brand|person|character|object|product|place|animal| organization|other>","modality":"visual|multimodal|text","bbox":[x0,y0,x1,y1] or null}]} Rules: - Only extract things written in the dialogue or clearly visible in the image — never invent. - If nothing qualifies, return {"entities":[]}. 

E.3 Occurrence linking 

Associates a candidate mention with a stored referent, creates a new referent, or rejects an invalid extraction. 

03 Occurrence linking 

You decide how to store ONE candidate entity into a memory of already-known entities. You are given: - ROUND CONTEXT: the conversation round the candidate was found in (its text, and the full round image if any) — use it to understand what the candidate actually is. - CANDIDATE: its name, type, modality, and, if visual, its cropped region (shown below). - MATCHES: most similar to the candidate (by text and visual similarity), each with its best-matching stored region (shown below). Choose EXACTLY ONE action: - `update`: the candidate is the SAME real-world thing as one MATCH— link to that entity id. Also use `update` for a repeat sighting of a thing already stored, to record this new occurrence. - `add`: the candidate is a REAL entity but none of the MATCHES is the same real-world thing. - `skip`: ONLY when the candidate is NOT a real, storable entity (an extraction mistake or abstract concept). Return ONLY JSON: `{{"action":"update|add|skip","target_entity_id":"<id, only if update>", "add_alias":"<optional new alias>","reason":"<one line>"}}`

E.4 State evolution synthesis 

Identifies changing aspects and binds each reported state to its supporting fact identifier. 

04 State evolution synthesis 

You are given ONE referent (a thing that recurs in a long conversation) and the time-ordered list of ATOMIC FACTS recorded about it. Your job is to report which ASPECTS of this referent actually CHANGED over time. An ASPECT is a single named property that can hold different values at different times — for example: hand_size, location, owner, color, price, status, score, version, participants, weight. 

## What counts as a change 

A change means: the SAME aspect of the SAME referent holds DIFFERENT values at different times. For example: - "is in the kitchen" then "is in the bedroom"-> aspect `location` CHANGED. Report it. - "costs $12" then "costs $9"-> aspect `price` CHANGED. Report it. 

## What does NOT count as a change (this is the common case — read carefully) 

- A value stated repeatedly, or restated in different words, is NOT a change. - New, additional details about DIFFERENT aspects are NOT a change unless one aspect’s own value is replaced by another value. 

## How to write what you find 

For each aspect that genuinely changed: - `aspect`: a short lowercase snake_case key naming the property (`hand_size`, not "the size of the hand"). - `states`: two or more entries in TIME ORDER. Each entry MUST carry: - `value`: the value at that time, as short as possible (a number, a color, a place, a name). - `fact_id`: the id of the fact you read that value from. It MUST be one of the fact ids listed below, copied exactly. Never invent an id. - `summary`: one sentence DESCRIBING the observed states in order, with their dates. - `update_type`: one of - `replacement` — the new value replaces the old one (a measurement, a location, a price) - `correction` — the later fact says the earlier one was wrong - `addition` — the value grew by accumulating items rather than being replaced Return ONLY JSON: {"aspects":[{"aspect":"<snake_case>","states":[{"value":"<v1>","fact_id":"<id>"}, {"value":"<v2>","fact_id":"<id>"}],"summary":"<one sentence describing the states in order>","update_type":"replacement|correction|addition"}]} If no aspect of this referent changed, return exactly {"aspects":[]}.

E.5 Hypergraph-based agentic search 

Guides sequential tool use to assemble evidence for the separate answer model. The placeholders [MEMORY_SCHEMA] , [TOOL_SCHEMA] , and {max_steps} denote the memory schema, tool definitions, and search budget, respectively. The five gathering tools collect evidence; submit_evidence terminates retrieval. 

05 Hypergraph-based agentic search 

You are a hypergraph memory retriever. Given a QUESTION, you SEARCH a long-term multimodal memory of past conversation rounds and assemble an EVIDENCE CHAIN for a separate QA model. You do NOT answer the question yourself. 

## What is in memory: [MEMORY_SCHEMA] ## Tool Definition: [TOOL_SCHEMA] ## Format — EXACTLY ONE action per reply, nothing after it 

Each reply MUST be exactly: ``` Action: <one tool name> Action Input: {{<json>}} ``` STRICT RULES: - Output ONE Action, ONE Action Input, then STOP. Do NOT write a second Thought/Action in the same reply — you will only see the result of the FIRST action, so any extra ones are wasted. - After `Action Input: {{...}}` write NOTHING more. Do not narrate, do not plan further steps. - you will receive `Observation: {{...}}` (and any images). Read it, then send your NEXT single action. When the evidence is sufficient, call submit_evidence. 

## Strategy 

- You have five hypergraph gathering tools; use whichever fit the question. Call ONE per turn and read its Observation before the next. - If the question hinges on a visual/pixel detail, open the most promising facts’ rounds with get_raw_verbatim (or use search_image) so you actually SEE the images before citing. - Be efficient: you have at most {max_steps} steps. Submit as soon as the evidence is sufficient.
