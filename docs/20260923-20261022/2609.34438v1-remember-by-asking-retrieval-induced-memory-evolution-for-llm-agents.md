## 摘要
长期记忆对于语言智能体在扩展的多会话交互中保持连贯且有效的行为至关重要。现有记忆系统主要在读取时使用检索，而写入时的记忆形成仍依赖于直接抽取或压缩。然而，当未来信息需求未知时，一次性压缩整个交互可能会忽略之后可能重要的局部细节。为此，我们提出 RIME，一种检索诱导的记忆框架，将记忆构建从整体式压缩转向以证据为中心的整合。RIME 使用通用自提问来检索聚焦的对话证据，并将记忆形成建立在检索到的证据与相关历史记忆之上，这些信息被共同协调到具有时间与来源信息的演化记忆库中。在推理时，压缩记忆作为主要而非唯一的证据来源：当其无法支持答案时，RIME 会检索相关源对话及其局部上下文，以恢复记忆形成过程中被遗漏的信息，而无需处理完整历史。在 LoCoMo 上使用 Qwen3-235B-A22B 与 GPT-5.6 Sol 的大量实验表明，RIME 在所有比较方法中于全部三项质量指标上始终取得最佳性能，同时所需的查询时 LLM token 数显著更少。

## Abstract
Long-term memory is essential for language agents to maintain coherent and effective behavior over extended, multi-session interactions. Existing memory systems mainly use retrieval at read time, while write-time memory formation still relies on direct extraction or compression. However, when future information needs are unknown, compressing an entire interaction in one pass can overlook locally important details that may matter later. To this end, we introduce RIME, a retrieval-induced memory framework that shifts memory construction from monolithic compression toward evidence-centered integration. RIME uses generic self-questions to retrieve focused dialogue evidence and grounds memory formation in both the retrieved evidence and relevant historical memories, which are jointly reconciled into an evolving memory bank with temporal and provenance information. At inference time, compressed memory serves as the primary rather than the sole source of evidence: when it cannot support an answer, RIME retrieves relevant source dialogue together with its local context to recover information omitted during memory formation, without resorting to full-history processing. Extensive experiments on LoCoMo with Qwen3-235B-A22B and GPT-5.6 Sol show that RIME consistently achieves the best performance across all three quality metrics among the compared methods, while requiring substantially fewer query-time LLM tokens.

## 1. 核心问题与研究动机

- **背景**：长期记忆是语言智能体在多会话、长时程交互中保持行为连贯的基础；缺少持久记忆，智能体无法保留用户特定信息、跨会话连接事件或复用过往经验。已有工作从记忆流、记忆库发展到结构化/自适应记忆系统（Mem0、A-MEM、Nemori、SimpleMem、LightMem 等）。
- **核心痛点**：现有系统主要在**读时（read time）**使用检索，而**写时（write time）的记忆形成**仍依赖一次性抽取或整体压缩。
  - 未来查询需求不可预知，一次性压缩整段交互会**遗漏局部重要细节**；
  - 细节一旦在形成阶段被丢弃，仅靠压缩记忆**无法恢复**；
  - 而回退到完整历史（如 D-Mem 的 Full Deliberation）又带来**高昂推理开销**。
- **整体含义**：论文主张把记忆构建从“整体式压缩（monolithic compression）”转向“**以证据为中心的整合（evidence-centered integration）**”，并让压缩记忆成为推理时的**主要但非唯一**证据来源——即“通过提问来记忆”。

## 2. 方法论：RIME 框架

### 2.1 核心思想
用一组**通用自提问**（与下游查询无关）作为检索线索，在记忆固化**之前**先把与各类信息相关的对话证据“捞出来”，再结合局部上下文与相关历史记忆做联合协调，写入带时间与来源信息的演化记忆库；推理时若压缩记忆不足，则**选择性**回取源对话片段而非全历史。

### 2.2 记忆形成阶段（Retrieval-based Memory Formation）
- **通用形成问题集**：固定 $Q=\{q_r\}_{r=1}^{R}$，实现中 $R=6$，覆盖：人物与关系、事件、活动、计划、状态与偏好、具体事实细节；跨所有会话共享，不依赖下游查询。
- **问题引导的证据召回**：以嵌入余弦相似度 $s(a,b)=\frac{\phi(a)^\top\phi(b)}{\|\phi(a)\|_2\|\phi(b)\|_2}$ 度量，对每个 $q_r$ 在当前会话 $S_t$ 中取 top-$k_f$（=10）轮对话 $R_t^{(r)}$；随后并集得到 $R_t=\bigcup_{r=1}^{R}R_t^{(r)}$。
- **两轮局部上下文扩展**：$\tilde{R}_t^{(\ell+1)}=\tilde{R}_t^{(\ell)}\cup N_t(\tilde{R}_t^{(\ell)}),\ \ell=0,1$，其中 $N_t(\cdot)$ 加入解析局部指代所需的邻近轮次，最终证据集 $E_t=\tilde{R}_t^{(2)}$。
- **历史记忆接地**：将问题与召回证据按相似度降序拼接为查询 $z_t^{(r)}=\mathrm{Concat}(q_r,R_t^{(r)})$，从上一时刻记忆库 $M_{t-1}$ 取 top-$k_h$（=5）条相关历史记忆，并集为 $H_t$。
- **联合形成与协调**：单次 LLM 调用 $O_t=F_{\text{mem}}(E_t,H_t)$，同时完成事实抽取、会话内去重、指代消解与历史协调；操作类型为 $\{\text{ADD},\text{UPDATE},\text{DELETE},\text{NOOP}\}$（NOOP 表示历史记忆已覆盖当前证据）；每条记忆保留**时间信息与对话来源（provenance）**；最终 $M_t=\mathrm{Apply}(M_{t-1},O_t)$。

### 2.3 记忆使用阶段（Selective Memory Use）
- 先用查询检索 top-30 语义记忆（OpenAI `text-embedding-3-small`），在**不提供原始对话**的条件下生成初答 $\tilde{y}_i=F_{\text{ans}}(q_i^{\text{usr}},M_i)$。
- 若 $\tilde{y}_i=\text{NONE}$（记忆不足），则用 **TF–IDF** 在全部历史会话中检索 top-20 源对话轮次，并为每轮扩展前后各 15 轮的上下文窗口：$E_i^{\text{src}}=R_i^{\text{src}}\cup \mathrm{Ctx}_w(R_i^{\text{src}})$；最终答案由源证据生成。
- 该设计的关键：回退路径是**廉价词法检索 + 局部上下文**，而非对全历史做 deliberative 推理。

## 6. 主要结论与发现

- 在 LoCoMo 的 1,540 道非对抗题上，RIME 在 Qwen3-235B-A22B 与 GPT-5.6 Sol 两个骨干下**三项质量指标（LLM-Judge、F1、BLEU-1）全部第一**，同时查询时 LLM token 显著低于 A-MEM、Nemori、D-Mem 等审议式记忆系统。
- **把检索前移到写入阶段是有效的**：以通用问题为检索线索、先取证据再固化，优于对整段会话的直接压缩；而仅把六个维度写进压缩提示（Question-Prompted Compression）几乎没有稳定收益（Judge 72.66 vs. 71.62，F1 甚至略降 48.87 vs. 49.26），说明**“检索”而非“提示措辞”**才是关键。
-

- **选择性回取是“够用即可”的保险机制**：消融显示移除选择性源检索后质量下降，但触发率并不高（Qwen 16.8%、GPT 6.0%），说明大部分问题可由压缩记忆独立回答，源级回取只在少数“记忆不足”的情形下兜底；这既解释了 token 为何能远低于全历史审议式方案，也说明 RIME 的收益不是靠“多读原文”堆出来的。
- **跨骨干一致性**：两个能力差异明显的骨干上，RIME 相对最强基线（Nemori / D-Mem）的优势方向一致（Judge 约 +1.2～+4.5 分），提示该方法不依赖某一特定模型的特殊行为。
- **效率—质量权衡的重新定位**：Mem0、RAG 的查询 token 更低（2.20K / 更低），但质量差距达数十个 Judge 分；RIME 在“接近轻量检索方案的成本量级”上取得了“接近甚至超过审议式方案的质量”，把帕累托前沿向外推了一档。

## 7. 局限与可改进方向

- **证据面偏窄**：单一数据集（LoCoMo）、单一语言（英文）、排除 adversarial 子集，缺少跨域（如代码、工具调用日志、多模态交互）与跨语言验证。
- **增益归因不够细**：问题引导检索、两轮上下文扩展、历史记忆接地、单次联合协调四个环节耦合在一个 pipeline 中，缺少逐项拆解；特别是 Question-Prompted Compression 的微弱提升，反而让“问题检索本身贡献多少”这一问题悬而未决。
- **固定超参缺乏依据**：$R=6$ 的问题集被描述为“通用”，但未给出问题集的构造过程、覆盖度分析或替换实验；$k_f$、$k_h$、top-30、窗口 $w=15$ 均为经验取值。
- **成本核算不完整**：只报告查询侧 token，未报告写入侧（每会话 6 次检索 + 上下文扩展 + 1 次 LLM 协调调用）的开销，也未给出端到端总成本或与基线在写入侧的对比，因此“整体更高效”的结论尚不完整。
- **回退路径较朴素**：源级回取使用 TF–IDF 词法匹配，对同义改写、跨语言指代、抽象提问的召回能力有限；论文未讨论改用稠密检索或混合检索的代价与收益。
- **记忆库的长期演化风险未评估**：ADD/UPDATE/DELETE 操作在多会话累积下可能产生漂移、冗余或错误覆盖，论文未报告记忆库规模增长曲线、删除率、冲突处理准确率等演化侧指标。
- **评测偏差风险**：LLM-Judge 与答案生成同源，缺少人工或异源模型交叉验证；无多次运行方差与显著性检验，单次结果的稳健性未知。

## 8. 实践启示

- **把“写什么”当作检索问题而非摘要问题**：在记忆固化前用一组与查询无关的通用问题做证据召回，是一种低成本、可插拔的改进，可直接叠加到现有 Mem0/A-MEM 类系统的写入链路上。
- **压缩记忆应被设计为“主证据 + 可回溯指针”**：为每条记忆保留时间戳与对话来源，使系统在记忆不足时能以低成本定位原文，而不是重跑全历史推理——这是 RIME 效率优势的结构性来源。
- **“提问维度”可作为记忆 schema 的轻量替代**：相比预定义字段的结构化记忆，用自然语言问题集充当“软 schema”，在保持灵活性的同时提供了覆盖度约束。
- **效率评估应区分写入与读取**：对长时程智能体而言，写入成本随会话数线性累积，可能比查询成本更关键；后续工作报告应同时给出两侧开销。

  5. 与结构化记忆（如知识图谱式）结合是否能进一步提升 multi-hop 与 temporal 类问题的表现？

## 10. 总体评价

RIME 的核心贡献不在于提出新的模型或训练目标，而在于**重新分配了记忆系统中的“检索预算”**：把原本集中在读时的检索能力前移到写时，用通用自提问作为证据探针，从“先压缩、后检索”转为“先取证、后固化、必要时回源”。这一视角简洁、可解释、工程上易落地，并在 LoCoMo 上用双骨干验证了“质量最优 + 查询成本显著低于审议式基线”的组合优势。

其主要不足在于**验证广度与归因深度**：单数据集、固定超参、组件耦合、写入成本缺失、评审同源，使得结论的稳健性与适用边界仍有待更系统的实验澄清。总体而言，这是一篇**问题定位清晰、方法轻量、实证有说服力但证据面偏窄**的工作；其“以提问铭记”的思想比其在单一 benchmark 上的具体分数更具迁移价值。
