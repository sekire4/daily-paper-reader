## 摘要
随着LLM能力不断提升，智能体正在更长的时域上处理日益复杂的任务。其不断增长的交互历史使得记忆压缩成为必要，以保持在上下文窗口内并降低预填充成本。现有方法对历史进行摘要或压缩其KV缓存，通常会增加模型计算，以保留信息供未来请求使用。新的用户请求可能改变哪些历史重要，但如果KV缓存已过期，用模型重新评估该历史需要重新编码。过去的注意力提供了历史重要性及消息间依赖关系的信号，而与当前任务的相关性必须利用新的用户请求来评估。我们提出ReCAP，一种记忆压缩方法，将注意力推导的重要性分数和依赖链接存储在轻量级持久化上下文图中。对于每个新请求，ReCAP将存储的重要性与来自请求的相关性线索相结合，并沿依赖链接选择消息及其支撑上下文，而无需额外的模型调用进行选择。与Codex默认的基于摘要的压缩相比，ReCAP在Qwen3-Coder和gpt-oss上将压缩与冷恢复的估计延迟降低约95%。在任务质量相当的情况下，它还将SWE-Together上每次调用的历史上下文大致减半，并在Lost-in-Conversation的代码任务上相较完整历史将准确率分别提高19.8和41.2个百分点。

## Abstract
As LLM capabilities advance, agents are tackling increasingly complex tasks over longer horizons. Their growing interaction histories make memory compaction essential for staying within context windows and reducing prefill cost. Existing methods summarize the history or compress its KV cache, often adding model computation to preserve information for future requests. A new user request can change which history matters, but reassessing that history with the model requires re-encoding it if the KV cache has expired. Past attention provides signals of historical importance and dependencies between messages, while relevance to the current task must be assessed using the new user request. We introduce ReCAP, a memory compaction method that stores attention-derived importance scores and dependency links in a lightweight, persistent context graph. For each new request, ReCAP combines stored importance with relevance cues from the request and follows dependency links to select messages and their supporting context, without additional model calls for selection. Compared with Codex's default summarization-based compaction, ReCAP reduces estimated latency for compaction and cold restoration by approximately 95% on both Qwen3-Coder and gpt-oss. It also roughly halves the historical context per call on SWE-Together at comparable task quality and improves accuracy on the code tasks of Lost-in-Conversation over full history by 19.8 and 41.2 points.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体（agent）正承担越来越长程的任务（如仓库级编程、自主研究），一次会话可持续数十分钟至数小时，累积大量用户指令、工具调用与工具输出。历史最终会超出上下文窗口，且智能体负载的输入长度常达输出长度的数十倍，重复预填充（prefill）成为主要开销。
- **记忆压缩的必要性**：现代 agent harness 采用“记忆压缩”（memory compaction），将历史压缩为更短上下文，以突破单窗口限制并降低重复编码成本。
- **现有方法的三个关联难题**：
  1. **保留什么取决于未来用途**：新用户请求可能改变任务方向或回溯早期决策；基于当前查询的 KV 驱逐在后续查询变化时会失效。
  2. **预判未来用途需要额外计算**：如 Attention Matching 需合成参考查询、重新预填充；摘要式压缩需额外生成调用。
  3. **缓存过期带来重建成本**：用户思考时间占会话时间绝大部分，跨小时请求几乎必然错过服务缓存；若压缩器等待请求到达，则需重新编码历史以获得新鲜注意力。
- **关键观察（论文 §3.2）**：
  - 注意力高度集中于少量历史块：在 10% 历史 token 预算下可保留约 65% 注意力质量。
  - 过去轮次的注意力可预测下一轮历史复用：10% 预算下中位标识符覆盖约 0.68，接近未来用途 oracle 的 0.71；加入请求标识符重叠后约 0.69。
  - 新请求会重定向注意力：改变目标文件平均重分配 10.1% 注意力，仅改写措辞为 5.3%；32 个任务中 28 个呈现该模式。
- **整体含义**：论文主张“推理本来就会计算注意力”，不应在请求结束后丢弃该信号；应将其持久化为轻量图结构，使压缩既无需额外模型调用，又能随新请求动态调整，并在 KV 缓存过期后仍可工作。

## 2. 方法论：ReCAP 持久上下文图

### 2.1 核心思想

- 将会话历史建模为**持续演化的有向图** \(G_t=(V_t,E_t)\)：
  - **节点**：可原子化载入工作上下文的历史块，包括用户消息、带工具调用及结果的助手消息、普通助手消息；工具调用与其结果绑定，保证消息序列合法。
  - **节点属性**：累积重要度 \(u_t(v)\in[0,1]\)。
  - **边**：从“支撑块”指向“依赖块”，权重表示依赖强度；边随时间累积。
- 图仅存储块引用、标量分数和依赖链接，**独立于 KV 缓存持久存在**；新请求到来时通过图遍历与字符串匹配完成选择，**不调用模型**。

### 2.2 从注意力持久化重要度与依赖

- **重要度更新**：
  - 在每轮结束时采样已完成轮次的 token 位置，跨注意力头与选定层平均，得到历史 token 的接收注意力 \(\rho_t(j)\)。
  - 对块 \(v\) 内 token 取平均得 \(\bar\rho_t(v)\)，再用指数移动平均更新：
    \[
    u_t(v)=(1-\alpha)u_{t-1}(v)+\alpha\frac{\bar\rho_t(v)}{\bar\rho_t^{\max}}
    \]
  - 未在本轮观测到的节点保留旧分数，供后续回溯使用；新节点从 0 开始。论文取 \(\alpha=0.6\)。
- **依赖边记录**：
  - 在依赖块 \(b\) 内采样位置，测量其对更早块 \(a\) 的平均注意力质量 \(d_t(a,b)\)。
  - 当 \(a\) 早于 \(b\) 且 \(d_t(a,b)>\theta\)（\(\theta=0.02\)）时添加边 \(a\to b\)；边权保留历史最大观测值。
- **观察状态与陈旧标记**：
  - \(O_t\) 记录已获得注意力测量的节点。
  - \(S_t\) 标记“可能被后续更强注意力块取代”的早期块：标识符 Jaccard 相似度 > 0.5，且后续块接收注意力显著更强（约大于前者 2 倍并加 0.05 的余量）。
  - 陈旧节点仅降低优先级，不删除节点与文本。

### 2.3 查询条件化的上下文选择

- **请求相关性**：计算请求与块之间的标识符重叠，并按逆文档频率加权：
  \[
  \ell_v=\sum_{w\in I(q_{t+1})\cap I(v)}\log\frac{|V_t|}{df_t(w)}
  \]
  强调稀有文件名、函数名、错误符号等显式引用。
- **综合评分**：
  \[
  s_v=z(u_t(v))+\lambda z(\ell_v)+\epsilon\,\xi_{t,v}\mathbf{1}[v\notin O_t]-\kappa\mathbf{1}[v\in S_t]
  \]
  其中 \(z\) 为标准化，\(\lambda=0.5\) 控制查询贡献，未观测节点获得探索奖励 \(\epsilon=0.1\)，陈旧节点受罚 \(\kappa=2.0\)。
- **保护集与打包**：
  - 保护集 \(P_t\) 包含所有用户消息节点，以及每个被修改文件的最新编辑/写入节点，用于保留任务指令与智能体最近改动。
  - 从 \(P_t\) 出发，按分数降序（同分按时间）加入块，直到名义预算 \(B_t=\lfloor\beta c(V_t)\rfloor\)，\(\beta=0.1\)；保护集即使超预算也保留。
- **依赖扩展**：
  - 对初始选择 \(C_0\) 中的每个块，沿入边加入未选中、非陈旧的前驱块，扩展预算为 \((1+\delta)B_t\)，\(\delta=0.1\)，且仅扩展一跳。
  - 选择集满足 \(P_t\subseteq C\) 且 \(c(C)\le\max\{c(P_t),(1+\delta)B_t\}\)。
- **工作上下文构造**：
  - 选中块按时间顺序渲染于系统指令与当前轮之间；省略历史时附加提示说明工作区仍可检索细节。
  - 同一用户轮内的工具步骤复用固定选择，便于前缀缓存（prefix caching）复用。

### 2.4 与缓存和黑盒模型的兼容

- **与前缀缓存互补**：缓存仍有效（warm boundary）时跳过选择，直接追加请求并复用 KV；缓存过期（idle boundary）时才执行 ReCAP 选择并预填充压缩上下文。
- **黑盒代理注意力**：闭源 API 不暴露注意力时，可用小型代理模型（如 Qwen3-0.6B）重放服务上下文，将注意力映射回相同块；图只存块级统计，不依赖具体模型。
- **图更新在 CPU 后台完成**，不处于关键路径。

## 6. 主要结论与发现

- **质量保持**：在两个 benchmark、两个模型族上，ReCAP 的任务质量与无压缩全历史恢复相当或接近，且普遍优于 Recency、Random、LLMLingua-2、LongLLMLingua 与 Codex 风格摘要压缩；KV 驱逐因不可逆丢弃而在请求转向后损失明显。
- **上下文大幅缩减**：平均每次调用上下文 token 数显著低于全历史基线，接近 10% 名义预算量级（保护集与依赖扩展会使实际比例略高）。
- **零额外模型开销**：ReCAP 不产生任何压缩用的骨干模型输入/输出 token，这是相对摘要式压缩与 Attention Matching 类方法的结构性优势；图更新与选择在 CPU 后台完成，不进入关键路径。
- **延迟优势**：在冷启动（缓存已过期）场景下，"ReCAP 选择 + 预填充压缩上下文"的合计估计延迟低于重新预填充完整历史；在缓存仍有效时直接复用前缀缓存，二者互补而非互斥。
- **消融验证注意力信号的价值**：去掉注意力图（退化为纯请求相关性/启发式）后质量下降，说明持久化的注意力统计确实携带了请求文本之外的未来用途信息；块粒度（段落级 vs 行级）也影响效果，过细粒度削弱依赖边与重要度的统计稳定性。
- **黑盒可迁移**：用小型代理模型（Qwen3-0.6B）重放上下文以获取注意力，在三个设置下均优于无注意力对照，说明块级注意力统计具有一定跨模型可迁移性，为闭源 API 场景提供了可行路径。
- **压缩模式分析**：被选中的块中同时存在"持续保留""复活"（早期被压低、后续重新变重要）与"新增"三类来源，其中"复活"现象直接印证了论文对"保留什么取决于未来用途"的问题设定，也解释了为何基于当前查询的 KV 驱逐会失效。

## 7. 贡献定位与批判性评价

- **概念贡献（最强）**：将"记忆压缩"重新表述为"注意力信号的持久化与查询条件化检索"，指出压缩器不必在请求结束后立即决策，也不必在请求到来时调用模型——这一"把决策推迟到需要时、用廉价图检索代替昂贵重编码"的框架性转换，是本文最有价值的部分，其适用范围超出编程 agent。
- **工程贡献**：与前缀缓存的显式协同（warm boundary 跳过、idle boundary 触发）、CPU 后台更新、块级统计与模型解耦，使方法具备实际部署形态，而非仅停留在离线指标。
- **实证贡献**：三项观察性研究（注意力集中、跨轮复用、请求重定向）本身即是对 agent 长上下文行为的有益刻画，可独立于 ReCAP 被引用。
- **主要疑点**：
  1. "未来用途可由过去注意力预测"这一经验规律在任务类型切换（如从调试转为重构、从单文件转为跨仓库）时的失效边界未被刻画。
  2. 保护集规则（所有用户消息 + 每个被修改文件的最新编辑节点）在长会话中可能自身膨胀，论文未报告保护集占预算的实际比例分布。
  3. 陈旧标记依赖标识符 Jaccard 相似度阈值 0.5，对命名风格差异大的代码库可能误判，缺少误差分析。
  4. 与"检索增强"路线的边界模糊：ReCAP 本质是历史块上的稀疏检索 + 图扩展，若与外部向量检索或文件系统工具检索结合，增益是否重叠未讨论。
- **总体判断**：问题定义清晰、动机链条完整、方法轻量且工程可行，属于"以细致观察驱动简单机制"的工作；主要短板在于统计严谨性（单次运行、消融范围窄、超参数未扫描）与真实会话验证不足，这些不否定核心论点，但限制了结论的强度与外推范围。

## 8. 可迁移启示

- 对 agent 系统设计者：不应在轮次结束时丢弃注意力这一"免费"信号，将其降维为块级标量并持久化，成本极低而信息量可观。
- 对缓存系统设计者：压缩与缓存不是替代关系，应按"缓存是否 warm"分流处理，避免为未被请求的历史反复付出编码成本。
- 对评测实践者：agent 记忆方法的评测应同时报告质量、上下文量、压缩额外 token、延迟与内存，并强制报告多次运行的方差；仅报质量会系统性偏袒摘要式方法，仅报上下文量会偏袒激进丢弃方法。
- 对后续研究：值得补充的方向包括——真实用户会话轨迹上的 idle 分布测量、跨任务类型切换下的预测失效分析、预算比例 \(\beta\) 与保护集规模的敏感性研究、以及与工具级检索的联合设计。
