## 摘要
面向大语言模型（LLM）的长期记忆系统因能在各类应用中扩展推理能力而日益流行。当前记忆系统依赖 LLM 智能体来组织和整合记忆，导致写入操作成本高且效率低。为解决这一局限，我们提出 MemFit，一种面向对话智能体的长期记忆系统，可降低记忆操作的成本和延迟。与依赖昂贵 LLM 调用进行记忆构建、或通过压缩丢弃表层细节的现有系统不同，MemFit 将每一轮对话逐字存储在仅追加存储中，插入近乎即时且无需 LLM，并用片段摘要为各轮对话建立索引，而非替换它们。此外，MemFit 采用无需 LLM 的多路径检索策略，在文本和多模态设置中，对说明文本增强的片段结合词汇与语义信号，并使用交叉编码器重排序。在 LoCoMo、MemGallery 和 LongMemEval-S 三个广泛使用的基准上的实证结果表明，MemFit 在实现最先进性能的同时，将记忆构建时间和成本降低数倍，为持久化智能体记忆提供了一种可扩展且高效的解决方案。

## Abstract
Long-term memory systems for large language models (LLMs) have gained popularity for extending reasoning capabilities across applications. Current memory systems rely on LLM agents to organize and consolidate memory, resulting in costly, inefficient write operations. To address this limitation, we propose MemFit, a long-term memory system for conversational agents that reduces the cost and latency of memory operations. Unlike existing systems that rely on expensive LLM calls for memory construction or discard surface-level details through compression, MemFit stores each turn verbatim in an append-only store with near-instantaneous, LLM-free insertion, indexing turns with segment summaries rather than replacing them. Additionally, MemFit uses an LLM-free, multi-path retrieval strategy that combines lexical and semantic signals with cross-encoder reranking over caption- augmented episodes in both textual and multimodal settings. Empirical results on three widely used benchmarks, LoCoMo, MemGallery, and LongMemEval-S, show that MemFit achieves state-of-the-art performance while reducing memory construction time and cost several-fold, providing a scalable and efficient solution for persistent agentic memory.

## 一、核心问题与研究动机

- **背景**：LLM 受限于固定上下文窗口，且随 token 数增加出现“上下文腐烂”（context rot）。为扩展跨会话推理能力，学界为 LLM 智能体引入外部长期记忆系统，在推理时仅检索最相关内容。
- **现有系统的两大痛点**：
  1. **写入昂贵**：MemGPT、MemoryOS、A-MEM、Mem0、LightMem、SimpleMem 等普遍依赖频繁 LLM 调用进行记忆组织、抽取、巩固或压缩，导致构建成本高、延迟大；且写入时的压缩/合并会不可逆地丢弃表层细节。
  2. **检索不精确**：多数系统仅用语义相似度检索，易产生“上下文污染”（context pollution），即召回语义相近但无关的记忆。
- **核心研究问题**：能否在不依赖频繁 LLM 调用的前提下，同时实现高效存储与精确检索？
- **整体含义**：作者主张把 LLM 移出“写路径”和“搜索本身”，用“逐字追加存储 + 摘要索引 + 免 LLM 多路检索”替代“LLM 驱动的记忆巩固”，从而在效果与成本之间取得更优平衡。

## 二、方法论

### 2.1 核心思想
- **只追加、不重写**：每轮对话逐字存为一个 episode，插入仅需一次编码器前向 + 两次索引追加，无 LLM 调用；后续新轮次到达时不重写、不重嵌入、不重摘要已有内容。
- **摘要用于“索引”而非“替换”**：片段摘要只负责定位对话区间，原始轮次仍逐字可检索，从而保留证据完整性。
- **不做巩固/删除**：事实更新时旧值与修正值并存并带日期，把“选哪条”推迟到问题已知时由检索结果（按时间排序）呈现，避免写入时误判丢弃不可恢复的证据。
- **检索完全免 LLM**：用词法 + 语义打分、加法式扩展、交叉编码器重排完成，仅答案抽取调用一次 LLM。

### 2.2 记忆表示与存储
- 每个 episode 表示为 $e_i=(x_i, z_i, g_i, m_i)$：
  - $x_i$：带时间与说话人标签的格式化文本（如 `[Time: 2023-05-12][Speaker: Lena] ...`）；
  - $z_i$：冻结句编码器的 L2 归一化嵌入；
  - $g_i$：全局序号，保持时序；
  - $m_i$：时间戳、说话人、会话/轮次 ID 等元数据。
- **双索引**：
  - BM25 稀疏索引（精确匹配人名、日期、稀有名词）；
  - 稠密索引矩阵 $Z\in\mathbb{R}^{N\times d}$，打分即矩阵-向量积 $Zz_q$（匹配同义改写）。
- **多模态文本-图像融合**：图像 ID 与详细 caption 以结构化文本追加进 $x_i$（如 `[Image D1:IMG_001: a golden retriever on a beach...]`），使视觉内容走与文本相同的词法/语义通路；caption 优先用标注，否则由 MLLM 生成。

### 2.3 片段摘要层（写路径中唯一的 LLM 调用）
- **TextTiling 无 LLM 分段**：在每个间隙计算两侧各 $b=\max(3,\text{round}(\sqrt{N}/2))$ 个 episode 平均嵌入的余弦一致性；在深度超过 $\mu_\delta+\sigma_\delta/2$ 的局部极小处切分。
- 每个 ≥3 个 episode 的片段做**一次 LLM 调用**，输入最多 14 条等距摘录，输出两句、≤200 token 的摘要；摘要带自身嵌入与成员 ID 作为 provenance。

### 2.4 四阶段检索流程
1. **混合候选生成**：词法 top-60 ∪ 语义 top-60；对并集做 min-max 归一化后凸组合
   $$s_i=\alpha\cdot\hat{d}_{sem}(z_q,z_i)+(1-\alpha)\cdot\hat{c}_{lex}(q,x_i),\quad \alpha=0.7$$
   再叠加元数据加成（说话人 +0.10、月份 +0.08、年份 +0.05）。
2. **加法式候选扩展**（只增不减）：
   - 摘要层用同一混合分数检索，top-5 摘要通过 provenance 拉入其成员 episode；
   - 伪相关反馈：用 top-2 episode 中 IDF 最高的 12 个稀有词重跑检索，针对跨会话多跳问题。
3. **重排与 pack 组装**：交叉编码器对 top-50 一阶段候选 + 全部扩展候选打分；对 episode 与 summary **分别类内标准化**后再排序；取 $k=10$，每个 episode 附带同会话 $w=1$ 的邻居。
4. **答案抽取**：单次 LLM 调用，按时间排序、相对时间已预解析为绝对日期；多模态模式下同时传入问题图像与检索图像。

### 2.5 效率论证
- 插入 = 一次嵌入 + 两次索引更新，无 LLM；写时 LLM 成本仅“每片段一次摘要”。
- 检索仅稀疏扫描与矩阵-向量积随记忆规模线性增长，无逐查询 LLM 调用。

## 六、主要结论与发现

- **效果 SOTA**：
  - LoCoMo 平均 F1：GPT-4.1-mini 50.26（vs SimpleMem 43.24）、GPT-4o 49.33（vs 39.06）、Qwen3-8B 44.19（vs 33.45）、Gemma3-27B 45.42（vs 28.98）；
  - MemGallery：67.66 F1（vs A-MEM 62.28、MemoryOS 61.09）；
  - LongMemEval-S：64.60%（vs LightMem 64.29、A-MEM 62.60、NaiveRAG 61.00、全上下文 56.80、Mem0 53.61）。
- **鲁棒性**：换用较弱开源 backbone 时 MemFit 性能下降远小于基线（GPT-4.1-mini→Gemma3-27

B：-15.6 分 vs Mem0 -27.9、A-MEM -23.0），说明其对 reader 质量依赖较低，性能更多来自记忆组织与检索本身。

- **效率显著占优**：
  - LoCoMo 全量（Gemma3-27B）下，MemFit 的构建 LLM 调用约 200 次量级、成本约 \$0.1 级，而 Mem0/A-MEM 需数千次调用、成本高一个数量级以上；构建时间 946 s，明显快于 Mem0 与 A-MEM。
  - 单问题延迟 1.95 s，低于多数基线；token 消耗主要来自答案抽取的单次调用，检索阶段零 LLM 开销。
  - 结论：把 LLM 移出写路径与检索路径，可同时降低构建成本与查询成本，而效果不降反升。

- **消融结论**：
  - 逐组件去除后性能单调下降，5 个组件（混合检索、摘要扩展、PRF、交叉编码器重排、邻居扩展）在 18 组对比中方向一致（全为正贡献），但单组件显著性有限（多数 p>0.05），说明各组件为“累积增益”而非各自独立强效应。
  - 摘要层扩展对多跳/时序类问题贡献最大；PRF 对跨会话稀有实体匹配贡献明显；重排主要提升 top-10 的精度而非召回。
  - 全去除配置仍优于多数基线，表明“逐字存储 + 双索引”是主要收益来源。

- **多模态结论**：MemGallery 上，纯文本 → 加问题图 → 加检索图的递进配置带来稳定增益；带图问题（487 题）上的提升幅度大于纯文本子集，说明图像 caption 化后走统一检索通路是有效的。

- **敏感性结论**：pack size 在 10 附近达到较优平衡（5 偏少、20/30 收益递减且成本上升）；上下文窗口 w=1 已足够，w=2 增益有限；候选池宽度与扫描宽度在中等取值后趋于饱和，说明方法对超参不敏感、易于复用。

- **负面/中性结果（作者如实报告）**：
  - MemGallery 的 KR、CD、MR 等类别上 MemFit 并非最优，部分被 A-MEM/MemoryOS 反超；
  - LongMemEval-S 上与 LightMem 的差距（64.60 vs 64.29）在统计上不显著；
  - 弃答题（30 道）上的拒答行为未做专门优化，准确率受 reader 影响较大。

## 七、局限与未来工作

- **证据完整性 vs 上下文噪声的权衡**：逐字存储避免了写入时信息丢失，但 pack 中会带入与问题弱相关的原始轮次，可能对 reader 造成干扰；作者以重排 + 邻居扩展缓解，但未系统量化“噪声代价”。
- **片段摘要仍是写路径的 LLM 依赖**：虽然频率低（每 ≥3 episode 一次），但在超长对话或高频写入场景下仍是成本与延迟的组成部分；摘要质量依赖摘录采样（最多 14 条），可能遗漏片段内的关键细节。
- **检索的可扩展性未充分验证**：稀疏扫描 + 稠密矩阵-向量积为线性复杂度，实验最大规模约 115k token/段历史，缺少百万级 episode 的压力测试与近似最近邻（ANN）索引下的精度-速度权衡分析。
- **时间推理依赖预解析**：相对时间被预解析为绝对日期，跨时区、模糊时间表达（“上周左右”）的处理未展开讨论。
- **未做训练**：全部使用冻结编码器与现成 LLM，未探索轻量微调（如领域适配的交叉编码器）带来的进一步增益。
- **评测协议风险**：LongMemEval-S 的对比沿用 LightMem 论文的 backbone 与裁判设置，跨论文比较存在协议差异；MemGallery 部分基线结果来自原论文，环境不完全可控。
- **真实部署缺失**：无多用户并发、增量更新冲突、隐私与遗忘（删除请求）等工程层面的讨论，而“不删除、只追加”在合规场景（如被遗忘权）下可能需要额外机制。

- **优点**：

  2. **设计克制且有原则**：只追加不重写、摘要仅作索引、不做巩固删除、事实冲突交由时间排序呈现——每条设计决策都有明确的“避免不可逆信息损失”的理由，而非堆砌模块。

  4. **实验诚实**：报告负面类别、不显著项与 p 值，消融覆盖三个 reader，敏感性逐项单变量扫描，符合可复现研究的规范。
  5. **工程可复用性高**：全基准共用一套超参、冻结小模型编码器、无训练，落地门槛低。

- **可质疑之处**：
  1. **“免 LLM 检索”的边界**：交叉编码器本身是神经模型，重排质量与领域迁移性未在跨域语料上验证；所谓“免 LLM”更准确是“免生成式 LLM 调用”，表述上有一定修辞色彩。
  2. **收益归因**：全去除配置已优于多数基线，说明主要增益来自存储范式而非检索技巧；但消融的统计显著性偏弱，组件贡献的定量拆分（如每组件对 F1 的边际贡献置信区间）不足。
  3. **对比公平性**：部分基线结果取自原论文而非同环境重跑，尽管作者说明了协议一致性，仍存在实现差异、prompt 差异、裁判版本差异的残余风险。
  4. **规模外推**：线性检索在 10 万 token 级历史下表现良好，但真实长期记忆系统的核心挑战往往在千万级 episode 与高频写入，论文未给出该区间的行为预测（如是否必须引入 ANN 及由此带来的召回损失）。
  5. **“不遗忘”的代价**：旧值与修正值并存虽保留证据，但在事实频繁变更的场景会增加 pack 内的冲突密度，reader 需自行消解；论文未量化冲突密度对准确率的影响曲线。

## 九、启示与可迁移要点

- **范式层面**：长期记忆系统的瓶颈可能不在“如何用 LLM 组织记忆”，而在“如何设计不依赖 LLM 的索引与检索结构”；把生成式模型限制在“摘要索引”和“最终作答”两个薄层，是兼顾成本与效果的可迁移架构模式。
- **工程层面**：
  - 双索引（BM25 + 稠密）加 min-max 归一化凸组合、再叠元数据加成，是低成本提升召回的有效配方；
  - “只增不减”的加法式扩展（摘要 provenance 拉入 + PRF）比“剪枝式”过滤更安全，适合证据敏感场景；
  - 类内标准化后再跨类排序，可缓解 episode 与 summary 分数尺度不一致的问题。
- **评测层面**：同时报告效果、成本、延迟与显著性检验，并公开负面结果，应成为记忆系统论文的基准实践；效率测量在 API/HTTP 层计量比理论估算更可信。
- **应用层面**：适合个人助理、客服历史、多会话对话等“证据需可追溯”的场景；对合规删除、多用户隔离、超大规模检索，需在部署时补充机制。

## 十、一句话总结

MemFit 以“逐字追加存储 + 摘要仅作索引 + 免生成式 LLM 的多路检索重排”重构了智能体长期记忆的写入与检索路径，在 LoCoMo、MemGallery、LongMemEval-S 三个基准上以显著更低的构建与查询成本取得领先或持平的准确率，其核心价值在于证明了“把 LLM 移出记忆的关键路径”是一条效果与效率双赢的可行路线，但其超大规模可扩展性、组件级显著性与真实部署约束仍待进一步验证。
