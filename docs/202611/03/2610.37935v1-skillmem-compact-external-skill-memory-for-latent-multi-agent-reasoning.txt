ABSTRACT 

Latent multi-agent systems reduce inference cost by keeping intermediate reason-ing and inter-agent communication in continuous representations. Reusable skills, however, are commonly supplied as text or stored as layer-wise Key-Value states or skill-specific model parameters, introducing repeated processing or substantial per-skill storage. We introduce SkillMem , which represents each reusable skill as a small external latent memory and makes it directly available during latent multi-agent reasoning. A role-conditioned cross-attention reader allows the same mem-ory to guide different agents according to their roles and current hidden states. We train the skill memories and shared reader through behavioral distillation, match-ing the change in token predictions induced by a textual skill while keeping the backbone frozen. For our experiments, we obtain textual skills from paired suc-cessful and failed multi-agent trajectories, although existing skills can also be compiled directly. Across six benchmarks and Qwen3 models ranging from 4B to 14B parameters, SkillMem provides strong gains for smaller backbones while preserving efficient latent multi-agent inference across model scales. We use the same 8 × 256 memory configuration across all evaluated model scales, requiring 9.6 KB of skill-specific storage per skill, including its retrieval embedding. For a library of 100 skills, SkillMem reduces total storage by more than 38 × com-pared with alternative skill representations and achieves up to a 4.23 × end-to-end inference speedup. These results show that compact procedural memories can be reused without sacrificing the efficiency of latent multi-agent reasoning. 

1 INTRODUCTION 

Large language model (LLM) based multi-agent systems (MAS) assign different roles to agents, allowing them to plan, critique, and refine a solution across multiple reasoning steps. This division of work can improve performance over a single model response, yet role specialization alone does not prevent recurring errors. Some of these errors can be addressed by procedures such as check-ing assumptions or verifying intermediate results. Skills (Zhang et al., 2025) capture such reusable procedures from previous experience and make them available for similar problems. In text-based MAS, agents express their reasoning and exchange intermediate results in natural language. Latent reasoning and latent MAS replace this text-based reasoning and communication with continuous representations, reducing the need to generate and process intermediate text (Hao et al., 2024; Shen et al., 2025; Zou et al., 2026). A textual skill is typically inserted into an agent’s prompt, so the model must prefill the skill tokens each time the skill is used. Across repeated uses, this extra prefilling can erode the inference speed gained from latent reasoning and communication. This raises a question: 

how should agents reuse skills efficiently when their reasoning and communication remain in latent space? 

To avoid repeatedly processing skill text, we can store skills in other forms. For example, a cached key–value (KV) prefix avoids recomputing a skill prompt’s activations, but its storage grows with the prefix length and the number of layers (Jin et al., 2026). A skill-specific LoRA adapter stores parameter updates for the layers it modifies (Zhang & Qi, 2026). These trade-offs motivate a compact but efficient, retrievable skill representation that agents can use directly during latent reasoning. We introduce SkillMem , a framework that stores each reusable skill as a small set of learned latent memory vectors. The memory is external to the frozen backbone and can be retrieved independently of other skills. Given a task query, SkillMem selects a relevant skill and makes its memory avail-able throughout latent multi-agent reasoning. Agents continue to exchange latent states, while the retrieved skill provides procedural guidance without adding its textual description to each agent’s prompt. This separates the choice of a skill from the way an agent uses it. Sharing a skill across agents requires more than giving every role the same memory vectors. A plan-ner and a critic may use the same procedure at different stages and for different purposes. SkillMem therefore uses a role-conditioned reader to access the retrieved memory embedding at selected layers of the frozen backbone. The memory is stored once, while the reader uses the current agent’s role to produce a role-dependent update to its hidden states. This allows agents to share procedural knowledge without requiring a separate skill representation for each role. The remaining challenge is how to learn a useful skill memory. Rather than training the memory to reconstruct the skill description, we train it to preserve the skill’s effect on model behavior. We first generate a response using the textual skill. We then measure how much the skill changes the probability of each token in that same response. Behavioral distillation trains the memory and shared reader to reproduce these changes while keeping the backbone frozen. In our experiments, the textual skills come from paired successful and failed multi-agent answer trajectories for the same task. Comparing these trajectories helps identify reusable procedures. The compilation step takes a textual skill as input, so it can use either a skill discovered from trajectories or an existing skill that has already proved useful. Across six reasoning, question-answering, and code-generation benchmarks, SkillMem improves on the latent MAS baseline. On Qwen3-4B, accuracy rises from 17.97% to 35.63% on GPQA-Diamond and from 72.40% to 89.90% on GSM8K. Each skill requires only 9.6 KB of skill-specific storage. SkillMem achieves a 4.23 × end-to-end speedup over TextMAS and a 1.63 × speedup over Latent-MAS with text skills. With a library of 100 skills, its total storage, including the shared reader, is 38.3 × smaller than KV Skill and 86.6 × smaller than LoRA Skill. These results show that SkillMem can provide reusable skills for latent multi-agent reasoning, as summarized in Figure 1. 

2 RELATED WORK 

Latent multi-agent reasoning and memory. LatentMAS (Zou et al., 2026) enables agents to rea-son and communicate through continuous states rather than exchanging natural-language messages. KVComm (Ye et al., 2025) and RecursiveMAS (Yang et al., 2026) further study efficient commu-nication and computation in multi-agent systems. Building on latent collaboration, LatentMem (Fu et al., 2026) constructs agent-specific memories from retrieved interaction experience, while Agent Primitives (Jin et al., 2026) represents predefined multi-agent operations with KV-based latent states. SkillMem addresses a different unit of reuse: a task-level procedural skill stored as a persistent mem-ory that can be retrieved and shared across agent roles. 2Skill representations and behavioral distillation. Textual skills can be applied through prompt-ing, but their instructions must be processed whenever they are inserted into an agent’s context. S2L (Zhang & Qi, 2026) and LatentSkill (Yu et al., 2026) compile textual skills into LoRA-based model adaptations. SkillSmith (Dery et al., 2026) studies the composition of learned KV-prefix skills and textual knowledge. SEED (Wu et al., 2026) distills skill-induced behavioral changes into the agent policy. SkillMem likewise learns from the behavioral effect of a textual skill, but stores that effect in an independently retrievable external memory. A reader shared across skills and roles ac-cesses the memory while the backbone remains frozen. We compare against S2L as a parameter-based skill representation in our experiments. 

Continuous representations and context compression. Prompt and prefix tuning (Lester et al., 2021; Li & Liang, 2021) learn continuous representations that condition a frozen model. Gisting and AutoCompressor (Mu et al., 2023; Chevalier et al., 2023) compress information from a textual context into continuous representations. These methods motivate compact continuous conditioning, while SkillMem learns a separate memory for each reusable procedure and accesses it through a shared, role-conditioned reader during latent multi-agent reasoning. 

Experience-based skill learning and routing. Voyager (Wang et al., 2024) and ExpeL (Zhao et al., 2024) reuse knowledge from previous agent trajectories. SkillRL (Xia et al., 2026) uses successful and failed single-agent trajectories to build a hierarchical skill bank and jointly updates the skills and agent policy through reinforcement learning. We derive textual skills by comparing success-ful and failed multi-agent trajectories, retaining the roles involved in each reasoning stage. Skill-Router (Zheng et al., 2026) studies skill selection at scale. Our retriever selects a skill for the task, while SkillMem focuses on how the selected skill is stored and used across agents.

4 METHOD 

SkillMem stores each textual skill s as a compact memory Zs that can be retrieved independently (Section 4.1). Given a task query q, the system retrieves a skill s and makes its memory Zs available to every agent in the latent MAS pipeline. Agents continue to communicate through KV states, while a role-conditioned reader uses Zs to update their hidden states according to their roles (Section 4.2). We train the memories and reader to reproduce how textual skills change the frozen backbone’s predictions (Section 4.3). Each skill is compiled into a compact latent memory by matching the behavioral effect of skill injection. At inference time, the retrieved memory is shared across agents and consumed through a role-conditioned reader while inter-agent communication remains entirely latent. 4.1 SKILL MEMORY AND SKILL RETRIEVAL 

We define a skill as a reusable reasoning procedure that can guide agents on multiple problem in-stances. Let S = {s1, . . . , s N } be a skill library, where si = ( ni, d i, p i) contains a name, a descrip-tion of when the skill is useful, and procedural instructions. Let E(·) denote a text encoder based on the frozen backbone. We index each skill using ei = E([ ni; di; pi]) . Given a task query q, we compute eq = E(q) and retrieve sq = arg max si∈S sim( eq , ei), where sim is cosine similarity. The selected skill is used by every agent in the multi-agent run. We store each skill s as a persistent external memory Zs ∈ RM ×dmem . This memory contains M

learned vectors for that skill, each of dimension dmem . After selecting s, the system loads Zs for use across agent roles. Each skill has its own memory, requiring O(M d mem ) skill-specific storage. Inserting a textual skill into an agent’s prompt requires processing its tokens when the skill is used. Caching the skill’s layer-wise KV states avoids repeated processing, but stores states for every skill token at every Transformer layer. For a skill of Ts tokens, KV storage scales as O(LT sdkv ), where 

L is the number of layers and dkv is the KV dimension. The storage of Zs does not depend on Ts.4.2 ROLE -C ONDITIONED MEMORY READER

and current reasoning state. We therefore insert a role-conditioned cross-attention reader at selected Transformer layers ℓ. For each token , the reader forms queries from its hidden state and the 

agent’s role , and forms keys and values from Zs. The query is matched against the memory keys to determine which memory vectors are relevant to the current token, and the corresponding values provide the information read from memory. Agents continue to communicate through latent states. 4.3 BEHAVIORAL SKILL DISTILLATION 

A compact memory cannot be expected to reproduce the wording of a textual skill. Instead, we train it to reproduce the effect of that skill on the model’s predictions. For each skill, role, and calibration task, we first generate a fixed response using the textual skill. We then score the same response under three conditions: with the textual skill, without the skill, and with the skill memory. The change caused by the textual skill provides the training target for the memory. During this process, we train the skill memories and reader while keeping the backbone frozen. Figure 3 illustrates this procedure. 

Teacher responses and behavioral targets. Consider a textual skill s, an agent role ρ, and a calibration task x. We add the textual skill to the prompt for role ρ and use the frozen backbone to generate a teacher response ys,ρ,x = ( y1, . . . , y T ), where T is the response length and t ∈{1, . . . , T } indexes a token position. For readability, we omit the task index x from the notation below. Intermediate agents normally communicate through latent states and do not generate text. For these roles, we generate a textual response only to construct a training target. The generation starts from the role prompt without the KV states passed from preceding agents. These teacher responses are used only during training and do not change the latent communication process at inference time. We score each teacher response under three conditions. The text condition includes the textual skill in the prompt. The base condition uses the same prompt without the skill. The memory condition 5also removes the skill text but provides Zs through the role-conditioned reader. All three conditions use teacher forcing: when scoring token yt, the model receives the same preceding teacher tokens 

y<t . This ensures that the three scores differ only in how the skill is provided. Let ℓtext ,ρ t , ℓbase ,ρ t , and ℓmem ,ρ t denote the log-probability assigned to yt under the three conditions. We define the text-induced and memory-induced changes relative to the base model as ∆text ,ρ t =

6.3 STORAGE AND EFFICIENCY 

Table 2 compares the efficiency of different skill representations on Qwen3-8B. 

Storage. Text Skill has negligible storage but must be processed at each use. KV Skill and LoRA Skill require 13.0 MB and 30.7 MB per skill, respectively, while SkillMem uses only 9.6 KB per skill plus one shared reader. From 10 to 1000 skills, SkillMem is 3.9×–308 × smaller than KV Skill. 

Inference efficiency. SkillMem achieves 7.95 s end-to-end latency, comparable to LatentMAS at 8.18 s and lower than Text Skill and KV Skill at 12.98 s and 12.01 s. Its fixed eight-vector memory adds neither skill tokens nor skill-specific KV prefixes, preserving efficient latent inference. 

Training efficiency. For 10 MedQA skills, SkillMem trains its shared reader in 11.7 minutes, versus 110 minutes for separate LoRA adapters, a 9.4× reduction. This advantage comes from sharing the reader across the skill bank, whereas S2L trains a separate adapter for each skill. 6.4 ABLATION STUDIES

Role conditioning. Table 3(a) compares the full reader with role-agnostic, constant-embedding, shuffled-embedding, and per-role memory variants. Removing role conditioning causes the largest drop, reducing average accuracy from 75 .15% to 67 .37% on Qwen3-4B and from 77 .97% to 76 .50%

Memory capacity. Table 3(b) shows a non-monotonic relationship between memory size and ac-curacy. to between 62 .43% and 62 .93% in Table 3(c). The largest drop occurs without Lshift , supporting direct matching of the behavioral change induced by the textual skill. The full objective performs best overall, showing that the three losses provide complementary training signals. 

7 CONCLUSION AND FUTURE WORK 

We introduced S KILL MEM , which represents each reusable skill as a compact external memory for latent multi-agent reasoning. A role-conditioned reader allows agents with different roles to share the same memory, while behavioral distillation transfers the effect of a textual skill without modifying the frozen backbone. Across six benchmarks and three model scales, the results show that compact skill memories can provide useful procedural guidance with low skill-specific storage and efficient latent inference. 9Future work can extend S KILL MEM to retrieve and compose multiple skills within the same reason-ing process, including methods for resolving conflicting guidance. Retrieval could also incorporate the agent’s role and current reasoning state in addition to the task query. Finally, skill memories could be updated online as agents encounter new tasks and interaction patterns.

B SKILL RETRIEVAL 

Each discovered skill is indexed once, offline, by embedding its skill name, description, and skill prompt (concatenated) with the same frozen backbone used for evaluation: we run a forward pass with output hidden states=True , take the last hidden layer, apply attention-mask-weighted mean pooling over token positions, and L2-normalize the resulting vector. When source questions from the discovery trajectories are available, we additionally embed each source question with the same procedure and aggregate the resulting similarity scores with the description-level score by taking their mean (rather than using the skill description alone). At inference time, the input question is embedded with the identical procedure, and the top-1 skill is retrieved by cosine similarity between the query embedding and each skill’s indexed embedding. Retrieval is performed once per evaluation example (not per agent role): all agents in the same multi-agent rollout for a given question consume the same retrieved skill. We do not apply a minimum-similarity threshold for skill selection (threshold = 0 ), so every routed example is assigned a skill; we found that a small positive threshold instead routes a large majority of examples to “no skill” and understates the benefit of skill augmentation. Retrieval is precomputed once per benchmark and cached, and the same cached routing decisions are reused across every skill-based method in Table 1 (KV Skill, S2L, and SkillMem) to ensure a matched comparison.

Role representation. For each agent role ρ, we encode its system-instruction text πρ with the frozen backbone and pool hidden states from the middle decoder layer ( ⌊L/ 2⌋, i.e. layer 18 for Qwen3-4B/8B and layer 20 for Qwen3-14B) using a fixed (untrained) attention query and projec-tion: both are drawn once from a seeded random Gaussian initialization and kept frozen for the lifetime of the model wrapper, computed under no grad and never registered as trainable param-eters. The resulting role embedding eρ ∈ R64 is therefore not learned; the four agent roles are dis-tinguished purely by the content of their respective instruction text, not by any trained role-specific parameters. This keeps the shared reader’s role-conditioning entirely a function of frozen backbone representations, introducing no additional trainable role-specific parameters. 

Reader parameters are not shared across insertion layers. Each of the four insertion layers has its own independent set of reader weights ( Wq , W k, W v , W o, W g , plus a LayerNorm): readers at different depths are separately parameterized modules, not a single reader applied repeatedly. Only the memory bank Zs is shared as a single per-skill vector across all four readers; each reader learns its own layer-specific mapping from that shared memory into its local residual stream. 16 D.2 INTERMEDIATE -R OLE BEHAVIORAL DISTILLATION 

Because L ATENT MAS agents other than the final (judger) role never emit text during normal in-ference, obtaining a token-level supervision target for their behavioral-distillation losses (Eqs. 3–5) requires generating text for those roles during training only . For every (skill, role) pair, we generate one teacher continuation per calibration example by running the frozen backbone’s ordinary text-generation path – with the retrieved skill’s text injected into that role’s own prompt and no context from other agents (context = ∅) – and decode greedily. This continuation is cached once and reused for all subsequent training steps; it is never regenerated on the fly. The same context = ∅ conven-tion is used at inference time ( cross-agent information is carried entirely through the shared latent KV cache, not through the prompt text), so the prompt text seen at training time exactly matches the prompt text seen at inference time for every role. The one difference between the two settings is that, at training time, the teacher continuation for a given role is generated from a fresh KV state (no upstream latent context), whereas at inference time the same role’s turn is conditioned on the latent KV cache accumulated from preceding agents; the textual content of the prompt itself does not depend on this KV prefix. The generated teacher tokens serve solely as a fixed teacher-forcing target for computing ltext , lbase , and (during training) lmem : they are never fed back into the model as generation input and never appear anywhere in the deployed (inference-time) pipeline, which loads only the trained memory bank and reader weights. Because the planner, critic, and refiner roles are, by design, not instructed to produce a final answer, we do not apply an answer-correctness filter to their generated teacher continuations (doing so would be a category error, since these roles have no notion of a “final answer” to check); only the judger’s continuation is filtered by answer correctness before being accepted into the teacher cache. Interpretation. The bound contains two terms with different meanings. The first, δ, measures how accurately behavioral distillation reproduces the textual skill effect on the states observed during training. The second, (LF + LG)LΦϵalign , captures the additional error introduced when the learned skill is applied to latent reasoning states. LatentMAS directly targets the input component of this term through its input-output alignment operator, while the frozen backbone maps both text-derived and aligned latent inputs into the same intermediate hidden-state interface. The analysis therefore does not require textual and latent reasoning states to be identical. It only states that behavioral transfer remains controlled when the aligned latent trajectory stays within a local region where the frozen backbone and the two skill-effect functions vary smoothly. 

F DIRECTLY DISCOVER LATENT VECTOR AS SKILLS 

The pipeline described in the main text discovers skills in two stages: the backbone model compares calibration trajectories and produces a natural-language skill description, after which behavioral distillation compiles that description into the memory vector Zs used at inference. A natural question is whether both stages can be skipped, discovering Z directly from the base MAS model’s own hidden states, with zero gradient updates. We explored two variants of this idea. 

Contrastive extraction. For each calibration question we sample 8 attempts under temperature decoding with the TextMAS carrier and keep any pair where at least one attempt reached the cor-rect final answer and at least one did not (MedQA and GPQA-D yielded 13 such pairs out of 20 calibration questions each; GSM8K yielded only 5, since its baseline accuracy is high enough that few sampled attempts fail). For each pair we render the two trajectories to text and extract a rep-resentation from each side using the same mechanism already used to initialize Z from skill text: hidden states from a fixed decoder layer are pooled by attention against M =8 fixed random queries and projected to dmem =256 by a fixed random matrix. The skill vector for a pair is the difference 

Zpair = Zsuccess − Zfailure , and the final Zskill is the mean of Zpair over all valid pairs. The raw ex-tracted norm is roughly two orders of magnitude smaller than a gradient-trained Z (e.g. ∼1–11 vs. 

∼335–360), so we rescale Zskill to match the mean norm of an already-trained checkpoint’s skills before evaluating it through that checkpoint’s (already-trained, skill-agnostic) cross-attention reader. 19 Latent generation. Rather than hand-extracting a direction, this variant lets the base model gener-ate one. We concatenate several (success, failure) pairs into a single reflection prompt instructing the model to identify what separates the correct attempts from the incorrect ones, then run M =8 steps of the model’s own continuous latent reasoning – the identical mechanism the Planner/Critic/Refiner agents already use for their internal thinking, with no text ever decoded. The resulting M ”thought” embeddings are projected to dmem with the same fixed random map and rescaled identically to the extraction variant. 

Results. Both variants require zero gradient training and reuse an already-trained, shared cross-attention reader; only Z itself is produced without training.
