## 摘要
基于 Web 的应用日益依赖对长多模态文档的理解，回答其中问题通常需要综合跨页面、表格和图的信息。智能体式检索增强生成通过迭代检索与推理来处理这些任务。然而，智能体式执行并非总是必要，会引入额外计算并可能导致错误答案。我们的实证分析表明，智能体式执行带来的收益依赖于查询，而额外操作可能提升、保持或降低答案准确率。这些发现促使我们同时控制智能体调用及其后续执行。为应对这些挑战，我们提出 RouteDRAG，一个由四个组件组成的学习型框架。统一文档索引将多模态内容组织为图结构支持的索引，并从初始检索中导出查询表示。自适应路径路由保留精确回答，并预测智能体相对于更短执行路径的相对收益。动态智能体执行维护一个持续演化的工作区，并细化规划器提议以控制工具使用与终止。序列策略学习首先根据观测结果训练操作控制，然后利用所得智能体的性能训练路径路由。在两个基准上，RouteDRAG 相较于仅使用更短路径的执行平均提升 3.47 个百分点准确率，同时仅将 79.3% 的查询分配给智能体。值得注意的是，它在两个基准上均超过统一智能体执行，同时需要更少的回答调用。我们的代码现已在 https://github.com/Ereshkigal1/RouteDRAG 提供。

## Abstract
Web-based applications increasingly rely on understanding long multimodal documents, where answering questions often requires combining information across pages, tables, and figures. Agentic retrieval-augmented generation addresses these tasks through iterative retrieval and reasoning. However, Agentic execution is not always necessary, introducing additional computation and potentially incorrect answers. Our empirical analysis reveals that Agentic execution provides query-dependent benefits, while additional operations may improve, preserve, or degrade answer accuracy. These findings motivate controlling both Agent invocation and subsequent execution. To address these challenges, we propose RouteDRAG, a learning-based framework comprising four components. Unified Document Index organizes multimodal content into a graph-backed index and derives query representations from initial retrieval. Adaptive Path Routing preserves exact answering and predicts the relative benefit of Agent over shorter execution paths. Dynamic Agent Execution maintains an evolving workspace and refines Planner proposals to control tool use and termination. Sequential Policy Learning first trains operation control from observed outcomes and then trains path routing using the resulting Agent's performance. Across two benchmarks, RouteDRAG achieves an average accuracy improvement of 3.47 percentage points over shorter-path-only execution while assigning only 79.3% of queries to Agent. Notably, it also surpasses uniform Agent execution on both benchmarks while requiring fewer answering calls. Our code is now available at https://github.com/Ereshkigal1/RouteDRAG.

## 2. 方法论

### 核心思想
RouteDRAG 是一个学习型框架，将“是否调用 Agent”与“如何执行 Agent”统一为两个相互关联的决策，并通过**序列策略学习**让路由决策与更新后的 Agent 实际表现对齐。

### 关键技术细节（四组件）

- **统一文档索引（Unified Document Index）**
  - 仿照 RAG-Anything / LightRAG，将文本块、实体、关系、视觉元素与结构化元数据组织为图结构索引 \(K_D\)，并保留原始文档位置。
  - 支持四条执行路径：Exact、Standard、Direct VLM、Agent；索引与预训练检索编码器冻结。
  - 查询表示：取 top-8 chunk 与 top-4 entity，经冻结语义编码器与共享可训练投影 \(P_\psi\) 映射到 64 维，用掩码注意力得到 \(z_q, z_c, z_g\)，再经门控与融合网络得到 \(h_0\)（融合查询、检索内容统计与相似度特征 \(u_0\)）。

- **自适应路径路由（Adaptive Path Routing）**
  - 先执行可验证的 Exact 门控 \(g_{exact}\)；否则固定策略选择短路径 \(C(q) \in \{\text{Standard}, \text{VLM}\}\)。
  - 不独立预测每条路径正确性，而是预测 **Agent 相对短路径的收益**：\(\hat{\Delta}_\theta(q) = w_h^\top h_0 + w_u^\top \tilde{u}_0 + b\)。
  - 路由策略：Exact 命中则 Exact；\(\hat{\Delta}_\theta(q) > \tau\) 则 Agent；否则走 \(C(q)\)。阈值 \(\tau\) 在开发集上确定。

- **动态 Agent 执行（Dynamic Agent Execution）**
  - 维护演化工作区 \(W_t\)（检索内容、来源引用、操作历史）。
  - 对候选操作 \(a\)，用动作条件注意力汇总当前 chunk/entity，并结合状态、操作嵌入与历史向量得到 \(z_\phi(W_t,a)\)。
  - 以 FINISH 为参照定义相对操作分数 \(\hat{d}_t(a) = z_\phi(W_t,a) - z_\phi(W_t,\text{FINISH})\)。
  - 控制器在合法动作集 \(\Gamma_t\) 内选最优动作 \(a_t^*\)；若其相对 Planner 提议的增益超过固定 margin \(m\)，则替换提议动作（参数仍由 Planner 生成），否则保留原提议。执行后更新工作区，直到 FINISH 或达到执行上限。

- **序列策略学习（Sequential Policy Learning）**
  - **操作级学习**：比较“立即终止”与“多执行一个操作”的正确性差 \(d_{i,t,a} = Y(\text{Stop}(T_a(W_{i,t}))) - Y(\text{Stop}(W_{i,t}))\)；损失 \(L_A = L_{reg} + \alpha L_{rank}^A + \beta L_{BC}\)，包含回归、同状态动作排序与 Planner 模仿。
  - **路径级学习**：执行更新后的 Agent \(A_\phi\)，与短路径比较得 \(\Delta_i = Y(A_\phi(q_i)) - Y(C(q_i)) \in \{-1,0,1\}\)；损失 \(L_R = \mathbb{E}_i(\hat{\Delta}_i - \Delta_i)^2 + \mu \mathbb{E}_{(i,j)\in P_R}\ell(\hat{\Delta}_j - \hat{\Delta}_i)\)，含回归与跨查询排序。
  - **顺序训练**：先训练共享表示与操作控制器，再冻结它们、用更新后 Agent 的结果训练路由头，确保路由反映 Agent 实际行为。

- RouteDRAG 在 DocBench 与 MMLongBench-Doc 上分别达到 **75.86%** 与 **53.80%** 准确率，优于所有对比 RAG 基线。
- 相比 **Uniform Agent**，准确率提升 **1.18/1.28 个百分点**，同时减少回答调用 **16.4%/14.9%**、token **11.6%/10.6%**。

- 核心洞见：**不仅要控制是否调用 Agent，还要控制其如何执行**；操作级控制与路径级路由应联合、顺序学习。

## 7. 优点

- **路由设计巧妙**：不预测绝对正确性，而是预测 Agent 相对指定短路径的**相对收益**，更贴合“是否值得多花计算”的实际决策；Exact 门控保证结构化查询的精确性。
- **控制与规划解耦**：控制器只做动作选择与终止判断，参数仍由 Planner 生成，保留原工具执行流程，侵入性低、

- **控制与规划解耦**：控制器只做动作选择与终止判断，参数仍由 Planner 生成，保留原工具执行流程，侵入性低、**易于作为插件接入现有 Agentic RAG 框架**，而不必重写工具链。
- **顺序训练保证“路由所见即所得”**：先训练共享表示与操作控制器，再用**更新后 Agent 的真实结果**训练路由头，避免路由基于“名义 Agent”而非“实际 Agent”做判断，这是许多路由工作容易忽略的一致性细节。
- **成本—准确率可连续调节**：单一阈值 \(\tau\) 即可在 Efficient / Medium / High 等多档工作点间切换，便于按线上预算部署，实用性强。
- **实验规范度较高**：统一回答模型、以源 PDF 为单位做文档级 5 折交叉验证、阈值仅在开发集校准、主结果报告 5 次运行标准差、跨 5 种 VLM backbone 验证，整体可比性与可复现性较好。

## 8. 局限与可改进之处

- **阈值与超参仍靠人工标定**：路由阈值 \(\tau\)、控制器 margin \(m\)、执行步数上限均为固定超参，未做端到端可微优化或“预算约束下最大化准确率”的显式建模（如拉格朗日乘子 / 约束策略优化），跨数据集迁移时可能需重新调参。
- **收益预测为点估计，缺少不确定性**：路由头只输出标量 \(\hat{\Delta}_\theta(q)\)，未给出置信区间或校准误差，边界查询易被误路由；若能输出分布并配合弃权/回退机制会更稳健。
- **代价非对称性未建模**：O2 明确指出 Agent 会把 2.09%/3.57% 的正确回答变错，但路径级损失对 \(+1\) 与 \(-1\) 对称处理；在错误代价高的场景（金融、法律、政务）应引入代价敏感学习或风险约束。
- **检索侧被冻结**：索引与检索编码器不参与训练，检索质量构成性能上限；扰动实验虽显示鲁棒，但极端噪声下仍会退化，未探讨联合微调检索器或索引重排的收益。
- **实验覆盖的边界**：MMLongBench-Doc 最长文档分箱仅 5 个问题（来自 1 篇 PDF），该区间结论统计意义有限；backbone 泛化仅单次运行、无标准差，部分增益（如 Qwen3-VL-4B 上 +0.55/+0.73 个百分点）未做显著性检验。
- **评测维度偏窄**：仅报告答案准确率，未评估引用/溯源正确性、开放式生成质量、多轮交互与拒答行为；判分依赖固定 Qwen-based judge，存在判官偏差与长度/格式偏好风险。
- **系统层面证据不足**：效率仅在 batch size = 1 的单卡 A100 上测得，未报告吞吐、并发、端到端在线延迟分解；训练算力（GPU 数、时长、GPU 小时）与离线索引构建成本均未披露，难以评估总拥有成本。
- **方法适用范围**：结论建立在“存在一条可用的短路径 + 一个可调用的 Agent”这一前提上；对于短路径本身很弱、或 Agent 工具集高度异质的场景，相对收益信号的方差可能更大。

## 9. 对读者与实践的启示

- **不要把 Agent 当默认选项**：应先用小规模标注量化“Agent 相对短路径的边际收益”，再决定是否默认启用；论文中 94.83%/89.73% 的查询上两路径结果一致，说明大量算力被花在“不改变结果”的调用上。
- **路由目标应是“相对增益”而非“绝对正确率”**：直接预测“多花这些 token 值不值”，比预测“能不能答对”更贴合工程决策，也更容易与预算约束对齐。
- **操作级控制是降本主杠杆**：在 84.51% 的匹配比较中额外操作不改变正确性，说明“早停 + 动作筛选”比单纯削减 Agent 调用次数更能省 token，且不牺牲准确率。
- **训练与部署必须行为一致**：路由头应在“实际会部署的那一版 Agent”产出的结果上训练，否则离线指标与线上表现会系统性偏离。
- **可迁移性**：该“路径路由 + 操作控制器 + 顺序训练”范式可外推到工具调用 Agent、多跳检索 Agent、代码/数据分析 Agent 等，作为轻量插件而非重构方案。
- **工程落地建议**：优先实现 Exact 门控与 FINISH 早停这类“低风险高收益”组件，再逐步引入学习型路由；同时为路由决策记录日志，便于后续做在线校准与成本审计。

## 10. 一句话总结

RouteDRAG 用“**是否调用 Agent（路径级路由）+ 调用后如何执行（操作级控制）**”两个联合决策，并以顺序策略学习让路由对齐 Agent 的真实行为，在几乎不损准确率的前提下显著削减了 Agentic RAG 的调用与 token 开销，把“Agent 是否值得”从经验判断变成了可学习的成本—收益权衡。
