Abstract 

LLM agents are flexible in language interaction, but using them as long-horizon planners is costly and prone to hallucinated or invalid actions. This paper targets a different role for LLMs: constrained bridges between language and symbolic plan-ning. We propose MemPlan, a memory-conditioned PDDL planning framework for partially observable interactive text environments. MemPlan keeps the PDDL domain fixed and reconstructs the PDDL problem at each step from parsed obser-vations, candidate hypotheses, and interaction memory. Positive graph memory assigns relevance-based action costs to candidate hypotheses for missing objects, lo-cations, or conditions, guiding the planner toward more plausible checks. Negative memory records execution-refuted assumptions and compiles them into exclusion constraints, preventing repeated attempts at candidates already contradicted by feedback. A unified schema-conditioned language–symbol interface, trained of-fline with supervised fine-tuning, connects text environments to the planning loop through observation-to-fact parsing and symbolic-action-to-command grounding. Experiments on TextWorld, ALFWorld, and Robotouille show that MemPlan im-proves task completion and step efficiency over language-only and PDDL-aware baselines, while substantially reducing online token cost compared with LLM-planning baselines such as ReAct. The same fine-tuned interface is also reused across TextWorld task types without task-specific fine-tuning. Our code and data are available at: https://github.com/tewiSong/MemPlan .

1 Introduction 

Interactive text environments require agents to solve long-horizon tasks under partial observability and delayed consequences, using natural-language observations and natural-language commands [Côté et al., 2018, Shridhar et al., 2021, Gonzalez-Pumariega et al., 2025]. Recent LLM agents can interpret textual feedback and generate plausible commands, but using LLMs as the primary planner remains costly and unreliable. In interactive settings, they may hallucinate actions, lose track of earlier observations, or fail to maintain a consistent long-horizon plan [Valmeekam et al., 2023, Sun et al., 2023, Zhang et al., 2025]. Classical planners offer a complementary strength. Given a PDDL domain, a symbolic state, and a goal, planners such as Fast Downward [Helmert, 2006] can search explicitly over action preconditions and effects [Aeronautiques et al., 1998]. Prior work empirically shows that replacing an LLM planner with a classical planner can save approximately 93.1% of LLM tokens [Dagan et al., 2023]. The difficulty is that partially observable text environments do not directly provide the complete

symbolic state required by a closed-world planner. Static LLM-to-PDDL formalization methods cannot interactively update the planning problem from environment feedback [Liu et al., 2023, Guan et al., 2023, Gestrin et al., 2024]. Existing work addresses this mismatch through two main routes. Belief and open-world completion methods make planning possible by first choosing or generating a completed symbolic state [Tala-madupula et al., 2010, Dagan et al., 2023]. This approach works when the completion is reliable, but in text environments a missing object, location, or condition can have many plausible completions. Committing to one completed state before planning can lead to unnecessary search or repeated failed trials. Iterative PDDL refinement methods update domain or problem files from new observations and error feedback [Zhang et al., 2024, Gong et al., 2025]. This gives the representation more flexibility, but correctness then depends on repeated online formalization, which can introduce malformed PDDL, hallucinated facts, invalid goals, or forgotten observations. This motivates a different use of symbolic planning under partial observability: a closed PDDL problem is still needed at each planner call, but the agent should avoid committing to a single guessed world state or relying on online LLM rewriting of PDDL files. To this end, we propose MemPlan, a memory-conditioned PDDL planning framework for partially observable text environments. MemPlan treats missing task-relevant state as candidate symbolic hypotheses and compiles interaction memory into the PDDL problem before each planner call. Positive graph memory ranks hypotheses for missing objects, locations, or conditions through action costs, allowing the planner to test more relevant candidates first. Negative memory records failed searches or refuted assumptions as symbolic exclusions, preventing repeated attempts at candidates already contradicted by the environment. A frozen schema-conditioned language–symbol interface connects text observations and commands to this symbolic loop through observation-to-fact parsing and symbolic-action-to-command grounding. Our contributions are as follows. First, we introduce memory-conditioned PDDL problem construc-tion, enabling a closed-world planner to operate in partially observable text environments without online PDDL rewriting. Second, we propose a positive/negative memory mechanism that ranks unresolved hypotheses with graph-derived costs and excludes execution-refuted candidates from later planning calls. Third, we train an offline schema-conditioned language–symbol interface for parsing observations and grounding symbolic actions, reducing online LLM use to constrained interface calls. We evaluate MemPlan on TextWorld, ALFWorld, and Robotouille, measuring task completion, step efficiency, token cost, and cross-task use of the learned interface. 

2 Related Work 

State, memory, and feedback in language agents. A large body of work studies how language agents act in interactive environments without an explicit symbolic planner. In text-based games, Keep CALM uses language models to generate action candidates and combines them with reinforcement learning for action selection [Yao et al., 2020]. More recent work focuses on maintaining internal state over long interactions. QuBE constructs question-based belief states to reduce reasoning derailment under partial observability [Kim et al., 2024], while WKM introduces a world-knowledge model with global task knowledge and local dynamic state knowledge for agent planning [Qiao et al., 2024]. AriGraph builds semantic and episodic graph memory for LLM agents in interactive text games [Anokhin et al., 2025]. Feedback-driven agents such as AdaPlanner refine language plans online using environment feedback [Sun et al., 2023]. These methods improve memory, action generation, or feedback use for LLM policies. MemPlan uses memory differently: graph-memory relevance is compiled into PDDL hypothesis-action costs, and execution-refuted assumptions are compiled into symbolic exclusions for a classical planner. 

LLM-based PDDL formalization and planner interfaces. Another line of work connects language models with classical planning. LLM+P translates natural-language planning problems into PDDL, calls a classical planner, and translates the symbolic plan back into natural language [Liu et al., 2023]. Guan et al. use LLMs to construct PDDL world models and incorporate corrective feedback from validators and humans [Guan et al., 2023]. LLM-DP moves toward embodied interaction by using LLM-generated beliefs to sample plausible world states for symbolic planning [Dagan et al., 2023]. PDDLEGO and PDDLEGO+ study partial observability by iteratively formalizing, planning, growing, and refining PDDL representations through interaction [Zhang et al., 2024, Gong et al., 2025]. Open-world and structured embodied planning. Talamadupula et al. integrate a closed-world planner with an open-world robot using open-world quantified goals, runtime objects, execution monitoring, replanning, and soft goals [Talamadupula et al., 2010]. This work motivates the use of planner-internal placeholders for objects that may be discovered during execution. MemPlan adapts this idea to language-mediated environments, where both observations and executable actions are textual. The agent must therefore parse text observations into symbolic facts, ground symbolic actions back to admissible commands, and update memory from textual feedback. Recent structured embodied planning systems also use intermediate symbolic or graph representations: LLM-REGRESS performs open-world embodied planning with lifted regression and LLM-inferred affordances [Liu et al., 2025]; DELTA constructs planning problems from scene graphs and LLM decompositions [Liu et al., 2024]; LLM+MAP combines LLM reasoning with PDDL-style multi-agent planning for bimanual manipulation [Chu et al., 2025]; and HIVE uses a PDDL-empowered formal backbone for multimodal instruction execution [Vyas et al., 2025]. These systems highlight the value of structured representations, while MemPlan focuses on partially observable text environments and memory-conditioned PDDL problem construction. 

3 Method 

We study planning in partially observable text environments. At step t, the agent receives a task goal 

g, a textual observation ot, and an admissible command set At. The agent must select a command

3.1 Offline Schema-Conditioned Language–Symbol Interface 

MemPlan uses one language–symbol interface with two instruction formats. The interface is trained offline by supervised fine-tuning and frozen during evaluation. Online, it only performs observation-to-fact parsing and symbolic-action-to-command grounding. It does not generate plans, repair the PDDL domain, or rewrite PDDL problems. 

Observation-to-fact parsing. Let SD denote the predicate and type schema induced by D, and let Ot denote the current object glossary. Given (ot, SD , Ot), the parser outputs candidate triples. A triple is accepted into Ft only when its relation appears in SD , its argument types match the schema, and its entities are grounded in Ot or introduced as placeholders used only inside planning. The parser extracts local symbolic evidence from the observation; MemPlan constructs the full PDDL problem. 

Symbolic-action-to-command grounding. Given the first symbolic action ut, the current obser-vation ot, and the admissible command set At, the grounder scores each command c ∈ A t with

The candidate set Ht is generated from observed entities, memory graph neighborhoods, recently visited areas, and values compatible with the current goal. Once feedback resolves the placeholder to a concrete entity, later PDDL problems use the concrete entity. This placeholder mechanism is inspired by open-world planning with runtime objects and execu-tion monitoring [Talamadupula et al., 2010]. MemPlan adapts it to text environments by pairing placeholders with learned parsing, learned grounding, and memory-based hypothesis testing.

. During the next call to B UILD -PROBLEM , the refuted candidate is omitted or made inapplicable through exclusion predicates, such as searched or not_at . Thus M + 

> t

controls which hypotheses are tried earlier, while M − 

> t

prevents the planner from repeating hypotheses already contradicted by the environment. This construction differs from iterative PDDL rewriting methods. The PDDL domain remains fixed, and the LLM does not rewrite the domain or problem online. MemPlan rebuilds the problem by injecting placeholders, costing hypotheses with positive graph memory, and excluding refuted hypotheses with negative memory. 53.4 Online Planning and Memory Update 

Algorithm 1 summarizes the online loop. MemPlan executes only the first grounded action of each plan, updates M + 

> t

with supported observations and resolved placeholders, updates M − 

> t

with searched or refuted hypotheses, and replans after feedback. 

4 Experiments 

We evaluate MemPlan on interactive text environments with partial observability. The experiments address four questions. Q1: Does MemPlan improve task completion and step efficiency over language-only and PDDL-aware baselines, and how does its online LLM token cost compare with LLM-planning baselines? Q2: How does memory-conditioned PDDL planning compare with memory-augmented LLM agents? Q3: Can MemPlan handle synchronous and asynchronous long-horizon planning in Robotouille? Q4: Which components contribute to the observed gains? 

4.1 Experimental Setup Benchmarks. We evaluate MemPlan on TextWorld [Côté et al., 2018], ALFWorld [Shridhar et al., 2021], and Robotouille [Gonzalez-Pumariega et al., 2025]. ALFWorld is our main end-to-end bench-mark; TextWorld is used for memory-agent comparison, cross-task interface use, and ablations; Robotouille tests synchronous and asynchronous long-horizon planning. We evaluate on 134 ALF-World episodes, 7 TextWorld task instances, and 151 Robotouille task-seed runs. For Robotouille, success is first averaged over seeds within each task configuration and then macro-averaged across task configurations. Full split details, interaction budgets, metric definitions, and statistical reporting are provided in Appendix A. 

PDDL domains. MemPlan uses one fixed PDDL domain per environment. We use the ALFWorld-released ALFRED domain and construct Robotouille domains from public domain metadata. TextWorld does not provide PDDL domains for the evaluated task families, so we generate its domains offline before evaluation. GPT-5.1 drafts each domain from environment-level task rules and action descriptions, without access to test-instance maps, object placements, oracle trajectories, interaction logs, or evaluation feedback. Validator and planner error messages are used for one offline repair round when needed. In our TextWorld protocol, 5/7 domains ( 71 .4% ) are valid on the first attempt, and the remaining two are repaired successfully after one offline feedback round. The repaired domains are fixed for evaluation; MemPlan only rebuilds instance-level problem files online. 

MemPlan implementation. Given the fixed domain for each environment, MemPlan constructs instance-level PDDL problems online from the current observation, task goal, positive memory, nega-tive memory, and candidate hypotheses. Symbolic planning is performed by Fast Downward [Helmert, 2006]. The language–symbol interface uses Qwen2.5-7B as the backbone. We supervise fine-tuning one unified interface on TextWorld cook and hunt tasks, using 17,000 observation-to-fact examples and 9,600 symbolic-action-to-command examples, then freeze it for all evaluations. ALFWorld and Robotouille interface splits are used only for post-training diagnostic validation; they are not used for supervised fine-tuning, checkpoint selection, or hyperparameter tuning. 

Baselines and metrics. We compare against language-only baselines, PDDL-aware baselines, and TextWorld memory-agent baselines. We report task success, environment steps, and online LLM token usage; metric definitions and evaluation protocols are detailed in Appendix A.

MemPlan has three main limitations. First, it assumes that a task-level PDDL domain is available and covers the relevant object types, predicates, action schemas, preconditions, and effects. Although TextWorld domains can be generated and repaired offline before evaluation accurately, MemPlan does not automate domain construction inside the online agent; incorrect or incomplete domain rules can still lead to invalid symbolic plans. Second, negative memory currently uses hard exclusions: once feedback marks a candidate hypothesis as refuted, the candidate is removed from later PDDL problems. This avoids repeated failed checks, but it can be brittle when feedback is ambiguous or incorrectly parsed, because a valid candidate may be excluded too early. Future work could replace this hard exclusion with confidence-weighted negative memory, where weak or ambiguous feedback lowers a candidate’s priority instead of removing it immediately. Third, our evaluation is limited to simulated text environments with benchmark-specific action spaces and, when available, admissible commands. We do not evaluate safety-critical deployment, physical robotics, or open-ended environments without constrained command sets. 

6 Conclusion 

This work shows that a fixed-domain classical planner can be used effectively in partially observable text environments when interaction memory is made part of PDDL problem construction. MemPlan represents unresolved task-relevant information as candidate hypotheses, uses positive graph memory to assign planner-visible action costs, and converts execution-refuted assumptions into exclusions for later planning calls. This design keeps the LLM out of the online planning role and uses it only for constrained parsing and grounding. Across ALFWorld, TextWorld, and Robotouille, the results show that memory-conditioned PDDL construction improves task completion and step efficiency over language-only and PDDL-aware baselines. More broadly, MemPlan suggests a concrete role for memory in neural–symbolic agents: interaction memory can be compiled into planner-visible costs and constraints, rather than only retrieved as language context.

A.4 PDDL Domains and Planner 

MemPlan separates fixed PDDL domains from online PDDL problem construction. The domain specifies object types, predicates, action schemas, preconditions, and effects. The problem file specifies the current objects, initial facts, goal facts, memory-conditioned candidate hypotheses, action costs, and exclusion constraints. During evaluation, MemPlan reconstructs only the problem file online; the domain file remains fixed. The source of the fixed domain differs by benchmark. For ALFWorld, we use the benchmark-provided ALFRED PDDL domain released with ALFWorld. For Robotouille, we construct PDDL domains from public domain metadata and transition specifications. For TextWorld, because the benchmark does not provide PDDL domains for the evaluated task families, we generate domains offline before evaluation. The domain-generation prompt contains environment-level task rules and action descriptions only; it does not include test-instance maps, object placements, oracle trajectories, interaction logs, or evaluation feedback. GPT-5.1 drafts each domain, and validator or planner error messages are used for one offline repair round when needed. In our protocol, 5/7 TextWorld domains 14 are valid on the first attempt, and the remaining two are repaired successfully after one feedback round. The resulting domains are fixed during evaluation and are not updated online. MemPlan uses Fast Downward [Helmert, 2006] for symbolic planning. Generated problem files include: 

(:metric minimize (total-cost)) 

The planner configuration is satisficing, so action costs bias hypothesis selection without guaranteeing globally optimal-cost plans. After each planner call, MemPlan executes only the first grounded command, observes textual feedback, updates memory, and replans when needed. When an observation fallback is used, the unrealized symbolic action is not treated as executed. Memory is updated only from environment feedback.

A.6 Graph-Memory Hypothesis Cost Construction 

For each unresolved placeholder z, MemPlan constructs candidate hypotheses h = ( z, r, v ) from entities and relations observed in the current episode. Candidate values are drawn from observed locations, containers, receptacles, objects, states, and task-related entities in positive memory. Can-didates already refuted by negative memory are removed before PDDL problem construction. The internal negative-memory records are triples for consistency with hypothesis representation, but BUILD PROBLEM compiles them into the arity required by the target PDDL domain. For example, a placeholder-specific refutation may compile to not_at( z,v), while a domain that only needs to block repeated room checks may compile the same evidence to a unary predicate such as searched( v).For each remaining candidate h = ( z, r, v ), MemPlan computes a relevance score Score t(h) ∈ [0 , 1] 

as a text-based graph-memory retrieval score. The query string is 

qt(z) = Goal: g ; Missing: z. 

The candidate document is 

dt(h) = Candidate: (z, r, v ) ; Context: Linearize( N1(v; M + 

> t

)) ,

where N1(v; M + 

> t

) is the one-hop neighborhood of v in the positive-memory graph. The function 

Linearize( ·) serializes neighboring triples in a deterministic order. We encode qt(z) and dt(h) with the frozen mContriever encoder (checkpoint facebook/mcontriever ) [Izacard et al., 2022] and compute cosine similarity: 

sim t(h) = cos (Enc( qt(z)) , Enc( dt(h))) .

The score is normalized over the current candidate set: 

Score t(h) = sim t(h) − min h′∈H t sim t(h′)max h′∈H t sim t(h′) − min h′∈H t sim t(h′) + ϵ .

17 We set ϵ = 10 −8 for numerical stability. The score is used only to order hypothesis-checking actions. It does not generate symbolic plans, add memory facts, or decide whether a candidate is true. MemPlan converts the score into a PDDL action cost: 

κt(h) = κbase + ⌈λ · max(0 , τ − Score t(h)) ⌉ ,

where κbase is the base action cost, τ is the relevance threshold, and λ controls the penalty scale. Physical actions use κbase . Hypothesis-checking actions receive larger costs when their relevance scores are lower than τ .The generated PDDL problem includes: 

(:metric minimize (total-cost)) 

Thus, the planner is biased toward checking hypotheses with stronger positive-memory support. Since the planner configuration is satisficing, these costs guide search without guaranteeing a globally minimum-cost plan. All cost parameters are fixed before test-time evaluation and are not tuned on test episodes. Negative memory can still remove a high-scoring candidate after it is refuted by execution feedback. 

A.7 Positive-Memory Hyperparameter Sensitivity 

We tested all nine combinations of τ ∈ { 0.40 , 0.50 , 0.60 } and λ ∈ { 5, 10 , 20 }, with κbase = 1 .Across the evaluated TextWorld tasks, all nine settings achieved a normalized score of 1.00; mean episode lengths ranged from 31.0 to 34.1 steps. These results support the role of positive memory in ordering hypothesis checks and improving interaction efficiency. The ability to complete the tasks also depends on placeholders, negative memory, and the fixed PDDL domain.

18 B Interface Training and Validation Details 

B.1 Unified Interface Model 

MemPlan uses Qwen2.5-7B fine-tuned as a unified schema-conditioned language–symbol interface. The same frozen model handles two task formats: observation-to-fact parsing and symbolic-action-to-command grounding. 

Observation-to-fact parsing. The input contains a textual observation, the domain predicate schema, and an object glossary. The output is a set of PDDL-compatible facts. Outputs are checked against valid predicate names and typed object identifiers before they are used to update memory or construct the next PDDL problem. 

Symbolic-action-to-command grounding. The input contains a symbolic planner action, the current textual observation, and the admissible command set. The output is an executable text command. This turns command generation into candidate selection from admissible commands. 

B.2 Training Data 

The Qwen2.5-7B interface is fine-tuned on 17,000 observation–fact examples and 9,600 symbolic-action–command examples. Observation–fact labels come from simulator annotations. Symbolic-action–command labels are constructed through heuristic alignment between planner actions, oracle trajectories, and admissible commands. B.7 Interface Error Categories 

We classify interface errors into the following categories. 

Parser omission. A true observation-supported fact is missing from the parser output. 

Parser hallucination. The parser outputs a fact that is not supported by the observation. Schema validation removes malformed or type-invalid hallucinations before they can update memory. 

Entity mismatch. The parser or grounder selects the wrong object identifier, receptacle, or location among valid candidates. 

Predicate mismatch. The parser uses a domain-valid predicate whose relation type does not match the observation. 

Grounding mismatch. The grounder selects an admissible command whose surface form is executable but does not correspond to the intended symbolic action. 

No safe grounding. The symbolic action contains an unresolved placeholder or context-dependent object that cannot be grounded to an admissible command. In this case, MemPlan executes an admissible observation command when available. The unrealized symbolic action is not treated as executed, and memory is updated only from environment feedback.
