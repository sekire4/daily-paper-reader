## 摘要
日常家庭信息常在对话中交流，却很少被记录下来，导致细节容易被遗忘或记错。我们提出一种语音智能家居助手，它通过记录对话，并从已存储和新采集的语音中检索信息，充当家庭记忆。该助手运行在 Android 平板上，采用模块化架构，其中语音识别、说话人分离、嵌入和语言模型可通过编排层进行配置或替换。设备端唤醒词检测和基于 VAD 的查询采集支持免提交互。录制的音频按可配置的块进行处理，经转录和说话人分离后，转换为带有对话级时间戳的轮次感知段落，并索引到向量存储中。对于记忆查询，检索增强生成流水线会选择关键段落，并利用它们生成答案。该界面支持录音、对话管理以及查看带时间戳的来源。

## Abstract
Everyday household information is often exchanged in conversations but never written down, making details easy to forget or misremember. We present a voice-enabled smart-home assistant that acts as a household memory by recording conversations and retrieving information from stored and newly captured speech. The assistant runs on an Android tablet with a modular architecture in which speech-recognition, diarisation, embedding and language models can be configured or replaced through an orchestration layer. On-device wake-word detection and VAD-based query capture support hands-free interaction. Recorded audio is processed in configurable chunks, transcribed and diarised, converted into turn-aware passages with conversation-level timestamps, and indexed in a vector store. For memory queries, a retrieval-augmented generation pipeline selects key passages and uses them to generate an answer. The interface supports recording, conversation management and inspection of timestamped sources.

### 2. 方法论

#### 2.1 核心思想

- 系统包含两条协同处理路径：
  - **查询路径**：设备端唤醒词检测与 VAD 查询采集 → 远程 ASR 转写 → 向量检索 → 语言模型生成答案。
  - **记忆路径**：长对话按可配置音频块录制 → 转写与说话人分离 → 构建轮次感知段落 → 增量写入会话专属向量索引。
- 通过**编排层**解耦 Android 应用与具体语音、嵌入、语言模型服务，使模型可配置、可替换。

#### 2.2 关键技术与流程

- **设备端交互**：
  - Kotlin/Android 前台 Service 管理音频流程，`AudioRecord` 采集 16-bit PCM，写入线程安全环形缓冲区。
  - 使用 MFCC + 轻量 GRU 唤醒词检测器，激活词为“OK Aura”，TorchScript 本地执行。
  - Silero VAD 在设备端判断语音活动，语音概率阈值 0.5、静音间隔 2 秒判定查询结束；查询音频以 WAV 发送至 ASR。
- **编排与模型服务**：
  - 编排层为 Python FastAPI 服务，使用 Pydantic 校验请求、配置驱动任务路由、OpenAI Python 客户端及适配器封装不同 ASR/LLM 后端。
  - 默认配置：短查询转写 `whisper-large-v3-turbo`，长对话转写与说话人分离 `WhisperX`，答案生成 `gemma-4-31B`，嵌入模型 `all-MiniLM-L6-v2`。
  - 论文称还部署并注册了 Mistral-Small-3.1-24B-Instruct-2503、EuroLLM-9B-Instruct、Apertus-8B-Instruct-2509，以及 MEUSLI-SLAM-ASR、Voxtral-Mini-3B-2507 等替代后端。
- **轮次感知记忆构建**：
  - 将分块内相对时间戳转换为会话级时间戳：
    - \(t^{start}_i = t_c + s_i\)
    - \(t^{end}_i = t_c + e_i\)
    - 其中 \(t_c\) 为块偏移，\(s_i/e_i\) 为块内段边界。
  - 连续分段仅在以下条件同时满足时合并为同一 turn：时间戳有效、说话人标签相同且已知、前段结束到后段开始的间隔在 \(-0.2\) 至 \(1.0\) 秒之间；否则新建 turn。
  - 由于各音频块独立做说话人分离，同一说话人可能获得不同局部标签；系统使用语言模型结合当前 turns、近期上下文和持久说话人注册表进行**说话人标签协调**，并可在保留分段边界处拆分疑似错误合并的 turn。
  - 段落按可配置字符目标长度构建，turn 不拆分，因此单 turn 可能超过目标长度；每段保留说话人文本、首 turn 开始时间、末 turn 结束时间及 turn 数。
- **向量存储与 RAG**：
  - 使用 LanceDB，每个会话对应独立表；段落嵌入与文本、元数据一同存储。
  - 查询时用与该会话关联的嵌入模型编码查询，取 top-k 最近段落，可选距离阈值过滤，并恢复原始摄入顺序以保持对话顺序。
  - 检索段落文本与用户查询进入语言模型上下文；时间戳、turn 数等元数据单独返回平板用于来源展示，不放入语言模型提示。
- **界面与配置**：
  - 支持命名对话、选择音频块时长、录音/停止、实时波形、对话选择与删除、短期问答历史及清除历史。
  - 来源面板显示如“Snippet 1 – Time 00:12”的带时间戳证据。
  - 可配置检索段落数、回答长度、采样参数、语言、嵌入模型、段落大小与切分策略、ASR/语言模型等。
  - 当前原型支持西班牙语和英语。

- 论文展示了一个可运行的原型：通过模块化编排层将 Android 交互层、模型服务和会话记忆流水线分离，使兼容的语音、嵌入和语言模型可在不改变交互逻辑的情况下替换。

### 7. 优点
