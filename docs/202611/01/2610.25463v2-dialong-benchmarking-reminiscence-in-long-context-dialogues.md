## 摘要
基于 Transformer 的大型语言模型（LLM）在长对话上下文中能够多好地保持和回忆记忆？已知 LLM 会在其上下文中遗忘长距离事实信息，然而该领域仍缺乏一个全面的基准来定量评估这些不足。我们提出 DiaLong，一个长上下文对话数据集及配套的记忆任务，用于标准化该领域的评估。它包含 100 段由人类创建并由 LLM 扩展的独特对话，其长度超出了现有数据集中可见的长度。我们选择的记忆任务是事实回忆：将关于一段对话的 40 个候选事实分类为真或假。该任务直接探查模型主动保持和检索信息的能力，是衡量扩展对话上下文中记忆的关键指标。在 DiaLong 上测试最新 LLM 和提出的记忆增强方法时，我们证明仍需开展更多工作才能使 LLM 具备更好的记忆表现。通过增强记忆能力，LLM 可以在扩展对话中更好地保持连贯性、相关性和类人交互。提升这些能力将有助于 LLM 在各种对话场景中满足多样化的用户需求和期望。

## Abstract
How well can transformer-based Large Language Models (LLMs) retain and recall memories in long contexts of dialogue? LLMs are known to forget long-range factual information in their context, yet the field lacks a comprehensive benchmark to quantitatively assess these shortcomings. We present DiaLong, a long-context dialogue dataset and accompanying memory task that standardizes evaluation in this space. It consists of 100 unique conversations created by humans and then augmented with LLMs, extending beyond lengths found in existing datasets. Our selected memory task is fact recall: classify 40 candidate facts about a dialogue as true or false. This task directly probes the model's ability to actively retain and retrieve information, serving as a critical measure of memory within extended conversational contexts. In testing both the latest LLMs and proposed memory enhancements on DiaLong, we demonstrate that more work needs to be done to enable LLMs with better memory performance. By enhancing memory capabilities, LLMs can improve in maintaining coherence, relevance, and human-like interaction over extended conversation. Improving these capabilities will help LLMs fulfill diverse user needs and expectations in various conversational scenarios.

## 1. 核心问题与研究动机

- **核心问题**：基于 Transformer 的 LLM 在长对话上下文中能否有效**保持（retain）与回忆（recall）** 长程事实信息？现有模型普遍存在“遗忘”现象，但领域内缺乏统一、可量化的长对话记忆基准。
- **背景与痛点**：
  - LLM 受限于上下文窗口；超出窗口的 token 会被直接丢弃（OpenAI API 文档明确指出“被移除的消息模型将完全不知晓”）。
  - 仅靠扩展上下文窗口不可行：自注意力二次复杂度导致算力开销巨大，且已有研究表明单纯加长窗口会在长上下文上显著性能退化（如“Lost in the Middle”中的 U 型曲线）。
  - 对话任务的特殊性：对话知识库在推理时持续增长，要求模型巧妙利用从未见过的对话内容，而非仅靠训练集记忆。
  - 现有对话数据集（PersonaChat、DailyDialog、EmpatheticDialogues、MultiSessionChat 等）对话过短，不足以构成“长上下文”，且多数缺少记忆任务与人工验证（见论文 Table 1）。
- **整体含义**：DiaLong 旨在填补“长上下文 + 记忆”双重评估的空白，推动 LLM 在长对话中实现连贯、准确、类人的交互。

## 2. 方法论

### 2.1 核心思想
构建一个**人类原创、LLM 扩展**的超长多会话对话数据集，并配套**事实真假二分类**记忆任务，直接检验模型的主动保持与检索能力。

### 2.2 数据构建流程（Figure 2）
1. **基础数据**：以 MultiSessionChat（MSC，基于 PersonaChat，4 个会话）为起点，保留其“人类撰写 + 多会话结构”的优点。
2. **流畅度增强（Augmentation）**：将每个约 250 token 的 MSC 会话连同精心设计的提示词输入 GPT-4，要求重写对话、增加平滑过渡，同时保留全部关键点、角色人设一致，并将角色名改为 Person 1 / Person 2。
3. **长度扩展（Extension）**：将增强后的每个会话再次输入 GPT-4，要求“尽可能延长”，续写 400–550 词，保持真实自然、人设一致、不重复、不中断。每个会话扩展至约 1,000 token，最终每段对话约 4,000 token（4 会话 × 1,000）。
4. **事实库（Fact Bank）构建**：
   - **真事实**：GPT-4 仅基于对话中**显式陈述**（非推断）生成关于人物的 bullet 列表，并在括号中标注可验证的行号。
   - **假事实**：GPT-4 生成与话题相关但事实错误的陈述（每条也标注行号），且不声明其为假。
   - 行号引用便于人工逐条核验。

### 2.3 记忆任务设计
- 每个会话**随机抽取 40 条候选事实**，与对话上下文拼接，要求模型输出判定为真的候选编号列表（如 `[91, 92, 93]`），无法判断时返回空列表 `[]`。
- 任务配置从 **1 个会话（约 1K token）到 8 个会话（约 8K token）**：
  - 对 4K 上下文模型：1–4 会话为**上下文内**记忆，5–8 会话为**上下文外**记忆。
  - 超出上下文窗口时，**从对话开头截断 token** 直至适配（模拟基础 LLM 的遗忘行为）；对带记忆模块的模型则**顺序输入**对话。
- 支持拼接多个对话以模拟极长对话（如 100 个会话约 100K token），且每个会话的事实唯一可验证。
- 选择真假二分类而非 QA 的理由：判定更明确、直接度量回忆与理解，减少歧义。

### 2.4 数据集统计（Table 2）
- 100 段对话，共约 16K 个问题；平均每段 3.7K token、110.3 条话语、每条话语 34.1 token。
- 平均每段 197.8 条事实（真 117.0 / 假 80.8），4 个会话，每会话平均 936.4 token。

## 3. 实验设计

- **数据集 / 场景**：DiaLong 本身（100 段对话），按会话深度 1–8 逐步加长进行评测。
- **Benchmark 任务**：40 条候选事实的真假分类（准确率、精确率、召回率等）。
- **对比方法与对象**：
  - **基线 LLM**：GPT-3.5、GPT-4（开箱即用）。
  - **记忆增强方案**：SCM4LLMs（Self-Controlled Memory System，Liang et al., 2023），驱动 GPT-3.5，对比有/无记忆模块在 7 个会话深度上的表现。
  - **人类基线**：Amazon Mechanical Turk 工人（附录 F/G），采用与模型近乎相同的任务提示。
  - 附录还提及对开源模型（LLaMa2、Xwin、Tulu2）与私有模型（Claude V2）使用统一基本提示，以及 LLMLingua 提示压缩方案（仅压缩对话上下文至 4,000 token 以内）。
- **质量与人类实验控制**：
  - 每 40 条事实中嵌入 1 条**明显错误且无关的对照事实**作为质量过滤。
  - MTurk 参与者筛选：Master Workers、HIT 通过率 >95%、位于美国、批准 HIT 数 >5,000。
  - 报酬 $3.50/任务（约 $15/小时，高于美国最低工资）。

## 6. 主要结论与发现

1. **上下文内记忆较好，上下文外急剧下降**：GPT-3.5 与 GPT-4 在上下文窗口内表现优异，但对话被挤出窗口后准确率骤降。
2. **GPT-4 具有较好的“知不知”能力**：上下文外仍保持高精确率，说明其瓶颈在**记忆**而非推理/理解，幻觉率相对较低。
3. **记忆增强方案有效但远未完善**：SCM4LLMs 显著减缓了上下文外的性能跌落，且跌落之后保持相对稳定，表明它能保留部分（而非全部）关键事实。
4. **人类不受上下文窗口限制**：MTurk 工人在对话变长时准确率不下降，只是耗时增加（可随时回看全文），说明任务本身可解，LLM 距人类水平仍有差距。
5. **总体判断**：现有 LLM 与记忆增强方案在长对话记忆上仍需大量改进；DiaLong 为这一方向提供了统一评测工具。

## 7. 优点

- **数据双重属性**：人类原创 + LLM 扩展，兼顾真实性与长度；并经过人工复核与 MTurk 外部验证。
- **任务设计直接**：真假二分类比 QA 更明确，能同时度量回忆与理解，且允许模型报告“不确定”（空列表）。
- **可验证性强**：每条事实附带行号引用，便于人工核验；嵌入对照事实作为注意力/质量过滤器。
- **长度可控可扩展**：1–8 会话的分层设计精准区分上下文内/外；支持拼接至 100K token 级别。
- **包含人类基线**：较早期工作更严谨，提供了人机对比参照。
- **贴近真实部署**：超窗时从头截断、记忆模块顺序输入，模拟真实聊天机器人的遗忘行为。

## 8. 不足与局限

- **“长”的程度有限**：主实验对话仅约 4K token，相对现代 128K 级上下文模型并不算真正“长”；更长的拼接场景未在正文系统评测。
- **LLM 生成带来的偏差风险**：扩展对话与真假事实均由 GPT-4 生成，可能存在风格单一、事实分布偏差或假事实质量参差；虽有人工复核，但复核规模与一致性未量化。
- **模型覆盖与结果透明度不足**：正文仅详述少数模型，开源模型与 Claude V2、LLMLingua 的结果缺乏正文数值支撑；仅评测一种记忆增强方案。
- **截断策略较粗糙**：统一从头截断可能不完全反映各模型实际的分块/滑窗机制。
