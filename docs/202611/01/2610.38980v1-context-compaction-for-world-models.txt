# ABSTRACT 

World models let observers explore and interact with generated worlds. Recent work shows that when observers revisit a region, current models often fail to regenerate it consistently. We view this as a context retrieval problem. LLM agents manage context retrieval at two layers of their stack. At the model layer, the KV cache design determines how much context fits in memory. At the agent harness layer, harnesses such as Claude Code pick the context sent to the LLM. Prior work on world models has mostly focused only on the model layer. In this paper, we make three contributions. First, we build a benchmark to measure world model context retrieval. It generates new worlds for every episode, preventing a model from recalling rooms using training data. It also separates context retrieval from guesses based on nearby frames. Second, we build an agent harness that performs context compaction for world models, which to our knowledge no prior work has studied. Third, we use our benchmark to study four world model designs. Context compaction lets our world models retrieve rooms up to 4 times beyond their context window without retraining. However, world models with sliding-window attention lose most of their context retrieval when dreaming. Therefore, a dreaming world agent benefits more from extending the reach of its world model using context compaction than switching to sliding window attention at the model layer. 

# 1 INTRODUCTION 

World models are systems that can predict a given envi-ronment from actions and observations. World models are useful in the realm of robotics and physical AI because they allow am RL agent to learn from a world model’s imagined environment and then use that training to act in the envi-ronment (Ha & Schmidhuber, 2018; Hafner et al., 2020). In addition to agents, people can also explore and play in-side the vast and imaginative worlds constructed by world models (Bruce et al., 2024) making way for a plethora of opportunities in the entertainment and video game indus-try (Team et al., 2026). When an observer explores and interacts with a world model’s generated world for an extended period of time, they often return to places they visited earlier on in their trajectory. A realistic world model is expected to generate the same output for a given place on a revisit as it did on the first visit. Unfortunately, two recent evaluations (Lian et al., 2025; Ye et al., 2026) demonstrate that world models do not currently maintain good consistency when observers revisit the same area in the generated world. We view this as a context retrieval problem, similar to how LLMs are expected to maintain the context of a user’s con-

Context in LLMs is typically managed at two layers of the inference stack: the model layer and the agent harness layer. At the model layer, there is a subtle tradeoff between the size of the KV cache and an LLM’s context retrieval. If an LLM designer reduces the number of bytes of KV cache required per LLM token, it enables a fixed amount of GPU memory to fit a longer context. On the other hand, reducing the size of the KV cache per token can also reduce how accurately an LLM retrieves previous tokens in its context. There are many optimizations that reduce the size of an LLM’s KV cache. Multi-query attention (Shazeer, 2019) and Grouped-query attention (Ainslie et al., 2023) share an LLM’s keys and values across multiple attention heads. A Decoder-Decoder model (DD) (Sun et al., 2024) com-putes an LLM’s keys and values once for a token and shares them across all of the LLM’s upper layers. Sliding Win-dow Attention (SWA) (Beltagy et al., 2020) lets each of an LLM’s tokens only attend to a fixed window of tokens preceding it. In addition to the KV cache, some model ar-chitectures also focus on reducing the compute necessary for the prefill stage in inference. For example, recently, the Causal Encoder-Decoder (CED) introduced by DeepSeek-V4.1-Flash (DeepSeek-AI, 2026) lets an LLM project the keys and values for each upper layer from the hidden state of the middle layer. At the agent harness layer, a harness tries to manage the context of an LLM through a process called context com-paction (Tirmazi et al., 2026). Most commonly, such as in Claude Code and OpenCode, context compaction involves creating an LLM-generated summary of the agent’s ses-sion (Tirmazi et al., 2026). More recently, Codex with GPT-6 Astra can experimentally keep notes across context windows in place of a single summary. Earlier context win-dows stay searchable, allowing the model to retrieve details from previous messages and tool outputs when it needs them (OpenAI, 2026). Unlike LLMs, the problem of context retrieval in world models has not been adequately studied. The vast majority of prior work is limited in scope and focuses primarily on the model layer. Prior work explores how a world model’s architecture or its KV cache can be modified for better con-text retrieval. WorldMem (Xiao et al., 2025) is a video world model that stores previously generated frames into a memory bank and retrieves them back into its diffusion trans-former blocks during inference. Similarly, WorldPack (Os-hima et al., 2026) attempts to pack previously generated frames into fewer tokens allowing more frames to be fit into the context window during inference. WorldKV (Yi et al., 2026) keeps and retrieve KV-cache chunks that are evicted by a sliding window. Finally, CaR (Peng et al., 2026) learns a compression network to improve context retrieval. All of the above papers evaluate their design by checking whether a frame that an observer revisits looks similar to the frame that the world model generated on the observer’s original visit. However, this method of evaluating the model design does not completely answer the isolated question of whether a world model is good at context retrieval . When a world model generates a frame on an observer’s revisit that is similar to the original frame, it can be due to three distinct reasons. 1. The world model retrieved the original frame from its 

context .2. The world model reconstructed a frame similar to the original frame from its original training data that the model memorized. 3. The world model inferred a frame similar to the origi-nal frame using context clues from other recent frames that are in its context. In this paper, we call the latter two cases context recon-struction and context inference respectively, to distinguish them from context retrieval . Since most evaluations of prior work score only the output of the world model, they can-not separate the three cases. The closest prior work to our approach is a recent study that replaces the memory that a world model reads with memory from elsewhere (such as another scene) and measures how much of the benefit of memory depends on its content (Tiwari et al., 2026). However, they evaluate existing world models on existing datasets and do not control whether those scenes appear in the training data. Therefore, the study still cannot rule out context reconstruction. When it comes to the agent harness layer, we are not aware of any prior work that uses an agent harness to manage the context of a world model similar to how existing LLM har-nesses such as Claude Code and Codex manage the context of an LLM. The closest prior works we were able to find are WorldPlay (Sun et al., 2025) and Echo-Memory (King et al., 2026). While WorldPlay and the context-based vari-ants of Echo-Memory use a retriever outside of the model to choose frames for a world model, they require the world models to be trained using the frames chosen by the external retriever. In other words, they are not agent harness layer optimizations in the same sense as context compaction in LLM agents. Claude Code, for example, manages the con-text of an existing Anthropic LLM such as Claude Opus without having to change the LLM’s weights or re-train it. World in World (Song et al., 2026) retrieves earlier gener-ated states for a frozen world model without training, but it does so inside the model, by restoring their KV caches and by rescaling attention during generation. Our agent harness leaves the computation of the world model unchanged and only decides which context the world model reads. In this paper, we conduct a thorough study of the problem of context retrieval in world models. We train research world models of about 14M parameters that generate video game rooms and then use them to investigate how an array of systems decisions across the model layer and agent harness layer impact context retrieval. Concretely, we make the following three contributions. 1. Create a benchmark for world models that specifically evaluates a world model’s context retrieval. Unlike prior work, our benchmark separates context retrieval from context reconstruction and context inference. 2. Introduce an agent harness for world models that can perform context compaction. Our agent harness man-ages the context of an underlying world model without having to retrain or modify its weights. Our approach is similar to how agent harnesses for LLMs such as Claude Code, Codex, and OpenCode work. 3. Conduct an evaluation of the effect of systems de-cisions at the model layer and agent harness layer (as well as their combinations) on context retrieval in world models, both when the world model reads true frames and when it dreams. We vary the model architecture and the agent harness in-dependently and measure context retrieval on each config-uration. Note that the two layers interact with each other and both play a part in a world model’s ability to do accu-rate context retrieval. For example, a good context com-paction algorithm at the agent harness layer can extend the reach of a world model’s context retrieval far beyond the model’s context window. Similarly, the design of the KV cache at the model layer significantly impacts the size of the model’s context window assuming the available memory is fixed. Figure 1 shows both effects. In practice, a world agent dreams, i.e., its world model predicts new frames from frames that it generated earlier. Once our world agents dream, world models whose lower blocks use SWA lose almost all of their context retrieval, with or without context compaction, as we show in the middle plot of Figure 1.

Let MD be any decoder-only Transformer. We use N to denote the number of transformer blocks in MD. We use 

D to denote the width of MD’s embedding vectors, i.e., each token is mapped to a vector of length D. We use ρ to denote the number of bytes used to store each floating point value in MD. ρ depends on the precision used to store MD’s KV cache. Finally, we use h and dh to denote the number of attention heads and the width of each attention head in 

MD respectively. Note that h · dh = D. Treating D as a constant, the compute cost of generating each new token after L tokens in MD is O(N L 2) since the compute cost of each individual transformer block in MD is O(L2).We can use a Key-Value (KV) cache to store the keys and values of each processed token in each transformer block in MD. Using a KV cache reduces the compute cost of generating each new token after L tokens in MD to O(N L ).

MD’s KV cache needs to store 2N LDρ bytes. If we use Sliding Window Attention (SWA) with a window size of 

w tokens then the compute cost of an SWA transformer block is O(w) and O(w2) with and without a KV cache respectively. The KV cache only needs to store 2wDρ bytes for an SWA transformer block. We derive these costs along with a more rigorous treatment of model architectures in Appendix A.

# 3 WORLD RETRIEVAL 

In this section, we introduce a benchmark that evaluates a world model’s context retrieval capabilities in a way that de-couples them from the world model’s context reconstruction and context inference capabilities, as discussed in § 1. 

3.1 Benchmark World 

Our world consists of an 8 × 8 grid of video game rooms. Each room in the world is a 16 × 16 grid of tiles. There are eight types of tiles in the world such as a rock tile and a water tile. The borders of the room hold walls and a door for each neighboring room. Consequently, each border can have at most one door tile and the rest of the tiles of the border are wall tiles. We use public domain sprites (Drummyfish, 2018) for the tiles. We uniformly randomly choose a room in the world and place the observer in the room. The observer is placed in the center of the current room and an action in the Observer

world consists of the observer moving through a door to a neighboring room. Consequently, each frame in our world is a given video game room. Similarly, each step in our world is at the granularity of a room transition. Please refer to Figure 2. In our benchmark, we generate episodes (for both training and evaluation) by making the observer navigate the benchmark world using a random walk. At any given step, we uniformly randomly choose one of the doors of the current room and make the observer go through that door. However, we exclude the door the observer just entered through from the set of doors we uniformly randomly choose from. In case there is a dead end, i.e., when there is no door other than the door the observer entered from, we make the observer return through the same door. Using our approach, the observer frequently revisits rooms without the need for scripted loops. The length of the walk between an observer’s original visit and the observer’s revisit to the same room ranges from a few steps to the length of the benchmark’s episode. We denote this length as the gap of the revisit for the remainder of this paper. We group room revisits by their gap into the following seven bins: 1–7, 8–15, 16–31, 32–63, 64–127, 128–255, and 256–511 steps. Note that we incrementally double the interval of the gap bins. 

3.2 World Model 

Our benchmark world and its evaluation can be used with any world model that can ingest our video game rooms tokenized in any form and predict the next room. In this section, we provide an overview of the world models we specifically train and evaluate on. For our world models, we use 8 tokens to encode frames and 1 token to encode the observer’s action. We tokenize a video world room in the following way. Each of the 8 tokens corresponds to a type of tile, e.g., the water tile is assigned a token. Each token is computed from a 16 × 16 boolean map where a 

1 at position (x, y ) corresponds to the water tile being at tile position (x, y ) in the video game room’s 16 × 16 tile grid. The action token simply encodes the direction of the door the observer wants to transition to. Note that there is at most 1 door for each of the four directions in a room. Consequently, our world models are sent 9 tokens for each step. Our world models generally have a context window of 

128 steps. We train and evaluate on four world models. In the notation of § 2, all four of our world models have N = 8 transformer blocks with h = 6 attention heads. Each attention head has width dh = 64 . All four world models also all have an embedding width of D = 384 . We store the KV cache in float32, so we use ρ = 4 bytes per floating point value for all cache sizes. The first model uses the Decoder-only archi-tecture, MD, as described in § 2. The second model uses the Decoder-Decoder architecture, MDD . The third model uses a Causal Encoder-Decoder architecture, which we described using MCED with ordinary lower transformer blocks. Our fourth world model is a variant of MCED that uses SWA for its lower blocks similar to MDD ’s lower blocks. We will refer to this variant of MCED as MCED -SWA . Figure 3 illus-trates the design of the four world models. Note that all four models have roughly 14M parameters. Specifically, MD has 14,352,000 parameters. Both MCED and MCED -SWA have 14,352,768 parameters. Finally, MDD has 13,465,728 pa-rameters. For simplicity, we use MD, MCED , MCED -SWA ,and MDD interchangeably with Decoder-only, CED, CED-SWA, and DD in the rest of this paper. 

3.3 Context Reconstruction 

Context reconstruction occurs if a world model has observed a frame in our world in its training data. For foundation world models that are typically pretrained on a large corpus of data from the internet and other sources, we prevent this by ensuring that the video game rooms in our benchmark world are randomly generated at benchmark time. For world models specifically trained for our benchmark world, we ensure that separate pseudorandom seeds are used for train-ing and evaluation. Training on pseudorandom seeds of our benchmark world that are not the same as the evalua-tion seeds can certainly teach a world model general terrain statistics of the world such as the typical size of a patch of water. However, it cannot teach a world model the specific layout of a given room generated during evaluation. This property ensures that to predict a revisited room with a high accuracy upon a revisit, a world model cannot successfully rely on context reconstruction from its training data. 

3.4 Context Inference 

Context inference occurs if a world model is able to accu-rately predict a revisited frame without actually retrieving the original visit frame from its context. As we discussed earlier, this can be due to the model using context clues from other recent frames that are in its context. To separate con-text retrieval from context inference, we score each revisit in two runs. In the first run, the world model reads its normal context window. In the second run, we keep only the 5 most recent steps of the benchmark world in the context window and replace all earlier steps with the same number of steps from another benchmark world. We call the second run a 

shuffled run and refer to its context window as a shuffled context window. Note that the reason we chose to keep the 5 most recent steps (as opposed to any other number of recent steps) is because 

5 steps is the receptive field of the SWA transformer blocks in two of the model architectures, CED-SWA and DD, that we describe in § 3.2. In these two model architectures, each of the four lower blocks attends over the 2 most recent steps. The information from earlier steps therefore can move at most one step forward through each lower block. Hence the output of the final lower block depends on the five most recent steps only. If we keep the 5 most recent steps, we can prevent the input of the lower transformer blocks that rely on SWA from changing. The shuffled run therefore changes only the history that a model reads through attention beyond its local window. We keep the same 5 steps for every model architecture in the paper, therefore, we score all model architectures on the same shuffled contexts. Let αoc be the accuracy of a world model on a revisited room in our benchmark world when the world model is provided the original context window. Let αsc be the accuracy of the world model when it is provided a shuffled context window. We define the context retrieval gain , ∆cr , to be 

∆cr = αoc − αsc .For any room that was visited earlier than 5 steps ago, if a world model is relying on context retrieval for its prediction, it will have a much lower αsc as compared to αoc . This is because the shuffled context will not contain the originally visited frame that the world model is using to predict the revisited frame. Therefore, the world model’s context re-trieval gain will be large. On the other hand, if the world model is relying primarily on context inference, the differ-ence between αoc and αsc will not be as stark, resulting in a lower context retrieval gain. # 4 WORLD AGENTS 

Popular LLM agents such as Claude Code and Codex are responsible for managing the context of their underlying LLM (Tirmazi et al., 2026). In the same way, we build an agent harness for our world models to manage context. Note that similar to LLM agent harnesses, our harness does not require the underlying world model to be retrained. Also like LLM agent harnesses, our harness is independent of the underlying model and can be used interchangeably with all four model designs that we test on and, in fact, should be easy to adapt for any world model that can work with our benchmark. Analogous to how an LLM along with the harness is called an LLM agent, we refer to a world model together with its harness as a world agent .Our agent harness is situated at the interface between a world model and an observer. We record every frame and action of an observer’s session with the model in the harness.

4.1 Compacted World 

Recall that an observer can choose one of four available actions in a given room. The observer can take a door at any of the room’s four borders to go into a neighboring room. In the agent harness, we can build the compacted context of the session using only the observers actions. After an action, the observer moves by one room in our room grid. Therefore, we track the position of the observer in the harness without storing any information about the room’s tiles. If the observer takes two steps at the same position, we only need to keep the most recent frame of the visited room in the context. Note that the harness cannot simply send these frames as a list since our models trained only on raw steps, in which every step moves to an adjacent room. The compacted context therefore has to look like a real walk. Our agent harness plans the shortest walk that passes through every visited room and ends at the current one. This is an instance of the traveling salesman problem. Since the traveling salesman problem is NP-hard in general, our harness uses the Christofides approximation (Christofides, 2022) to plan a short tour through every visited room and removes the longest edge of the tour to obtain a walk. Each step of the walk carries the newest frame of its room and the action toward the next room. For exam-ple, suppose the observer’s trajectory in a 4 room world is A, B, A, B, C, B, C, D, C, D . The compacted context is the walk A, B, C, D . When the visited rooms do not lie on a single path, the walk must pass through some rooms more than once. If room B connects to rooms A, C, and D, for example, the walk is A, B, C, B, D .

4.2 Compaction Policies 

Our agent harness can follow one of two policies. Under 

compact every step , the harness compacts the full context before every call to the world model. Under compact when full , which is similar to the policy of coding agents such as Claude Code 1, the harness appends raw steps until the context holds 128 steps, compacts it, and then appends raw steps again. During our experiments with the compact when full policy, we observed that the agent harness compacted about once every 50 steps. We also observed that the context sent to the world model held about 103 steps on average.

5.1 Experimental Setting 

We train our world models on 5000 generated episodes of our benchmark world. Each episode is 512 steps. We evalu-ate our models on 400 separate episodes. Each training win-dow spans 128 steps. We train with 3 random seeds, 42 , 43 ,and 44 , and conduct 20K optimizer updates using batch size 

4. We give each world model identical training windows in the same order for each seed. We use AdamW (Loshchilov & Hutter, 2019) for optimization with a peak learning rate of 3 × 10 −4, β1 = 0 .9, β2 = 0 .95 , a weight decay of 0.1,gradient norm clipping at 1.0, and a one-cycle schedule. During each evaluation, we sample 40 revisits from each of our 7 gap bins. We score every world model and every context that the agent harness sends on the same revisits. In our figures and results, we report the mean over our 3 seeds and error bars are one population standard deviation.

5.3 Model Layer 

In this section, we show that when designing the KV cache at the model layer, world model designers face a tradeoff between how much context fits in a given amount of memory and how accurately the world model retrieves information from that context. We show both sides of this tradeoff in Figures 6 and 7. In Figure 6, we fix the memory budget of the world model’s KV cache to 2,304 vectors. This memory budget is enough for us to store all 128 steps in the context window if we are using DD, since we only need to store 2 vectors per token for DD. However, since we need to store 16 vectors per token for Decoder-only and CED, we cannot store more than 16 steps in their context window. Similarly, since we need to store 8 vectors per token for CED-SWA, we cannot store more than 32 steps in its context window under our memory budget. Please refer to Appendix B.4 for more details. For our constrained memory budget experiment, we train bounded versions of Decoder-only and CED in which their transformer blocks attend only to the 16 most recent steps. Similarly, we train a bounded version of CED-SWA, where the upper blocks attend only to the 32 most recent steps. We train these bounded versions of our world models from scratch, with identical training data, seeds, and number of updates as the existing (unbounded) versions of our world models. An alternative here would have been to shorten the context windows of existing versions of our world models only at inference time to fit the memory budget. However, this approach would make the existing versions of the world models read shorter context windows compared to the ones they were trained on. This confounds the effect of smaller memory with the effect of the mismatch between the context lengths the world model trained on and the ones it is evalu-ated on making it difficult to isolate these two in our results. Note that we do not need to train a bounded version of DD because the unbounded 128-step context window version of DD already fits within our memory budget. Therefore, we use the same version of our DD world model in both Figure 6 and Figure 7. Using the same memory budget, DD is able to retrieve rooms with revisit gaps of up to 127 steps. However, the context retrieval gain of Decoder-only, CED, and CED-SWA declines significantly as soon as the revisit gap becomes larger than their context window. In other words, when memory is the constraint, a smaller KV cache per token lets a world model retrieve rooms much further back in a world agent exploration session. 5.4 Dreaming 

The process of dreaming occurs when we make a world model predict new frames based on frames previously pre-dicted by the world model (Ha & Schmidhuber, 2018; Hafner et al., 2020). Without dreaming, we include the ground truth frames from our benchmark world in the world model’s context window and only use the world model to predict the current frame. In other words, dreaming implies we are allowing the context window of a world model to in-clude frames from the world model’s own output. Dreaming is often a more realistic setting for world agents in the same way that LLM agents typically include their own outputs

Consequently, the keys and values in the KV cache, which were computed at the old positions, no longer match their current steps. This forces the agent harness to prefill the entire window again. In the compact every step policy, we plan a new walk before every step. Since each new walk can visit the rooms in a different order, the context changes from one step to the next forcing us to prefill the compacted context on every step of the session. The inference latency is lower than with the raw context window since the compacted context itself is smaller. In the compact when full policy, we only plan a walk when the context is full, which happens about once every 50 steps. Otherwise, we just decode a step from the KV cache. Hence we only prefill on 8 of the session’s 512 steps. Consequently, compact when full has the lowest agent latency. CED, CED-SWA, and DD prefill about 1.5 times faster than Decoder-only, since their upper blocks only process the most recent step. # 6 RELATED WORK 

Laird & Clark (2026) compare memory mechanisms in transformer world models on a state recall task. Our paper additionally matches parameter counts within 7% for our evaluated world models and measures context retrieval gain using a shuffled run. R2M-Bench (Gu et al., 2026) compares each revisit with pairs from the same rollout that revisit nothing at a matched gap. Its controls, however, still act on the output of the world model. Our benchmark acts on the context instead. It rules out context reconstruction by generating a new world for every episode and separates context retrieval from context inference with the shuffled run. At the model layer, we compare designs that share keys and values across blocks. Other work reduces the memory of the KV cache in different ways. StreamingLLM (Xiao et al., 2024) keeps only a few initial tokens and a window of recent tokens. H2O (Zhang et al., 2023) evicts all but the most important and the most recent tokens. KIVI (Liu et al., 2024) quantizes keys and values to 2 bits. Since these techniques act on the KV cache of a given design, they can in principle be combined with the designs we compare. At the agent harness layer, MemGPT (Packer et al., 2023) manages the context of an LLM by moving data between its context window and an external memory, similar to how an operating system manages memory. Tirmazi et al. (2026) formalize context compaction as the step in an agent loop that shrinks the state of the agent to fit the context window of the model. In language, what a compacted context preserves is hard to measure. In our benchmark world, however, we know that a compacted context preserves every visited room, which lets us measure context retrieval through a compacted context directly. 

# 7 LIMITATIONS AND CONCLUSION 

Our work has three main limitations. First, we evaluate a single benchmark world at a single model scale with three training seeds. Our world models also never train on com-pacted contexts. Second, our world agents only dream on revisits and only for loops of up to 128 steps. Therefore, we do not yet know how dreaming affects context retrieval beyond the raw context window. Third, the rooms of our benchmark world are laid out on a predetermined grid which simplifies our context compaction algorithm. Consequently, our results show context compaction in its ideal case. In world models where the camera moves continuously, an agent harness would first have to decide which frames show the same place. Context retrieval in world models depends on both layers of the inference stack. At the model layer, a smaller KV cache per token reduces context retrieval at a fixed context length but allows for a longer context at a fixed memory budget. At the agent harness layer, context compaction lets a world model retrieve rooms far beyond its context window without retraining. However, once a world agent dreams, only the world models whose lower blocks attend over the full con-text instead of relying only on SWA show consistent context retrieval, with or without context compaction. Therefore, it is often easier for a world agent to extend the reach of its world model with context compaction at the agent harness layer as opposed to sacrificing full attention in the lower blocks of the world model. This section contains a set of fun deep dives across multiple aspects of our evaluation. 

B.1 Agent Harness Layer 

In Figure 5 of § 5.2, we showed the context retrieval gain for all four world model designs only over the gap bins that are larger than 128 steps, i.e., larger than the context window length of the models. In this section, we look at the context retrieval gain across all gap bins in detail. In Figure 10, we show the gain of each world model for all our gap bins both when we send the raw context window directly and when we conduct context compaction at each step. When we send the raw context window, the gain of all our world model designs drops to near zero as soon as the revisit gap is larger than the model’s context window length of 128 steps. However, when we do context compaction, the gain stays roughly flat across all gap bins. Note that at gaps of 8 to 127 steps, the context compaction version almost always has a lower score compared to the raw context window for all our world models. We suspect that part of this difference comes from the shuffled run. The shuffled run keeps the five most recent steps of the context, and a compacted walk can pass through the revisited room within its last five steps. In that case, the shuffled context still contains the revisited room, which lowers the context retrieval gain of the compacted context. 

B.2 Truncated Contexts 

As mentioned in § 5.2, we want to rule out that the gains of context compaction come from simply sending a shorter context to the world model. In Figure 11, we compare con-text compaction with the alternative of simply truncating the context by keeping the most recent steps. Beyond 128 steps, the context retrieval gain of using a truncated context drops to near zero similar to using no context compaction. Therefore, a shorter context alone is not the reason for con-text compaction improving a world model’s long context retrieval beyond its context window length.

B.4 Memory Budget 

In Figure 6 in § 5.3, we use a fixed memory budget of 

2, 304 vectors for the KV cache of all four of our world model designs. Note that each vector has 384 elements each of which is a 32-bit floating point value. In this section, we discuss the reasoning behind our memory budget. We first show that to maintain a context window size of 128 steps, our most memory efficient world model design, DD, requires 2, 304 vectors. As mentioned in § 5.3, we then show that the same memory budget results in a context window length of only 16 steps for Decoder-only and CED and a context window length of 32 steps for CED-SWA. Recall from § 3.2 that each step of our benchmark world is 9 tokens, i.e., 8 tokens for the tiles of a room and 1 token for the action. In DD, we store a shared key vector and a shared value vector per token for its upper blocks, i.e., 2 vectors per token. Therefore, a context window of 128 steps needs 

2 × 9 × 128 = 2 ,304 vectors in DD. Since each vector has 

D = 384 elements stored as 32-bit floating point values, this is about 3.5 MB. When using Decoder-only and CED, we have to store a key vector and a value vector per token in each of their 8 transformer blocks, i.e., 16 vectors per token. Hence, their context window is 2,304 /(16 × 9) = 16 

steps. With CED-SWA, we have to store a key vector and a value vector per token in each of its 4 upper blocks, i.e., 8 vectors per token. This results in a context window size of 

2,304 /(8 × 9) = 32 steps. Note that we also need to store 

4 × 2 × 9 = 72 vectors for the 4 lower blocks of CED-SWA and DD that use SWA with 2-step windows. However, since the number of vectors needed by SWA blocks do not grow with the context, we do not count them toward the budget for simplicity. They add only a fixed cost of about 3.125% to the total memory of CED-SWA and DD.
