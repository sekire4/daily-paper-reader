## 摘要
基于图的检索增强生成（GraphRAG）通过将语料组织成图并沿其结构进行检索来回答多跳问题。现有检索方法存在两点局限。基于扩散和相似度的方法沿固定边权重或依据与问题的相似度扩展检索，但未能消解问题中的隐含实体指代，导致相关性误差在逐跳过程中累积。相比之下，基于探索的方法让大语言模型对下一跳进行推理，但每一跳都需要单独生成，推理成本很高。我们观察到，大语言模型在生成任何 token 之前，就能从检索到的段落和多跳问题中消解隐含实体指代。进一步分析识别出一小组注意力头，称为“寻址头”（addressing heads），它们能在单次前向传播中跨多跳捕捉这一能力。基于这一发现，我们提出 HyperAddress，在带描述标签的超图上运行个性化 PageRank，利用寻址头确定重启分布和转移权重，从而在查询时无需任何生成即可引导多跳检索。在 MuSiQue、2WikiMultiHopQA 和 HotpotQA 上，HyperAddress 平均比最强基线高出 3.5 个 Recall@5 点和 7.4 个 All@5 点，且提升幅度随跳数增加而增大。其回答速度提升一倍以上，索引构建成本仅为一半。

## Abstract
Graph-based retrieval-augmented generation (GraphRAG) answers multi-hop questions by organizing a corpus into a graph and retrieving along its structure. Existing retrieval methods face two limitations. Diffusion- and similarity-based methods expand retrieval along fixed edge weights or by similarity to the question, without resolving its implicit entity references, allowing relevance errors to accumulate across hops. In contrast, exploration-based methods let an LLM reason about the next hop, but require a separate generation at each hop, leading to high inference costs. We observe that an LLM can resolve implicit entity references from retrieved passages and a multi-hop question before generating any tokens. Further analysis identifies a small set of attention heads, termed addressing heads, that capture this capability across multiple hops in a single forward pass. Building on this finding, we propose HyperAddress, which runs Personalized PageRank on a description-labelled hypergraph, using addressing heads to determine the restart distribution and transition weights, thereby guiding multi-hop retrieval without any generation at query time. On MuSiQue, 2WikiMultiHopQA, and HotpotQA, HyperAddress outperforms the strongest baseline by 3.5 points of Recall@5 and 7.4 points of All@5 on average, with gains that grow with the number of hops. It answers more than twice as fast and builds its index at half the cost.

## 1. 核心问题与研究动机

- **背景**：多跳问答中，问题往往通过“桥接实体”间接指向关键证据（例如问“《Princeps Pastorum》的作者葬于何处”，需先识别作者是 John XXIII，再检索其传记）。标准稠密检索以整句问题与段落比对相似度，几乎无法召回第二跳证据。
- **GraphRAG 的两类现有范式及其局限**：
  - **扩散/相似度方法**（HippoRAG 2、LinearRAG、PropRAG 等）：沿固定边权或问题相似度扩展检索，**不消解问题中的隐式实体指代**，无关实体持续向外扩散，相关性误差逐跳累积。
  - **探索式方法**（IRCoT、Self-Ask、Think-on-Graph 等）：由 LLM 逐跳生成推理与下一跳实体，**每跳都需要一次生成**，上下文随跳数增长、推理成本高；且通常在扁平文本上推理，未显式利用图结构。
- **核心问题**：能否以低计算成本，同时结合**图结构信息**与**问题语义**完成多跳检索？
- **关键观察（动机基石）**：LLM 在读取检索段落与多跳问题后、**生成任何 token 之前**，就已能消解隐式实体指代；该能力集中于少数中层注意力头（“寻址头”），且一次前向即可覆盖多跳。

## 2. 方法论：HyperAddress

### 2.1 核心思想

- **解耦语义引导与结构探索**：语义理解由 LLM 的注意力（单次前向、零生成）提供，关系探索由图上的随机游走（PPR）完成，查询时**完全不生成 token**。

### 2.2 三条实证观察（第 3 节）

- **观察 1：稀疏寻址头**。在 Qwen3-4B 的 1,152 个头中，仅 8 个头（均位于第 18–22 层 / 共 36 层）承担寻址功能；对它们做均值消融后，探针准确率从 76.5% 降至 48.5%，桥接被描述的 MuSiQue 两跳题从 40.1% 降至 19.7%（随机头仅损失 ≤4 点）。
- **观察 2：词级多跳寻址**。单次前向即可为多跳桥接分别打分，每个桥接在其**自身描述所在词位**得分最高（而非最后 token 处）。若只在最后 token 读取，第二/三跳桥接的 top-5 命中率分别从 85.3%→52.3%、85.0%→36.2%。
- **观察 3：上下文依赖的寻址**。将问题或段落分别离线编码后，寻址头的 MRR 大幅下降（两者都离线时从 .734 降至 .332，接近随机 .169）；因此必须在**查询时联合阅读**，索引中只存描述标签。

### 2.3 离线：描述标签超图（Description-Labelled Hypergraph）

- **定义**：$\mathcal{H}=(\mathcal{P},\mathcal{E},w,D)$，段落为顶点，实体为超边（包含所有提及该实体的段落），关联 $(p,e)$ 带权重 $w(p,e)=|e|^{-1/2}$ 与标签 $D(p,e)$（段落中对实体的 1–3 条描述，措辞模拟问题的指代方式）。
- **构造**：LLM 为每段写“地址簿”（实体规范名、提及位置、描述），另含段落事实、段落可回答的问题等“内容项”；别名归并成超边。**新增段落只需处理自身并接入已有超边**，支持非参数化持续学习。
- **设计要点**：与知识图谱相反——段落为节点、实体为超边、关系存于关联标签中，既让初始重启能匹配描述，又让在线阅读在原文上识别实体。

### 2.4 在线：注意力引导的 PageRank（Algorithm 1）

- **游走**：在段落与超边间交替转移，转移概率正比于 $w(p,e)$，即带边依赖顶点权重的超图随机游走；稳态满足
  $$\pi=(1-d)\,r+d\,T_w^{\top}\pi,\quad d=0.85,\ \text{30 次迭代}$$
- **寻址打分**：每轮取 top-$m$（$m$=10）段落 + 问题做**一次前向**（在第 22 层后即停），对问题未命名的候选实体计算指针分数
  $$s_h(t,e)=\frac{\sum_{j\in M_e}\alpha_h(t,j)W_h^O v_h(j)}{\sum_j \alpha_h(t,j)W_h^O v_h(j)}$$
  取 $\max_t$、z-normalize 后跨 8 个头平均得 $\rho_q(e)$；限制在段落 $p$ 内提及上得关联分数 $a_q(p,e)$。
- **引导重启**（式 3）：top-$n$（$n$=5）候选获得 $\lambda=0.02$ 的重启份额，均分给其超边与提及它的段落。
- **引导转移**（式 4）：$w_q(p,e)=w(p,e)\exp(\beta\,a_q(p,e))$，$\beta=1$，双向重加权；段落保留最近一轮的关联分数。
- **轮次与重写**：$R=2$ 轮；轮间用指针分数 + 标签相似度选出最可能的实体，把问题中对应描述片段替换为实体名（相似度阈值 0.7），新问题的重启以权重 2 叠加。
- **最终排序**：$z(\log\pi)+0.5\,z(\text{dense similarity})$ 融合。
