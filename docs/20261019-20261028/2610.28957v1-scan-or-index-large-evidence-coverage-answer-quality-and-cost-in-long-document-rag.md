## 摘要
扫描长文档中的每个段落看似全面，但它是否能保留更多有用证据或产生更好的答案？我们比较了11种检索配置，涵盖词法检索与稠密检索、混合重排序，以及使用Jev、OpenAI Decisions和Cloudflare Clef的全文扫描。评估使用396个QASPER问题和来自八本完整教材的80个问题，采用共同段落、五段落上限和固定答案生成器。在书籍上，Hybrid + Jev取得观测到的最高证据覆盖率（94.1%），相比之下Jev全文扫描为88.7%，OpenAI稠密检索为81.3%。全文扫描最初检查每个段落，但后续缩减步骤可能丢弃相关证据。更高的证据覆盖率也并不总能产生更好的答案：在检索方法中，Hybrid + Decisions取得观测到的最高书籍答案准确率（0.892），尽管其恢复的参考证据较少。在所测试部署下，全文扫描在书籍上带来显著更高的延迟，而随着查询累积，可复用稠密检索的预计API成本低于付费的基于决策的方法。大多数QASPER文章已经适合混合候选池，限制了扫描的收益。这些结果凸显了证据保留、答案质量和复用成本作为选择长文档检索策略的互补标准。

## Abstract
Scanning every passage in a long document seems thorough, but does it preserve more useful evidence or produce better answers? We compare 11 retrieval configurations spanning lexical and dense search, hybrid reranking, and full-document scanning with Jev, OpenAI Decisions, and Cloudflare Clef. Our evaluation uses 396 QASPER questions and 80 questions from eight complete textbooks, with common passages, a five-passage limit, and a fixed answer generator. On books, Hybrid + Jev achieves the highest observed evidence coverage (94.1%), compared with 88.7% for Jev full scan and 81.3\% for OpenAI dense retrieval. Full scans examine every passage initially, yet later reduction steps can discard relevant evidence. Higher evidence coverage also does not consistently produce better answers: Hybrid + Decisions achieves the highest observed book Answer Accuracy among retrieval methods (0.892), despite recovering less reference evidence. Full scanning incurs substantially higher latency on books under the tested deployments, while reusable dense retrieval has lower projected API cost than paid decision-based methods as queries accumulate. Most QASPER articles already fit within the hybrid candidate pool, limiting the benefit of scanning. These results highlight evidence retention, answer quality, and reuse cost as complementary criteria for choosing a long-document retrieval strategy.

# 《Scan or Index? 长文档 RAG 中的证据覆盖率、答案质量与成本》论文总结

## 1. 核心问题与研究动机

- **背景**：检索增强生成（RAG）需要先从长文档中找出少量有用段落，再交给语言模型生成答案。长文档（如整本教材）动辄数百页、上千段落，检索策略直接决定“能拿到多少证据”和“每个问题要重复多少计算”。
- **核心问题**：面对一篇长文档，是**逐段全文扫描**（full scan，看似更全面），还是**建立可复用索引后再检索**（index + rerank）？全文扫描是否真的保留更多有用证据、产生更好答案，代价又有多大？
- **关键张力**：
  - 稠密检索需预先编码段落，但表示可跨查询复用，准备成本被摊薄；
  - 基于决策模型（Jev、OpenAI Decisions、Cloudflare Clef）的选择器可对候选段落做重排，也可逐段扫描；后者免去预计算嵌入，但长文档必须分窗处理再归约，**证据可能在归约阶段丢失**；
  - 因此真正要回答的是：更广的访问范围能否换来足够多的最终证据，以抵消重复计算的成本。
- **整体含义**：论文主张用**证据保留、答案质量、复用成本**三个互补维度来选择长文档检索策略，而非默认“扫描更全面”。

## 2. 方法论

- **核心思想**：在同一文档、同一问题、同一段落边界、同一答案生成器的受控条件下，横向比较 11 种检索配置，并把“证据从源文档到最终答案”的全链路拆开追踪。
- **统一的段落与预算设置**：
  - 所有方法使用 `cl100k_base` 分词器，切分为约 **500 token、75 token 重叠**的段落；
  - 最终最多返回 **5 个段落**，打包进 **2,500 token** 的生成上下文；
  - 决策模型按 **12,000 token** 请求上限分窗，每窗保留至多 10 个候选，多轮比较后归约到 5 个。
- **三类检索路线**（共 11 种配置）：
  - **索引式检索**：BM25、OpenAI dense（text-embedding-3-small）、BGE-M3 dense、Hybrid RRF（BM25 + BGE-M3 经倒数排名融合，常数 60）；
  - **混合重排**：从最多 50 个混合候选中，分别用 BGE reranker、Jev、Decisions、Clef 重排；
  - **全文扫描**：Jev / Decisions / Clef 先看全部段落，再逐级归约。
- **关键度量：证据覆盖率 EC@k**：
  - 设 $R_k$ 为前 $k$ 个段落覆盖的源 token 区间并集，$S_j$ 为一组完整的参考证据单元，则
    $$\mathrm{EC@}k=\max_j \frac{1}{|S_j|}\sum_{e\in S_j}\frac{|e\cap R_k|}{|e|}$$
  - 证据单元等权、重叠 token 只计一次、不同备选证据集不混合；完全恢复需整组证据单元齐全；检索失败记 0 覆盖。
- **缩减追踪（reduction trace）**：对三种决策模型记录证据在“初始候选池 → 第一次选择 → 最终候选池 → 返回段落”各阶段的留存率，定位证据损失发生在哪一步。
- **成本投影模型**：设 $P_m$ 为单文档准备成本、$Q_m$ 为单次查询成本，则
  $$C_m(N)=P_m+NQ_m,\qquad A_m(N)=\frac{C_m(N)}{N}$$
  用于估计每文档重复 $N$ 次查询的累计与平均 API 成本；未知消费按已确认小计取下界。
- **答案评估**：固定生成器 `gpt-4.1-mini`（温度 0、512 token 输出），用 RAGAS 0.4.3 的 **Faithfulness** 与 **Answer Accuracy**，由 `gpt-6.1-sol` 盲评（不暴露方法名）；另设“无证据”和“参考证据”两个对照。
- **统计方法**：先在文档内平均、再跨文档平均；配对差异用 10,000 次整文档 bootstrap 重采样，报告未做多重比较校正的 95% 区间。

## 3. 实验设计

- **数据集 / 场景**：
  - **QASPER**：396 个问题（来自 264 篇论文），其中 320 个可答、76 个不可答；可答题要求证据可在原文定位，排除歧义及依赖图表的问题；
  - **教材集**：8 本完整 OpenStax 教材、80 个问题（每本 4 个事实型、3 个解释型、3 个多章节型），问题与参考答案主要由前沿模型 GPT-Astra 基于相关章节生成，引文经与原文核对；
  - **开发集**：60 个 QASPER 训练问题 + 2 本额外教材的 20 个问题。
- **规模差异**：论文文章含 2–70 个段落（中位数 11），几乎全部落在 50 候选池内；教材含 662–2,245 个段落（总计 446 万 token、10,508 段落），必须大量预筛或归约——两个语料因此测试不同的检索条件。
- **Benchmark 性质**：这是作者自建的受控评测协议（固定段落、固定 5 段上限、固定生成器），而非某个公开榜单；精确 oracle 表明 5 段限制在所有可答题上都能达到 100% 证据覆盖。
- **对比方法**：11 种检索配置（见上）+ 2 个答案对照（无证据、参考证据），共 13 个答案臂。
- **答案评估样本**：200 题固定样本 = 100 可答 QASPER + 40 不可答 QASPER + 60 教材题。
- **计时**：主实验用每题首次执行；另有 100 题子集（两语料各 50 题）× 每题 3 次、随机方法顺序的端到端重复计时。

## 4. 资源与算力

- **未涉及任何模型训练**：全部为推理评测，无训练时长、无训练算力消耗。
- **推理硬件**：
  - BGE 系列（BGE-M3、bge-reranker-v2-m3）运行在 **NVIDIA GB10**，FP32、batch size 8；
  - Clef（27B Cloudflare 模型）运行在**另一台共享 GB10**，BF16，一次一个前向，含本地日志；
  - Jev 与 Decisions 通过 API 调用，允许 2 路并发。
- **成本口径**：API 费用按执行期记录的价格与实际消费计算；Clef 及本地方法无 API 费用，**本地 GPU 等计算资源未计价**；生成与评判成本单独核算、不计入检索成本。
- **说明**：论文明确承认延迟数字绑定于上述部署条件（硬件、精度、并发、服务状态），不具跨环境可移植性。

## 5. 实验数量与充分性

- **实验规模**：
  - 主检索：11 配置 ×（396 QASPER + 80 教材）= **5,236 次主检索**（5,222 成功、14 失败）；
  - 答案评估：13 个答案臂 × 200 题 = **2,600 次生成**，其中 2,586 次产出可用答案；评判请求 4,244 次、成功 4,233 次；
  - 重复计时：每语料 50 题 × 3 次 × 多方法；
  - 分析维度包括：证据覆盖率、缩减追踪（4 个阶段）、延迟（中位数/p95）、成本投影（1–1,000 查询）、配对答案差异、留一教材稳健性、上下文打包损失、弃答率。
- **充分性**：
  - 优点是多维度交叉验证较完整：证据层面有 oracle 校准，答案层面有双对照，成本层面有实测单价支撑，并做了留一文档的敏感性分析；
  - 但教材仅 8 本、答案评估每题仅 1 次生成，配对比较的样本量（50–60 题、8 个文档簇）偏小，区间较宽，作者也声明区间未做多重比较校正。
- **客观与公平性**：
  - 公平性设计较好：所有方法共享文档、问题、段落边界、5 段上限与生成器，重排方法共享同一候选池；
  - 但存在不完全对等之处：Clef 为本地 27B 模型、Jev/Decisions 为托管 API，部署条件、并发度、精度不同；计时比较并非同硬件同条件；Clef 的重复计时仅完成 18/400 次，延迟结论主要依赖单次主执行；
  - 答案评分完全自动化、无独立人工评估，且评判模型与被评模型同属前沿模型家族，存在自偏好与位置偏差风险（作者已引用相关文献提示）。

## 6. 主要结论与发现

- **教材上证据覆盖**：Hybrid + Jev 最高（**94.1%**），Clef 全文扫描 91.6%、Jev 全文扫描 88.7%、Clef 混合 91.2%、Hybrid + Decisions 87.4%、OpenAI 稠密 81.3%、Decisions 全文扫描仅 76.6%。
- **扫描不等于保留**：全文扫描初始覆盖 100%，但归约过程持续丢证据——Jev 依次降至 99.4% → 95.7% → 93.2%（损失主要在中间轮），Clef 在最终选择一步从 98.8% 掉到 91.6%，Decisions 最终仅 85.2%。
- **QASPER 区分度有限**：混合候选池在 395/396 题中已包含整篇文章，多数决策方法覆盖率达 96%–98.8%，说明该数据集主要测试“段落选择”而非“预筛 vs 全扫”的差异。
- **覆盖高 ≠ 答案好**：教材上 Hybrid + Decisions 的 Answer Accuracy 最高（**0.892**），高于覆盖最高的 Hybrid + Jev（0.864）；Decisions 全文扫描 0.888、Jev 全文扫描 0.874。配对比较显示 Hybrid + Decisions 比稠密检索高 0.057（[0.019, 0.103]），Jev 全文扫描高 0.048（[0.003, 0.098]），但 Hybrid + Decisions 与 Hybrid + Jev 之差 0.028（[−0.005, 0.062]）不显著。
- **延迟**：教材上混合重排远快于全文扫描——中位延迟 Jev 1.72 s vs 25.10 s、Decisions 4.51 s vs 63.36 s、Clef 54.69 s vs 约 23.3 分钟；QASPER 上两者接近。
- **成本**：每文档 1,000 次查询时，OpenAI 稠密投影约 **$0.0135**（含准备），Hybrid + Jev ≥ $2.52、Jev 全文扫描 ≥ $64.43、Decisions 全文扫描 ≥ $155.85；稠密检索在第 **6 次**查询起就比 Hybrid + Jev 更便宜（交叉点 N ≈ 5.21）。
- **证据依赖性的重要警示**：无证据对照在教材上仍得 0.808 分，而在 QASPER 上仅 0.052，说明教材题的高分不能证明强证据依赖；上下文打包还会在检索后再损失证据（92.0% → 90.4%）。
- **弃答能力弱**：40 个不可答 QASPER 题上，六种决策配置仅弃答 11–14 次，远低于参考证据对照的 40 次。
- **总结论**：应把证据保留、答案质量与重复使用成本合并考虑；教材场景下混合重排更快且覆盖与答案均优；长文档不应盲目全文扫描。

## 7. 优点

- **问题切中实际**：把“扫描 vs 索引”这一工程直觉转化为可量化的三目标权衡，并明确区分证据覆盖与答案正确性两个概念。
- **度量设计扎实**：EC@k 定义清晰（等权证据单元、重叠去重、备选不混合），并用精确 oracle 验证 5 段上限在本数据上可达 100% 覆盖，排除预算人为压低结论的可能。
- **过程可解释**：缩减追踪把“扫描为何失效”定位到具体阶段（中间归约 vs 最终选择），比只报最终指标更有诊断价值。
- **控制变量严谨**：共享文档、问题、段落边界、候选池、5 段上限与固定生成器，并设无证据/参考证据双对照，能识别“高分但弱证据依赖”的假象。
- **成本分析有实操价值**：给出准备成本 + 查询成本的线性投影与明确的查询数交叉点，并诚实标注下界与未计价项。
- **透明度高**：公开代码与配置，报告失败次数、评分缺失、留一文档敏感性、上下文打包损失等“不完美细节”，并对自动评分的偏差风险主动设限。

## 8. 不足与局限

- **样本规模与代表性**：教材仅 8 本、80 题，答案评估每题仅 1 次生成，配对比较样本 50–60 题、文档簇仅 8 个，统计功效有限，区间较宽且未做多重比较校正。
- **参考标签质量**：教材问题与参考答案由前沿模型生成，仅做文本对齐核对而非独立人工验证；QASPER 虽有人工参考，但覆盖指标可能漏掉其他同样有效的支撑段落。
- **QASPER 区分度不足**：几乎所有文章都装进 50 候选池，该数据集无法有效检验全文扫描的潜在收益，结论主要由小规模教材集承担。
- **评估自动化风险**：Answer Accuracy 与 Faithfulness 均为 LLM 评判，存在自偏好、位置偏差与提示敏感性；未做人工复核，且未验证引用标签的正确性。
- **部署条件不对等**：Clef 为本地 27B 模型（BF16、串行），Jev/Decisions 为托管 API（2 路并发），延迟比较跨硬件、跨服务状态；Clef 重复计时仅完成 18/400 次，其延迟结论稳健性偏弱。
- **成本口径不完整**：仅计 API 费用，本地 GPU、生成与评判成本均未计入，因此“稠密更便宜”的结论只适用于 API 计费视角，不代表总拥有成本。
- **应用范围受限**：结论限定于“已知单文档内检索”、≤5 段、2,500 token 上下文；跨文档、多轮对话、需要图表证据、超长上下文直接生成等场景未覆盖；弃答能力弱的发现也提示实际部署需额外的“无证据”判定机制。
