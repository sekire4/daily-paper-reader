## 摘要
记忆有助于基于大语言模型的多智能体系统复用经验，但存储的建议可能有缺陷，或被应用于错误的情境。仅凭团队层面的成功或失败，无法可靠判断某条记忆是否需要修正，或本就不应被使用。我们提出 DiscernMem，一个无需训练的框架，可同时提升记忆质量和记忆使用效果。为提升质量，缺陷感知记忆精炼（Defect-Aware Memory Refinement, DMR）将团队在仅使用单条记忆与不使用记忆时的执行情况进行比较，诊断规则缺陷，并在当前任务和更早任务上测试修复效果，以防止丢失先前有用的行为。为引导恰当使用，边界学习元记忆（Boundary-Learning Meta-Memory, BLM）记录每条记忆的过往使用情况及效果，学习其所属角色应基于任务上下文和传入消息在何时应用或避免使用该记忆。这些组件共同帮助团队纠正有缺陷的经验，同时保留那些虽被错误应用但仍有用的规则。在四个基准上使用 Qwen3-4B-Instruct-2507 进行的实验表明，DiscernMem 在 AutoGen、CAMEL 和 MacNet 上取得最高平均分，比已报告的最强基线高出 0.51–4.32 分。它在所有三个系统上的代码生成和符号规划任务中均领先，包括在 CAMEL 上取得 37.71 的 PDDL 分数，而对比方法为 28.48。

## Abstract
Memory helps LLM-based multi-agent systems reuse experience, but stored advice can be flawed or applied in the wrong situation. Team-level success or failure alone cannot reliably show whether a memory needs correction or should not have been used. We propose DiscernMem, a training-free framework that improves both memory quality and memory use. To improve quality, Defect-Aware Memory Refinement (DMR) compares team executions with a single memory and with no memory, diagnoses rule defects, and tests repairs on current and earlier tasks to guard against losing previously useful behavior. To guide appropriate use, Boundary-Learning Meta-Memory (BLM) records each memory's past uses and effects, learning when its owner role should apply or avoid it based on task context and incoming messages. Together, these components help teams correct flawed experience while retaining useful rules that were applied incorrectly. Experiments with Qwen3-4B-Instruct-2507 on four benchmarks show that DiscernMem achieves the highest average score on AutoGen, CAMEL, and MacNet, exceeding the strongest reported baselines by 0.51-4.32 points. It leads on code generation and symbolic planning across all three systems, including a PDDL score of 37.71 versus 28.48 on CAMEL.

## 一、核心问题与整体含义

- **背景**：持久化外部记忆使 LLM 多智能体系统能够在不改变模型参数的前提下复用跨任务经验（如 Generative Agents、Reflexion、Voyager、G-Memory、ConMem、ReMe、MemRL 等）。
- **核心痛点**：仅"记住"并不足够。已存储的行为规则可能本身有缺陷，也可能在错误情境下被调用；而团队层面的成功/失败是联合结果，无法直接归因到单条记忆——一个 agent 可能补偿另一个 agent 的缺陷规则，一条有用的记忆也可能被用在一个因其他原因失败的任务上。
- **关键区分**：当某条记忆损害团队表现时，应判断是 **修复规则内容（content defect）**，还是 **修正其适用边界（contextual misuse）**。语义相关性或聚合效用分数都无法单独解决这一区分。
- **整体含义**：论文主张将"记忆内容精炼"与"记忆适用性学习"视为经验驱动适应的两个互补方面，并提出无需训练的框架 DiscernMem 来同时处理二者。

## 二、方法论

### 2.1 核心思想
- 每条记忆表示为 \(m_i^v=(r_i,b_i^v,\mu_i^v)\)：所有者角色 \(r_i\)、行为规则正文 \(b_i^v\)、元记忆 \(\mu_i^v=(C^{use},C^{avoid},E,P)\)（使用/回避条件、非源任务效果记录、历史修正记录）。
- 将记忆更新拆成两条独立路径：**DMR** 负责规则内容评估与修复；**BLM** 负责从复用历史中学习"何时用/何时不用"。
- 整个框架 training-free，主干 LLM、角色与通信结构均冻结。

### 2.2 缺陷感知记忆精炼（DMR）
- **配对回放评估**：对任务 \(q\) 上的每条被使用记忆 \(m_i^v\)，重放两次完整协作——一次只把该记忆给其所有者，一次不给任何角色任何记忆；两次使用相同配置与随机种子。计算
  \[
  \Delta_i^v(q)=s(q;m_i^v)-s(q;\varnothing)
  \]
  按容差 \(\epsilon\) 判定正/负/中性效果。无记忆回放可在同一任务的多条记忆间共享。
- **缺陷与误用诊断**：先用 LLM 检查所有者行动前可观察上下文 \(o_u\) 是否落在 scope 内：
  - `avoid(u)`：命中回避条件；`in(u)`：命中使用条件且未命中回避条件。
  - 仅对"负面且在 scope 内"的使用，才让 LLM 比较配对轨迹，诊断具体内容缺陷（缺步骤、动作顺序错、停止条件错等）。
  - 归因函数：
    \[
    d(u)=\begin{cases}\text{SCOPE}, & \text{avoid}(u)\lor\text{out}(u)\\\text{CONTENT}, & \text{defect}(u)\\\text{NONE}, & \text{otherwise}\end{cases}
    \]
  - 已有回避匹配优先于测得的负面效果；scope 归因不触发内容编辑，而进入 BLM。
- **证据引导的规则修复**：CONTENT 归因时，修复 LLM 接收缺陷诊断、引用的回放步骤、源轨迹、scope 与能力记录 \(P_i^v\)，生成最多 \(K\) 个局部编辑候选（ADD/REPLACE/DELETE/REORDER/NO_UPDATE）。
- **跨任务修复验证**：每个候选需在触发任务 \(q\)、保留集 \(H_1\)（此前有正面效果或验证证据的任务，种子采样）、相关集 \(H_2\)（按嵌入相似度检索的其他历史任务）上满足
  \[
  s(h;c)\ge \max\{s(h;m_i^v),s(h;\varnothing)\}-\epsilon,\quad \forall h\in\{q\}\cup H_1\cup H_2
  \]
  且完整失败数不增加：\(F(c)\le F(m_i^v)\)。
- **更新规则**：通过的候选中优先选在触发任务上提升超过 \(\epsilon\) 的；新版本变为 provisional，效果记录清空，历史修正记录累加；若所有轮次失败，保留原正文但记忆转为 inactive。

### 2.3 边界学习元记忆（BLM）
- **适用边界学习**：SCOPE 归因且识别出可观察例外 \(\phi_u\) 时，把 \(\phi_u\) 加入回避条件；只有在至少 \(n^+\) 个不同任务上取得正面效果后，才用 LLM 将历史上下文泛化为使用条件并扩展 \(C^{use}\)。更新是**加性**的，回避条件覆盖使用条件。
- **生命周期管理**：provisional / active / inactive 三态。
  - 晋升：\(|Q|\ge 2\)、平均效果 \(>\epsilon\)、无负面记录。
  - 持续伤害：provisional 在 \(|Q|\ge 3\)、平均效果 \(<-\epsilon\)、至少两次负面且无正面时失活；active 连续三次负面失活；SCOPE 归因不计入持续伤害。
  - 持续无效：至少 5 个任务上改变配对回放但效果全为中性则失活。
  - 修复失败：诊断出内容缺陷但预算内无法修复则失活（校准失败除外）。
  - 复活：重新评估得到正面效果时回到 provisional。
- **角色特定检索**：对每个任务和角色，按上下文与"正文+使用条件"的余弦相似度排序，经阈值 \(\theta\) 过滤后用 LLM 选择器筛选，最多注入 \(k_{inj}\) 条；注入时同时给出使用/回避条件供所有者判断。

### 2.4 新经验准入与校准
- 仅当本次任务没有记忆被归因为 CONTENT 缺陷时，才从轨迹中抽取新经验；每个角色最多提出一条规则或弃权。
- 用嵌入相似度检索同角色已有记忆，再由 LLM 判断是否"同一可执行操作"；匹配则附加到现有记忆并在当前任务上评估，不匹配则作为 provisional 新记忆。
- 新记忆在相似历史任务（排除源任务）上做配对回放校准；负面校准效果直接触发修复，无需复用归因。
