## 摘要
个人智能体需要利用长期交互历史，检索并应用适合用户当前请求的外部知识。即使答案基于相关文档，若忽视用户的具体情况，也可能并不适用。这带来两个相互关联的挑战：利用历史条件识别新请求所需的知识，以及将该知识应用于用户的具体情境。现有基准推动了记忆召回、个性化检索和记忆引导行动，但对这两个挑战的联合评估仍探索不足。我们提出 ColaBench，一个面向健康与日常生活的合成基准，包含跨 10 个 Profile 的 349 个任务和由 13,033 篇文档构成的知识库。其 Evidence Graph 将个人状况与其在公开交互会话中的披露联系起来，记录先前的文档接触情况，并将答案要求与个人证据和新获取的文档证据相关联。我们还提出 MemKB，它使用状态摘要为查询和规则应用提供信息，并利用记忆—文档链接检索与用户历史相关的知识。MemKB 达到 86.25% 的准确率，每个任务平均 4.07 轮交互。任务级分析发现，在整合多个历史 Fact 信息的任务上收益更大；错误分析进一步指出，缺乏支持的个人假设和规则误用是使用检索证据的障碍。ColaBench 提供可追踪的任务和评估框架，用于研究记忆如何引导知识获取与规则应用。

## Abstract
Personal agents need to draw on long-term interaction history to retrieve and apply external knowledge suited to a user's current request. Even an answer grounded in relevant documents can be unsuitable when it overlooks the user's circumstances. This creates two connected challenges: using historical conditions to identify the knowledge needed for a new request, and applying that knowledge to the user's situation. Existing benchmarks advance memory recall, personalized retrieval, and memory-guided action, while the joint evaluation of these two challenges remains underexplored. We introduce ColaBench, a synthetic benchmark in health and daily living, with 349 tasks across 10 Profiles and a knowledge base of 13,033 documents. Its Evidence Graph connects personal conditions to their disclosures across public interaction sessions, records prior document exposure, and links answer requirements to personal and newly acquired document evidence. We also introduce MemKB, which uses state summaries to inform queries and rule application, and memory-document links to retrieve knowledge associated with the user's history. MemKB achieves 86.25% Accuracy with an average of 4.07 interaction rounds per task. Task-level analysis finds larger gains on tasks integrating information across multiple historical Facts; error analysis further identifies unsupported personal assumptions and rule misapplication as obstacles to using retrieved evidence. ColaBench provides traceable tasks and an evaluation framework for studying how memory guides knowledge acquisition and rule application.

## 1. 核心问题与研究动机

- **背景**：个人智能体需要依赖长期交互历史来处理用户不断变化的需求。用户常常不会重复陈述过往经历、偏好与约束，而当前任务又往往需要新获取的外部知识。

- **两个相互关联的挑战**：
  - **知识获取**：利用历史条件判断“该检索什么”，即便当前请求未明示这些条件。
  - **规则应用**：将检索到的前提、例外与流程匹配到已知个人情境，同时保留仍未知的部分。
- **现有工作缺口**：LoCoMo、LongMemEval 侧重记忆召回与跨会话推理；TREC iKAT 侧重个性化检索；Mem2ActBench、MemoryArena 侧重记忆引导的工具使用与多会话行动。但**“历史条件如何引导新知识的获取与应用”这一联合评估仍未被充分探索**，且缺乏可追踪证据依赖的任务构造。
- **论文目标**：构建可追踪证据链的基准 ColaBench，并提出记忆引导检索方法 MemKB，系统评估记忆在知识获取与规则应用中的效用。

## 2. 方法论

### 2.1 总体框架：Evidence Graph 驱动的 Plan–Create–Review 多智能体构建

- **Evidence Graph**：$G=(V,E)$，节点类型包括 Document、Profile、Fact、Topic、Turn、Item；边刻画文档关系、Fact–Topic 组织、Fact 披露、文档暴露与 Item 证据依赖。
- **核心作用**：文档链接引导知识探索；Fact 披露与文档暴露记录约束后续 Item 只能使用“已披露的个人条件”和“历史中未暴露的新文档”；答案要求链接到个人证据与知识证据，使每个任务可追溯。
- **任务定义**：$x=(q, H, K; M)$，其中 $q$ 为当前请求，$H$ 为公开交互历史，$K$ 为冻结知识库，$M$ 为评估指标。

### 2.2 分阶段构建流程

- **Stage 0 文档层**：从公开健康信息、药品标签、开放教材等采集 11,069 篇基础文档；由 LLM 从种子文档出发检索并建立带描述与权重的知识关系边，再补充网络文档，最终语料 13,033 篇。
- **Stage I Profile 与 Fact 接地**：Director 智能体基于已有 Profile 与检索文档规划场景，生成 Fact（个人条件）与 Topic（交互任务）；独立审查智能体检查一致性、相关性与任务完整性。
- **Stage II 公开交互轨迹生长**：Simulator 仅能访问冻结的 Profile 与 Topic，Assistant 仅使用公开对话与检索知识；Simulator 根据 Assistant 实际回复追问或切换 Topic，形成连续 Trace；被接受的交互作为 Turn 节点记录 Fact 披露与文档暴露。
- **Stage III Item 构造**：
  - Builder 从已披露个人条件出发，寻找“必须依赖这些条件才能应用”的新知识，建立任务与答案证据；
  - Question writer 从公开背景与任务意图写出自然请求，把必要个人上下文留在历史中；
  - **History-removal test**：让盲解者在无历史条件下作答，检验任务是否真正依赖历史；
  - 最终审计检查来源支撑、知识新颖性、与前置交互的连续性。
- **Item 增强与验证**：增强智能体在固定历史下选择两种方向之一——重组原证据内的条件依赖，或用同一 Topic 下检索到的新文档重建规则应用；更新问题、参考答案与答案要求；经独立 History Gate 与证据审查后接受或丢弃。

### 2.3 MemKB：记忆链接的知识检索

- **记忆卡片**：用 Mem0 增量构建个人记忆并保留写入记录，将每条历史交互链接到存活的 memory ID，形成卡片 $m_i$，包含源消息 ID 与记忆文本的归一化嵌入。
- **状态库 $S(H)$**：用 LLM 从完整公开历史中抽取紧凑状态库，保留每条条件涉及谁、时间上下文、未解决条件与源消息 ID；在首次模型调用前注入系统提示，使个人条件影响初始查询，并在每次搜索返回时重复提供以支持规则适用性判断。
- **文档链接**：
  - 对每张卡片，用记忆文本加历史文档标题/片段查询完整 KB；
  - 保留**历史中未暴露**的 top 语义候选作为离线文档链接；
  - 历史 Read 文档与离线邻居共同构成卡片的链接文档集。
- **三通道检索与融合**：
  - 语义通道 $L_{sem}$：对当前查询 $q_t$ 做向量检索；
  - 关键词通道 $L_{key}$：词项匹配；
  - 记忆链接通道 $L_{mem}$：用 $q_t$ 检索卡片，按卡片排名**轮转（round-robin）**从每张卡片取一篇未在候选列表中的链接文档，直至候选预算耗尽；
  - **RRF 融合**（等权重，$\kappa=60$）：
    $$s(d)=\sum_{c\in\{mem,sem,key\}} \frac{\mathbb{1}[d\in L_c]}{\kappa+\mathrm{rank}_{L_c}(d)}$$
  - 每个文档每通道最多贡献一次；返回文档附带相关片段、文档 ID 与行号范围。
- **规则应用**：同一回答智能体比较检索规则的条件与用户状态/记忆记录，可继续搜索或调用 Read；提示词包含**来源归因约束**：区分说话者、行为者与事件状态，未指明来源或状态时保留不确定性。

## 3. 实验设计

### 3.1 数据集 / 基准

- **ColaBench**：健康与日常生活领域的合成基准。
  - 10 个 Profile、21 个 Session、1,198 条消息；
  - 52 个 Fact、600 个 Topic、349 个 Item；
  - 11,069 篇基础文档 + 1,964 篇网络补充 = **13,033 篇文档**；
  - 107 个多 Fact 任务；153 个引用多 Session 的任务；
  - 1,015 条答案要求（平均每任务约 2.9 条）。
- **知识库来源**：MedlinePlus（4,849）、openFDA 药品标签（2,803）、NCI（2,371）、NICHD（818）、MyHealthfinder（103）、Open RN 教材（90）、体力活动指南（24）、CDC（11）。

### 3.2 对比方法

| 方法 | 说明 |
|---|---|
| No Memory+Hybrid | 无记忆，仅 Hybrid 检索 |
| Graphiti+Hybrid | 时序知识图谱记忆 |
| A-MEM+Hybrid | 记忆演化与邻居扩展 |
| Mem0+Hybrid | 非图记忆 + Hybrid |
| **MemKB（本文）** | 状态摘要 + 记忆–文档链接 + RRF |

- 所有方法共享同一冻结 KB、同一公开历史、最多 4 轮工具调用 + 1 轮最终回答；搜索默认返回 5 篇、最多 20 篇；Read 每次最多 100 行/3,000 tokens。
- 回答模型：DeepSeek v4.1 Flash；评估器：GLM-5.3 Flash（低推理强度）；嵌入：Qwen3-Embedding-0.6B（A-MEM 用 all-MiniLM-L6-v2）。

### 3.3 评估指标

- **Accuracy**：答案须覆盖所有显式子问题、正确核心结论与关键行动，包括相关个人条件、适用要求与限制；影响结论/行动/时机/适用性/安全的错误或遗漏判失败。
- **Read Recall**：$\text{Read Recall}=\frac{1}{N}\sum_{i=1}^{N}\frac{|G_i\cap D_i^{read}|}{|G_i|}$，$G_i$ 为标注的新支撑文档，$D_i^{read}$ 为最终答案前 Read 返回非空文本的文档。
- **Avg. Interaction Rounds**：含最终回答轮的平均轮数。
- **5 个答案质量维度**（1–5 分）：State Fidelity、Condition Coverage、Evidence Grounding、Rule Application、Answer Completeness。
