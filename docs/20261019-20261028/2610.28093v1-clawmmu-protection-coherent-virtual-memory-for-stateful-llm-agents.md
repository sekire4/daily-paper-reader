## 摘要
AI 智能体会保留长期记忆，其中大部分来自网页和工具结果。运行模型的软件——智能体执行框架（agent harness）——并不记录谁可以对这些记忆采取行动，因此，隐藏在抓取页面中的指令可能被当作是用户自己的指令。我们提出 ClawMMU，一种保护层，它为每一段记忆标注其所有者、作用域、来源和权限。只要内容进入模型上下文、被写入存储、从存储返回，或驱动工具调用，ClawMMU 都会检查这些标签。其核心规则是：信息可以提升权限，但权限绝不会自我提升。由于这些检查取决于内容来自哪里，而不是内容说了什么，记忆攻击就变成经典的保护故障，即使模型被欺骗，执行框架也能阻止这些攻击。

## Abstract
AI agents keep long-term memory, much of which comes from web pages and tool results. Agent harnesses, the software that runs the model, do not record who may act on this memory, so an instruction hidden in a fetched page can be treated as the user's own instruction. We propose ClawMMU, a protection layer that labels every piece of memory with its owner, scope, origins, and authority. ClawMMU checks these labels whenever content enters the model's context, is written to storage, returns from storage, or drives a tool call. Its central rule is that information may rise in authority, but authority never lifts itself. Because the checks depend on where content came from, not on what it says, memory attacks become classical protection faults that the harness stops even when the model is fooled.

## 1. 核心问题与整体含义

- **背景**：生产级智能体（Claude Code、Codex 等）跨会话保留长期记忆，包括指令文件（AGENTS.md/CLAUDE.md）、工具结果、压缩后的对话摘要等。运行模型并管理这些记忆的软件称为 **harness（执行框架）**。已有记忆组织研究（MemGPT 的分层记忆、ClawVM 的“类型化页面 + 虚拟内存式分页”）只解决**存储与调度**，不解决**保护**。
- **核心问题**：harness **不记录“谁有权对这段记忆采取行动”**，因此抓取网页或工具输出中隐藏的指令会被赋予与用户指令同等的权威。
- **三类具体攻击**：
  - 间接提示注入（Greshake 等；Zhan 等的 InjecAgent）：抓取页面在当前任务内发号施令；
  - 睡眠者记忆投毒（Pulipaka 等）：恶意文本先被存储、经多轮摘要与变换后“读起来像智能体自己的笔记”，数周后才触发（如伪造发票 →“以后所有付款用此账户”）；
  - 直接提示注入与共享智能体的多用户场景；以及 **confused deputy（混淆代理）**：不可信内容借用智能体的权限。
- **现有防御为何不够**：训练类方法（Instruction Hierarchy、SecAlign）与检测器只降低攻击率、**无保证**；合法文档本身也含指令；针对特定防御调优的自适应攻击可绕过多数已发表防御（Nasr 等，“攻击者后手”）。持久化使问题更严重；生产系统的“危险操作前询问用户”机制**不知道参数来自何处**。
- **核心类比与论点**：操作系统从不读取内存内容来判断权限，而由 **MMU 给每个页附加权限、每次访问都检查**。ClawVM 只带来了“分页”，缺了“MMU”；ClawMMU 补上这一层，把**语义安全问题转化为经典的保护故障（protection fault）**，从而在模型被欺骗时仍能拦截。

## 2. 方法论

### 2.1 核心思想
为每段记忆的**每个表示（representation）**附加一个**保护描述符（protection descriptor）**，在内容跨越模型上下文边界的四个时刻检查；判定依据是**内容从哪来（provenance）而非内容说了什么**。中心规则：

> **信息可以提升权威，但权威绝不自我提升（information may rise in authority, but authority never lifts itself）。**

### 2.2 保护描述符（四个字段）
- **owner**：谁产生（用户 / 智能体 / 队友等）；
- **scope**：哪些任务与会话可用；
- **origins**：由哪些页面构建而来（完整来源列表）；
- **authority**：有序等级，如
  - 最低 **Evidence**：工具调用、网页搜索结果——模型可读但**永不可据以行动**；
  - 最高 **Policy**：用户消息——所有者已批准的内容；
  - 中间级：用户偏好（如偏好航司）、队友写的指令文件。

### 2.3 继承规则（inheritance rule）——派生记忆的标签计算
文字化算法：
1. 取所有输入的权威等级，**派生记忆的权威 = 输入中的最低者**（low-water-mark）；
2. 可用范围 = 所有输入作用域的交集（“只能在所有输入都可用的地方使用”）；
3. `origins` = 所有输入来源的并集；
4. `owner` = 执行派生的一方；
5. **把模型本身视为最低权威输入**——因为注入文本可操纵模型写什么，故**模型自己写的记忆永远是 Evidence**；
6. 只有 owner 能提升权威（直接批准，或事先授予的预先批准）。

### 2.4 撤销机制（revocation）
- 每页带 **revocation counter**，owner 撤销/更正时 +1；
- 派生时把**所有祖先页面的当前计数值**抄入新描述符；
- 使用时若“记录值 < 当前值” ⇒ 该记忆由已撤销/过期来源构建 ⇒ 失效；无关记忆不受影响；
- **采用“使用时检测”而非“撤销时删除”**：因为副本可能存在于缓存、搜索索引、检查点中，难以定位删除；
- **当前计数器存放在检查点之外**，故回滚旧检查点无法让被撤销记忆“复活”。

### 2.5 四个“跨界”检查点（对应 MMU 操作）
| 检查点 | 对应 MMU 操作 | 作用 | 拦截的攻击 |
|---|---|---|---|
| **map** | 映射新页 | 新外部内容进入上下文时按来源赋描述符；每个上下文是一个 **compartment（所有者+作用域）**，默认拒绝跨域 | **地址空间违规**（内容进入不属于它的上下文） |
| **derive** | 换出/页出 | 模型写存储时按继承规则附加描述符 | **类型混淆**（不可信文本借摘要“洗”成策略） |
| **reload** | 页入 | 检索或检查点恢复时比对计数器；不一致则不信存储的描述符，重新走 map | **use-after-revoke**（含检查点回滚） |
| **authorize** | 每次访问的权限检查 | 不控制“模型的决策”，而保护**调用参数的完整性**：每个安全相关值（如收款人）必须溯源到足够权威且无被撤销来源的内容 | **confused deputy** |

### 2.6 授权细节（附录 B）
- 每个工具有一份**经人工审查的能力模式（capability schema）**，把每个参数标注为 `checked` / `safe`（可来自任何地方）/ `uncovered`；
- `checked` 参数必须溯源到 schema 要求的权威等级；含 `uncovered` 参数的调用**直接拒绝**；无法溯源的值赋予**最低权威**；
- **常设权限**（如每月付房租）附加更严格条件：**若提出该调用的上下文中进入了任何不可信内容，则常设权限失效**，必须由 owner 逐次批准精确调用 ⇒ 不可信内容无法“创建、选择或重定向”权限。

### 2.7 共享机制（附录 A）
- 两个 compartment 只能通过 **assembly capability（不可伪造的所有者令牌）**共享同一上下文；该令牌**只允许一起读，不提升任何内容的权威**。

## 6. 主要结论与发现

- **设计层面结论**：把“来源标签 + 四点检查 + 继承规则 + 撤销计数器 + 逐参数授权”组合起来，可使**不可信内容既不能获得用户权威，也不能触发外部动作（如付款）**；且**不依赖模型抵抗攻击**——被欺骗的模型可以“提议”有害动作，但会被 harness 拒绝。
- **明确声明的非保证（范围界定清晰）**：
  - 不保证模型做出正确决策；
  - 不保证派生记忆内容正确；
  - **不保证机密性**（可读内容仍可能泄露）；
  - 模型可以传“有足够权威但值错误”的参数。
- **理论定位**：继承规则 = 经典 **Biba 低水位标记完整性策略**（读不可信数据者自身变为不可信）；compartment 与“仅 owner 可提权”继承自 **HiStar / Flume** 的信息流控制。智能体记忆带来两个新情形：**不可信的模型本身在产生派生数据**、**检查点恢复旧状态**。
- **相对已有系统的增量**：同时具备“记忆标签 + 抗检查点回滚的撤销 + 逐参数检查”，并新增**默认拒绝的 owner/scope 隔离**。
- **工程主张**：只需在四个跨界点各设一个 hook 加**稳定的页面标识**，因此方法**可推广到 ClawVM 之外**。
- **开放问题（作者自列）**：大规模审查能力 schema；多智能体系统中的权威归属；**撤销生效之前已发生的动作**如何处理；对“扩大作用域的批准”如何审计。

## 7. 优点

- **问题选得准**：把“长期记忆的持久化”识别为安全问题的放大器（投毒经多次摘要后“像自己的笔记”），抓住了现有防御的结构性弱点（概率性、无保证）。
- **类比严谨且落地**：不是修辞性类比，而是把 MMU 的四类操作逐一对应到 agent 上下文的四个跨界点，形成可实现的 hook 清单。
- **判定依据与语义解耦**：检查基于 provenance 而非内容措辞，天然规避“合法文档也含指令”的假阳性困境，并对自适应攻击更具鲁棒性（不依赖模型不被骗）。
- **撤销设计巧妙**：**计数器 + 使用时检测 + 计数器置于检查点之外**，同时解决“副本难以删除”和“回滚检查点复活毒化记忆”两个难题（正面对上 ACRFence 类语义回滚攻击）。
- **逐参数授权**：不试图理解模型推理，而保护参数完整性，是务实且可实施的安全边界；常设权限的“上下文洁净”条件设计精细。
- **诚实界定保证范围**：明确列出不保证项（正确性、机密性），学术上可信度高。
- **可组合性**：明确声明只依赖 hook 与稳定页标识，可与 ClawVM/MemGPT 类记忆系统叠加。

## 8. 不足与局限

- **无实现、无实验（最大局限）**：所有安全主张均未经实证；作者自认 ClawMMU 为“design”，Table 1 中自家一行为设计属性。
- **人工负担与可用性风险**：安全性依赖**经审查的 capability schema**，作者承认“错误的 `safe` 标注是主要残余风险”；大规模 schema 审查本身是未解难题，且 schema 错误会直接变成漏洞。
- **误报与批准疲劳未量化**：`checked` 参数过严会频繁阻断正常流程；常设权限在“上下文中出现任何不可信内容”即失效，实际使用中可能极其频繁地要求人工批准，可用性代价未知。
- **覆盖不到的攻击面**：
  - 不保证**机密性**（记忆泄露、跨用户读取）；
  - 撤销**之前**已执行的动作无法挽回；
  - 模型“编造”的值被赋予最低权威，但若 schema 漏标（`uncovered` 之外的漏判）仍可能放行；
  - 语义层面的错误（有权威但内容错误）不在防护内。
- **威胁模型未形式化**：没有形式化的攻击者模型、没有安全性证明（相较 TMA-NM 声称的 machine-checked guarantees）。
- **多智能体与权威归属未解决**：作者自己列为开放问题；而多智能体恰恰是当前部署趋势。
- **继承规则的效用代价未评估**：“模型本身视为最低权威输入”意味着**模型写的所有记忆永远是 Evidence**，这可能严重限制记忆系统的实用价值（如自动整理的用户偏好），但文中未讨论缓解手段或代价。
