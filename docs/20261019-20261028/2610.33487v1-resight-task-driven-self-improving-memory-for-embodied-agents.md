## 摘要
机器人可以利用历史观测在熟悉环境中回答时空查询，但相关证据的存在并不意味着现有工具支持任务所需的各种操作。我们提出 ReSight，一种面向具身智能体的任务驱动自改进记忆系统，它能在任务需求出现时扩展处理和访问历史观测的能力。ReSight 保留关键帧及其时空关联，将观测证据与可扩展的派生字段分离，从而使已存储的观测能够针对新需求被重新处理。一个执行智能体和一个编程智能体通过不同接口共享该记忆：前者在有界在线预算内调用已注册工具，后者使用可编程工作区和更大的探索预算来检查证据、编写程序并按需获取模型。为实现 ReSight 中的能力扩展，我们开发了 Explore-Distill-Mount (EDM)，它无需任务参考答案即可从执行与探索记录中识别能力缺口，并将探索得到的解决方案转化为可复用的记忆构建器、查询工具和技能，从而按需扩展记忆表示与访问能力。在三个公开基准上的实验展示了有效的基础记忆访问与能力扩展。在每个基准内保持执行模型和在线预算不变的情况下，EDM 将 OC-NaVQA 上的平均位置误差从 33.10 m 降至 24.72 m，并将 FindingDory 上的高层成功率从 38.3% 提升至 63.8%。在工具和技能冻结的情况下，在未参与探索与蒸馏的 FindingDory 片段上，成功率仍提升 28.3 个百分点。在真实机器人巡逻记忆上的实验进一步表明，这些能力可复用于后续查询和新记忆，且平均在线工具调用次数更少。

## Abstract
Robots can use historical observations to answer spatiotemporal queries in familiar environments, but the presence of relevant evidence does not imply that existing tools support the operations a task requires. We introduce ReSight, a task-driven self-improving memory system for embodied agents that expands the capabilities for processing and accessing historical observations as task demands arise. ReSight retains keyframes and their spatiotemporal associations, separating observation evidence from extensible derived fields so that stored observations can be reprocessed for new needs. An execution agent and a coding agent share this memory through different interfaces: the former calls registered tools within a bounded online budget, while the latter uses a programmable workspace and a larger exploration budget to inspect evidence, write programs, and acquire models as needed. To realize capability expansion in ReSight, we develop Explore-Distill-Mount (EDM), which identifies capability gaps from execution and exploration records without task reference answers and converts exploration-derived solutions into reusable memory builders, query tools, and skills, extending memory representations and access capabilities as needed. Experiments on three public benchmarks demonstrate effective base memory access and capability expansion. With the execution model and online budget held fixed within each benchmark, EDM reduces mean position error on OC-NaVQA from 33.10 m to 24.72 m and improves high-level success on FindingDory from 38.3% to 63.8%. With the tools and skill frozen, success still improves by 28.3 percentage points on FindingDory episodes excluded from exploration and distillation. Experiments on real robot patrol memories further demonstrate reuse of these capabilities for subsequent queries and new memories, with fewer online tool calls on average.

## 二、方法论

### 2.1 核心思想

- **可重访的时空证据记忆**：以保留的 RGB 关键帧为锚点，附带时间、位姿、深度、标定等难以从图像恢复的采集上下文。
- **分离“观测证据”与“派生字段”**：初始字段（场景/物体描述、视觉与文本嵌入）与后续扩展字段（OCR 文本、事件、几何）分层存储，所有字段通过 frame id 链接回源图像。
- **非对称双智能体共享同一记忆**：
  - **执行智能体**：数据库视图，在**有界在线预算**内调用注册工具，通过渐进披露（先返回文本摘要，需要时再打开原图）节省上下文；
  - **编程智能体**：文件系统/工作区视图，可读文件与图像、写代码、装依赖、下模型，拥有**独立且更大的探索预算**。

### 2.2 关键技术细节

- **记忆形式化**：`M(r) = (O, F(0), X(r))`，其中 O 为保留记录，F(0) 为初始字段，X(r) 为 r 次扩展后累积的派生字段与索引。
- **检索融合**：视觉（SigLIP2）、场景描述（e5）、物体描述三通道独立排序，用**倒数排名融合 RRF** 合并：`score(i,q) = Σ_c w_c/(κ + rank_c(i,q))`，κ=60，等权。
- **EDM 三步流程**（算法 1）：
  1. **Explore**：编程智能体对同一记忆上的全部查询联合求解，输出答案、可复跑程序、笔记与证据帧；不读取参考答案。
  2. **Distill**：先用脚本按行为标记（强行作答、重复相同调用、未看图即答、与探索者答案不一致）定位问题查询；再做**能力台账**（将每个操作分类为 direct / composable / partial / missing）与**缺口地图**（按成因分组，决定补救方式为 builder 还是 tool）；以探索程序为起点实现工具，禁止重建 direct/composable 操作，partial 操作只补缺失能力；可选 replay 轮次根据执行轨迹迭代修订；最后写一份 ≤N 行、每行注明来源的 skill 注入执行者 system prompt。
  3. **Mount**：注册工具、暴露 builder 生成字段、注入 skill；执行模型与在线预算**前后保持不变**。
- **优化目标**：`max_ΔH E_{q~D_gap}[s_B(q;H′) − s_B(q;H)]`，`H′ = Mount(H, ΔH)`，即只在能力缺口任务分布上提升同预算下的得分。
- **记忆更新**：`X_b = b(M(r))`，`M(r+1) = (O, F(0), X(r) ∪ X_b)`；builder 可在新记忆上重跑。

### 2.3 典型能力扩展实例

- **物体定位工具**：分割 + 深度反投影 + 多视角聚合，返回物体坐标而非相机位姿（OC-NaVQA 案例 3D 误差 14.95 m → 2.59 m）。
- **交互时间线工具**：枚举 pick/place 交互区间、按持续时间排序、按钟表时间对齐，解决“08:36 交互的物体”“重排耗时最长的物体”。
- **OCR 符号索引**：全记忆扫描文本建索引，一次调用返回可读帧与标志位置。
- **照片检索工具**：patch 级 SigLIP2 索引 + 位姿/时间合并去重，解决“数一数见过几个同款电话亭”（重访导致重复计数）。

### 5.2 充分性与公平性评估

- **优点**：
  - 主对比严格固定执行模型与在线预算，属于**同预算前后对照**，因果归因较清晰；
  - 设置了**留出集**（81–90）检验泛化，回应了“探索与评估同池”的质疑；
  - 设置 **EDM w/o Explore 消融**，区分“探索解”与“执行轨迹”的贡献；
  - 跨宿主（RAVEN）迁移实验增强了外部效度；
  - 提供 McNemar 精确检验（如 28 vs 144，p = 5×10⁻²⁰）。
- **不足**：
  - 主实验的**诊断与评估使用同一公开任务池与记忆**（episodes 91–100），存在对测试分布的适应性；
  - 部分结论依赖特定闭源模型（GPT-5.6-sol / Opus-5），跨模型稳健性只做了标注器维度；
  - 真实机器人仅评记忆查询，**下游物理执行只作演示、未量化**；
  - 时序/位置误差等指标的方差与置信区间报告不充分。

## 六、主要结论与发现

- **基础记忆有效**：GOAT-core 上直接检索达 90.8% SR@5（Sol）/ 89.8%（Qwen），高于 MoM 仅视觉的 81.5%；智能体式 90.6%。
- **能力扩展显著**：
  - OC-NaVQA 平均位置误差 33.10 m → 24.72 m，≤10 m 占比 19.7% → 36.6%，时序 MAE 0.587 → 0.475 min；
  - FindingDory 总体成功率 38.3% → 63.8%（ReSight），38.9% → 66.6%（RAVEN），多目标 7.9% → 50.6%，时序 41.0% → 82.9%。
- **能力可冻结复用**：留出集 81–90 上 37.5% → 65.8%（+28.3 pt），同时 token/query 下降 69.4%，说明增益可跨片段迁移而非过拟合。
- **探索解不可替代**：去掉 Explore 仅用执行轨迹蒸馏仅得 46.4%，其事件工具把“基座停顿”误当作交互，10 个 episode 中 3 个计数错误。
- **效率提升**：ReSight 挂载后 43k tokens/query，远低于 RAVEN 的 150k；真实机器人平均工具调用 5.10 → 1.20，成功率 12/30 → 30/30。
- **代价与权衡**：OC-NaVQA 上二值准确率从 86.6% 略降至 82.1%（McNemar p = 0.45，不显著），token 与请求数在该子集上略增，说明能力扩展并非全面提升。

## 七、优点

- **问题定位精准**：“证据可得 ≠ 操作可得”的能力缺口视角，比单纯提升检索精度更贴近真实部署痛点。
- **架构设计优雅**：证据与派生字段分离 + 晚期绑定，使同一份原始观测可被反复再加工，避免重复采集；双智能体用**非对称接口与预算**解耦“快响应”与“深思考”。
- **自改进信号无需参考答案**：仅用行为标记（强行作答、重复调用、未看图即答、答案分歧）定位缺口，实用性强，避免标注依赖。
- **蒸馏产物层次完整**：同时产出 memory builder（全量预处理）、query tool（查询时计算）与 skill（使用策略），并有“禁止重建 direct/composable 操作”的约束防止工具膨胀。
- **实验设计有防御性**：留出集、w/o Explore 消融、第二宿主迁移、标注器替换、真实机器人新楼层复用，多角度回应可迁移性质疑。
- **效率意识**：渐进披露与紧凑文本返回显著降低在线 token 与请求数，具备工程落地价值。

## 八、不足与局限

- **任务分布覆盖有限**：作者自承使用预定义查询集与任务类别，真实部署中的长尾、演化型查询未被充分刻画；多次连续能力扩展的长期演化未评估。
- **诊断/评估同池风险**：主结果在 episodes 91–100 上既探索又评测，虽以留出集缓解，但留出集仍是同一 benchmark 同分布片段。
- **模型依赖性强**：执行与标注强绑定 GPT-5.6-sol，探索依赖 Opus-5；能力蒸馏质量受编程智能体能力上限约束，弱模型下结论未知。
- **真实世界验证偏弱**：真机仅覆盖单个办公楼、两个楼层、6 类任务，且评测时机器人运动被禁用；物理闭环只在附录作定性演示。

  - **算力与成本不透明（续）**：未报告 GPU 资源、离线构建与探索总成本；EDM 的探索预算（如真实机器人 400 轮、编程智能体的调用次数与 token 上限）只给出上限而未给出实际消耗，也未讨论**预算规模对工具质量的影响曲线**——即“多花 2 倍探索算力能换来多少成功率”，而这恰恰是决定该方法能否在工业界摊销的关键参数。
  - **离线/在线成本边界模糊**：论文以“离线可服务多查询”为效率辩护，但缺少**摊销模型**（如按查询数摊薄后的总成本 vs. 基线一次性索引成本），因此“更省 token”的结论只在在线侧成立，端到端经济性未被证明。

- **缺口发现的可靠性未被独立评估**：
  - 缺口定位依赖四类**行为标记启发式**（强行作答、重复相同调用、未看图即答、答案分歧），但论文未报告这些标记的**查准率/查全率**，也未与人工标注的“真实缺口”做一致性检验；
  - 存在**静默失败**风险：执行智能体可能给出看似合理但错误的答案而不触发任何标记，此类缺口不会被蒸馏，形成系统性盲区；
  - “与探索者答案不一致”作为标记，隐含假设探索者（Opus-5）更可信，但在探索者自身也失败的任务上，该信号会失效甚至误导。

- **工具正确性缺乏验证与回归机制**：
  - 论文展示了 builder 与 tool 的构建流程，但未见**自动化单元测试、工具级回归测试或跨记忆的稳定性检查**；工具一旦生成即被挂载，若在未见过的新楼层/新场景上失效，系统缺少降级或回退策略；
  - 工具的**版本管理与冲突处理**未讨论：多次 EDM 迭代后可能出现功能重叠或语义冲突的工具（如同一能力被两个 builder 以不同口径实现），论文只给出“禁止重建 direct/composable 操作”的静态约束，缺少运行时仲裁；
  - 工具引入的**新失败模式**（分割错误、深度反投影在透明/反光表面的失效）只在定性案例中被提及，未做错误传播分析。

- **skill 注入的工程约束被弱化**：
  - skill 以“≤N 行、每行注明来源”注入 system prompt，但 N 的取值、注入后对执行模型指令遵循能力的影响、以及多轮 EDM 后 skill 累积导致的**prompt 膨胀与规则冲突**均未量化；
  - 缺少“skill 是否真的被模型遵循”的验证（如消融：只挂工具不注入 skill vs. 两者都挂），因此工具与 skill 的相对贡献未被分离。

- **统计严谨性不足**：
  - 仅个别对比给出 McNemar 检验，多数结果以单点数值呈现，**未报告置信区间、随机种子或多次运行方差**；
  - 真实机器人 6 任务 × 5 次 = 30 次运行的样本量偏小，12/30 → 30/30 的跃升虽醒目，但基线侧的失败模式集中（可能仅由 1–2 类任务主导），缺少按任务的分层报告；
  - 位置误差用**平均值**汇总，易受少数大误差样本支配，中位数与分位数缺失，导致 33.10 m → 24.72 m 的改善幅度难以判断其分布形态变化。

- **任务与具身形态的单一性**：
  - 三个基准均为**室内静态场景 + 视觉语言查询**，缺少动态场景（人/物持续移动）、多楼层跨域、户外或非视觉模态（音频、触觉、力反馈）的验证；
  - “具身”主要体现在查询接口与下游演示，**闭环控制、主动探索（为补缺口而主动去采集新观测）未被纳入**——当前系统只能重加工已有记忆，无法请求“再去看一眼”，这限制了能力缺口在证据本身缺失时的补救空间。

- **可解释性与审计性**：
  - 派生字段（OCR 文本、事件区间、3D 坐标）虽链接回 frame id，但**工具输出的置信度、失败原因、参数敏感性**未随字段一同存储，下游难以判断某条派生字段是否可信；
  - 论文未讨论记忆的**遗忘/淘汰机制**：随着 builder 反复扩展，派生字段与索引持续增长，存储与检索开销的长期演化未评估。

## 九、启示与可拓展方向

- **从“检索记忆”到“计算记忆”**：本文最有价值的观念迁移是把记忆系统视为**可编程的证据基座**，检索只是其中一种访问方式；这为具身智能体之外的场景（长视频分析、工业巡检日志、个人数字助理）提供了通用范式。
- **自改进的监督信号来自系统自身**：以行为异常而非人工标注驱动能力发现，成本低、可在线运行，但其可靠性取决于标记设计的覆盖度；未来可引入**执行者自评置信度、工具调用失败率、跨智能体一致性**等更丰富的无监督信号。
- **预算非对称是一种可复用的架构原则**：将“低预算快响应”与“高预算深加工”分离到两个智能体，并把后者的产物**编译**为前者的工具与提示，这一“编译式改进”思路可推广到任何受在线延迟/成本约束的 agent 系统。
- **值得推进的实验**：(1) 缺口检测的精确率/召回率评估与静默失败挖掘；(2) 探索预算–收益曲线与端到端成本摊销；(3) 多次连续 EDM 迭代的能力累积与冲突治理；(4) 引入主动采集（允许智能体请求新观测）以覆盖“证据缺失型”缺口；(5) 弱模型宿主（开源 7B–30B 级）下的迁移验证。

## 十、总体评价

- **贡献层次**：论文的主要贡献不在单点指标，而在**问题重构**（能力缺口）与**系统机制**（证据/派生字段分离 + 非对称双智能体 + 无参考答案的探索–蒸馏–挂载闭环）。指标提升（FindingDory +25 pt、留出集 +28.3 pt、真机 30/30）是这一机制的实证支撑，而非全部价值。
- **证据强度**：中等偏强。固定执行模型与在线预算的前后对照、留出集、w/o Explore 消融、第二宿主迁移、标注器替换共同构成了较完整的因果链；但诊断/评估同池、统计报告不充分、真机规模偏小仍是明显弱点。
- **工程可行性**：较高。离线构建、在线轻量、渐进披露、token 下降 69% 等特征契合实际部署；但工具正确性保障、版本治理与成本透明度不足，距离产品化仍有距离。
- **适用边界**：最适合“历史观测已足够、但缺少相应计算/访问操作”的长程具身查询场景；对证据本身缺失、需要主动探索或动态环境频繁变化的场景，当前设计并不覆盖。
- **一句话判断**：这是一篇**以系统洞察取胜**的工作——它把“记忆”从被动索引升级为可自我扩展的计算平台，并用一组设计良好的对照实验证明了该路径的有效性与可迁移性；其短板主要集中在评测严谨性、成本透明度与真实闭环验证，属于可通过后续工作补齐的工程与实证问题，而非范式性缺陷。
