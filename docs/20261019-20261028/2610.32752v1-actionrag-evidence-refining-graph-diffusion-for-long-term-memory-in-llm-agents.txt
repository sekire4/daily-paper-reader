# ActionRAG: Evidence-Refining Graph Diffusion for Long-Term Memory in LLM Agents

Abstract 

LLM agents need long-term memory that can recover precise and mutually consistent ev-idence from growing interaction histories, particularly when answers depend on relations among facts rather than isolated semantic matches. Current memory pipelines remain vulnerable at two stages: indexing errors can fragment repeated entities or merge distinct ones, and online retrieval often treats initial similarity scores as final even when the sur-rounding graph provides evidence for revising them. We introduce ActionRAG , a graph memory architecture that couples cautious indexing with query-time graph retroevaluation. Its indexing pipeline reconciles type labels and applies tiered entity resolution. Given a query, dual-channel entity and triple retrieval forms an initial evidence set and induces a bounded local graph. Query-conditioned receiver-normalized diffusion refines triple scores using local path structure. Seed protection, hub-penalized flux, and triple materialization preserve direct evidence while recovering missed connections. We evaluate ActionRAG on MemoryAgentBench (MAB), which tests accurate retrieval, conflict resolution, long-range understanding, and test-time learning. Across its eight deterministic-scoring columns, Ac-tionRAG achieves 55 .1 average accuracy, improving over the strongest retrieval-based mem-ory baseline by 5 .4 points. Under MAB’s query-time cost accounting, mean synthesis cost stays below $0.001 per query on the four reported cost columns, and the sum of separately measured retrieval-side p99 components is 440 .7 ms on our consumer Apple Silicon setup. 

Keywords: graph retrieval-augmented generation; graph diffusion filtering; memory-augmented LLM agents; knowledge graphs 

1. Introduction 

Large language model (LLM) agents accumulate information across many turns of inter-action and must recall, reconcile, and update facts as those interactions unfold. A useful memory for such agents is not a single skill but a bundle of them: looking up a specific fact buried deep in past dialogue, reasoning across several facts to answer a multi-hop question, recognizing when a new statement supersedes an older one, and absorbing fresh informa-tion at test time. MemoryAgentBench (MAB) (Hu et al., 2026) operationalizes exactly this view, evaluating memory in LLM agents via incremental multi-turn interactions along four competencies: accurate retrieval, test-time learning, long-range understanding, and conflict resolution. The dominant memory architecture today is dense retrieval-augmented generation (RAG) (Lewis et al., 2020): chunk the interaction history, embed each chunk, and look up the top-

k matches per query. This flat index works for single-hop fact recall but loses signal on

multi-hop reasoning (each chunk is scored in isolation) and on conflict resolution (a super-seded fact and the fact that overrides it share most of their semantic content and become indistinguishable to a chunk embedder). The result is a measurable accuracy gap on exactly the MemoryAgentBench slices that real agents need to handle. Graph-structured memory addresses this by representing the agent’s history as a typed entity–relation graph. Microsoft’s GraphRAG (Edge et al., 2024) and LightRAG (Guo et al., 2024) use shallow heuristic traversal over the resulting graph, which is fast but loses much of the multi-hop signal. HippoRAG (Guti´ errez et al., 2024) and its successor HippoRAG-v2 (Guti´ errez et al., 2025) take the stronger route of extracting named entities from the query, linking them to nodes in a global corpus graph, and using those nodes to seed Personalized PageRank (PPR) (Page et al., 1999; Haveliwala, 2002). This provides effective associative retrieval, but it introduces an LLM call before every graph search and makes retrieval depend on the entities retained by that call. Predicate-level cues that are not expressed as salient named entities may therefore receive weak or no initial activation, causing relevant relations to be overlooked. ActionRAG instead retrieves both entity and concrete triple seeds directly, then uses local graph diffusion to retroevaluate the resulting triples. This removes query-time LLM parsing from retrieval while preserving relational cues that entity-only seeding can miss. Although an agent’s memory may be large, evidence relevant to a particular query often occupies a small region once plausible entities and relations have been identified. ActionRAG builds this region over a cautiously indexed entity–relation graph. Its indexing pipeline reconciles type labels, resolves repeated or ambiguous entities through tiered checks, and preserves source provenance. At query time, direct retrieval over both entities and concrete triples produces an initial evidence set. ActionRAG then constructs a bounded local graph and applies query-conditioned, receiver-normalized diffusion to revise triple relevance using surrounding path structure. Graph connectivity therefore acts as a second-stage evaluator of retrieved evidence rather than replacing semantic retrieval altogether. We evaluate ActionRAG on the eight deterministic-scoring columns of MemoryAgentBench. ActionRAG has the highest reported score among retrieval-based memory agents on six of the eight columns where the unweighted mean of these heterogeneous scores is 55 .1, 5 .4points above HippoRAG-v2. 

Contributions. 

• A cautious graph-indexing pipeline with label reconciliation, tiered entity resolution, provenance preservation, and conflict-aware summarization. 

• An evidence-refining local graph diffusion method that combines dual-channel retrieval with relational retroevaluation, yielding the highest reported score among retrieval-based memory agents on six of the eight deterministic MAB columns. 

2. Related Work 

2.1. Long-Context and Memory-Augmented LLMs 

One line of work expands the context window to hold an entire interaction history. Frontier models offer 128K–1M token contexts (OpenAI, 2024b; Anthropic, 2024; Gemini Team, Google, 2024), while position interpolation (Chen et al., 2023), NTK and YaRN scaling ActionRAG 

(Peng et al., 2024), and LongRoPE (Ding et al., 2024) extend them further. However, accuracy declines when relevant information lies deep in the window (Liu et al., 2024; Kamradt, 2023), and inference cost rises with context length, so long context alone is insufficient. External-memory systems instead store information around the LLM. MemGPT (Packer et al., 2024) pages between a small in-context working memory and a larger archive, a design productionised by Letta (Letta, 2024). Mem0 and Mem0g (Chhikara et al., 2025) extract structured user facts and retrieve them through a learned policy. A-MEM (Xu et al., 2025) adds agentic links and a self-organising memory graph and Zep (Rasmussen et al., 2025) maintains a temporal knowledge graph for evolving facts. Agentic retrieval systems such as Self-RAG (Asai et al., 2024) and MIRIX (Wang and Chen, 2025) add reflection or multi-agent memory control around retrieval. These systems address the competencies defined by MemoryAgentBench (Hu et al., 2026): accurate retrieval, test-time learning, long-range understanding, and conflict resolution. Their retrieval can nevertheless depend on opaque learned policies or flat similarity lookups that underuse structural signal. 

2.2. Retrieval-Augmented Generation 

Retrieval-augmented generation (Lewis et al., 2020; Guu et al., 2020) conditions an LLM on top-k documents retrieved by a sparse model such as BM25 (Robertson and Zaragoza, 2009) or a dense bi-encoder (Karpukhin et al., 2020; Izacard et al., 2022; Wang et al., 2022; Xiao et al., 2024). Recent embedding baselines include proprietary OpenAI Text-Embedding-3 models (OpenAI, 2024a) and Qwen3-Embedding (Zhang et al., 2025). Stronger pipelines add cross-encoder or LLM re-rankers (Nogueira et al., 2020; Sun et al., 2023), or late-interaction models such as ColBERT and ColBERTv2 (Khattab and Zaharia, 2020; San-thanam et al., 2022). On MemoryAgentBench, dense RAG is competitive for accurate retrieval but underperforms on multi-hop and conflict-resolution questions. Independent chunk scoring misses cross-chunk structure and cannot reliably distinguish semantically similar statements when one supersedes the other. 

2.3. Knowledge Graphs for Retrieval and Reasoning 

A complementary line structures retrieval through graphs or persistent memory. RAP-TOR (Sarthi et al., 2024) builds a tree of recursive summaries, GraphRAG (Edge et al., 2024) extracts an entity–relation graph and summarises its communities for global queries, and LightRAG (Guo et al., 2024) combines local entity and global relation retrieval over a lightweight graph. Cognee (Markovic et al., 2025) optimises the interface between knowl-edge graphs and LLMs for multi-hop reasoning. These approaches can underrepresent specific relational paths through summarization or heuristic expansion. Mem0 (Chhikara et al., 2025) extracts and consolidates salient conversational memories, and its graph variant represents entities and relations to support relational retrieval. A-MEM (Xu et al., 2025) organises memories as Zettelkasten-inspired notes with generated attributes and dynamic links, updating existing notes as new evidence arrives. MemoRAG (Qian et al., 2025) in-stead uses a dual-system architecture: a lightweight long-range model forms global memory and generates draft-answer clues that guide retrieval for a more expressive answering model. 3. ActionRAG 

3.1. Overview 

ActionRAG separates persistent memory construction from query-local retrieval. It assumes that each query touches only a bounded neighborhood of the accumulated interaction graph, so evidence diffusion operates on a query-conditioned subgraph rather than the corpus-level graph. Figure 1 summarizes the online pipeline. 

Offline indexing (§3.2) converts multi-turn interaction histories into a typed entity– relation graph. An LLM extracts typed (head , relation , tail) triples, entity mentions are canonicalized, and entity and triple descriptions are embedded with BGE-M3 (Chen et al., ActionRAG 

2024). Postgres stores the graph, its pgvector indices, and source-chunk back-pointers for every triple.

3.2. Cautious Graph Construction 

The indexer turns an interaction history into an entity–relation graph and records the source chunk for every graph item. Chunks are processed in parallel, but names and types are resolved across the complete batch before the graph is updated. 

Structured extraction and temporal grounding. For each chunk, an LLM emits typed entity mentions and directed (head , relation , tail) mentions with textual descriptions. The current type vocabulary is supplied as a soft constraint, allowing the extractor to introduce a more specific label when no existing type is suitable. Dates, durations, and temporal phrases are retained inside the corresponding entity or relation description rather than represented as graph nodes. When a dialogue has a session timestamp, relative phrases such as “yesterday” or “last week” are converted to absolute dates using that timestamp. The resolved date is stored in the fact description instead of creating a separate node for it. 

Label reconciliation. Free-form extraction improves coverage but can produce several names for the same entity type. Before updating the graph, the indexer groups proposed types using name and description similarity, maps each group to an existing canonical type when possible, and registers unmatched groups as new types. Alias chains are resolved before the resulting type map is applied to the batch. 

Entity resolution. Mentions are resolved after their types have been canonicalized. A unique node with the same normalized name and a compatible type is reused directly. If no exact match exists, the indexer reuses a fuzzy name match only when it is the clear best candidate. All remaining mentions are grouped by normalized name, canonical type, and description similarity. One node is then created for each group before any relations are written, preventing parallel workers from creating duplicate nodes. Resolved entity pairs Mahla Vandrangi 

are stored as typed triples, with repeated observations merged into the same edge. Each graph item retains links to its source chunks, preserving the original evidence. 

Temporal graph summarization. Nodes and relations supported by several mentions are periodically summarized into a single description. Hierarchical summarization retains dates and links to the source chunks, after which the updated description is embedded for retrieval. The graph thus provides a compact semantic representation while the original evidence remains available through these links. 

3.3. Query-Time Evidence Refinement by Graph Diffusion Motivation. Semantic retrieval scores graph items independently. It can therefore re-trieve two strongly matching facts while missing the relation that connects them, simply because the connecting relation is not itself similar to the query. Unrestricted graph ex-pansion has the opposite problem: high-degree entities introduce many generic facts and consume the context budget. ActionRAG treats the initial retrieval as a proposal rather than a final result. It constructs a bounded query-local graph, retroevaluates each proposed item using nearby evidence, removes weak proposals, and exposes useful relations that were absent from the initial set.

4. Experiments 

We evaluate ActionRAG on MemoryAgentBench (Hu et al., 2026), which tests long-term memory through incremental multi-turn interactions. We report its eight deterministic task columns across four competencies: accurate retrieval (SH-DocQA, MH-DocQA, and EventQA), conflict resolution (FC-SH and FC-MH), long-range understanding (Detective QA), and test-time learning (MCC and Recom). All ActionRAG results use the receiver-normalized diffusion method in Section 3.3; unless stated otherwise, all baseline numbers are taken directly from the MAB paper. We compare against the MAB baseline families most relevant to retrieval-based memory: long-context references, simple and embedding RAG, structure-augmented RAG, and agentic memory agents, including HippoRAG-v2 (Guti´ errez et al., 2025). 

4.1. Setup Benchmark and scoring. The eight columns aggregate finer-grained datasets: SH-DocQA and MH-DocQA from RULER, three context-length variants of EventQA, five in-context classification datasets for MCC, Redial for Recom, Detective QA, and four context-length variants each for FC-SH and FC-MH. Following MAB, we use substring exact match for DocQA, EventQA, and fact consolidation, exact match for MCC and Detective QA, and Recall@5 for Recom. We preserve MAB’s within-column aggregation and report the ActionRAG 

unweighted mean of the eight column scores as the “deterministic average.” Tasks requiring an LLM judge are excluded from this aggregate. 

ActionRAG configuration. Each query retrieves the ten nearest entities and ten nearest concrete triples. Entity seeds are expanded by at most two hops and triple seeds by one hop, after which the initial set is capped at 200 items. The query-local graph uses hop bound H=3, distance-decay rate β=1, and minimum traversal cost δ=0 .01. We apply one receiver-normalized solve with direct-evidence weight α=0 .15; no second diffusion round is performed. Items scoring below ε=0 .10 times the maximum refined score are pruned, except for the S=10 strongest initial items, and at most L=5 unseen triples are materialized using Eq. (5). Retrieved graph facts are packed into a 7 ,000-token context. Full retrieval settings appear in Appendix C. Indexing follows Section 3.2 and uses Claude Haiku 4.5 for extraction and graph sum-marization. BGE-M3 ( ∼560M parameters) supplies all embeddings (Chen et al., 2024), and gpt-4o-mini generates the final answers for direct comparison with MAB Table 17. All ActionRAG experiments were run on a consumer Apple Silicon laptop (macOS 26.5.2, Darwin 25.5.0, arm64). In comparison, MAB reports HippoRAG-v2 timings on four NVIDIA L40 GPUs with an AMD EPYC 7713 CPU, so the latency results are not hardware-matched.

5. Conclusion 

ActionRAG combines reconciled graph construction with query-local receiver-normalized diffusion, pruning, and materialization for long-term agent memory. Across eight hetero-geneous deterministic MAB columns, it records the highest reported retrieval-based score on six and an unweighted mean of 55 .1. Component ablations indicate that the best con-figuration combines reconciled, summarized indexing with retrieval-time refinement. Gains center on test-time learning and conflict resolution where weaker MH-DocQA and Detec-tiveQA results expose limits for narrative evidence. It also maintains low query cost and sub-half-second main-evaluation retrieval, while packed context remains nearly constant as the graph grows. Future work can include better algorithms for graph expansion which are more robust to hyperparameter values. Mahla Vandrangi

Appendix D. Retrieval latency protocol 

We measure isolated retrieval, excluding answer generation, on the same Apple Silicon laptop with local Postgres/pgvector and no discrete GPU. Diffusion timing covers 50 MH-DocQA queries after initialization and includes local-graph construction, path scoring, solv-ing, pruning, materialization, and packing, but excludes query embedding. BGE-M3 em-bedding is measured separately at batch size one with normalized embeddings, 20 warm-ups, and 200 measured calls. The reported p99 adds the two component p99 values and we omit concurrent full-retrieval wall time because database and Python scheduling make it more variable.
