Abstract 

Retrieval-augmented generation over text-rich knowledge graphs requires identifying evi-dence that contributes to answering a question, rather than merely matching its textual content. Existing agentic retrievers adaptively balance global search and multi-hop exploration but primarily rely on textual similarity to guide retrieval. We propose CARA, a training-free, 

CA usally guided Retrieval Agent that explic-itly evaluates the causal relevance of retrieved evidence through two complementary criteria: consequentiality, measuring whether adding ev-idence improves answerability, and essentiality, assessing whether removing evidence weakens answerability. CARA integrates these assess-ments with path consistency to guide graph ex-ploration and employs reciprocal rank fusion to aggregate evidence from multiple agents. We evaluate CARA on three STaRK datasets and augment STaRK with ground-truth answers to enable downstream question answering evalu-ation. Experimental results demonstrate that CARA consistently outperforms existing re-trievers. CARA also improves answer quality and faithfulness while examining fewer graph nodes and requiring fewer retrieval operations. These findings demonstrate that causal rele-vance assessment enables more focused and ef-fective agentic graph retrieval, improving both retrieval performance and downstream question answering. 

1 Introduction 

As a promising direction in retrieval-augmented generation (RAG), retrieval over text-rich knowl-edge graphs (KGs) rather than flat documents is increasingly used to help large language models (LLMs) answer questions and ground answers in evidence. Unlike flat document retrieval, KG re-trieval must jointly exploit nodes (breadth-oriented) and traverse along relations (depth-oriented). Bal-ancing between the search breadth and depth is a long standing challenge for KG retrieval (Polonuer et al., 2026). With the advances of agents, several recent studies (Sun et al., 2024; Yu et al., 2025) delegate such tasks to retrieval agents which have autonomy to balance search breadth and depth with-out a pre-specified number of node searches or hops. However, these agents’ retrieval process is driven primarily by textual similarity and graph structure, which can still favor evidence that is only associated with the query but not necessary for answering it. For example, consider the ques-tion, “Which medicine should this patient avoid?” A similarity-based retriever may return a clinical note stating, “The patient currently takes several medicines, including aspirin and metformin,” be-cause it contains many words similar to the query. However, this information does not answer the question. Another record may simply state, “Al-lergy: amoxicillin.” Although this short record has no textual overlap with the question, it provides the key evidence needed to answer the question. This illustrates why textual similarity alone is not enough to make a substantive contribution to the answer. In this study, we advocate for a causal retrieval agent, which has autonomy, but more importantly, is able to retrieve evidence that is “causally relevant” to answering the query, rather than merely textually similar. In this study, we operationalize the causal relevance using two complementary criteria: • Consequential : does adding the retrieved evi-dence materially increase answerability? • Essential : does removing the retrieved evi-dence materially reduce answerability? This operationalization is inspired by recent work on faithful rationale evaluation (DeYoung et al., 2020; Yu et al., 2019). It worthwhile to note that this causal relevance does not focus on the literal “cause-effect” relations, which is only one special case of this broader notion. 1arXiv:2610.22017v1 [cs.AI] 15 Oct 2026 In this paper, we design and implement a 

CA usally guided Retrieval Agent for question an-swering, named CARA , by retrieving causally rel-evant evidence, defined as consequential and es-sential evidence that is directly helpful to answer a query. After global anchoring and during neigh-borhood hop, the retrieval agent invokes a causal reasoning module, asking whether the current hop is consequential and essential for resolving the in-formation need. This reasoning guides the agent’s next decision on whether to continue hopping, to re-anchor globally, or to finish when sufficient support has been found. Our contributions are threefold: (1) we formu-late causal relevance as being consequential and essential, distinguishing answer-bearing evidence from merely textually similar evidence; (2) we in-troduce a training-free prompt-based causal reason-ing module that evaluates the causal relevance from the perspectives of both the current hop and the accumulated path developed so far; and (3) we aug-ment the well-known STaRK benchmark dataset with ground truth answers to the queries (ques-tions), expanding its utility from only evaluating retrieval performance to evaluating both retrieval and question answering performance. 

2 Related Work 

Recent work on retrieval-augmented generation has increasingly moved beyond flat passage retrieval toward structured knowledge, multi-hop reasoning, and autonomous search. Three lines of research are particularly relevant to our work: knowledge-graph retrieval for question answering, causal retrieval and reasoning, and agentic retrieval. 

2.1 Knowledge Graph Retrieval for LLM Question Answering 

Knowledge-graph retrieval represents entities and their relations explicitly, enabling LLMs to access evidence that is distributed across multiple con-nected pieces of information. Representative works include GraphRAG (Edge et al., 2024), KG2RAG (Zhu et al., 2025), GRAG (Hu et al., 2025), G-Retriever (He et al., 2024), SubgraphRAG (Li et al., 2025a), KAR (Xia et al., 2025), GraphSearch (Yang et al., 2025), HybGRAG (Lee et al., 2025), CoRAG (Zheng et al., 2025), and MoR (Lei et al., 2025). These approaches demonstrate the value of com-bining search with graph structure, but they primar-ily determine relevance through textual, relational, or structural compatibility. They do not explicitly ask whether a retrieved piece of evidence is conse-quential or essential to answering the query, which motivates our causal relevance formulation. 

2.2 Causal Reasoning for LLM Question Answering 

A growing body of work incorporates causal rela-tions into retrieval and reasoning. Representative works include CDF-RAG (Khatibi et al., 2025), HCG-RAG (Saouda et al., 2026), CausalAgent (Wang et al., 2026), and CausalRAG (Wang et al., 2025). Although these approaches differ in implementa-tion, they generally associate causality with cause-effect relations, dependency structures, or causal mechanisms represented in the underlying knowl-edge. Our notion is different. CARA does not require a retrieved edge or node to represent a lit-eral cause-effect relation. Instead, we define causal relevance at retrieval time in terms of whether evi-dence is consequential and essential for answering the query. Thus, our focus is not causal structure in the world being described, but the causal con-tribution of retrieved evidence to the answering process. 

2.3 Agentic Retrieval for LLM Question Answering 

Agentic retrieval turns retrieval from a fixed pipeline into an adaptive decision process. Rep-resented works include ReAct (Yao et al., 2023), AvaTaR (Wu et al., 2024a), MA-RAG (Kumar and Jain, 2025), SEMA-RAG (Huang et al., 2026), and OmniSearch (Li et al., 2025b). Several re-cent methods extend agentic retrieval to knowledge graphs, including Tree-of-Traversals (Markowitz et al., 2024), Think-on-Graph (Sun et al., 2024), Think-on-Graph 2.0 (Ma et al., 2025), RoG (Luo et al., 2024), Search-on-Graph (Sun et al., 2026), and Explore-on-Graph (Yan et al., 2026). Together, these methods establish graph retrieval as an adap-tive search process in which an agent can decide where and how far to traverse. However, existing agentic retrieval approaches are primarily based on textual similarity instead of causal retrieval we advocate for. 3 Method: CARA over Knowledge Graph 

The overview of CARA (CA usally guided 

Retrieval Agent) is in Figure 1. We study agentic retrieval over a knowledge graph G =

⟨V, E, ϕ V , ϕ E , d V ⟩, where V and E denote entities and edges, ϕV and ϕE assign a type to each node and relation, and dV (v) denotes the text attributes associated with node v, such as titles, descriptions, or other metadata. Given a natural language query (or question) Q, retrieval is formulated as a process in which an agent A = ⟨LLM , T , C⟩ interacts with the graph through two retrieval tools T and a causal reasoning module C. The retrieval tools include: 1) GlobalSearch that conducts global node search and 2) Neighbors that conducts one-hop neighbor-hood exploration. The causal module C is neither an independent agent nor a tool. It is an LLM-based reasoning and assessment module embedded within an agent. It analyzes the candidate nodes returned by the Neighbors tool and provides causal assessments that inform the agent’s subsequent de-cisions and actions. 3.1 Retrieval Tools 

For an agent, there are two retrieval tools: 1) Glob-alSearch for seed nodes search (breadth-oriented search) and 2) Neighbors for one-step hopping along the relations (depth-oriented search). 

GlobalSearch retrieves the k highest-scoring nodes in the entire graph for an agent-generated subquery q based on the original Q:

G(q, k ) = Top -kv∈V rel (q, d V (v)) . (1) We implement rel () using BM25 (Robertson and Zaragoza, 2009) over an inverted index of node text attributes dV (v). The agent-generated subquery q can evolve throughout exploration, al-lowing the agent to issue focused retrieval requests based on the trajectory state st. Global search is a breadth oriented search over KG, providing broad entry points into the graph or re-anchoring points when a local path becomes unproductive. 

Neighbors retrieves adjacent (one-hop neighbor) nodes subject to optional node- and edge-type con-straints Ft = ( FV,t , F E,t ) selected by the agent. The result is a filtered set NFt (vt) of one-hop neigh-borhood of the current node vt. To further trim this filtered set, this Neighbors tool conducts another BM25 search to keep the top k from this filtered set: 

Nt = Neighbors( vt, q t, F t)= Top -ku∈NFt (vt) rel (qt, d V (u)) . (2) Here Nt = {u1, . . . , u k} denotes the candidate neighbors retrieved at hop t. The repeated applica-tions of the Neighbors tool compose into multi-hop traversal. GlobalSearch remains available along the way for re-anchoring. Unlike traditional non-agentic retrieval, the number of hops is not speci-fied in advance. Instead, the agent decides whether 3to continue hopping, re-anchor globally, or finish based on the accumulated evidence. It is notewor-thy that each candidate neighborhood node ui, will further be passed through the causal reasoning mod-ule C before the agent chooses its next action. 

3.2 Causal Reasoning Module 

Neighbors retrieval identifies nodes that are struc-turally adjacent and textually similar to the current exploration state. However, neither graph adja-cency nor textual similarity guarantees that a can-didate node provides evidence that materially con-tributes to answering the query. Therefore we in-troduce a causal reasoning module C that evaluates each candidate according to its consequentiality and essentiality for resolving the information need. Given the candidate set Nt = {u1, . . . , u k} re-turned by the Neighbors tool, the module receives the query Q, the current node vt, the candidate nodes Nt, their connecting relations, and the accu-mulated paths Pt+1 . Unlike literal causal reasoning that seeks cause-effect relations in the underlying domain, our notion of causal relevance is retrieval-oriented: evidence is considered causally relevant when its presence or absence materially affects the ability to support an answer to Q. This opera-tionalization is motivated by two complementary properties: consequentiality and essentiality. For each candidate ui, the module C estimates a consequentiality score ci ∈ [0 , 1] and an essential-ity score ei ∈ [0 , 1] . Consequentiality asks whether incorporating the candidate node and its associated hop materially changes the evidence available for answering the query. It captures the candidate’s in-cremental answer contribution, rather than simply its textual similarity. The LLM is therefore asked whether adding ui,together with its relation to vt, introduces informa-tion that substantially strengthens or advances the answer. Essentiality instead asks whether removing the candidate evidence from the currently available evidence would materially reduce the ability to justify an answer. More directly, the LLM is prompted to reason counterfactually: if this candidate node and its con-necting relation were unavailable, would an im-portant part of the evidence needed to answer the query be lost? A high ei therefore indicates that the candidate carries information that is difficult to replace with evidence already contained in the current trajectory. We combine these two judgments into a node-level causal relevance score: 

cau i = λc i + (1 − λ)ei, (3) where λ ∈ [0 , 1] controls the relative emphasis on consequentiality and essentiality. Importantly, cau i

should not be interpreted as a probability that a literal causal relationship exists between vt and ui.Rather, it measures whether the candidate evidence has a materially incremental and counterfactual contribution to answering Q.Causal relevance alone, however, evaluates a can-didate primarily with respect to the query and the evidence currently available. In multi-hop retrieval, a locally useful candidate may still lead the agent away from the reasoning trajectory developed so far. We therefore introduce a separate path consistency score pi ∈ [0 , 1] . Unlike cau i, which measures the node-level contribution to answering the query, 

pi evaluates whether the transition vt → ui forms a coherent continuation of the accumulated path developed so far. In particular, the module exam-ines whether the relation connecting vt and ui is compatible with the information need represented by the current trajectory and whether following this candidate preserves a plausible chain of evidence toward the answer. The final score for candidate node ui is: 

st(ui) = αcau i + (1 − α)pi, (4) where α ∈ [0 , 1] controls the relative importance of node-level causal relevance and the trajectory-level consistency. The highest-scoring candidates are returned to the retrieval agent. Importantly, the causal reasoning module C is an assessment module rather than an autonomous agent. It does not independently invoke Glob-alSearch or Neighbors . Instead, its assessments enhance the information presented to the retrieval agent and therefore influence subsequent search de-cisions. Based on the causal and path-consistency assessments, the agent may continue along a promising neighborhood path with Neighbors , re-formulate the subquery, modify node or relation filters, re-anchor through GlobalSearch , Append 

nodes to the retrieved set, or terminate with Finish 

when additional exploration is unlikely to provide consequential evidence. In this way, causal rea-soning affects not merely the reranking of already retrieved nodes, but the direction and termination of the retrieval process itself. 43.3 Aggregation of Each Agent Result 

To improve robustness and reduce dependence on a single retrieval trajectory, we run multiple agents in parallel. Each agent j independently interacts with the knowledge graph, producing a retrieval trajec-tory τ (j) and an ordered list of retrieved nodes R(j).Independent trajectories may differ in their initial anchors, generated subqueries, neighborhood ex-pansions, and traversal decisions. Such diversity allows different agents to explore alternative paths through the graph and reduces sensitivity to any single search trajectory. Rather than directly concatenating the node lists from different agents, inspired by the classic idea of reciprocal rank fusion (RRF) (Cormack et al., 2009), we aggregate them in the following way. For a candidate node u, its cross-agent fusion score is:

First, it rewards high within-agent rank. Second, it re-wards cross-agent consensus. Thus, evidence that is repeatedly identified across different trajectories receives stronger aggregate support than evidence found by only one trajectory. The final candidate set is formed from the union of the nodes retrieved by all agents, ranked in descending order of their RRF scores. In the rare case that two nodes receive identical RRF scores, the node with the better best rank across agents is placed first. 

4 Experiment Setup 

We evaluate CARA from two complementary per-spectives: retrieval performance and question an-swering performance. 

4.1 STaRK and Ground-Truth Answer Augmentation 

We evaluate on the three text-rich knowledge graphs in the well-known benchmark STaRK (Wu et al., 2024b). It contains three datasets: AMA-ZON, MAG, and PRIME. AMAZON represents an e-commerce domain, MAG a scholarly domain, and PRIME a biomedical domain. STaRK pro-vides natural-language queries Q together with ground-truth entities relevant to answer Q, allow-ing retrieval systems to be evaluated against known nodes. However, it does not provide a ground truth for evaluating generated answers. We therefore augment STaRK with ground-truth answers. For each query Q, we use the ground truth entities’ text attributes dV (v) and related relations as the source information and employ Qwen3.8-27B to generate answers. We instruct the model in the prompt to satisfy four requirements: Relevance , ensuring that the answer directly addresses Q; Faithfulness , en-suring that all factual claims are supported by the provided entity information; Coverage , ensuring that the names of all ground-truth entities are ex-plicitly mentioned; and Naturalness , ensuring that the answer is fluent and natural rather than enu-merating a list of retrieved entities. After answer generation, we took two extra steps to validate the answers. First, we validate the answer using an automatically calculated indicator Completeness 

defined as the proportion of ground-truth entities whose complete names are explicitly mentioned in the generated answer. If Completeness is be-low a threshold, we prompt the model to regen-erate a new version of answer until it reaches the threshold. We repeat this generation-and-validation process, resulting in more complete ground truth answers. Second, we manually inspect stratified samples (approximately 10% of the generated an-swers) across AMAZON, MAG, and PRIME to validate that the resulting ground truth answers are appropriate across different domains and query types. 

4.2 Baselines 

We compare CARA with conventional retrievers and agentic retrievers used in prior work. The con-ventional retrievers include the classic sparse re-trieval, BM25 (Robertson and Zaragoza, 2009); dense embedding retrieval that rank nodes by cosine similarity, ada-002 (OpenAI, 2022) and GritLM-7B (Muennighoff et al., 2025); knowledge-aware retrieval KAR (Xia et al., 2025) that con-ducts query expansion and applies relation type constraints during retrieval. Agentic retrievers in-clude Think-on-Graph (Sun et al., 2024), which is a training-free LLM agent that iteratively expands paths in the graph using beam search; GraphFlow (Yu et al., 2025), which learns to generate multi-hop retrieval trajectories using GFlowNets (Bengio et al., 2021); and ARK (Polonuer et al., 2026), which has adaptive use of global search and neigh-5borhood exploration but without causal reasoning during graph traversal. All agentic systems (CARA and agentic base-lines), the causal module, the common answer generator use the same open-weight backbone, Qwen3.8-27B, served with vLLM with thinking disabled. The agents’ LLM calls sample with tem-perature 1.0, and all other calls decode greedily. CARA runs m = 3 agents per query (question) with Tmax = 150 steps each; GlobalSearch returns 

k = 30 candidates and Neighbors returns k = 20 .

4.3 Retrieval Evaluation 

We first evaluate the performance of the entity-retrieval task. We report Hit@1, Recall@20, and Mean Reciprocal Rank (MRR). These metrics cap-ture complementary aspects of retrieval perfor-mance: the proportion of a correct entity ranked first, the proportion of ground truth entities success-fully retrieved among the top 20 ranked results, and how highly the first correct entity is ranked overall. 

4.4 Question Answering Evaluation 

We next evaluate whether the retrieved evidence improves downstream question answering. To iso-late the effect of retrieval, all retrieval systems use the same answer generator (LLM, Qwen3.8-27B), prompt, decoding configuration, and context bud-get. The only difference between systems is the retrieved evidence supplied to the answer generator. In this end-to-end setting, each retriever produces its own ranked evidence set, and the common gen-erator answers the question using that evidence. To test whether better retrieval leads to better answers, we evaluate answer correctness using BERTScore (Zhang et al., 2020) between the generated answer and the ground truth answer. We also evaluate an-swer faithfulness using the Ragas framework (Es et al., 2024), measuring whether factual claims in the generated answer are supported by the retrieved context. 

5 Results 

5.1 Retrieval Performance 

As the first step of experiment, we tried different λ

values from 0 to 1 (in Equation 3, balancing conse-quentiality and essentiality) and α values from 0 to 1 (in Equation 4, balancing node-level causal rele-vance and path consistency). It is worthnoting that the setting of λ = 0 or 1 or α = 0 or 1 is equiva-lent to a component-level ablation study. Averaged across datasets and metrics, λ = 0 .5 and α = 0 .5

achieve the highest performance, supporting the selection of these values. Table 1 compares CARA ( λ = 0 .5, α = 0 .5)with conventional and agentic retrievers on the three STaRK datasets. CARA achieves the highest Hit@1 and MRR across AMAZON, MAG, and PRIME, demonstrating its effectiveness in ranking relevant entities. Compared with ARK, its closest agentic baseline, CARA’s improvements are par-ticularly pronounced on MAG, whose questions tend to be relation-heavy. These findings suggest that incorporating causal relevance assessment and the rank-based aggregation into adaptive graph ex-ploration improves retrieval effectiveness across diverse knowledge domains, especially in relation-heavy domains. 

5.2 Question Answering Performance 

Table 2 evaluates the downstream question answer-ing performance of CARA against KAR and ARK using BERTScore and the RAGAS faithfulness. CARA achieves the highest BERTScore across all three datasets, demonstrating that improved re-trieval effectiveness translates into better answer quality. CARA also consistently improves faith-fulness over ARK, with particularly notable gains on MAG and PRIME. Interestingly, KAR achieves the highest faithfulness across all datasets despite substantially lower BERTScore values. This sug-gests that generating answers closely grounded in retrieved evidence does not necessarily guar-antee their correctness or completeness relative to ground-truth answers. Overall, these findings high-light the importance of evaluating both answer qual-ity and faithfulness, and demonstrate that causal-guided retrieval improves downstream question an-swering while maintaining strong evidence ground-ing.

5.5 Efficiency and Exploration Behavior 

Table 4 compares the computational efficiency and exploration behavior of CARA and ARK across three datasets. Interestingly, CARA achieves more focused graph exploration despite introducing an additional causal reasoning module. Compared with ARK (the closest agentic baseline), CARA reduces GlobalSearch calls as well as Neighbors 

calls across the datasets. The number of examined nodes also decreases for the three datasets. These results suggest that causal relevance assessment helps agents identify promising evidence paths while avoiding unnecessary exploration. Compared with AMAZON whose questions are more entity-oriented, MAG and PRIME involve more relation-intensive biomedical questions that require deeper multi-hop exploration. This differ-ence is reflected in CARA’s substantially higher number of Neighbors calls and therefore causal reasoning calls per query, suggesting that causal guidance is particularly important for navigating complex relational structures. However, the addi-tional causal reasoning introduces latency overhead. The particularly pronounced overhead on MAG and PRIME highlights a trade-off between retrieval effectiveness and computational efficiency, suggest-ing opportunities for reducing latency through par-allel or batched causal assessments. 

6 Conclusion 

In this paper, we proposed CARA, a training-free causally guided retrieval agent for question answer-ing over text-rich knowledge graphs. Unlike ex-isting agentic retrievers that primarily rely on tex-tual similarity, CARA evaluates retrieved evidence through consequentiality and essentiality, together with path consistency, to guide graph exploration. Reciprocal rank fusion further aggregates evidence from multiple independent agents. We also aug-mented the STaRK benchmark with ground-truth answers to enable downstream question answering evaluation. Experiments on three datasets demon-strate that CARA consistently improves retrieval effectiveness, while also improving answer quality and faithfulness compared with ARK. Moreover, CARA achieves more focused exploration by exam-ining fewer nodes and requiring fewer retrieval op-erations. However, the additional causal reasoning introduces inference latency overhead, particularly for relation-intensive questions. 8Limitations 

Despite its promising results, CARA has several limitations. First, causal relevance is operational-ized through LLM-based assessments of conse-quentiality and essentiality rather than formal infer-ence. These assessments may be sensitive to model biases, prompting strategies, and errors in evalu-ating evidence contributions. Second, although CARA reduces retrieval operations and examined nodes, the additional causal reasoning module in-creases computational overhead and inference la-tency, particularly for relation-intensive questions. Third, downstream question answering evaluation relies on automatically constructed ground-truth answers and LLM-based faithfulness assessments, which may introduce evaluation noise. Future work will explore more efficient causal assessments and alternative evaluations.

A.2 Prompts of the Causal Reasoning Module 

Prompt of the causal reasoning module C

You are the causal reasoning module C of a retrieval agent that explores a knowledge graph to answer a query. You are an assessment module, not an agent: you do not search the graph and you do not choose the agent’s next action. The agent has just used the Neighbors tool on the current node; assess each returned candidate node. 

What “causal” means here 

* Causal relevance is retrieval-oriented. Evidence is causally relevant when its presence or absence materi-ally affects the ability to support an answer to the query. It is not a cause-effect relation in the domain. 

Task You are given four inputs: 1. Query Q

* The natural-language query the agent is answering. 

2. Accumulated paths Pt+1 

* The paths the agent has traversed so far, ending at the current node. 

3. Current node vt

* The node the agent has just expanded, with its type and text description. 

4. Candidate set Nt = {u1, . . . , u k }

* The candidate neighbors returned by Neighbors , each with its type, its connecting relations to vt and its text description. 

Assess every candidate ui with three scores in [0 , 1] .

1. Consequentiality ci: the candidate’s incremental an-swer contribution. 

* Would adding ui, together with its relation to vt, in-troduce information that substantially strengthens or ad-vances the answer to Q, beyond what the accumulated paths already provide? * This is not textual similarity: a candidate that repeats known evidence, or is only on the same topic as Q, scores low even if it shares many words with Q.2. Essentiality ei: the counterfactual loss without the candidate. 

* If ui and its connecting relation were unavailable, would an important part of the evidence needed to answer Q be lost? * This is not the general importance of the node: score high only when the evidence is difficult to replace with evidence already contained in the current trajectory, and low when an equivalent piece is already on a path. 3. Path consistency pi: the coherence of the step vt → ui.

* Does the transition form a coherent continuation of the accumulated paths? Is the connecting relation compatible with the information need in Q (required entity types, rela-tions and named entities), and does following ui preserve a plausible chain of evidence toward the answer? * This is not mere adjacency: every candidate is already a neighbor of vt.

Scoring Scale (the same for all three scores) * 0.0–0.2: unrelated or fully redundant with the accumu-lated paths. * 0.3–0.4: weak. 0.5–0.6: moderate. 0.7–0.8: strong. * 0.9–1.0: decisive, e.g. the answer entity, an indispens-able bridge, or evidence without which Q cannot be an-swered. 

Rules 

1. Neither adjacency nor textual similarity is evidence by itself. 

* Candidates are listed in the order the Neighbors tool returned them; this order carries no evidential weight. 2. Use only the given inputs. 

* Base every score on the query, the accumulated paths, the connecting relations and the candidate descriptions. 3. Assess each candidate independently. 

* The scores need not sum to anything. Do not predict the final answer. 4. Assess every candidate. 

* Return a line for every candidate, including irrelevant ones, which receive low scores. 

Output Format 

Return one line per candidate, in the given order: node_index | ci | ei | pi

Do not output anything else.
