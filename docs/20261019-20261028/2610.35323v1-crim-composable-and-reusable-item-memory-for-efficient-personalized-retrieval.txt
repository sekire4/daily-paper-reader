## Abstract 

Large language models incur substantial training and inference costs in personalized search and recommendation, as growing in-teraction histories lengthen request inputs and repeatedly expose the same item text to the model. We propose Composable and 

Reusable Item Memory (CRIM), a framework that separates item-level semantic encoding from request-level history modeling. A small set of learnable summary tokens compresses each item into compact continuous memories, while segment-level readout to-kens (REC tokens) introduce predictive supervision within the interaction history. These memories are independent of users and queries and can therefore be reused across requests. At inference time, CRIM composes cached memories in interaction order and incorporates an optional query to produce a personalized retrieval representation, reducing repeated item-text encoding while retain-ing request-dependent contextual modeling. We further introduce a joint training mechanism that combines cached memories with sampled live re-encoding. Re-encoding only a few history items per request allows the retrieval objective to jointly optimize the item and request encoders at limited computational cost, while periodic cache refreshes maintain consistency. Extensive evaluation and cost analysis on MovieLens-1M, Qilin, and our new LazSeq dataset show that CRIM achieves state-of-the-art retrieval performance with sub-stantially lower inference costs at the same backbone scale, while limiting item re-encoding during joint training. We will publicly release our code and dataset.

## 1 Introduction 

Personalized Web search and recommendation retrieve relevant items from large catalogs using a user’s ordered interaction his-tory and, when available, a current query. Large language models provide rich semantic representations of items and queries, but growing histories increase both training and inference costs. Re-peatedly encoding the same items across users and requests adds further overhead. Efficient personalized retrieval therefore requires addressing three challenges: reusing item semantics while retaining request-dependent contextual modeling; preserving both semantic information and interaction patterns in compressed representations; 

> 1arXiv:2610.35323v1 [cs.IR] 26 Oct 2026 Li et al.

and jointly optimizing item and retrieval encoders when cached representations reduce the amount of differentiable computation. Existing methods address different aspects of these challenges. Recformer [24] jointly models item text and interaction sequences, while processing history text for each request. Token Factory [5] converts heterogeneous features into soft tokens and compresses recommendation inputs, and ICAE [13] learns compact memories through autoencoding and language modeling. These approaches demonstrate the value of compression. For personalized retrieval, however, an item representation must also remain useful when composed into different histories, and text reconstruction alone does not directly supervise interaction patterns. Representation caching offers a complementary way to reduce repeated computa-tion. GNNAutoScale [11], for example, reuses historical embeddings in graph neural networks. Applying caching to language-model-based item encoding requires coordinating encoder updates with the gradient paths available through cached representations, with-out allowing full-history re-encoding to consume the savings from reuse. Our central idea is to separate stable item semantics from dy-namic request context. We propose Composable and Reusable Item 

Memory (CRIM). An item memory encoder (IME) independently maps each item to a compact block of continuous memories shared across users and requests. A request encoder (RE) composes these blocks in interaction order and incorporates an optional query to generate a personalized retrieval representation. This design moves repeated item-text encoding offline while preserving contextual modeling of the current history and information need. Preserving item-text semantics allows retrieval to use the LLM’s pretrained semantic knowledge alongside learned interaction patterns. To support semantic compression and sequence learning to-gether, CRIM combines learnable summary tokens with segment-level readout tokens, termed REC tokens. Summary tokens en-code each item’s semantics into a small number of continuous vectors. REC tokens read out intermediate history prefixes to pre-dict subsequent interactions, introducing supervision throughout the sequence. We further develop a joint training mechanism that combines cached memories with sampled live re-encoding. Only a few history positions are re-encoded for each request, allowing retrieval gradients to update the IME through those positions. The remaining positions reuse cached memories and participate in RE training. Periodic refreshes keep the memory cache aligned with the evolving encoder. This mechanism allows item memories to adapt to the retrieval objective while limiting the cost of re-encoding long histories. We introduce LazSeq, a benchmark for query-conditioned re-trieval with approximately 30,000 requests, a shared catalog of 49,993 distinct items, and histories of up to 500 interactions. To-gether with MovieLens-1M (ML1M) [14] and Qilin [4], it supports an extensive evaluation across retrieval methods and task set-tings. CRIM achieves state-of-the-art retrieval performance. Com-pared with the Qwen3-Embedding-4B baseline [37], it improves Re-call@100 by 2.49% on LazSeq and 33.61% on ML1M, and NDCG@100 by 5.64% on Qilin, all measured as relative improvements. As shown in Figure 1, CRIM combines strong retrieval quality with lower la-tency and fewer serving tokens on LazSeq at the same backbone scale. Our cost analysis relates offline investment and request com-putation to the volume of requests that reuse item memories. Our contributions are fourfold: 

• Composable and reusable item memory. We propose a novel framework that separates item-level semantic en-coding from request-level history modeling, enabling reuse across requests while retaining personalized contextual modeling. 

• Semantic compression with sequence supervision. We combine summary tokens for compact item representa-tions with REC tokens that introduce predictive supervision within interaction histories. 

• Efficient joint training. We combine cached memories with sampled live re-encoding, allowing item memories to adapt to the retrieval objective while controlling re-encoding costs. 

• LazSeq and comprehensive evaluation. We introduce a long-history retrieval dataset and evaluate retrieval quality and computational efficiency across three datasets, sup-ported by a cost analysis of memory reuse. 

## 2 Related Work 

Language models for personalized retrieval. Recformer [24] orga-nizes item attributes as text sequences and jointly learns language representations and interaction patterns. TIGER [29] maps items to semantic identifiers and autoregressively predicts the next item. GEMS [38] unifies search and recommendation through gradient subspace decomposition that coordinates task-specific optimization signals. Related adaptation methods include LiRA [22], which aligns low-resource languages in a shared semantic space for multilingual retrieval, and AgentDet [21], which coordinates detection agents through a shared blackboard and knowledge base for zero-/few-shot object detection. CRIM focuses on repeated item encoding in long histories, using shared item memories to support request-dependent composition and integrate history with an optional query in a dense retrieval framework. 

Context compression and reusable item representations. Prefix-tuning [25] and prompt tuning [19] learn continuous task prompts. Context compression instead encodes input content: LLMLin-gua [17] prunes prompt tokens, while continuous compressors retain information from long text in a small set of vectors. ICAE [13] learns compact memory slots through autoencoding and language modeling, while EBMC [6] pretrains a decoupled compressor using text reconstruction and completion. For industrial recommendation, Token Factory [5] maps heterogeneous features to soft tokens and compresses behavioral inputs. Dual-purpose Semantic IDs [20] combine discrete encoding with on-demand vector reconstruction to reduce item representation storage and transfer costs. CRIM uses individual items as the unit of reuse: summary tokens retain item semantics, and REC tokens introduce prediction objectives within interaction histories so that compact memories support composition and retrieval across users.

## 3.3 Sequence-Aware Memory Composition 

Independent item memories retain item semantics, while personal-ized retrieval additionally requires modeling interaction order and evolving interests. The RE therefore composes memories chronolog-ically and uses segment-level supervision to learn representations of different history prefixes. The memory vectors enter the RE as continuous input embed-dings through a learnable residual mapping. For the 𝑘 -th memory vector 𝑧 𝑖,𝑘 of item 𝑖 ,¯𝑧 𝑖,𝑘 = 𝑧 𝑖,𝑘 + 𝑊 in 𝑧 𝑖,𝑘 + 𝑎 𝑘 , (4) where 𝑊 in is a residual projection and 𝑎 𝑘 is a learnable within-item memory-position embedding. Both are initialized to zero, so the RE initially receives the original memories and gradually learns an input representation suited to history modeling. We divide the history into 𝐽 = ⌈𝑁 /𝑏 ⌉ contiguous segments of at most 𝑏 items. A shared set of learnable segment readout tokens, termed REC tokens, is inserted after each segment. History memo-ries use causal attention. The REC tokens of segment 𝑗 can attend to all memories up to that segment and earlier REC tokens within the same readout block. Subsequent history memories, query tokens, and the final retrieval position do not attend to REC hidden states. This provides additional supervision positions while preserving direct interactions among history memories. For query-conditioned retrieval, query tokens follow the history and can attend to all history memories. The final EOS hidden state passes through a representation adapter and normalization to pro-duce 𝑢 . Inserting REC tokens does not advance the position indices of subsequent memories and query tokens, preserving their original positional relationships. ## 4 Experiments 4.1 Experimental Setup 

Datasets. We evaluate on LazSeq, Qilin, and MovieLens-1M (ML1M). LazSeq and Qilin support query-conditioned personalized retrieval, where a model combines the user history and current query to predict a target item. ML1M supports sequential recom-mendation without an explicit query. Each request contains one target. History lengths are capped at 500 for LazSeq and 100 for Qilin and ML1M. All ML1M methods use the same request-level data protocol, without expanding history prefixes into additional training examples. Appendix A.2 gives dataset statistics, loading details, and checkpoint-selection protocols. 

Baselines. All baseline results are obtained from our own re-productions, and we will release the corresponding code. We compare three groups of methods. The ID-based group con-tains GRU4Rec [15], NARM [23], STAMP [26], SASRec [18], BERT4Rec [32], S3Rec [39], LightSANs [10], SINE [33], and FEARec [7]. Generative retrieval and language-model recommen-dation methods include TIGER [29], LlamaRec [36], GenSAR [30], and GEMS [38]. The dense text encoders include GTE-1.5B [2], E5-Mistral-7B [34], Gemma3-4B (pretrained and instruction-tuned), Llama3.1-8B, Ministral-8B-Instruct, Phi-4-14B, Qwen3-4B, and Qwen3-Embedding-0.6B and -4B. Qwen3-Embedding-4B shares CRIM’s backbone and is the main reference for examining memory compression and computational cost. ID-based methods use history item IDs. CRIM and query-aware dense encoders receive history item text and the query on LazSeq and Qilin. TIGER, LlamaRec, GenSAR, and GEMS use implementa-tions adapted to the current retrieval tasks. Dense results use the corresponding LoRA-trained checkpoints. 

Evaluation. We evaluate retrieval over the complete valid item catalog, retaining items that already occur in the user history. Recall@ 𝐾 and NDCG@ 𝐾 measure target retrieval and ranking quality. Results are averaged across test requests. We additionally report MRR@100, assigning zero to targets ranked below 100, and full-catalog MRR where available. Beam-limited runs without com-plete ranks do not report full-catalog MRR. 

Implementation. We train with eight NVIDIA A100-80GB GPUs. CRIM uses Qwen3-Embedding-4B in BF16 with LoRA rank 16 for both encoders. A shared set of 𝐾 = 4 summary tokens produces four memory vectors per item. Each history segment contains 𝑏 = 4items followed by 𝑅 = 4 REC tokens. The re-encoding budget is 𝜅 =

8 on LazSeq and 𝜅 = 4 on Qilin and ML1M, and item memories and trainable candidate caches are refreshed after each epoch. Semantic pretraining uses a KL weight of 0.1. Joint training uses a learning rate of 10 −4, temperature 0.05, segment loss weight 1, and semantic reconstruction weight 0.1. On LazSeq and Qilin, joint training runs for at most three epochs with a global batch size of 64. The retrieval loss is computed within logical groups of at most eight target items. ML1M uses at most ten epochs with batch size eight, a mean readout from the final REC block, fixed pooled candidate encodings, and an additional title-generation loss. Its retrieval negatives also include catalog-sampled items. Table 5 in Appendix A.2 gives the full configurations. 

## 4.2 The LazSeq Dataset 

We construct LazSeq for personalized search with long interaction histories. Each request contains an ordered history, a current query, and a target item; history and target items have shared IDs and titles. Repeated interactions are retained. A shared item catalog supports the study of semantic reuse across requests. 

Scale and characteristics. LazSeq contains approximately 30,000 requests with up to 500 history interactions each. Its shared catalog comprises 49,993 distinct items from history and target positions. CRIM uses 23,999 training requests, 3,000 validation requests, and 2,999 test requests. Fixed request splits and a title catalog support reproducible comparisons. Figure 6 in Appendix A.1 illustrates query–history filtering and catalog construction; the appendix also details the request splits. 

## 4.3 Retrieval Results and Comparative Analysis 

Tables 1–3 compare CRIM with sequential, generative, and dense retrieval methods. We report Recall, NDCG, MRR@100, and full-catalog MRR, with cutoffs shown in the tables. Relative improve-ments use unrounded results. Appendix A.4 compares method groups and additional ranking cutoffs. 

Long-history retrieval on LazSeq. CRIM achieves the highest Re-call@50, Recall@100, and Recall@1000, reaching 0.5835, 0.6969, and 0.9330, respectively. These values improve over the strongest base-line at each cutoff by 0.49%, 2.43%, and 0.83%: Qwen3-Embedding-4B at 50, GTE-1.5B at 100, and Phi-4 at 1000. ## 5 Conclusion 

We presented CRIM, a personalized retrieval framework that sep-arates reusable item semantics from request-dependent history modeling. Summary tokens compress items into continuous memo-ries, and REC tokens provide predictive supervision within ordered histories. Cached memories and sampled live re-encoding jointly train the IME and RE with a small differentiable item-encoding budget. Across LazSeq, Qilin, and ML1M, CRIM achieves strong candidate recall and ranking quality. On LazSeq, it reduces serving input length by 80.75% and delivers a 4 .05 × latency speedup over the same-scale dense reference.

## A Implementation and Evaluation Details A.1 LazSeq Construction 

Figure 6 summarizes the filtering and catalog construction steps. 

Request filtering. We retain requests with at least 100 original interactions and a lexical query–history overlap of at least 0.5, keeping the most recent 500 history items. To compute overlap, the query is lowercased and split on whitespace, discarding tokens of length one. The score is the fraction of retained query tokens appearing in the concatenated recent history titles. Requests may target either an item already present in the history or a previously unseen item. 

Catalog construction and splitting. We aggregate eligible requests and count item occurrences in target and retained history positions. These frequencies determine the retained item set; requests are kept if their target belongs to this set. We then fill training, validation, and test splits in processed stream order at an approximate 8 : 1 : 1 ratio. Item frequencies are computed before splitting. The final shared catalog is the union of retained item IDs appearing in the three output splits. This request-level protocol provides a common candidate space across splits. 

## A.2 Training and Evaluation Protocols 

Model configuration. Table 5 gives the training settings. Figures 3 and 4 detail semantic pretraining and joint training. The backbone has hidden dimension 2,560. LazSeq semantic pretraining runs for five epochs with 32 items per GPU, summary learning rate 3 ×

10 −3, identity learning rate 5 × 10 −4, cosine decay, and 5% warm-up. A 128-dimensional identity embedding projects to two prefix tokens; item titles are capped at 96 tokens. Each segment uses up to 1,024 catalog negatives. Joint training uses weight decay zero and gradient clipping at one. The LazSeq ablations use eight GPUs with the same global batch and logical contrastive groups. The cache-refresh variants refresh candidate vectors every epoch. LazSeq and Qilin use the EOS readout and joint objective above. The queryless ML1M configuration uses the mean hidden state of the final REC block for the request representation and fixed pooled candidate encodings. It additionally uses a target-title gen-eration loss and catalog-sampled retrieval negatives. Section 4.1 summarizes these settings. 

Data and checkpoint protocols. Qilin has 7,144/893/893 train-ing/validation/test requests and 159,477 catalog items; ML1M has 3,437/429/431 requests and 3,566 items. Each dataset uses a shared title catalog. LazSeq counts are given in Section 4.2. LazSeq is split at the request level, and a user can occur in multiple splits. Catalog membership is determined before the request split, while model training uses training requests. Filtering the retained catalog may shorten a history below the original 100-interaction eligibility threshold. The selected CRIM epochs are 3, 2, and 7 for LazSeq, Qilin, and ML1M. Checkpoint selection uses validation Recall@3000, Re-call@3000, and Recall@10, respectively. LazSeq ablations select validation Recall@3000, then evaluate the selected checkpoint once on the test set. Full MRR is unavailable for the beam-limited TIGER and GenSAR runs. Method years in the tables indicate publication or specific model release.

Figure 1 measures five warm-ups followed by two passes over 200 fixed requests at batch size one. The cache is built before timing. The request path includes input preparation, encoding, cosine retrieval over 49,993 candidates, and returned IDs. Backbone operations use BF16; the stored serving memories and candidate vectors use FP32. The serv-ing cache occupies 2.560 GB for CRIM, comprising 2.048 GB of item memories and 0.512 GB of candidate vectors. Dense reference can-didates occupy 0.512 GB. The online costs are 90.66 and 368.32 ms per request. These esti-mates cover optimizer computation, initial cache construction, and inference with a fixed model and catalog. For a cache-refresh or model-update schedule, the corresponding measured maintenance cost enters Δ𝐶 off in Equation (11). Each additional GPU-hour of relative offline cost requires approximately 12,965 further requests to amortize at these request costs. For the service-volume inset in Figure 5, monthly and annual totals are divided by 30 and 365, respectively. Starred per-second rates are multiplied by 24 × 60 × 60 = 86 ,400, the number of seconds in a day. They represent daily equivalents at the reported rates.
