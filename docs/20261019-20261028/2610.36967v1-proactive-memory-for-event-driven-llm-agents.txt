Abstract 

Proactive LLM agents anticipate service opportunities from ongoing observations and accumulated history. Existing approaches emphasize recent context or retrieval of related memories, providing limited support for validating recurring behavioral regularities and assessing their applicability to the current event. We propose Proactive Memory (ProactMem), which organizes history into recent events, temporal trajectories, and behavioral regu-larities. Trajectory facts are checked against source events, and regularities are assessed through historical replay before being matched to current conditions. We also construct ProactiveStream, a longitudinal benchmark covering three application scopes, where agents process isolated event streams chronologically under episode-aware opportunity labels. On ProactiveStream, ProactMem achieves an overall effectiveness (F1) of 52.6%, a 21.4% relative improvement over the strongest of five external baselines. Code is available at: https://anonymous.4open.science/r/ProactMem-5351/.

3 Proactive Memory 

ProactMem uses three complementary memory lay-ers (Figure 2): event memory for recent public events, temporal trajectory memory for source-checked activity summaries, and behavioral reg-ularity memory for replay-assessed conditional reg-ularities. Construction checks source fidelity and historical support. The decision stage combines current observations with applicable historical evi-dence through contextual assessment and interven-tion control.

Replay-assessed behavioral regularity memory. 

Historical replay tests whether a proposed behav-ioral regularity recurs in the recorded observa-tions. Weekly consolidation groups seven com-pleted daily records per entity in time order, with each record assigned to one cycle. A cycle may span more than seven calendar days. An LLM proposes a trigger g, expected behavior p, time window, optional weekday restrictions, and source daily identifiers. Replay checks these conditions against validated daily facts: an observable trig-gered day is fulfilled when p occurs at or after the trigger within the window and violated otherwise. Missing observations are censored, inapplicable days are excluded, and each date contributes at most once. Let nf count fulfilled (supporting) days and nv count violated days:

(6) The base rate is the frequency of p over observable days under the same time-window and weekday restrictions across both triggered and other observ-able days. A zero denominator gives a zero score. Confidence measures consistency across observ-able triggered days, whereas lift accounts for how common the expected behavior is under compara-ble temporal restrictions. A frequently observed activity can yield high confidence even when it also occurs without the trigger. Comparing the two frequencies makes this distinction explicit when assessing a proposed regularity. The support re-quirement further ensures that activation rests on repeated observations across distinct days. A well-formed proposal remains a candidate un-til nf ≥ 3, confidence ≥ 0.5, and lift ≥ 1.0; it then becomes active and available for retrieval. Mal-formed proposals are rejected. 3.3 Proactive decision Contextual assessment and intervention control. 

For each event, the decision context combines the current event, recent events, temporal trajectories, selected regularities, and observable episode state: 

Ct = ( et, S t, W t, R t, Q t), (8) where Qt describes the service opportunity’s ob-servable state; the controller separately records previously allowed interventions to track service coverage. The LLM produces (˜ yt, ˜mt) = πθ(Ct),proposing intervention when the current event or 

historical context supports concrete, timely, feasi-ble, low-risk assistance, and abstention otherwise. For the walking example, a retrieved regularity sup-plies the historical reason to consider a reminder. The assessment then uses recent activity and the current situation to determine whether such assis-tance is timely and feasible. Within each scope, all methods apply the same intervention controller policy to their own context and intervention history. The controller compares proposed services with previously allowed inter-ventions and converts duplicates to abstain . Scope-specific changes in opportunity state, service iden-tity, contextual regularities, or local day permit renewed assessment; each intervention originates from an LLM proposal. The controller finalizes the proposal as (ˆ yt, ˆmt), the output defined in Sec-tion 2. Appendix B.3 specifies matching fields, phase transitions, and re-entry rules. Inference stages et, retrieves prior memory and matches current conditions, assembles Ct for as-sessment, applies intervention control, and com-mits et after finalization. Each complete public event enters the event buffer and open-day buffer, advancing trajectory construction, regularity re-play, and lifecycle updates. Abstained events can still record completed activities, changed circum-stances, or violations of an existing regularity. Stor-ing them preserves the observations needed to re-vise memory as behavior changes. Maintenance incorporating et can affect only later decisions. The current event is therefore assessed against the mem-ory available on arrival, together with its own ob-served content. Reference labels are reserved for offline evaluation.

5.2 Main results (RQ1) 

We compare ProactMem with five external methods on ProactiveStream. 

Comparisons with external methods. Across all three scopes, ProactMem achieves higher ef-fectiveness and balance than the external baselines (Table 2, RQ1). The comparison reflects differ-ent trade-offs across scopes. On Sports, Mem0 attains greater coverage alongside more false in-terventions; ProactMem is more selective, with higher relevance and lower intrusion. On Home, ProactMem recovers more opportunities than every external baseline, with fewer false interventions than the higher-frequency A-MEM and Graphiti. On Code, it likewise obtains the highest cover-age, whereas Mem0 achieves lower intrusion with substantially less opportunity recovery. The gains therefore come with different changes in operating behavior: more selective intervention on Sports and broader opportunity recovery on Home and Code. Appendix D examines reference sensitivity and episode behavior on a separate diagnostic sam-ple. Rescoring fixed diagnostic outputs against separate-team references gives similar effective-ness on Sports and lower effectiveness on Home and Code, indicating that absolute performance de-pends on how actionable opportunities are labeled. 

5.3 Model comparison (RQ2) Within-series model scaling. With all other set-tings fixed, construction and decision LLMs change together (Table 3). Effectiveness increases and in-trusion decreases from GPT-5.6 Luna through GPT-5.6 Terra to GPT-5.6 Sol across scopes. Stronger backbones can improve both the construction of conditional regularities and their use in decisions about the current event. Controlled ablations retain GPT-5.6 Luna. 

Cross-family event-only comparison. Using the shared event-only interface, we compare GPT-5.6 Luna, Gemini 3.8 Flash, DeepSeek V4 Flash, and GLM 5.3 Flash on two selected complete streams per scope (Figure 3; Appendix B.5). On Home and Code, Luna recovers more opportunities than DeepSeek and GLM, while the latter achieve higher specificity. Sports provides a contrast: Luna achieves both higher coverage and higher speci-ficity than DeepSeek. 75.4 Ablation and memory analysis (RQ3) Proactive agent ablation. Figure 4 compares event-only memory, event and trajectory memory, and the full hierarchy using Luna under shared de-cision settings. Trajectories extend activity context beyond recent events, while regularities organize recurring evidence around its conditions of applica-bility. Adding trajectory memory raises effective-ness in every scope, with the largest improvement on Code. Intrusion remains unchanged on Sports and Home and rises slightly on Code, so the gain at this stage lies mainly in opportunity recovery. The full hierarchy improves effectiveness further and lowers intrusion across all three scopes. It re-tains recurring behavior together with its triggers and time windows, allowing earlier observations to inform assessment when the corresponding condi-tions recur. The improvement on both measures is consistent with a useful role for this more selective historical context. These configurations also use representation-dependent intervention keys, so the comparison captures memory retrieval and inter-vention control operating together. 

Memory validation. Source validation checks trajectory fidelity; replay assesses historical sup-port for conditional regularities. Table 4 compares both ablations with the same model and decision settings. w/o replay gate retains current matching and bypasses activation thresholds for well-formed, source-linked candidates reconstructed online. w/o trajectory validation retains schema-valid extrac-tions for the same entity, weekly construction, and replay, omitting fact checks. Both reduce relevance and effectiveness; removing replay yields the larger effectiveness decline. On Code, trajectory valida-tion is associated with fewer false interventions at unchanged coverage (RQ3). 

Intervention control. The Code analysis reveals a trade-off between coverage and selectivity. On recorded proposals, suppression removes more false positives than true positives, improving rele-vance and effectiveness while reducing coverage. Later states and decisions stay fixed (Appendix C). 

6 Related work 

Agent memory. Generative Agents, Memory-Bank, and MemGPT organize experience through reflection, memory updates, or tiered context man-agement (Park et al., 2023; Zhong et al., 2024; Packer et al., 2023). For retrieval, Mem0 uses extracted memories, A-MEM links records, and HippoRAG relies on graphs (Chhikara et al., 2025; Xu et al., 2025; Gutiérrez et al., 2024). Graphiti also tracks when event-derived relations are valid and where they originate (Zep, 2026). 

Proactive agents and memory. ProactiveAgent studies whether to propose a task or remain silent given annotated events (Lu et al., 2025). To antic-ipate service needs, ContextAgent combines sen-sory contexts with historical personas (Yang et al., 2025), and PASK couples streaming demand de-tection with hybrid long-term memory (Xie et al., 2026). MemCog explores memory for dialogue reasoning (Li et al., 2026); Remember When It Matters uses a separate memory agent to supply se-lected reminders for long-horizon action (Wu et al., 2026). ProactMem checks trajectory facts against source events and tests regularities through replay before matching them to current conditions. 

Evaluation of proactive service. LoCoMo and LongMemEval assess long-term conversational memory and reasoning (Maharana et al., 2024; Wu et al., 2025). For proactive agents, bench-marks examine task proposals, latent-need detec-tion, or memory triggering (Lu et al., 2025; Xie et al., 2026; Li et al., 2026). ProactiveStream follows successive intervene or abstain decisions as memory accumulates, using isolated, causally replayed streams and episode-aware references for intervention timing. Interruption costs vary with task phase and user receptivity (Adamczyk and Bailey, 2004; Iqbal and Bailey, 2007, 2008; Mehrotra et al., 2016). We therefore evaluate both opportunity recovery and intrusion. 

7 Conclusion 

We introduced ProactiveStream to evaluate proac-tive assistance over event streams as history ac-cumulates. ProactMem combines recent events, source-checked temporal trajectories, and replay-assessed behavioral regularities, bringing evidence from earlier observations into current decisions. Across Sports, Home, and Code, it achieves higher effectiveness and balance than the eval-uated baselines. The memory ablations further show improved opportunity recovery with trajec-tories and fewer false interventions with the full hierarchy. These results support maintaining his-torical evidence at multiple temporal scales for event-driven proactive assistance. 8Limitations 

ProactiveStream covers low-risk service settings in Sports, Home, and Code under a protocol fixed after joint method and benchmark development. Independent held-out evaluation and cross-family transfer of constructed memory remain future work. Reference labels represent service opportunities under the annotation protocol; the 450-target re-view assesses three selected streams. The Code suppression diagnostic holds later states fixed; controller-free behavior requires a sequential com-parison. Historical replay assesses observed sup-port; prospective validity under changing behavior requires further study. Our offline metrics evalu-ate opportunity detection. Recipient benefit, inter-ruption burden, end-to-end cost, and deployment safety require prospective measurements. The re-ported results support comparisons within the eval-uated protocols, with broader generalization de-pending on additional populations, observation con-ditions, and model families. 

Ethical considerations 

Our evaluation is limited to optional activity sup-port, gentle check-ins, and low-risk repository as-sistance. Medical and high-risk safety decisions require separate domain-specific validation and safeguards. Inference is isolated by stream, and reference labels, episode annotations, and scoring metadata are excluded from model inputs. Longitudinal events and derived memories can reveal sensitive routines even when identifiers are pseudonymized. Event content, prediction traces, and inferred trajectories require access and reten-tion protections; external-model use should limit data transmission and respect source permissions. Deployment should require informed opt-in and allow inspection, correction, deletion, retention control, and disabling proactive assistance. An in-tervention prediction represents a service proposal; consequential action requires separate authoriza-tion. These deployment safeguards require separate implementation and evaluation.

10 A Benchmark and annotation protocol 

A.1 Public events and availability Sports. HeartSteps (Klasnja et al., 2019) sup-plies 1,456 mobile activity meta-events from nine complete participant streams over 367 observed participant-days. Public fields include decision-time availability, recognized activity, recent steps, location category, weather, and local decision slot. Services concern optional activity support. Inputs omit future outcomes and randomized treatments. 

Home. CASAS (Cook et al., 2013) supplies ambient-sensor traces from four homes over 14 consecutive days each. Per local day, ten-minute source blocks are assigned exactly once to 28 reg-ular 50-minute segments and one 40-minute tail, yielding 406 events per home. A segment becomes available only after interval closure and contains within-interval motion counts, room sequences, door actions, and compact numeric summaries. Gentle check-ins exclude disease, fall, travel, dan-ger, and unsupported preference inference. 

Code. Public repository activity, including GH Archive records (Grigorik, 2026), supplies 1,459 events across four repositories with 174 reference interventions. Pushes, issue updates, pull-request actions, and reviews retain GitHub’s native event granularity, with one decision per event. Records are ordered by timestamp and then event ID. Each repository owns isolated memory and intervention state even when contributors overlap. Services cover low-risk triage, review, and maintenance; na-tive PushEvent records enter the stream. 

Public-input contract. Both label classes share the same scope-specific schema: event and stream identifiers, timestamps, and contemporaneously ob-servable fields. Reference labels, candidate flags, episode annotations, memory-level markers, and scoring masks are reserved for evaluation. Evalua-tion includes early events before temporal trajecto-ries or behavioral regularities are available. 

A.2 Reference labels and causal replay 

Annotators apply the opportunity and novelty se-mantics in Section 4.2 to each current event and its complete prior history within the same stream, independently of a tested method’s memory. LLM-assisted triage prioritizes the review queue; three team members independently assign labels while blinded to decisions from the evaluated systems, followed by cross-review and adjudication of every public event. The Home aggregation rule precedes event con-struction. Each evaluation version fixes the event inventory, labels, intervention prompt, event mem-ory bound, and validation settings before main runs on the jointly developed benchmark. Every stream starts from empty method state and is replayed chronologically under the causal execution order in Section 3.3. Current events are committed only after the output is finalized; mainte-nance incorporating an event affects later decisions. Labels are joined offline; reference episode states and scoring metadata are reserved for evaluation.

After admission, confidence combines replay and online counts in a support ratio smoothed with one initial success and failure; censored observations preserve both counts. Two consecutive violations move an active regularity to weakening , lowering retrieval priority; four move it to dormant . A ful-filled observation restores a weakening regularity to active at confidence ≥ 0.5. Dormant regularities return to candidate for replay readmission. 

Current matching. Current matching is deter-ministic. Retrieval admits upcoming, pending, or deviated occurrences of active or weakening regu-larities. Occurrence priority is deviated, followed by pending and upcoming. 

B.3 Intervention control 

In Sports and Home, the intervention key combines scope-specific episode state, proposed service ac-tion and target, and sorted regularity identifiers available in context. Plain summaries or graph facts supply an empty list of regularity identifiers. Sports state includes availability and activity; Home state includes activity and room and onset, confirmed, and sustained phases at one, two, and three or more consecutive matching observations. Without an explicit episode key, scope-specific time or target fields identify the opportunity, with unchanged evi-dence additionally required for duplicate suppres-sion. State changes, sequence restarts, changed service or regularity identifiers, and local-day tran-sitions can generate new keys. Code uses the identity of the repository and ob-ject, along with the most recent allowed interven-tion’s mode, recipient, content, and firing condi-tion. An exact match converts a repeated create 

proposal to abstain ; changed signatures and other episode operations pass this check. Representation-dependent key evidence can yield different suppres-sion decisions across memory interfaces.

D.2 Episode references and matching 

A model-assisted post-hoc analysis on these targets reconstructs episodes defined by service goals and objects from positive event anchors. Each reference specifies a service goal and object, causal evidence, onset, explicitly listed valid observations, and any deadline or closure evidence. Semantic matching uses these fields to associate interventions with reference episodes. 

Matching and follow-up. Episode coverage fol-lows ProactMem’s own interventions, initialized from recorded prefix outputs. Only target inter-ventions are scored. An intervention must match the goal and object at a listed valid observation. Its proposed service time is the decision time plus its specified delay (zero for immediate service), and must meet any explicit episode deadline. The first timely match covers the episode. Each out-put receives at most one credit: the first uncovered compatible episode in the fixed reference order, otherwise the first already covered one. Subsequent matches are compared with the method’s preceding assistance for that episode. A valuable follow-up requires new causal evidence that changes the actionable service or next step, and a message addressing that change. Rephras-ing or continued status alone is redundant; value requiring unobserved delivery, recipient response, or completion remains uncertain. Each reference episode receives coverage credit once. 

Metrics and boundaries. Let I count all target interventions, F first valid interventions across all reference episodes, V valuable follow-ups, R re-dundant follow-ups, and U uncertain follow-ups. New reference episodes have onsets within the tar-get interval. Episode coverage divides covered new episodes by all new reference episodes; supported relevance is SR = ( F + V )/I , and redundant inter-vention rate is RIR = R/I . Uncertain, unmatched, late, and unresolved outcomes contribute only to the intervention count I. Table 9 combines the rates and outcome counts. Episode coverage is highest on Home and low-est on Code; the redundant-intervention share is highest on Home and lowest on Sports.
