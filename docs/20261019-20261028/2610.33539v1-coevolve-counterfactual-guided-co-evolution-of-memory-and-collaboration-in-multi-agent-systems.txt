## ABSTRACT 

Large language model (LLM)-based multi-agent systems have demonstrated re-markable capabilities across diverse tasks. Yet their memory and collaboration architectures often remain static, constraining continued adaptation and improve-ment over time. Recent work addresses this limitation by evolving memory or collaboration based on interaction experience. However, updates to these inter-dependent components are not necessarily aligned: an evolved workflow may require experience that memory does not provide, while evolved memory may encode guidance that the workflow cannot use. To address this problem, we propose CoEvolve, a skill-centered framework for aligned memory–collaboration evolution. CoEvolve represents reusable local collaboration patterns as skills that link evolving collaboration decisions to their supporting memories. It further compares original and counterfactual trajectories to identify local evolution sig-nals, which coordinate updates to the skill library, skill memory, and executor memories across rounds. Experiments on the ALFWorld and WebShop bench-marks confirm that CoEvolve achieves the best overall performance among the evaluated baselines, while ablation studies further validate the effectiveness of aligned co-evolution and counterfactual-guided evolution. Our code is available at https://github.com/MINE-USTC/CoEvolve .

## 1 INTRODUCTION 

Large language model (LLM)-based agent systems have demonstrated strong capabilities on com-plex reasoning tasks and are increasingly deployed in open-ended settings that require long-horizon planning, collaboration, and sustained interaction with the environment (Hao et al., 2026b; Zhang et al., 2026d). Yet the underlying models are typically fixed after training, while the memory and collaboration architectures of many multi-agent systems (MAS) remain unchanged after deploy-ment (Gao et al., 2026). Consequently, these systems have limited ability to incorporate interaction experience and adapt to new tasks, evolving knowledge, or changing environments. To move beyond static designs, recent self-evolving approaches use task outcomes or execution traces to revise persistent MAS components across rounds. One line of work evolves how mem-ory represents, organizes, and retrieves experience. For example, MemEvolve (Zhang et al., 2025a) jointly evolves experiential knowledge and its modular memory architecture, while Mem-Skill (Zhang et al., 2026b) evolves reusable memory operations and their selection. Another line adapts how agents communicate and organize their workflows. GPTSwarm (Zhuge et al., 2024), for instance, optimizes communication graphs, whereas HFlow (Liu et al., 2026b) revises work-flow structures using execution experience and human–agent feedback. EvoChamber (Zhang et al., 2026d) further adapts both individual agents and team organization at test time. Together, these studies show that persistent components can improve from experience. However, memory and col-laboration should not evolve independently because they are mutually dependent. When this dependency is not maintained, a locally useful update may fail to improve overall system behavior. We call this incompatibility cross-component mismatch . As shown in Figure 1(a), memory evolution may produce guidance that a fixed workflow cannot invoke. Conversely, Figure 1(b) shows that collaboration evolution may introduce decisions without sufficient experience in fixed memory. In both cases, collaboration requirements and memory support evolve out of sync. Figure 1(c) illustrates the desired case, where each collaboration capability remains aligned with the memory support required for its decisions. This motivates a shared interface that jointly coordinates the evolution of collaboration and memory. Effective coordination also depends on identifying where updates should occur. Existing evolu-tion signals provide two main forms of evidence for this decision. Performance-driven methods use task-level scores, such as pass rates or final rewards, to search for or select candidate agent systems (Hu et al., 2025; Zhuge et al., 2024; Zhang et al., 2025b). While these scores enable com-parisons between system designs, they provide limited guidance on which local decisions should be improved. In contrast, process-driven methods inspect execution experience to diagnose potential improvements. ReCreate (Hao et al., 2026a) reasons over interaction histories before editing agent scaffolds; Meta-Team (Hao et al., 2026b) organizes distributed evidence through post-task commu-nication; and RetroAgent (Zhang et al., 2026c) uses retrospective feedback to refine agent behavior. Although more informative, these signals remain grounded in the observed trajectory and do not directly test whether replacing a local segment would change the outcome. Decision-level counter-factual credit assignment provides a more direct test by evaluating local alternatives under matched context (Chen et al., 2026). However, identifying an outcome-sensitive segment alone does not indicate how the corresponding collaboration pattern and memory support should evolve together. Building on these analyses, we propose CoEvolve, a counterfactual-guided framework for the aligned co-evolution of memory and collaboration. Keeping the two evolution processes aligned requires a shared unit for local collaboration capabilities and their supporting experience. To this end, CoEvolve represents reusable local collaboration patterns as skills and organizes three evolv-able components around them: a skill library stores executable collaboration patterns, skill memory guides stage allocation, and executor memories support execution. This design supplies new col-laboration capabilities with relevant memory while giving evolved memory concrete decision inter-faces. To obtain evolution signals that indicate where updates should occur, CoEvolve constructs counterfactual trajectories from matched branch points after each round and compares them with the original trajectories. The resulting differences are further localized to identify outcome-sensitive 2pivot segments. These pivot-level signals jointly update the skill library, skill memory, and executor memories, keeping collaboration capabilities aligned with their memory support across rounds. Our main contributions are summarized as follows: • We identify cross-component mismatch as an alignment challenge in self-evolving MAS and propose CoEvolve, which uses skills as shared interfaces to coordinate the evolution of collaboration patterns and their supporting memories. • We introduce a counterfactual signal-acquisition method that identifies outcome-sensitive pivot segments and converts them into coordinated updates to the skill library, skill memory, and executor memories. • We evaluate CoEvolve on ALFWorld and WebShop, where it achieves the highest over-all scores among the evaluated methods, and ablation studies validate the effectiveness of aligned co-evolution and counterfactual-guided evolution. 

## 2 RELATED WORK 

2.1 SELF -E VOLVING AGENTS 

Self-evolving agents adapt based on feedback from their own interactions and execution, rather than relying solely on knowledge fixed at training time. This adaptation is carried by persistent com-ponents that survive across tasks. Early work evolves an artifact as a whole through evolutionary search, without separating its parts: EvoPrompt (Guo et al., 2024) evolves prompts with evolutionary operators; FunSearch (Romera-Paredes et al., 2024) discovers new programs by pairing a language model with an evolutionary loop; and AlphaEvolve (Novikov et al., 2025) iteratively improves algo-rithms through direct code changes. Later work modularizes evolution by targeting a specific com-ponent: on the memory side, MemSkill, MemEvolve, and EvolveMem respectively evolve memory operations, modular memory architectures, and retrieval configurations (Zhang et al., 2026b; 2025a; Liu et al., 2026a); on the collaboration side, HFlow and Meta-Team revise workflow structures and team organization from execution evidence (Liu et al., 2026b; Hao et al., 2026b). Recent studies also coordinate evolution across multiple components (Zhang et al., 2026d; Cheng et al., 2026; Wu et al., 2026), but do not explicitly align evolving collaboration decisions with the memories that support them. CoEvolve targets this cross-component mismatch by treating skills as a shared interface and updating collaboration patterns together with their supporting memories. 2.2 AGENT SELF -E VOLUTION METHODS 

Evolution signals have shifted from task-level outcomes to per-step evidence. Early methods treat the outcome of the entire system as the signal: ADAS (Hu et al., 2025) retains the agentic systems proposed by its meta agent that score higher on the task; AFlow (Zhang et al., 2025b) searches over workflow candidates with Monte Carlo tree search and uses execution results to guide the search; and GPTSwarm (Zhuge et al., 2024) optimizes node prompts and graph edges against downstream task performance. A second group derives per-step signals from execution experience: ReCreate (Hao et al., 2026a) reasons over interaction histories before editing agent scaffolds; Meta-Team (Hao et al., 2026b) organizes evidence through post-task communication; RetroAgent (Zhang et al., 2026c) uses retrospective numerical and linguistic feedback; and tool-interactive critique (Gou et al., 2024) re-vises behavior based on verification feedback. Counterfactual methods compare local alternatives under matched context (Chen et al., 2026) or verify critical steps by testing whether an alternative changes the outcome (Li et al., 2026). CoEvolve uses outcome-sensitive pivots to update a collabo-ration pattern together with the memory that supports it.

Skill. To represent collaboration in a reusable and evolvable form, we model collaboration patterns as skills. As shown in Figure 2, a skill s is defined by its purpose and applicable scenario. To support more complex collaboration, a skill may contain multiple stages, each of which is a finer-grained skill. Stages can be arranged in series or in parallel. New skills can be formed by composing existing skills or created directly. 

Memory. To connect evolving collaboration patterns with the supporting experience, we organize memory around the skill space using skill memory Ms and executor memory Me. In Ms, structural fields identify the skill and context, while evolvable metadata fields specify which experience to store; a skill-specific field separates experience for different collaboration decisions. Me stores stage-level execution experience in success and failure memories. Both memories evolve with the skill space, allowing their support to adapt as collaboration patterns change. 3.3 SKILL -C ONDITIONED TASK EXECUTION

## 4 EXPERIMENTS 

In this section, we first describe the experimental setup, including the datasets, evaluation metrics, and baselines, and then present the experimental results. 4.1 EXPERIMENTAL SETUP 

Datasets. We evaluate CoEvolve on two widely used interactive decision-making benchmarks: ALFWorld (Shridhar et al., 2021) and WebShop (Yao et al., 2022). ALFWorld is a text-based em-bodied environment for household tasks, and we use its valid-unseen split of 134 tasks. WebShop simulates web-based shopping interactions, for which we use the official test set of 500 tasks. Fur-ther details are provided in Appendix C. 

Evaluation Metrics. We report task success rate (SR) on ALFWorld and the purchased-product score on WebShop. We additionally report the average execution length on both benchmarks. 

Baselines. We compare CoEvolve with representative collaboration- and memory-based meth-ods. Collaboration-based baselines include DyLAN (Liu et al., 2024) and MacNet (Qian et al., 2025), while memory-based baselines include ExpeL (Zhao et al., 2024), AWM (Wang et al., 2025), 6EvolveR (Wu et al., 2025), MemEvolve (Zhang et al., 2025a), and AutoGen-GMemory (Wu et al., 2023; Zhang et al., 2026a). Detailed descriptions of the baselines are provided in Appendix D. Un-less otherwise specified, all methods are evaluated using Qwen3-235B-A22B-Instruct-2507 (Qwen Team, 2025); full implementation details and prompts are provided in Appendices E and I. ## 5 CONCLUSION 

In this paper, we introduce CoEvolve as a framework for the aligned co-evolution of collabora-tion and memory in LLM-based multi-agent systems. It represents reusable collaboration patterns through a shared skill space, which provides a common interface for evolving collaboration deci-sions and their supporting memories. The framework further uses counterfactual trajectory com-parisons to identify outcome-sensitive local signals and guide coordinated updates to the skill li-brary, skill memory, and executor memories. Experiments on ALFWorld and WebShop show that CoEvolve achieves the best overall performance among the evaluated methods. Ablation studies confirm that jointly evolving collaboration and memory provides greater gains than evolving either side in isolation, while counterfactual-guided evolution supplies more informative signals for system improvement. Robustness analyses show that these benefits remain consistent across different or-chestrator capacities. Overall, CoEvolve provides a unified approach for evolving how multi-agent systems collaborate together with the experience that supports their collaboration.

## C BENCHMARK DETAILS 

ALFWorld. ALFWorld is a text-based embodied decision-making benchmark that aligns interac-tive text environments with household tasks from ALFRED (Shridhar et al., 2021). Agents observe textual environment descriptions and issue text actions to navigate, find, and manipulate objects. We evaluate on the valid-unseen split of 134 tasks using task success rate, with at most 30 interaction steps per task. 13 WebShop. WebShop is a simulated e-commerce website benchmark for grounded web interac-tion (Yao et al., 2022). Each task specifies a shopping goal; the agent searches for items, inspects product pages, selects options, and attempts a purchase. We use the official 500-task test set and report purchased-product score, with at most 30 interaction steps per task. 

## D BASELINE DETAILS 

We provide detailed descriptions of the baseline methods used in our experiments. 

Collaboration-based methods. We include the following collaboration-based baselines: • DyLAN (Liu et al., 2024) dynamically organizes agent interactions according to task requirements, enabling task-specific collaboration among agents. • MacNet (Qian et al., 2025) coordinates multiple agents through a structured collaboration network that determines how information and intermediate results are exchanged during task execution. 

Memory-based methods. We include the following memory-based baselines: • ExpeL (Zhao et al., 2024) extracts reusable insights from past experience and applies them to improve performance on future tasks. • AWM (Wang et al., 2025) induces reusable workflows from prior experience and retrieves relevant workflows to guide subsequent task execution. • EvolveR (Wu et al., 2025) iteratively refines reusable experience based on feedback collected during interaction and task solving. • MemEvolve (Zhang et al., 2025a) jointly evolves experiential knowledge and the underlying memory architecture, allowing both stored experience and memory organization to adapt over time. • AutoGen-GMemory (Wu et al., 2023; Zhang et al., 2026a) equips multi-agent systems with structured collaboration memory, allowing agents to retain and reuse information from previous interactions. 

## E IMPLEMENTATION DETAILS 

E.1 EVOLUTION CONFIGURATION 

We run CoEvolve for three evolution rounds, sampling 50 tasks from the official training split in each round. No validation/test tasks are used during evolution. Counterfactual trajectories are constructed from at most 20 failed tasks per round. In each round, we generate four candidate skills: two from successful trajectories, one from improved counterfactuals, and one from failure cases. These candidates are evaluated in the following round before being promoted to the skill library. We use Qwen3.5-Plus (Alibaba Cloud, 2026) for the orchestrator and evolution modules, and GPT-4.1-nano (OpenAI, 2025) for the executors during evolution. During evaluation, we use Qwen3-235B-A22B-Instruct-2507 (Qwen Team, 2025) for both the orchestrator and executors of CoEvolve, as well as for all baselines. For memory retrieval, we use all-MiniLM-L6-v2 as the embedding model and set λ1 = λ2 = λ3 = 1 .14 E.2 COMPLETE WORKFLOW
