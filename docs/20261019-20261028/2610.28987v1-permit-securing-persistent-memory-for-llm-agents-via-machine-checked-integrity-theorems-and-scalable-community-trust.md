## 摘要
持久记忆在很大程度上是注入和投毒攻击中缺乏防御的表面，同样的风险限制了智能体之间的记忆共享。我们提出PerMIT，一种在明确信任假设下具有可证明完整性保证的记忆架构：仅信任用户键入的输入和在门控处确认的值。PerMIT通过有限记忆接口对不可信的环境派生值的释放和使用进行中介，同时保留智能体驱动的多轮规划和工具选择。在此有限接口上，我们证明了两条完整性定理，并在Lean 4中进行了机器检验；二者共同确保环境派生记忆只有在门控处确认后才能到达敏感动作，并且仅通过门控显示的内容影响智能体行为。因此，我们威胁模型中的每种攻击都归结为单个可审计决策，实践中可由人类、LLM验证器或二者共同做出。在Trojan Hippo上，PerMIT在自我验证和轻量级验证器下记录到零观察到的攻击成功。由于每次确认都是对确切内容的记录裁决，认可会跨用户累积，获得足够认可的条目成为社区确认项，无需进一步验证。在明确假设下，我们证明并在仿真中验证了一种协同扩展性质：随着社区增长，推广毒害和错误驱逐良性知识的风险下降，而每用户验证工作量不增加。在$τ^2$-bench上，最多90个自主智能体的社区使用PerMIT构建共享知识库，没有直接记忆注入被推广，所得知识显著改善新智能体在留出任务上的表现，这暗示了一条使智能体在测试时安全自我改进的路径。

## Abstract
Persistent memory is a largely undefended surface for injection and poisoning, and the same risk limits memory sharing among agents. We present PerMIT, a memory architecture with provable integrity guarantees under an explicit trust assumption: only user-typed inputs and values confirmed at a gate are trusted. PerMIT mediates the release and use of untrusted environment-derived values through a finite memory interface, while preserving agent-driven multi-turn planning and tool choice. Over this finite interface, we prove two integrity theorems that are also machine-checked in Lean 4, which together ensure that environment-derived memory reaches a sensitive action only if confirmed at the gate and influences the agent's behavior only through what the gate displays. Every attack in our threat model thereby reduces to a single auditable decision, which a human, an LLM verifier, or both can make in practice. On Trojan Hippo, PerMIT records zero observed attack success with self-verification and lightweight verifiers. Because each confirmation is a logged verdict on exact content, endorsements accumulate across users, and sufficiently endorsed items become community-confirmed with no further verification required. Under explicit assumptions, we prove and corroborate in simulation a co-scaling property: as the community grows, the risks of promoting poison and of wrongly evicting benign knowledge fall, while per-user verification effort does not rise. On $τ^2$-bench, communities of up to 90 autonomous agents use PerMIT to build shared knowledge bases with no direct memory injection promoted, and the resulting knowledge significantly improves new agents on held-out tasks, suggesting a path toward agents that safely self-improve at test time.

## 1. 核心问题与研究动机

- **持久记忆是 LLM 智能体最大的未防御面之一**：智能体通过浏览网页、调用工具、读取文件等方式将环境内容写入持久记忆；一旦被注入或投毒，一次性的提示注入可转化为跨会话的持久污染（Trojan Hippo 的“休眠载荷”即典型）。
- **记忆共享进一步放大风险**：现有共享记忆框架（如 Open Knowledge Format, OKF）只定义交换协议，不处理投毒；共享状态还可能造成无攻击者的跨用户污染。安全顾虑因此长期阻碍记忆共享的实际部署。
- **现有防御缺乏形式化保证**：A-MemGuard 依赖推理路径共识、Collaborative Memory 依赖动态读写策略、CaMeL 提供能力隔离与用户确认但把形式验证留作未来工作、FIDES 提供信息流控制但聚焦执行期而非记忆生命周期。它们均未对“持久记忆全生命周期”给出可机检的完整性定理。
- **核心洞察**：把不可信记忆的所有风险收敛到一个**有限、可审计的确认门**上——只有用户键入的值和门控处确认的确切值才被信任；每次确认都是对确切内容的记录裁决，因而可跨用户累积为社区信任，使“安全”与“便利”随社区规模同向提升，而非此消彼长。

## 2. 方法论

### 2.1 核心思想：有限记忆接口 + 确认门

- **角色分离**：受保护智能体 P-LLM 保留规划与工具选择能力；隔离读取器 Q-LLM（实现为 Recursive Language Model, RLM）只能读不可信存储、无工具能力；可信检索器 RE 只读已背书存储。
- **七个记忆操作**：`write`、`recall`、`fill`、`crystallize`、`display`、`confirm`、`evict`。不可信内容以**不透明句柄**暴露给 P-LLM，句柄解析结果（真实值/空/不存在）对 P-LLM 不可区分；只有确认门接受后，才写入一份新的 C 标签副本（原 U 块不变）。
- **标签体系**：T（用户键入）、U（不可信）、C（个人确认）、PC（P-LLM 自组合）、CC（社区确认）；块一旦写入不可变，信任只能通过“显示 + 接受确认”创建新块来提升。
- **确认门展示**：决策面板显示将流动的确切字节、来源（TCB 认证事实区 + 标记为未验证的不可信来源字符串）、用户指令与工具；人类、LLM 验证器或二者共同决策。

### 2.2 两条单用户完整性定理（Lean 4 机检核心）

- **Action Integrity（动作完整性）**：在任意执行、任意攻击下，每个到达敏感工具的参数，要么是用户键入的确切值，要么是该用户为该确切工具、在该次调用或之前确认过的确切字节。形式化上要求每个敏感汇点事件满足“类型化 / 已背书 / 本次门控接受”三选一。
- **Reasoning Integrity modulo the display transcript（显示记录模下的推理完整性）**：对任意两个匹配配置、同一用户键入流、耦合随机性、共同视野的执行，若完整显示记录 DT 相同，则 P-LLM 的操作序列、工具调用、回复流与未门控汇点投影均相同。即隐藏的不可信内容在显示记录固定后没有额外影响。
- **证明结构**：隔离引理（不可信字节只以句柄形式到达 P-LLM）→ 白名单中介引理（敏感工具参数三选一）→ 背书唯一信任提升引理 → 归纳不变式；双执行比较用展开（unwinding）方法，显示段确定性引理保证前缀可比即相等。
- **Lean 4 机检范围**：单用户核心（无运行级 batch 集成）、batch 确认作为独立层、8 个可执行场景；公理报告仅依赖 `propext` 与 `Quot.sound`，无 `sorryAx`。联邦协议、概率界、预算结果仅为纸面证明。

### 2.3 联邦层（PerMIT-Attest）：社区信任累积

- **背书单位**：`(value, tool)` 对；每次确认签名并记录到联邦日志，绑定确切内容与确切工具，不跨工具转移。
- **提升规则**：条目在窗口结束时，若在某一工具上获得至少 N 个来自至少 D_pool 个身份池的新鲜背书，则提升为 CC；每个身份对同一字节串的首次日志决策才计权重（byte-permanent freshness），重复接受不再计权，重复拒绝仍可作为合格拒绝。
- **争议处理**：合格拒绝立即冻结所有工具上的提升并标记条目；需求驱动的面板由前 k 个合格判决组成（默认 k=31, m=20, m_rej=12），达到 m 接受则平反、达到 m_rej 拒绝则驱逐；面板无全局截止时间，按需求节奏推进。
- **毒害提升概率上界**（公式文字说明）：
  - 普通路径项：\((1-q_{pre})^{N-f}\)，即 N−f 个诚实新鲜检查全部漏检的概率；
  - 面板路径项：\(\Pr[\mathrm{Bin}(k-f_s,\,1-q_{pan}) \ge m-f_s]\)，即诚实陪审员中至少 m−f_s 人接受的概率；
  - 总上界 \(B_{att}\) 为两项之和，在部署几何下（q=0.6, N=10, f=2, k=31, m=20, f_s=1）为 \(8.96\times10^{-3}\)（每次提升尝试 0.896%）。
- **错误驱逐上界**：\(\exp(-2\delta_b^2(k-f_s))\)，其中 \(\delta_b = p_b - m/(k-f_s)>0\)；当 \(q+p_b>1\) 且 k 足够大时两个裕度可同时满足。
- **协同扩展定理（Theorem S6.13）**：在明确假设（饱和 \(V(M)=\Theta(M^\beta)\)、时间平滑 A10、覆盖充分 A11、工具跨度有界 A12、每用户需求质量有界 A13、Sybil 界 \(f=o(M^{1-\beta})\)、\(q+p_b>1\) 等）下，选择裕度调度 \(N=f+g_N\)、\(k=f_s+g_k\)，可使毒害提升概率、错误驱逐概率与每用户确认负担同时趋于零/不增。

## 3. 实验设计

### 3.1 数据集 / 场景与 Benchmark

- **Trojan Hippo**：持久记忆投毒的跨会话基准；攻击者控制入站邮件内容，载荷经工具读取后静默存入记忆，经 N 个良性会话后在敏感请求时触发外泄。覆盖金融、健康、法律、税务、身份五类主题；四种记忆后端（Explicit、Mem0、RAG、滑动窗口）+ 无记忆对照；七类良性能力套件，用算术平均 AM 与调和平均 HM 汇总（HM 为主）。
- **联邦层仿真**：120 用户社区、122 条目（含 2 个毒条目）；50 亿次提升尝试；9 种自适应攻击策略（blast、planned-target、stop-on-reject、bank-and-resubmit、target-and-stop、self-dispute、panel-reserved 及两种组合）；相关性 ρ 扫描、面板参数扫描、安全-努力前沿。
- **τ²-bench telecom**：自主智能体社区构建共享知识库，社区规模 M∈{12,24,60,90}；24 个 held-out 任务 × 2 trials = 48 配对 episode；另做 banking 域对照与跨 backbone 迁移实验（Claude-Haiku-4.5，200 步 47 对、400 步 48 对）。
- **Lean 4 机检**：单用户核心定理 + batch 独立层 + 8 个可执行场景断言。

### 3.2 对比方法

- **单用户层**：无防御、仅用户提示、禁用不可信工具、限制记忆长度、可证明策略（provable policy，双标签 IFC）、A-MemGuard、LLM-Auditor；PerMIT 门控配置包括 OpenGate（全接受）、OracleGate（理想正确用户）、LLM 自验证、Qwen-3.5-2B/4B 轻量验证器。
