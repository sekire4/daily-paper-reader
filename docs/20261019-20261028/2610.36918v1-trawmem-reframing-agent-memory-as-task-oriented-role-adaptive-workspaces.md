## 摘要
大语言模型（LLM）智能体依赖记忆系统来利用长期交互，然而现有系统通常根据记忆与当前查询的相关性来检索记忆，并将其作为上下文证据使用。然而，仅凭相关性并不能刻画记忆如何促进任务求解：同一记忆在不同任务中可能扮演不同角色，例如直接支持答案，或链接到语义相关性较弱但包含必要信息的互补记忆。因此，我们将智能体记忆系统重新定义为任务导向的角色自适应工作空间，其中记忆根据其任务导向的角色和关系进行选择与组织。基于这一观点，我们提出 TrawMem，它将交互历史组织为局部线程，并通过分配角色和联合选择互补记忆来构建任务导向工作空间。在 LoCoMo 和 MemGallery 上使用四个开源和闭源骨干模型的实验表明，相较于代表性记忆系统，TrawMem 取得了一致提升，宏平均 F1 提高 2.23–3.14 个百分点。在 LoCoMo 上，TrawMem 在 Qwen3.5-9B 和 DeepSeek-V4-Flash 上分别将 LLM-Judge 分数较 SimpleMem 提高 4.07 和 4.31 个百分点，同时上下文 token 数分别减少约 12.8% 和 5.1%。

## Abstract
Large language model (LLM) agents rely on memory systems to leverage long-term interactions, yet existing systems typically retrieve memories based on their relevance to the current query and use them as contextual evidence. However, relevance alone does not characterize how a memory contributes to task solving: the same memory may serve different roles across tasks, such as directly supporting the answer or linking to complementary memories with weaker semantic relevance but necessary information. We therefore reframe agent memory systems as Task-Oriented Role-Adaptive Workspaces, where memories are selected and organized by their task-oriented roles and relations. Based on this view, we propose TrawMem, which organizes interaction histories into local threads and constructs task-oriented workspaces by assigning roles and jointly selecting complementary memories. Experiments on LoCoMo and MemGallery with four open- and closed-source backbones show consistent improvements over representative memory systems, with macro-F1 gains of 2.23-3.14 points. On LoCoMo, TrawMem improves the LLM-Judge score over SimpleMem by 4.07 and 4.31 percentage points on Qwen3.5-9B and DeepSeek-V4-Flash, respectively, while requiring approximately 12.8% and 5.1% fewer context tokens, respectively.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在长程多轮对话、个性化助手、持续任务中需要跨交互维护记忆。上下文窗口有限，长历史中"中间位置"信息易被忽略（lost in the middle），且每次查询重处理全历史推理开销大，因此记忆系统成为必要组件。
- **现有范式**：Mem0、A-MEM、LightMem、SimpleMem 等系统主要按"记忆与当前查询的语义相关性"检索记忆，并将其作为上下文证据拼接给答案模型。
- **核心问题**：相关性无法刻画记忆在任务求解中的**角色**。同一记忆在不同任务中可能：直接支撑答案（anchor）、作为连接其他互补记忆的桥梁（bridge）、或仅提供背景（context）。仅按相关性检索会漏掉语义相关较弱但信息必要的互补记忆。
- **整体含义**：作者主张把智能体记忆从"待检索的记录集合"重构为**任务导向的角色自适应工作空间（Task-Oriented Role-Adaptive Workspaces）**——记忆按其在当前任务中的角色与关系被选择和组织，而非仅按相似度排序。

## 2. 方法论

### 2.1 核心思想
两阶段框架：先把连续交互历史组织为**局部线程**并建立线程图；再针对每个任务定位线程邻域，为候选记忆分配**任务导向角色**，并通过**子模覆盖优化**联合选择互补记忆，组装成工作空间。

### 2.2 关键技术细节

**Stage 1：从记忆到局部线程**
- 将交互历史 \(D=\langle u_1,\dots,u_T\rangle\) 切分为若干连续局部线程 \(T_j=(a_j, L_j)\)，其中 \(a_j\) 为 LLM 生成的线程摘要（thread head，作为检索入口），\(L_j\) 保留原始有序记忆单元（内容、顺序、来源、时间信息）。
- 线程头编码为向量 \(h_j\)，记忆单元编码为 \(e_v\)；构建线程图 \(G_H\)：连接源顺序相邻的线程及语义相近的线程，支持从种子线程扩展到邻居。

**Stage 2：从线程邻域到工作空间**
- **任务上下文定位**：查询编码 \(z_q\)，线程初始分 \(r_q^0(T_j)=(1+d_{\text{idx}}(z_q,h_j))^{-1}\)；从高分线程沿 \(G_H\) 传播 \(\tilde r_q(T_k)=\gamma r_q(T_j)+(1-\gamma)w_H(T_j,T_k)\)，受跳数与邻域大小限制，得到邻域 \(\mathcal H_q\) 与候选单元集 \(\mathcal U_q\)；单元直接匹配分 \(\alpha_q(v)=\frac{1+\cos(z_q,e_v)}{2}\)。
- **任务导向角色分配**：角色集合 \(\mathcal R=\{\text{anchor},\text{bridge},\text{context}\}\)。以任务可观测需求 \(x_q=(1,z_{\text{temp}},z_{\text{rel}},z_{\text{len}})^\top\) 计算角色需求分布 \(\delta_q=Ax_q/\mathbf 1^\top Ax_q\)；以关系特征 \(f_q(v)\) 经矩阵 \(M(\delta_q)\) 与 softmax 得到角色软权重 \(\rho_q(v)\)；角色适应性 \(\phi_q(v)=\delta_q^\top\rho_q(v)\)。
- **角色引导的工作空间组装**：
  - 局部图 \(G_q\) 连接单元与线程头、线程内相邻单元及线程间边；路径代价 \(C_q(T_j,v)=d_q(T_j,v)+\lambda_m[1-\alpha_q(v)]+\lambda_r[1-\phi_q(v)]\)。
  - 预算 \(B_q=\max\{1,\min(B,|\mathcal U_q|)\}\)，单单元激活上限 \(\kappa_q=1/B_q\)；优先级 \(w_q(v)=\min\{\kappa_q,\sum_{T_j\in\mathcal H_q}\tilde r_q(T_j)\exp(-C_q(T_j,v)/\tau)\}\)，归一化为 \(\pi_q(v)\)。
  - 选择目标 \(J_q(S)=\mathbb E_{v\sim\pi_q}[\max_{u\in S}K_q(u,v)]+\mathbb E_{r\sim\delta_q}[\max_{u\in S}\rho_{q,r}(u)]+\sum_{u\in S}\alpha_q(u)+D_q(S)\)，其中 \(D_q(S)\) 为选中线程覆盖权重。四项均具边际收益递减，故 \(J_q\) 为单调子模函数；贪心逐步加入边际增益最大的单元，最多 \(B_q\) 步，满足 \(1-1/e\) 近似保证。
  - 最终 \(W_q=\text{Assemble}(S_{t^\star},\{\text{相关线程头}\})\)，保留原内容、线程头与线程内顺序，与查询一起输入答案模型。

## 4. 主要实验结果

> 说明：以下为对原文结论的归纳性描述，具体数值请以论文表格为准。

### 4.1 整体性能
- 在 LoCoMo 与 MemGallery 上，TrawMem 在 F1、BLEU-1、LLM-Judge 三项指标上整体优于全部相关性检索基线，且优势在 LLM-Judge 上最明显——说明收益不仅来自"更多证据"，更来自"证据组合方式"正确。
- 与"全历史拼接"相比，TrawMem 在显著更小的上下文预算下取得相当或更好的成绩，验证了工作空间式组织对长上下文的替代性。
- 跨四个骨干（开源与闭源）表现一致，说明方法不依赖特定模型能力，具有较好的可迁移性。

### 4.2 分问题类型分析
- **Multi-hop / 多跳类**：提升幅度最大，直接对应 bridge 角色的设计动机——需要串联多个语义上并不直接相似、但信息互补的记忆片段。
- **Temporal 类**：受益于线程内保留原始顺序与时间信息，以及线程头对时间区间的概括。
- **Single-hop 类**：与强相关性基线差距较小，符合预期（此类问题本就以 anchor 记忆为主，相关性检索已接近最优）。
- **MemGallery 细粒度类别**：在需要跨模态/跨粒度整合的类别上收益更明显，纯检索式方法在语义粒度不匹配时更容易漏检。

### 4.3 消融实验
- **去掉角色分配**（退化为纯相关性+覆盖）：性能明显下降，且在多跳问题上下降最多，证明"角色"是核心增益来源而非装饰性模块。
- **去掉线程图与邻域传播**（仅用单线程内记忆）：候选集召回不足，多跳问题受损最重。
- **去掉子模覆盖项**（改为按优先级 top-\(B\) 直接截断）：出现记忆冗余、互补单元被挤出预算的现象，说明多样性/覆盖约束不可省。
- **去掉路径代价中的角色项 \(\lambda_r\) 或匹配项 \(\lambda_m\)**：均带来一致但不完全的退化，表明两类信号互补。
- **预算 \(B\) 敏感性**：性能随预算先快速上升后趋于饱和，说明方法在较小预算下即可捕获大部分必要信息；过大预算反而可能引入 context 噪声。

### 4.4 效率分析
- 离线阶段一次性构建线程与线程图，在线阶段仅做向量检索、有限跳图传播与 \(B\) 步贪心，复杂度与历史总长度基本解耦。
- 相比"每问重读全历史"的推理成本显著降低；相比纯相关性检索基线，额外开销主要来自图传播与小规模贪心选择，属于可接受量级。
- 子模贪心的 \(1-1/e\) 近似保证使性能对贪心步数与候选集规模不敏感，工程上易于调参。

### 4.5 定性/案例分析
- 典型案例显示：与查询语义相似度较低的记忆（bridge）在被正确纳入后，才使多跳问题可解；仅按相关性排序时该记忆常排在预算之外。
- 也存在失败情形：线程切分不当导致关键信息被割裂到不同线程、或角色需求分布估计偏差时，工作空间会漏选必要单元。

## 5. 主要贡献与创新点
1. **问题重构**：把智能体记忆从"相关性检索"重新表述为"任务导向的角色自适应工作空间组装"，指出相关性≠任务必要性这一被忽视的缺陷。
2. **角色化建模**：显式定义 anchor / bridge / context 三类任务角色，并以任务可观测需求动态估计角色需求分布，使同一记忆在不同任务中获得不同权重。
3. **两阶段可扩展架构**：线程化组织 + 线程图邻域定位，把长历史的检索复杂度从"全历史"降到"局部邻域"。
4. **有理论保证的组装**：将工作空间选择构造为单调子模最大化，贪心求解具 \(1-1/e\) 近似保证，兼顾互补性、多样性与预算约束。
5. **系统性实证**：在文本与多模态两个长程记忆基准、四个骨干模型上与多种记忆系统对比，并给出充分消融。

## 6. 局限性
- 线程切分与线程头摘要依赖 LLM，切分错误或摘要失真会沿流水线传播，且难以事后纠正。
- 角色体系为三分类（anchor/bridge/context），可能无法覆盖更细的任务角色（如"反例""约束条件""否定证据"）。
- 角色需求分布由线性映射 \(A x_q\) 估计，表达能力有限；更复杂的任务需求可能需要更强的建模。
- 子模目标中各项权重（匹配、角色、覆盖）需调参，跨领域迁移时可能需要重新校准。
- 评测以 QA 类记忆基准为主，对"记忆写入/更新/遗忘"等动态维护过程讨论较少。

## 7. 结论与启示
- 核心结论：记忆系统的瓶颈不只是"检索得准不准"，而是"是否按任务所需的结构把记忆组织起来"；角色与互补性是与相关性同等重要的选择信号。
- 实践启示：可在现有记忆系统之上以"重排+覆盖选择"的轻量方式引入角色与子模选择，而不必重构整个存储层。
- 研究方向：角色体系的自动发现与扩展、端到端学习角色分配、将工作空间思想扩展到多智能体共享记忆与工具使用场景。
