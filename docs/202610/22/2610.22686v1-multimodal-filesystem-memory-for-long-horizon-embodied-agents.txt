ABSTRACT 

Agents operating over long horizons need an effective memory that allows them to reuse their experience throughout long interactions. If the entire history of an interaction is retained, it becomes difficult to find the relevant experience, while compressing it into summaries may result in the loss of visual and spatial details that are required later on. We present MFM , a multimodal filesystem memory architecture that keeps complementary types of agent memory. Episodic memory 

stores the observations, actions, and outcomes, and spatial memory associates experiences with locations. Semantic and procedural memory build up general knowledge and reusable methods of acting, and working memory holds the current plans. MFM makes use of searchable textual records to connect these different representations to the underlying multimodal episodes. The agents are able to find previous experiences by means of contextual cues and to examine the original observations in order to recover details that are missing from their textual descriptions. Through consolidation, the agents convert experience into higher-level knowledge and procedures while still keeping references to the original episodes. In the case of long-horizon Minecraft and computer-use tasks, MFM leads to improved performance with three base models. With GPT-6-Astra, MFM completes Mine Diamond from Scratch and reaches 16 out of 24 milestones on the 

Ender Dragon task, as against 12.7 for the best baseline. On CUABench-KiCad it attains a mean reward of 0.440, as compared to 0.400 for the best baseline and 0.267 in the case of no persistent memory. 

1 INTRODUCTION 

Agents that are intelligent and capable of operating autonomously over long periods in compli-cated, open-ended environments need to remember what they have seen, discovered, and previously done (Park et al., 2025; Wang et al., 2026). A large part of this kind of memory will generally be visual or spatial in character, for instance the route by which one can get back to an object that it has seen before. It is not clear what the appropriate form of compact memory the agent should use to store such observations. If one stores everything directly then it becomes difficult to find relevant experiences as the amount of history increases. Conversely, summaries of the memory enable quicker retrieval, but may result in important details being discarded later (Lu et al., 2026; Zou et al., 2026). We represent memory as a multimodal filesystem (MFM) which simultaneously holds different types of memory. We organize the memory based on the distinctions between various human memory systems (Tulving, 1972; Squire, 2004). In the MFM, episodic memory preserves past observations and interactions, spatial memory connects experiences to locations in the environment, semantic memory records facts and relationships, procedural memory contains reusable methods of acting, and working memory holds the current plan and the immediate subgoals. As shown in Fig. 2, associative indexing links these representations via searchable cues to the stored evidence. Text acts as an addressing layer for multimodal records: the agent begins by searching the descriptions of events, actions, and locations and then looks up the references in order to examine the corresponding observations. For instance, it can find a previous visit to a cave by means of its coordinates or by referring to an action that was attempted, check the recorded view, and then compare it with the current observation. The cues employed to locate an episode need not include a description of all the details of the episode. This enables us to navigate a long history of past episodes using compact records and at the same time retain detailed visual information which may only become relevant later. With increasing experience, MFM employs self-evolving consolidation in order to update its knowl-edge, skills, and current working plans. Specific observations can lead to the establishment of new facts or relationships, useful action sequences can be turned into reusable procedures, and new information discovered can cause the agent to alter its present plan. These updates link episodic experience to semantic, procedural, and working memory. For instance, the agent might connect a resource with a cave that has just been explored, record a reliable procedure for getting to it, and change its route if a subsequent observation indicates that the entrance is blocked. Since the memories written by the agent include references to the episodes that support them, the agent can go back and look at the original evidence whenever its interpretation becomes uncertain or is contradicted. Our work consists of three parts. Firstly, we propose a method for organising a multimodal agent’s memory within a single filesystem, covering episodic, spatial, semantic, procedural, and working memory. Secondly, we implement this organisation in MFM, which combines cue-based retrieval and visual inspection with consolidation into revisable knowledge and reusable procedures. Thirdly, we demonstrate through long-horizon Minecraft and computer-use tasks that MFM surpasses both memory-free and memory-augmented baseline methods when using three base models, and that it is able to reuse its memory across different tasks. Using GPT-6-Astra, our system manages to complete the MCU Mine Diamond from Scratch task in all instances and achieves 16 out of 24 milestones on Ender Dragon , whereas the best baseline achieves an average of 12.7. On CUABench-KiCad, its mean reward is 0.440, compared to 0.400 for the best baseline and 0.267 for an agent lacking persistent memory. 

2 RELATED WORK 

Filesystem and Multimodal Memory. Approaches that use a filesystem allow agents to search through and modify persistent records. PRO-LONG has demonstrated that searchable textual in-teraction logs can support long-horizon reasoning (Fox et al., 2026), and in other cases filesystems are used as organizational structures for agent memory (Zhou et al., 2026a). Multimodal memory systems are designed to organize long sequences of visual data in order to enable question answering and reasoning (Fan et al., 2024; Liu et al., 2026a; Long et al., 2026). Other research looks into task-conditioned retention (Zou et al., 2026), retrieval reliability in the face of temporal decay and conflicting evidence (Lu et al., 2026), query-aware relational organization (Li et al., 2026), and analytic operations performed on accumulated observations (Tian et al., 2026). Table 1 summarizes the differences between MFM and related systems. 

Memory for interactive agents with a long horizon. The ability to carry out long-horizon inter-actions demands a type of memory that enables continuous perception, exploration, and planning. The latest ARC-AGI-3 systems integrate foundation models with interaction harnesses and external memory (ARC Prize Foundation, 2026; Fox et al., 2026; Zeng et al., 2026; Rodionov, 2026), and VISTA keeps records of visual information that agents can go back to and compare (Han et al., 2026). In the field of robotics, efforts are directed towards multi-scale memory, the learning of history compression, and the development of benchmarks for memory-dependent policies (Torne et al., 2026; Wang et al., 2026; Dai et al., 2026). Spatial memory also helps with navigation and reasoning (Ge et al., 2026; Zhang et al., 2026). In Minecraft, Voyager creates a collection of executable skills (Wang et al., 2024), JARVIS-1 retrieves successful plans from its multimodal memory (Wang et al., 2025), and later agents introduce hybrid multimodal memory (Li et al., 2024), what-where-when representations (Park et al., 2025), and accumulated knowledge as a means of self-improvement (Xie et al., 2026). New benchmarks have recently emphasised exploration and long-horizon competence (Zheng et al., 2025; Ju et al., 2026; Zhou et al., 2026b). Although PRO-LONG indexes only text and VISTA revisits frames without having a searchable index, MFM provides a general-purpose multimodal episodic filesystem. 

3 MULTIMODAL FILESYSTEM MEMORY 

We present MFM , a multimodal filesystem memory architecture designed for long-horizon agents. This architecture incorporates three complementary elements: episodic records which store the multimodal experience, a searchable index that enables textual access to these records, and agent-written memory which structures plans, findings, environmental knowledge, and reusable procedures. 3.1 PROBLEM SETUP 

An agent interacts with an environment over a long horizon to achieve a task objective g. At step t,it receives an observation ot = ( vt, x t), where vt is a visual observation and xt contains textual or structured information, and selects an action at. Its interaction history is Ht = ( o1, a 1, . . . , a t−1, o t).As this history grows beyond the model’s context budget, the agent must retain information outside its active context and retrieve it when needed. We represent this external memory as Mt = ( Et, I t, C t),where Et = ( e1, . . . , e Nt ) stores the Nt completed episodes retained at step t, It provides an index for locating these episodes, and Ct contains agent-written knowledge. Below, we discuss how these components support complementary forms of memory. 3.2 MEMORY REPRESENTATION 

As shown in Figure 2, MFM divides memory into three parts: episodic records of multimodal experi-ence, a searchable index, and agent-written memory. This approach is based on the difference between episodic memory, which relates to specific experiences, and semantic and procedural memory, which concern knowledge and ways of acting (Tulving, 1972; Squire, 2004). The episodic store Et holds the observations, states, and actions, while the index It gives cues for finding these records. The agent-written memory Ct links discoveries from different episodes and keeps environmental knowledge, reusable procedures, and working plans. The following section explains each of these in turn. 

Episodic memory. To revisit a past experience, the agent needs access to what it observed, what it attempted, and what happened. We retain episodes as multimodal records,

Episode identifiers and timestep metadata link these records to the corresponding agent interactions. Images retain perceptual details that may be absent from a textual description, while states, actions, and outcomes allow the agent to reconstruct the circumstances of an event. Preserving these records allows the agent to inspect details whose relevance becomes apparent only later. Fig. 3(a) illustrates the contents of an episode. 

Associative indexing. Episodic memory is useful only if the agent can retrieve relevant experiences when needed. MFM associates each episode with cues describing what happened, where it occurred, and when it took place. This use of cues to access detailed records is motivated by indexing accounts of episodic memory (Teyler & Rudy, 2007). We represent the index as 

It = ( z1, . . . , z Nt ), zi = (id i, k i, ρ i),

where ki contains searchable cues and ρi contains references to the stored evidence. The cues include temporal and available location metadata, action type, retrieval tags, and a short action–outcome description. The harness maintains one entry per completed episode in index.jsonl .The index serves as an addressing layer : cues narrow the search to relevant episodes, while references provide access to their underlying observations. For example, the agent can locate an encounter near a cave through its recorded location, an object tag, or an attempted action, then inspect the corresponding image. This allows the agent to retrieve an experience through its context without first recalling its precise visual content. Details absent from the index remain available for inspection in the stored observations. Fig. 3(b) illustrates this separation between cues and evidence, and Algorithm 2 summarizes episode storage and indexing. 

Spatial memory. For embodied interaction, location provides a common frame for connecting experiences collected at different times. MFM supports this function through spatial information distributed across its episodic store, index, and agent-written memory. Our memory filesystem maintains an append-only grid of traversed cells in a world frame in grid.jsonl . Episode coordinates support retrieval by spatial proximity or vertical position, while stored egocentric views let the agent verify a retrieved location by its appearance (Fig. 1(a,d)). The agent further records landmark knowledge in notes.md , such as the entrance to a mine that has become blocked, together with coordinates and references to supporting episodes. These representations draw on complementary ideas from cognitive maps (Tolman, 1948), memory for events and their locations (Clayton & Dickinson, 1998), and visual place recognition (Cartwright & Collett, 1983). 

Semantic and procedural memory. The agent must also accumulate knowledge that is still useful after a specific episode has ended. This knowledge is stored in the agent-created collection Ct, which provides support for both semantic and procedural memory as well as the working memory mentioned below. Semantic memory involves recording facts and the relationships between them across different experiences. For instance, a note can link a resource to a cave, connect the cave to its coordinates, or relate an attempted action to the result of that action. These associations are given in plain text and include episode identifiers or file paths, enabling the agent to refer back to the relevant evidence. Useful discoveries and local knowledge are stored in notes.md , while more general environmental patterns and operating instructions are kept in GUIDE.md .Procedural memory consists of methods that can be reused. In the procedures/ directory there are textual or executable sequences of actions which the agent is able to reuse and modify during later interactions. Experience is converted into these kinds of knowledge and skill through periodic consolidation (Kumaran et al., 2016). The agent can add to, correct or reorganize these procedures as new evidence becomes available, the underlying episodic records staying unaltered. 

Working memory. To continue an ongoing task across context changes, MFM maintains the agent’s current plan and immediate subgoals in working.md (part of Ct). This file records the current plan, unresolved questions, and information needed to resume after a context reset. It connects the agent’s accumulated experience and knowledge to the decisions required by its present objective. 3.3 MEMORY RETRIEVAL

Agent-initiated search. Given its current information need, the agent constructs a query qt over the episode index It and receives matching entries Rt. A query specifies conditions on recorded context, such as a time interval or location. For example, an agent investigating a failed action can locate episodes around the time it occurred. Search then identifies episodes that match the requested context, while the agent judges which are useful for its current decision. Each result provides the episode identifier, contextual cues, an action–outcome summary, and references to the evidence. Matches are returned in chronological order, with an optional limit that retains only the most recent matches. 

Visual inspection. If you find a particular episode, you gain access to information that goes beyond the description in its index. The agent then chooses the references Pt ⊆ S

zi∈Rt ρi from the results and loads the relevant evidence into the context, Dt = {Load( p) | p ∈ P t}, where Load converts a reference into its stored frame, state, or other record. This approach of selectively loading evidence enables the agent to look at the evidence it needs without including the entire interaction history in the context. With respect to visual evidence, the agent may examine an original frame, compare a number of frames on a contact sheet, place a previous observation alongside the current view, or zoom in on a region of interest. These operations help answer different questions regarding the same experience, for example identifying an object, recognising a location, or understanding the outcome of an action. Since the observations are available independently of the textual clues, the agent is able to look at details that are missing from ki and reconsider a previous interpretation. When an inspection involves a question, the agent keeps both the question and the result so that the reason for the lookup is not lost. 3.4 SELF -E VOLVING CONSOLIDATION 

Episodic memory preserves past experiences, while semantic and procedural memory capture knowl-edge and skills for future scenarios. MFM connects these forms of memory through consolidation, drawing on how complementary memory systems support learning from experience (Kumaran et al., 2016). During consolidation, the agent examines accumulated evidence and updates its understanding of the environment, reusable procedures, and its current plan. These updates change the agent-written memory Ct while preserving the recorded history (Et, I t). Algorithm 4 summarizes this procedure. 6Preprint 

From experience to knowledge and skills. Consolidation allows findings from individual episodes to inform subsequent behavior. The agent can record a useful observation as local knowledge in 

notes.md , or update GUIDE.md when experience supports a broader regularity. For example, an encounter may establish where a resource was found, while repeated encounters may suggest conditions under which an action succeeds or fails. The agent can also qualify earlier guidance when new observations reveal limits to its applicability. Procedural updates record effective methods of acting; the agent is able to convert a sequence of actions into a textual or executable procedure and then modify it as a result of the changes revealed by later attempts. Working-memory updates link the knowledge that has been accumulated to the current task by having the agent revise the file working.md to show the completed subgoals, any changes to the plan, and the questions that remain unanswered. The agent decides which of these updates to make on the basis of the evidence available and the role of each memory, and the resulting documents and procedures stay accessible during future interactions. 

Revision with preserved episodic evidence. Knowledge gained from experience can become out of date or incorrect. By linking the knowledge that agents write to the episodic observations that support it, agents are able to go back and look at the basis of their earlier beliefs. For instance, after having noticed a sheep on a hillside the agent then decides to go back for food, enlarges the original frame, and discovers that the animal was in fact a wolf; it then corrects the note and alters its plan while still keeping the reference to the episode. If the agent had kept only the textual description it would have lost the visual details required to correct that interpretation. Therefore, by preserving the episodic evidence the agent can reevaluate its earlier conclusions as its understanding develops. Figure 3(d) shows that the agent updates its GUIDE to indicate that the death message names a Piglin and that the previous identification as a brute has not been confirmed. 

4 EXPERIMENT RESULTS 

We evaluate MFM to understand how persistent multimodal memory affects task performance, decision-making, and interaction efficiency. We compare MFM with baseline methods on long-horizon embodied and computer-use tasks (Section 4.2), examine the memory component contribu-tions via ablation studies (Section 4.3), and illustrate qualitative retrieval behaviors (Section 4.4), with a portal-building case study examining task completion and interaction efficiency, and analyze how the agent learns and reuses skills through memory (Section 5.1). 4.1 EXPERIMENTAL SETUP 

We evaluate MFM across two diverse domains, averaging all main and ablation results over three random seeds (determining the Minecraft world or KiCad task order). We limit each configuration to three seeds because long-horizon runs with frontier models are expensive. All models are ran with 

high reasoning efforts. • Minecraft : MCU-AgentBeats (Zheng et al., 2025; Liu et al., 2026b): open-world exploration and interaction in Minecraft, scored via scene-specific milestones. The details of both tasks are included in E.1. For the Mine Diamond from Scratch task, we use 12,000 max steps; for the Ender Dragon task, we use 36,000 max steps. • CUABench-KiCad . Built on the CUABench framework (Cua AI, Inc., 2025; Cua AI, 2026) via low-level action spaces, this environment evaluates visual GUI agents on realistic electronic design automation workflows in KiCad. It contains N = 25 tasks. For MFM, VISTA, and PRO-LONG, memory can carry over across tasks. A task may receive a score in [0 , 1] when the solution satisfies only a subset of the required criteria. 

Baselines and models. We compare MFM against direct evaluation (no persistent memory), PRO-LONG (Fox et al., 2026), and VISTA (Han et al., 2026) using frontier base models (GPT-5.6-Sol, Claude Opus 5, and GPT-6-Astra). 5 SELF -I MPROVEMENT WITH MFM 

5.1 SKILL LEARNING THROUGH MEMORY 

We look into whether long-term memory allows agents to enhance their future behaviour by turning experience from interactions into reusable procedures. In this context, self-improvement means adapting as a result of the memory accumulated in MFM. MFM includes the facilities needed to store, modify, and carry out procedures written by the agent, and it is the agent itself that decides which behaviours to keep and when to reuse them. We do not specify the resulting skill library and do not require a fixed number of skills for each run. The analysis presented in this section includes observations of skill creation and reuse over different trajectories, an ablation study of the 9Preprint agent-written procedures, and a controlled study of the number of steps required to solve new tasks with or without reusing the agent-written procedures. 

From experience to reusable behaviour. The trajectories show how agents convert their experience of interaction into permanent action routines. In a run of GPT-6-Astra Dragon, after manually cutting a descending staircase (steps 5,068 to 5,249), the agent created the procedure cut_step , which is parameterised by heading and cuts one step while advancing (C.1); it then invoked this procedure 60 times, once for each of the four cardinal headings. A second procedure, quarry_north_pair ,extracts the upper and lower block from the wall in front and gathers the dropped items (C.2); the 27th time it was called, at step 17,462, it broke the first diamond ore block. Reuse also carries over from one life to another. The procedure bridge_north , which places one floor block while sneaking and takes the target cell as input (C.3), was written in the previous life after the agent had manually placed two blocks over the lava and was then called three times in that same life. In this life the agent called it nine times between steps 19,261 and 20,103, using inputs ranging from 

(x=-3037, y=29, z=-5657) to (x=-3037, y=33, z=-5665) . Each invocation placed one cobblestone block and left the agent’s health unchanged, and the bridge ended up reaching the lava pool where mining of obsidian took place at step 20,736. The agent also disabled one inherited procedure, level_step , having traced the previous death in the lava back to this procedure’s release of the sneak key. 

Contribution to task performance. The results from the procedure ablation show that the procedures written by the agent do in fact contribute to task performance in MFM. For instance, when these procedures are removed for GPT-5.6-Sol, the mean milestone completion drops from 9.7 to 8.7 on Diamond and from 10.7 to 9.0 on Dragon. Our analysis points to two mechanisms that account for these improvements. Firstly, the skills allow agents to carry out the tasks more quickly; as presented in Table 5, reusing skills acquired during an earlier task decreased the average number of environment steps required to complete three new tasks: Iron shield, Climb out, and Cook meat by 30%, 7%, and 26% respectively. Secondly, skills can enable agents to reach milestones that would otherwise be impossible for them to achieve, as shown in the case of the blaze-fighting skill. If there are no agent-written skills that take visual inputs (for example, C.9), then none of the methods or models evaluated is able to go beyond milestone 16 to accomplish milestones such as killing a blaze or an enderman. These findings indicate that procedures enhance both the efficiency of task completion and the variety of milestones that can be achieved, even though they do not mean that each stored procedure is beneficial or that having a larger library of skills will necessarily lead to better performance.

6 CONCLUSION 

We introduced MFM, a multimodal filesystem memory that organizes episodic, spatial, semantic, procedural, and working memory as folders and files in one shared filesystem. Episodic records preserve raw observations, states, actions, and outcomes; a searchable index of contextual cues addresses them; and agent-written knowledge, procedures, and plans cite the episodes that support them. An agent can thus locate past experience by when, where, or what happened, inspect the original observation for details text omits, and revise what it has learned without discarding the evidence. Across Minecraft and KiCad with three base models, MFM outperforms memory-free and memory-augmented baselines, each component contributes, and memory transfers across tasks. We hope MFM can serve as a foundation for memory in long-horizon multimodal and embodied agents. 

Limitations and Future Work . MFM improves long-horizon performance, but exploration remains hard: even GPT-6-Astra at maximum reasoning effort (from a concurrent experiment posted online) did not complete Ender Dragon. Finding better ways of coupling memory to exploration and route planning could help agents find landmarks and avoid repeated traversal. Our evaluation is also limited 10 Preprint to single agents in Minecraft and KiCad; shared memory across agents could combine experience from different regions or solution attempts, and broader environments would test how far the design transfers. 11 Preprint

A.4 INSPECTION STATISTICS 

We quantify a mechanism behind Sec. 4.4 over the main Minecraft runs (three models, two tasks, three seeds): how often inspecting a stored frame changed the agent’s next action (Fig. 16). 

Does looking at a stored frame change the next action? The agent looks before it commits, and the transcripts hold no counterfactual, so a within-call before/after comparison is empty by construction. What can be measured is the destination. A turn is a retarget if its plan names a go_to /look_at 

coordinate the running plan did not contain, and a recall target if that coordinate lies within 8 blocks of where the looked-at episode was recorded; the null for recall is the fraction of all stored episodes that would match the coordinate by position alone. D HARNESS AND IMPLEMENTATION DETAILS 

This appendix covers five things: the episode index (Section D.1), the spatial grid (Section D.2), the configuration of each method and the action interface shared by all methods (Section D.3), and storage and cost statistics (Section D.4). D.1 EPISODE INDEX 

The harness appends one row to index.jsonl for each completed episode (Box 1). Each row contains: • the episode identifier and the path to the episode’s directory; • the first and last environment steps of the episode; • the kind of action executed; • a one-line summary; • a list of tags; • the agent’s position (x, y, z ).The summary records the procedure call with its arguments, followed by its outcome: how long it ran, how far the agent moved, how the inventory changed, and any milestone reached. Tags flag notable events such as a milestone, an inventory change, or a failure to move ( stuck ). D.3 METHOD CONFIGURATIONS 

Table 6 lists the configuration of each method on Minecraft. All methods receive the same 12 KB standing brief in prompt. All methods act through the same 28 atomic procedures (Table 7). The atoms are closed-loop: they read the structured game state at every step. No method has access to task-specific macros such as tree harvesting, strip mining, or portal building. We reimplemented PRO-LONG and VISTA in our harness without changing their core algorithms. PRO-LONG keeps its programmatic text logs, and VISTA keeps its archive of visual observations and its inspect interface. 

Matched inspection, different addressing. VISTA and MFM have equivalent visual inspection capabilities: both store every observation losslessly with its step identity, and both let the agent reopen earlier frames, crop and enlarge regions, and compare several past or current views in one context. The methods differ only in how the agent locates evidence and what it does with it. VISTA addresses frames by turn and frame identifier; MFM additionally provides a harness-written index of cues (time, position, action type, tags, outcome summary) that the agent can query, and agent-written memory that cites the supporting episodes. Our comparison with VISTA therefore isolates the contribution of the addressing layer and consolidation, not of the inspection tools. 

Why only MFM writes executable procedures. Neither baseline provides a persistent place for agent-written procedures: PRO-LONG’s durable memory is a single harness-owned log, and VISTA’s writable memory is limited to two notes files. Turning an action sequence into a procedure also requires checking whether that sequence has succeeded before. MFM’s associative index makes this check direct: the agent can query past episodes by action type and outcome tags, then inspect the linked frames to confirm the result. VISTA addresses frames only by turn identifier, and PRO-LONG’s text log, while searchable, has no structured action or outcome fields and no links to visual evidence, so the same check requires scanning and reconstructing past attempts. Without these supports, the baselines kept their procedural knowledge as prose notes rather than callable procedures. 33 Preprint D.4 STORAGE AND COST
