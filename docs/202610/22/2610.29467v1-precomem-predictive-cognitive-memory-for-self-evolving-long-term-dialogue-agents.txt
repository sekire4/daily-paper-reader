Abstract 

Long-horizon dialogue agents need to keep user memories stable enough for personalization while adapting when the user genuinely changes. Existing memory systems often append every observation or overwrite old entries by heuristic rules, which makes transient noise hard to distinguish from real belief drift. We introduce 

PreCoMem , a memory consolidation framework inspired by predictive coding that represents memory as confidence-weighted beliefs about the user’s state. Its core signal, Effective Surprisal , combines semantic deviation and contradiction evidence, then downweights this signal when retrieval is diffuse and unreliable. According to effective surprisal, a two-threshold gate maps each turn to one of three deterministic updates: MAINTAIN reinforces supported beliefs, PROFILE 

stores ambiguous cues as low-confidence hypotheses, and CORRECT softly decays reliably contradicted facts. The PROFILE stage acts as an explicit waiting room, preventing premature commitment to noisy evidence. Experiments on LoCoMo, LongMemEval-S, and PersonaMem-v2 show consistent state-of-the-art accuracy; our new DiMoBench confirms that PreCoMem adapts to non-stationary belief drift without over-reacting to noise. The code is available at https://github.com/ ZhongWishing/PreCoMem .

†Corresponding authors. 40th Conference on Neural Information Processing Systems (NeurIPS 2026). arXiv:2610.29467v1 [cs.AI] 21 Oct 2026 Large Language Models (LLMs) are moving from stateless responders toward long-term partners that interact with the user over hundreds or thousands of turns [1–3]. Such partners need more than stored transcripts; they require a user model to sustain personalized interaction [4, 5]. To formalize the core units of this user model, we define a belief as a compact, actionable claim about the user’s preferences, goals, or life context, paired with a confidence weight that can be reinforced or revised over time. This user model underpins both agent personalization and behavioral self-correction, thereby redefining the role of long-term memory: rather than merely serving as simple context extension [6, 7], long-term memory enables the agent to maintain consistent behavior across sessions. The harder question is not whether information can be stored, but how it should be consolidated and revised. A practical memory consolidation mechanism must decide which observations to retain, how strongly to trust them, and when to maintain, revise, or correct stored items without explicit supervision. We refer to this as the memory stability–plasticity problem : the agent should preserve stable user traits while remaining plastic enough to adapt when those traits change [8]. Long-horizon interaction makes the problem hard for three coupled reasons. First, most turns carry little signal, while a small fraction may contain cues indicative of more persistent user states. Second, user preferences and life facts evolve over time [9], so the system must adapt under non-stationarity and belief drift [10, 11]. Third, corrective feedback is rarely explicit [12], and noisy retrieval over long contexts further blurs the picture [13–16]. Therefore, the brittle memory update mechanism causes two opposite failures: premature correction from noise, or persistent over-reliance on outdated memories, which we call old-memory pull , a phenomenon related to loss of plasticity and retrieval interference in continual adaptation systems [8, 17]. Recent memory systems have made impressive progress on retrieval and storage organization. Hierar-chical and OS-style stores [6, 18, 19], structured indices with timestamps or topic shards [20–23], and agentic retrievers [24, 25] all sharpen what the system can recall. However, the question of when to update is still often handled by recency overwriting, fixed-threshold importance, or one-shot append rules [4, 26]. These triggers cannot reliably separate persistent drift from transient noise [17], so they collapse the stability–plasticity trade-off precisely where long-horizon dialogue stresses it most. A fuller literature discussion is provided in Appendix Section A. We draw inspiration from predictive coding , which posits that learning is driven by mismatch between expectation and reality, i.e., prediction error [27, 28]. In information theory the same quantity is called surprisal [29, 30]. We use this view as a design principle for the update path rather than as a claim that dialogue memory is a fully specified probabilistic model. The resulting criterion is simple: events consistent with current memory should be reinforced, while surprising events may require learning or correction [31, 32]. Crucially, surprisal must be paired with a measure of retrieval reliability , so that update decisions stay conservative when recall itself is uncertain or noisy [13, 33]. Building on this view, we propose PreCoMem (Predictive Cognitive Memory) , a self-evolving long-term memory framework for conversational LLM agents. PreCoMem operates in two active phases over a shared memory store. In memory leveraging , it retrieves confidence-weighted be-liefs to condition response generation. In memory evolution , it compares new observations with recalled evidence and computes Effective Surprisal Seff , a reliability-adjusted mismatch score. A two-threshold gate then routes each update to MAINTAIN , PROFILE , or CORRECT , corresponding to consistent, ambiguous, and reliably contradictory evidence. Figure 1 illustrates this loop on a coffee-to-tea preference shift, where a low-confidence hypothesis is gradually promoted to a fact while the contradicted old fact is softly decayed. In summary, we (i) propose PreCoMem , a memory consolidation framework that casts long-term memory as a dynamic prediction of the user’s state; (ii) introduce a reliability-weighted surprisal sig-nal that gates each update through MAINTAIN , PROFILE , or CORRECT ; and (iii) evaluate on LoCoMo, LongMemEval-S, PersonaMem-v2, and DiMoBench/DiMoBench-XL, controlled write-path stress tests with gradual drift and decoy retrieval. PreCoMem outperforms the strongest contemporary baselines while keeping effective memory stable across 1050 turns.

This read–write loop differs from prior memory systems in two ways. First, every belief item carries a continuous confidence weight wt(m) ∈ [0 , 1] that is reinforced or softly decayed by the operators, instead of relying on discrete commit decisions such as A DD /I GNORE /U PDATE in O-Mem [21] or binary expiry intervals in EverMemOS [19]. Second, PROFILE buffers ambiguous observations as low-confidence hypotheses, letting weak evidence accumulate across turns before it is committed or discarded. In implementation, each operator pairs a closed-form update rule with a fixed-prompt LLM sub-agent. The sub-agent only identifies which items are relevant and emits one bounded scalar, such as 

EVIDENCE _STRENGTH , SEVERITY , or INITIAL _CONFIDENCE . The deterministic layer then plugs these scalars into Equations (7), (8) and (10). Thus the LLM proposes local magnitudes, while the gate, confidence bounds, and closed-form w updates control when and how memory changes accumulate. Algorithm 1 (Appendix Section B.4) gives the per-turn pipeline. 

2.2 Memory primitives Dialogue and memory state. At turn t = 1 , 2, . . . , the user input is ut, the agent response is yt, and 

Qt−1 is a rolling working-memory window. Long-term memory is Mt = ( Bt, Et, Tt). The belief store Bt contains editable facts and hypotheses with confidence weights. The episodic cache Et stores immutable raw dialogue traces with source pointers. The optional topic table Tt is only a retrieval prior. This keeps beliefs editable and evidence traceable. 

Items, confidence, and hypothesis lifecycle. A memory item m has content c(m), type τ (m) ∈{FACT , HYPOTHESIS }, and retrieval metadata such as embeddings, topic labels, entities, timestamps, and source pointers into Et. For belief items, wt(m) ∈ [0 , 1] is an operational support score. Episodic traces are fixed at wt(e) ≡ 1 and used only as provenance, not in confidence-weighted Top-K ranking. A HYPOTHESIS is a provisional belief: it is reinforced under supporting evidence, decayed when evidence stays absent, and promoted to FACT when confidence crosses τpromote . Type transitions are one-way. Contradicted facts are softly decayed by CORRECT (Section 2.4) rather than demoted, 3yielding low-confidence “deprecated” facts that confidence-weighted retrieval naturally deprioritizes. Appendix Section C.7 confirms this retention is accuracy-neutral.

DiMoBench setup. DiMoBench (Dialogue Implicit Memory Drift Benchmark) is a controlled diagnostic setting for gradual attitude and preference drift. A user’s latent stance reverses around a change point, while keyword-matched chatter and entity confounders pollute the stream so naive retrieval and overwrite-style updates become brittle. The released suite has five independent 350 -turn dialogues, each driven by a distinct persona, with 200 QA pairs per dialogue ( 1,000 total; results averaged across personas); DiMoBench-XL extends this to 1050 turns and three sequential drifts, with 420 QA pairs each, 2,100 in total (Appendix Section C.6). 

Update dynamics. Figure 4(b) plots LLM-judge accuracy across dialogue turns. Before the change point all methods are stable; afterwards PreCoMem experiences a transient drop but recovers fastest and stabilizes at 84% , while EverMemOS, TiMem, and O-Mem plateau at 78–80% and Mem0 fails to recover ( 54% ). End-to-end traces are provided in Appendix Section C.11. 

Operator ablation on DiMoBench. Ablating each operator individually (Figure 4(c)) yields qualitatively distinct failure modes: removing PROFILE caps the asymptote at 72% (vs. 84% ); removing CORRECT delays recovery (turn 320 vs. 250 ) and lowers the plateau to 77% ; removing 

MAINTAIN fails to stabilize within the horizon ( 54% at the end), confirming that the three operators play distinct stabilizing roles. Appendix Section C.4 provides the full analysis, and the same three qualitative signatures reproduce on the third-party AMemGym benchmark (Appendix Section C.1). 

3.4 Hyperparameter analysis 

We sweep the retrieval budget k ∈ { 1, . . . , 20 } on LoCoMo ( gpt-4.1 ). Accuracy rises sharply through 

k ≈ 6, peaks at k = 10 (Overall 85 .06% ), then drops mildly. Larger k flattens the Top-k score distribution, lowering ρt and dampening the effective surprisal xt that drives CORRECT . It also increases the chance that one retrieved item spuriously appears contradictory under the max-based contradiction component dconf . We therefore fix k = 10 ; the full sweep and retrieval-latency profile are reported in Appendix Sections C.5 and C.9. Because the write path acts only on retrieved beliefs, Appendix Section C.8 further measures how often the belief due for an update actually enters the Top-k and what a miss costs.

and +3 .4 overall points, so storage remains bounded in both the soft sense ( Neff plateau) and the hard sense. This suggests the memory gain is not purchased by unchecked accumulation. 

4 Conclusion 

PreCoMem treats long-horizon conversational memory not as a transcript to be stored, but as confidence-weighted beliefs about the user’s state that must be continually checked. A reliability-adjusted surprisal signal routes each turn into MAINTAIN (reinforce supported beliefs), PROFILE 

(buffer ambiguous cues as low-confidence hypotheses), or CORRECT (softly decay contradicted facts). The PROFILE waiting room is the central design choice: it lets evidence accumulate before commit-ment, so the agent stays consistent under noise without freezing under genuine drift. Across LoCoMo, LongMemEval-S, PersonaMem-v2, and DiMoBench, this discipline yields the best overall accuracy while keeping memory bounded over a thousand turns; qualitative case studies (Appendix Sec-tion C.11) show calibrated recommendations beyond retrieval-only baselines. We see continuous confidence and explicit hypothesis lifecycles as a useful baseline for long-term memory systems, where what to commit matters as much as what to recall . A Related work 

Long-term memory for conversational LLMs. Early work attacks the fixed context window with externalized hierarchical or virtual memory [4, 6]. More recent systems either organize the store more aggressively or learn richer write rules. Structured organizations include interlinked note stores with associative links [24], time-aware knowledge graphs [20], OS-style hierarchical scheduling [18, 19], and dedicated memory-box layouts that segment a user’s history into typed shards [23]. Learning-based update rules optimize memory operations against downstream rewards [25, 44, 45], while 

interpretable triggers target a single failure mode such as preference change [46], redundancy [22, 47], controllable reliance [48], or affective state [49]. A systematic gap shared by these systems is the 

stability–plasticity regime: append-only memories [24] treat every observation as equally valid and dilute retrieval; overwrite memories compress aggressively but lose information that later turns out to be relevant [26]; OS-style memories [18, 19] schedule access well but still fall back on importance heuristics for writes; and reinforcement-trained memories [25, 44, 45] face sparse credit assignment, since most reward signal is several turns downstream of the responsible read/write decision. PreCoMem is complementary to all of these: it treats the write path as a single regime-gated 

decision driven by a calibrated prediction-error signal, instead of relying on recency heuristics or task-specific reward shaping. 

Predictive coding and surprisal as write signals. Predictive coding theory holds that perceptual systems update internal models when observations deviate from prediction [27, 28], and information theory gives this deviation a precise scalar form: surprisal [29, 30]. The same logic has long shaped accounts of episodic memory: novel events are encoded preferentially, and reactivation drives reconsolidation of related traces [31, 32]. Translating this into long-term conversational memory 15 requires two extra ingredients absent from prior memory systems. First, surprisal must be calibrated against retrieval reliability , otherwise diffuse recall produces noisy update signals [13, 33]. Second, surprisal must be regime-gated , since consistent, ambiguous, and reliably contradictory evidence call for qualitatively different memory edits. PreCoMem operationalizes both ingredients: Seff multiplies raw surprisal by an entropy-based reliability coefficient, and a two-threshold gate maps the result to 

MAINTAIN /PROFILE /CORRECT .

Benchmarking long-term memory. LoCoMo [34] provides 1,500 + questions over multi-session dialogues with explicit single-hop, multi-hop, temporal, and open-domain splits. LongMemEval-S [16] tests five core abilities (information extraction, multi-session reasoning, knowl-edge updates, temporal reasoning, abstention) with 500 questions over chat histories of roughly 

115 k tokens each. PersonaMem-v2 [35] stresses implicit personalization across 1,000 personas and 

20 ,000+ preferences, where most signal is buried in everyday task-oriented turns. Two more recent benchmarks move closer to the write path: AMemGym [36] evaluates memory on-policy against a simulated user whose latent task state changes across periods, and LoCoMo-Plus [37] probes implicit cognitive constraints (causal, state, goal, and value) over long dialogues; we report both in Sec-tion C.1. EvalMem [50] complements these end-task benchmarks with an operation-level diagnostic framework that scores individual memory operations such as adding, updating, and deleting items. These benchmarks probe the read path or the end result of memory updates; none of them, however, isolates the write-path decision under continuous, gradual drift with adversarial retrieval interference. Our companion benchmark DiMoBench fills this gap with five independent 350 -turn dialogues, one per persona, whose latent attitudes reverse gradually across change points; an extended variant, 

DiMoBench-XL , contains five independent 1050 -turn dialogues, each with three sequential drifts.

Why low-confidence facts are retained rather than pruned. We deliberately apply the wt(m) <

0.1 pruning rule only to hypotheses, not to facts. Two design considerations motivate this asymmetry. First, because retrieval is confidence-weighted, an outdated fact with w ≈ 0.02 contributes roughly 50 × less to the retrieval score than a currently supported fact with w ≈ 1; such items are naturally pushed out of the Top-K evidence set by currently supported beliefs and become functionally inactive 

under confidence-weighted retrieval even though they remain in storage. Second, long-horizon dialogue often revisits past user traits after long gaps (e.g., a user stops drinking coffee for months and then mentions it again); retaining the deprecated fact at low confidence preserves the reasoning chain and episodic-cache links needed to recover such context, whereas hard deletion would force the system to rebuild that trait from scratch. The resulting effective memory , i.e., the subset of items that can still influence Top-K retrieval, therefore remains controlled even if raw storage accumulates history. Under truly extreme horizons, raw storage can be further bounded by a timestamped time-to-live on long-deprecated facts without modifying the core operators; we leave this as an engineering safeguard rather than a core mechanism.

B.4 Per-turn pipeline (hybrid execution) 

Algorithm 1 makes the hybrid execution discussed in Section 2.4 explicit. Each turn invokes (i) a deterministic Retrieve step, (ii) a deterministic computation of ρt, S raw , x t, (iii) a regime-specific LLM sub-agent (one of Maintain-Agent , Profile-Agent , Correct-Agent ; prompts in Section D) that emits per-item scalar scores, and (iv) a deterministic application of the closed-form updates in Equations (7), (8) and (10). The sub-agents only inject which items to touch and 

how strongly ; gating, soft-decay, reinforcement, and hypothesis-promotion mechanics are entirely symbolic.

DiMoBench evolution-operator ablations. We ablate PreCoMem’s three evolution operators on DiMoBench: PROFILE (hypothesis writing), CORRECT (surprisal-gated soft correction), and 

MAINTAIN (reinforcement/smoothing). We report accuracy every 10 turns from turn 150 to 350. As shown in Figure 4(c), removing PROFILE lowers the final accuracy ceiling (72%), removing CORRECT 

substantially slows post-drift recovery, and removing MAINTAIN leads to high-variance dynamics that do not stabilize within our evaluation horizon (ending at 54% accuracy). 

Operator-level analysis. DiMoBench is designed to separate three regimes that stress different update behaviors: a stable pre-change phase (turns ≈150–200), a short change-point phase with mixed/ambiguous cues and decoy retrieval (turns ≈200–240), and a stable post-change phase where the latent attitude has reversed (turns ≈240–350). Under this structure, the three operators contribute in complementary ways. 

PROFILE : buffered adaptation under implicit drift. Many change-point cues are neither clean confirmations nor decisive contradictions: they are novel, partially ambiguous, and often entangled with confounders. PROFILE converts these medium-Seff signals into low-confidence, testable hy-potheses, enabling the system to accumulate multiple weak cues before committing. This “waiting room” is especially important on DiMoBench because questions explicitly probe trend/change-point reasoning and hypothesis-vs-fact distinction. When PROFILE is removed, the system loses this intermediate representation and commits weak cues without a waiting room (premature commitment under decoys), which reduces the asymptotic ceiling (72% vs. 84% for full PreCoMem). 

CORRECT : targeted suppression of outdated beliefs. After the drift, previously correct high-confidence beliefs become systematically misleading, and decoy retrieval makes stale evidence likely to reappear. CORRECT provides a selective revision mechanism by downweighting contradicted items via the ζt(m)-modulated soft decay while leaving non-contradictory items largely unchanged. This targeted decay is crucial for reducing old-memory pull and preventing interference from pre-change beliefs. Without CORRECT , outdated facts remain competitive in retrieval, so the agent must rely on accumulating new nodes and indirect effects to “outvote” entrenched beliefs, yielding a substantially slower recovery (reaching 75% only around turn 320 vs. turn 250) and a lower final plateau (77% vs. 84%). 

MAINTAIN : consolidation for stability. MAINTAIN acts as a consolidation step that repeatedly rein-forces supported beliefs, which sharpens confidence-weighted retrieval, increases retrieval reliability 

ρt (by making the score mass more concentrated), and stabilizes the routing signal xt(= Seff ). It also underpins the hypothesis lifecycle: hypotheses created by PROFILE require repeated reinforcement to cross the promotion threshold and become stable facts. This stabilization is critical in the post-change phase, where the system should stop oscillating and settle into the post-change regime. When 

MAINTAIN is ablated, supported post-change beliefs cannot be progressively consolidated; retrieval remains diffuse and volatile, the reliability-adjusted loss becomes noisy, and updates keep “chasing” confounded evidence. Empirically, this yields persistent volatility: accuracy continues to fluctuate and ends at 54% at the end of our evaluation.

LLM-direct-write baseline. A natural alternative to the hybrid design of Section 2.1 is to let the same LLM decide the whole write step. The direct-write baseline matches PreCoMem in every other component (retrieval, embedding, Top-K=10 , context, judge, seeds, gpt-4.1 ); the only change is that the LLM emits the entire write decision as one object, { route , target_ids , operation ,

new_weights , new_belief }, whose weights are written verbatim, replacing the gate, the closed-form updates and the [0 , 1] clamping. Table 13 shows that accuracy is lower in every seed ( −2.75 

on LoCoMo, −3.15 on LongMemEval-S) while per-query tokens are slightly higher (3.2k / 3.9k against 3.1k / 3.8k), so the loss is not offset by efficiency. Replaying the write decisions on a frozen store, direct write emits a missing target id in 3.6% of decisions, a self-contradictory operation in 2.7% and invalid JSON in 1.8% (mutually exclusive categories); such malformed writes corrupt the store silently and compound, whereas the closed-form updates stay in [0 , 1] by construction. The loss is spread over all LoCoMo splits (Single-Hop −1.65 , Multi-Hop −4.80 , Temporal −2.70 , Open-Domain −6.50 ). The deterministic layer is what keeps long-horizon memory bounded.

Sensitivity to gating thresholds. Theoretically, one may dynamically compute or adapt the thresh-olds (e.g., by estimating the action costs/effects in Equation (27)), which could yield better per-sample or per-stage performance. However, such on-policy adaptation introduces additional computation and confounds controlled evaluation because the observed behavior becomes entangled with an evolving threshold schedule. We therefore adopt a fixed threshold pair (θlow , θ high ) in all experiments and justify a reasonable choice via a sensitivity study. For controllable and cost-bounded ablation, we select a representative LoCoMo sample (Sample 1; 400 dialogue turns and 105 QA pairs) whose question types are relatively balanced and whose scale supports rapid iteration. Rather, it provides a stable and interpretable operating point with competitive accuracy under a fixed computational budget, and we keep it constant across experiments for fair comparison and reproducible observations.

Theoretical view. From a Bayesian perspective, the thresholds encode a prior on belief persistence: stable users have a stronger prior that beliefs are unchanged, so a higher θhigh corresponds to requiring stronger likelihood evidence to revise them, and vice versa for dynamic users. From a signal detection perspective, θlow and θhigh trade off false-update rate (triggering CORRECT on noise) against missed-update rate (failing to trigger on genuine drift); since these two error rates have different relative costs for different users, the Bayes-optimal decision boundary is user-dependent. Equation (37) is a minimal realization of this idea that only reads summary statistics PreCoMem already maintains and introduces no extra trainable parameters. 

Empirical results on LoCoMo. We evaluate the adaptive variant, denoted PreCoMem (DT) , on the full LoCoMo benchmark with two backbones ( gpt-4o-mini and gpt-4.1 ), keeping every other setting identical to the main experiments. As shown in Table 15, relaxing the fixed thresholds to Equation (37) yields consistent gains in overall accuracy ( +0 .98 on gpt-4o-mini , +1 .15 on gpt-4.1 ), with the largest improvement on the Open-Domain subset under gpt-4o-mini (+3 .92 ), which is the category most exposed to long-horizon drift. The same trend holds on LongMemEval-S, where PreCoMem (DT) lifts the overall score from 84 .28 to 85 .36 under gpt-4o-mini , with the largest gains on KU (knowledge update, +1 .62 ) and SSP (single-session preference, +1 .95 ); these are precisely the question types that require per-user calibration of how aggressively to update beliefs. These results show that adaptive thresholding is an almost-free extension that further personalizes PreCoMem for users with different stability profiles. We keep the fixed-threshold setting as the default in the main paper for controllable comparison, but we consider adaptive thresholding a natural deployment-time configuration, especially in long-horizon and cross-user settings.

Importantly, questions avoid explicit sentiment keywords and instead require reasoning from behavioral cues (plans, actions, reactions), making drift detection and correction rely on implicit evidence chains rather than lexical matches. 

Why DiMoBench is needed. Existing long-horizon dialogue benchmarks predominantly evalu-ate the read path : whether a system can correctly retrieve and reason over a static conversational record (LoCoMo [34]) or whether it can infer implicit personalization from accumulated preferences (PersonaMem-v2 [35]). None of them explicitly stress-test the write path , i.e., whether a memory system can correctly decide when to maintain, update, or correct its stored beliefs under gradual, implicit drift. DiMoBench is designed to fill this gap along three axes that are absent from exist-ing benchmarks simultaneously: (i) continuous non-stationarity , where the latent attitude reverses gradually over hundreds of turns without any explicit announcement; (ii) implicit behavioral cues ,where the drift manifests only through activity choices, reactions to invitations, and hedging language rather than sentiment keywords; and (iii) adversarial retrieval interference , where five tagged interfer-ence types ( entity_confusable , keyword_trap , temporal_decoy , hypothetical_vs_fact ,

none ) systematically probe two stability–plasticity failure modes: old-memory pull and premature correction . This write-path orientation is what lets DiMoBench reveal the distinct contributions of MAINTAIN , PROFILE , and CORRECT in Section C.4, which cannot be isolated on LoCoMo or PersonaMem-v2 alone.

C.8 Retrieval dependence and reliability calibration 

The write path acts only on the retrieved set Ct: if the belief that should be revised is not retrieved, the contradiction cannot be detected and CORRECT cannot fire in that turn. This section quantifies that dependence and then examines what the reliability coefficient ρt actually tracks. 

Belief-update recall and failure decomposition. A miss does not stall adaptation: the observation still enters the episodic cache and can form a hypothesis, and 20% of missed events (147 of 718) are corrected later by subsequent cues or hypothesis promotion. To separate association from causation we force the target belief into the Top-10 at every missed event (displacing the lowest-ranked item) and re-run the write path and the question. This closes only 26–32% of the hit–miss gap (last column of Table 23): forcing the hit raises accuracy on the affected questions by 4.5–6.5 points, while the rest of the gap reflects that missed events are intrinsically harder and that gating and localization can still fail once the target is retrieved. 

What ρt measures: calibration. ρt = 1 − Ht is the normalized concentration of the Top-K

retrieval scores. It does not judge whether an individual retrieved item is correct; it weights how far the surprisal computed from that recall can be trusted, and because it enters only multiplicatively it can make the gate more conservative but never more aggressive. Two cases illustrate the behavior. If several relevant memories are correctly retrieved with similar scores, ρt is lower and the update is dampened and deferred; no information is lost, since supporting evidence keeps accumulating through the hypothesis lifecycle and a genuine change is still committed after slightly more confirmation. If a wrong memory receives a very high score, ρt is high, but ρt is deliberately not the sole trigger: whether CORRECT fires still depends on dconf , an NLI verifier run against the actual new utterance, and the change is a bounded, reversible soft decay that keeps provenance. To check that concentration is a usable proxy for evidence precision, we stratify the 2,829 gate events of the AMemGym runs (943 per seed) into quintiles of ρt and measure, per quintile, the precision of the retrieved set against the user’s current gold state, the recall of the belief due for update, the accuracy of the contradiction decision against 400 blind-annotated events (80 per quintile), the correctness of the resulting update, the share of CORRECT firings judged unwarranted (false-CORRECT ), and the accuracy of the next state-query probe on the touched attribute (Table 24). Precision, contradiction accuracy, update correctness and downstream accuracy all rise monotonically from Q1 to Q5, and false corrections fall from 2.1% to 0.6% (only 5 of the 612 CORRECT firings were judged false overall), whereas recall is non-monotone and peaks in the middle quintiles. ρt therefore tracks evidence precision, as a precision weight on the prediction error should.

Metrics. Results and analysis. Table 26 summarizes the comparative performance. PreCoMem achieves a retrieval P50 / P95 of 1.95s / 3.86s and an E2E P50 / P95 of 2.35s / 4.36s. • Efficiency via vectorized scoring: PreCoMem achieves a competitive P50 by leveraging a confidence-modulated hybrid scoring mechanism (Equation (1)). Rather than relying on computationally intensive generative re-ranking or iterative graph traversals, our approach efficiently aggregates semantic and lexical signals through parallelizable matrix operations. This design ensures that the computational overhead remains modest relative to pure vector retrieval, even as the complexity of the belief store increases. • Stability via deterministic flow: A critical advantage of PreCoMem is its robustness against latency spikes. Unlike agentic architectures (e.g., A-Mem) that may trigger unpredictable, recursive reasoning loops to resolve ambiguities, PreCoMem employs a deterministic, non-recursive retrieval flow. This architectural choice constrains both the retrieval tail (P95: 3.86s) and the E2E tail (P95: 4.36s), ensuring consistent performance without the extreme delays (E2E P95 up to 7.68s for A-Mem) often observed in stochastic agentic systems. • Retrieval vs. E2E gap: The gap between retrieval and E2E latency is dominated by generation, which is largely independent of the memory backend. PreCoMem’s E2E overhead over the retrieval stage (0.4s at P50, 0.5s at P95) is comparable to other non-agentic baselines, confirming that adding PROFILE /CORRECT does not materially inflate generation cost.

Axis 1: Robustness to noise and faithful preservation of user core traits. Existing systems represent the importance of an incoming observation categorically . GAM [25] writes one compressed memo per session into an immutable page-store with no per-item weight; EverMemOS [19] validates each MemCell within a hard time interval [tstart , t end ] and treats it as expired once the interval closes; TiMem [22] encodes importance through its five-level temporal hierarchy and explicitly notes the absence of a storage-time forgetting mechanism; MemBox [23] stores all events inside a sealed topic box at uniform weight; O-Mem [21] updates persona slots via an LLM that selects one of three categorical actions (A DD /I GNORE /U PDATE ); Mem0 [26] commits ADD/UPDATE/DELETE/NOOP and physically removes contradicted memories on DELETE; and A-Mem [24] replaces an existing note with an LLM-rewritten note via Memory Evolution. None of these systems can defer com-mitment when evidence is ambiguous: a weak signal is either ignored or instantly written as a fact. PreCoMem’s continuous confidence weight wt(m) ∈ [0 , 1] paired with the HYPOTHESIS waiting room lets weak cues accumulate evidence across turns and only graduate into FACT once support concentrates. The same mechanism preserves established traits: soft-decay correction (Equation (10)) reduces the influence of contradicted facts without erasing them, so a transient noise burst cannot remove a long-established trait the way a hard DELETE or overwrite would. This explains the LongMemEval-S gains on SSP (single-session preference), MS (multi-session aggregation), and KU (knowledge update) in Table 1, where ambiguous and conflicting cues dominate the question pool and categorical commit decisions are exactly the wrong granularity. 

Axis 2: Retrieval coherence and avoidance of fragmentation. Each baseline retrieval substrate carries a structural failure mode that PreCoMem sidesteps. GAM iterates a deep-research loop over its page-store, whose answer correctness is order- and budget-sensitive; EverMemOS issues dense+BM25 retrieval over Atomic Facts, fuses by RRF, and then runs a sufficiency-check loop that can leave cross-shard inconsistency between MemCells of the same scene; TiMem performs a two-stage hierarchical recall whose scope depends on a planner classifier; MemBox returns full topic boxes wholesale with no within-box reweighting; O-Mem aggregates three parallel channels (working / episodic / persona) by union, so irrelevant attribute hits dilute the context window; Mem0 falls back on a single dense-similarity threshold and discards deleted-but-relevant facts; and A-Mem performs pure cosine top-k over linked atomic notes, where the fine granularity amplifies fragmentation noise. All of these substrates therefore require an explicit reranker, sufficiency loop, or planner to suppress incoherent reads. PreCoMem instead multiplies a tri-signal relevance score by the per-item confidence 

wt(m) (Equation (1)), which acts as an implicit reranker at no extra LLM call: high-support items naturally rise to the Top-K, deprecated items naturally sink, and the entropy-based reliability ρt

(Equation (3)) further damps unreliable updates when the score mass is diffuse. This is what produces the bounded retrieval contamination in Table 20 and the bounded effective memory in Figure 5(b,c), both of which scale to the 1050-turn DiMoBench-XL run without recourse to a maintenance loop. 

Coupling the two axes. The two axes are complementary: Axis 1 controls what is committed so that the belief store stays faithful to the user’s core traits under noise, while Axis 2 controls what surfaces at read time so that the dialogue agent sees a coherent, currently-supported view. Existing baselines optimize one axis at a time (e.g., EverMemOS’s profile updates target Axis 1; GAM’s deep-research targets Axis 2) but lack a single mechanism that couples them. What the dialogue agent actually sees. Confidence weights wt(m) and other metadata are not ex-posed to the response-generation LLM. Case 1: Skill level calibration. Figure 11 (left) illustrates this case. The user initially reports a credential (CET-6), which can tempt a retrieval-only system to over-trust a single strong signal and recommend overly advanced practice. PreCoMem instead consolidates evidence across sessions: repeated behavioral cues (e.g., failing to articulate at an English corner) and professional feedback (teacher assessment) lower confidence in an over-optimistic self-evaluation, while preserving the belief that the foundation is adequate. At query time, Memory Leveraging recalls these calibrated beliefs (rather than a single credential trace) to condition response generation, leading to a plan that targets fluency and practice rather than premature advanced content. 

Case 2: Project experience reasoning. Long-horizon career discussions often mix stable skills (proven experience) with tentative claims (currently learning) and difficulty signals (struggles with complex systems). PreCoMem uses its confidence-weighted belief store to separate what is established 43 (e.g., Python/Flask) from what is still emerging (e.g., React “loading”) and what should be deferred (e.g., microservices architecture). This produces right-sized recommendations: it proposes a near-term path aligned with demonstrated capability, while explicitly marking a challenge zone for later progression. 

Case 3: A new topic entering a populated store. Suppose the store holds the user’s work and food profile but nothing about music, and the user says for the first time: “I signed up for guitar lessons and practiced for an hour last night.” No belief matches and the Top-K items are only loosely related, so absolute scores are low but one still dominates, giving a moderate ρt and, by the mechanism described in Section C.8, PROFILE . The Profile-Agent writes the hypothesis “the user may have taken up guitar” with w0 < τ promote , linked by provenance to that turn and retrieval-visible at once, so the agent can already answer cautiously. If guitar recurs, MAINTAIN reinforces the hypothesis until it crosses τpromote and becomes a FACT ; otherwise it remains a low-confidence hypothesis that never outranks committed facts. A new topic therefore enters provisionally, is usable immediately, and is committed only after repeated support. 

Connection to the consolidation loop. Across these cases, PreCoMem’s leveraging–evolution loop links response quality to memory consolidation. Evidence recalled for the current answer is also used to update confidence through MAINTAIN /PROFILE /CORRECT (Section 2.4), so future retrieval and recommendations reflect accumulated support, implicit verification, and soft correction under contradiction.
