## 摘要
长时间运行的智能体存在记忆问题，而这不是大多数系统所优化的那个问题。存储每一条轨迹并检索最近邻在早期有效，但随后会悄然失效：存储库中会塞满智能体之后重复的失败，以及五十轮之前曾经为真的事实。RSPM（递归自剪枝记忆）借用了生物学已经找到的解决方案。智能体会间隔性地睡眠。它将其近期失败进行聚类，把每个簇提炼成一条简短规则，并删除刚刚从中学习到的原始片段。规则除非得到强化，否则会衰减；在多种上下文中反复出现的规则会被提升为通用规则。我们在三个几乎没有共同点的设置上测试了该方法：一个经难度校准的 SWE-bench 模拟、跨 12 个对话基准的时间一致性，以及 LoCoMo-10 上的长时程问答。三者分别提升了 9.1、11.9 和 7.6 个点。更有趣的是，两项对存储本身进行观测的研究在没有朝该目标调参的情况下，收敛到几乎相同的工作点：重试循环减少约 93%，存储条目减少约 30%。这暗示，知道该忘记什么，是智能体记忆的一种普遍属性，而不是特定于基准的技巧。

## Abstract
Agents that run for a long time have a memory problem, and it is not the one most systems optimize for. Storing every trace and retrieving the nearest neighbors works early and quietly stops working later: the store fills up with failures the agent then repeats, and with facts that were true fifty turns ago. RSPM (Recursive Self-Pruning Memory) borrows the fix biology already found. At intervals the agent sleeps. It clusters its recent failures, distills each cluster into a short rule, and deletes the raw episodes it just learned from. Rules decay unless something reinforces them, and rules that recur across many contexts get promoted into general ones. We tested this on three settings with little in common: a difficulty-calibrated SWE-bench simulation, temporal consistency across 12 conversational benchmarks, and long-horizon QA on LoCoMo-10. All three improve, by 9.1, 11.9, and 7.6 points respectively. More interestingly, the two studies that instrument the store itself converge on nearly the same operating point without being tuned toward it: roughly 93% fewer retry loops and roughly 30% fewer stored entries. That hints that knowing what to forget is a general property of agent memory rather than a benchmark-specific trick.

## 1. 核心问题与整体含义（研究动机与背景）

- **问题定位**：长时程运行的 LLM 智能体（如处理 SWE-bench 级 GitHub issue、跨数十轮会话的助手、需回溯任意历史轮次的问答）普遍采用"**只增不减**"的记忆设计——保存全部轨迹、检索最近邻（RAG 范式）。作者指出，这一假设在早期有效，但随后会**静默失效**。
- **失效的三种表现（"记忆债 / memory debt"）**：
  - **存储膨胀**：条目线性累积，而 top-k 检索的有效容量不增长；朴素对话基线最终存 675 条、实际只能浮现 5 条。

  - **记忆过时**：已废弃 API 说明、用户四十轮前更改的偏好仍具全权重；对话超过 100 轮后基线准确率从约 **70% 滑落到约 58%**。
- **与现有工作的差异**：MemGPT 做分层分页、MemoryBank 做未用轨迹衰减、Reflexion / Voyager 把"经验教训"与原始经验并列存储——**但没有一个方法做到"先巩固、再删除"**。
- **生物学类比**：慢波睡眠中海马体回放近期片段、新皮层抽取模式，"片段消失、教训留存"（Stickgold 2005；McClelland et al. 1995），未被巩固者按 Ebbinghaus 曲线衰减。RSPM 将这两条观察直接写为算法。
- **整体含义**：论文主张"**知道该忘记什么**"可能是智能体记忆的通用属性，而非某个 benchmark 的特定技巧；剪枝与检索同等重要。

## 2. 方法论：RSPM（Recursive Self-Pruning Memory）

- **核心思想**：在普通检索增强智能体外包一层"睡眠—巩固—剪枝"循环，**用删除原始片段来支付巩固的成本**，使记忆总量不因抽象化而膨胀。
- **三大机制**：
  1. **睡眠周期（Sleep cycles）**
     - 触发条件：每 **S = 10** 个任务固定触发一次，或近期**失败率突增**时提前触发。
     - 单周期流程：聚类近期失败 → 每个簇蒸馏为**一条紧凑约束/规则** → **删除**产生该规则的原始 episode（图 1 中的虚线回指）。
  2. **时间衰减（Temporal decay）**
     - 每个知识单元赋予半衰期，有效强度公式：
       **P_eff(t) = P_0 · δ^⌊(t − t_0)/W⌋**
     - 低于阈值即"退休"，旧教训必须被重新强化才能保留。
  3. **升格（Promotion）**
     - 层级：**L3（实例/仓库级）→ L2（类别级）→ L1（通用级）**。
     - 判据：同一约束在 **3 个上下文**成立 → 升为类别级；在 **5 个上下文**成立 → 升为通用级。
- **检索侧**：检索打分被"存活规则"**重新加权**，即规则不仅压缩存储，也参与召回排序。
- **三种领域特化实例**（"什么使条目可剪枝"的不同定义）：
  - 软件工程：**失败聚类**（failure clustering）；
  - 时间一致性：**时间替代/失效检测**（temporal supersession）；
  - 长时程 QA：**失败关联**（failure association）。
- 论文以文字描述算法流程，**未给出伪代码、聚类算法选择、规则蒸馏提示词或冲突检测器实现细节**。

## 6. 主要结论与发现

- **性能提升**：SWE-bench 模拟 solve rate **40.0% → 49.1%（+9.1）**；时间一致性 **80.6% → 92.5%（+11.9）**，且超过 Oracle 的 88.4%；LoCoMo **+7.6 点至 72.8%**。
- **增益随难度增长**：SWE-bench 上从 <15 分钟问题的 +5.4 点升至 >4 小时问题的 **+13.2 点**，符合"压力越大巩固越重要"的预期。
- **存储结构**：19,008 个 issue 上形成 **3,438 条仓库级约束、24 条错误类规则、18 条通用规则**，存储条目比基线少 **30.6%**；LoCoMo 记忆曲线在约 **472 条**处趋平（基线 675 条）。
- **收敛现象**：三项独立调参的实验落到几乎相同的工作点——**重试循环减少约 93%、存储减少约 30%**，作者将其解读为"机制的均衡点"而非调参产物。
- **长时程不衰减**：基线随对话变长持续退化，RSPM 保持平稳。
- **遗忘的失败模式（重要负结果）**：在一个自然错误率 35% 的 LoCoMo 对话上，RSPM 触发 21 次睡眠、剪掉 43% 存储，最终**低于基线 19.5 点**；根因是"**参与失败的记忆导致了失败**"这一过强假设——该假设在记忆过时时成立，在**任务本身困难**时失效。
