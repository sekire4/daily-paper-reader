## 摘要
全模态助手不仅要记住用户说了什么，还要记住用户展示和传达了什么。现有的长期记忆基准大多为文本-图像形式，或只报告单一的端到端分数，因此无法定位证据在表示、检索、传递或读取过程中是否丢失。我们提出 MOSAIC，一个包含 923 个问题的基准，基于 11–24 个会话的、以人物设定为基础的历史，涵盖文本、图像、视频和音频。MOSAIC 构造有针对性的空间、时间和韵律信号，而非装饰性媒体，其中空间信息具有最强的因果验证，标注韵律具有选择器级验证，并将这些信号与匹配的诊断协议配对；该协议冻结问题、读取器、提示和预算，同时对表示、检索和传递进行干预。匹配分解表明，表示损失依赖于模态，即使给定金标准证据，残余的读取问题仍占主导，且在这些控制条件下拒答仍然较弱：较强的可回答分数与拒绝失败并存。因此，MOSAIC 将全模态记忆评估从排行榜转变为对写入、检索、传递和读取失败的诊断。

## Abstract
Omni-modal assistants must remember not only what users say, but also what they show and convey. Existing long-term memory benchmarks are mostly text-and-image or report a single end-to-end score, so they cannot locate whether evidence is lost when it is represented, retrieved, delivered, or read. We introduce MOSAIC, a benchmark of 923 questions over persona-grounded histories of 11-24 sessions spanning text, image, video, and audio. MOSAIC constructs targeted spatial, temporal, and prosodic signals rather than decorative media, with the strongest causal validation for spatial information and selector-level validation for annotated prosody, and pairs them with a matched diagnostic protocol that freezes the question, reader, prompt, and budget while intervening on representation, retrieval, and delivery. Matched decomposition shows that representation loss is modality-dependent, residual reading dominates even under gold evidence, and abstention remains weak on these controls: strong answerable scores coexist with failures to refuse. MOSAIC thus turns omni-modal memory evaluation from a leaderboard into a diagnosis of write, retrieve, deliver, and read failures.

## 一、核心问题与研究动机

- **背景**：GPT-4o、Gemini、Qwen-Omni、MiMo 等全模态助手正从单轮演示走向持久化、多会话部署。用户可能在 1 月分享产品照片、3 月留下饮食语音备忘，之后期望两者共同支撑推荐——这要求跨时间、跨模态地检索并串联证据。
- **现有基准的不足**：
  - 长期记忆基准大多只覆盖文本+图像（如 LoCoMo 图像常非必需、Mem-Gallery/MemLens 止步于图文共指），**缺少视频与音频**；
  - 多数只报告**单一端到端分数**，无法定位证据究竟在表示（write）、检索（retrieve）、交付（deliver）还是阅读（read）环节丢失；
  - 多跳文本 QA（HotpotQA、MuSiQue）缺乏多模态、多会话设定。
- **核心主张**：将全模态记忆流水线拆为 **WRITE → RETRIEVE → DELIVER → READ** 四阶段，用冻结读取器、提示、打包器、预算与评判器的**匹配干预**分别归因失败，把评估从“排行榜”变为“环节级诊断”。

## 二、方法论

### 1. 核心思想
- 构造**原生模态承载的“模态缺口”**（modality gap）——即只有原生模态能保留、文本/字幕会丢失的信息，而非装饰性媒体；
- 用**匹配诊断协议**在固定条件下逐段替换流水线组件，使每对分数下降可归因于被干预阶段。

### 2. 形式化流程
- 对历史 H、问题 q、交付预算 B：
  - M = W(H)（写入记忆表示）
  - R = G(q, M)（检索单元）
  - D = P(R, B)（序列化并打包进读取器请求）
  - â = F(q, D)（读取并作答）
- 关键区分：检索到的工件只有**实际送入模型**才算“交付”，否则计为交付失败而非阅读失败。

### 3. 七种匹配条件（同一批 784 道可答题）
- 金标符号事实（界定残余阅读/评分误差）
- 金标原生证据（隔离原生感知成本）
- 金标通用文本（VL 字幕 + Whisper ASR，隔离文本化损失）
- 金标结构化文本（查询盲的结构化写入器，隔离可避免的压缩）
- 检索原生、全部交付（隔离检索损失）
- 检索原生、生产上限（top-20、每模态≤3 件、100MB，隔离交付损失）
- 端到端原生 RAG（加入查询改写）

### 4. 模态缺口的构造性设计
- **图像**：背景细节、细粒度属性（品牌/价格/标签）、空间配置；
- **视频**：动作顺序、重复次数（1–2 / 4–5 / 8+ 分档）、状态转换；
- **音频**：中性措辞下的高兴/不高兴韵律，需在 ≥2 个同类候选中做选择。
- 每个可答题至少含一个“挑战承载事实”，并通过**删除测试**保证移除任一必需事实后问题不可答。

### 5. 推理链与事实角色
- 角色：NARROWER（缩小候选）、SELECTOR（定位实体）、ANSWER（携带最终值），模式为 NAR* SEL* ANS；
- 跨模态链要求必需事实横跨 ≥2 种模态；ANSWER 终值始终为短文本串以便判分。

### 6. 生成流水线（四阶段）
- 人物设定采样（Nemotron-Personas）→ 问题优先的链设计（桥实体约束、实体对约束）→ 验证-修复循环（12 种命名失败模式，最多 3 轮）→ 会话实现（时间泄漏防护、禁用值列表）→ 媒体合成（FLUX-2-pro / Kling–Seedance / Qwen3-TTS）→ 过滤与人工审计。

### 7. 逐项模态干预（12 个附加条件）
- 图像：原始 vs 仅 OCR vs 仅对象 vs 空间描述；
- 视频：原始 vs 有序稀疏帧 vs 打乱帧 vs 事件/计数文本；
- 音频：原始 vs ASR vs ASR+金标韵律标签 vs ASR+对调标签。

### 8. 双轨架构
- **Track A（固定读取器）**：比较各后端在相同读取器/提示/预算下产出的有效证据；
- **Track B（原生端到端）**：各系统用其原生控制器与读取器，描述可部署能力；
- 三种表示：Caption-Text（VL 字幕+ASR）、Omni-Text（单一全模态字幕，保留韵律）、Native-MM（多模态嵌入+全模态读取器）。

## 三、实验设计

### 1. 数据集
- **MOSAIC-Eval**：923 题（784 可答 + 139 拒答），70 个人设，每项 11–24 个会话（均值 17.5），约 18.8M token（每人设约 269K），10,765 个多模态工件（图像 4,297 / 视频 561 / 音频 5,907）。
- 可答题中 85.2% 需 ≥2 个事实、75.0% 需 ≥2 种模态；必需证据出现在图像/音频/视频/文本的比例分别为 99.5% / 54.1% / 23.5% / 35.3%（有重叠）。
- 题型分布：知识更新 20.9%、时间推理 20.5%、信息抽取 19.3%、拒答 15.1%、MSR 桥接 12.1%、MSR 选择 12.1%。
- 合成数据：人设、证据会话与全部媒体均为合成；填充对话取自 LongMemEval 公开池（UltraChat MIT / ShareGPT Apache 2.0）。

### 2. Benchmark 与对比方法
- **Track A**：平面 RAG（字幕文本 / Omni 文本 / 原生多模态）、A-MEM（字幕/Omni）、MemoryOS（字幕/Omni）。
- **Track B**：Naive RAG、ReAct-RAG、A-MEM、MemoryOS，分别跑 Caption / Omni / Native-MM 三种表示（共 12 个配置）。
- **读取器**：主读取器 Gemini 3.5（温度 0，关闭扩展思考，且**未参与数据构造**）；第二读取器 MiMo-V2.5（120 题试点复现阶梯）；Track B 文本用 DeepSeek-v4-Flash，原生用 MiMo-V2.5 / Gemini 3.5。
- **评判**：主评判 Qwen3.7-Plus（0–1 五档语义评分），GLM-5.2 与 Grok-4.5 作三评判面板复核（11,076 条三重评分）。
- **指标**：可答判分、正确拒答率与误拒率配对、必需事实 Recall@k、完整链 Recall@k / 链交付率、逐项配对效应（item-bootstrap 95% CI、W/T/L、persona 聚类 bootstrap 敏感性检验）。

### 3. 实验组数概览
- 7 个匹配阶段条件 + 12 个逐项模态干预 + 交付预算扫描（top-20/3 媒体、top-10/3 媒体、top-5/1 媒体）+ Track A 6 配置 + Track B 12 配置 + 三评判面板 + 100 题人工审计 + 100 题探针-YES 追审 + 视频功效分析。

## 五、实验数量与充分性

### 充分性亮点
- **配对设计严格**：所有阶段对比使用相同 QID、读取器、提示、打包器、预算与评判器，报告逐项配对差值与 bootstrap 置信区间、W/T/L 计数，并做 persona 聚类敏感性检验。
- **多重验证**：第二读取器（MiMo）在 120 题试点复现金标与预算阶梯；三评判面板 κ ≥ 0.96、Spearman ≥ 0.95；人工抽查 50 题与主评判 κ ≈ 0.79/0.69（人类均值 0.82）。
- **质量保证**：三标注者 100 题审计（94.3% well-posed），分层重加权估计发布集金标正确率 ≈97.8%、证据充分率 ≈96.6%；过滤谱系 1,050 → 1,004 → 879 → 923 完整披露。
- **交付失败可归因**：9,338 个“检索到但未交付”工件**全部**归因于每模态媒体数上限，无 token 上限、序列化或格式失败。

### 局限与风险
- **视频统计功效不足**：视频分层仅 n=56–64 个唯一 QID，80% 功效下 MDE 为 8.9–11.2 分，非显著结果**不能**证明时序压缩无损。
- **音频对比不确定**：原始音频 vs ASR 仅 +0.8、金标韵律标签 vs ASR 仅 +1.5，均不显著；作者承认文本化音频常残留副语言词汇线索，且其他金标跳已暴露答案值。
- **探针选择偏差**：探针通过（n=740）与人工救回（n=44）在金标符号下几乎相同（0.846 vs 0.845），但在金标原生下相差 27.8 分（0.799 vs 0.520），说明原生绝对分数偏乐观。
- **区间未做多重比较校正**：报告为逐对比未调整区间，探索性挑战层零结果需谨慎解读。

## 六、主要结论与发现

### 1. 阶段分解（784 可答题，固定 Gemini 3.5）
- 金标符号事实 **0.846** → 即使完美证据仍有 **15.4 分**残余阅读/评分误差；
- 金标原生证据 **0.783**（感知成本 **6.2** 分 [3.2, 9.3]）；
- 通用字幕/ASR **0.690**（相对原生 **−9.3**），结构化写入器仅恢复 **+1.4**（[−0.9, 3.7]，不显著）；
- 检索损失 **7.6** 分（[5.2, 9.9]），生产打包再损失 **3.8** 分（[1.5, 6.0]），完整链交付率从 0.675 降至 0.491；
- 端到端原生 RAG 达 **0.653**。
- **阅读是最大的单一关联损失**，且其主导性跨流水线稳定；原生流水线中检索领先，文本派生流水线中文本化领先。

### 2. 表示损失依模态而异
- **视觉被文本化严重压缩**：细粒度/背景项上原始图像比仅 OCR 高 **18.5** 分；空间配置项上高 **32.0** 分；显式空间描述比仅对象文本恢复 **15.4** 分（弥补约三分之一差距）——**“说出有哪些物体”不够，排列本身承载事实**。
- **视频感知成本最高**：符号 0.900 vs 原生 0.729（**17.1** 分），但有序帧 vs 打乱帧、事件文本 vs 稀疏帧均不显著（功效不足）。
- **韵律**：原始音频 vs ASR 不显著，但**正确金标韵律标签 vs 对调标签**在 399 个 QID 上提升 **4.6** 分（[1.7, 7.7]，W/T/L 46/330/23），证明标注选择器具有因果载荷。
