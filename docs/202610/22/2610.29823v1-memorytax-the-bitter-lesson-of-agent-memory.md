## 摘要
Mem0 和 Zep 等智能体记忆系统会在任何问题到来之前决定保留什么；编码智能体则保留原始历史，并让模型用自己的工具在其中搜索。我们考察：当模型强大到足以自行搜索时，精心设计的记忆是否仍有帮助。在一个 LoCoMo 对话（419 轮、152 个问题）上，我们运行四种记忆方法（完整上下文、BM25、Mem0、Zep）和三种编码智能体（Pi、Codex、Claude Code），每种均分别搭配 GPT-4o-mini、GPT-6 Luna 和 Claude Opus 5.5，并记录每次 rollout 的开销。这是一项简短的实证研究，每个实验单元仅包含一个对话和一次运行。智能体记忆是对弱模型的一种昂贵补丁：Mem0 仅在 GPT-4o-mini 上优于完整上下文，而且仅其构建开销就超过一次完整上下文运行的总成本。智能体记忆也存在上限，这一上限由写入记忆的模型决定：更强的读取者无法找回较弱写入者遗漏的内容。在 Claude Opus 5.5 下，Pi 位居成本-准确率前沿之首，以不到完整上下文一半的成本取得 99% 的得分；其唯一一次失误是答案键有误。这一领先部分来自只有这些智能体能读取的照片说明：在证据不含照片的 88 个问题上，Pi 与完整上下文仅相差一个答案。

## Abstract
Agent memory systems such as Mem0 and Zep decide what to keep before any question arrives; coding agents keep the raw history and let the model search it with its own tools. We ask whether designed memory still helps once the model is strong enough to search for itself. On one LoCoMo conversation (419 turns, 152 questions), we run four memory methods (full context, BM25, Mem0, Zep) and three coding agents (Pi, Codex, Claude Code), each with GPT-4o-mini, GPT-6 Luna and Claude Opus 5.5, and record what every rollout costs. This is a short empirical study, with one conversation and one run per cell. Agent memory is a costly patch for a weak model: Mem0 beats full context only with GPT-4o-mini, and its build alone costs more than a whole full-context rollout. Agent memory also has a ceiling, set by the model that writes it: a stronger reader does not recover what a weaker writer left out. With Claude Opus 5.5, Pi tops the cost-accuracy frontier, scoring 99% for less than half the cost of full context; its one miss is a wrong answer key. Part of that lead comes from photo captions that only the agents could read: on the 88 questions whose evidence has no photo, Pi and full context differ by one answer.

## 1. 核心问题与研究动机

- **背景**：当前主流智能体记忆系统（Mem0、Zep 等）采用“**先决定保留什么**”的范式：模型在问题到来之前就从对话中抽取事实或构建时序知识图谱，回答每个问题时只看到少量检索片段。
- **对立范式**：编码智能体（Pi、Codex、Claude Code）与递归语言模型则**保留原始历史**，让模型用自己的工具（shell、grep、文件读取等）按需搜索。
- **核心问题**：借用 Sutton 的“苦涩教训”（*The Bitter Lesson*）——内建于系统的知识初期有效、随后进入平台期，而随算力扩展的通用方法最终胜出——论文追问：**当模型强到足以自行搜索时，预先设计的记忆是否还有价值？**
- **整体含义**：这是一项**短小的实证研究**（作者自述），目的不是提出新系统，而是用“成本–准确率”这一双维度视角重新审视记忆系统的必要性，并指出“为更强模型不需要的记忆付费”构成一种**记忆税（Memory Tax）**。

- 将“记忆方法”与“智能体搜索”放在**同一成本口径**下比较：不只比准确率，还比**一次完整 rollout 的美元开销**（构建 + 全部 152 问）。

### 2.2 对比的七种方法（表 1）
| 方法 | 存储内容 | 回答时模型看到 |
|---|---|---|
| Full context | 原始历史 | 全部 |

## 6. 主要结论与发现

### 6.1 记忆是弱模型的昂贵补丁
- GPT-4o-mini：Mem0 **78%** > 全上下文 74% = BM25 74% > Zep 43%；智能体反而差（Pi 63%、Codex 28%、Claude Code 29%，后两者多数题根本不打开对话文件）。
- GPT-6 Luna：全上下文 **92%** > BM25 82% > Mem0 80% > Zep 51%。
- Claude Opus 5.5：Mem0 = 全上下文 **95%**，Zep 87%，智能体最高（Pi 99%、Codex 98%、Claude Code 97%）。
- **构建成本倒挂**：Mem0 构建单独花费 \$0.56 / \$0.45 / \$25.88，均高于同模型全上下文整轮 \$0.43 / \$0.29 / \$17.84；按每题差价需 372 / 545 / 596 题才能回本，而 LoCoMo 只有 152 题。Mem0 与 Zep **从未出现在成本–准确率前沿上**。

### 6.2 记忆存在由“写入者”设定的天花板
- Zep：GPT-4o-mini 写的图，被 4o-mini / Luna / Opus 读取仅得 43% / 43% / **45%**；Opus 写的图为 66% / 71% / **87%**。
- Mem0：4o-mini 存储读出 78/83/84，Opus 存储读出 89/91/95（差距更小但仍同序）。
- 结论：**更强的读取者无法找回更弱写入者丢弃的信息**——记忆是“保真度”瓶颈，而非“检索能力”瓶颈。

### 6.3 强模型下 Pi 位居前沿
- Pi + Opus 5.5：**99% @ \$6.95**，全上下文同模型 95% @ \$17.84；Codex 98% @ \$25.41、Claude Code 97% @ \$28.41。
- Pi 唯一错误是**答案键本身有误**（题问 Caroline 于 2023-10-13 分享的画，实为 Melanie 分享；Pi 指出该错误却被判错）；在其余 151 题上 Pi 全对。
- **领先来源拆解**：Pi 答对而全上下文答错的 7 题中，6 题证据落在含照片的轮次（caption 只有智能体能读）；在**无照片证据的 88 题**上，Pi 100%，全上下文/Mem0/Codex/Claude Code 均 99%——即“读同样的文本时，二者只差一题”。
- 因此作者明确表示：**“搜索是否优于全读”本研究无法定论**；能确定的是同等输入下 Pi 以不到一半成本达到同等水平。

## 7. 优点（亮点）

- **成本作为一等公民**：把“准确率”换成“成本–准确率前沿”和“累积成本–正确率曲线”，并给出 turn 数、token 数两个正交视角（图 4），直击记忆系统在工程落地中的真实权衡。
- **写入/读取解耦的交叉设计**极为巧妙：利用“检索不调用 LLM”这一特性把读者换掉，从而干净地分离“存储保真度”与“读取能力”两个混杂因素，是全文最有说服力的实验。

- **主动纠错**：发现并公开 LoCoMo 答案键错误，且指出该错误对多个强模型配置同样造成误判，体现评测素养。
- **协议透明**：附录给出容器、工具权限、轮次上限、成本核算、答案模板与 judge prompt 全文，可复现性较好。
- **克制的表述**：反复强调样本小、单次运行、结论是“提示性（suggest）”而非“证明”，并明确列出五类局限。

## 8. 不足与局限

- **规模极小**：仅 LoCoMo 十条对话中的 1 条、每个 cell 仅 1 次运行；几题之差可能不具稳定性，无方差、无置信区间、无显著性检验。
- **评分噪声**：单一 GPT-4o-mini 判官 + 宽松 rubric，存在同族偏好与“冗长即对”的风险；已确认至少一处标准答案错误。
- **照片信息不对称**：智能体可读 caption、记忆方法不可读，这一差异污染了“智能体 vs 记忆方法”的横向比较（作者承认，但未做补齐实验）。
- **上下文长度受限**：历史可完整放入所有模型窗口，因此“全上下文”始终是可行选项；对超长历史（如 LongMemEval、无法装入窗口的场景）结论未必成立，而后者恰恰是记忆系统的目标场景。
- **配置单一**：Mem0 / Zep 只用默认抽取与检索参数，未

调参，也未报告抽取质量（如事实遗漏率、错误率）的定量指标，因此无法区分“方法本身上限低”与“默认配置不适配”。
- **任务与场景单一**：LoCoMo 是单条长对话的问答，open-domain 仅 13 题；不覆盖多会话跨时间演化、跨文档/跨用户记忆、工具调用历史、超长历史（超出窗口）等记忆系统真正的目标场景，外推性有限。
- **智能体侧未做适配**：Pi / Codex / Claude Code 均使用默认工具与统一提示词，未针对“何时打开文件、如何切分检索”做提示工程或工具定制；Codex 与 Claude Code 大量题目根本不打开 `conv.json`，这既可能是模型行为倾向，也可能是提示词未引导所致，论文未做消融。
- **成本口径偏窄**：仅计模型调用标价，未计容器启动、检索服务运维、人工调参与系统开发成本；也未考虑缓存、批处理、蒸馏等工程优化，因此“美元成本”是相对比较而非绝对 TCO。
- **单对话选择缺乏敏感性分析**：作者以“与十条对话整体水平接近”为由选取 conv-26，但未展示选择过程或逐对话结果，无法判断该对话是否在某些方法上恰好有利/不利。
- **版本敏感性**：结论绑定于特定模型与工具版本（GPT-6 Luna、Opus 5.5、Pi 1.1.0 等），随模型迭代可能迅速变化——这既是论文的核心论点（苦涩教训），也意味着其数值结论具有时效性。

## 9. 讨论与启示

- **对记忆系统研究**：论文把评价轴从“准确率”转向“成本–准确率前沿”，提示记忆方法的合理定位应是**弱模型/短上下文/高频复用的场景**；当读取者足够强时，记忆的边际价值可能低于其构建成本，甚至成为负资产（写入即信息损失）。
- **对评测方法**：写入者/读取者解耦的交叉设计提供了一个可复用的实验范式——凡“检索不调用 LLM”的记忆系统都可换读者，从而把“存储保真度”与“读取能力”分离；这对区分“记忆没用”与“记忆没做好”至关重要。
- **对工程实践**：若模型具备可靠的工具使用能力，“保留原始历史 + 按需搜索”在成本上可能优于“预先抽取 + 检索”，尤其当构建成本需要大量查询才能摊薄时（本研究中需 372–596 题，远超 152 题）。
- **对“苦涩教训”的呼应**：论文的经验形态是——**手工设计的记忆抽象是一种先验注入**，短期有效、长期被通用搜索能力超越；但这只是“提示”而非“证明”，因为搜索与全读在同等输入下几乎打平，真正的差异来自多模态 caption 的可得性。

## 10. 总体评价

这是一篇**篇幅短小、定位克制、设计巧妙**的实证研究：它不提出新系统，而是用统一的成本口径与一组干净的解耦实验，对“智能体记忆是否必要”提出可检验的质疑。其最强之处在于**成本–准确率视角**与**写入/读取交叉设计**，最弱之处在于**样本极小、单次运行、评分噪声与多模态信息不对称**。作者对局限的坦诚陈述（样本小、单次运行、结论为“提示性”）使其作为**假设生成型工作**是可信的；但若被引用为“记忆系统无用”的定论，则超出了其证据强度。更准确的读法是：**在模型足够强、历史可完整入窗、且原始文件可被工具访问的条件下，预抽取记忆的成本优势并不自动成立；记忆的价值需要在更长历史、更弱模型、更高复用率的场景中重新定位。**

（完）
