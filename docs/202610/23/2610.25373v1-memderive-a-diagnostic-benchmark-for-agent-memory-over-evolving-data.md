## 摘要
长期运行的智能体依赖对过去交互的记忆来获取任务状态，例如哪些已完成、哪些条件仍然成立。这种状态通常是派生状态。没有任何记录直接陈述它，必须根据规则从演化历史的多条记录中计算得到。现有记忆基准仅对最终答案评分，未提供其背后中间状态的参照。因此，错误答案无法追溯到被遗漏的状态，而悄然过时的状态也无法被检测到。我们提出 MemDerive，一个面向演化数据的智能体记忆诊断基准。它用符号方式指定每个场景，使用 Datalog 推导精确的金标准答案，记录每个查询的金标准推导 DAG 和支持事件，并用虚构实体和干扰项以自然语言呈现历史。其 10 个场景包含 4,692 个事件和 1,503 个查询，难度沿访问、演化和组合三个维度变化。基于该真实标注，MemDerive 评估答案可靠性，通过探测金标准推导 DAG 的节点来诊断失败，并跟踪随着事件到达答案是否保持正确。我们对四个记忆系统的评估揭示了最终答案基准所隐藏的失败。在派生状态上，每个记忆系统都落后于简单的 BM25 检索，尽管同一答案模型在给定支持事件时达到 96.01%。大多数失败属于未收集型：系统持有缺失的中间状态，却没有为需要该状态的问题检索它。记忆系统也很少传播隐式变化，而这些变化没有任何新记录直接陈述。这些结果为记忆设计提出三项原则：沿推导过程收集输入，存储规则及其版本，并通过记录的依赖关系维护派生状态。

## Abstract
Long-running agents rely on memory of their past interactions for task state, such as what has been completed and which conditions still hold. Such state is usually a derived state. No record states it, and it must be computed by rules from multiple records of an evolving history. Existing memory benchmarks score only the final answer, with no reference for the intermediate states behind it. A wrong answer therefore cannot be traced to the state that was missed, and a state that silently became outdated goes undetected. We present MemDerive, a diagnostic benchmark for agent memory over evolving data. It specifies each scenario symbolically, derives exact gold answers with Datalog, records the gold derivation DAG and the supporting events of every query, and renders the history in natural language with fictional entities and distractors. Its 10 scenarios contain 4,692 events and 1,503 queries whose difficulty varies along access, evolution, and composition. On this ground truth, MemDerive evaluates answer reliability, diagnoses failures by probing the nodes of the gold derivation DAG, and tracks whether answers stay correct as events arrive. Our evaluation of four memory systems reveals failures that final-answer benchmarks hide. On derived state, every memory system falls behind simple BM25 retrieval, although the same answer model reaches 96.01% when given the supporting events. Most failures are ungathered, as a system holds the missing intermediate state but does not retrieve it for the question that needs it. Memory systems also rarely propagate implicit changes, which no new record states. These results suggest three principles for memory design. Gather inputs along the derivation, store rules with their versions, and maintain derived states through recorded dependencies.

## 1. 核心问题与研究动机

- **背景**：长时运行的智能体依赖记忆来判断任务状态，例如“哪些已完成”“哪些条件仍成立”“还剩下什么”。这类状态通常不是某条记录直接陈述的，而是需要根据规则从多条历史记录中计算得到，作者称之为**派生状态（derived state）**。
- **核心问题**：现有记忆基准（LoCoMo、LongMemEval、StateMemBench、MemTrace 等）主要只评分最终答案，缺少对中间派生状态的参照。因此：
  - 错误答案无法追溯到具体遗漏了哪个中间状态；
  - 某个状态悄然过时（没有新记录直接提到它）也无法被检测；
  - 现有基准中的更新多为“显式更新”，而派生状态会因依赖变化而发生“隐式变化”。
- **整体含义**：论文把智能体记忆类比为数据库中的“视图”：基础数据是自然语言历史，视图在问题到来时才被定义。派生状态具有四个难点：
  - **隐式性**：没有记录直接陈述；
  - **联合支撑**：多个事件只有组合起来才相关，且数量可能超过检索预算；
  - **分层依赖**：中间状态逐层组合，底层错误会向上传播；
  - **间接变化**：输入事实或规则变化即可改变派生状态，即使新事件没有提到该状态。
- **初步证据**：在 LoCoMo/LongMemEval 历史中加入同历史的“状态问题”后，Mem0 从 86.7% 降至 33.3%，Cognee 从 60.0% 降至 16.7%；给定正确子问题答案后答案模型可解全部状态问题，说明瓶颈在**中间状态的获取**，而非组合。

## 2. 方法论

### 2.1 核心思想

- 用**符号化场景 + Datalog 程序**生成精确金标准，避免人工标注派生状态；
- 为每个查询记录**金标准推导 DAG**和**支撑事件/见证集（witness）**；
- 将符号历史**渲染为自然语言**，并加入虚构实体与干扰项；
- 以黑盒方式评测记忆系统，通过“状态探针”定位失败，通过“跟踪查询”评估维护能力。

### 2.2 关键定义与流程

- **事件与历史**：事件 \(e=(t_e,r_e,A_e)\)，包含观测时间、自然语言记录、符号动作集合；历史 \(O\) 是事件集合。系统只读记录文本，金标准只依赖动作。
- **版本与截断**：查询固定观测截断 \(\tau\)，只可见 \(O_{\le\tau}\)；每个事实取最新版本，被后续修订/取消的旧版本视为过时。规则同样带版本并被解析。
- **派生程序与闭包**：\(P_\tau\) 由领域固定规则和当前规则组成，是带分层否定与聚合的 Datalog 程序；闭包 \(C_\tau=\text{Derive}(P_\tau,B_\tau)\)，派生状态是 \(C_\tau\setminus B_\tau\) 中的事实。基准不物化整个闭包，只计算查询所需状态。
- **查询与金标准**：查询 \(q=(\theta,\tau)\)，目标 \(\theta\) 为派生状态；答案标签包括 answerable、justified-zero、unknown。对于计数/总和/空集，只有某事件断言集合“完整”时才能判定答案。
- **金标准推导 DAG**：根为目标，内部节点为中间派生状态及所用事实/规则，叶子为断言这些事实或声明规则的事件；共享输入使其为 DAG 而非树。高度衡量推导深度，宽度衡量单层组合输入数。
- **支撑与见证**：支撑 \(S(q)\) 为贡献于某推导的事件集合；见证 \(W\subseteq S(q)\) 为可推导出答案的最小事件子集，遵循最小 why-provenance。干扰项是记录看似相关但不影响答案的事件。

### 2.3 三维难度控制

- **Access（访问）**：通过事件分散、词汇缺口、间接指代和干扰项，控制支撑事件是否容易聚齐；
- **Evolution（演化）**：构造多次修订的更新链，并把过时记录放在历史后段；
- **Composition（组合）**：控制组合度，从单一操作到版本解析、规则应用、完整性检查的组合。
- 每个查询在生成时即控制难度，并在金标准 DAG 上度量，因此失败可归因到具体维度。

### 2.4 评测方法（Q1–Q3）

- **Q1 答案可靠性**：
  - 答案按类型确定性判分，不用语言模型裁判；
  - 引用评分：精度 \(p_E\) 对支撑集 \(S(q)\)，召回 \(r_W\) 取所有见证中的最佳匹配；两者调和平均为引用 F1；
  - Witnessed Accuracy：答案正确且 \(p_E,r_W\ge 0.5\)。
- **Q2 失败诊断**：
  - 将金标准 DAG 的节点转成**状态探针**，每个探针在两种上下文中回答：
    - **继承上下文**：使用父节点问题所返回的上下文，模拟推导时实际可用的信息；
    - **定向上下文**：把探针作为新查询直接问系统，测试其能否直接返回该状态。
  - **失败前沿**：某节点在继承上下文中错误、但其所有子节点正确，即为失败首次偏离点；
  - **失败分类**：
    - **ungathered（未收集）**：直接问能答对，但需要它的上层请求没有取回；
    - **unretrievable（不可检索）**：即使直接问也无法返回事实或规则；
    - **misderived（错误推导）**：输入已收集但派生状态算错。
  - **两种恢复干预**：
    - 自证据恢复：从系统直接答对的停止节点自底向上重建答案；
    - 金证据恢复：错误叶子替换为金标准状态后重建，用于判断错误证据是否“承重”。
- **Q3 派生状态维护**：
  - 固定查询在多个检查点 \(\tau_1<\cdots<\tau_m\) 重复提问，系统在检查点前增量摄入新事件；
  - 定义 **Refresh**（变化后答案是否更新）与 **Preservation**（未变化答案是否保持），均以上一检查点答对为条件；
  - 区分**显式变化**（新事件的动作直接断言包含新答案的事实）与**隐式变化**（无新记录提到变化状态，仅通过依赖传播）；
  - 辅助指标： stale-answer rate、recovery delay、continuous correctness、摄入与查询时成本。

### 2.5 基准构造流水线

1. 符号化场景规格（事件、Datalog 规则、查询目标与截断、难度控制）；
2. 参考求值器一次性产生金标准答案、推导 DAG 和见证；
3. 自然语言渲染：忠实记录、实体虚拟化、加入词汇缺口与干扰项；
4. 编译为状态探针与检查点查询。

## 6. 主要结论与发现

- **发现 1：记忆系统在派生状态上普遍落后于原始检索。**
  - 四个记忆系统答案准确率 30.41–48.30%，最强 Mem0 仍低于 BM25 的 58.28%；
  - Full-Context 79.84%，Oracle 96.01%，说明差距在记忆系统供给的内容；
  - 匹配上下文预算后差距仍存在：Mem0 在 8K 后平台约 77.25%，16K 时事件级 BM25 仍达 78.75%；
  - 准确率沿 Access、Evolution、Composition 三个维度均下降；宽推导同样重要，高宽推导上 Oracle 仍 86.80%，记忆系统仅 15.25–25.22%；
  - 在 LongMemEval 上 Mem0 84.00% 超过 BM25 78.60%，但在 MemDerive 上 BM25 超过所有记忆系统，排名不可迁移。
- **发现 2：大多数失败是“未收集”（ungathered）。**
  - 记忆系统 61–85% 的错误答案含 ungathered 状态；
  - 直接问时 BM25/Cognee/Mem0 能返回 86–94% 的上一层状态，但在需要它的请求上下文中仅 54–74%；
  - 自证据恢复最多提升 30.0 个百分点；
  - 规则尤其难返回：Mem0 仅 17%、LightMem 仅 8% 的规则探针正确；
  - LightMem 不同：83% 错误含不可检索事实，摄入阶段丢失证据，只有金证据恢复能修复较多失败。
- **发现 3：维护能力“保旧强、更新弱”。**
  - 记忆系统保持 91.03–92.86% 的未变化答案，但只刷新 35.71–63.64% 的变化答案；
  - 显式变化刷新率 82.4%，隐式变化仅 41.1%；原始检索分别为 83.3% 和 63.1%；
  - 记忆系统的 stale answer 多发生在隐式变化后，原始检索多发生在显式变化后；
  - 到最后一个检查点，106 个变化中仍有 66–79 个未被恢复（Oracle 仅 1 个）；
  - 连续正确率从首个检查点 28.03–65.15% 降至最后 16.67–41.67%，Oracle 保持 93.18%。
- **成本发现**：记忆系统把成本前移到摄入，但摄入工作既未缩小准确率差距，也未改善隐式变化刷新。
- **设计原则**：
  - 沿推导路径收集输入（拆分派生状态请求为输入请求）；
  - 规则应作为一等对象随版本存储；
  - 通过记录依赖关系维护派生状态，类似增量视图维护。

## 7. 优点

- **问题定义清晰且有理论根基**：将派生状态形式化为带版本、分层否定与聚合的 Datalog 闭包，并与数据库视图、provenance、增量视图维护建立联系。
- **金标准精确可复现**：符号规格 + 参考求值器同时产生答案、推导 DAG 和最小见证，避免人工标注与 LLM 裁判的不稳定性。
- **诊断能力强于只看最终答案**：状态探针、失败前沿、三类失败分类和两种恢复干预，能定位“错在哪一层、为什么错、是否承重”。
- **难度可控**：Access、Evolution、Composition 三维独立控制，便于归因分析。
- **防捷径设计**：实体全部虚构、问题使用派生谓词词汇、关键术语可只出现在干扰项中，降低预训练知识泄漏。
- **评测公平性考虑细致**：统一答案模型、引用精度对额外支撑不惩罚、召回取最佳见证、维护指标条件于前一检查点正确。
- **实验分析维度丰富**：按支撑大小、见证年龄、过时引用、组合度、高度/宽度、算子族、上下文预算、成本等多角度切分。
- **可复现性**：公开数据集与评测框架，并说明可重新生成场景以应对训练数据污染。

## 8. 不足与局限

- **领域覆盖有限**：仅 3

- **领域覆盖有限**：仅 3 个领域（TripOps、ShopOps、EduOps）、10 个场景，均属业务流程型规则推理；缺少开放域对话、个人生活记忆、多模态或跨会话长期记忆等场景，外部效度仍有待检验。
- **符号生成带来的“整洁性”偏差**：事件、规则、完整性声明均由程序生成后再渲染为自然语言，底层结构规整、实体虚构、指代与词汇缺口可控；真实用户历史中的噪声、歧义、自相矛盾陈述、口语省略与错误信息未被系统刻画，渲染模板与真实语言分布的差异也未量化。
- **版本语义相对简化**：事实取最新版本、规则带版本解析，能覆盖修订与取消，但真实系统还可能出现并发写入、回滚、部分覆盖、冲突未决等情形，论文未讨论这些更复杂语义下金标准的定义方式。
- **“完整性”判定依赖符号规格**：justified-zero 与 unknown 的区分依赖某事件显式声明集合完整，而真实历史中“集合是否完整”通常不可判定，这一标签在开放场景中的可迁移性存疑。
- **系统覆盖与调参有限**：仅四个记忆系统，均使用默认配置，未做系统级超参搜索或提示工程优化，可能低估部分系统的能力上限；也未纳入更多新兴记忆架构（如基于结构化表、SQL 或工作流引擎的方案）。
- **答案模型单一、缺少统计检验**：仅使用 GPT-5.6 Sol，未报告多模型复现、多次采样方差、置信区间或显著性检验，结论对答案模型的依赖性未知。
- **子集评测的统计功效**：诊断覆盖 1,029 个查询、维护仅 132 个查询 × 5 检查点（106 个变化转移，其中隐式变化 88 个），虽覆盖每个场景，但隐式变化样本量偏小，分维度结论的稳健性需谨慎看待；上下文预算实验也仅 400 查询。
- **跨基准比较的不可比性**：LoCoMo、LongMemEval 使用各自官方问题集与更严格的裁判提示，绝对分数不能与原始论文直接对齐，只能作方向性参照。
- **成本口径不完整**：只报告 API token 费用与中位检索延迟，未给出延迟分布尾部、本地部署成本、缓存与重试开销，也未把成本与准确率合成统一效用指标。
- **缺少人类基线与人工评估**：未报告人类在该基准上的表现，也未对渲染文本的自然度、可读性或标注质量做人工核验。
- **未物化完整闭包**：基准只计算查询所需状态，因此无法评估系统在“未被查询的派生状态”上的行为，也无法检测系统是否在其他状态上悄然出错。
- **对未显式建模依赖的系统可能不完全公平**：隐式变化的判定以金标准依赖图为准，对不维护依赖关系的架构而言，该指标更多反映其架构选择而非单纯“能力缺陷”，论文对此的解释空间有限。

## 9. 总体评价与启示

- **定位**：MemDerive 的价值主要不在于“再做一个更难的记忆问答数据集”，而在于把**派生状态**这一被现有基准系统性忽略的记忆对象形式化，并配套了可归因的诊断工具链。它更接近“记忆系统的视图维护测试台”，而非单纯的端到端问答榜单。
- **方法论贡献**：符号规格 + 参考求值器 + 自然语言渲染的三段式流水线，兼顾了金标准的精确性与评测表面的自然性；推导 DAG、最小见证、状态探针、失败前沿与三类失败分类构成了一套可复用的诊断语汇，可迁移到其他需要多跳证据组合的评测中。
- **实证贡献**：三条发现具有较强的实践指向——(1) 抽取式/图式记忆系统在需要组合多条记录的场景中可能不如原始检索；(2) 主要瓶颈是“上层请求没有把下层证据取回”，而非“取回后不会组合”；(3) 维护能力呈现“保旧强、更新弱”，隐式变化是主要盲区。这三点直接指向“沿推导路径检索”“规则一等化存储”“依赖驱动的增量维护”三条设计原则。
- **适用边界**：结论最适用于规则明确、状态可判定的业务型长历史场景（报销、订单、学位审核等）；对开放式、主观性、无明确规则的记忆任务，其指标与结论需重新校准。
- **开放问题**：如何在不依赖符号规格的前提下判定“完整性”与“隐式变化”；如何把依赖图思想引入端到端神经记忆系统；如何在检索预算受限时做推导感知的查询分解；以及如何将成本、延迟与准确率统一为可比较的效用度量。
