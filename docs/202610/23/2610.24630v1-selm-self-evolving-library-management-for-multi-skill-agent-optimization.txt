## ABSTRACT 

Large language model (LLM) agents increasingly use skills as a lightweight way to acquire task-specific knowledge. Recent work enables skills to evolve from task trajectories. However, these methods often lack systematic management of evolved skills, making it difficult for agents to reuse and accumulate skills across domains, thus limiting performance on subsequent tasks. To reliably accumulate, reuse, and maintain useful skills across tasks, we present S ELM (Self-Evolving Li-brary Management), a framework that formulates skill evolution as library-level management. SELM jointly manages skill retrieval, updating, and lifecycle by maintaining skill confidence and utility signals. It introduces utility-aware re-trieval to select useful skills, a Map-Reduce framework to generate targeted up-dates from task-specific experience, and lifecycle controls to retain or remove skills based on their effectiveness. These mechanisms enable the skill library to continuously accumulate useful experience while preserving and pruning skills across tasks, improving agent performance on complex tasks across diverse do-mains. We evaluate S ELM on four agent benchmarks covering diverse tasks and execution environments, and S ELM consistently outperforms in most settings. 

## 1 INTRODUCTION 

Large language model (LLM) agents are increasingly used to solve complex tasks across different domains. To improve agents’ behaviors on specific tasks, recent work introduced skills (Anthropic, 2025), which are pieces of text that can be plugged into the agent context to provide task-specific knowledge, procedures, or experience. This gives agents a simple way to gain specialized knowledge without additional model training. Recent work has explored how skills can evolve as the agent runs. Early skills were mostly static: they were written by experts or saved from successful experiences and then kept unchanged (Zhao et al., 2024; Anthropic, 2025). More recent methods allow agents to update skills from their ex-ecution trajectories (Yang et al., 2026a; Alzubi et al., 2026; Liu et al., 2026; Zhang et al., 2026a; Zheng et al., 2025; Ni et al., 2026; Ma et al., 2026; Zhou et al., 2026; Zhang et al., 2026b). After running tasks, the agent can examine which skill worked or failed, then edit existing skills or create new ones. In this way, skills can change with the agent’s experience and adapt to new tasks and environments. However, although these evolution methods propose many strategies to evolve skills (Alzubi et al., 2026; Zhang et al., 2026a; Zheng et al., 2025; Zhou et al., 2026; Zhang et al., 2026b), few of them focus on how to manage them. A skill revision that best fits the current round can be harmful to later processes. For instance, a skill that is unused or unhelpful for the present task may be overwritten or discarded; once that change is committed, a later task can never recover the deleted skill. The core problem is that existing methods always treat skill updates as separate, one-round edits, rather than managing skills as a dynamic, long-term library. Thus, a skill management library is needed to decide not only how a skill should change, but also which skills should be retrieved, which skills should be updated, and which skills should remain in the library. To address these limitations, we propose S ELM (Self-Evolving Library Management), a framework that manages skills as a library and jointly controls their retrieval, updates and lifecycle. By tracking and leveraging skill confidence and utility, S ELM enables the library to evolve with task experience and improves the performance of the agent across complex tasks in different domains. Specifically, S ELM introduces a skill library with explicit mechanisms for managing skill states. To dynamically evaluate skill usefulness, each skill is associated with a confidence score and a utility score. Confidence reflects how strongly the skill is supported by update operations, while utility reflects how useful it has been across tasks. These mechanisms provide a clear basis for deciding which skills should stay active, which skills should be removed, and which failed skills should not be added again. The library can thus keep a skill that is unused on the current task but still useful later, and drop one that keeps failing, instead of committing every local edit, enabling reliable, long-term skill management. Second, S ELM designs a Map-Reduce framework for skill updates. Applying every trajectory to all the skills will make experience from different types of task overwrites each other. SELM 

therefore groups execution trajectories by task category(Map) and analyzes each group separately, identifying which skills are affected and what changes are needed. It then combines these analyses into operations(Reduce), such as adding new skills, editing existing ones, and deleting those that no longer help. All these operations apply only to the relevant skills and unrelated skills are left unchanged, so a change that helps the current category won’t erase skills required later, which enhances skill effectiveness. Third, S ELM proposes utility-aware skill retrieval . Existing methods mainly retrieve skills based on their semantic relevance to the current task (Yang et al., 2026b), which overlooks whether the skill has been useful in previous tasks. S ELM leverages historical utility to enhance skill retrieval. It first selects skills from the same task category and then ranks them by their relevance to the current task and their past usefulness. This helps the agent distinguish skills that are relevant to task on hand and have proven useful through previous execution experience, thus enabling more effective skill selection. 2Finally, we evaluate S ELM on four agent benchmarks covering diverse execution environments and areas. SELM achieves state-of-the-art results among skill-evolution methods, outperforming both single-document optimization and prior multi-skill baselines without updating model parameters. Our contributions are (1) introducing a skill library that tracks skill confidence and utility, managing skill validation, retention, and removal, enabling reliable skill management throughout the evolution process; (2) designing a Map-Reduce framework that analyzes trajectories by task category and generates targeted operations, allowing the agent to update relevant skills based on task-specific experience; and (3) developing a utility-aware retrieval method that ranks skills using both task relevance and historical utility, enabling the agent to select skills that are both relevant and useful. Across our experiments, S ELM outperforms existing skill optimization methods, demonstrating the effectiveness of the proposed framework. 

## 2 RELATED WORK 

Skill construction and evolution. Recent work has increasingly explored constructing and evolv-ing textual skills from agent experience, moving beyond manually specified or static skill represen-tations (Zhao et al., 2024; Anthropic, 2025). More broadly, approaches such as TextGrad (Yuksek-gonul et al., 2025) and GEPA (Agrawal et al., 2026) optimize textual instructions through feed-back without updating model parameters, while Dynamic Cheatsheet (Suzgun et al., 2026) and ACE (Zhang et al., 2026c) iteratively refine textual context from agent experience. Building on this paradigm, SkillOpt and SkillGrad optimize a shared skill document or skill package by repeat-edly editing textual knowledge based on execution feedback (Yang et al., 2026a; Wang et al., 2026). Other approaches distill execution trajectories into standalone lessons, strategic principles, or veri-fied skills, thereby converting individual experiences into reusable knowledge (Zhao et al., 2024; Wu et al., 2026; Ni et al., 2026; Ma et al., 2026; Qiu et al., 2026). Rather than maintaining a single shared artifact, SkillWeaver (Zheng et al., 2025), EvoSkill (Alzubi et al., 2026), SkillEvolver (Zhang et al., 2026a), Memento-Skills (Zhou et al., 2026), and CoEvoSkills (Zhang et al., 2026b) construct collec-tions of specialized skills to capture different task types or capabilities. Complementary approaches construct skills from external domain resources or learn skill-related policies through interaction and co-training (Yang et al., 2026b; Liu et al., 2026; Xia et al., 2026; Jiang et al., 2026). Despite these advances, existing methods primarily focus on how skills are created or improved, treating skill evolution as a sequence of local construction or editing operations. This becomes limiting when multiple skills coexist: updates to a shared artifact can introduce conflicting changes, while independently accumulated skills provide limited mechanisms for determining which skills should be updated. 

Skill library management. Early work such as Voyager (Wang et al., 2023) and ExpeL (Zhao et al., 2024) retrieves executable or experiential knowledge according to the relevance of the cur-rent task. Subsequent systems make skill selection more behavior-aware and introduce mecha-nisms for validating candidate skills or deciding whether updates should be merged, accepted, or discarded (Zhou et al., 2026; Yang et al., 2026a;b; Alzubi et al., 2026; Zhang et al., 2026b; Qiu et al., 2026). More recent work explicitly considers the maintenance of the skill library itself. Skil-lOps studies how an existing skill collection can be periodically reorganized to address issues that emerge as the library grows (Pu et al., 2026), while MUSE-Autoskill organizes skill creation, cata-log retrieval, per-skill memory, and test-driven refinement into successive lifecycle stages (Lin et al., 2026). Lifelong evaluations further suggest that usage frequency alone is insufficient to characterize the utility of a skill, motivating more explicit utility-aware management (Zhang et al., 2026d). How-ever, these approaches generally address retrieval, validation, update selection, or lifecycle main-tenance as separate mechanisms, rather than jointly optimizing them as coupled decisions over a continually evolving skill library.

## 4 METHOD 

SELM freezes the target model M and optimizes only the skill library. At each iteration, the agent retrieves a small set of skills from the current library, uses them to solve a batch of training tasks, and converts the resulting trajectories into library updates. The updated library is then evaluated on the selection set and retained only when it passes the validation gate. This iterative process jointly improves skill retrieval, skill updates, and library quality, with the overall procedure summarized in Algorithm 1 (Appendix A). For each skill, S ELM manages it through two pieces of information: confidence score and utility score. The confidence score v(s) reflects how strongly a skill should be retained based on update operations, while the utility score u(s) records how useful the skill has been across tasks. These two scores support different stages of the library evolution process: confidence is updated by UP-VOTE/DOWNVOTE operations and used for lifecycle control, while utility is used to guide skill retrieval and updated from execution outcomes. Multi-timescale Updates. Following prior work on iterative skill evolution (Yang et al., 2026a), SELM uses both fast and slow updates. Fast updates are performed after each training batch to incorporate recent trajectory feedback, while slow updates are performed less frequently across epochs to consolidate changes that persist over time. 5.2 MAIN RESULTS 

Table 1 shows that S ELM consistently improves agent performance across different benchmarks and target models. Compared with no-skill baseline and existing skill optimization methods, S ELM 

achieves substantial gains in both no-harness and Claude Code settings, demonstrating the effec-tiveness of managing skills as a structured library rather than optimizing a single shared document. The improvements are also consistent across Claude-Opus-4.6, DeepSeek-V4-Pro, and Qwen3-30B-A3B, suggesting that the benefit of library-level optimization is not tied to a specific target model. Meanwhile, Static human-written skills and one-shot LLM skills provide only limited improve-ments, while trajectory-driven methods perform better but remain below S ELM . This indicates that the main benefit comes from continuously managing which skills should be retrieved, updated, and retired. In particular, the advantage is more pronounced in heterogeneous settings such as Skills-Bench, where task-specific feedback can conflict when compressed into a single skill document. 5.3 ABLATION STUDY

Library-management controls are critical to the effectiveness of skill evolution. Table 2 shows that removing the validation gate causes the largest single drop, while removing the utility score and utility-aware retrieval reduces only 2.9 points. Removing both meta skills and slow updates also leads to a large degradation, compared with 53.1% when removing meta skills alone. The graveyard provides a smaller but consistent gain, with accuracy dropping to 50.4% without it. These results show that validation, utility-aware selection, and longitudinal library updates are important for preventing ineffective skill changes from accumulating. 

SELM is relatively insensitive to the EMA decay factor around the default setting. As shown in Figure 3(a), α=0 .4 achieves 56.5% accuracy, while α=0 .2 and 0.6 obtain 55.1% and 55.3%, respectively. More extreme values, α=0 .1 and 0.8, reduce accuracy to 52.4% and 53.1%. This indicates that the performance gain is not dependent on a narrowly tuned smoothing coefficient. 

A stronger optimizer generally produces a more effective skill library, while weaker optimizers can still benefit stronger target models. Figure 3(b) shows that, with Qwen3-30B-A3B as the target, replacing the optimizer with DeepSeek-V4-Pro and Claude-Opus-4.6 increases soft accuracy from 20.45% to 24.75% and 31.34%, respectively. The same trend holds for DeepSeek-V4-Pro as the target. Meanwhile, using Qwen3-30B-A3B as the optimizer still improves Claude-Opus-4.6 from the no-skill baseline. 5.4 LIBRARY EVOLUTION ANALYSIS 

Table 3 shows how the skill library changes during evolution on SpreadsheetBench with Qwen3-30B-A3B. The initial library contains 5 skills and achieves 17.5% accuracy on the selection set. In Epoch 1, five new skills are added, but the accuracy remains unchanged. This shows that simply adding more skills does not improve performance. In Epoch 2, only two new skills are added while four skills are downvoted, and the accuracy increases to 30.0%. The slow update then makes two edits, adds two meta skills, and downvotes two more skills. Three skills are eventually moved to the graveyard because their confidence becomes non-positive, and they are therefore excluded from future retrieval. The final library achieves 36.43% accuracy, compared with 30.0% for the no-skill baseline. These changes show that the library does not improve simply by growing in size; useful skills are added, while skills that repeatedly receive negative feedback are removed or revised. 

## 6 CONCLUSION 

We propose S ELM , a framework that manages skills as a library. S ELM tracks skill confidence and utility, validates skill updates, and retires failed skills. Through the Map-Reduce framework and utility-aware retrieval, S ELM helps the agent select the most relevant and effective skills. Semantic deduplication. The graveyard mechanism operates at the name level (exact string match), preventing exact-name oscillation but not semantically equivalent skills with different names from coexisting. Embedding-based similarity detection would be a natural extension. 

Cross-environment transfer. A skill library optimized on one benchmark could potentially warm-start optimization on another, analogous to transfer learning in neural networks. We leave explo-ration of cross-benchmark transfer to future work. 

Scalability. While we demonstrate effectiveness with up to 30 skills across 8 categories, scaling to hundreds of categories or thousands of skills would require more sophisticated indexing (e.g., embedding-based retrieval) and potentially hierarchical library organization. 

Optimizer model dependence. The quality of evolution depends on the optimizer LLM’s ability to analyze trajectories and synthesize CRUD operations.
