## Abstract 

We study whether geometric relationships between conversation turns, memory texts, and queries can predict answer correctness before generation. We evaluate four memory implementations with dense or hybrid retrieval and one observation-summary comparator. We embed these texts in a shared space. A logistic classifier uses 25 features describing query proximity, memory–conversation correspondence, and conversation structure. On LongMemEval-small, pooled AUROC is 0.640 over 2,367 question–system pairs, below a question-difficulty baseline of 0.655. Perfor-mance varies by question type: geometry reaches 0.841 on single-session-assistant questions, but system identity alone reaches 0.826. After controlling for diffi-culty and identity, geometry adds no statistically established pooled improvement (∆ = +0 .002 , 95% CI [−0.010 , 0.014] ). A fixed-store context-selection experi-ment finds higher accuracy with proximity-ranked memories than with random subsets, consistent with ordinary retrieval relevance. On LoCoMo, nearest-turn similarity has modest predictive value for single-hop questions and near-chance estimates for several other categories. Training uses correctness labels; predic-tion uses pre-answer features and no additional LLM generation call. The results characterize associations between memory representations and correctness, rather than establish a reliable deployment diagnostic. In particular, embedding proximity does not verify fact coverage or distinguish memory-construction, retrieval, and generation errors. 

## 1 Introduction 

Long-term agent memory can use text retrieval, summaries, knowledge graphs, symbolic stores, or parametric updates. This study focuses on text memory representations associated with dense retrieval. We also include an observation-summary system as a comparator. Benchmark QA accuracy measures one aspect of these systems, alongside cost, latency, storage, and other concerns. A separate question is whether a signal available before generation can help identify queries that are likely to receive an incorrect answer.

We study three representations: source conversation turns, memory texts produced by a system, and an incoming query. Dense retrieval systems already embed memories and queries. We addition-ally embed conversation turns in the same space (Figure 1). We compute two feature blocks and conversation covariates: • Query reachability : nearest-memory distance, mean distance to the five closest memories, local memory density, and nearest-turn distance. Here, reachability names an embedding-proximity measurement. • Memory–conversation correspondence : turn-to-memory proximity, session alignment, memory count, and memory dispersion. These describe geometric correspondence rather than verified coverage of individual facts. A logistic classifier predicts answer correctness from these features. We examine variation across question types, incremental prediction beyond question difficulty and system identity, and accuracy under different context-selection rules. The strongest observed AUROC is 0.841 for single-session-assistant questions. However, system identity alone reaches 0.826 on that same type. The high within-type score therefore does not establish independent prediction of instance-level memory failures. Pooled over all types, geometry adds no significant gain beyond difficulty and system identity (§5.6). Memory construction can omit evidence, retrieval can miss evidence already stored, and generation can fail despite sufficient retrieved context. We test the hypothesis that the first two cases leave geometric signatures. Our use of retrieval-bound refers to this motivating hypothesis, not a verified classification of the observed errors. Distances alone cannot show whether an answer-bearing fact was stored, included in the actual prompt, or used correctly. A warning score could eventually support abstention, broader retrieval, or recovery from the source conversation. Our present results do not validate such a deployment policy. ## 2 Related work 

Agent-memory benchmarks and systems. LongMemEval [Wu et al., 2025] evaluates 500 ques-tions in six categories over multi-session histories. LoCoMo [Maharana et al., 2024] uses a different conversational dataset and question taxonomy. Memory-system studies report end-to-end QA results alongside other measurements [Chhikara et al., 2025, Rasmussen et al., 2025]. We examine whether features of the memory representation are associated with per-question correctness. 

Selective prediction and confidence. Selective prediction ranks examples by expected correctness and allows deferral [Hendrycks and Gimpel, 2017, Geifman and El-Yaniv, 2017]. Verbalized confidence and P(True) use the answer model’s own judgment [Kadavath et al., 2022]. Our geometric score is supervised during training but does not require another generation call at prediction time. 

Retrieval diagnostics and query-performance prediction. Query–passage similarity is an es-tablished retrieval signal. Query-performance prediction estimates retrieval difficulty from query or ranked-list statistics [Cronen-Townsend et al., 2002, Carmel and Yom-Tov, 2010]. RAG evaluation also measures answer groundedness, often using LLM judges [Es et al., 2024, Saad-Falcon et al., 2024]. Our reachability features overlap with ordinary similarity and ranked-list signals. The setting here is a memory representation constructed from a conversation. We add conversation–memory correspondence, compare correctness across memory implementations, and examine differences by question type. The intervention tests the value of relevant context, without establishing a new geometric cause separate from relevance. 

## 3 Geometric features 

A shared model E : text → Rd embeds conversation turns T , stored memory texts M , and a query q.Distances are cosine distances between unit-normalized embeddings. The core reachability scalar is 

q_nn_mem = min m∈M d(q, m ). The query block has six features. The correspondence block has 14 features: seven coverage, two alignment, and five memory-dispersion features. The full model also includes five conversation-structure covariates, for 25 features in total (Appendix A). Coverage here means proximity between embedded texts. A nearby memory may omit the required detail, express a stale fact, or contradict the source. A distant memory may still contain the answer. The classifier is logistic regression on standardized scalar features. Inspectable inputs do not give its coefficients a causal interpretation. 

## 4 Experimental setup 

Systems and benchmark. We evaluate five implementations on LongMemEval-small. Four retrieve text using dense similarity, with hybrid retrieval in one case. The fifth constructs an observation summary and passes it to the answer model. We use the following functional names: • Sem-RAG : semantic-chunk RAG over source turns (65.8% accuracy). • Obs-Extract : a local Mastra-style observation-memory implementation (67.9%). Its logged representation is one observation summary. • Ext-Dense : instruction-based extraction and dense retrieval (72.6%). • Svc-Mem : a local LangMem-based implementation (73.2%). • Ext-Hybrid : instruction-based extraction and hybrid retrieval (86.0%). These results concern the particular configurations in our harness. They do not represent all configu-rations of the named libraries or products. The answer model and judge use the gpt-4o API alias across these runs. Answer prompts remain specific to each implementation. The feature analysis uses deduplicated memory texts recorded in answer logs, rather than the precise context passed to the answer model. Joining these representations and judged answers gives 2,367 question–system pairs over 500 distinct questions. Appendix B gives counts and implementation details. 3Protocol. We use StratifiedGroupKFold with five folds, grouping by question_id and using seed 0. This keeps all system rows for a question in one fold. Scaling is fitted on each training fold. Reported AUROCs use one cross-validation pass. Each per-type result comes from a separate classifier trained within that type. We predict correctness and report AUROC for that ranking; reversing labels and scores gives the corresponding failure AUROC. 95% intervals resample question groups from fixed out-of-fold predictions, with 1,000 draws. They capture sampling variation conditional on that fit, not model-refitting or split-selection uncertainty. Paired comparisons use the same question-group resampling. The original analysis imputes undefined features using column means before the fold split. The question-difficulty baseline likewise fits unsupervised PCA on the full question set. These operations do not use labels, but expose preprocessing to held-out covariates. Grouping controls the specific leakage caused by repeated question rows. The conversation-only baseline is 0.505 under this grouped protocol. Primary embeddings use text-embedding-3-small .

5.7 Selective answering: an exploratory illustration 

Ranking original out-of-fold predictions by P(correct) and retaining the top-scoring fraction raises accuracy among retained rows from 0.734 at full coverage to 0.786 at 70% coverage and 0.841 at 30%. These are retrospective calculations on the evaluation predictions, rather than a separately tuned and tested deferral policy. They do not establish a benefit over difficulty-plus-identity deferral, and no intervals for these coverage points are reported. The score requires no additional LLM generation call, but embeddings and feature computation still incur cost.

## 6 Discussion 

Interpretation. Proximity and representation features are associated with correctness, and the association varies by question type. However, system identity alone approaches the high within-type score, and geometry does not add significant pooled value beyond identity and difficulty. The intervention confirms the importance of selected context, consistent with established retrieval relevance. For memory-system evaluation, this distinction matters: a high pooled or within-type prediction score can reflect differences between implementations, rather than detect unsupported queries within an implementation. Comparisons should therefore include system-identity and question-difficulty controls, alongside results within comparable memory representations. The reachability gap summarizes outcomes offline. It does not certify evidence sufficiency or a live prediction’s reliability. An answer-distant reference anchor suggests a possible memory omission, but cannot verify one. A useful next study would audit whether an answer-entailing memory exists in the store and reaches the actual prompt. That could separate memory construction, retrieval, and generation errors more directly than embedding distances. 

Limitations. The study covers two English benchmarks and five harness implementations. Obs-Extract exposes a whole summary as one memory text, so representation granularity differs substan-tially across systems. Question type does not control architecture or question-content effects. The analysis uses one grouped-CV split and fixed-prediction bootstrap intervals. Full-set imputation and question PCA expose preprocessing to held-out covariates. Feature choices were explored on this benchmark without a final independent test set or nested model selection. The intervention uses one extracted-memory system and fixed memory counts rather than equal token budgets. The reference-anchor bins use labels and thresholds, with no entailment audit. LoCoMo category estimates lack conversation-level uncertainty. API aliases were not recorded as dated model snapshots. These limits preclude claims of general deployment reliability. 

Privacy and broader impacts. A validated diagnostic might help reduce unsupported answers through deferral or additional evidence gathering. An unreliable score could instead encourage false confidence or unnecessarily withhold useful answers. We have not evaluated fairness across user groups or languages. Correspondence features require access to source-turn embeddings. Deployments should enforce consent, retention limits, joint deletion of turns and derived embeddings, and access controls between users. Memory poisoning and disclosure to external embedding providers also require consideration. We evaluate existing benchmarks, without introducing a study with human participants. 

Conclusion. Geometry describes memory representations and their association with answer cor-rectness. The observed association is strongest for single-session-assistant, but system differences account for much of that result. The incremental pooled signal beyond difficulty and identity is not established. The contribution is a characterization of the evaluated signals and their limits. Verified failure attribution and deployment decisions require further study.

## B Reproducibility details 

Implementations and row coverage. Sem-RAG is the harness store rag-mem , Ext-Dense is 

redis-instruct , Ext-Hybrid is remis-instruct-full , Obs-Extract is mastra-om , and Svc-Mem is langmem . The latter is a local library integration, rather than a managed service. Rows are Sem-RAG 412, Ext-Dense 456, Ext-Hybrid 500, Obs-Extract 499, and Svc-Mem 500. The 133 missing rows relative to 5 × 500 reflect incomplete logged answer/judge coverage. Missingness need not be random, so run accuracies are not a fully paired system comparison. The predictor table includes 500 distinct question IDs. Per-type row/distinct-question counts are: single-session-assistant 265/56, temporal-reasoning 623/133, single-session-user 333/70, single-session-preference 137/30, multi-session 639/133, and knowledge-update 370/78. For each example, the feature code deduplicates the memory strings in its answer-log records and treats their union as M . It does not reconstruct the exact answer-model prompt. Claims about the complete backend store or actual prompt inclusion would require a separate audit. 

Classifier and preprocessing. We use scikit-learn LogisticRegression , L2 regularization, C =1, solver=lbfgs , max_iter=2000 , and no class weighting. StratifiedGroupKFold uses five folds, shuffling, and seed 0. Each training fold fits its own standard scaler. Undefined entries are mean-imputed column-wise before splitting. There are 2,495 such entries: five features undefined for each of 499 single-summary Obs-Extract rows. Columns with no finite values are filled with zero. Per-type results fit separate models on the corresponding rows. The difficulty baseline uses type one-hot encoding, character count, and PCA-64 of question embeddings. PCA uses all unique 10 question texts without labels, including held-out covariates. Future evaluation should fit imputation and PCA within each fold and reserve an independent final test set. 

Feature choices and computation. Query top-k uses k = 5 . Density thresholds are the 25th, 10th, and 5th percentiles of pairwise turn distances. Coverage and redundancy use the 10th and 5th percentiles because the 25th-percentile versions saturated in exploratory analysis. The conver-sation GMM selects K ∈ { 1, . . . , min(10 , |T |)} by BIC, with diagonal covariance, seed 0, and 

reg_covar = 10 −4. Memory effective rank is exponential entropy of normalized singular val-ues [Roy and Vetterli, 2007]. Silhouette measurements use cosine distances [Rousseeuw, 1987]. Figure 1 uses t-SNE only for display [van der Maaten and Hinton, 2008]. Embedding inputs are capped at 24,000 characters; local models also apply their tokenizer’s context limits. We use their default encoding configuration. Embedding computation is additional work unless those represen-tations are already retained. Pairwise-distance features have quadratic time or memory cost in the relevant set size. We do not provide complete runtime, hardware, or API-cost accounting.

Intervals exclude classifier refitting and exploratory feature-selection uncertainty. The embedding comparison reports sample standard deviation across four models. The context-selection intervention uses gpt-4o-mini and gpt-4o answer aliases, with gpt-4o-mini judging. Answer and judge calls use temperature 0. at temperature 0. The judge uses the harness’s generic answer-correctness prompt. Category-table labels come from the full-conversation condition ( rich ).
