## 摘要
LLM 记忆被广泛用于长期对话理解。智能体记忆系统通常采用变更、结构化组织、学习式检索策略或其他复杂操作。这种复杂性总是必要的吗？我们研究 Raw-RAG，一种朴素 RAG 基线，它在原始历史记录上使用稠密检索和重排序，为阅读器 LLM 提供证据。在 LoCoMo、LongMemEval、MEME 和 MemoryAgentBench 上，Raw-RAG 在七个基准-模型设置中的六个里于所比较的记忆系统中排名第一，比最强的对比智能体记忆系统高出 0.13–5.53 分。我们探究了原始历史检索为何仍具竞争力。证据分析表明，其对必要证据的更高覆盖率可以抵消较低的证据利用率。有用证据既包括答案值，也包括推导这些答案所需的关系和依赖路径。即使完全访问经过转换的记忆存储，相对于原始证据仍存在准确率差距，这凸显了保留原始信息的重要性。这些发现挑战了在所评估的对话任务中复杂智能体记忆的必要性，并将朴素 RAG 确立为一项基本基线。

## Abstract
LLM memory is widely used in long-term conversation understanding. Agentic memory systems often use mutation, structural organization, learned retrieval strategies, or other complex operations. Is this complexity always necessary? We study Raw-RAG, a naive RAG baseline using dense retrieval and reranking over raw history to supply evidence to a reader LLM. Across LoCoMo, LongMemEval, MEME, and MemoryAgentBench, Raw-RAG ranks first among the compared memory systems in six of seven benchmark-model settings, outperforming the strongest compared agentic memory system by 0.13-5.53 points. We investigate why raw-history retrieval remains competitive. Evidence analysis shows that its higher coverage of necessary evidence can offset lower utilization. Useful evidence includes both answer values and the relations and dependency paths needed to derive them. Even complete access to transformed memory stores leaves an accuracy gap relative to raw evidence, highlighting the importance of preserving raw information. These findings challenge the necessity of complex agentic memory for the evaluated conversation tasks and establish naive RAG as an essential baseline.

## 1. 核心问题与整体含义

- **研究动机**：LLM 长期对话记忆领域近年涌现大量“智能体记忆系统”，普遍引入事实抽取、摘要、变更（UPDATE/DELETE）、层次整合、图构建、学习式/迭代式检索等复杂操作。作者追问：**这些复杂性是否总是必要？**
- **背景张力**：RAG 常被认为不适合长期记忆，理由有二——(a) 概念上 RAG 面向静态语料，难以处理被取代的事实、删除与依赖状态变化；(b) 经验上已有评测显示 RAG 落后于智能体记忆系统。
- **整体含义**：论文以“朴素 RAG over 原始历史”为诊断基线，系统性地检验上述两点质疑，主张在现有对话类基准上，复杂记忆管理带来的增益被高估，**保留原始信息 + 高质量检索**才是主要瓶颈所在，并呼吁将朴素 RAG 作为必备对照基线。

## 2. 方法论：RAW-RAG

- **核心思想**：不做任何 LLM 驱动的记忆变换（不抽取、不摘要、不建图、不变更），直接对原始对话历史做稠密检索 + 交叉编码器重排序，把证据交给 reader LLM，由 reader 自行完成时间排序与状态重建。
- **索引构建**：
  - 每条消息保留日期、说话人、内容；缺失日期标记为 unknown；图像以 caption 文本入索引。
  - 以 GPT-4 分词器切分为 **256 token 窗口、32 token 重叠**（stride 224），建立扁平向量索引。
  - 每个窗口回链原始消息，便于证据组装时恢复完整对话轮次。
- **检索流程（两阶段）**：
  1. 稠密检索：用问题嵌入做余弦相似度，取 **Top-128** 候选窗口：
     \(D_q = \text{Top128}\{\cos(e(q), e(c)) : c \in \text{chunks}(H)\}\)
  2. 交叉编码器重排序：对 (问题, 窗口) 联合打分，取 **Top-15**：
     \(S_q = \text{Top15}\{r(q,c) : c \in D_q\}\)
  - 选中窗口可展开为完整源对话轮次（turn expansion），仅改变 reader 可见文本，不改变选择分数。
- **Reader 输入**：检索 query 与最终作答 prompt 分离；按基准附加日期提醒、任务模板、选项等；主实验不设额外证据 token 上限，也无自动截断。
- **基准适配**：MEME 按源顺序呈现以保留时间推进；MemoryAgentBench 关闭轮次展开，FactConsolidation 源以单条事实为 chunk 且无重叠，以保留序号线索。
- **重排序器**：Qwen3-Reranker-4B 使用“Given a question and a passage, determine if the passage contains information relevant…”的 yes/no 分类模板。

## 6. 主要结论与发现

- **主结果**：RAW-RAG 在 **7 个基准-模型设置中的 6 个**排名第一（排除 Full-context），领先最强智能体记忆系统 **0.13–5.53 分**（LoCoMo +0.65–0.95、LongMemEval +0.13、GPT-4o-mini MEME +2.24、MemoryAgentBench +4.48–5.53）。唯一落后的是 DeepSeek-V4-Flash 的 MEME（MemMachine 领先 1.52 分）。
- **变异并非必要**：Mem0 的 UPDATE+DELETE 仅占 LoCoMo 写决策 4.39%、LongMemEval 2.46%；**有效变异仅 1.90% / 1.34%**。改为 ADD/NONE-only 后 LoCoMo 从 67.36% 升至 69.42%，各题型均不降。
- **Reader 能自行重建状态**：在证据完整的前提下，DeepSeek-V4-Flash 在 MEME 级联任务达 82.32%、失效任务 91.54%，说明复杂状态转移可从原始证据中解析。
- **瓶颈是“证据获取”而非“证据利用”**：RAW-RAG 覆盖率最高（MemoryAgentBench 45.29%、MEME 76.35%），而各系统利用率区间窄（80.00–89.71%）；覆盖率跨系统差异（40.66 pp）远大于利用率差异（21.04 pp）。
- **路径完整性关键**：RAW-RAG 的条件路径覆盖 P(path | result) 最高（62.34%），MemU 仅 9.62%——检索到答案值不等于保留推导所需的时间/依赖关系。
- **原始信息保留不可替代**：即使给予完整存储的金标访问，各系统仍比原始证据低 **4.06–30.54 分**；保留源文本的 RAW-RAG 与 MemMachine 恢复最好（57.54 / 57.46 vs 原始 61.60）。
- **效率优势显著**：MEME 切片 Add+Search 仅 305.91 s，比次快系统快 5.1×、比 EverMemOS 快 30.4×；BEAM-1M 摄入 0.33 h vs Memora 26.95 h（约 83×）。
- **记忆管理增强反而有害**：原子事实抽取 −19.62 分（TTL 从 47.68 崩至 15.37）、摘要增强 −5.81、图扩展 −5.78。
- **检索设计要点**：reranker 不可或缺（−3.92 分），final-k=1 灾难性下降（−11.73），k=120 因噪声下降（−14.57），k∈[5,60] 稳定；chunk 128–1024 影响不显著。

## 7. 优点

- **问题意识尖锐**：用“朴素基线”反向检验领域默认假设，属于高价值的方法论纠偏；并系统审查 14 篇前人工作中的 RAG 基线配置缺陷（chunk 过大、top-k 过小、缺 rerank），指出“差距可能来自弱基线”。
- **诊断链条完整**：从“变异是否必要”→“reader 能否重建状态”→“覆盖率 vs 利用率”→“结果覆盖 vs 路径覆盖”→“完整存储 oracle”，层层递进定位瓶颈，而非仅报告分数。
- **消融与控制设计细致**：统一 5k 预算、turn-expansion-aware 裁剪、complete-store 与 raw control 共享任务策略、gold-informed selector 公式明确。
- **统计规范**：配对 bootstrap + Holm 校正 + 置信区间，明确说明重采样单元（问题/源/episode）与适用边界。
- **效率视角**：同时报告准确率、摄入延迟与 token 成本，揭示“复杂记忆的代价”这一常被忽视的维度。
- **可复现性强**：附录给出完整 prompt 模板、baseline 配置、硬件与软件版本、评分解析规则，并开源代码。

## 8. 不足与局限

- **任务覆盖有限**：仅限离线、公开、文本对话基准；未覆盖交互式、多模态、工具调用、需要向其他系统暴露权威状态或执行删除合规的场景。
- **原始存储的代价未量化**：raw history 随历史线性增长，存在存储与隐私/删除合规问题；固定候选与 reader 预算可能漏掉分散或低相似度证据。
- **Reader 依赖性强**：状态重建能力高度依赖 reader（MEME oracle 跨模型差 35 分），结论对弱 reader 是否成立未知；跨系统利用率估计受各自问题集影响，非完全受控比较。
- **Complete-store 诊断的解释边界**：导出为最终快照（除 EMem），被覆盖/删除对象不可见；raw 与 store 的差距混合了信息损失、证据组装、位置效应（lost-in-the-middle）等多因素，作者亦承认“不是信息损失的纯度量”。
- **基线公平性残留问题**：部分基线用已发表分数（reader/prompt/预算不一致）、Mem0/MemOS 部分实验用早期托管版本、各系统沿用原生调参而未统一重调。
- **统计与结论强度不均**：PersonaMem-v2 未做显著性检验且 RAW-RAG 仅列第三；5k 预算下的 LoCoMo/LongMemEval 提升包含 reader/judge 波动（LoCoMo 增益主要来自未改动上下文的题目）；部分消融（如原子事实）耦合了 token 量与格式破坏两种因素。
- **“复杂性不必要”的边界需谨慎外推**：作者明确限定于“所评估的对话任务”，未否定在更长历史、多模态、有明确状态机或合规删除需求的场景中结构化记忆的价值。
