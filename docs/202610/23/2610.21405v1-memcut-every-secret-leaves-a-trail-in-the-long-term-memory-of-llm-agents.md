## 摘要
长期记忆已成为大语言模型（LLM）智能体的关键组成部分，而大多数研究聚焦于准确高效地检索相关信息。然而，可靠的记忆系统还必须应请求遗忘敏感用户数据。为评估这一能力，我们提出 MemCut，一个面向用户请求遗忘的系统性基准。其在长程对话中手工设计的 456 个秘密均具有完整标注的证据轨迹，用于测试删除后的恢复，包括从从未直接陈述这些秘密的消息中恢复。我们提出两种恢复指标。原生恢复（Native recovery）通过系统的检索来衡量读取器的成功率，而残余恢复（residual recovery）衡量同一读取器在直接获得可追溯到已标注披露或证据的存活对象时的成功率。我们建立三个参考删除基线，以测试现有检索器和写入模型在五种记忆设计和四种 LLM 下对遗忘的支持程度。删除披露内容对原生恢复的降低远大于对残余恢复的降低。由 LLM 引导从二十个检索候选中额外删除十个轮次后，仍留有 39–76% 的残余恢复。子集扫描（144 个事实、三个系统、两个模型）表明，在固定预算下扩大候选池比删除所有原始候选更能降低残余恢复。这些扫描将候选覆盖识别为参考基线中的瓶颈。

## Abstract
Long-term memory has become a crucial component of large language model (LLM) agents, with most research focusing on retrieving relevant information accurately and efficiently. However, a dependable memory system must also forget sensitive user data upon request. To evaluate this capability, we introduce MemCut, a systematic benchmark for user-requested forgetting. Its 456 hand-designed secrets in long-horizon conversations have fully annotated evidence trails to test recovery after deletion, including from messages that never state the secrets directly. We propose two recovery metrics. Native recovery measures reader success through the system's retrieval, whereas residual recovery measures the same reader's success when directly given surviving objects traced to annotated disclosures or evidence. We establish three reference deletion baselines to test how far existing retrievers and write models support forgetting across five memory designs and four LLMs. Disclosure removal reduces native recovery far more than residual recovery. LLM-guided deletion of ten additional turns from twenty retrieval candidates leaves 39-76% residual recovery. Subset sweeps (144 facts, three systems, two models) show that widening the pool at a fixed budget reduces residual recovery more than deleting all original candidates. These sweeps identify candidate coverage as a bottleneck in the reference baselines.

## 1. 核心问题与研究动机

- **背景**：长期记忆（long-term memory）已成为 LLM 智能体的核心组件，但现有研究几乎全部聚焦于“如何更准、更快地检索”，而**如何按用户请求可靠地遗忘敏感信息**（如诊断结果、并购交易）受到的关注极少。GDPR 第 17 条明确规定了“被遗忘权”。
- **核心洞察**：删除“直接披露秘密的那条消息”≠ 遗忘。秘密会以**证据轨迹（evidence trail）**的形式散落在大量普通记录中——这些记录单独看无害、从不直接陈述秘密，但组合起来可以推导出秘密（如“访问地点→地址→唯一注册公司”推出收购标的）。
- **关键概念区分**：现有基准（LoCoMo、LongMemEval、MemoryAgentBench、Memora、ForgetEval、MemLeak、TOFU）只测“直接回忆”或“相关线索”，而 MemCut 测的是**可推导性（derivability）**：存活记录联合是否仍能推出未言明的秘密。
- **另一层动机**：助手“答不出来”也不能证明遗忘成功——检索器可能只是没找到存活证据，换一个查询或检索器仍会泄漏。因此需要把“看不见”与“不存在”分开度量。

## 2. 方法论

### 2.1 任务形式化
- 定义**受保护事实（protected fact）**为 secret；其**证据 E** 为支持但不陈述该事实的轮次；**披露 D** 为直接陈述它的轮次。
- 每个样本 = 1 个受保护事实 + 1 个 **episode**（长多会话对话，所有对象可追溯到源轮次）。
- 标注三类结构：**disclosure D**、**sufficient sets S**（最小证据组合，可多路推导）、**distractors**（形似但不支持的干扰轮次）。
- **遗忘判据**：删除集 X 真正遗忘该事实，当且仅当 `D ⊆ X` 且对每个 `S ∈ S` 都有 `X ∩ S ≠ ∅`（即 X 必须“击穿”每一条推导路径）。
- **cut** = 与所有充分集相交的证据轮次集合；**minimal cut** = 最小的 cut。

### 2.2 两个恢复指标
- **Native recovery（Nat）**：用系统自身检索回答问题，衡量“助手还会不会说出来”。
- **Residual recovery（Res）**：跳过检索，直接把所有存活对象（可追溯到标注披露/证据者）喂给同一读取器，衡量“记忆本身还支不支持”。
- **隐藏风险份额**：`Hid = (Res − Nat) / Res`，是“残余成功中被原生检索漏掉的比例”的**保守下界**（因两者独立作答，Nat 偶尔命中 Res 未命中者，故实际缺口更大）。
- **三项设计约束保证可比**：① 同一模型回答两者（reader 固定）；② 清理与原生恢复使用同一 retriever；③ 删除某轮即删除其派生的全部对象（**closure**），使 Res 只看到删除器真正保留的内容。

### 2.3 基准构建
- **人类设计、模型措辞**：作者指定披露、证据、充分集、干扰项，GPT-6 渲染为对话，作者逐轮核对，每 episode ≥12 小时。
- **规模**：15 个 episode，跨工作/家庭/社交，1–3 个月，平均 2,893 轮，共 43,402 轮 / 490 会话 / 1.74M tokens；456 个秘密（每 episode 约 30 个），四类推导各 113–115 个。
- **四种推导类型**：Fact assembly（实体属性拼装）、Relation chain（跨实体链接）、Aggregation（数值聚合）、Temporal/state reasoning（时序状态推理）。
- **证据特性**：平均跨 8.0 个会话，仅 1.8% 证据与披露同会话；每事实平均 8.1 个证据轮、15.7 个最小充分集（共 7,148 个，每个 2–5 轮、均值 2.7 轮）、26.6 个高混淆干扰项；最小 cut 平均 3.04 轮、最大 5 轮。
- **防猜测设计**：四选一、允许拒答、选项细节级干扰、两种选项顺序均需答对。
- **质量校验**：Qwen3.8-Flash 作独立读取器，组合证据恢复率 96–99%，三个对照组（最佳单证据轮 / 移除标注证据与披露后 / 仅问题选项）均为 0%；两名与建库无关的标注者审计 120 个分层事实，初始一致率 97.6%；枚举法与动态规划两算法对全部 456 个最小 cut 交叉验证一致。

## 3. 实验设计

### 3.1 基准与场景
- 使用自建的 **MemCut**（456 事实、15 episode、四类推导），主表覆盖全部 456 事实；扫描实验使用 EP01–05 的 144 个事实子集。
- 每个事实在 store 的**全新副本**上评估，避免事实间干扰。

### 3.2 三种参考删除基线
- **S0**：删除披露及其派生对象（披露移除基线）。
- **S1**：检索排序清理——用删除请求查询一次，构造 20 轮候选池，删 top-10。
- **S2**：LLM 引导清理——用写入模型对同 20 候选重排后删 top-10（固定池以隔离“选择”因素）。
- 预算合理性：单事实证据 ≤10 轮、最小 cut ≤5 轮，故 10 轮预算“理论上够用”。

### 3.3 五种记忆设计
- 两种逐字检索库：**Turn RAG**（按轮检索）、**Session RAG**（按会话检索）。
- 三种带推导的系统：**MemoryBank**（原始轮 + 日摘要）、**Nemori**（主题段改写为叙事）、**LightMem**（离线整合摘要、不留原文）。
- 统一协议：以 **turn** 为计量单位（记录源轮、按 closure 删除、池与预算按轮计），使不同对象粒度的系统可比；harness 将开源。

### 3.4 四个写入/读取模型
DeepSeek-V4.1-Flash、Qwen3.8-Flash、GLM-5.3-Flash、MiMo-V2.5，同一模型负责写入、候选打分与作答。
