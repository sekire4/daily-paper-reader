## 摘要
长程对话智能体需要有效的记忆系统，以从交互历史中回忆事实、事件和关系。在本工作中，我们提出一种混合记忆架构，包含情景记忆和结构化关系记忆，以及一种能够保持效率的巩固机制。我们在两个基准 LoCoMo 和 LongMemEval-S 上开展了实证研究。实验表明，这两类记忆始终具有互补性，将二者结合可优于最先进的记忆框架，并在 LoCoMo 上达到 90.2% 的准确率、在 LongMemEval-S 上达到 85.5%。

## Abstract
Long-horizon dialogue agents require effective memory systems to recall facts, events, and relationships from interaction histories. In this work, we propose a hybrid-memory architecture comprising episodic memories and structured relational memories and a consolidation mechanism which preserves efficiency. We conduct an empirical study across two benchmarks: LoCoMo and LongMemEval-S. Our experiments demonstrate that the two memory types are consistently complementary, combining both outperform state-of-the-art memory frameworks and achieves 90.2% accuracy on LoCoMo and 85.5% on LongMemEval-S.

## 1. 核心问题与研究背景

- **核心问题**：基于大语言模型（LLM）的长程对话智能体在需要回忆、整合并推理跨越多个会话的交互历史时，能力仍然根本受限；仅靠扩大上下文窗口既不经济也不可靠。

- **本文定位**：走非参数化路线，指出既有系统（MemGPT、MemoryOS、ReadAgent、Mem0、A-Mem、H-Mem、Zep、Nemori）多采用**单一记忆表示**（知识图谱、Zettelkasten 笔记、层级索引等），难以同时兼顾“叙事上下文与时间顺序”和“紧凑可查询的实体关系结构”。
- **整体含义**：论文主张记忆的有用性存在两种不同假设——情景记忆保留叙事与序列，结构化关系记忆优先紧凑的关系结构——二者**互补**而非替代；并进一步引入**离线巩固**机制来控制记忆库的单调膨胀。

## 2. 方法论

### 2.1 总体框架（三阶段）

1. **记忆整理（Curation）**：以会话（session）为粒度，会话结束后对整段对话记录做一次抽取。
2. **记忆巩固（Consolidation）**：离线周期性执行，对记忆库聚类后合并或删除。
3. **记忆检索与问答（Retrieval & QA）**：查询时分别从两类存储检索，拼接为上下文生成回答。

### 2.2 情景记忆（Episodic Memory）

- 由 LLM 为每个会话生成**整体性**记忆条目，字段包括：
  - `title`：3–7 词短标题；
  - `summary`：一句话要点；
  - `details`：保留叙事上下文（事件、背景、确切人名/数字/引语）；
  - `timestamp`：会话时间戳（ISO 格式，无法推断则为 null）。
- 设计意图：保留事件的时序与语境丰富度，服务于时间推理类问题。

### 2.3 结构化关系记忆（Structured Relational Memory）

- 由 LLM 从对话中抽取实体关系五元组 **(e, r, o, t, c)**：
  - `e` 实体、`r` 关系标签（snake_case 谓词）、`o` 客体；
  - `t` 时间戳：为关系事实提供时间 grounding，缓解“关系记忆只存事实、不存其何时为真”的常见失效模式；
  - `c` 源上下文：提供**溯源信息**，保留说话者意图、陈述情境等结构化抽取必然丢失的细微语义。
- 抽取规则强调：代词消解到真实姓名、相对时间显式换算为绝对日期、宁多勿漏的持久性过滤。

### 2.4 记忆巩固（Consolidation）

- **动机**：记忆库随交互单调增长，带来存储成本、检索开销与噪声。
- **流程（受 BERTopic 启发的两阶段）**：
  1. 取所有记忆的预计算嵌入（1536 维，`text-embedding-3-small`）；
  2. 用 **UMAP** 降维（cosine 距离、10 邻居、5 个目标维度、min_dist=0）；
  3. 用 **HDBSCAN** 聚类（欧氏距离、Excess of Mass 选择、`min_cluster_size`、`min_samples=1`）。
- **形式化描述**：设记忆集合 \(M=\{m_1,\dots,m_N\}\)，每个 \(m_i\) 有嵌入 \(e_i\in\mathbb{R}^d\) 与元数据；聚类得到 \(C=\{C_1,\dots,C_K\}\)，\(C_k\subseteq M\)。对每个簇施加算子 \(\Phi(C_k)\to M'_k\)，包含两种操作：
  - **MERGE**：把冗余或互补的记忆合并为一条巩固记忆 \(\tilde M_k=\text{merge}(C_k)\)；
  - **DELETE**：删除过时、冲突或被取代的记忆 \(M'_k=\tilde M_k\setminus\{m_i\}\)；
  - 最终 \(M'=\bigcup_{k=1}^{K} M'_k\)，得到紧凑、去噪的记忆集。
- 合并/删除的**具体决策由 LLM 在簇内完成**，聚类只负责缩小决策范围。

### 2.5 检索与问答

- 两库**独立**做 top-k 语义相似度检索：
  - 情景库：以 `details` 字段建一个向量/条目；
  - 关系库：以“Subject, Relation, Object”拼接的自然语言串建一个向量/元组。
- **非对称预算**：情景取 top-\(k\)，关系取 top-\(2k\)；理由是关系元组远比情景条目简短，同等 token 预算下可容纳约两倍条目。
- 取 \(k=10\)（性能在 \(k>10\) 后进入平台期）。
