# CALM: Conflict-Aware Lifecycle Memory Governance for Long-Horizon Language Agents 

Chang Li 1, Xianhao Ou 1, Xinyan Ma 1, Hao Li 1, Haoyuan Xu 1

Jiafeng Liang 1, Xiaohan Wang 2, Jiajun Chai 2, Guojun Yin 2, Ming Liu 1*1Harbin Institute of Technology 2Meituan 

Abstract 

A memory can be outdated for present-day reasoning yet indispensable for reconstructing the past. Relevance-based retrieval overlooks this tension: semantic relevance, evidence-grounded validity, and query-specific eligibility are distinct. We propose CALM, a conflict-aware lifecycle memory governance framework that decouples persistent memory preservation from query-time admission. CALM converts heterogeneous records into evidence-grounded memory cells, updates validity and lifecy-cle states using support, conflict, and depen-dency signals, and admits query-appropriate evidence through training-free or learned gat-ing informed by temporal applicability. Across LongMemEval-S and LoCoMo with Qwen and GPT backbones, CALM outperforms state-of-the-art baselines, achieving the best overall ac-curacy. Compared with simple filtering and reranking, query-conditioned admission further improves evidence selection. Conflict-block-ing and robustness analyses show CALM sup-presses erroneous retrieved memories while re-taining useful evidence. Historical-reconstruc-tion experiments demonstrate that preserving superseded records supports accurate earlier-state reasoning without compromising current-state answers. 

1 Introduction 

For long-horizon language agents, reliable memory requires deciding not only what to retain, but also what to use. As users relocate, revise preferences, or change commitments, interaction histories accu-mulate records that remain informative about the past but may no longer describe the present. Exist-ing memory-augmented systems have advanced the storage, organization, and retrieval of such histories (Packer et al., 2023; Zhong et al., 2024; Gutierrez et al., 2024; Rasmussen et al., 2025). This mismatch can turn successful retrieval into misleading reasoning. Consider a user who moves from Seattle to Boston. The earlier residence should not deter-mine the answer to a current-location query, but it remains necessary for a question about where the user previously lived. As illustrated in Figure 1, deleting the earlier record loses historical evidence, whereas admitting both records indiscriminately can obscure the current state. This example exposes three distinct properties of memory: semantic rele-vance measures relatedness to a query; query-inde-pendent validity reflects the memory’s persistent, evidence-governed status; and query-conditioned eligibility determines whether it should enter the working context given the query’s temporal target, applicability scope, and intent. Even a superseded memory may be eligible for historical reconstruc-1arXiv:2610.38573v1 [cs.AI] 28 Oct 2026 tion, while an otherwise well-supported memory may still be ineligible when its time or scope does not match the query. Graph-based and temporal memory systems can represent evolving memory relationships, while recent work further highlights the challenges posed by conflicting records (Gutierrez et al., 2024; Xu et al., 2025; Rasmussen et al., 2025; Tao et al., 2026). However, recording an update or conflict does not, by itself, resolve which retrieved records should be admitted for a particular question. A memory-use policy must account for both persis-tent evidence and the conditions imposed by the query. This calls for separating lifecycle gover-nance from query-conditioned admission, rather than relying on memory organization or relevance-based ranking alone. We introduce Conflict-Aware Lifecycle Memory Governance (CALM), a two-level framework sepa-rating persistent lifecycle governance from query-conditioned admission. Between the memory back-end and working context, CALM adapts heteroge-neous records into evidence-grounded cells while preserving provenance and temporal information. It updates stored validity and lifecycle states using deterministic support, conflict, and dependency rules, with temporal cues guiding applicability rather than automatic decay. At query time, a shared hard eligibility filter precedes either a train-ing-free policy (CALM-ZS) or a learnable gate (CALM). Both select evidence using retrieval rel-evance, stored validity, query–memory compati-bility, and query-conditioned risk. CALM thus retains superseded records for historical queries while excluding them from current-state reason-ing, without modifying the underlying retriever or answer model. We evaluate CALM on LongMemEval-S (Wu et al., 2025) and LoCoMo (Maharana et al., 2024) across Qwen and GPT backbones. CALM achieves the best or tied-best overall accuracy across evalu-ated settings, reaching 79.60% on LongMemEval-S with Qwen3-30B-A3B-Instruct-2507. Controlled comparisons with simple filtering and rerank-ing demonstrate the benefits of combining lifecy-cle governance with query-conditioned admission. Conflict-blocking and robustness analyses show that CALM suppresses misleading evidence while preserving useful memories; historical reconstruc-tion confirms that superseded information remains accessible without compromising current-state rea-soning. Component ablations and efficiency anal-yses further highlight the complementary roles of persistent governance and query-aware selection. Our contributions are as follows: • We formulate long-horizon memory use as a query-conditioned eligibility problem, distin-guishing semantic relevance, query-independent validity, and query-specific admission while pre-serving historical evidence. • We propose CALM, which couples evidence-grounded lifecycle governance with compatibil-ity and risk-aware admission, and instantiate both training-free and learned gating policies. • We validate CALM across two benchmarks and three answer-model backbones through compar-isons with existing memory systems and simple alternatives, alongside robustness, historical-re-construction, and efficiency analyses. 

2 Related Work 

2.1 Long-Term Memory for LLM Agents 

Long-term memory enables LLM agents to re-tain interaction histories, personalize responses, and support planning and reasoning across ses-sions. Early agents retain observations, feed-back, and acquired skills to support cross-ses-sion planning (Park et al., 2023; Shinn et al., 2023; Wang et al., 2024). MemoryBank (Zhong et al., 2024) maintains user information, while MemGPT (Packer et al., 2023) pages context across hierarchical memory tiers; external-memory archi-tectures further scale recall (Wang et al., 2023). However, persistent retrieval alone does not en-sure that past evidence is valid or applicable to the current query. 

2.2 Structured Memory Systems 

Recent systems organize memories through linked notes, graphs, and hierarchies (Anokhin et al., 2025; Sun et al., 2026; Nan et al., 2025). Hip-poRAG (Gutierrez et al., 2024) combines knowl-edge graphs with Personalized PageRank for as-sociative multi-hop retrieval, while A-Mem (Xu et al., 2025) dynamically links and evolves mem-ory notes. Mem0 (Chhikara et al., 2025) consol-idates conversational facts through add, update, and delete operations. MemoryOS, MemOS, and EverMemOS (Kang et al., 2025; Li et al., 2025; Hu et al., 2026) explore hierarchical management and memory lifecycles. While HippoRAG em-phasizes associative retrieval, A-Mem focuses on 2adaptive memory organization, and Mem0 handles incremental memory updates, CALM focuses on post-retrieval eligibility control. 

2.3 Temporal Consistency and Memory Governance 

Prior work studies memory staleness, conflicts, and interference (Chao et al., 2026; Tao et al., 2026; Shi et al., 2026; Lam et al., 2026; Hu et al., 2025; Lin et al., 2026; Dash et al., 2026). Zep (Ras-mussen et al., 2025) tracks superseded facts with bi-temporal graphs, while Mem0 (Chhikara et al., 2025) resolves conflicts through memory updates. A-TMA (Shi et al., 2026) coordinates memory-bank maintenance, state-aware evidence expansion, and answer-time resolution. In contrast, CALM targets post-retrieval admission : it maintains evi-dence-grounded, query-independent validity and lifecycle states, including dependency invalidation, then applies hard eligibility constraints and train-ing-free or learned gates to fixed retrieved candi-dates. Unlike A-TMA’s evidence expansion and answer-side state resolution, CALM explicitly gov-erns which existing memories enter the working context without modifying upstream retrieval or the answer model.

Framework Overview. Inspired by the adaptive lifecycle of human memory (Atkinson and Shiffrin, 1968; Nader et al., 2000; Hupbach et al., 2007), we propose CALM, a conflict-aware lifecycle mem-ory governance framework that separates persis-tent memory preservation from query-time utiliza-tion. As illustrated in Figure 2, CALM comprises three stages: Evidence-Grounded Memory Adapta-tion converts heterogeneous backend records into canonical memory cells; Lifecycle-Aware Memory Governance maintains evidence-grounded valid-ity and lifecycle states through support, conflict, dependency, and temporal signals; and Query-Con-ditioned Memory Gating selects eligible memories using either the training-free CALM-ZS rule or the learnable CALM policy. Rather than replac-ing the underlying storage or retrieval architecture, CALM separates persistent lifecycle governance from query-local admission decisions, allowing su-perseded memories to remain available for histori-cal reconstruction without automatically entering current-state reasoning.

4 Experiments 

4.1 Experimental Setup 4.1.1 Datasets and Baselines 

We evaluate CALM on LongMemEval-S (Wu et al., 2025), which contains 500 questions across six memory-reasoning categories, and LoCoMo (Ma-harana et al., 2024), which contains 1,986 ques-tions over ten long conversations. Our reported LoCoMo evaluation covers the 1,540 non-adversar-ial questions; the remaining 446 adversarial ques-tions are excluded. All methods are evaluated on the corresponding benchmark conversations and question subsets. External baselines retain their native memory-construction and retrieval pipelines. For CALM, benchmark-provided LoCoMo obser-vations and summaries are incorporated as alter-native representations of the same conversation evidence, not as answer labels or gate supervision. We compare with Mem0 (Chhikara et al., 2025), MemOS (Li et al., 2025), EverMemOS (Hu et al., 2026), and LightMem (Fang et al., 2025). Detailed protocols are given in the Appendix B.1. 

4.1.2 Metrics and implementation details

Outputs from Qwen3 are evaluated by qwen-turbo, while those from GPT-4.1-mini and GPT-4o-mini (OpenAI, 2024) are evaluated by their corresponding models. Mem-ory selection quality is assessed using erroneous-memory blocking (EMB), useful-memory reten-tion (UMR), and conflict leakage (CL), together with erroneous-memory injection and historical-reconstruction analyses. 4.2 Main Results 4.2.1 Main results on LongMemEval-S 

Table 1 shows that CALM achieves the best or tied-best overall accuracy across all three back-bones, reaching 79.60%, 83.00%, and 78.20% with Qwen3-30B, GPT-4.1-mini, and GPT-4o-mini, re-spectively. Moreover, its consistent gains over CALM-ZS demonstrate that learnable query-conditioned gating improves memory selection by preventing irrelevant or conflicting records from entering the reasoning context. 

4.2.2 Main Results on LoCoMo. 

As shown in Table 2, CALM achieves the best overall accuracy across all three answer models, reaching 88.70%, 93.51%, and 88.70%, respec-tively. CALM remains competitive across single-hop, multi-hop, open-domain, and temporal questions. Together with ablations and simple-alternative comparisons, these results indi-cate that the gains arise from combining lifecycle-aware governance with learned admission rather than simple post-retrieval heuristics. The lower Qwen3-30B multi-hop score suggests a trade-off between stronger conflict suppression and preserv-ing evidence for complex reasoning.

Comparison with Simple Alternatives. To ex-amine whether CALM’s gains stem from simple post-retrieval heuristics, we compare temporal fil-tering, recency reranking, and validity reranking under identical memory representations, retrieved candidates, answer model, evaluation protocol, and memory-token budget (Appendix B.6). Tempo-ral filtering excludes time-incompatible records, while reranking adjusts candidate ordering without explicit admission. 5 Conclusion 

Reliable long-horizon memory requires more than retaining information: it requires deciding when preserved evidence should inform an answer. We presented CALM, a framework that separates evi-dence-grounded, query-independent lifecycle gov-ernance from query-conditioned admission of re-trieved memories. By preserving provenance and superseded states while controlling admission through query compatibility and risk, CALM sup-ports historical reconstruction without compromis-ing current-state reasoning. Experiments on Long-MemEval-S and LoCoMo across Qwen and GPT backbones show the best overall accuracy. Conflict-blocking, historical-reconstruction, and compar-isons with simple filtering and reranking strategies further demonstrate the value of governing mem-ory use beyond semantic relevance alone. Future work will explore scalable lifecycle maintenance in dynamic, multimodal environments. 8Limitations 

CALM has several limitations. First, its lifecycle governance relies on deterministic rules and avail-able evidence metadata, which may miss implicit or complex conflicts. Second, query-conditioned gat-ing depends on upstream retrieval quality and may occasionally exclude useful evidence, particularly for multi-hop reasoning. Third, the learned gate requires development-set supervision, and its gener-alization to unseen domains remains to be explored. Finally, our evaluation is limited to LongMemEval-S and the non-adversarial subset of LoCoMo. The scalability of lifecycle-graph maintenance in larger, continuously evolving memory environments also warrants further investigation.

The im-plemented lifecycle manager stores a validity at-tribute Vi ∈ [0 , 1] separately from evidence confi-dence, support count, conflict links, and cascade risk. A stale or superseded memory can be archived only when the optional retention policy is enabled, under the archival conditions described above. In historical recollection, a compatible historical record may be reactivated in a query-local copy without changing the persistent state. A.5 Online Updating and Context Construction 

At each interaction step, CALM adapts newly ex-posed backend records, merges exact duplicates, updates local conflict and dependency links, recom-putes validity and lifecycle states, and persists both active and inactive memories with their evidence and validity intervals. At query time, the backend returns Rq. CALM computes the four features in (17), applies the common hard filter, and then uses either (19) or (21). Strongly conflicting survivors are resolved before serialization. Admitted memories are greed-ily packed until the next memory would exceed the memory-token budget. Rejected and budget-dropped memories remain in persistent storage. Relation updating is local to a bounded set of candidate neighbors. Query-time gating therefore requires O(|R q|) feature computations and gate evaluations, independent of the total number of stored memories.

Baselines. We compare CALM with four rep-resentative long-term memory systems that cover different memory-construction, organization, and retrieval paradigms. EverMemOS (Hu et al., 2026) proposes a self-organizing memory operating system inspired by biological engrams. Its memory lifecycle includes episodic trace formation, semantic consolidation, and reconstructive recollection, enabling informa-tion to be progressively organized and recalled over long interaction histories. LightMem (Fang et al., 2025) is a lightweight memory-augmented generation framework that or-ganizes information into sensory, short-term, and long-term memory stages. It emphasizes efficient memory consolidation and retrieval while reducing storage and inference overhead. For each external baseline, we use its official implementation and retain its native memory-con-struction, storage, consolidation, and retrieval pipeline. We do not replace baseline retrievers with the CALM retriever, since retrieval and mem-ory organization are integral components of the evaluated end-to-end systems. Adaptations are lim-ited to dataset conversion, answer-model interfaces, and output formatting. The answer model, genera-tion prompt, decoding configuration, and evaluator are held consistent across methods whenever sup-ported by the corresponding implementation.

B.5 Implementation and Training Details Memory processing pipeline. Each conversa-tion is processed through memory adaptation, life-cycle governance, retrieval, query-conditioned gat-ing, context packing, answer generation, and auto-matic evaluation. CALM-ZS and CALM receive the same retrieved candidates and the same four-di-mensional input [ζtq,i , V ti , ψ tq,i , 1 − Rtq,i ]. CALM-ZS uses the fixed score and admission rule in (18) and (19), whereas CALM uses the learned score and admission rule in (20) and (21). Both poli-cies use the same hard eligibility filter and query– memory features. 

Learnable gate. The gate is a one-hidden-layer MLP with GELU hidden activation and sigmoid output, trained with weighted binary cross-entropy over the query–memory pairs defined in the Eli-gibility supervision paragraph. The learned-gate threshold is fixed at 0.50 ; the training-free thresh-old is specified in Appendix A.4. The gate is trained separately from the answer model, and no parameters of the answer model, retriever, or mem-ory backend are updated. Gate-training pairs are constructed from a sep-arate development set that is disjoint from the re-ported evaluation instances. None of the Long-MemEval-S or LoCoMo evaluation questions, ref-erence answers, or associated memory graphs is used for gate optimization. Hard negatives in-clude semantically relevant but outdated, conflict-ing, wrong-time, scope-incompatible, and invalid-dependency memories. CALM-ZS requires no training.

B.8 Historical Reconstruction 

The historical-reconstruction experiment evalu-ates whether a memory system can preserve ear-lier states without allowing them to interfere with present-state reasoning. We evaluate all identified update chains that contain at least one earlier state and one later replacement, including changes in res-idence, preference, profile attributes, commitments, and factual status. Each retained chain is associated with two paired query types. A current-state query asks for the state valid after the latest update. A historical-state query asks for the state valid before a specified update or during an earlier interval. The paired queries use the same underlying repository and retrieval pipeline, so success requires query-con-ditioned memory use rather than different stored content. We compare four memory-management strate-gies. Keep-All preserves and admits all records. 

Latest-Only retains only the most recent record in an update chain. Relevance-Only preserves all records but selects them using semantic relevance without lifecycle or compatibility control. CALM 

preserves both earlier and later records while using query-conditioned gating to determine which state enters the working context. Accuracy is computed separately for current-state and historical-state questions. CALM outper-forms the strongest alternative by 3.71 percentage points on current-state questions and by 9.26 per-centage points on historical-state questions. The larger improvement on historical queries shows that suppressing a superseded memory during cur-rent-state reasoning does not require deleting it from persistent storage.

Question-Type-Specific Instructions Different LongMemEval question categories require differ-ent forms of memory interpretation and evidence 22 aggregation. We therefore instantiate {type_-rules} based on the question type in the unified answer-generation prompt. This choice is indepen-dent of answerability and evaluation annotations. 

Single-Session User Tasks 

The answer should come from a user message in one relevant session. 

Single-Session Assistant Tasks 

The answer should come from the assistant’s previous response, not from the user’s request alone. 

Multi-Session Tasks 

Use MULTI-SESSION COVERAGE first. Combine all relevant sessions. If the question asks for a count, list, comparison, order, or multiple facts, check each dated user-mentioned item separately before answering; count distinct user-mentioned items only and do not merge separate actions into one. 

Temporal Reasoning Tasks 

Use the TEMPORAL EVIDENCE TABLE first. Normalize relative phrases using any supplied relative-date notes, identify the relevant dated events, then answer with the final date, order, duration, or named event. If the question asks how long event A was before or after event B, compute A-to-B; use distance from the question date only when the question asks relative to today or the question date. 

Knowledge Update Tasks 

Use KNOWLEDGE UPDATE TABLE first. If older and newer memories conflict, use the newest supported update as the final answer. 

Single-Session Preference Tasks 

Use USER PREFERENCE CLUES first. Answer from the user’s stable or most recent preference, constraint, or profile instead of generic advice; mention the specific remembered preference or context in the final answer. 

Default Tasks 

Answer directly from the most relevant supported memories.

Answer Generation Prompt The model is in-structed to identify the target speaker, integrate evidence across memory representations when nec-essary, resolve temporal expressions using the as-sociated session timestamps, and return only a con-cise final answer. 

Question-Type-Specific Instructions Different LoCoMo question categories require different forms of evidence selection, cross-session aggre-gation, temporal normalization, and commonsense inference. We therefore insert one category-spe-cific instruction into the general answer-generation prompt. 

Single-Hop Questions 

Find the one memory that directly states the requested fact. Preserve exact names, places, objects, quantities, and dates. 

Multi-Hop Questions 

Combine all relevant memories, possibly from different sessions or speakers. The answer must satisfy every part of the question rather than copying only one supporting fact. 

Temporal Questions 

Distinguish the session timestamp, which indicates when something was said, from the event time, which indicates when it happened. Resolve relative expressions such as 

yesterday , last Sunday , last year , or next month against the timestamp of the corresponding memory, and return the requested date, period, duration, or order.
