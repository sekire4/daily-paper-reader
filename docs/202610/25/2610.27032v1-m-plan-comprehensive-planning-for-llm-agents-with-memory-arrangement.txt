## ABSTRACT 

Large language model (LLM)-based agents have recently demonstrated outstanding performance in single-turn tasks, yet they continue to struggle with long-horizon tasks, particularly in environments without prior training. A key limitation of single LLMs is their difficulty in processing long contexts, which stems from weaknesses in continuous decision-making and reasoning capabilities. Although existing multi-agent systems (MAS) equipped with long-term memory bases can partially address this gap, they mostly rely on knowledge reuse or summarization—an approach that is often constrained by directly retrieval without any adaptation for the current task, while the retrieved memory may contain much history noises waiting to be preprocessed. In contrast, MAS characterized by task-specific guidance often lack long-term memory specifically designed for the guidance. To address these challenges, we propose M-Plan, a closed-loop MAS framework that integrates long-term and short-term memory. By combining global-local and past-current guidance, M-Plan enhances agents’ performance on multi-turn tasks while maintaining a plug-and-play design. During task execution, agents receive task-specific milestones and insights, and are provided with local hints only when confusion arises, which form global-local guidance together. These guidance generation and utilization construct the short-term memory as well. After task completion, relevant information about the current task is optimized or reorganized before being sent to the long-term memory storage for future retrieval. The designments mentioned above build a comprehensive framework different from other individual long-term or short-term memory works. Extensive experiments on multi-turn tasks including ALFWorld, Webshop, and PDDL across diverse models demonstrate that M-Plan outperforms multiple baseline methods in both accuracy and efficiency. 

## 1 INTRODUCTION 

Large language models (LLMs) have been widely applied across numerous domains, and extensive research has demonstrated their strong capability to solve a diverse range of tasks [1]. With the increasing continuity and complexity of real-world tasks in daily human activities, LLMs are required to tackle multi-turn, long-horizon tasks more frequently. Such tasks demand sustained decision-making and reasoning across multiple turns, while also requiring models to maintain and process long contexts. However, these demands remain challenging for existing LLMs, which, despite their remarkable performance on single-turn instructions, often struggle in multi-turn scenarios [2; 3]. Common issues observed in LLM-based agents include forgetting information from intermediate turns, overemphasizing initial and final turns, which indicate that a single LLM is insufficient to handle increasingly complex contexts. To address these challenges, researchers have proposed two major approaches for adapting LLM-based agents. The first exploits training to optimize agents on downstream tasks [4; 5; 6; 7; 8; 9; 10], primarily including Supervised Fine-Tuning (SFT) and Reinforcement Learning (RL), typically with human-annotated training sets, which are sometimes hard to get. ## 2 RELATED WORK 

2.1 LONG TERM MEMORY 

Existing long-term memory works can be broadly categorized into parametric or non-parametric approaches. Parametric methods typically rely on large-scale trajectories or other pre-collected information to train models through reinforcement learning (RL) or supervised fine-tuning (SFT), thereby encoding long-term memory into model parameters [21; 22; 23]. For example, MEMOS [21] proposes a large and complex memory operating system with parametric memory storage. Me-mento [9] further uses RL to improve retrieval quality. However, parametric memory is still ultimately 3M-Plan: Comprehensive Planning For LLM Agents with Memory Arrangement derived from non-parametric data, such as textual knowledge or trajectories. Although training can improve agents’ performance on downstream tasks, it introduces substantial computational costs and usually requires complex data preparation in advance. To support plug-and-play and convenient deployment, lots of works design non-parametric mem-ory [11; 14; 13; 24; 25; 26]. A typical method [27; 28; 29; 30] is to construct memory bases using vectors or textual representations for semantic retrieval. A representative paradigm is to store ex-tracted, summarized, or general knowledge and reuse it to guide agents in action execution. For example, work [11] sets a series of agents refining, editing, and integrating general insights to be reused in future tasks, and also extracts the key steps similar to the plan of the history trajectories as in-context content. However, these methods often struggle to extract truly transferable knowledge and usually lack task-specific adaptation. Directly using retrieved memories may also introduce semantic noise from other tasks. Although historical trajectories can serve as useful examples, they are not always reliable in multi-step decision-making scenarios. To improve robustness and task-specific adaptation, M-Plan introduces a short-term memory mechanism on top of long-term memory. We further design an Optimizer module to compress and refine completed task experiences, forming a closed-loop process that feeds successful experiences and failure lessons back into long-term memory. In this way, retrieval and feedback integrate long-term and short-term memory into a unified system. 2.2 SHORT TERM MEMORY 

Agent-based short-term memory mechanisms for planning and acting have shown significant potential in multi-turn interactive tasks. Existing methods can be roughly divided into two categories. The first category relies on global guidance [31], step-wise guidance [32; 33], or their combination. For example, HiAgent [16] segments the working trajectory into subgoals to organize the context, enabling partial local compression and guidance. HiPlan [17] introduces a planning system equipped with global milestones and step-wise hints. Another common approach is to insert reasoning traces into the action trajectory, with ReAct [34] as a typical example, followed by related studies [15; 35]. However, these methods overlook the fact that plans alone cannot always provide sufficient guidance for task completion. Moreover, step-wise generation or judgment can introduce substantial time and token costs. The second category adopts retrieval-augmented planning, such as [15; 17]. Although these methods are convenient and effective, they often rely on few-shot examples like full trajectories or other static memory. To provide deeper and more comprehensive guidance during task execution, M-Plan introduces an Insighter into the short-term memory module. We further design a dynamic external memory base for task-level retrieval, enabling short-term memory to evolve across different agents. 2.3 LONG SHORT -T ERM MEMORY 

Several existing works have introduced systems that combine long-term and short-term memory [23; 36; 37]. For example, MemVerse [23] adopts a sliding window to process short-range dialogue information and uses a relational graph to store task information, including episodic, core, and semantic memories in textual form. It further employs a supervised fine-tuned model to transform graph-based memories into model weights. Another work [36] constructs process and feasibility memories to organize knowledge from successful and failed trajectories, while also monitoring task progress locally. However, these methods typically require retrieval or complex memory modification at each step, which may slow down execution and substantially increase computational cost. In contrast, our system avoids frequent step-wise retrieval or examination while maintaining strong performance and further establishes a closed-loop optimization mechanism through the interaction between long-term and short-term memory. 

## 3 METHODOLOGY 

3.1 OVERVIEW 

As shown in Figure 2, from the function view, M-Plan can be separated into three modules: long-term memory storage, short-term memory generation, and optimizer. Following M-Plan’s workflow, there will be a closed-loop in the whole, meaning that results made by short-term memory can influence it 4M-Plan: Comprehensive Planning For LLM Agents with Memory Arrangement in a future turn, and information derived from long-term memory can enlarge the base after finishing the current task. Overall, with MAS design, whose prompts are presented in Appendix. A, M-Plan can utilize the following two kinds of information as guidance to help action agents execute the task: 1. Global guidance: A generated milestones list Mg = [ m1, m 2, m 3, ..., m x], playing the role of planning route, where each mx represents one key subgoal need to achieve. A generated insights list Ig = [ i1, i 2, i 3, ..., i y ], where each iy represents one key insight as noticeable reference. Historically successful trajectories Tg from memory base provide demonstrations and experiences like the human recalling when meeting similar tasks. 2. Local guidance: A structural hint hl can be included to the context to remind the action agent to get rid of the current problems, performing as a local guide. However, only under the conditions where the action agent is confused, the hint will be generated and exploited. This strategy can be likened to a wise, deep-thinking pattern with an external brain assistant, and also conforms to human thinking patterns, in which people will think more deeply to tackle traps or trouble. 3.2 LONG -TERM MEMORY STORAGE 

We first introduce the long-term memory storage module, able to break the limitation of single short-term memory in most work. This module equips agents with historical task information as references, thereby enabling more effective task-specific generation. Notably, the memory base does not rely on any pre-collected data or demonstrations. Instead, it starts from scratch and continuously absorbs external information from short-term memory during task execution. Specifically, Each memory item El is defined as follows: 

El = {Ml, I l, T l, F l, D l}, (1) where Ml denotes task milestones, Il represents task insights, Tl records the execution trajectory, Fl

is a Boolean flag indicating whether the trajectory succeeds or fails, and Dl is the task description, which serves as the key for semantic search. These memory items are stored in a vector database. In addition, following the graph-based memory organization strategy in [11], we model the relationships among memory items in graph form, where edges are added between similar tasks to facilitate faster retrieval and better structural organization. To better utilize long-term memory, the retrieval process can be formulated as follows: 

{E1, E 2, ...E j } = Ret (Q), ES = {E1, E 2, ...E k}{E1, E 2, ..., E j , ..., E k} = Extend (ES ), (2) where Ret (Q) denotes the retrieval function triggered by the task query Q, which retrieves j relevant memory items from the memory base according to semantic cosine similarity. The retrieved set is denoted as ES . To further improve diversity and robustness, we apply a one-hop graph expansion strategy to enlarge the retrieval scope and obtain the final top-k memory items. Specifically, for each item in ES , we search its directly connected one-hop neighbors in the memory graph and append them to the original retrieved set, beyond those retrieved by semantic similarity. 3.3 SHORT -TERM MEMORY GENERATION 

However, current work relying solely on long-term memory may be insufficient for task-specific enhancement because historical experiences mainly provide coarse references from past tasks and cannot fully capture the dynamic states, and task-specific constraints of the current execution process. Moreover, most existing short-term planning works generate only coarse-grained plans, lacking sufficient details. And step-wise guidance at every step can also introduce substantial computational cost. To address these limitations, we introduced a multi-agent based short-term memory, including a 

P lanner , an Insighter , a Hinter , and an Actioner . Specifically, we first retrieve two successful cases and one failed case from long-term memory. The two success trajectories serve as fundamental in-context demonstrations. The P lanner receives the description Dl and milestones Ml of past successful trajectories for positive reference, together with the current task description Ds, and generates a new milestone list for the current task: 

{ms1, m s2, m s3, ..., m sx } = P lanner (Dl, M l, D s). (3) 5M-Plan: Comprehensive Planning For LLM Agents with Memory Arrangement The Insighter receives the milestone list Ms = {ms1, m s2, m s3, ..., m sx }, adding more related details to enrich the content of the blueprint, and takes the task description Dl from both successful and failed cases, along with the current task description Ds, the current task milestones and their corresponding insight list Il, to identify the information that may be valuable for the current task. It then generates a new insight list: 

{is1, i s2, i s3, ..., i sy } = Insighter (Dl, I l, D s, M s). (4) Then, the Hinter receives Ds, the ongoing trajectory Tc, the global milestone list Ms and insight list Is = {is1, i s2, i s3, ..., i sy } as input. The hint-generation process is formulated as follows: 

{state, position, gap, correction } = Hinter (Tc, M s, I s, D s). (5) To reduce computational cost, we adopt a conditional step-wise hinting strategy. Instead of guiding every step, the Hinter is activated only when the Actioner falls into an action trap or performs an invalid action according to the environment feedback. More detailed rules of the Hinter are expanded on Appendix. D. The generated hint consists of four components: state , which describes the agent’s current state, such as objects it has already collected; position , which indicates the current milestone to be achieved; gap , which provides advice on how to complete the current milestone; and 

correction , which suggests an action correction for the next step. The Actioner is responsible for selecting and executing actions based on the retrieved successful trajectories, current observation, task description, generated milestones, insights, and conditional hints. 3.4 OPTIMIZER 

Apart from long and short-term memory, there remains a problem of how to process and exploit the information from finished tasks, which is also rarely explored in current work. When P lanner or 

Insighter directly receives unrefined information, their performance may be hindered, especially when the long-term memory is still in a raw stage. To address this issue, we design an Optimizer 

module to reflect on finished task trajectories, including both successful and failed ones, and to form a closed-loop optimization process. Specifically, the Optimizer works by refining the current task-specific generation, rather than entirely restarting summarization or extraction. The Optimizer 

can be divided into three small parts: milestone list polishing for Ms, insight list complement for Is,and trajectory sparsification for the entire task trajectory T raj .In our former exploration phase, we found that a successfully executed multi-turn task may still have an imperfect Ms, which can be polished by analyzing the whole trajectory. When the task successfully finished, the optimizer is more likely to discover redundant milestones during execution. However, it is harder for optimizer to polish Ms when the task fails, because the failure is mostly caused by not following Ms well. In other words, Ms is usually correct, though it may not be perfect, which is why we only polish it when the task succeeds. In contrast, for Is, it is harder to extract more valuable information from successful tasks, but notable points can often be obtained from failed ones. Moreover, given that refining Is solely from the current failed trajectory remains challenging, we also input the most similar retrieved successful trajectory to facilitate this refinement by contrasting failed and successful rollouts. The sparsification of T raj is much simpler, since it only removes repeated or invalid action-observation pairs in the trajectory. Note that sparsification is only applied to successful trajectories, since failed ones need to keep failure-related details. Overall, the outputs of the three parts are derived from the short-term memory mechanism above and will be sent to long-term memory storage as references for short-term memory generation in the next task, and then form a complete closed loop between long-term and short-term memory.

4.1 METRICS 

Effectiveness : For ALFWorld [18], we report the success rate ( SR. ) to indicate the proportion of tasks completed successfully. For Webshop [19] and PDDL [20], in addition to SR. , we report the average reward to reflect the degree of attribution alignment ( i.e. , how well the purchased objects satisfy the target requirements). 

Efficiency : We report the average number of steps over all tasks ( AS. ) for ALFWorld [18] and PDDL [20] to directly compare the action efficiency of different agents. In addition, we separately report the average number of steps for successful tasks ( ASS. ), which reflects efficiency under a fixed success rate. However, a common phenomenon in these benchmarks is that a lower SR. may lead to a lower ASS. , because the agent may only succeed on easier tasks that require fewer steps. Therefore, for a fairer comparison, we define Meta-Step , computed as ASS./SR. , as a more comprehensive efficiency metric. For Webshop [19], unlike ALFWorld, there is no fixed number of steps for failed tasks, and most failures result from incorrect purchases made in early steps. Thus, a smaller AS. does not necessarily indicate better efficiency. Therefore, for Webshop, we mainly focus on Meta-Step .Another important dimension of efficiency is token usage. Given that a certain number of tokens are consumed to complete a task, both gains and losses should ideally be considered. However, the loss caused by task failure is difficult to quantify in these benchmarks. Therefore, we adopt F t as a more robust and interpretable measure of pure profit, defined as:

## 5 CONCLUSION 

In this paper, we have proposed a comprehensive planning framework for LLM agents with memory arrangement. M-Plan combines long short-term memory and global-local guidance together, which can boost LLM agents to tackle multi-turn or other similar complex tasks. The framework can address the limitations of reusing, high cost, not fully guided by abundant global and conditional 9M-Plan: Comprehensive Planning For LLM Agents with Memory Arrangement local guidance, and lacking evolution mechanisms by long short-term memory coordination with closed-loop optimization. The experiments on simulated environment benchmarks, ALFWorld, Webshop and PDDL fully show more admirable effectiveness and efficiency than baselines. 

Limitation: While M-Plan is mature in long-horizon text processing, there is great potential for M-Plan to be extended to deal with real-world environments, and it can be applied with some compression and storage techniques to enhance engineering value.

## C EXPERIMENT SETUP 

Datasets We evaluate M-Plan on three widely test multi-turn benchmarks for long-horizon planning and decision-making: 1. ALFWorld [18] is a simulated household environment base on text interaction. This benchmark comprises six kinds of subsets: put, put two, examine under the light, clean & put, heat & put, and cool & put, checking the capacity of an agent for understanding its own state and changes of environment via interactions. The maximum interaction step this benchmark can proceed is 50, also taken in our experiments. And we conduct tests on the officially established split of 134 out-of-distribution tasks. 2. Webshop [19] is a benchmark simulating an online shopping website, filled with over 1.18 million products. It will require the agent to search for target commodities and click some buttons to buy the ideal product, while reading different web pages. We conduct experiments on a set of 200 instructions. We set the max steps as 40. 3. PDDL [20] is a benchmark simulating four kinds of robot tasks, including making cocktails, placing blocks, moving balls and dealing with tyres. The agent is required to complete the specified goal, which typically comprises multiple subgoals within a 30-step budget. 

Baselines : we compare M-Plan with the following LLM-based agent baselines, ranging from classic short-term memory reasoning to long-term memory retrieval paradigms, including: 1. G-Memory [11] is a representative retrieval-augmented memory approach to reuse detailed trajectories, plan-like key steps, and history summarized insights, and places many agents to refine or integrate insights for both successful and failed task trajectories. 2. ReasoningBank [14] is a typical extraction and reusing long-term memory method. The retrieved memory item is a series of collections of insights, comprising titles, descriptions, and content of each title, summarized by an agent, used to guide similar tasks. 3. Hiplan [17] is a short-term memory method equipped with a prepared memory library, contain-ing a few trajectories to be retrieved. It also uses milestones as global guidance and step-wise hints. During the execution, similar milestones and trajectory segments will be searched to generate a hint in each step. 

Reproduction Details . Since no official trajectory data are provided for Hiplan [17], we carefully construct six expert trajectories for ALFWorld, each corresponding to one of its six task types, as well as 25 task trajectories for Webshop. Following the paper, all trajectories are annotated with milestones and segments. Rather than providing an excessive number of cases, we aim to use a compact set of high-quality trajectories to improve performance. All preparation activities are completed using Qwen3-32B. For long-term memory methods and M-Plan, to ensure a fair alignment between our method and the compared approaches, we do not provide any prepared trajectory shots. The models used in the experiments are all deployed on two Nvidia A100 GPUs. 

## D HINTER DETAIL 

Precisely, we establish two distinct principles tailored for different scenarios: 1. Loose Triggering: In ALFWorld and Webshop, agents often perform redundant revisiting and rechecking actions, which may trap them in persistent loops. Accordingly, for such occasions, once repeated actions appear in the action history, hints will be generated to provide guidance, as such repetitive behaviors tend to induce further troubles in these environments. Hints are also triggered if the most recent action is invalid. 15 M-Plan: Comprehensive Planning For LLM Agents with Memory Arrangement 2. Strict Triggering: In PDDL environments, hint activation follows a stricter rule: hints are triggered only when the current action duplicates the immediately preceding action or is invalid. This design permits permissible repeated actions, preserves task-solving effectiveness, and improves efficiency. Additionally, since the environment observation can directly indicate whether the current action is valid or invalid, we use this feedback for action validation without introducing an additional agent, thereby further reducing system complexity and computational overhead. However, another issue arises with the Hinter module. Although it is designed to help the Actioner escape potential traps, the Hinter itself may produce repetitive unhelpful or misleading guidance. For this reason, we introduce a mechanism to suspend the Hinter when the next action would trigger the same hint repeatedly. After getting paused, the Hinter awaits further information from the Actioner to think again.
