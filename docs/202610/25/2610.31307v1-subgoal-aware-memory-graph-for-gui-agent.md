## 摘要
GUI智能体旨在通过移动界面交互来自动化复杂的用户任务，但在长时程场景下进行有效决策需要复用先前的经验，而不是仅依赖环境观察。现有的基于记忆的方法通常将经验存储为单一动作级别或完整轨迹。单步动作往往过于细粒度，难以承载有意义的语义，因为单个动作的成功并不一定意味着朝着总体目标取得进展。相比之下，完整轨迹往往过于粗粒度，且难以在不同任务之间复用。我们提出一种子目标感知记忆图，将过去轨迹提炼为子目标级别的结构化、可复用证据。我们将子目标定义为共享单一意图的连续动作，这一粒度使任务进展变得有意义。为减少冗余并支持跨任务复用，我们将子目标经验组织为图中的节点，其中相关记忆可基于环境观察进行合并、扩展和检索。在SPA-Bench上，我们的方法相比基线将成功率提高了11.11%。

## Abstract
GUI agents aim to automate complex user tasks by interacting with mobile interfaces, but ef- fective decision-making in long-horizon set- tings requires reusing prior experience rather than relying solely on the environment ob- servations. Existing memory-based methods typically store experience either at the single- action level or as entire trajectories. Single- step actions are often too fine-grained to carry meaningful semantics, since the success of an individual action does not necessarily imply progress towards the overall goal. In contrast, whole trajectories are often too coarse-grained and difficult to reuse across different tasks. We propose a subgoal-aware memory graph that distils past trajectories into structured, reusable evidence at the level of subgoals. We define a subgoal as consecutive actions shar- ing a single intent, the granularity at which progress toward the task becomes meaning- ful. To reduce redundancy and support cross- task reuse, we organise subgoal experiences as nodes in a graph, where related memories can be merged, extended, and retrieved based on the environment observation. On SPA-Bench, our method improves success rate by 11.11% over the baseline.

# 《Subgoal-aware Memory Graph for GUI Agent》论文中文总结

## 1. 核心问题与研究背景

- **应用场景**：GUI 智能体通过点击、滑动、文本输入等操作移动端界面，自动化完成下单、设闹钟、改设置等复杂用户任务。
- **长时程挑战**：在 SPA-Bench 等基准中，单个任务可能需要跨多个屏幕执行 30 步以上 GUI 动作。仅依赖当前环境观察不够，因为许多"子目标"在不同任务、不同 App 中反复出现，若不复用历史经验，智能体必须从头重新探索相同工作流。
- **现有记忆粒度的两难**：
  - **单动作级**（如 GUI-Explorer 挖掘的 per-step `(observation, action, outcome)` 三元组）：过细，局部"成功"不代表朝总体目标推进，且很快积累大量冗余条目。
  - **整轨迹级**（如 HyMEM 的轨迹嵌入图、EchoTrail-GUI 检索完整成功回合）：过粗，绑定单一任务路径，难以在"共享中间步骤但具体路径分叉"的任务间复用。
- **核心主张**：应在两者之间引入**子目标（subgoal）**这一中间抽象——即共享单一意图的连续动作段。子目标既能体现任务进展（同一子目标可因底层行为不同而成功或失败，见图 1），又天然可跨相关任务迁移。

## 2. 方法论

### 2.1 核心思想

将历史轨迹蒸馏为**子目标级**的结构化、可复用证据，并组织为**有向图**：节点是视觉相似 GUI 状态的聚类，边是子目标转移（连接子目标起始状态与结束状态）。推理时按当前截图检索相关子目标，作为提示注入智能体上下文。

### 2.2 三阶段流程

**阶段一：子目标抽取与标注（Segmentation & Annotation）**

- 由 LLM 接收完整动作序列，输出分段边界；每个子目标为一段连续动作，共同实现一个连贯子意图（如"打开搜索栏并提交查询"）。
- 仅保留每段的首、尾截图作为视觉锚点，丢弃中间帧。
- 每个子目标表示为带类型元组：`g = ⟨s_from, s_to; text, effect, behaviour, success⟩`
  - `s_from, s_to`：边界截图（视觉锚点）
  - `text`：子目标意图的自然语言摘要
  - `effect`：由边界状态对比得到的一句话视觉变化描述
  - `behaviour`：底层动作序列的简洁摘要，突出主要交互模式
  - `success ∈ {yes, no, uncertain}`：由 LLM 裁判给出的子目标级成功标签

**阶段二：记忆图构建（Graph Construction）**

1. **环境状态合并**：对每个边界截图计算图像嵌入，与已有记忆节点比较；若最近节点满足 `cos(s, m_j) ≥ τ`（τ=0.9），则并入该节点，否则新建节点。每个节点维护成员截图及用于后续匹配的运行均值嵌入。
2. **有向子目标边**：每个子目标成为从源节点到目标节点的有向边，存储意图、视觉效果、成功标签与行为模式；**成功与失败尝试均保留**，以便检索时同时提供正反例。
3. **构建时去重**：仅当两条出边指向同一目标节点、成功标签相同、且意图文本嵌入余弦相似度 `> θ`（θ=0.9）时判为重复，丢弃后出现者；目标、结果或意图不同者作为独立证据保留。

**阶段三：记忆检索（Retrieval）**

- 每个决策步以当前截图 `s_q` 触发检索：嵌入后与各节点嵌入比较余弦相似度，取 **top-k（k=1）** 最近节点。
- 收集这些节点的全部出边子目标（成功与失败均返回，并标注结果），格式化为简短 memory block 追加到智能体提示中，使智能体既能模仿已知成功、也能规避已知失败模式。

## 3. 实验设计

- **环境**：云端 Android 手机实例，经 ADB 控制。
- **Benchmark**：SPA-Bench 英文单应用 **level-3** 划分（较难层级）；剔除少数无法在云手机运行的 App 后，**仅保留 13 个任务**。
- **基座模型**：Qwen3-VL-8B-Instruct（冻结 LLM，不做权重更新）；图像与文本嵌入均由 Qwen3-VL-Embedding-8B 计算。
- **超参数**：τ = 0.9、θ = 0.9、k = 1。
- **对比方法**（同一 backbone 与设置）：
  - `None`：无记忆基线
  - `Subgoal Flat`：扁平子目标存储（不建共享视觉状态节点）
  - `Action Graph`：动作级记忆图
  - `Task Graph`：任务级（整轨迹）记忆图
  - `Subgoal Graph`：本文方法

## 6. 主要结论与发现

- **主结果**：子目标图记忆将成功率从基线 34.19% 提升至 45.30%，**绝对提升 11.11 个百分点**。
- **粒度对比**：动作级图（38.46%）与任务级图（36.75%）相对基线收益有限，说明单动作与整轨迹都不是理想记忆粒度。
- **图结构必要性**：将子目标改为扁平存储后成功率降至 30.77%，甚至低于无记忆基线，表明图结构（跨轨迹合并冗余记忆、保持检索上下文精确）是关键。
- **总体判断**：在长时程移动任务中，复用历史经验有效，而"子目标粒度 + 图式组织"是兼顾语义有效性与跨任务可复用性的可行折中。

## 7. 优点

- **粒度选择有洞察力**：明确论证了单动作"无语义"与整轨迹"不可迁移"的双重缺陷，子目标作为中间抽象层的动机清晰且有图示佐证。
- **图结构设计务实**：以视觉状态聚类为共享节点，使不同轨迹的经验自然汇聚；边同时保留成功与失败，支持"模仿成功 + 规避失败"的双向利用。
- **支持增量扩展与去重**：新轨迹可不断并入，构建时去重控制图规模，具备长期使用的工程可行性。
- **无需训练**：在冻结 LLM 设定下通过上下文注入提升性能，部署成本低、通用性强。
- **消融针对性强**：同时做了粒度消融（动作/任务/子目标）与结构消融（Flat vs. Graph），较直接地验证了两个核心设计决策。

## 8. 不足与局限

- **实验覆盖不足**：仅 13 个任务、单一 benchmark 与单一 level-3 划分，缺少跨 benchmark（如 AndroidWorld、Android in the Wild）与跨 backbone 的验证，结论泛化性存疑。
- **统计严谨性欠缺**：未报告方差、置信区间或显著性检验，小样本下的 11.11% 提升可靠性有待加强。
- **超参数未调优分析**：τ、θ、k 均取固定值，缺乏敏感性实验；k=1 的检索可能过于保守。
- **对 LLM 的强依赖与误差传播**：子目标分割、意图摘要、effect 描述、success 判定全部由 LLM 完成，任一环节出错都会污染记忆库，而文中未评估这些环节的可靠性。
- **视觉相似度假设的局限**（作者自述）：方法假设 GUI 可近似为离散状态空间，在视频播放器等高度动态界面上，连续帧视觉变化大，视觉相似度作为语义等价代理噪声较大。
- **部署开销**：4 GPU-hours 构建 + 每步约 0.5 秒检索延迟，对实时交互场景构成额外负担。
- **篇幅限制**：全文仅 6 页，分割提示词、裁判提示词、Flat 变体构造等关键实现细节缺失，影响可复现性。
