## 摘要
基于大语言模型（LLM）的智能体近来在单轮任务中表现出色，但在长时程任务中仍面临困难，尤其是在没有先验训练的环境中。单个LLM的一个关键局限在于难以处理长上下文，这源于其在连续决策与推理能力上的不足。尽管配备长期记忆库的现有多智能体系统（MAS）能够部分弥补这一差距，但它们大多依赖知识复用或摘要，这种方法往往受限于直接检索而缺乏对当前任务的适应，同时检索到的记忆可能包含大量有待预处理的历史噪声。相比之下，以任务特定指导为特征的MAS通常缺乏专门为该指导设计的长期记忆。为应对这些挑战，我们提出M-Plan，一个融合长期与短期记忆的闭环MAS框架。通过结合全局-局部与过去-当前指导，M-Plan在保持即插即用设计的同时提升了智能体在多轮任务中的表现。在任务执行过程中，智能体会获得任务特定的里程碑与洞见，并且仅在出现困惑时获得局部提示，这些共同构成全局-局部指导。这些指导的生成与利用也构建了短期记忆。任务完成后，与当前任务相关的信息会在被送入长期记忆存储以供未来检索之前进行优化或重组。上述设计构建了一个不同于其他单独长期或短期记忆工作的综合框架。在ALFWorld、Webshop和PDDL等多轮任务上跨多种模型的大量实验表明，M-Plan在准确性和效率上均优于多个基线方法。

## Abstract
Large language model (LLM)-based agents have recently demonstrated outstanding performance in single-turn tasks, yet they continue to struggle with long-horizon tasks, particularly in environments without prior training. A key limitation of single LLMs is their difficulty in processing long contexts, which stems from weaknesses in continuous decision-making and reasoning capabilities. Although existing multi-agent systems (MAS) equipped with long-term memory bases can partially address this gap, they mostly rely on knowledge reuse or summarization, an approach that is often constrained by directly retrieval without any adaptation for the current task, while the retrieved memory may contain much history noises waiting to be preprocessed. In contrast, MAS characterized by task-specific guidance often lack long-term memory specifically designed for the guidance. To address these challenges, we propose M-Plan, a closed-loop MAS framework that integrates long-term and short-term memory. By combining global-local and past-current guidance, M-Plan enhances agents' performance on multi-turn tasks while maintaining a plug-and-play design. During task execution, agents receive task-specific milestones and insights, and are provided with local hints only when confusion arises, which form global-local guidance together. These guidance generation and utilization construct the short-term memory as well. After task completion, relevant information about the current task is optimized or reorganized before being sent to the long-term memory storage for future retrieval. The designments mentioned above build a comprehensive framework different from other individual long-term or short-term memory works. Extensive experiments on multi-turn tasks including ALFWorld, Webshop, and PDDL across diverse models demonstrate that M-Plan outperforms multiple baseline methods in both accuracy and efficiency.

# M-Plan 论文结构化总结

## 一、核心问题与研究背景

- **研究痛点**：LLM 智能体在单轮任务上表现优异，但在长时程（long-horizon）、多轮交互任务中仍存在明显短板——遗忘中间轮次信息、过度关注首尾轮次、难以维持连续决策与长上下文推理。
- **现有两条技术路线的局限**：
  - **训练型路线**（SFT / RL）：效果可观，但需要人工标注数据与大量算力，部署成本高、灵活性差。
  - **免训练 MAS 路线**：
    - *长期记忆型*（如 ReasoningBank、G-Memory）：依赖"检索即复用"或摘要，检索结果缺乏对当前任务的适配，历史轨迹噪声大、泛化性弱。
    - *短期规划型*（如 HiPlan）：有全局蓝图或逐步提示，但通常缺少与之配套的长期记忆，且逐步生成提示带来高昂 token 开销；仅有高层里程碑又不足以支撑具体动作执行。
- **整体含义**：论文主张长期记忆与短期记忆不应割裂，而应通过"检索—生成—执行—反思—回写"的闭环相互增强；同时用"按需触发"的局部提示替代"每步提示"，在效果与成本之间取得平衡。

## 二、方法论

### 2.1 核心思想

- 提出 **M-Plan**：一个即插即用（plug-and-play）的闭环多智能体框架，融合**长期记忆存储**、**短期记忆生成**与**优化器（Optimizer）**三大模块。
- 引导分为两层：
  - **全局引导**：任务特定的里程碑列表 `M_s = [m_1,…,m_x]`（规划路线）+ 洞见列表 `I_s = [i_1,…,i_y]`（注意事项与任务知识）+ 历史成功轨迹作为上下文示范。
  - **局部引导**：结构化提示 `h_l`，仅在智能体陷入"动作陷阱"或执行无效动作时触发。
- 记忆闭环：短期记忆在任务中产生的内容，经 Optimizer 精炼后写入长期记忆，供后续任务的短期记忆生成使用。

### 2.2 长期记忆存储

- **记忆条目定义**：`E_l = {M_l, I_l, T_l, F_l, D_l}`，分别对应里程碑、洞见、执行轨迹、成功/失败布尔标志、任务描述（作为语义检索键）。
- **存储结构**：向量数据库 + 任务相似度图（相似任务间连边），支持结构化组织与更快检索。
- **检索流程**：
  1. `Ret(Q)` 按语义余弦相似度召回 j 条记忆 `E_S`；
  2. 对 `E_S` 中每条记忆做**一跳图扩展**，加入其直接邻居，得到最终 top-k 记忆 `Extend(E_S)`，以提升多样性与鲁棒性。
- **冷启动特性**：记忆库不依赖任何预采集数据或专家示范，从零开始、在任务执行中持续吸收信息。

### 2.3 短期记忆生成（四智能体协作）

- **Planner**：输入历史成功任务的描述 `D_l`、里程碑 `M_l` 与当前任务描述 `D_s`，生成当前任务的里程碑列表 `M_s = Planner(D_l, M_l, D_s)`。
- **Insighter**：在 `M_s` 基础上补充细节与任务约束，输入含成功与失败案例的描述、洞见 `I_l`、`D_s` 与 `M_s`，输出 `I_s = Insighter(D_l, I_l, D_s, M_s)`。
- **Hinter（条件触发）**：输入当前轨迹 `T_c`、`M_s`、`I_s`、`D_s`，输出四元组 `{state, position, gap, correction}`，即当前状态、所处里程碑、差距建议、下一步动作纠正。
  - **触发规则分场景**：
    - *宽松触发*（ALFWorld、Webshop）：历史中出现重复动作或最近动作无效即触发；
    - *严格触发*（PDDL）：仅当当前动作与上一步重复或动作无效时触发，允许合理的重复动作；
    - 动作有效性直接由环境观测反馈判定，不额外引入判定智能体；
    - 若下一次动作会重复触发同一提示，则**暂停 Hinter**，避免产生重复无用甚至误导性提示。
- **Actioner**：综合检索到的成功轨迹、当前观测、任务描述、里程碑、洞见与条件提示，选择并执行动作。

### 2.4 Optimizer（闭环关键）

- 只对"当前任务生成的指导"做精炼，而非从头重新摘要，分三部分：
  - **成功任务**：`Polish M_s` —— 分析完整轨迹后删除冗余里程碑；`Sparsify T_c` —— 删除重复或无效的"动作-观测"对。
  - **失败任务**：`Refine I_s` —— 由于单凭失败轨迹难以提炼洞见，额外引入最相似的成功轨迹做对比；同时**保留完整失败轨迹**（不稀疏化），以留存失败相关细节。
  - 设计动机：成功任务中 `M_s` 往往正确但不够精炼；失败任务多因未遵循 `M_s`，故不对失败任务的 `M_s` 做打磨。
- 优化结果回写长期记忆，形成长期—短期记忆的完整闭环。

### 2.5 评估指标中的公式设计

- **Meta-Step = ASS / SR**（成功任务平均步数 ÷ 成功率），用于修正"成功率低反而步数少"的偏差，使效率比较更公平。
- **收益归一化**：`F_t = (2/π)·arctan(SR/FR)`，`C_t = A_t / F_t`（`A_t` 为平均 token 消耗，`FR` 为失败率）。用 arctan 抑制 SR→1 时的数值爆炸，并将上界归一到 1；`C_t` 表示"单位成功收益的 token 成本"，越小越好。

## 三、实验设计

- **数据集 / 场景**（均为文本交互的长时程多轮基准）：
  - **ALFWorld**：文本家务环境，6 类子任务（put、put two、examine、clean/heat/cool & put），最大 50 步，测试官方 134 个分布外任务。
  - **Webshop**：模拟电商网站（118 万商品），200 条指令，最大 40 步。
  - **PDDL**：4 类机器人规划任务（调酒、摆积木、移球、处理轮胎），30 步预算。
- **基座模型**：Qwen3-32B 与 Qwen3-14B 两种规模。
- **对比基线**：
  - **G-Memory**：检索增强的分层记忆，复用详细轨迹、关键步骤与历史洞见；
  - **ReasoningBank**：抽取并复用长期记忆洞见；
  - **HiPlan**：短期记忆规划，全局里程碑 + 逐步提示，配预置记忆库。
- **评价指标**：成功率 SR、平均奖励 AD（Webshop/PDDL）、平均步数 AS、成功任务平均步数 ASS、Meta-Step、token 指标 `A_t / F_t / C_t`。

## 六、主要结论与发现

- **效果**：M-Plan 在全部三个基准、两种模型上均取得最优。ALFWorld 上 Qwen3-32B 达 **99.3%** 成功率；Webshop 上较 G-Memory 提升约 20 个百分点 SR、约 7 个百分点奖励；PDDL 上 SR 达 **52.8%**，超过最优基线的两倍。
- **效率**：ALFWorld 上 Meta-Step 降至 12.28，比 HiPlan 低约 30%；Webshop 上 Meta-Step 较 HiPlan 降低逾 50%；PDDL 上 Meta-Step 从 60+ 降至 29.22。token 层面，ALFWorld 的 `C_t` 比 HiPlan 低近 70%。
- **关键发现**：
  - "选择性提示"可以在不牺牲成功率的前提下大幅削减 token，验证了逐步提示并非必需；
  - 检索历史案例对性能贡献显著（去 Retrieval 后 PDDL SR 从 52.8 降至 42.5）；
  - Hinter 是影响最大的模块之一（去掉后 SR 降至 41.1、Meta-Step 升至 37.64），说明纠错型局部引导对避免死循环至关重要；
  - 小模型（14B）上优势收窄，说明框架效果依赖基座 LLM 生成高质量任务特定指导的能力。

## 七、优点

- **架构层面**：把长期记忆、短期规划与反思优化整合为一个闭环系统，明确区分"成功任务打磨计划、失败任务提炼洞见"的非对称优化策略，设计有洞察力且贴合实际失败模式。
- **成本控制**：条件触发式提示 + 动作有效性直接由环境反馈判定（不额外引入判定智能体）+ Hinter 重复提示暂停机制，三处设计共同压低 token 与调用次数。
- **工程可用性**：即插即用、免训练、记忆库从零自建，不依赖预采集数据，部署门槛低。
- **评估方法学**：提出 Meta-Step 与 `C_t` 两个指标，正面回应了"低成功率导致低步数"和"失败损失难以量化"两类常见评测偏差，具有可复用价值。
- **实验透明度**：报告三次重复的均值与方差，主动说明 Webshop 不适用 token 指标的原因，并披露 HiPlan 轨迹为自行构造。

## 八、不足与局限

- **环境覆盖有限**：全部实验在文本模拟环境完成，未涉及真实世界或具身/多模态场景；作者在结论中也承认这是主要局限，尚未验证向真实环境扩展的可行性。
- **消融覆盖不足**：消融仅在 PDDL + Qwen3-32B 单一设定下完成，缺少跨数据集、跨模型的模块贡献分析；也无超参敏感性实验。
- **基线公平性存疑**：HiPlan 依赖作者自建的少量专家轨迹，其表现可能被低估或高估；不同方法初始信息条件不对等，横向比较的严格性有限。
- **指标公式的表述瑕疵**：正文称 `F_t` "在 SR = 0.5 处取得最大值"，但从 `F_t = (2/π)·arctan(SR/(1-SR))` 看，该函数对 SR 单调递增，SR = 0.5 实为拐点（增速最大处）而非最大值点，表述不够严谨。
- **成本结构未被完整刻画**：虽然 `C_t` 显示 M-Plan 单位收益 token 成本低，但 PDDL 上其绝对 token 消耗（0.17M）实际高于 G-Memory（0.12M）与 ReasoningBank（0.07M）；同时记忆库持续增长带来的检索噪声、存储开销与延迟未被讨论。
- **依赖强基座模型**：14B 模型上相对基线的优势明显收窄，说明框架对 LLM 生成里程碑与洞见的质量敏感，弱模型下闭环可能放大错误。
- **潜在偏差风险**：Hinter 的触发规则按环境手工定制（宽松/严格两套），存在针对 benchmark 调参的可能，跨环境迁移时需重新设计规则；此外记忆库自演化缺乏遗忘或冲突消解机制，长期运行可能出现记忆污染。
