Abstract 

Multi-vector retrieval models such as ColBERT often outperform single-vector models of com-parable scale by matching queries and doc-uments at the token level. However, retain-ing a vector for every token substantially in-creases storage requirements and slows re-trieval compared to single-vector bi-encoders, limiting their scalability. We introduce FLINT (Fixed-budget Late INTeraction), an architec-ture that uses attention-based pooling to rep-resent each query and document with a fixed number of embedding vectors. Unlike architec-tures that pool only document representations while retaining token-level queries, FLINT ap-plies pooling symmetrically to both sides, limit-ing document storage and the number of vector comparisons needed during retrieval. FLINT achieves comparable ranking effectiveness to the closest baselines on BEIR and outperforms them on several benchmarks with longer and more complex queries, including BrowseC-omp+, CRUMB, and TREC Tip-of-the-Tongue 2025. We demonstrate that FLINT’s effective-ness–efficiency benefits extend across encoder architectures, testing it on two separate back-bones (BERT and ModernBERT). On long-query corpora, FLINT delivers 1.5–2.8× faster end-to-end retrieval than ConstBERT, the clos-est baseline. FLINT also reduces index size by 5.3–9.3× relative to token-level late-interaction models such as ColBERTv2. 

1 Introduction 

Multi-vector retrieval models such as ColBERT often outperform bi-encoders (Reimers and Gurevych, 2019) of comparable scale because they preserve token-level representations and enable fine-grained matching between query and docu-ment tokens (Khattab and Zaharia, 2020). How-ever, this effectiveness comes at a substantial cost in latency and storage. While a standard bi-encoder stores a single vector for each document, ColBERT-style models store one vector for every document to-ken . Consequently, their index size grows with doc-ument length, substantially increasing storage re-quirements and retrieval-time computation, which leads to higher latency and limits scalability. ColBERTv2 (Santhanam et al., 2022b) substan-tially reduces ColBERT’s storage footprint through residual compression and improves retrieval ef-fectiveness while retaining token-level representa-tions. The PLAID index (Santhanam et al., 2022a; MacAvaney and Tonellotto, 2024) further improves retrieval efficiency through centroid-based candi-date filtering and pruning. XTR (Lee et al., 2023) scores documents using retrieved tokens and esti-mates missing token similarities. WARP (Scheerer et al., 2025) accelerates XTR-style retrieval by computing scores directly from compressed token embeddings. MUVERA (Dhulipala et al., 2024) uses fixed-dimensional encodings for single-vector MIPS search, followed by multi-vector reranking. Despite these advances, storage requirements re-main large and tied to document length through token-level representations retained for ranking. 

MacAvaney et al. (2025) address these efficiency limitations by proposing ConstBERT, in which they pool each document into a fixed set of 32 embed-ding vectors. This fixed representation substan-tially reduces index sizes relative to ColBERTv2 while preserving effectiveness on MS MARCO and BEIR. However, ConstBERT retains one em-bedding vector per query token, so the number of query vectors and the associated search cost still grow with longer and more complex queries, where latency also increases. This motivates the ques-tion: Can we design a fixed-budget late-interaction architecture that preserves effectiveness on long, complex, out-of-distribution queries while reducing both document storage and query-side search cost? 

We give a more detailed comparison with related work in Appendix A. To retain the storage efficiency of fixed-budget representations without sacrificing effectiveness, arXiv:2610.27273v1 [cs.IR] 19 Oct 2026 and to further reduce retrieval latency, we intro-duce FLINT (Fixed-budget Late INTeraction). The key idea is to retain multiple representations for matching without tying each representation to a single input token. As illustrated in Figure 1, learned latent vectors attend over the full token sequence, each aggregating information from mul-tiple tokens into an output embedding. Thus, longer inputs can change the information captured by these embeddings without increasing their number. The pooling module converts each variable-length token sequence into a fixed number of embedding vectors for multi-vector retrieval and replaces the single-vector mean-pooling operation commonly used in bi-encoders. Figure 2 compares FLINT’s architecture with prior models. Unlike ConstBERT, FLINT applies attention-based pooling symmetri-cally to both documents and queries. As a result, 

FLINT’s storage cost per document is indepen-dent of document length, and its fixed query-vector budget keeps late-interaction search la-tency nearly constant as query length increases .We evaluate FLINT on standard general-domain retrieval benchmarks, as well as out-of-domain benchmarks featuring substantially longer and more complex queries. On BEIR (Thakur et al., 2021), FLINT outperforms the single-vector base-line and remains competitive with existing late-interaction models, while requiring substantially less storage than token-level retrieval. On more complex benchmarks, including CRUMB (Killing-back and Zamani, 2025), TREC Tip-of-the-Tongue 2025 (Arguello et al., 2026), and BrowseComp+ (Chen et al., 2026), FLINT generally provides stronger retrieval effectiveness than ConstBERT. These results show that FLINT fixed-budget repre-sentations on both the query and document sides can retain strong retrieval effectiveness even for long, out-of-distribution queries. FLINT combines these effectiveness results with substantial savings in storage and retrieval time. 

FLINT reduces index size by 5.3–9.3× relative to token-level late-interaction models. Beyond reducing storage, FLINT substantially improves retrieval-time efficiency. Because it produces a fixed number of vectors for both documents and queries, its search cost remains nearly constant as query length increases. On the evaluated long-query corpora, FLINT achieves 1.5–2.8 × faster end-to-end retrieval and 2.5–4.8× faster search time than ConstBERT. We note that FLINT is or-thogonal to other existing efficiency techniques, including dimensionality reduction and PLAID indexing (Santhanam et al., 2022a), which can provide complementary improvements in storage and retrieval speed. We evaluate FLINT with ModernBERT-large (Warner et al., 2025) as an al-ternative backbone and show that its effectiveness– efficiency benefits remain robust. Our main contributions are: • We introduce FLINT 1, a fixed-budget late-interaction architecture that applies symmetric attention-based pooling to both document and query representations, decoupling storage and retrieval cost from input length. • We show that FLINT outperforms a single-vector baseline, remains competitive with existing late-interaction models on standard benchmarks and better preserves effectiveness on longer, out-of-distribution queries, while achieving lower re-trieval latency than ConstBERT. • We demonstrate that FLINT generalizes across backbones and exposes the vector budget V as a tunable effectiveness–efficiency trade-off. 

2 FLINT: Fixed-Budget Late Interaction 

2.1 Fixed-Budget Representations 

Given a query q and a document d, a shared trans-former backbone (Vaswani et al., 2017) indepen-dently encodes each input into a sequence of con-textualized, h-dimensional representations. Let 

Xq ∈ R|q|× h and Xd ∈ R|d|× h denote the resulting query and document representations, respectively, where |q| and |d| are the numbers of query and doc-ument tokens, and h is the hidden dimensionality of the transformer. In standard late-interaction models such as Col-BERT, all token representations are retained for scoring. Consequently, the number of stored doc-ument vectors grows with document length, while the cost of query–document matching grows with the number of query and document vectors. To address this limitation, FLINT inserts an attention-based pooling module between the transformer and the late-interaction scoring layer. The module maps the variable-length query and document representa-tions, Xq and Xd, to fixed-budget pooled represen-tations Zq, Z d ∈ RV ×h, where V denotes the fixed number of vectors allocated to each query and doc-ument. 3 Experiments 

3.1 Datasets 

We evaluate FLINT across four complementary re-trieval suites spanning diverse tasks, queries, and corpus sizes. BEIR (Thakur et al., 2021) represents conventional zero-shot retrieval across heteroge-neous domains, including question answering, fact verification, and biomedical search, with predom-inantly short and keyword-like queries. CRUMB 

(Killingback and Zamani, 2025), in contrast, cov-ers multi-aspect and reasoning-intensive retrieval tasks whose queries express multiple constraints, use domain-specific terminology, and often have limited lexical overlap with relevant documents. We additionally evaluate two retrieval settings that differ substantially from standard passage re-trieval. TREC Tip-of-the-Tongue 2025 (Arguello et al., 2026) evaluates known-item re-finding from long, conversational descriptions that may include vague details, comparisons, and incorrect recollec-tions. BrowseComp+ (Chen et al., 2026) evaluates deep-research retrieval, where systems must iden-tify human-verified supporting evidence among challenging distractor documents. Together, these suites cover both short, conventional information needs and longer, out-of-distribution queries. This long and complex query regime is particularly im-portant for evaluating FLINT because the retrieval cost of token-level late-interaction models grows with the number of query representations. Details of dataset statistics are reported in Appendix C. 

3.2 Baselines 

Our primary goal is to isolate the effectiveness and efficiency trade-offs introduced by the retrieval ar-chitecture, rather than compare independently opti-mized retrieval systems. We therefore focus on con-trolled comparisons with single-vector, token-level late-interaction, and document-only fixed-budget architectures, using matched backbones and train-ing settings where possible. Methods such as XTR (Lee et al., 2023; Scheerer et al., 2025), token prun-ing (Acquavia et al., 2023), and other indexing or compression techniques address related efficiency challenges but modify different components of the retrieval pipeline. We discuss these approaches in Appendix A. Here, we compare the results of our FLINT BERT model against ColBERTv2 (San-thanam et al., 2022b) and ConstBERT (MacA-vaney et al., 2025). On ModernBERT, we com-pare against ColBERTv2, ConstBERT, and single-vector-based architectures.

We evaluate the trained models for ColBERT and ConstBERT on our exact setup to ensure fair comparison. In testing an alternate back-bone, we replace BERT with ModernBERT while keeping FLINT’s symmetric attention-based pool-ing architecture unchanged. 4 Retrieval Effectiveness 

We first evaluate whether FLINT’s fixed-budget representations preserve retrieval effectiveness rela-tive to fixed-budget and token-level late-interaction baselines. Storage and retrieval-time efficiency are explored separately in Section 5. 

4.1 Overall Retrieval Effectiveness 

Table 1 reports NDCG@10 on BEIR and the three complex-query benchmarks; additional Re-call@1000 results are reported separately in Ap-pendix Table 6. FLINT remains competitive with ConstBERT on BEIR, showing that symmetric attention-based pooling preserves effectiveness on conventional, predominantly short-query retrieval tasks. For example, on Quora, FLINT achieves an NDCG@10 of 0.848, outperforming ConstBERT at 0.817 and closely approaching ColBERTv2 at 0.855. ColBERTv2 nevertheless performs better on many BEIR collections and has the highest BERT-based average, which illustrates the effectiveness advantage that full token-level representations can retain in the short-query domain. FLINT’s advantage becomes clearer on the complex-query benchmarks. Among the BERT-based models, FLINT achieves the highest average NDCG@10 on CRUMB, TREC-ToT 2025, and BrowseComp+. For example, on TREC-ToT 2025, FLINT improves NDCG@10 from 0.047 with Con-stBERT to 0.065 and also exceeds ColBERTv2 at 0.046. Although the absolute scores on these bench-marks are lower than on BEIR, this reflects the substantially greater difficulty of the tasks, which involve long, out-of-distribution queries, limited lexical overlap, uncertain recollections, and chal-lenging distractor documents. Overall, FLINT preserves competitive effective-ness on conventional retrieval tasks while provid-ing stronger ranking effectiveness on longer and more complex information needs. Although token-level ColBERTv2 remains more effective on some datasets, FLINT’s ability to retain competitive ef-fectiveness with compact representations is valu-able in light of the substantial storage and latency reductions examined in Section 5.

4.3 Impact of the Budget V

We examine how the number of vectors per query and document, V , affects FLINT’s effectiveness with the ModernBERT backbone. Reducing the budget from V =32 to V =16 lowers effectiveness across all benchmark suites. Nevertheless, FLINT with V =16 still outperforms the single-vector base-line on every suite and ModernBERT ConstBERT on all three complex-query suites, while requiring approximately half of ConstBERT’s index size. Increasing the budget from V =32 to V =64 

leaves average BEIR effectiveness nearly un-changed (0.531 vs. 0.530) but improves perfor-mance on complex queries. These results sug-gest that longer, multi-constraint queries benefit from a larger vector budget, whereas the predom-inantly short queries in BEIR gain little beyond 

V =32 . The budget thus provides a direct way to trade additional storage and computation for improved effectiveness on complex queries.

5.3 PLAID Cell Activation 

PLAID does not score every document in the cor-pus. Each query vector probes its nearest centroids, activating the corresponding cells and contributing documents to the candidate pool. The union of the corresponding cells determines the candidate doc-uments that are then scored with MaxSim. There-fore, activating more cells broadens the search and generally increases the number of candidates; ac-tivating fewer cells reduces search work. How-ever, fewer activated cells are useful only insofar as the resulting candidate pool is still effective. Fig-ure 5 shows that FLINT consistently activates fewer cells than ConstBERT on the three long-query cor-pora. This translates into fewer candidate docu-ments, as ConstBERT scores 2.3–4.6× more can-didates across the two backbones. It also compares each candidate against 5–7× more query vectors. 

FLINT therefore reduces search work by scor-ing fewer candidates and performing fewer vec-tor comparisons per candidate. 

The reduction in activated cells is larger on BERT, where FLINT’s pooled vectors are also more concentrated in direction and probe fewer dis-tinct cells (Appendix D). These savings accompany competitive effectiveness relative to ConstBERT on conventional retrieval and stronger results on the complex-query suites, showing that FLINT can search a smaller candidate pool without sacrificing overall retrieval effectiveness.

6 Conclusion 

We introduced FLINT, a fixed-budget late-interaction architecture that addresses two central scaling challenges: document storage and query-side search cost. Shared attention-based pooling maps both queries and documents to a fixed num-ber of vectors, preserving multi-vector matching without retaining one vector per token. FLINT achieves 5.3–9.3× smaller indices than token-level models and, on the long-query corpora, 

1.5–2.8× faster end-to-end retrieval than Const-BERT. Its search latency remains nearly constant as queries grow longer. With the vector budget 

V controlling the effectiveness–efficiency trade-off, FLINT makes storage and search computation explicit architectural choices, supporting efficient retrieval for long and complex queries. Limitations 

Training distribution. Our BERT FLINT model is supervised on the same MS MARCO pas-sage triples as ColBERTv2 and ConstBERT. We adopt this deliberately, so that differences between FLINT, ConstBERT, and ColBERTv2 reflect the pooling architecture rather than the training data, but it means the only query distribution the pool-ing module ever observes during training is MS MARCO’s short, keyword-like queries. Our cen-tral claims concern long, complex queries, so those results are entirely zero-shot generalization. To our knowledge, there is no comparable MS MARCO-scale dataset of high-quality long queries. More-over, multi-vector retrievers are known to be sen-sitive to both the scale and quality of training data. We therefore leave long-query-specific training to future work. 

Limited budget sweep. On BERT we fix the bud-get at V =32 , matching ConstBERT’s setting so the two fixed-budget systems are directly comparable. We vary V ∈ { 16 , 32 , 64 } only on ModernBERT, so it remains open whether symmetric pooling de-grades more or less gracefully than document-only pooling at smaller budgets, and whether a larger budget would close FLINT’s remaining gap to Col-BERTv2 on BEIR. We also tie the query and docu-ment budgets to the same value. Decoupling them, for instance a smaller query budget paired with a larger document budget, is unexplored. 

Scope of the evaluation. On BERT, absolute ef-fectiveness on the complex-query suites is low for every system we evaluate, with the best NDCG@10 on TREC Tip-of-the-Tongue 2025 reaching only 

0.065 . FLINT’s improvements in this regime are consistent across suites, but they are improvements within a band where all late-interaction models we test perform poorly, and the small absolute margins should be read with that in mind. Our evaluation also covers two encoder-only backbones of modest scale, so behavior under substantially larger back-bones remains untested.

A Related Work 

Fixed-size multi-vector representations. 

MetaEmbed (Xiao et al., 2026) appends learnable tokens to the input of a vision-language model and uses their final hidden states as multi-vector embeddings for multimodal retrieval, trained with Matryoshka-style nested groups so the number of vectors can be chosen at test time. FLINT instead targets long-query text retrieval and pools the encoder outputs with a separate cross-attention module rather than adding tokens to the input. It uses a fixed budget V per model instead of nested groups, and projects each vector to a low dimension, whereas MetaEmbed keeps the full hidden dimension, creating much larger indices. They also focus primarily on multi-modal benchmarks rather than on long and complex textual datasets. Poly-encoders (Humeau et al., 2020) use learned codes that attend over the query tokens to produce several query vectors, while each document re-mains a single vector compared through attention. FLINT pools both queries and documents into mul-tiple vectors and scores them with MaxSim. ConstBERT (MacAvaney et al., 2025) pools each document into a fixed number of vectors with a learned linear layer and keeps queries token-level without compression. FLINT pools both sides with cross-attention, so query cost does not grow with query length. 

Reducing token vectors. Token pooling (Clavié et al., 2024) clusters document token vectors post-hoc, and static pruning (Acquavia et al., 2023) re-moves low-impact document vectors. As presented in both papers, however, the number of vectors still grows with document length and queries are un-changed, whereas FLINT learns a fixed number of vectors for both sides. Query embedding pruning (Tonellotto and Mac-donald, 2021) keeps the query token vectors of the rarest terms for candidate generation. FLINT instead learns to summarize all query tokens into 

V vectors and also fixes the document side vector count. 

Efficient multi-vector search. XTR (Lee et al., 2023) trains the model so that its first-stage token retrieval finds the relevant document tokens, then scores documents using only those retrieved to-kens. This skips loading every candidate’s full set of vectors, but it keeps one vector per token for queries and documents, so its index is as large as ColBERT’s. WARP (Scheerer et al., 2025) is a faster search engine for XTR-style retrieval, but its index still stores one vector per token. MUVERA (Dhulipala et al., 2024) is a latency-focused pre-filter: it compresses each multi-vector set into one fixed-dimensional encoding (FDE) for fast single-vector candidate search, then reranks candidates with the full token-level vectors. Because the FDE index sits on top of the full multi-vector index, its storage exceeds that of the multi-vector index alone, whereas FLINT reduces storage. 

Single-vector retrieval. With V =32 vectors of dimension 128, FLINT represents each input with 4096 values. Single-vector models that produce vector embeddings with the same amount of floats, such as RepLLaMA (Ma et al., 2024), rely on much larger backbones: it fine-tunes LLaMA-7B as a bi-encoder producing one 4096-dimensional vec-tor scored by dot product. To our knowledge, no single-vector model with a similarly sized and per-forming backbone produces embeddings of this size. A size-matched comparison would thus alter the backbone’s strength, and we therefore leave it out of scope. We instead compare against a single-vector model with the same backbone and training data (Section 4.2). 

Other approaches. TRIAL (Kang et al., 2025) improves the scoring function rather than compress-ing representations; SCV (Park et al., 2025) com-presses only documents via span pooling with a single-vector prefilter, so query-side cost still scales with query length; Zong & Piwowarski (Zong and Piwowarski, 2025) dynamically prune document tokens, with pruning ratio varying per document and query tokens left uncompressed. FLINT com-presses queries and documents to a fixed, input-length-independent budget. 

B Experimental Settings 

Training. On BERT, FLINT is trained on MS MARCO passage-ranking triples with 64 candi-dates per query, in fp16 with a global batch size of 48, a learning rate of 10 −5, and a linear schedule over 267K steps. On ModernBERT-large, we train the FLINT ( V ∈ { 16 , 32 , 64 }), ConstBERT ( 32 

document vectors), and ColBERTv2 architectures ourselves (ModernBERT FLINT, ModernBERT ConstBERT, and ModernBERT ColBERTv2) un-der the multi-vector training regimen of Warner et al. (2025), on MS MARCO with 32 candidates per query, for one epoch in bf16 with a global batch size of 16, a learning rate of 3 × 10 −5, and 5% warmup. The FLINT pooling module uses a learn-ing rate of 10 −4. Training queries are truncated to 84 tokens. The single-vector baseline is a publicly available ModernBERT-large bi-encoder, 3 trained identically to the single-vector retriever introduced in (Warner et al., 2025). 

Pooling module. The pooling module uses 

H=8 attention heads and a feed-forward expan-sion ratio of r=4 on BERT ( h=768 ) and r=2 on ModernBERT ( h=1024 ), with dropout 0.1. Pooled vectors are projected to h′=128 dimensions. On BERT, the query and document sides use separate projections; on ModernBERT, they share one. 

Sequence lengths. At evaluation, queries are truncated to M =512 tokens for every model. The evaluation document length N differs between backbones because of ConstBERT: its learned pool-ing maps a fixed number of token positions to its 32 document vectors, so N is fixed when ConstBERT is trained. The released BERT ConstBERT check-point uses N =250 , so we truncate documents to 

N =250 for all BERT models. On ModernBERT, we train ConstBERT with N =512 and truncate documents to N =512 for all ModernBERT mod-els. Within each backbone, every model therefore sees the same document context. 

Query padding. BERT ConstBERT and Col-BERTv2 pad queries shorter than 32 tokens up to 32, matching ColBERTv2’s default and the setting they were trained with. All ModernBERT models are trained without query padding and are evalu-ated the same way. BERT FLINT queries are not padded during training or evaluation, and FLINT always produces V query vectors.
