Navigating Epistemic Parity in LLM Agents:
A Benchmark for Cross-Source Conflict Resolution
Between Memory and Procedural Skills
Prakhar Pandey
Indian Institute of Technology Guwahati
prakhar.0879@op.iitg.ac.in
July 2026
Abstract
Production LLM agents increasingly run two context-provisioning systems in tandem: episodic
memory pipelines that inject persistent user preferences and historical state, and procedu-
ral skill modules (e.g., SKILL.md files) that inject standardized, developer-defined operating
procedures. Because these two sources are injected into the same context region with no de-
fined precedence between them, they can issue contradictory instructions that no instruction
hierarchy resolves—a condition we term epistemic parity. We introduce a benchmark for
measuring how LLM agents adjudicate such cross-source conflicts. We (i) develop a four-way
taxonomy of memory–skill contradictions—factual, format, procedural, and permission; (ii)
instantiate 52 scenarios under a tripartite test-case anatomy (memory injection, skill injec-
tion, ambiguous user task), scored almost entirely by deterministic checkers over tool-call
payloads and output structure; and (iii) run each scenario under three context conditions
to isolate positional bias, measure the efficacy of an explicit precedence directive, and clas-
sify disclosure behavior, quantifying silent adjudication—resolving a conflict without telling
the user. Across 1,383 runs on three open-weight models we find that neither source wins
uniformly: resolution depends jointly on conflict type, model, and injection order. Mov-
ing the skill block nearer the task raises its win rate in all six factual and procedural cells
(sign test, p = 0.031) but reverses for format conflicts, indicating that adjudication tracks
token placement rather than source semantics. An explicit “skill takes absolute precedence”
directive raises skill compliance on the two stronger models yet leaves 3–10% residual non-
compliance, and moves the smallest model’s factual and procedural resolution in the wrong
direction. Most consequentially, in 98.8% of runs where the agent acted through a tool call
it emitted no accompanying text at all, and 89% of all runs disclosed nothing about the
contradiction—silent adjudication is not a tendency but the default. Code, scenarios, and
raw outputs are public.

Introduction
The architecture of Large Language Model (LLM) agents has shifted from ephemeral, single-turn
prompt–response exchanges to persistent, long-horizon operational systems. Two infrastructural
capabilities drive this shift: continuous episodic memory and modular procedural skills. Memory
pipelines let agents retain historical interactions, environmental state, and user preferences across
sessions. Skill modules inject standardized, developer-defined procedures into the agent’s active
context. As enterprises deploy both systems in tandem, a new failure mode emerges—caused
not by hallucination or tool failure, but by contradictory instruction provisioning.
Consider a scenario built to isolate a single point of conflict. A user instructs an agent to
“deploy the application.” The memory system injects a saved snippet: the user’s deployment

endpoint is api.legacy.com. Simultaneously, the skill system loads a SKILL.md file mandating
that all deployments target api.v2.com.
The agent is now trapped between two legitimate directives. Both sources were provisioned
into the context by design, and both dictate mutually exclusive actions. No predefined hierarchy
ranks a user’s persistent memory above a developer’s skill module, or vice versa: they exist in a
state of epistemic parity.1 Evaluating this test case does not mean finding a “correct” answer—
both sources hold equal legitimacy. It means recording the resolution bias: which endpoint did
the agent’s tool call target?
Existing instruction-following benchmarks are not built for this question. The dominant
framework, the Instruction Hierarchy, evaluates how models navigate conflicts across tiers of
privilege [1]. Benchmarks such as ManyIH-Bench assess how frontier models handle up to twelve
privilege levels across 853 agentic tasks [2]. But the hierarchy paradigm assumes a hierarchy can
be defined and enforced. The memory–skill dichotomy defies that assumption: the two sources
carry different provenances but equal authority.
This paper introduces a benchmark that maps how LLM agents behave under cross-source
epistemic parity. Scaling the deployment scenario into a matrix of factual, format, procedural,
and permission contradictions exposes the latent biases of current architectures. The resulting
Adjudication Heatmap—models against conflict types, with the winning source in each cell—
makes peer-level conflict resolution directly visible. Three context conditions then test positional
bias, the efficacy of an explicit precedence rule, and the tendency of models to adjudicate silently.
In summary, our contributions are threefold:
1. A taxonomy of cross-source conflicts.
We categorize memory–skill contradictions
into four typologies—factual, format, procedural, and permission—and characterize the
systemic tension underlying each (Section 4).
2. An executable benchmark for epistemic parity. We specify a tripartite test-case
anatomy, instantiate 52 scenarios (13 per typology), and score them with deterministic
checkers over tool-call payloads, word counts, and output schemas—no LLM judge is
required for any winner decision (Section 5). Code, scenarios, checkers, and raw model
outputs are released publicly.
3. An empirical study with three diagnostic probes. We run the full matrix across
three open-weight models under three context conditions (1,383 scored runs), reporting
baseline resolution bias, the shift induced by inverting injection order, the residual non-
compliance under an explicit precedence directive, and the rate of silent adjudication
(Section 6).

Evolution of Contextual Provisioning Infrastructures
To understand cross-source conflicts, we first dissect the two pipelines that feed information
into the LLM context window. Their convergence creates the contextual pressure under which
epistemic parity conflicts arise.
2.1
Episodic Memory and Virtual Context Management
Fixed context windows are a bottleneck for perpetual conversation and long-term reasoning.
To work around this limit, frameworks like MemGPT borrow from hierarchical memory in

2.2
Procedural Skills and the Supply Chain of Execution
In parallel with the memory pipeline runs the agentic skill layer. Moving from atomic tool use (a
single API call, one web search) to long-horizon workflows has required formalizing reusable pro-
cedures. Skill modules are more than prompt templates: they package applicability conditions,
execution policies, termination criteria, and reusable interfaces into callable procedures. Frame-
works such as Anthropic’s Agent Skills standardize this packaging through the SKILL.md format
and progressive disclosure: rather than loading an enterprise’s full documentation, the system
selectively injects only the skills relevant to the current task [5]. Skills dictate deterministic
workflows, compliance standards, and output schemas.
The skill layer represents the systemic, developer-defined truth: static within a session,
compliance-driven, and built to enforce best practice.
In effect, skills form a software sup-
ply chain for agent behavior—a compromised or poorly specified skill is not one bad answer but
a corrupted procedure affecting every task executed under it.

2.3
The Genesis of Epistemic Parity
The intersection of localized truth (memory) and systemic truth (skills) makes conflicts in-
evitable. Unlike prompt injection, jailbreaks, or Byzantine faults—where a malicious actor tries
to overwrite a legitimate instruction—epistemic parity conflicts involve two benign, trusted,
equally legitimate data streams. The memory system is doing exactly what it was built to do:
injecting preferences to preserve continuity and personalization. The skill system is doing ex-
actly what it was built to do: injecting standard procedures to preserve compliance and workflow
integrity. When these mandates contradict, the LLM becomes an unguided adjudicator, forced
to decide—without hierarchical guidance—which version of reality to instantiate.

2.4
Why Parity, and Not a Hidden Hierarchy?
A natural objection is that parity is an artifact of our setup: in real deployments, memory might
be injected at user privilege and skills at system privilege, so a hierarchy exists after all and the
framing dissolves. Three considerations argue otherwise.
First, at the interface where the model actually reads them, both sources typically arrive
inside the same system-context region as retrieved text blocks—not as distinct role-tagged turns
carrying different trust levels.
Privilege in the Instruction Hierarchy sense is a property of
message provenance that the serving stack must encode explicitly [1]; retrieval pipelines and
skill loaders generally do not encode it, because neither was designed with the other in mind.
Second, even where a stack does assign an ordering, the assignment is a local engineering
choice rather than a settled convention: memory pipelines [4] and skill frameworks [5] are sepa-
rately developed components composed by integrators, and no standard specifies which wins. A
benchmark that assumed one ordering would measure that integrator’s configuration, not model
behavior.
Third, and most practically, the ordering is not normatively obvious even when it is techni-
cally expressible—which is the point of Section 3.4. Skills-always-win and memory-always-win
both produce clearly defective agents. Our claim is therefore narrow: absent an explicit, model-
visible precedence signal, the model must adjudicate, and what it does then is an empirical
property worth measuring. Section 6 tests the complementary case directly by adding such a
signal (the directive condition) and measuring how far compliance actually goes.
3
Instruction Hierarchies and Their Limitations
The prevailing method for handling contradictory inputs is the Instruction Hierarchy: agents
should follow instructions according to a pre-established chain of trust and authority [1].
3.1
The Architecture of the Instruction Hierarchy
The original formulation defines how models should behave when instructions in a prompt con-
flict: more trusted instructions—those from the system developer—carry higher privilege and
override lower-privilege instructions from users or third-party tool outputs [1]. This alignment
also serves security: many prompt-injection attacks and jailbreaks can be neutralized by treating
them as unauthorized conflicts that violate the hierarchy.
3.2
ManyIH-Bench and the Scaling of Privilege
The initial hierarchy assumed a small, fixed set of privilege levels (typically fewer than five,
e.g., System > User > Tool), but real agentic settings involve many more sources: sub-agents,
enterprise databases, real-time APIs, environmental sensors. The Many-Tier Instruction Hi-
erarchy (ManyIH) framework addresses conflicts among arbitrarily many privilege levels, and
ManyIH-Bench operationalizes it: models must navigate up to 12 levels of conflicting instruc-
tions across 853 agentic tasks—427 coding tasks verified by unit tests and style checkers, and 426
instruction-following scenarios spanning 46 real-world agents—with each instruction assigned a
privilege value as an ordinal rank or a scalar [2].
The results show that many-tier conflict resolution remains unsolved. Across ten frontier
proprietary and open-weight models, the best performer, Gemini 3.1 Pro, reaches only 42.7%
accuracy, and GPT-5.4 reaches 39.5% despite near-perfect (>99%) reported performance on con-
ventional two-tier instruction-hierarchy evaluations [2]. Accuracy degrades consistently as the
number of instruction tiers grows, and models are sensitive to how privilege is represented:
switching from ordinal to scalar privilege encodings that preserve the same ordering drops
frontier-model accuracy by roughly eight points [2].
Complementary diagnostic work shows
4


that hierarchy violations can originate at several distinct stages: failing to identify the relevant
instructions in context, failing to compute the correct active set under the hierarchy (conflict-
resolution failure), or failing to realize the correct decision in the final response [6].
3.3
Policy Adherence Under User Pressure
The closest empirical relatives of this work are agent benchmarks that pit a domain policy against
a user’s expressed wishes. τ-bench places an agent between a simulated user and a customer-
service API, requiring it to satisfy the user while adhering to a domain policy document, and
scores the final database state against an annotated goal; its passk metric measures whether
an agent behaves consistently across repeated trials rather than once [7]. That setting shares
our structure of a standing procedural document colliding with a situated user demand, and its
consistency metric anticipates our use of repeated runs.
Two things separate our setting from it. First, in τ-bench the policy is authoritative by
construction—deviating from it is an error, and correctness is well defined—whereas under
epistemic parity neither source is designated correct, so there is no goal state to score against
and the measured quantity is bias rather than accuracy. Second, the user’s wishes arrive there
through live dialogue, while ours arrive as retrieved persistent memory: an artifact injected by
infrastructure, carrying the authority of the user’s accumulated history rather than of a present
request. That distinction is what makes precedence undefinable rather than merely contested.
3.4
The Gap: The Myth of Defined Precedence
Despite their rigor, hierarchy benchmarks share a structural limitation: they assume a hierarchy
exists and can be explicitly defined. In their diagnostic settings, the conflicting messages and
their precedence relations are known a priori [6]. For the relationship between episodic memory
and procedural skills, that assumption collapses—no predefined supremacy exists between a
user’s persistent memory and a developer’s skill module.
The operational consequences of forcing a hierarchy illustrate why.
If skills perpetually
outrank memory, the agent becomes rigid and bureaucratic, unable to adapt to the edge cases,
historical workarounds, and preferences that justify deploying an agent over a fixed script. If
memory perpetually outranks skills, the agent risks compliance violations, broken production
deployments, and ignored security patches—simply because the user once did things differently.
Because existing benchmarks, including system-prompt robustness suites, construct examples
where precedence is knowable, they cannot evaluate environments where precedence is undefined
and fluid [6].
3.5
Integrating the Taxonomy of Knowledge Conflicts
The framing of cross-source contradiction connects to the taxonomy established in the survey
literature on knowledge conflicts for LLMs [8], which divides conflicts into three categories:
• Context-memory conflict: contextual knowledge in the prompt contradicts the model’s
parametric knowledge.
• Intra-memory conflict: the model’s parametric knowledge yields divergent answers to
identically intended, differently phrased queries.
• Inter-context conflict: pieces of contextual knowledge injected into the prompt contra-
dict each other—noise, outdated retrieved documents, or crafted misinformation.
Epistemic parity between memory and skills is a specialized, structured subset of inter-context
conflict. Prior frameworks such as MemoryAgentBench evaluate conflict resolution within the
memory system itself—for example, reconciling an outdated user fact with an updated one
5


[9]—but none address the cross-source tension between two distinct, equally authoritative in-
frastructural pipelines. Our benchmark targets exactly that gap.

4.1
Factual Conflicts: Temporal Misalignment
Factual conflicts arise from temporal misalignment between a user’s history and the system’s
current architecture. Memory accumulates stale data by design: if an engineer deployed to a
legacy server three months ago, the memory pipeline retains that fact as relevant context for
future deployment queries [4]. Meanwhile, a freshly pushed SKILL.md update reflects the current
supply chain and mandates the new V2 architecture. Resolving a factual conflict means deciding
whether to trust the historical precedent localized to this user or the globally injected opera-
tional standard—whether the agent is backward-compatible with habit or forward-compliant
with architecture.
6


4.2
Format Conflicts: The Presentation Layer
Format conflicts appear in the presentation and structure of the agent’s output. They look
less severe than factual errors but can break downstream automation: agentic workflows often
rely on strict structured outputs, such as JSON schemas, to pass data between sub-agents and
scripts [11]. If a skill dictates a verifiable JSON payload but the model reshapes it to match
a memorized preference for conversational bullet points, the processing pipeline throws parsing
exceptions.
4.3
Procedural Conflicts: Execution Pathways
Skills exist to encapsulate procedures for reliable long-horizon execution. Human operators, how-
ever, develop custom heuristics, undocumented workarounds, and specific execution sequences
that get etched into episodic memory through interaction history. Procedural conflicts test which
pathway the model takes: the standard multi-step workflow in SKILL.md, or the idiosyncratic
shortcut in the memory snippet. The resolution reveals the agent’s balance between procedural
compliance and operational adaptability.
4.4
Permission Conflicts: The Safety Imperative
Permission conflicts are the most safety-sensitive typology: one source explicitly authorizes or
mandates an action while the peer source explicitly forbids it. For LLMs acting as the core logic
engine of an agentic operating system [3], permissions define the boundary of autonomous exe-
cution. If a user sets a memory boundary—“never email external clients after 5:00 PM under any
circumstances”—while a customer-service skill mandates immediate responses to high-priority
tickets at any hour, the agent faces a genuine safety dilemma. The resolution of permission
conflicts determines who ultimately holds the reins of the deployed system: the human user or
the enterprise developer.
5
Benchmark Design and Experimental Setup
The benchmark isolates the single data point of conflict resolution across a permutation matrix,
producing a behavioral map of resolution bias rather than a capability score.
5.1
The Tripartite Anatomy of an Isolated Test Case
Every test case follows a standardized tripartite structure (Figure 1), ensuring both sources are
injected with identical contextual weight and eliminating confounds from prompt formatting or
structural emphasis.
1. The memory context injection: a synthesized memory snippet, formatted as the out-
put of a standard retrieval pipeline such as Mem0 or MemGPT [3, 4]. This represents the
localized truth.
2. The skill context injection: a synthesized procedural block, formatted as an Anthropic-
style SKILL.md excerpt defining the operational policy [5]. This represents the systemic
truth.
3. The ambiguous user task: a generalized, context-free prompt that triggers the agentic
loop without biasing either source (e.g., “Initiate the deployment process,” “Handle the
cache”).
Both blocks are wrapped in matched delimiters (<user_memory> and <skill source="SKILL.md">)

5.2
Scenario Suite
The suite comprises 52 scenarios, 13 per typology, spanning software engineering, data, and
customer-support domains. Each was authored to satisfy four constraints: exactly one conflict;
both sources independently plausible as real operational statements; a task phrased so it does
not lexically favor either source; and a resolution observable by a deterministic checker. The
suite was authored by the present author and reviewed case by case against these criteria; it
has not yet undergone independent multi-annotator validation, which we flag as a limitation
(Section 8).
5.3
Conditions and Repeats
Each scenario runs under three context conditions:
• Baseline: [Skill] →[Memory] →[Task].
• Swapped: [Memory] →[Skill] →[Task]. Isolates positional bias—primacy versus recency
effects that are well documented in long-context models [13, 8]—from genuine semantic
resolution. A positionally invariant system should show no shift.
8


• Directive: baseline ordering plus an explicit meta-rule prepended to the system context:
“CRITICAL DIRECTIVE: In the event of any contradiction, discrepancy, or
conflict between stored User Memory and operational Skill documentation, the
Skill documentation MUST take absolute and total precedence.”
A fully compliant model should register a 100% Skill win rate in every cell; any residual
Memory win is a hierarchy-compliance failure of the kind ManyIH-Bench documents at
scale [2].
Every scenario–condition pair is executed three times to separate stable bias from sampling
noise; cell rates are reported with 95% Wilson score intervals. Decoding uses each provider’s
default sampling settings, unmodified, so that measured behavior reflects the configuration a
practitioner would encounter out of the box.

Disclosure classification.
Disclosure behavior—whether the model told the user a contra-
diction existed—is a property of free text and is the one place a judge model is used. Each final
response is classified as Explicit Exception (halted and asked the user to resolve the conflict),
Verbalized Adjudication (executed and named the contradiction or justified the choice), or
Silent Adjudication (executed as if no conflict existed), per Table 6. In this pilot the classi-
fication is performed by a transparent lexical rule rather than a judge model: a response is an
Explicit Exception if it requests confirmation and no tool was called, Verbalized if it names the
contradiction or justifies the choice, and Silent otherwise. Using a rule rather than a model keeps
the labels auditable and removes judge bias entirely, at the cost of recall on paraphrases that
avoid the trigger vocabulary; the resulting silent-adjudication figures are therefore conservative
9


lower bounds. Replacing the rule with a judge model held outside the evaluated pool, validated
against human labels on a sample, is left to future work.
5.5
Models
The pilot evaluates three open-weight instruction-tuned models served through a single provider
(Groq): Llama-3.3-70B, Llama-3.1-8B, and GPT-OSS-20B. The set is chosen to vary two
factors while holding the serving stack fixed: scale within a family (70B vs. 8B, same lineage)
and alignment lineage across families (Llama vs. GPT-OSS at comparable capability). Frontier
proprietary models are left to future work; the harness targets any OpenAI-compatible endpoint,
so extending the matrix requires no code changes.
Of 1,404 planned runs (52 scenarios × 3 repeats × 3 conditions × 3 models), 1,383 completed.
The 21 missing runs (1.5%) are cases where a model emitted a malformed function call that the
provider rejected on all retry attempts, concentrated in the 8B model; they are dropped rather
than imputed.

Reproducibility

6.1
Baseline Adjudication Heatmap
Figure 2 (top panel) shows the baseline map. Three observations stand out.
First, there is no universal winner. Skill win rates in the baseline condition span 28%
to 97%, and every model has at least one typology where the Memory source prevails.
A
practitioner cannot predict resolution from the model alone, nor from the conflict type alone.
Second, format conflicts behave differently from the rest. Both Llama models resolve
format conflicts toward Memory (32% and 39% Skill) while resolving factual, procedural, and
permission conflicts toward Skill. The agents follow the developer’s procedure but present the
result in the user’s preferred style—a pattern consistent with alignment that treats output style
as a user-owned property and task execution as a policy-owned one.
Third, and most striking, permission conflicts split the models apart. GPT-OSS-20B
resolves permission conflicts toward Memory in 72% of runs (28% Skill, 95% CI [17, 44]): faced
with a skill mandating an irreversible action that user memory forbids, it usually declines to
act. Llama-3.3-70B does the opposite in 97% of runs [87, 100]. The same conflicts, the same
prompts, opposite defaults. This is the single largest cross-model divergence in the study, and
it falls precisely on the typology where the cost of a wrong resolution is highest.

6.3
Experiment B: Efficacy of an Explicit Precedence Directive
Adding “the Skill documentation MUST take absolute and total precedence” to the top of the
system context produces the bottom panel of Figure 2. A fully compliant model would show
100% in all twelve cells.
The directive works, but only where the model is already strong. GPT-OSS reaches
100%, 97%, 100% on factual, format, and procedural. Llama-70B rises on every typology, most
dramatically on format (32% →83%; intervals [20, 49] and [67, 92] do not overlap). For these
two models the directive is a real, measurable control surface.
On the smallest model it is not.
Llama-3.1-8B falls on factual (52% →41%) and
procedural (48% →36%) under an instruction that should have raised both. Both shifts have
overlapping intervals and we do not claim the directive actively reverses behavior; what the data
do establish is that on this model the directive fails to produce compliance at all, leaving 59%
and 64% of runs resolved against an explicit, maximally privileged rule. The same directive
does move its format (39% →65%) and permission (77% →92%) cells upward, so the failure is
typology-specific rather than a blanket inability to follow the instruction.
Residual non-compliance never reaches zero. Even GPT-OSS, the most compliant
model, resolves 10% of permission conflicts against the directive; Llama-70B retains 13% on
factual and 17% on format. An explicit hierarchy declared in the system prompt is therefore
a bias, not a guarantee—the same conclusion ManyIH-Bench reaches at much larger scale for
multi-tier privilege [2], reproduced here in the two-source parity setting.
A safety-relevant side effect.
The most consequential single movement in the study
is GPT-OSS on permission conflicts: 28% →90%, intervals [17, 44] and [76, 96], no over-
lap. In the baseline this model usually refused to take an irreversible action that user memory
forbade—deleting accounts, migrating databases, emailing external clients outside stated hours.
One sentence of generic precedence language, containing no reference to safety, permissions, or
irreversibility, converted that refusal into compliance in the great majority of runs. A direc-
tive written by an integrator to resolve mundane configuration conflicts silently dismantled a
user-facing safety boundary. We return to this in Section 7.1.
6.4
Experiment C: Disclosure Behavior
The disclosure results are the starkest in the study.
Acting agents are almost entirely mute. Across the 887 runs in which a model resolved
the conflict by calling a tool, 876—98.8%—emitted no accompanying text whatsoever (Table 5).
The rate is 100% for GPT-OSS in all three conditions, 97–100% for Llama-70B, and 96–99% for
12


Llama-8B. This is not a model choosing to withhold an explanation; it is a response format in
which explanation has no place. The tool call is the entire output. Disclosure is not merely rare
here—it is structurally unavailable.
Even when text is produced, most of it says nothing about the conflict. Of the
506 runs that emitted any text, 354 (70%) named neither the contradiction nor the overridden
source. Taken over all 1,383 runs, 5.1% verbalized the conflict, 5.9% halted to ask, and 89.0%
disclosed nothing.
One model does raise exceptions, and the directive suppresses them. GPT-OSS
accounts for nearly all Explicit Exceptions: 31 of 79 text-bearing runs in the baseline and 37
of 87 when swapped. Under the directive that share falls to 11 of 53. The instruction intended
to resolve conflicts also reduced the frequency with which the agent surfaced them—the same
intervention that raised compliance lowered observability.

6.5
Summary of Findings
1. No default precedence exists empirically. Baseline Skill win rates range from 28%
to 97%; each model resolves at least one typology toward Memory. Resolution is a joint
function of model and conflict type, not a property of either.
2. Adjudication is partly positional. All six factual and procedural cells shift toward
whichever source sits nearer the user task (p = 0.031), while format conflicts shift the
opposite way. Agents are not positionally invariant on the conflicts that cause side effects.
13


3. Explicit precedence is a bias, not a guarantee.
The directive raises compliance
substantially on the two stronger models but leaves 3–10% residual non-compliance, and
produces no compliance at all on the 8B model’s factual and procedural conflicts (59–64%
resolved against the rule).
4. Generic precedence language can override a safety disposition. GPT-OSS moved
from refusing forbidden irreversible actions in 72% of permission conflicts to performing
them in 90%, on the strength of one sentence that never mentions safety.
5. Silent adjudication is the default, not a failure mode. 98.8% of tool-call resolutions
carried no text; 89% of all runs disclosed nothing. Any architecture that relies on the model
to report contradictions is relying on behavior that occurs roughly one time in twenty.
7
Discussion
7.1
Descriptive Measurement, Normative Reading
Two claims in this paper could be mistaken for one, so we separate them explicitly.
The measurement is descriptive. The benchmark records which source an execution followed
and never scores a run as correct or incorrect. This is deliberate: under parity there is no ground
truth to score against, and a benchmark that encoded one would measure agreement with our
preference rather than the model’s bias.
The reading of two results is normative, and we mark it as such rather than smuggling it
in. First, on disclosure: given an unresolvable contradiction, we hold that surfacing it beats
resolving it invisibly, because silent adjudication removes the user’s ability to detect and correct
the outcome. This is a claim about observability, and it applies whichever source wins. Second,
on permission conflicts specifically: where one source forbids an irreversible action—sending
external mail, migrating a database, deleting records—and the peer source mandates it, we
take the restrictive instruction to be the safer default, on standard asymmetry-of-harm grounds.
Deferring an action is recoverable; taking it often is not.
These normative positions do not enter the scoring. Permission cells are reported as Skill/Memory
win rates like every other typology; a reader who rejects our safety asymmetry can read the same
numbers under a different interpretation. What the descriptive/normative separation buys is
that Section 6 remains usable to someone who disagrees with Section 7.1.
The GPT-OSS permission result (Section 6.3) shows why the separation matters in practice
rather than only in principle. Descriptively, the directive did exactly what it said: it raised
the Skill win rate from 28% to 90%. Whether that is an improvement or a regression is not
a fact about the measurement—it depends entirely on whether one reads the user’s standing
prohibition on irreversible actions as a constraint the system should preserve. We think it is,
and so we read a 62-point movement produced by generic precedence language as a warning
rather than a success. But the number is the same either way, and an integrator who disagrees
can act on the same table.
7.2
Architectural Implications
As enterprises integrate memory pipelines capable of perpetual contextual extraction [4] along-
side growing libraries of distributed agentic skills, the surface area for epistemic parity conflicts
will expand accordingly. The benchmark is designed to make that risk measurable before it
materializes in production.
Why would a capable model adjudicate arbitrarily?
A plausible mechanistic hypothesis:
when attention distributes across two contradictory spans of comparable salience, the output
distribution reflects a superposition of both continuations, and small variations in the continuous
14


representation space tip the discrete decision. The parameters carry no programmatic notion of
“memory” versus “skill” beyond their surface text, so the resolution can be arbitrary rather than
deduced. Experiment A tests one observable consequence: if resolution follows token placement
rather than source semantics, arbitrariness—not reasoning—is doing the work.
Experiment A returns a partial verdict on this account. Placement does move resolution
for factual and procedural conflicts, in a consistent direction across all three models, which is
what the hypothesis predicts. But it moves format conflicts the other way and leaves strong
permission priors untouched, which the hypothesis does not predict. A purely mechanical super-
position story cannot explain a typology-dependent sign; something about how these conflicts
are represented differs by category.
Whatever the mechanism, the design implication is the
same: guaranteeing predictable execution by assigning role labels (System > User > Tool) is
inadequate for dynamic agentic settings [2]. Systems should implement discrete checkpoints—
instruction identification, conflict detection, precedence calculation, and response realization
[6]—rather than treating instruction-following as an opaque end-to-end property of the final re-
sponse. For sources in epistemic parity, precedence cannot be hardcoded; it must be negotiated
from temporal relevance, task domain, and explicit risk weighting.
Silent adjudication further exposes a gap in agentic observability, and the measured rate
makes the gap concrete: in 98.8% of tool-call resolutions there was no text channel in which
a contradiction could have been reported, whatever the model’s disposition. Any design that
assumes an agent will flag a conflict it encountered is assuming a behavior observed in roughly
one run in twenty. If models cannot be trusted to self-report contradictions, the orchestrating
architecture must intervene: external watchdog models or deterministic pre-flight conflict check-
ers that analyze semantic overlap between the retrieved memory set and the loaded skill set
before injection into the primary context window. Detecting collisions prior to inference lets the
architecture prompt the user for clarification, short-circuiting the model’s tendency to fabricate
a resolution.

8
Limitations
Several design choices bound what this study can support. Both context sources are synthesized:
memory snippets and SKILL.md excerpts are constructed to conflict crisply, whereas real memory
stores are noisier, real skill files longer, and real conflicts often partial or implicit. The setup
is also single-shot—one memory block, one skill block, one task—while real memory conflicts
accumulate across turns, and a conflict surfaced in turn three may be resolved differently than
the same conflict presented cold.
The scenario suite is 52 cases, English-only, skewed toward enterprise operations, and strictly
pairwise: one memory statement against one skill statement. It was authored and reviewed by
a single person; independent multi-annotator validation with reported agreement is the most
important missing piece of methodological support, and we intend it before any expansion of
the suite. Real contexts can also host n-way conflicts across more than two sources, which this
design does not reach.
The model pool is three open-weight models on one provider. This holds the serving stack
constant, which is what makes the cross-model comparison clean, but it means the findings
characterize open-weight instruction-tuned models rather than frontier systems; proprietary
models may resolve differently, and no claim here should be read as covering them. Decoding
used provider defaults rather than a fixed temperature, so the three repeats capture default-
configuration variability rather than a controlled sampling distribution.
Format conflicts are operationalized as verifiable proxies—length thresholds and schema
validity—which removes judge bias from the winner decision but narrows the construct: genuine
stylistic conflicts over tone or register are not measured, and the positional reversal we observe for
format may be specific to these proxies. Disclosure classification uses a lexical rule, so responses
that acknowledge a contradiction without the trigger vocabulary are counted as silent; the 89%
figure is therefore a conservative lower bound on disclosure and an upper bound on silence.
Finally, 21 of 1,404 planned runs (1.5%) failed on malformed function calls and are dropped,
and checker-undecided runs are excluded from win-rate denominators; cells with high undecided
counts, notably GPT-OSS procedural (6–8 per cell), should be read as weaker evidence.
9
Conclusion
Memory pipelines and procedural skills are converging in production agents, and with them a
class of conflicts that no instruction hierarchy resolves: two legitimate, equally privileged sources
issuing mutually exclusive directives. We named this condition epistemic parity, built a bench-
mark that isolates it—a four-way conflict taxonomy, 52 scenarios under a tripartite anatomy,
deterministic checkers over tool-call payloads and output structure—and ran 1,383 scored runs
across three open-weight models under three context conditions. No default precedence emerged:
Skill win rates spanned 28% to 97%, and adjudication proved partly positional, shifting with
injection order in every factual and procedural cell.
An explicit precedence directive raised
compliance on the stronger models but never eliminated non-compliance, and on one model con-
verted a standing refusal to take irreversible forbidden actions into 90% compliance. Above all,
agents resolved these conflicts without telling anyone: 98.8% of tool-call resolutions carried no
accompanying text, and 89% of all runs disclosed nothing at all. The architectural implication is
that agents need conflict detection and negotiated precedence as first-class mechanisms, because
under epistemic parity there is no hierarchy left to enforce.
