## 摘要
生产环境中的LLM智能体越来越多地并行运行情景记忆流水线与程序性技能模块（如SKILL.md文件）。二者被注入同一上下文区域，且没有定义优先级，因此可能发出相互矛盾的指令，而任何指令层级都无法消解这些矛盾；我们将这一情形称为认知对等。我们提出一个基准，用于衡量LLM智能体如何裁决此类跨源冲突。我们（i）构建了记忆—技能矛盾的四类分类体系（事实、格式、程序、权限）；（ii）按照由三部分构成的测试用例结构（记忆注入、技能注入、模糊用户任务）实例化52个场景，评分几乎完全由针对工具调用载荷和输出结构的确定性检查器完成；（iii）在三种上下文条件下运行每个场景，以隔离位置偏差、衡量显式优先级指令的有效性，并对披露行为进行分类，同时量化“静默裁决”：即在未告知用户的情况下解决冲突。在三个开放权重模型上的1,383次运行中，没有任何一方来源一致胜出：冲突消解共同取决于冲突类型、模型和注入顺序。将技能块移近任务，会在全部六个事实与程序单元中提高其胜率（符号检验，p = 0.031），但在格式冲突中发生反转，表明裁决追随的是token位置而非来源语义。显式的“技能具有绝对优先级”指令提高了两个较强模型对技能的遵从度，但仍留有3–10%的残余不遵从，并使最小模型在事实与程序冲突上的消解朝错误方向移动。最具影响的是，在智能体通过工具调用采取行动的运行中，有98.8%完全未输出伴随文本；在所有运行中，89%未披露任何有关矛盾的信息：静默裁决是默认行为。代码、场景和原始输出均已公开。

## Abstract
Production LLM agents increasingly run episodic memory pipelines and procedural skill modules (e.g., SKILL.md files) in tandem. Both are injected into the same context region with no defined precedence, so they can issue contradictory instructions that no instruction hierarchy resolves, a condition we term epistemic parity. We introduce a benchmark for measuring how LLM agents adjudicate such cross-source conflicts. We (i) develop a four-way taxonomy of memory-skill contradictions (factual, format, procedural, permission); (ii) instantiate 52 scenarios under a tripartite test-case anatomy (memory injection, skill injection, ambiguous user task), scored almost entirely by deterministic checkers over tool-call payloads and output structure; and (iii) run each scenario under three context conditions to isolate positional bias, measure the efficacy of an explicit precedence directive, and classify disclosure behavior, quantifying silent adjudication: resolving a conflict without telling the user. Across 1,383 runs on three open-weight models, neither source wins uniformly: resolution depends jointly on conflict type, model, and injection order. Moving the skill block nearer the task raises its win rate in all six factual and procedural cells (sign test, p = 0.031) but reverses for format conflicts, indicating that adjudication tracks token placement rather than source semantics. An explicit "skill takes absolute precedence" directive raises skill compliance on the two stronger models yet leaves 3-10% residual non-compliance, and moves the smallest model's factual and procedural resolution in the wrong direction. Most consequentially, in 98.8% of runs where the agent acted through a tool call it emitted no accompanying text at all, and 89% of all runs disclosed nothing about the contradiction: silent adjudication is the default. Code, scenarios, and raw outputs are public.

# 论文结构化总结

## 一、核心问题与研究动机

- **背景**：生产级 LLM 智能体日益并行运行两套上下文供给系统——**情景记忆流水线**（如 Mem0/MemGPT 式检索，注入用户历史偏好与状态）与**程序性技能模块**（如 SKILL.md，注入开发者定义的标准操作流程）。
- **问题**：两者被注入**同一上下文区域**，且不存在任何预定义优先级；它们可能发出**相互矛盾但各自合法**的指令，任何指令层级（Instruction Hierarchy）都无法消解。
- **核心概念**：作者将这种"两个同等权威来源之间的无优先级冲突"命名为 **Epistemic Parity（认知对等）**。注意作者也承认，对格式/程序/权限这类"义务性"冲突，更准确的叫法应是"权威对等"。
- **与既有工作的区别**：
  - Instruction Hierarchy / ManyIH-Bench 假设层级**可被定义并强制执行**；
  - τ-bench 中策略**天然权威**，偏离即错误，有明确目标态可评分；
  - MemoryAgentBench 只处理记忆系统**内部**的新旧事实调和；
  - 本文场景中**没有正确答案**，衡量的是**裁决偏差**而非准确率。
- **整体含义**：当技能永远压过记忆，智能体变得僵化官僚；当记忆永远压过技能，则可能违反合规、破坏生产部署。二者都产生明显缺陷的智能体，因此优先级本身在规范上并不显然，模型的实际裁决行为值得实证测量。

## 二、方法论

### 核心思想
构建一个**隔离单点冲突**的基准：每个场景只含一个矛盾，两个来源以**同等上下文权重**注入，通过**确定性检查器**观察智能体执行时跟随了哪一方，从而绘制"裁决热力图"（Adjudication Heatmap），而非给出能力分数。

### 冲突分类体系（四类）
| 类型 | 定义 | 系统性张力 |
|---|---|---|
| **事实（Factual）** | 硬性操作数据、API 端点、环境状态 | 陈旧/定制的历史数据 vs. 更新/标准化的全局数据 |
| **格式（Format）** | 输出风格、结构、详细程度 | 用户体验/个性化 vs. 系统可审计性/机器可读性 |
| **程序（Procedural）** | 多阶段任务的步骤顺序与方法 | 习惯性人工启发式 vs. 优化的自动化 SOP |
| **权限（Permission）** | 操作授权、硬性禁止 | 用户安全边界 vs. 开发者自主性授权 |

### 三部分测试用例结构
1. **记忆注入**：Mem0/MemGPT 风格的合成记忆片段（局部真理）；
2. **技能注入**：Anthropic 风格 SKILL.md 片段（系统真理）；
3. **模糊用户任务**：不含偏向性的通用指令（如"启动部署流程"）。

两个块用**匹配的分隔符**（`<user_memory>` 与 `<skill source="SKILL.md">`）包裹，长度与具体程度相当，避免格式偏袒；每个场景只暴露**一个工具**（如 `deploy(endpoint)`），工具调用载荷即为胜负观测量。

### 三种上下文条件
- **Baseline**：`[Skill] → [Memory] → [Task]`
- **Swapped**：`[Memory] → [Skill] → [Task]`（隔离位置偏差：首因 vs. 近因）
- **Directive**：Baseline + 系统提示前置"技能文档必须绝对且完全优先"的元规则（检验显式优先级的有效性）

每个"场景×条件"执行 **3 次重复**，报告 95% Wilson 置信区间，采用提供商默认采样参数。

### 确定性评分规则
| 类型 | 检查器 | 胜者判定 |
|---|---|---|
| 事实/程序 | 工具调用载荷字符串匹配 | 含技能信号串 ⇒ Skill；含记忆信号串 ⇒ Memory；两者都有或都无 ⇒ undecided（排除出分母） |
| 权限 | 是否调用被禁止但被要求的工具 | 调用 ⇒ Skill；拒绝 ⇒ Memory |
| 格式 | 词数阈值 / JSON schema 有效性 | ≤简洁阈值 ⇒ Memory；≥冗长阈值 ⇒ Skill；解析为规定 JSON ⇒ Skill |

- **披露行为分类**（唯一使用文本判断之处，但用**透明词法规则**而非 LLM 评审）：显式异常（中止并请求澄清）、言语化裁决（执行并说明矛盾）、静默裁决（当作无冲突执行）。
- 词法规则牺牲了改写句式的召回率，因此 89% 的沉默率是**保守下界**。

## 三、实验设计

- **场景集**：52 个场景（四类各 13 个），覆盖软件工程、数据、客户支持领域；每条满足四约束——恰好一个冲突、双方各自独立可信、任务措辞不偏向任一方、结果可由确定性检查器观测。
- **Benchmark 性质**：这是作者**新建的基准**，而非在既有数据集上评测；对比维度不是"方法 vs. 方法"，而是：
  - 3 个模型之间（Llama-3.1-8B、Llama-3.3-70B、GPT-OSS-20B，均经 Groq 提供）；
  - 3 种上下文条件之间（Baseline / Swapped / Directive）；
  - 4 种冲突类型之间。
- **模型选择逻辑**：固定服务栈，变化两个因素——同族规模（70B vs. 8B）与对齐谱系（Llama vs. GPT-OSS）。
- **运行规模**：计划 52 × 3 重复 × 3 条件 × 3 模型 = **1,404 次**，实际完成 **1,383 次**；缺失 21 次（1.5%）为 8B 模型反复重试仍被拒的畸形函数调用，直接丢弃不插补。
- **可复现性**：场景、harness、检查器、评审提示、原始输出与逐次得分均公开于 GitHub。

## 四、资源与算力

- 论文**未报告任何训练算力**（GPU 型号、数量、训练时长均无），因为本研究**不涉及模型训练**，仅通过 Groq 对三个开源权重模型做**推理调用**。
- 也未说明推理总 token 量、API 成本或单次运行延迟。这一点属于**信息缺失**，读者无法据此估算复现成本。

## 五、实验数量与充分性

- **规模**：1,383 次评分运行；每个"模型×类型×条件"单元最多 39 次尝试（13 场景 × 3 重复），统计上偏小，故使用 Wilson 区间并谨慎解读重叠区间。
- **实验组数**：本质是 **3 模型 × 4 类型 × 3 条件 = 36 个单元格**的主矩阵，外加披露行为的描述性统计（887 次工具调用运行、506 次含文本运行）。
- **充分性评估**：
  - **优点**：三条件设计形成三个诊断探针（位置偏差、显式优先级、披露），事实/程序六单元同向移动的符号检验（p = 0.031）提供了跨模型一致性证据；确定性评分排除了评审偏差。
  - **不足**：
    - 场景由**单一作者**撰写与审核，**未经独立多标注者验证**（作者自认为最重要的方法学缺口）；
    - 仅英文、偏向企业运维、严格两两冲突，未覆盖 n 路冲突；
    - 仅 3 个开源权重模型、单一提供商，**不能外推到前沿闭源模型**；
    - 使用默认解码而非固定温度，3 次重复捕获的是默认配置波动而非受控采样分布；
    - 部分单元 undecided 较多（如 GPT-OSS 程序类 6–8 次/单元），证据强度较弱。
- **公平性**：两来源在格式、长度、分隔符上做了匹配，任务措辞中立，评分规则先于实验确定，整体设计较为客观；但缺乏人工标注验证与多提供商复现，外部效度有限。

## 六、主要结论与发现

1. **不存在经验上的默认优先级**：Baseline 下技能胜率跨度 **28%–97%**，每个模型至少有一类冲突倒向记忆；裁决是"模型 × 冲突类型"的联合函数。
2. **格式冲突行为独特**：两个 Llama 模型在格式上偏向记忆（32%、39% 技能胜率），而在事实/程序/权限上偏向技能——即"按开发者流程执行、按用户偏好呈现"。
3. **权限冲突出现最大跨模型分歧**：GPT-OSS-20B 仅 28% 技能胜率（面对不可逆操作通常拒绝执行），Llama-3.3-70B 达 97%，同一冲突、相反默认。
4. **裁决部分由位置驱动**：技能块移近任务后，全部六个事实/程序单元向技能移动（Llama-8B +17/+28，Llama-70B +9/+7，GPT-OSS +9/+6；符号检验 p = 0.031）；但格式冲突**反向移动**（39%→21%、32%→15%），GPT-OSS 不动。说明裁决追随 token 位置而非来源语义，且方向本身依类型而异。
5. **显式优先级是偏置而非保证**：Directive 使两个较强模型显著提升（GPT-OSS 达 100%/97%/100%；Llama-70B 格式 32%→83%），但**残余不遵从始终存在**（3–10%）；对最小的 Llama-8B 在事实（52%→41%）与程序（48%→36%）上**完全失效**，59%–64% 的运行违背显式最高规则。
6. **通用优先级语言可瓦解安全倾向**：GPT-OSS 权限冲突从 28%→90%（区间不重叠），一句**完全未提及安全、权限或不可逆性**的指令，把原本的用户安全边界消解为顺从。
7. **沉默裁决是默认而非故障模式**：887 次工具调用运行中 **876 次（98.8%）无任何伴随文本**；全部 1,383 次运行中 **89.0% 未披露任何矛盾**，仅 5.1% 言语化、5.9% 中止询问。Directive 还**抑制了异常上报**（GPT-OSS 显式异常从 31/79、37/87 降至 11/53）。

## 七、优点（方法与设计亮点）

- **问题刻画新颖且精准**：将"记忆 vs. 技能"从提示注入/越狱等恶意场景中区分出来，定义为两个**良性、可信、同等合法**数据流的冲突，填补了 inter-context conflict 的一个结构化子类空白。
- **分类体系有解释力**：四类划分各自对应清晰的系统性张力（陈旧 vs. 更新、UX vs. 可审计、习惯 vs. SOP、安全边界 vs. 自主授权），使热力图具备可解释性。
- **实验控制严谨**：三部分结构 + 匹配分隔符 + 中立任务措辞，最大限度消除格式混淆；每个场景仅一个冲突，保证单元格可归因。
- **评分几乎全确定性**：胜负判定不依赖 LLM 评审，避免评审偏差，符合 IFEval "可验证指令"传统并扩展到工具调用参数。
- **三探针设计巧妙**：位置（Swapped）、优先级（Directive）、披露（文本分类）分别对应机制、治理、可观测性三个层面，形成完整诊断链。
- **描述性与规范性明确分离**：作者显式声明测量是描述性的、对披露与权限的解读是规范性的，使持不同安全观的读者仍可复用同一张表。
- **披露统计采取保守口径**：词法规则导致 89% 是披露率下界、沉默率上界，结论方向稳健。
- **完全可复现**：代码、场景、检查器、原始输出全部公开。

## 八、不足与局限

- **构念效度**：记忆片段与 SKILL.md 均为**合成**且冲突"干净锐利"，真实记忆更嘈杂、技能文件更长、冲突常为部分或隐含。
- **单轮设定**：一次记忆块 + 一次技能块 + 一个任务；真实冲突跨轮累积，第三轮浮现的冲突可能与冷启动时裁决不同；也未覆盖两源以上的 n 路冲突。
- **场景规模与代表性**：仅 52 例、纯英文、偏向企业运维；由单一作者撰写审核，**缺乏独立多标注者验证与一致性报告**（作者自认最关键的缺失）。
- **模型覆盖窄**：3 个开源权重模型、单一提供商（Groq），结论不能外推到前沿闭源系统；默认解码未固定温度，重复实验捕获的是配置波动。
- **格式冲突的操作化偏窄**：以长度阈值与 schema 有效性作代理，未测量语气、语域等真正风格冲突；观察到的位置反转可能仅针对这些代理指标。
- **披露分类的召回损失**：词法规则会把"用非触发词承认矛盾"的响应误判为沉默，89% 为保守下界；作者计划未来用池外评审模型并对照人工标签。
- **数据完整性**：1.5%（21 次）运行因畸形函数调用被丢弃；undecided

- **数据完整性**：1.5%（21 次）运行因畸形函数调用被丢弃，且丢弃**并非随机**——全部集中在最小的 Llama-3.1-8B 上，属于与模型能力相关的选择性缺失，可能轻微高估该模型的有效表现；此外，被判为 undecided 的运行被排除出分母，使部分单元格的有效样本量从 39 降至 31–33（如 GPT-OSS 程序类），既拉宽了 Wilson 区间，也使不同单元格之间的分母不一致，跨格比较需谨慎。
- **统计推断偏描述性**：除符号检验（p = 0.031）外，论文主要依赖置信区间是否重叠来做判断，未做多重比较校正，36 个单元格的矩阵中存在相当数量的"边缘显著"陈述，读者不宜将单个单元格的百分比差异当作确证效应。
- **因果归因有限**：Swapped 条件只能证明"位置相关"，无法区分首因/近因、注意力衰减、分隔符语义等具体机制；Directive 条件把"元规则有效性"与"该条规则的具体措辞"混在一起，无法判断换一种表述（如"在安全前提下优先技能"）是否会得到不同结果。
- **缺乏人类基线**：论文没有让人类标注者在同样场景下做裁决，因此"模型的裁决是否合理"缺少参照系；89% 的沉默率究竟偏离人类多少，目前无法量化。
- **规范讨论的边界**：作者对"权限冲突应偏向记忆（安全）""披露应被鼓励"的价值判断是显式声明的，但基准本身不提供规范性评分，读者容易把热力图误读为"能力排名"。

## 九、启示与可延伸的研究议程

- **对系统设计者**：既然裁决随 token 位置与冲突类型漂移，把记忆与技能放在同一上下文区、依赖模型"自行领会"是**不可靠的工程实践**；更稳妥的做法是引入**显式的、结构化的冲突标记与仲裁层**（例如在注入前检测两源矛盾，或为不同来源打上机器可读的权威标签），而非仅靠自然语言元规则。
- **对对齐研究**：第 6 条发现（一句与安全无关的通用优先级语言即可瓦解拒绝行为）提示，**指令遵循能力与安全边界的耦合非常脆弱**，优先级指令实际上是一种"越权许可"；这为提示注入防御提出了一个非恶意但同样有效的攻击面。
- **对可观测性**：98.8% 的工具调用无伴随文本，说明**沉默执行是默认行为**，审计只能依赖外部日志而非模型自述；若要在生产中获得可解释性，需在设计上强制"冲突时必须声明"的输出契约，并配套可验证的检查器。
- **可直接延伸的实验**：(1) 引入多标注者人工裁决作为人类基线并报告一致性；(2) 扩展到 n 路冲突与多轮累积冲突；(3) 在前沿闭源模型与多提供商上复现，检验"模型规模/对齐谱系"的调节效应；(4) 用池外评审模型替代词法规则重测披露率，给出上界；(5) 把格式冲突从长度/schema 代理扩展到语气、语域、术语一致性等更贴近真实风格的维度；(6) 操纵冲突的"锐利度"（从显式矛盾到部分重叠），绘制裁决随矛盾强度的连续曲线。

## 十、总体评价

- **定位**：这是一篇**问题定义型 + 基准构建型**工作，其最大贡献不在于提出新方法，而在于**命名并测量了一个此前被忽视的结构化冲突类别**——两个良性、同等合法、无预定义优先级的上下文来源之间的裁决问题。
- **方法强度**：中上。场景隔离、分隔符匹配、任务中立、确定性检查器、三探针（位置/优先级/披露）设计共同构成了一条较完整的证据链；主要短板是单作者场景集、缺人类基线、模型与语言覆盖窄。
- **结论稳健性**：核心定性结论（不存在经验默认优先级、裁决随位置漂移、显式优先级是偏置而非保证、沉默是默认）由多模型、多类型的同向证据支撑，方向性可信；但**具体百分比的精度有限**，单格数字应视为指示性而非精确估计。
- **适用读者**：做智能体上下文工程、记忆系统、指令层级与提示注入防御的研究者与工程师；对仅关心单模型能力评测的读者，价值主要在方法论示范而非分数。
- **一句话结论**：当记忆与技能被平等地放进同一个上下文窗口时，**谁赢不由"谁更权威"决定，而由模型、冲突类型与 token 位置共同决定**——而模型几乎从不告诉你它做了这个选择。
