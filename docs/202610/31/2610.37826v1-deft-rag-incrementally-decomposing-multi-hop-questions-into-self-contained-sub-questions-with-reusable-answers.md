## 摘要
检索增强生成（RAG）使大型语言模型（LLM）能够通过从大规模语料库中检索相关段落来回答问题。然而，RAG 难以处理多跳问题：这类问题需要通过问题从未提及的中间实体，将分散在多个文档中的事实串联起来。基于图的 RAG 方法仅从问题中提到的实体进行一次检索，因此很少能恢复完整的证据链。迭代式 RAG 方法逐步恢复证据链，但其准确性受限于要求 LLM 执行的众多任务，例如规划子问题、判定子问题之间的依赖关系、在答案到达时重写子问题以及跟踪已知信息。我们提出 DeFT-RAG，一种由三个组件构成的 RAG 框架。首先，DeFT-RAG 根据原始问题以及截至目前已回答的子问题及其答案（问答对，QA pairs），一次生成一个自包含子问题。每个子问题都明确命名其询问的每个实体，从而无需规划、跟踪依赖关系或重写，并使 LLM 一次专注于单个细粒度任务。其次，DeFT-RAG 将剩余的 LLM 工作移至 LLM 之外：对记录已知信息的 QA 表进行基于规则的更新，以及由微调的轻量级决策模型做出是/否决策。第三，DeFT-RAG 缓存问答对，并在后续问题提出语义相同的子问题时复用答案。在 MuSiQue、2WikiMultiHopQA 和 HotpotQA 上，DeFT-RAG 在以 gpt-4o-mini 和 Qwen3.6 为骨干模型时，均在十三个基线方法中取得最佳准确率，同时向 LLM 提供的输入 token 数少于任何其他迭代式方法。在跨 1,000 个 MuSiQue 问题共享 QA 缓存的情况下，23.1% 的子问题由缓存回答，这使 LLM 调用减少 12.9%，且不降低准确率。

## Abstract
Retrieval-augmented generation (RAG) lets a large language model (LLM) answer questions by retrieving relevant passages from a large corpus. However, RAG struggles with multi-hop questions, which require chaining facts spread across several documents through intermediate entities that the question never mentions. Graph-based RAG methods retrieve once from the entities a question names and so rarely recover the full evidence chain. Iterative RAG methods recover it step by step, but their accuracy is limited by the many tasks they ask the LLM to perform, such as planning the sub-questions, deciding their dependencies, rewriting them as answers arrive, and keeping track of what is known. We propose DeFT-RAG, a RAG framework built on three components. First, DeFT-RAG generates one self-contained sub-question at a time from the original question and the sub-questions answered so far with their answers (QA pairs). Each sub-question names every entity it asks about, which removes the need to plan, track dependencies or rewrite, and lets the LLM focus on a single fine-grained task at a time. Second, DeFT-RAG moves the remaining LLM work outside the LLM: rule-based updates to a QA table that keeps track of what is known, and yes/no decisions made by a fine-tuned lightweight decision model. Third, DeFT-RAG caches the QA pairs and reuses an answer when a later question asks a sub-question with the same meaning. On MuSiQue, 2WikiMultiHopQA and HotpotQA, DeFT-RAG achieves the best accuracy among thirteen baselines with both gpt-4o-mini and Qwen3.6 as the backbone, while giving the LLM fewer input tokens than any other iterative method. With a QA cache shared across 1,000 MuSiQue questions, 23.1% of sub-questions are answered from the cache, which reduces LLM calls by 12.9% without lowering accuracy.

## 1. 核心问题与整体含义

- **研究背景**：检索增强生成（RAG）通过检索外部语料提升 LLM 回答知识密集型问题的能力，但在**多跳问答**中表现不佳。多跳问题需要把分散在多个文档中的事实，通过问题中未提及的**桥接实体**串联起来。
- **现有方法的两类不足**：
  - **图式 RAG**：通常只从问题中显式命名的实体出发检索一次，难以沿证据链到达未命名桥接实体。论文指出，多数图式方法在 MuSiQue 3-hop 问题上仅对 6–10% 的问题检索到完整证据链，接近 vanilla RAG 的 7%。
  - **迭代式 RAG**：逐步检索可提高证据链覆盖率，但把规划子问题、判断依赖、按答案重写子问题、跟踪已知信息等多项任务都交给 LLM，容易产生**规划错误、依赖错误、重写错误、跟踪错误**。此外，固定 top-k 检索会放大每一步的错误，且中间答案在问题回答后被丢弃，造成浪费。
- **整体含义**：论文试图把多跳问答中的 LLM 负担拆解为更细粒度、可外部化、可复用的流程：让 LLM 一次只生成一个**自包含子问题**，把状态维护和是/否判断移出 LLM，并缓存复用同义子问题答案，从而同时提升准确率、降低输入 token 和减少重复 LLM 调用。

## 2. 方法论

- **核心思想**：DeFT-RAG 不预先规划整条子问题链，而是根据原问题和当前已获得的问答对（QA pairs），每次只生成一个自包含子问题；该子问题显式命名其询问的实体，不依赖其他子问题答案，因此无需规划、依赖判断或重写。
- **LLM 只承担三类细粒度任务**：
  - `LLM_sub(Q, F_t)`：根据原问题 `Q` 和当前 QA 表 `F_t` 写出下一个自包含子问题。
  - `LLM_ans(q, P)`：根据筛选后的段落 `P` 回答一个子问题。
  - `LLM_fin(Q, F)`：根据最终 QA 表回答原问题。
- **QA 表与规则更新**：
  - QA 表初始为空 `F_0 = ∅`，每得到一个答案就更新：`F_{t+1} = F_t ∪ {(q_{t+1}, a_{t+1})}`。
  - 已答子问题加入表中；无答案子问题被记录并避免重复提问；重复子问题通过归一化措辞检测，并要求 LLM 重新生成。该过程**不调用 LLM 或 DM**，从而避免长上下文中的跟踪错误。
- **轻量决策模型（DM）**：
  - DM 基于 StartLux-Decision-4B（Qwen3.5 架构，4B 参数）微调，用 LoRA 训练，输出 yes/no 概率。
  - 决策形式为 `D(x)=1[p_DM(yes|x)≥τ]`，三类决策包括：
    - **相关性**：判断检索段落是否与问题相关，用于段落筛选；阈值 `τ=0.5`。
    - **直接回答**：判断原问题 top-w 段落是否已包含全部证据；阈值 `τ=0.7`，较严格，避免多跳问题被错误地一步回答。
    - **事实充分性**：判断当前 QA 对是否足以回答原问题；阈值 `τ=0.5`。
  - 段落选择公式可概括为：从 top-w 段落中仅保留 DM 判为相关的段落，使 LLM 看到更多候选但更少干扰。
- **QA 缓存复用**：
  - 由于子问题是自包含的，同一语义的子问题在不同原问题下应有相同答案。
  - 缓存先按忽略大小写和标点的相同措辞查找；若没有，则取最相似的若干已存子问题，由 DM 判断是否同义，阈值 `τ=0.8`。命中则直接复用答案，不检索、不调用 LLM。
- **整体算法流程**：
  1. 对原问题

1. 对原问题 `Q` 先用常规检索取 top-w 段落，用 DM 的“直接回答”判断这些段落是否已足够回答原问题；若足够，则直接调用 `LLM_fin` 给出答案，跳过迭代。
  2. 否则进入迭代：初始 `F_0 = ∅`，由 `LLM_sub(Q, F_t)` 生成下一个自包含子问题 `q_{t+1}`。
  3. 对 `q_{t+1}` 做检索（先用 QA 缓存查找，命中则直接复用答案），对检索到的段落用 DM 做相关性筛选，得到 `P`。
  4. 由 `LLM_ans(q_{t+1}, P)` 得到答案 `a_{t+1}`；若无答案则记录该子问题并避免重复提问。
  5. 更新 `F_{t+1} = F_t ∪ {(q_{t+1}, a_{t+1})}`，并用 DM 的“事实充分性”判断当前 QA 表是否已足以回答 `Q`；若充分则停止迭代。
  6. 最终由 `LLM_fin(Q, F)` 基于完整 QA 表生成原问题答案。
  7. 整个过程中，规划、依赖判断、重写、跟踪均被规则化流程或轻量 DM 替代，LLM 只做“写一个子问题 / 答一个子问题 / 答原问题”三件事。

## 3. 实验与主要结果

- **数据集**：主要在 MuSiQue（2-hop 与 3-hop）、HotpotQA 等多跳 QA 基准上评估；MuSiQue 因构造方式更严格、桥接实体更隐蔽，被作为核心压力测试集。
- **基线**：包括 vanilla RAG、迭代式 RAG（如 IRCoT 类方法）、图式 RAG（如 GraphRAG、RAPTOR 类方法）以及带规划的 agent 式方法。
- **准确率**：DeFT-RAG 在 MuSiQue 3-hop 上相对迭代式与图式基线有明显提升，尤其在需要多步桥接的问题上，证据链完整检索率显著高于“仅从问题实体出发”的图式方法；在 HotpotQA 上与强基线持平或略优。
- **效率**：由于子问题自包含且可缓存，重复/同义子问题不再触发检索与 LLM 调用，论文报告输入 token 数与 LLM 调用次数相比迭代式 RAG 明显下降；轻量 4B DM 承担了大量原本由大模型做的判断，进一步降低成本。
- **消融**：
  - 去掉 DM 的相关性筛选，噪声段落增多，答案准确率下降；
  - 去掉“直接回答”判断，多跳问题容易被一步错答，或迭代轮数无谓增加；
  - 去掉“事实充分性”判断，迭代停止条件失效，轮数与 token 上升；
  - 去掉 QA 缓存，同义子问题重复检索与重复调用 LLM，效率指标恶化而准确率基本不变，说明缓存主要贡献效率而非精度。
- **错误分析**：残余错误主要来自检索未召回关键段落、DM 在边界样本上的误判，以及子问题生成偏离原问题意图；论文指出这些是后续可改进方向。

## 4. 贡献与意义

- **方法贡献**：提出“自包含子问题 + 外部化状态 + 轻量决策模型 + 语义缓存”的组合框架，把多跳 RAG 中容易出错的 LLM 规划/跟踪职责拆解为可规则化、可模型化的细粒度组件。
- **概念贡献**：明确区分了多跳 RAG 中的四类 LLM 错误（规划、依赖、重写、跟踪），并给出针对性的结构性解法，而非仅靠提示工程。
- **实践意义**：在提升多跳准确率的同时降低 token 与调用成本，对实际部署 RAG 系统有直接参考价值；缓存机制使跨问题知识复用成为可能。

## 5. 局限与可讨论之处

- 子问题“自包含”要求显式命名实体，可能在某些开放式问题上不够自然，生成质量仍依赖 LLM。
- DM 为 4B 微调模型，其判断阈值（0.5/0.7/0.8）为经验设定，跨领域迁移时可能需要重新校准。
- 缓存依赖“同义子问题答案相同”的假设，在时效性强或语境敏感的问题上可能引入错误复用。
- 评测集中于英文多跳 QA 基准，中文及多语言场景的适用性尚未验证。
