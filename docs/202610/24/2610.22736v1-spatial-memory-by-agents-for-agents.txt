# Spatial Memory by Agents, for Agents 

Qianwei Wang 2, Ce Zhang 3, Zhanpeng Luo 4, Pengpeng Su 5, Shuo Yang 5, and Hao Xu 1,∗

Abstract — Spatial memory enables robots to reuse past observations for localization, navigation, and question answering. Designing such memory involves jointly deciding what to retain and how to retrieve it for diverse semantic, metric, and temporal needs. We investigate whether coding agents can automate this design process through iterative implementation and evaluation. Under a fixed development budget, a Designer Agent writes and revises code for memory construction and retrieval using feedback from a fixed Query Agent. The resulting implemen-tations are frozen before building memories from held-out observation histories, without access to downstream questions, and evaluated across five complementary task tracks using the same Query Agent. Across three independent design searches, Codex / GPT-6 Astra averages 44.23 on the equally weighted five-track score, versus 29.32 for ReMEmbR, the strongest evaluated baseline supporting all five tracks, a 50.9% relative improvement. Qualitative analysis relates performance differences to evidence retention and retrieval, while identifying grounding and evidence-use failures. These results demonstrate the potential of coding agents to automate spatial memory design, while revealing task-dependent trade-offs in performance and computational cost. Project page: https://ba-fa-3344.github.io/ .

I. I NTRODUCTION 

Spatial memory enables robots to use past observations to answer questions unknown during exploration. After traversing an office, a robot may be asked where a chair is, which cabinet is beside the desk, what the room looks like, or when it last saw an object. These questions require complementary spatial, semantic, and temporal evidence. Deciding what to retain and how to organize it is difficult: a memory supporting one query type may omit information essential to another. Existing systems organize observations differently. Re-MEmbR [1] stores captions with poses and timestamps, ConceptGraphs [2] builds object-centric graphs, DAAAM [3] maintains temporal object/place histories, and FARM [4] retrieves evidence through spatial relations. Perception models, association strategies, embeddings, and retrieval tools create a large, coupled design space: useful retrieval requires both retaining evidence and making it accessible to downstream agents. Repeated implementation, evaluation, and revision make manual development costly.

Coding agents offer a way to explore this space by implementing candidates, running experiments, and revising code in response to failures. Recent work demonstrates these capabilities in agent architectures and ML pipelines [5], [6], and in robotics through trace-guided program repair and real-world policy improvement [7], [8]. This motivates our question (Fig. 1): given reusable components, development feedback, and a fixed budget, how well can a coding agent design spatial memory for another agent across diverse tasks? 

Our workflow separates design , build , and query , with distinct Designer and Query Agent roles. The Designer iteratively develops memory construction and retrieval using public-task feedback. The selected implementation is frozen before building memories from held-out histories without downstream questions. A fixed Query Agent then answers through each system’s retrieval tools, enabling comparison under a common downstream agent. A. Spatial Memory Construction and Retrieval 

Dynamic scene graphs, Kimera, and Hydra organize geometry, objects, places, and temporal structure [9]–[11]; HOV-SG adds open-vocabulary room–floor hierarchies for navigation [12]. Other language-queryable representations include VLMaps’ top-down features [13], CLIP-Fields’ im-plicit fields [14], and OpenScene’s distilled point features [15]. ConceptFusion fuses multimodal features into geometry [16], whereas ConceptGraphs associates objects with descriptions and relations [2]. For downstream reasoning, ReMEmbR retrieves posed, timestamped captions [1]; 3D-Mem selects visual snapshots [17]; DAAAM exposes temporal object/place histories [3]; and FARM performs relational retrieval and visual verifica-tion [4]. Embodied VideoAgent combines appearance, context, geometry, and history [18], while GraphEQA couples scene graphs with task-relevant images [19]. Task-driven representations also have precedents: Clio adjusts map granularity to a supplied task list [20]. We search the implementation during development and freeze it before building on held-out histories. Similarly, VLMaps generates code to consume a map, whereas our Designer implements memory construction and access. Our focus is the selection and coordination of established mechanisms. 

B. Functional Evaluation of Spatial Memory 

Semantic MapNet studies semantic maps and their use in counting and navigation [21], MultiON tests multi-object navigation [22], and EMQA queries spatial and spatiotem-poral information from observed tours [23]. NaVQA and OC-NaVQA are the closest precedents for our protocol. ReMEmbR’s NaVQA formulation separates memory con-struction from spatial, temporal, and descriptive queries [1]. OC-NaVQA annotates actual object positions, uses full observation sequences, and compares memories using the same reasoning LLM [3]. OpenEQA adds open-ended history QA [24], and ScanRefer/ScanEnts3D supply grounded language annotations [25], [26]. We combine these resources with constructed questions into a shared build–package– query evaluation, retaining native OC-NaVQA reporting. The suite tests complementary memory capabilities through development feedback and held-out assessment for coding-agent design. 

C. Coding-Agent-Driven System Design 

ADAS searches code-defined agent architectures [5]; MLE-STAR uses ablation-guided refinement and ensemble search for ML pipelines [6]; and the Darwin Gödel Machine modifies a coding agent’s implementation [27]. MLE-bench evaluates budgeted machine-learning engineering through repeated agent runs [28]. In robotics, ASPIRE repairs robot programs using execution traces and distills reusable skills [7], while ENPIRE develops reset and verification interfaces with human feedback to support policy improvement through real-world trials [8]. Here, coding agents design persistent memory construction and access, evaluated across histories and tasks. III. S PATIAL MEMORY DESIGN WITH CODING AGENTS 

A. Spatial Memory as the Design Target 

Object grounding uses geometry and identity, while tempo-ral recall uses event histories [1]–[3]. These complementary demands motivate jointly designing memory retention and access. Given a posed RGB-D history O = {(It, D t, P t, τ t)},a system s = ( Bs, T s, p s) comprises a builder producing memory Ms = Bs(O), retrieval tools Ts, and tool-use instructions ps. A shared Query Agent answers through these interfaces: a = Aθ0 (q; Ms, T s, p s).The shared pool offers diverse pretrained modules, includ-ing YOLOE [29] for detection, FastSAM for segmentation, OpenCLIP and DINOv3 for visual features, Qwen3.5-4B for captioning, and Qwen3-VL-Embedding-2B for multimodal embeddings. We favor compact modules and a 4B consumer for onboard efficiency; quantized Qwen3.5-4B supports responsive inference on Jetson Orin devices [30]. 

B. Designer Protocol 

Each scratch search starts from an unimplemented builder with shared task instructions, metrics, module pool, and public data. The Designer may inspect public data and prior work and edit the builder, retrieval tools, and tool-use instructions; the evaluator and Query Agent core remain fixed. The loop is implement–evaluate–inspect–keep/revert–revise .Separate H100 workers build candidates and run Qwen3.5-4B evaluation, returning per-track scores, costs, predictions, and query-linked tool traces. The Designer can inspect public reference answers and memory packages, then record keep/revert decisions with rationales. Selection uses only public feedback. The 24-hour budget covers coding, API waiting, building, and evaluation. Configurations share task/evaluation interfaces but retain native harness editing, execution, and context man-agement. M ULTIFACETED EVALUATION 

A. Coverage, Sources, and Split 

Five tracks probe complementary memory requirements: category coverage and geometry (T1), instance discrimination (T2), semantic context (T3), temporal evidence (T4), and navigation-history QA (T5). We combine constructed questions with ScanNet and HM3D inputs [31], [32], ScanRefer expressions and Sca-nEnts3D annotations [25], [26], OpenEQA [24], and OC-NaVQA [3] on CODa [33]. Figure 3 summarizes 10,347 queries over 176 inputs: 167 spatial inputs and nine sequences. Public development contains 1,284 queries; frozen evaluation contains 9,063. Complete scene-scan/episode/trajectory IDs are disjoint across splits, although separate captures may revisit physical regions. T5 includes 177 official frozen ques-tions and 60 constructed, human-reviewed public questions on separate trajectories. 

B. What Each Score Measures 

Scores lie in [0 , 1] ; missing or malformed answers receive zero. a) T1: Category-level metric localization: The system returns instance positions for a category. A prediction at a 3D distance d from a target center receives credit w(d) = max(0 , 1 − d/g ), where g = clip( 12 bbox diagonal , 0.5, 2.0) 

meters. Each query specifies a prediction cap K. After maximum-credit one-to-one matching of only the first K

predictions, let G and P count targets and predictions, 

R = min( G, K ), and C be total credit. The soft F-score is the harmonic mean of C/R and C/ max( P, R ), measuring localization and instance coverage. 

b) T2: Referring-expression localization: Only the top-ranked position receives w(d) against the referred target, measuring instance resolution and localization. 

c) T3: Open-ended spatial QA: A reference-guided Qwen3.5-4B judge assigns a semantic correctness rating 

r ∈ { 1, . . . , 5}, mapped to (r − 1) /4. It uses a separate conversation from the Query Agent, but shares its checkpoint. 

d) T4: Temporal QA: For absolute time error e and observation horizon H in seconds, ℓ(e, H ) = clip(1 −log(1+ 

e)/ log(1 + H), 0, 1) rewards temporal precision relative to history length. For multiple events, the i-th prediction is paired with the i-th reference; scores are averaged over references, with missing events scored zero and extras ignored. 

e) T5: Navigation QA: Recorded-history questions use exact yes/no accuracy, clip(1 − dxy /(100 m) , 0, 1) for hori-zontal position error, or ℓ(e, H ) for time/duration converted to seconds. Original OC-NaVQA errors are also reported separately; this track does not measure active navigation success. 

C. Aggregation and Resource Accounting 

Each track uses a query-micro average; Unified equally averages the five tracks. Unsupported tracks are N/A, with no Unified for partial systems. Formal results use only frozen queries. Resources are reported separately: build time per frame, package size, peak RAM/VRAM, and end-to-end query latency. The shared Query Agent uses temperature zero, disabled thinking, a 2,048-token output limit, and five tool iterations. V. E XPERIMENTS AND ANALYSIS 

A. Setup and Reporting 

Each of four harness–model configurations performs three independent 24-hour searches. Eight H100 GPUs per search parallelize builds and Qwen3.5-4B evaluations for faster feedback. Claude uses Max effort; Codex and DeepSeek use High. Each system builds once per input and serves three query repeats. Scores are scaled by 100. Avg, our primary comparison, reports mean ± sample std across three search means, measuring design-search variability (Table I). Each mean averages three query repeats. Best is the run with the highest public Unified within each configuration. All checkpoint/run selection uses public feedback; frozen evaluation follows. To reduce model-related variation, baselines share the Qwen3.5-4B Query Agent and use common build components where possible. Our ConceptGraphs implementation uses YOLO-World, SAM, and OpenCLIP from the shared pool. ReMEmbR retains caption–pose–time memory, using the same Qwen3.5-4B captioner and Qwen3-VL-Embedding-2B embedder available to the Designers. For the same reason, FARM’s Qwen3.5-9B captioner and query parser are replaced with Qwen3.5-4B; we call this configuration FARM-4B. DAAAM retains its own mapping stack, including FastSAM, DAM, visual/text encoders, and tracking, and serves the shared Query Agent. LLM-with-Captions provides a caption-memory control. ConceptGraphs and FARM-4B are evaluated on their supported T1–T3. 

B. Effectiveness and Cost 

We first compare cross-task memory utility and deployment cost under the shared Query Agent. Broader memory utility across tasks. Codex / GPT-6 Astra averages 44.23 Unified across three searches versus 29.32 for ReMEmbR, the strongest full-track baseline: a 14.91-point (50.9% relative) gain (Table I). The other configuration averages range from 38.77 to 40.66; all 12 systems exceed ReMEmbR on Unified. Astra’s average exceeds DAAAM on all five tracks and FARM-4B on its three supported tracks. On T2, it reaches 37.55 versus 17.97 and 25.77, respectively. Its gains over ReMEmbR concentrate in localization and temporal QA; T3 is nearly tied, and ReMEmbR remains stronger on T5. Opus 5 has higher average T4/T5 scores than Astra, illustrating complementary task profiles. The Astra run selected by public Unified achieves 45.75 frozen Unified; Avg remains the primary across-search comparison. 

Compact memories with different query costs. Agent-designed systems also use compact storage (Table II). Mean package sizes span 4.31–23.94 MiB across configurations, compared with 67.90 for DAAAM and 67.77 for FARM-4B. Mean build TPF is also lower: 0.143–0.347 s/frame versus 0.667/0.425. ReMEmbR remains smaller at 2.07 MiB. Astra averages 23.94 MiB and 25.93 s/query, compared with Opus 5’s 4.31 MiB and 14.74 s/query, despite lower average T4/T5 scores. The workflow finds storage-efficient systems, but query-time reasoning adds a performance–cost trade-off.

G. Simulation Robot Deployment 

The recorded-history results motivate a further question: can the designed memory also guide a robot’s actions? We test navigation and QA in a ProcTHOR house [34] within Isaac Sim (Fig. 5). No Memory, Keyframe RAG, ReMEmbR, and Codex / GPT-6 Astra Best share a Qwen3.5-4B controller and task starts; memories are prebuilt from one robot survey and read-only. No Memory uses only current observations and task-local interaction; Keyframe RAG retrieves sampled survey images by embedding similarity, together with their poses and timestamps. The 40 tasks comprise 20 navigation goals and 20 QA questions covering counting, distance, and support relations. The controller receives live observations, pose, a known collision map, and each system’s native retrieval tools. Navigation succeeds when the robot declares the target found within 1 m with depth-confirmed visibility; QA uses exact integer or choice matching. Table V reports three inference-seed repeats. 

Turning memory into navigation targets. The agent-designed memory achieves 58.3% navigation success versus 10.0% for ReMEmbR. Its object coordinates and crops provide actionable targets: the successful sofa episode in Fig. 5 retrieves sofa/refrigerator candidates, then moves to and faces the selected sofa. ReMEmbR’s caption poses instead locate observations, not objects. Target confirmation remains difficult: in 20 of 25 failed episodes, the robot declares success prematurely; five are near the correct target but fail depth-based visibility. Improving this final stage requires connecting retrieved evidence with the robot’s current view and approach. 

Context and coverage in memory QA. QA is 33.3% versus ReMEmbR’s 36.7%: only two additional correct answers for ReMEmbR across 60 repeated trials. Distance comparisons favor ReMEmbR (9/18 versus 7/18); captions can preserve useful co-occurrence without object coordinates. Both systems struggle with complete, unique counts. For the table-count question in Fig. 5, the agent-designed system answers two instead of one in two repeats; the illustrated repeat inspects context and counts once. Bounded retrieval and instance/context ambiguity can impede enumeration: whole-house QA requires consistent evidence across objects and rooms, beyond a useful navigation target. VI. D ISCUSSION 

Conclusion. Spatial memory benefits from coordinated retention, retrieval, and use. Coding-agent design improves average cross-task utility over established baselines, producing compact memories with complementary localization, temporal reasoning, and navigation strengths. 

Limitations. Complete-system evaluation leaves individual mechanisms less understood; controlled ablations would deepen our qualitative analysis. The onboard-oriented pool and 4B consumer leave stronger cloud-hosted reasoners and hybrid designs largely unexplored. OC-NaVQA’s answerer-dependent results motivate these comparisons and independent T3 judges. Future Work. How should robotics benchmarks evaluate agent-adapted systems? Pairing task metrics with public feedback, held-out environments, explicit budgets, and agent-designed baselines could test new mechanisms, component coordination, and efficiency under changing demands.
