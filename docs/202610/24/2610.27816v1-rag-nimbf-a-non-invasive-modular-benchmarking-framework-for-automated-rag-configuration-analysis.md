## 摘要
检索增强生成（RAG）已成为将大语言模型（LLM）输出基于外部知识的主流范式。然而，从业者面临一个庞大的配置空间，涵盖分块、嵌入、检索、重排序、提示和生成模型，而关于这些组件如何相互作用的指导仍然有限。我们提出 RAG-NIMBF，一个模块化基准测试框架，它作为一种非侵入式评估层附加到现有 RAG 流水线上。该框架通过受控消融实验并结合端到端实验跟踪来评估配置空间。评估结合了基于 LLM 的答案质量评分、检索正确性度量和运行时指标。本研究在 SQuAD 数据集上跨多个生成模型验证了该框架。这一过程揭示了非显而易见的交互作用，并展示了实验如何被跟踪。研究结果表明，与传统的相似度搜索相比，检索在相关性与多样性之间的平衡显著提升了检索上下文的相关性和覆盖度，其中 MMR 在所扫描的模型上将 nDCG@5 提高了 +4 至 +11 个百分点。更详细的提示指令能够显著提高生成答案对检索证据的忠实程度，尤其是对于能力较强和推理型模型（在 Qwen3.6-27B、GPT-4o-mini 和 Qwen3.5-think 上提高 +10 至 +13 个百分点，但在 20B 生成器上可忽略不计）。总体而言，RAG-NIMBF 将 RAG 的配置空间转化为可复现、可比较的实验。通过以非侵入方式附加到现有生产流水线，它使从业者能够在不干扰现有工作流的情况下系统评估和改进已部署系统。这将临时性选择转变为基于证据的决策。

## Abstract
Retrieval-Augmented Generation (RAG) has become the dominant paradigm for grounding the outputs of large language models (LLM) in external knowledge. However, practitioners are faced with a vast configuration space comprising chunking, embedding, retrieval, reranking, prompting and generation models, and there is limited guidance on how these components interact. We present RAG-NIMBF, a modular benchmarking framework that attaches to existing RAG pipelines as a non-invasive evaluation layer. It evaluates the configuration space through controlled ablation with end-to-end experiment tracking. The evaluation combines LLM-based answer quality scores, retrieval correctness measures, and runtime indicators. This study validates the framework across multiple generation models on the SQuAD dataset. This process reveals non-obvious interactions and demonstrates how the experiments are tracked. The findings indicate that the retrieval balance of relevance and diversity substantially enhances the relevance and coverage of retrieved context in comparison to a conventional similarity search, with MMR raising nDCG@5 by +4 to +11 percentage points across the swept models. More detailed prompt instructions meaningfully increase how faithfully generated answers stick to the retrieved evidence, especially for capable and reasoning models (+10 to +13pp on Qwen3.6-27B, GPT-4o-mini and Qwen3.5-think, but negligible on the 20B generator). Overall, RAG-NIMBF transforms the configuration space of RAG into reproducible, comparable experiments. By attaching to existing production pipelines in a non-invasive way, it enables practitioners to systematically evaluate and improve deployed systems without disrupting existing workflows. This replaces ad hoc choices with evidence-based decisions.

- **核心问题**：每个环节都有多种设计选择，组合后形成庞大的配置空间；而现有研究与工具**缺乏关于组件之间如何交互的系统性指导**。文献指出，仅改变 chunk size、检索策略或提示措辞，就可能使忠实度（faithfulness）波动 10 个百分点以上。

  - 从业者多凭直觉、厂商宣传或社区默认值选型，而非基于自有数据做系统评估，且默认值对语料与模型高度敏感。
  - 中小组织通常只能在消费级/单卡硬件上部署 RAG，缺乏专用 GPU 集群，现有基准结果对其参考价值有限。
- **现有工作的空白**：
  - RAGAS、ARES、RAGChecker 等侧重**给单条流水线打分**，而非把"配置本身"作为研究对象，不做笛卡尔扫描、组件交互分析与可复现追踪。
  - LangSmith、Langfuse 提供追踪与成本遥测，但不做配置空间扫描。

  - 上述工具**均无法以非侵入方式挂接到既有 RAG 流水线**上。
- **整体含义**：论文主张把"RAG 配置空间"本身作为评测对象，用可复现、可比较的实验取代临时性（ad hoc）决策。

## 2. 方法论

### 2.1 核心思想（三条设计原则）

1. **非侵入式集成**：通过 `provider:name` 形式的模型标识符与 provider 路由（Ollama、OpenAI 兼容端点如 vLLM/TGI）接入既有组件，不修改模型或检索器内部；每个角色（生成 LLM、评判 LLM、嵌入）可单独配置 base URL。
2. **系统性配置探索**：用声明式环境配置文件给出各参数的可选值列表，框架计算**笛卡尔积**并逐一基准测试。作者明确选择穷举扫描而非贝叶斯优化/随机搜索，理由是后两者只给出最优点、无法观测**交互效应曲面**。
3. **混合评估**：RAGAS 质量指标、IR 检索指标、NLG 表面指标、运行时指标联合记录到 MLflow，避免单一分数被单独优化（"刷分"）。

### 2.2 流水线六阶段

配置 → 数据加载 → 分块 → 检索/索引 → 生成 → 评估，每阶段为独立模块；中间产物（chunks、向量索引、检索上下文）按内容指纹缓存复用。

- **数据加载**：注册表式适配器模式，把 HuggingFace 数据集统一为 `{question, ground_truth, context}`；内置 SQuAD、RagBench、T2-RagBench、Ragas-WikiQA、RagPerf-Wikipedia-NQ。
- **分块**：基于 LangChain 文本分割器实现三种策略——递归分割（默认）、固定长度（token/字符窗口+重叠）、语义分割（按嵌入相似度断点；此时 chunk size/overlap 参数被忽略）。句级、Markdown 感知、late chunking 因噪声方差大、语料无标记、长上下文算力开销被排除。
- **检索与索引**：向量库选用 ChromaDB 与 LanceDB（理由是本地持久化、低运维成本、规模足够）；检索支持相似度 top-k 与 **MMR**（可调 λ 平衡相关性与多样性），可选 HyDE 与 cross-encoder 重排；稀疏/混合检索（BM25、稠密+稀疏融合）明确不在范围内。
- **生成与路由**：按模型前缀路由请求，统一响应格式以兼容 RAGAS；对推理模型**剥离 `<think>` 思维链痕迹**后再评分，使忠实度反映最终答案而非中间推理，保证推理型与非推理型模型在同一协议下可比。
- **评估与追踪**：所有参数、指标、产物与追踪记录自动写入 MLflow，并附完整环境状态的"可复现性包"。

### 2.3 四层指标体系（表 1）

| 层 | 指标 | 含义 |
|---|---|---|
| RAGAS（由独立 critic LLM 计算） | Faithfulness | 答案中原子断言被检索上下文蕴含的比例 |
| | Context recall | 参考答案可归因于上下文的比例 |
| | Semantic similarity | 答案与参考答案嵌入的余弦相似度 |
| IR（对 SQuAD 金标段落，与 critic 无关） | Hit@k、Recall@k、nDCG@k | 检索集与金标集的命中/召回/折损累积增益 |
| NLG（对参考答案的表面重合） | BERTScore-F1、METEOR、ROUGE-L、BLEU | 词面/语义相似 |
| Runtime（直接取自推理服务器） | TTFT、TPS | 首 token 时延、每秒 token 数 |

- 关键设计：IR 层与生成器无关（固定嵌入与检索配置时为纯函数），因此可单独报告；RAGAS 由固定的强 critic 模型（Qwen3.5-397B-A17B，非思考模式，H100 集群）统一评判，避免"生成器弱 + 评判器弱"的混淆。

## 3. 实验设计

- **数据集**：SQuAD（100 题样本）。选择理由是抽取式 QA、有金标段落监督（可算 IR 指标）、参考答案短、公开易复现。
- **固定项**：嵌入模型固定为 `nomic-embed-text`（768 维），以隔离分块/检索/提示/生成器的影响；retrieval top-k = 12；重排器与 HyDE 关闭；critic 为 Qwen3.5-397B-A17B（不参与生成扫描）。
- **生成模型（6 个，表 2）**：Qwen3-32B-AWQ（32B dense，工作站）、GPT-OSS-20B（20B MoE/3.6B 激活，DGX Spark GB10）、Qwen3.5-35B-A3B（35B/3B 激活，GPU 集群）、Qwen3.6-27B-NVFP4（27B dense，工作站）、GPT-4o-mini（云端 API 参考）、DeepSeek-V4-Pro（862B，API，仅支持相似度检索，故只出现在对应子集）。整体取向是"消费级/单加速器可部署"为主，云 API 作为上界参考。
- **配置空间（表 3）**：模型 6 × 分块策略 2 × chunk size 2（500/1000）× overlap 2（100/200）× 检索 2（相似度/MMR）× 提示模板 2 = **192 组全网格**；但论文明确只实例化了其中一个**刻意缩小的子集**，定位为"受控消融"而非全选项基准。
- **两种提示模板（图 2）**：
  - *Concise*：仅用上下文、单句、直接、事实性、无推理无 markdown、含少样本示例、缺失时固定拒答句。
  - *Detailed*：去除示例，要求完整句子、清晰完整的答案、必要时给出计算或推理、不得以"Based on the provided context"开头。
- **对比方式**：并非与外部方法横向对比，而是**框架内部跨配置对比**（相似度 vs MMR、Concise vs Detailed、不同 chunk size/overlap、不同生成器），并报告运行时与质量的权衡。
- **统计处理**：所有指标为 100 题均值；保留逐题值用于 bootstrap（2000 次重采样，95% CI）与显著性分析；报告 faithfulness 排名稳健性约 ±0.01。

## 6. 主要结论与发现

- **RQ1 生成器比较**：GPT-4o-mini、Qwen3.6-27B、Qwen3.5-think 的平均忠实度并列领先（0.89/0.89/0.88），Qwen3-32B 0.83、GPT-OSS-20B 0.77 落后；最佳单配置可达 0.96（GPT-4o-mini）。**本地 Qwen3.6-27B 在平均忠实度上追平 GPT-4o-mini**，且前沿 API 模型在 RAG 相关指标上并不占优。全局检索质量：nDCG@5 = 0.75、Hit@5 = 0.86、Recall@5 = 0.69。
- **MMR 效应**：MMR 通过降低检索集冗余，使 **nDCG@5 提升 +4~+11pp**（GPT-4o-mini +11pp、Qwen3.5-think +10pp、GPT-OSS-20B 仅 +4pp）。但**忠实度效应随模型规模反转**：小模型受益（Qwen3-32B +5pp、GPT-OSS-20B +6pp），强模型受损（GPT-4o-mini −4pp、Qwen3.5-think −2pp、Qwen3.6-27B −1pp）——作者解释为强模型已能良好锚定最相似段落，额外上下文反而稀释。
- **提示模板效应**：Detailed 模板使忠实度在强/推理模型上提升 **+10~+13pp**（Qwen3.5-think +13、GPT-4o-mini +11、Qwen3.6-27B +10），Qwen3-32B +7pp，而 GPT-OSS-20B 几乎不变（+1pp）。代价是 **METEOR 下降 10~22pp**（详细答案与 SQuAD 简短参考答案表面形式偏离），BERTScore-F1 基本稳定（0~4pp）——说明词面指标与语义指标会背离，必须多指标联合
