## ABSTRACT 

Full-duplex speech agents must update persistent memory while listening and speaking, yet it remains unclear which events should be stored, revised, or excluded. Existing benchmarks isolate interaction timing from memory out-comes, obscuring the state transitions behind a correct answer. We introduce Du-plexLedger , a bilingual benchmark of 1,094 persistent sessions aligning four full-duplex scenarios with event-level W RITE /U PDATE /I GNORE /R ETAIN supervision, explicit pre/post memory states, and 6,564 same-session questions and checks. Evaluating five full-duplex models reveals an interaction–memory gap: no system combines strong boundary control with coherent final-state memory, and the best final-state fact coverage is 2.01%. We propose ACT-Mem , an 8.92M-parameter sidecar comprising an event controller, a versioned transactional ledger, and a typed retriever coupled with a frozen MiniCPM -o 4.5 backbone. On 219 held-out sessions, ACT-Mem increases latest-value accuracy from 4.11% to 8.68% while reducing stale assertions and distractor adoption. It improves interaction bound-aries but slows interruption stopping. These results motivate selective, auditable full-duplex memory rather than indiscriminate transcript retention. Code is avail-able at https://github.com/lyx-researcher/DuplexLedger .

## 1 INTRODUCTION 

Speech is a natural interface for agents that assist people continuously. End-to-end spoken language models now support open-ended voice interaction (Zhang et al., 2023; Tang et al., 2024; Chu et al., 2024; Xie & Wu, 2024), while full-duplex systems listen while speaking, enabling interruptions, backchannels, and overlapping turns (D´ efossez et al., 2024; Wang et al., 2025c; Roy et al., 2026; Liu et al., 2026). Yet concurrency creates a state-management problem: an utterance may introduce or revise a fact, remain incomplete, serve only as a backchannel, or be addressed to someone else. A dependable agent must decide what was said and whether it should modify persistent memory. 

Figure 1: From isolated interaction and memory to transactional full-duplex memory. Existing evaluation treats interaction and memory largely as separate capabilities. Full-duplex benchmarks emphasize turn taking, pause handling, overlap, and interruption, with recent exten-sions adding corrections and entity tracking (Lin et al., 2025; 2026b; Wang et al., 2026; Lin et al., 2026c; Modi et al., 2026). Memory methods and benchmarks instead study long-horizon storage, retrieval, and updating from serialized histories (Packer et al., 2023; Maharana et al., 2024; Wu et al., 2025; Xu et al., 2025), while recent speech agents begin to connect persistent memory with stream-ing interaction (Yao et al., 2025; Xie et al., 2026). The compared resources still do not jointly expose 1arXiv:2610.27581v1 [cs.AI] 20 Oct 2026 event admission, supersession, distractor exclusion, and memory-grounded spoken answers under adaptive concurrency. Without aligned state transitions, a correct answer cannot show whether the system maintained coherent memory or merely matched its current context. We formulate this capability as transactional memory for full-duplex agents : each event is admitted, rejected, or used to revise a versioned state. We introduce DuplexLedger , a bilingual benchmark of 1,094 persistent sessions aligning pause handling, speech to others, backchannels, and interruptions with WRITE , UPDATE , IGNORE , and RETAIN operations, explicit pre/post states, and same-session spoken questions. We further propose ACT-Mem , coupling an event controller, a versioned trans-actional ledger, and a typed retriever with a frozen full-duplex backbone. ## 2 RELATED WORK 

Full-Duplex Dialogue. Early spoken language models established end-to-end speech understanding and generation (Zhang et al., 2023; Tang et al., 2024; Chu et al., 2024; Xie & Wu, 2024). Full-duplex systems subsequently modeled synchronized channels, paired next-token prediction, or parallel au-dio streams to support concurrent listening and speaking (Nguyen et al., 2023; Veluri et al., 2024; Wang et al., 2025b; D´ efossez et al., 2024). Freeze-Omni retains a frozen language backbone, while MiniCPM -o 4.5, PersonaPlex , and Lychee-FD further target low-latency interaction, role control, and acoustic–semantic coordination (Wang et al., 2025c; Cui et al., 2026; Roy et al., 2026; Liu et al., 2026). These systems improve conversational timing, but generally provide no explicit policy for deciding which overlapping events should enter or revise persistent memory. 

Memory-Augmented Agents. Memory-augmented agents manage conversational history through hierarchical storage, temporal updates, structured retrieval, or latent memory (Packer et al., 2023; Zhong et al., 2024; Sarthi et al., 2024; Jim´ enez Guti´ errez et al., 2024; Xu et al., 2025; Zhang et al., 2026). EgoMem and VoiceMem connect persistent memory to streaming multimodal in-teraction (Yao et al., 2025; Xie et al., 2026). These methods improve retention and retrieval but process session-level evidence after observation; they do not jointly control event admission, causal supersession, or exclusion of non-addressed and incomplete speech during concurrent interaction. 

Full-Duplex and Audio Benchmarks. Full-Duplex-Bench evaluates pauses, backchannels, turn transitions, and interruptions; its overlap-focused extension adds speech to others and background speech (Lin et al., 2025; 2026b). HumDial-FDBench broadens human-recorded coverage, while adaptive benchmarks test correction handling, entity tracking, tool use, and interruption-conditioned state updates (Wang et al., 2026; Lin et al., 2026c;a; Modi et al., 2026). General audio bench-marks assess speech, scene, and paralinguistic understanding (Wang et al., 2025a); Audio Multi-Challenge also evaluates multi-turn inference memory, instruction retention, coherence, and spoken self-correction (Gosai et al., 2026). These protocols broaden audio-interaction evaluation but do not expose an event-level persistent-state ledger under adaptive full-duplex execution.

## 5 ACT-M EM : T RANSACTIONAL MEMORY FOR FULL -D UPLEX AGENTS 

5.1 DESIGN MOTIVATION AND OVERVIEW 

The failures in Section 4.4 motivate explicit control over memory admission and revision. We intro-duce ACT-Mem (Auditable and Causal Transactional Memory), an external module coupled with a frozen MiniCPM -o 4.5 backbone (Cui et al., 2026). As shown in Figure 3, streaming audio enters both the frozen full-duplex backbone and a frozen ASR/VAD module. The latter supplies transcripts and timing to a trainable event controller, which manages a transactional ledger implemented as ver-sioned memory. A typed retriever constructs evidence cards for memory questions. Only these cards enter the backbone through QA-only text prefill; all speech-generation components remain frozen. Architectural and runtime details are provided in Appendix E. 5.2 EVENT ADMISSION AND TRANSACTION LIFECYCLE

Super-seded, uncertain, aborted, and ignored content cannot enter an evidence card. 5.4 TYPED RETRIEVAL AND MEMORY CONDITIONING 

[Typed retrieval] Question type controls evidence scope and card generation. The typed retriever maps each question to one of four behaviors. A latest-value question selects the target entity’s active value, a recall question retrieves up to four active facts, and a summary question aggregates up to eight facts across types and entities. Rejection and behavior questions produce no card, preventing inadmissible content from being disclosed to the backbone. For retrieval-enabled questions, ranking combines dense similarity (Karpukhin et al., 2020), lexical overlap, recency, controller confidence, and stale/distractor penalties. The resulting card contains only typed facts and active values; insufficient evidence yields no card. 

ACT-Mem conditions generation without modifying the decoder (Lewis et al., 2020). At a stable-silence QA boundary, the backbone processes the question audio, receives one evidence card through QA-only text prefill, and generates a spoken answer. Context events and full-duplex challenges continue through the native audio interface without memory prefill. 5.5 TRAINING , C ALIBRATION , AND MODEL COMPLEXITY

## 6 EVALUATION OF ACT-M EM 

We evaluate ACT-Mem on the same 219 held-out sessions used for the baseline study, containing 1,314 questions/checks and 438 latest-value questions. The controlled comparison retains the frozen 

MiniCPM -o 4.5 backbone; no held-out session is used for training, checkpoint selection, or calibra-tion. Evaluation follows Sections 3.4 and 4.1. Relative changes use unrounded scores, and pointwise 95% confidence intervals for latest-value accuracy and final-state coverage are obtained from 20,000 paired bootstrap resamples of sessions. The controlled evidence therefore supports improved local state revision, but not yet complete reconstruction of the session-wide memory state. 

[Takeaway 2] The memory gains are concentrated in selective commitment rather than uniformly improving every outcome. Stale assertions and distractor adoption decrease by 0.22 and 2.28 per-centage points, respectively, showing that the latest-value gain is accompanied by fewer conflicting and incorrectly admitted facts. Distractor rejection and response rate decline by 2.28 and 1.45 points, although the latter remains high at 97.41%. Because distractor adoption and rejection are separately credited under fixed denominators, they are not complementary; their joint decline means that ACT-Mem produces fewer explicit adoptions but also fewer credited rejections. The principal benefit is therefore more selective state construction, while robust distractor rejection remains improvable. 6.2 EFFECTS ON FULL -D UPLEX INTERACTION 

[Takeaway 3] ACT-Mem improves most interaction-boundary metrics but slows interruption stop-ping. cFD increases by 10.8%, while early response, pre-end speech, and windowed intrusion de-crease by 18.6%, 7.6%, and 5.1%, respectively. Because cFD is conditioned on realized challenges and RCR decreases from 76.35% to 74.10%, this improvement should be interpreted as better be-havior on exposed challenges rather than uniformly greater challenge coverage. The main trade-off is interruption stopping: Stop@0.8 falls from 51.06% to 45.00%, and median stopping latency in-creases from 1.123 to 1.340 seconds. Thus, ACT-Mem improves observed onset and overlap control, while rapid interruption recovery remains its principal interaction weakness. 6.3 ABLATION STUDIES

## 7 CONCLUSION 

We frame persistent memory during concurrent speech as selective state management. Du-plexLedger aligns adaptive challenges, event-level operations, explicit reference states, and spo-ken QA across 1,094 bilingual sessions. This alignment supports joint evaluation of interaction and memory, while reference transitions and system traces help diagnose admission, supersession, exclusion, retrieval, and generation failures. Across five systems, no model dominates both inter-action and memory fidelity. ACT-Mem combines an event controller, versioned ledger, and typed retriever with a frozen backbone. On 219 held-out sessions, latest-value accuracy rises from 4.11% to 8.68%, with fewer stale assertions and distractor adoptions. Several interaction-boundary met-rics also improve, although interruption stopping becomes slower. These findings motivate explicit, auditable state management and further validation on natural conversations, additional languages, longer timescales, and other backbones. 

## ETHICS STATEMENT 

DuplexLedger contains AI-generated dialogues and synthetic speech rather than recordings of human participants or private conversations. Its controlled scenarios may nevertheless encode generation-model biases and should not be treated as representative of unrestricted real-world di-alogue.

## A DUPLEX LEDGER CONSTRUCTION AND DATA CARD 

A.1 CONSTRUCTION PRINCIPLES 

DuplexLedger was constructed to evaluate whether a spoken dialogue agent can maintain a coher-ent memory state while simultaneously respecting full-duplex interaction boundaries. We designed each session around three coupled requirements: (i) the dialogue must contain facts that evolve through additions and corrections; (ii) some audible content must be inadmissible to persistent mem-ory; and (iii) the interaction must contain a concurrency event whose correct handling depends on the model’s runtime speaking state. These requirements led to four scenarios: user interruption, user backchannel, within-turn pause, and speech addressed to another person. All dialogue content is synthetic. We used GPT-5.5 to generate the underlying Chinese and English task descriptions, conversational utterances, factual values, corrections, distractors, and reference answers under scenario-specific instructions. Generation was constrained by a structured schema specifying speaker roles, event order, memory dependencies, challenge types, and evaluation tar-gets. The generated content was subsequently normalized and instantiated by deterministic con-struction programs. The language model was used only during dataset creation and is not part of the benchmark execution or scoring pipeline. A.2 TASK AND DIALOGUE GENERATION 

We constructed sessions from a broad collection of everyday task templates, including scheduling, planning, customer support, troubleshooting, study assistance, household coordination, travel, doc-ument preparation, creative work, and low-pressure personal organization. The Chinese and English construction pools contain 73 and 72 base task templates, respectively, covering 72 high-level do-mains in each language. Each base task specifies two revisable attributes and several persistent facts. A typical task contains: • an initial value and a corrected value for a primary attribute; • an initial value and a corrected value for a secondary attribute; • a stable goal or constraint that should remain active; • an additional task-specific detail; • a named person and an associated responsibility; • a plausible but irrelevant distractor; 13 • an expected consolidated final state. To reduce exact repetition, each task was combined with a scenario-specific identifier, one of four discourse-style variants, and one of twelve instance-level modifiers. The modifiers vary properties such as budget conservatism, scheduling slack, communication requirements, fallback plans, execu-tion complexity, and family or workplace coordination. Timing, challenge position, pause length, overlap duration, and short-feedback form were sampled using fixed construction seeds. We also varied how the user concludes a session. A final turn may fully restate the task, omit the recap, provide only a partial recap, contain a self-correction, or explicitly request that the assistant not summarize. The intended proportions were 40%, 25%, 20%, 10%, and 5%, respectively. The released corpus contains 434 complete recaps, 268 sessions without a complete final recap, 218 incomplete recaps, 118 recaps containing a correction, and 56 explicit no-summary requests. This variation prevents the final memory state from being recoverable solely by copying the last user turn. A.3 SCENARIO -S PECIFIC INTERACTION DESIGN 

The same underlying memory requirements are combined with four distinct full-duplex phenomena. 

User interruption. The user begins with a provisional task state and later interrupts an active assis-tant response to correct one or more values. The interruption should terminate the obsolete response trajectory, and the corrected values should supersede their earlier versions. A second interruption may clarify that a nearby detail is irrelevant and must not enter persistent memory. 

User backchannel. Short acknowledgements such as “yes,” “okay,” or their Chinese equivalents are inserted while the assistant is speaking. These utterances provide listener feedback but introduce no new task fact. A correct system should continue its response without interpreting the backchannel as an interruption or memory write. 

Pause handling. The user produces an incomplete utterance, pauses, and then resumes with a completion or correction. The pause is represented explicitly rather than as a completed turn. A correct system should wait for the continuation and must not commit a provisional value merely because a long silence occurred. 

Speech addressed to another person. The session contains both user speech directed to a by-stander and audible speech from that bystander. Such content is topically plausible but is not ad-dressed to the assistant. It therefore serves as a controlled distractor: the model should neither respond to it nor incorporate it into the official task state. The user later returns explicitly to the assistant and continues the admissible task. A.4 STRUCTURED EVENT AND MEMORY ANNOTATION 

A session is represented as an ordered list of speech and silence events. Each event records its identifier, speaker, addressee, dialogue act, planned time interval, audio-rendering status, memory dependencies, and candidate memory writes. Events spoken by the primary user or bystander are audible; reference assistant events specify the intended conversational trajectory but are not rendered into the benchmark input. Memory is annotated at the item level. The annotation vocabulary covers goal , schedule ,

constraint , preference , episodic , named entity , task state , and correction .Each item contains a stable memory identifier, semantic type, textual content, and source event. Corrections additionally identify the earlier item that they supersede. Distractors are annotated sep-arately and are excluded from the oracle final state. For evaluation, the event annotations are mapped to four memory operations: W RITE , U PDATE ,IGNORE , and R ETAIN . Ordinary admissible facts produce W RITE ; explicit corrections and clarifi-cations produce U PDATE ; backchannels, side conversations, and bystander speech produce I GNORE ;and pauses without confirmed content produce R ETAIN . This mapping supplies the event-level su-pervision used to distinguish admission errors from supersession, retrieval, and answer-generation errors. 14 The construction procedure enforces two provenance constraints. First, every item in the oracle final state must be supported by an audible user event. Muted reference-assistant events cannot introduce a gold fact. Second, a superseding item must refer to an earlier item in the same session; future or cross-session references are disallowed. A.5 MEMORY QUESTIONS 

Every session contains six spoken evaluation targets: 1. two latest-value questions, one for each corrected attribute; 2. one factual-recall question about a stable requirement; 3. one distractor-rejection question; 4. one final-state summary question; 5. one scenario-specific behavioral check. Each question is aligned with its expected answer, supporting memory identifiers or events, and, when applicable, forbidden obsolete or distractor items. The latest-value questions require the cor-rected value and prohibit credit when the obsolete value is asserted. The distractor question tests whether the system rejects inadmissible content rather than rewarding silence alone. The summary question requires coverage of multiple active facts and therefore evaluates state consolidation be-yond isolated retrieval. Questions are synthesized as audio and presented after all contextual and challenge events, without resetting the model state. The question audio, reference text, and gold evidence annotations are stored separately. Reference answers and memory annotations are used only for scoring and are not exposed to the evaluated system. A.6 SPEECH SYNTHESIS AND TEMPORAL ALIGNMENT 

All speech is generated using text-to-speech synthesis; the dataset contains no recordings from hu-man participants. Audible event segments are rendered at 24 kHz and assembled according to the structured event timeline. Scenario-specific speaker assignments distinguish the primary user from the bystander in multi-speaker sessions. The reference assistant remains muted, because the assistant audio during evaluation must be produced by the system under test. We apply forced alignment to the synthesized speech to obtain word-level English boundaries and character-level Chinese boundaries. Punctuation is removed for alignment, while the original text is retained in the source annotation. The aligned event window is defined by the first and last aligned units with 120 ms of boundary padding. For each event, we retain the source sampling rate, number of samples, first and last aligned boundaries, leading and trailing silence, playback sample range, source duration, SHA-256 checksum, and quality-control flags. The fixed mixed waveform is retained as a compatibility artifact, but it is not the authoritative input for adaptive evaluation. The final protocol instead replays aligned event segments according to a closed-loop stage manifest. This distinction is necessary because a full-duplex challenge should occur when the evaluated model is actually speaking, rather than at a timestamp derived from a prerecorded reference trajectory. A.7 ADAPTIVE SESSION MATERIALIZATION 

For each session, we compile a chronological execution manifest containing ordinary context play-back, adaptive challenges, recovery periods, and same-session memory QA. Ordinary user events are streamed in real time. Before an interruption or backchannel, the scheduler waits for decoded-audio VAD to confirm that the evaluated model is speaking. It then injects the corresponding user event. If the required speaking state is not observed within the timeout, the challenge remains unrealized and the timeout is recorded. Pause intervals are represented as explicit wait stages. Speech directed to another person is played through a dedicated side-talk stage and is marked as not addressed to the assistant. After an ordi-15 nary response-required event, the scheduler observes response onset and subsequent silence before advancing. The six audio questions are asked only after the interaction stages have finished. The complete session uses one persistent model state: • the model is reset before a new session; • it is not reset between context and challenges; • it is not reset between challenges and memory QA; • it is not reset between individual QA items. The execution protocol uses 80-ms input chunks. Interruption and backchannel triggers require at least 500 ms and 800 ms of active assistant speech, respectively. Question input retains 400 ms of post-speech tail silence, and answer windows are determined dynamically. Runtime failures, trigger timeouts, and missing responses are recorded rather than silently discarded. A.8 VALIDATION AND QUALITY CONTROL 

We apply validation at three levels. 

Structural validation. Before synthesis, each session must contain all required fields, unique event and memory identifiers, chronologically valid timestamps, valid memory dependencies, and consistent overlap annotations. Memory reads may reference only previously introduced items. Supersession links must point to existing earlier items, and every final-state fact must trace to audible user speech. 

Audio and alignment validation. The construction pipeline verifies the existence and duration of every waveform, preserves source-file checksums, and records missing alignments, leading si-lence, and trailing residuals. The released corpus contains no missing event-audio files. Of 7,687 speech events, 7,589 have forced-alignment boundaries. The remaining events are retained with ex-plicit missing-alignment flags rather than removed. In addition, 3,007 aligned events contain more than 0.5 s of trailing residual audio; these cases remain visible through per-event quality-control metadata. 

Execution validation. Each session must contain a nonempty ordered stage list, unique stage identifiers, relative and resolvable audio paths, an adaptive state-wait stage before every interruption or backchannel injection, and a final same-session QA stage. Question windows must satisfy 

0 ≤ nstart < n speech -end ≤ nend .

DuplexLedger is fully synthetic and therefore does not reproduce the complete distribution of spon-taneous human speech. It should therefore not be interpreted as a complete benchmark for privacy-aware memory management. ## B ADAPTIVE FULL -D UPLEX EXECUTION PROTOCOL 

B.1 PROTOCOL OBJECTIVE AND EXECUTION UNIT 

The evaluation unit is a complete interaction session associated with one DuplexLedger sample. A session contains an annotated context, one or more full-duplex challenges, a recovery phase, and a set of memory questions. The audio content and event annotations are fixed before evaluation, whereas the wall-clock time at which a challenge is delivered is determined online from the de-coded assistant waveform. Consequently, the protocol distinguishes between a planned challenge, a trigger-satisfied challenge, and a realized challenge. A planned challenge is an event specified in the sample manifest. A trigger is satisfied only when the required assistant state is observed within the prescribed timeout. A challenge is realized only when the corresponding user audio is subsequently delivered to the model. This separation prevents a silent or non-responsive model from being credited with having successfully experienced an interruption that was never actually applied. Each sample is evaluated in one persistent model session. The session is reset before the first context event, but it is not reset between context, challenge, recovery, or memory-question stages. The event-level representation is compiled into an ordered stage manifest before model inference. The manifest contains event identifiers, source sample ranges, speaker and addressee labels, dialogue acts, semantic turn boundaries, response requirements, and the expected memory operation. The scheduler executes only this manifest; it does not infer the event ordering from a concatenated waveform at runtime. For ordinary response-required context events, the manifest inserts a response-start wait followed by a response-silence wait before the next context event. Adaptive interruption and backchannel events instead insert a state-trigger wait immediately before the challenge audio. This ordering ensures that the challenge is aligned to the model’s actual speaking state rather than to a fixed timestamp in the source recording. B.3 AUDIO WINDOWS AND CLOCK SEMANTICS 

For each speech event, the scheduler stores an actual source range [si, e i) in samples. The range is derived from the annotated speech window and expanded by a fixed padding of 120 ms , subject to the available source boundaries. The original waveform is never modified in place. A concate-nated waveform may be retained as a compatibility artifact, but it is not the authority for adaptive execution; the stage manifest and its sample ranges are authoritative. The protocol maintains two clocks. Media time measures the amount of user and assistant audio advanced by the scheduler, whereas wall time is measured with a monotonic runtime clock. Adaptive 18 sessions are therefore allowed to have different wall-clock durations for different models. Runtime records preserve both clocks, the decoded assistant VAD state, and the timestamps reported by the native audio bridge. Decisions about whether the assistant is speaking are made from decoded PCM audio rather than packet arrival. Input audio is processed in 80 ms chunks, and the scheduler polls state at 20 ms intervals. B.4 ADAPTIVE CHALLENGE TRIGGERING 

Interruption and backchannel challenges use a closed-loop trigger: wait for assistant speech → verify VAD duration → inject challenge audio .

An interruption requires at least 500 ms of continuous decoded assistant speech, while a backchannel requires at least 800 ms . Both trigger waits have a 10 s assistant-start timeout. If the condition is not satisfied before the timeout, the challenge audio is not sent and the event is recorded as an unrealized challenge with a trigger timeout. In particular, codec activity without VAD-confirmed speech does not satisfy the trigger. The remaining challenge types use different execution semantics. A pause is implemented as a scheduler wait over its annotated duration and does not force the assistant to speak. Speech ad-dressed to another participant is played as audio and followed by a 1.2 s observation interval. Its structured addressee label is retained in the evaluator’s event record; whether an auxiliary module also accesses this field is a separate input configuration described in Appendix E. Thus, these events test pause intrusion and target-speaker selectivity, respectively, rather than using the same speech-trigger rule as interruption and backchannel events. After an event whose semantic turn has ended and which requires a response, the scheduler waits for at least 160 ms of assistant speech. It then waits for stable silence for up to 12 s , with a 2 s 

silence criterion. Failure to observe response onset is recorded as a response-initiation failure; it is not converted into a zero-duration response. B.5 RECOVERY AND STOP -L ATENCY MEASUREMENT 

For an interruption, the assistant’s decoded waveform is monitored from the time at which challenge audio is injected. The runtime record stores whether the assistant was speaking before injection, whether speech continued after injection, the first observed speech offset, and whether the response ended within the configured silence window. Stop latency is computed only when a valid assistant speech interval and a valid interruption injection are both available. If the assistant does not stop before the response timeout, the event remains in the record with an explicit timeout or failure flag. Backchannels are not treated as interruptions: the protocol records whether the assistant continues, pauses, or restarts after the feedback audio. For non-addressee speech, the observation interval is retained even when the assistant remains silent, since silence is a valid selectivity outcome. All runtime failures are recorded under a “record-and-continue” policy whenever the session remains executable. A server crash, unsupported cancellation, or unrecoverable protocol violation terminates the sample and preserves the partial runtime artifacts. B.6 SAME -S ESSION MEMORY QUESTIONS

## D BASELINE MODELS AND INFERENCE CONFIGURATIONS 

D.1 EVALUATION SCOPE AND COMPARISON PROTOCOL 

We evaluate five publicly available full-duplex speech models: MiniCPM -o 4.5 (Cui et al., 2026), 

Freeze-Omni (Wang et al., 2025c), Moshi (D´ efossez et al., 2024), Lychee-FD (Liu et al., 2026), and PersonaPlex -7B-v1 (Roy et al., 2026). The models are selected to cover different streaming speech architectures and native interaction interfaces. All baseline models use the same session manifests, planned event order, source audio clips, and scheduling rules. Because speech-triggered challenges depend on each model’s realized output, the subset of challenge clips actually delivered can differ across models. A sample is executed as one persistent session: the session is reset before the sample begins, but not between context events, full-duplex challenges, recovery stages, or memory questions. The baseline speech models are not provided with gold memory states, reference answers, align-ment boundaries, event labels, addressee labels, or future events. This restriction concerns baseline-model inputs; the interfaces available to ACT-Mem’s auxiliary modules are specified separately in Appendix E. All models are evaluated with the same adaptive execution controller, the same challenge-triggering rules, the same session-reset policy, and the same answer-attribution proce-dure. Model-specific native chunk sizes, sampling rates, voice prompts, and transport protocols are retained when they are required by the corresponding implementation. All baseline models receive a neutral voice-assistant instruction in the language of the corresponding sample. The instruction is transported through the native interface when required by the model, but no task-specific memory or interaction instruction is added. A model may therefore use only its native audio history and the neutral instruction supplied at session initialization. All assistant audio is captured from the native model bridge and retained as a decoded waveform. The waveform is used for VAD-based state detection, challenge triggering, stop-latency measure-ment, and response-onset attribution. Memory answers are evaluated from independent answer windows rather than from a concatenated session transcript. For cross-model textual comparison, each answer waveform is transcribed with the same frozen external Whisper-small configuration. The language is taken from the sample manifest, decoding temperature is set to zero, and the same transcription backend is used for all models. Native model text, when available, is retained as a secondary artifact but is not used as the primary cross-model transcript. A transcription failure is recorded explicitly and makes the corresponding primary textual score unavailable; it is not silently converted to a zero-valued answer. The answer window opens after decoded assistant speech onset and closes on decoded silence, an explicit turn boundary, or the configured answer timeout. A late response after timeout is kept in a quarantine interval and is not assigned retroactively to the expired question. No answer text is reused between questions. D.6 CALIBRATION , T EST ISOLATION , AND REPRODUCIBILITY 

Before the held-out evaluation, a fixed calibration split is used to freeze the shared VAD, challenge-trigger thresholds, timeout values, text normalization rules, and scoring parameters. The held-out sessions are not used for prompt tuning, decoding-parameter tuning, VAD adjustment, timeout se-lection, or checkpoint selection. For every model, the evaluation record stores the public model identifier, checkpoint identity, repos-itory revision when available, model-profile configuration, prompt transport, decoding settings, ran-dom seed, native sample-rate configuration, assigned GPU resources, and runtime environment iden-tity. Checkpoint and configuration hashes are retained in the artifact manifest so that the reported results can be traced to an unambiguous model state without exposing machine-specific filesystem paths in the paper. GPU isolation is enforced during inference. A run is considered invalid for paper reporting if an unrelated process contaminates an assigned GPU. The same session and sample identifiers are pre-served across all runtime artifacts, allowing failed samples and resumed samples to be audited with-out double counting. D.7 FAILURE HANDLING AND EFFECTIVE DENOMINATORS 

Runtime failures, server disconnects, unsupported native controls, trigger timeouts, answer timeouts, and no-response questions are retained in the execution record. A failed sample is not silently re-moved from the attempted sample count. Instead, the evaluation reports protocol validity, behavioral observability, completion or failure status, and the effective denominator of every metric. A challenge that is not realized because its trigger condition is not reached is distinguished from a challenge that is realized but handled incorrectly. Likewise, a valid session with no assistant speech is distinguished from a protocol-invalid session. Conditional behavioral scores are computed only when their required audio and timing evidence exists, while challenge realization, trigger time-out, and failure counts are reported separately. This accounting prevents differences in interface robustness, speech observability, and challenge exposure from being mistaken for differences in full-duplex behavior or memory fidelity.
