## ABSTRACT 

When we say that a robot uses memory, does that memory actually play a role? Success-rate ablations alone cannot establish the use of task-relevant facts: they change information and computation together, while aggregate rates can hide off-setting gains and losses. We propose an Interventional Memory Evaluation Proto-col (IMEP) for vision–language–action (VLA) systems to address four questions: (1) Does memory provide a net benefit? (2) Under what conditions does mem-ory help? (3) Do changes to memory alter task outcomes? (4) Are these effects specific to task-relevant facts? At the retrieval interface, we compare target-fact substitutions with fact-preserving replacements, minimal numerical perturbations, and exact replicas, while assessing decision correctness separately from motor ex-ecution success. We evaluate within-episode, cross-episode, and agentic memory. In cross-episode learned-bank experiments, a one-unit-in-the-last-place (ULP) in-tervention, including its installation procedure, changes 11.9% of seed-paired out-comes, while changing key facts produces no clear additional effect over fact-preserving replacements. To examine when memory helps, we introduce Chain-Bench, where correct decisions require historical information unavailable in cur-rent observations. The full memory configuration raises task success from 39.1% to 74.3%, matching the oracle-decision condition under shared recorded execu-tions. These results show that correct history can support robot decisions, but establishing whether a memory system realizes this benefit requires fact-specific evidence beyond aggregate success rates. 

## 1 INTRODUCTION 

A robot’s current observation may omit information needed to act: an earlier visual cue, a previous episode’s experience, or a fact retained across tasks. Vision–language–action (VLA) systems there-fore augment policies with memory banks, event keyframes, or temporal representations (Shi et al., 2026; Zeng et al., 2026; Koo et al., 2026), experience retrieval (Sridhar et al., 2026), and external text records (Zhang et al., 2026b). These mechanisms aim to turn history into useful evidence for current decisions. Their value is often evaluated through memory ablations and task success (Shi et al., 2026; Zeng et al., 2026). Such gains show improved performance, but do they establish use of task-relevant stored facts (Figure 1a)? Three distinctions prevent that inference. First, enabling memory can change both information and computation. Second, an unchanged success rate can hide gains on some trials and losses on others (Milani Fard et al., 2016). Third, changing memory can alter behavior even when a replacement preserves the target fact or introduces only a small numerical perturbation. History can also support shortcuts, as shown by causal confusion and copycat behavior in imitation learning (de Haan et al., 2019; Wen et al., 2020). Behavioral sensitivity alone does not establish use of task-relevant facts. Conversely, an undetected net gain does not imply that memory has no effect. Interpretation also depends on whether current observations already reveal the answer, whether an intervention reaches the reader, and whether stored facts remain valid. ## 2 RELATED WORK 

VLA memory methods augment policies with learned banks, temporal representations, or retrieved experience (Shi et al., 2026; Koo et al., 2026; Sridhar et al., 2026). Robotic benchmarks test his-2Preprint tory dependence (Cherepanov et al., 2026; Dai et al., 2026), while MemoryAgentBench tests fact updating (Hu et al., 2026). ChainBench separates decision and execution readouts when query ob-servations omit the deciding fact. Causal scrubbing and activation patching probe behavioral dependence on internal variables (Chan et al., 2022; Zhang & Nanda, 2024). PoPE uses placebo controls to distinguish useful error content from presentation effects in code-model self-repair (Iscan, 2026). IMEP adapts these principles to embodied memory through fact-changing and fact-preserving interventions at a specified retrieval interface, paired outcome flips, and delivery checks. Appendix J expands these connections and their limits. 

## 3 INTERVENTIONAL MEMORY EVALUATION PROTOCOL 

3.1 EVALUATION TARGET AND PAIRED DESIGN 

IMEP evaluates whether memory benefits VLA systems and whether their responses to memory interventions are specific to task-relevant facts. Using paired comparisons and control interventions (Figure 2), it addresses four questions: 

Q1. Net benefit: Does memory provide a net benefit? 

Q2. Conditions: Under what conditions does memory help? 

Q3. Outcome sensitivity: Do changes to memory alter task outcomes? 

Q4. Fact specificity: Are these effects specific to task-relevant facts? The same task–seed pairs or multi-episode chains are evaluated across conditions. Let A denote ref-erence memory, X an intervention, and Y Xi ∈ { 0, 1} task success for unit i. We specify the memory interface, intervention time, controlled variables, and execution randomness, and score decisions separately where observable. Shared seeds do not guarantee identical execution. The framework and interpretation criteria were developed after the campaigns closed. They do not retroactively make post hoc checks confirmatory (Appendix G.3). 3.2 INTERVENTION DESIGN AND CONTROLS 

Access and oracle comparisons ( A, N, O ). A retains reference memory, N blocks reads or empties the bank, and O supplies the correct fact or decision. Blocking access measures utility together with any changed computation. Controls ( C, U ). C repeats the reference exactly; U applies a one-ULP numerical change. Fact substitutions ( S, T ). With the retrieval interface fixed at installation, S

substitutes a record with the same target fact; T substitutes one with a different target fact. Same-fact records can differ in other content. In cross-episode learned banks, U/S/T share an installation routine bypassed by C, so comparing U with C does not isolate numerical perturbation alone. Under Shell Game blackout, Sπ permutes and Tμ resamples retrieved latent values, but these operations are not verified semantic edits (Appendix E.1). 3.3 READOUTS : B ENEFIT , S ENSITIVITY , AND SPECIFICITY

To interpret the measured effects, Q2 examines whether the task requires history, whether interven-tions reach the reader, and whether stored facts remain valid. These checks guide attribution rather than specify universal prerequisites for memory to help. 

(a) Information: a history-required task hides the deciding fact from the current observation and requires one choice among K options, with no recovery by trying alternatives. Where decisions are observed, we compare no-memory accuracy with 1/K and require a positive lower bound on 

G = Acc O −Acc N . A no-memory accuracy interval containing 1/K does not establish equivalence to chance or rule out relevant information in model weights. 

(b) Delivery: check reads in A, empty reads in N , and substitution coverage: the fraction of units whose every decision query selects at least one unmodified substituted record. Coverage of one verifies this operational check, not fact use. When coverage is below one, interpretation concerns swaps as delivered. 

(c) Validity: vary persistence while holding other components fixed. Whole-configuration contrasts cannot isolate the effect of stale information. 

Measurement and decision rules. We retain campaign-specific verdicts and magnitude criteria. Under the retrospective rules, Q3 requires the lower bound on ρX to exceed the repeatability floor; Q4 requires the lower bound on θ to exceed zero and the upper bound on ρU , subject to the checks above. Remember Color’s registered equivalence analysis requires the 90% CI of ¯θ within ±7.5

percentage points (Lakens, 2017). The analysis concerns swaps as delivered and does not exclude smaller effects. Nonsignificance alone is not equivalence. Appendix K expands these checks and their implementation limits. 3.5 CHAIN BENCH : A M EMORY -R EQUIRED EVALUATION SETTING 

A write episode reveals an object’s drawer. Same-scene distractor episodes then write other records before a query with closed drawers and identical observations across targets. The robot commits to one drawer before a frozen π0.5 policy executes that choice. In the 202-chain study, the full-memory configuration uses a stipulated latest-write set, a calibrated presence gate, two-stage retrieval, and a leave-one-chain-out nearest-centroid readout, with no decision-time LLM call or evaluated eviction 4Preprint policy. Conditions share recorded executions within each chain, so identical correct decisions imply equal task success at the observed oracle ceiling SR ∗ = SR O , where SR O is the oracle’s observed task-success rate. The separate C/U/S/T study tests only the scripted decision reader on curated records, not motor outcomes or live memory writing and retrieval (Appendices C.1 and B.5). 

## 4 EXPERIMENTS 

4.1 EXPERIMENTAL SETUPS 

We evaluate within-episode, cross-episode, and agentic memory, reporting Q1–Q4 in that order for each layer. Table 1 summarizes the learned-bank net-benefit comparisons, Figure 3 shows responses to memory interventions, and Table 2 reports ChainBench decision accuracy and task success. The four-question framework and its interpretation criteria were developed after the campaigns ended. The cross-episode survival audit was also post hoc (Appendix G.3). 

Layer 1 (within-episode learned banks). On MIKASA-Robo Shell Game (Cherepanov et al., 2026), we evaluate episode-local memory using a community checkpoint of the MemoryVLA archi-tecture (Shi et al., 2026) in the released and structured-PCMB configurations. Comparisons between these configurations do not isolate the effect of memory access. We test with the view available and under an out-of-distribution camera blackout from elapsed step 6 to episode end, covering 85 of 90 frames. On SimplerEnv (Li et al., 2025), we remove the perceptual bank across twelve Frac-tal coke-can configurations (Fractal) and block episode-local memory reads on four Bridge tasks. Each Bridge task uses 24 seed-paired episodes. Three tasks enter the 72-pair analysis under the preregistered inclusion rule (Bridge grid). 

Layer 2 (cross-episode learned banks). On MIKASA-Robo, each task–seed pair is evaluated in two episodes (attempts 1 and 2), allowing the second episode to read records written during the first. We evaluate cross-episode memory in Shell Game under structured PCMB. On Remember Color 3 and 5 (RC3, RC5), the preregistered substitution study changes stored contents once at the start of attempt 2, preserving the initial retrieval path. We also test version conflicts on Remember Color 3, 5, and 9, memory carryover along five-attempt Bridge chains (Bridge carry), and a trained neural memory plugin on Remember Color and Shell Game. Appendix A.3 documents the checkpoint and implementation for each study. 

Layer 3 (agentic text memory). We evaluate agentic text memory using ChainBench (Section 3.5) on LIBERO (Liu et al., 2023). The main study uses 202 chains with K = 2 and a frozen π0.5

policy (Black et al., 2025a) for motor execution. A supporting study uses 143 chains with K =3, a different executor, and a different chain manifest. We analyze their results separately. We compare the full memory condition on curated records with an initial-fact baseline that ignores later updates, alongside no-memory, shuffled-record, and oracle-decision controls. We report decision accuracy and task success on the same chains. A separate live-harness coordinate study is reported in Appendix E.5. 

Detectability. We interpret undetected effects in light of the controls and resolution available for each readout. Removing the post-cue view reduces Shell Game success from 94 .0% to 73 .5% over 

200 paired episodes, showing that the success readout detects this large visual intervention. In the tested learned-bank simulators, exact replicates change 0/388 outcomes on the common Remember Color cohort and 0/400 on the Shell Game blackout cohort. The scripted ChainBench reader pro-vides a positive control for decision accuracy. These controls do not establish sensitivity to small fact-specific effects in learned banks. Q3 (sensitivity). Shuffling curated records reduces decision accuracy to 51 .5% and task success to 

38 .6% , showing that decisions and outcomes are sensitive to changes in the records. We did not apply the C/U/S/T ladder to motor outcomes because, in a separate execution-repeatability study, replaying identical instructions changes about 27% of outcomes (Appendix B.5). This execution variability would make the effects of memory interventions difficult to distinguish. 

Q4 (specificity). In a separate decision-level evaluation on 401 chains, the nearest-centroid readout changes no decisions under U or S (0/401 each), whereas different-fact swaps T change all 401 de-cisions (Figure 3c; Appendix B.2). These results support fact specificity for this readout on curated records. The same experiment also serves as the positive control for the decision readout, so these two uses do not provide independent evidence. This ladder does not test memory writing or retrieval by the live harness. 

Across layers. Does memory work? No detected learned-bank gain meets a registered net-benefit criterion, and the trained plugin’s bank reduces task success. On ChainBench, curated records in the 202-chain study raise task success to the observed motor-execution ceiling. When can memory help? No learned-bank setting establishes both the history requirement and delivery. ChainBench requires history, and full memory matches oracle accuracy, although this equality alone does not ver-ify delivery. Are the effects fact-specific? Learned-bank outcomes respond to memory interventions, including the one-ULP control and its installation procedure, but fact specificity is not established. The separate ChainBench decision-level experiment supports fact specificity for the nearest-centroid readout on curated records (Tables 1 and 2; Figure 3). 

## 5 CONCLUSION 

IMEP shows why memory-access gains and intervention sensitivity should be reported separately from evidence of fact-specific use. Across the evaluated learned banks, interventions alter outcomes, but the available controls do not establish fact specificity. ChainBench provides complementary ev-idence that historical records can support correct decisions, with specificity demonstrated for the evaluated reader on curated records. The main limitations concern measurement resolution and the scope of the evaluated systems. The learned-bank studies lack decision readouts and content posi-tive controls, leaving small fact-specific effects unresolved. The ChainBench findings concern the evaluated memory configuration and readout, with task success measured using shared recorded executions. Generalization across checkpoints and implementations remains unverified. Terminology. An episode is one simulator rollout. An attempt is an episode at a fixed position in a repeated-task sequence. A chain is the ordered sequence that may carry memory across attempts. A cell is one policy × task × memory interface at n seed-paired episodes. We use preregistered to mean fixed in a written protocol before the corresponding outcomes were collected. 

Sign conventions. Absolute differences between rates and their bounds are reported in percentage points (pp), while rates are percentages or proportions as labeled. Besides D = ( b − c)/n of Section 3.3, whose reference is the memory-on condition A, Appendices D.3 and F report ∆ = (c − b)/n , a named condition minus a named baseline, with b counting pairs in which that baseline succeeds, and declare it at each use. ∆ = −D when the baseline is the memory-on condition (Fractal); when it is the memory-off condition (ChainBench E1/E1B, Bridge carry, the plugin bank channel, the persistence-only 2 × 2), b and c are swapped relative to Section 3.3 and ∆ = D. We never subtract across the two conventions. Where a ∆-convention number is quoted, both conditions are named. For example, the version-conflict contrast is the structured-PCMB condition minus its released comparator, −3.91 pp (Appendix D.3). 

What the content estimand does and does not measure. We operationalize a memory contribution as the target-fact-specific increment under a retrieval and computation path fixed at installation. By construction ¯θ misses diffuse benefits that bypass the audited fact and effects that change retrieval, gating or consolidation timing: fact specificity is the unit of our attribution question, not a complete account of memory value. 

Tests and bounds. Unless stated otherwise, p-values are two-sided exact McNemar tests conditional on the b + c discordant pairs, with Holm correction for families frozen in advance. Campaign decision bounds are built from exact Clopper–Pearson bounds on the two discordance proportions,

80% . We label each bound at the coverage of the quantity being bounded, never at the coverage of a component. One design uses a different setting and says so where it is reported: the Bridge grid (GRID-1a) uses α = 0 .025 per component, so each one-sided endpoint has coverage at least 95% 

and the two-sided interval at least 90% . It is not a joint 95% interval. Campaign decision bounds retain the α used by their frozen adjudicators.

This check operates on the declared lists. 

Installation and retrieval. Substitution is installed once, at the start of attempt 2 and before its first query: the recipient scope’s records, ordered by (timestep, slot), each receive the payload of the donor record at the same position (cognitive and perceptual values, action chunk, pre- and post-action state, interaction signature, outcome embedding, and failure signature), while slot, scope, source episode, timestamp, version, cognitive and perceptual keys, and state signature are kept. The exact replicate installs nothing; the one-ULP condition installs the recipient’s own payload, with every stored payload value moved by one representable value, through the same routine. Retrieval uses a parameter-free similarity selector whose scorer reads only the two keys and the state signature, compared against the current cognitive and perceptual tokens: records are ranked by a weighted sum of cognitive and perceptual key similarity, a query is accepted only when the best state similarity is at least 0.45, and at most four records are returned. The scorer does not use content fields, versions, slots, or timestamps. Slots and timestamps are used only to break ties. Task and seed determine which records are searched through the opaque scope identifier. ## J RELATED WORK (E XTENDED )

Memory in VLA systems and agentic harnesses. Memory extends foundation policies (Black et al., 2025b;a; Zitkovich et al., 2023; Kim et al., 2025; Octo Model Team et al., 2024) through perceptual and cognitive banks with token merging (Shi et al., 2026), event-triggered keyframes (Zeng et al., 2026), and keyframe retrieval by a trained planner (Sridhar et al., 2026). HAMLET summarizes each timestep into learned moment tokens and aggregates them with a lightweight tem-poral memory module (Koo et al., 2026). Harness VLA uses memory-guided primitives to steer frozen policies (Zhang et al., 2026b), while dual-system designs separate deliberation from control (NVIDIA et al., 2025; Figure AI, 2025; Shi et al., 2025). Reflexion, ExpeL, and AgeMem also retain experience for subsequent agent decisions (Shinn et al., 2023; Zhao et al., 2024; Yu et al., 2026). Component ablations can establish the utility of these complete designs; attributing that utility to a particular stored fact requires additional controls. History is not automatically useful evidence: causal confusion in imitation learning (de Haan et al., 2019) and the copycat problem (Wen et al., 39 Preprint 2020) show how policies can exploit historical correlates rather than the information needed for the next action. These motivate our attribution question without establishing that the same failure occurs in the systems we evaluate. 

Memory benchmarks. MIKASA-Robo (Cherepanov et al., 2026), RoboMME (Dai et al., 2026), and RMBench (Chen et al., 2026) evaluate memory-dependent robotic manipulation. RoboMME-Interference examines interference from other sessions (Rathi, 2026). LongMemEval and LoCoMo evaluate long-term conversational memory (Wu et al., 2025; Maharana et al., 2024). MemoryA-gentBench supplies incremental multi-turn evaluations, including FactConsolidation: an earlier fact is followed by a contradictory update, and answers should reflect the latest information (Hu et al., 2026). This is closely related to record validity and updating in IMEP. However, evaluating up-dated answers is different from comparing same-fact and different-fact replacements at a specified retrieval interface. ChainBench complements these benchmarks with a query observation that omits the deciding fact and separate decision and execution readouts. IMEP specifies comparisons at the retrieval interface, adding paired outcome-flip accounting and delivery checks to task-level evalua-tion. 

Interventions and attribution. Causal abstraction (Geiger et al., 2021), causal tracing and activa-tion patching (Meng et al., 2022; Zhang & Nanda, 2024), and causal scrubbing (Chan et al., 2022) test behavioral dependence on internal variables. The replacement distribution limits what such in-terventions identify (Chan et al., 2022; Zhang & Nanda, 2024). Embodied Interpretability connects visual interventions to VLA generalization (Zhang et al., 2026a). Present but Not Remembered ex-amines visual history in frozen VLAs (Liao & Cao, 2026). Negative controls can reveal confound-ing (Lipsitch et al., 2010), while randomized-parameter and randomized-label sanity checks test saliency methods’ dependence on learned models and data (Adebayo et al., 2018). These checks do not by themselves establish sensitivity to small memory-content effects. PoPE uses placebo controls to distinguish useful error content from presentation effects in code-model self-repair (Iscan, 2026). IMEP brings these control principles to embodied memory evaluation through paired success/failure flips and separate decision and execution evidence. Learned-bank studies measure closed-loop out-comes, whereas ChainBench’s shared recorded executions and separate scripted-reader test support the narrower interpretations stated in the main text. 

Equivalence and undetected effects. Nonsignificance does not establish that an effect is negligi-ble. Equivalence testing instead compares uncertainty with a specified effect-size interval (Lakens, 2017). Inference for paired proportions also depends on the paired design (Tango, 1998). IMEP retains study-specific tests and margins, distinguishes original verdicts from post hoc intervals, and interprets equivalence only for the interventions as delivered. A narrow interval for one contrast cannot establish complete memory delivery or rule out an untested mechanism. 

## K ADDITIONAL PROTOCOL DETAILS AND INTERPRETATION 

This appendix details the intervention implementation, validity checks, and separation of decision and execution readouts used in Section 3. K.1 PAIRING AND INTERVENTION IMPLEMENTATION 

The evaluation unit is a task–seed pair (a scope) or a multi-episode chain. Comparisons reuse the same units across conditions, but matching seeds alone does not guarantee identical physical exe-cution. Each study must specify the memory interface, intervention time, controlled variables, and source of execution randomness. Blocking reads assesses memory-access utility together with any computation it changes. Content substitutions instead hold the retrieval interface fixed at installa-tion. They do not guarantee identical subsequent computation or semantically identical non-target content. In cross-episode learned-bank studies, U , S, and T use an installation routine that C bypasses. Keys, slots, timestamps, versions, and selected counts are preserved initially, but subsequent merges can modify the payload. Thus U versus C does not isolate numerical perturbation alone, and a same-fact donor is not semantically identical to the recipient. Under Shell Game blackout, Sπ permutes and 

Tμ resamples retrieved latent values at each read. These operations preserve the selected record but 40 Preprint are not verified fact-preserving and fact-changing edits. Their contrast measures resampling versus permutation (Appendix E.1). K.2 READOUTS AND VALIDITY CHECKS

Information requirement. To establish that a task requires history, the deciding fact must be absent from the current observation, and success must require one choice among K options, preventing recovery by trying alternatives. When decisions are scored, we compare no-memory accuracy with 

1/K and report G = Acc O − Acc N . An interval containing chance is a compatibility check, not an equivalence test or proof that model weights contain no relevant information. The history-required check also asks whether the lower bound on G exceeds zero. Memory can still help when partial current-observation cues are available, but that supports a different claim. 

Intervention delivery. Verify scheduled reads in A and empty reads in N . Substitution coverage is the fraction of units whose every decision query selects at least one unmodified substituted record. Coverage of one satisfies this operational delivery check without proving that the reader uses the target fact. Coverage below one limits interpretation to swaps as delivered. Merged records may still retain substituted fields. Audits are post hoc unless a survival gate was registered (Appendix D.1). Without substitution traces, matching oracle accuracy is behavioral evidence, not direct verification of the memory path. 

Record validity. Vary persistence while holding other components fixed to test outdated facts. A comparison between whole configurations cannot attribute an effect to stale information alone. 

Measurement and decision rules. Report repeatability controls, confidence intervals, and study-specific detection limits. Original campaign verdicts and magnitude criteria remain unchanged. The retrospective Q3 rule requires the lower bound on ρX to exceed the exact-replicate floor; Q4 re-quires the lower bound on θ to exceed both zero and the upper bound on ρU , subject to the validity checks. Remember Color’s registered equivalence analysis uses a 90% interval within ±7.5 per-centage points, following the confidence-interval logic of two one-sided tests (Lakens, 2017). This concerns swaps as delivered and does not exclude smaller effects. Nonsignificance establishes nei-ther equivalence nor absence of memory use. The framework and its interpretation criteria were formulated after the campaigns closed (Appendix G.3). K.3 CHAIN BENCH READOUT AND EXECUTION 

The 202-chain study compares full memory with no memory, shuffled or stale records, an initial-fact baseline that ignores updates, and an oracle decision. Full memory retains the latest write and uses a calibrated presence gate, two-stage retrieval, and a leave-one-chain-out nearest-centroid readout, without a decision-time LLM call. The latest-write set is stipulated rather than produced by an evaluated eviction policy (Appendix C.1). This evaluates a memory configuration and readout, not autonomous memory maintenance. We report decision accuracy Acc X and task success SR X separately. Conditions share recorded executions within each chain. Consequently, making the same correct decisions as the oracle neces-sarily yields its observed success rate SR ∗ = SR O , an execution limit for those recorded trials. The descriptive approximation SR X ≈ Acc X SR ∗ additionally assumes that wrong choices fail and that execution success among a condition’s correct choices is represented by the oracle’s overall rate. Agreement within a success-rate interval is a consistency check, not validation of this assumption. Repeated physical executions vary, so the C/U/S/T ladder is evaluated separately on the scripted decision reader.
