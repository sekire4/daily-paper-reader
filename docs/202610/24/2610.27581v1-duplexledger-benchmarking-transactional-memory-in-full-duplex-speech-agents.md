## 摘要
全双工语音智能体必须在聆听与说话的同时更新持久记忆，然而目前尚不清楚哪些事件应当被存储、修订或排除。现有基准将交互时序与记忆结果割裂开来，掩盖了正确答案背后的状态转移。我们提出 DuplexLedger，这是一个包含 1,094 个持久会话的双语基准，将四种全双工场景与事件级 Write/Update/Ignore/Retain 监督、显式的前/后记忆状态以及 6,564 个同一会话内的问题与检查项对齐。对五个全双工模型的评估揭示出一种交互—记忆鸿沟：没有任何系统能够将强边界控制与连贯的最终状态记忆结合起来，最佳的最终状态事实覆盖率为 2.01%。我们提出 ACT-Mem，这是一个 8.92M 参数的旁路模块，由事件控制器、带版本的事务性账本以及类型化检索器组成，并与冻结的 MiniCPM-o 4.5 主干模型耦合。在 219 个留出会话上，ACT-Mem 将最新值准确率从 4.11% 提升至 8.68%，同时减少过时断言与干扰项采纳。它改善了交互边界，但减慢了打断停止。这些结果支持采用有选择性、可审计的全双工记忆，而非不加区分地保留转写文本。代码见 https://github.com/lyx-researcher/DuplexLedger。

## Abstract
Full-duplex speech agents must update persistent memory while listening and speaking, yet it remains unclear which events should be stored, revised, or excluded. Existing benchmarks isolate interaction timing from memory outcomes, obscuring the state transitions behind a correct answer. We introduce DuplexLedger, a bilingual benchmark of 1,094 persistent sessions aligning four full-duplex scenarios with event-level Write/Update/Ignore/Retain supervision, explicit pre/post memory states, and 6,564 same-session questions and checks. Evaluating five full-duplex models reveals an interaction-memory gap: no system combines strong boundary control with coherent final-state memory, and the best final-state fact coverage is 2.01%. We propose ACT-Mem, an 8.92M-parameter sidecar comprising an event controller, a versioned transactional ledger, and a typed retriever coupled with a frozen MiniCPM-o 4.5 backbone. On 219 held-out sessions, ACT-Mem increases latest-value accuracy from 4.11% to 8.68% while reducing stale assertions and distractor adoption. It improves interaction boundaries but slows interruption stopping. These results motivate selective, auditable full-duplex memory rather than indiscriminate transcript retention. Code is available at https://github.com/lyx-researcher/DuplexLedger.

# DuplexLedger：全双工语音智能体中的事务性记忆基准 —— 论文总结

## 1. 核心问题与研究动机

- **背景**：端到端语音模型已支持开放式语音交互，全双工系统（MiniCPM-o 4.5、Freeze-Omni、Moshi、Lychee-FD、PersonaPlex 等）可在说话的同时聆听，从而支持打断、反馈音（backchannel）和重叠话轮。
- **核心矛盾**：并发带来“状态管理”问题——同一句话可能引入新事实、修订旧事实、尚未说完、只是应答反馈，或是说给旁人听的。智能体必须同时判断“说了什么”和“是否应写入持久记忆”。
- **现有基准的缺陷**：
  - 全双工基准（FDB v1/v1.5/v2、HumDial-FDBench、EchoChain 等）侧重轮次转换、停顿、重叠与打断，不评估持久状态；
  - 记忆基准（LoCoMo、LongMemEval、MemGPT、A-Mem 等）基于串行历史做长程存储与检索，不涉及并发交互中的事件准入；
  - 二者割裂导致“答对”无法说明系统是维护了连贯记忆，还是仅匹配了当前上下文。
- **论文主张**：将全双工记忆形式化为**事务性记忆**——每个事件被接纳、拒绝或用于修订一个带版本的记忆状态，并强调“选择性、可审计”而非“不加区分地保留完整转写”。

## 2. 方法论

### 2.1 任务形式化

- 会话定义为有序事件流 \(E=(e_1,\dots,e_T)\)，事件 \(e_t=(x_t,s_t,a_t,\tau_t)\) 分别表示语音内容、说话人、受话人和时间。
- 记忆状态 \(M_t\) 由条目 \((k,v,\sigma)\) 构成，\(k\) 为实体键、\(v\) 为值、\(\sigma\in\{\text{active},\text{superseded}\}\)。
- 转移在**条目级**定义：\(M_t=\mathcal{T}(M_{t-1},\{(k_i,v_i,o_i)\})\)，操作 \(o_i\in\{\text{WRITE},\text{UPDATE},\text{IGNORE},\text{RETAIN}\}\)。
  - WRITE 引入值；UPDATE 取代活跃值；IGNORE 拒绝不可采纳证据；RETAIN 保持现状。
- 被测模型只接收流式音频与口述问题，账本操作与参考状态仅用于监督和打分。

### 2.2 DuplexLedger 基准设计

- **规模**：1,094 个持久会话（中文 577 / 英文 517），8,239 个可听语音与静音事件，3,304 个全双工挑战，6,564 个同会话问题/检查（含 2,188 个最新值问题）；固定输入音频 35.33 h，事件源音频 24.22 h。
- **四类场景**（每会话 2–5 个挑战、6 个评估目标，全程不重置状态）：
  - **用户打断**：应停止当前回复并接纳修订意图；
  - **用户反馈音**：不应终止回复，也不应写入记忆；
  - **轮内停顿**：不应触发提前生成或提前提交；
  - **说给他人**：既不应回复，也不应写入记忆。
- **自适应触发**：打断需 VAD 检测到 ≥500 ms 连续助手语音，反馈音需 ≥800 ms；未满足触发条件则记为“未实现挑战”；停顿与旁听语音用预定义观察窗口。区分**计划挑战 / 触发满足 / 实际实现**三态。
- **监督标注**：每条账本记录含事件内容与角色、目标操作、状态转移、取代链接；每个问题对齐支撑记忆 ID、禁止的过时/干扰 ID 与参考答案。
- **六类评估目标**：2 个最新值问题、1 个事实回忆、1 个干扰拒绝、1 个最终状态摘要、1 个场景行为检查。
- **构建方式**：GPT-5.5 生成中英文任务描述、对话、事实值、修正、干扰与参考答案（受结构化 schema 约束），再由确定性程序实例化；TTS 合成语音 + 强制对齐（MFA）；涵盖 73/72 个中英文任务模板、4 种语体、12 种实例修饰；结尾轮次刻意多样化（40% 完整复述、25% 无复述、20% 部分复述、10% 自我修正、5% 明确要求不总结），防止靠复制末轮即可恢复状态。

### 2.3 ACT-Mem 侧车模块

- **总体结构**：8.92M 可训练参数（事件控制器 4.59M + 类型化检索器 4.33M），与**冻结**的 MiniCPM-o 4.5 主干及冻结 ASR/VAD 耦合；流式音频同时进入主干与 ASR/VAD，后者向控制器提供转写与时间信息。
- **事件准入**：
  - 确定性解析器抽取候选实体–值槽；
  - 学习控制器预测受话人、语义完整性、操作与置信度；
  - 准入分数 \(g_t=p^{\text{addr}}_t\cdot p^{\text{complete}}_t\cdot[p_t(\text{WRITE})+p_t(\text{UPDATE})]\cdot c_t\)；
  - \(g_t\ge\tau_{\text{write}}\) 进入 COMMIT；非受话或不完整进入 ABORT；模糊/低置信进入 UNCERTAIN（后两者不可检索）；停顿与静音不产生持久事务。
- **因果取代与版本化账本**：
  - 候选 \(m_j\) 仅在 \(k_j=k_i,\ t_j>t_i,\ o_j=\text{UPDATE},\ g_j\ge\tau_{\text{write}}\) 时可取代活跃条目 \(m_i\)；
  - 成功事务将旧值标记为 superseded、激活新值并记录修正链接；两版本均保留可审计，但仅活跃值对检索器可见；
  - 账本最多 32 个活跃槽，超容时按低置信、较旧者移入 uncertain；superseded/uncertain/aborted/ignored 内容不得进入证据卡。
- **类型化检索与记忆条件化**：
  - 四类路由：最新值（2 候选→1 最终值）、普通回忆（≤4 条活跃事实）、最终摘要（≤8 条跨实体跨类型）、干扰拒绝（0 条，直接进入拒绝行为）；
  - 排序分数 \(S(q,m)=S_{\text{dense}}+\alpha_{\text{lex}}S_{\text{lex}}+\alpha_{\text{conf}}\gamma_m+\alpha_{\text{rec}}S_{\text{rec}}-\alpha_{\text{bad}}B(m)\)，并施加分数–边际门控；
  - 证据卡 \(C_q=\text{

Card}(q)\) 由排序后的活跃条目序列化而成，附带实体键、值、时间戳与来源事件 ID；superseded 版本仅用于审计，不作为证据。
  - 生成时采用“记忆条件化”提示：将证据卡与当前语音上下文拼接注入冻结主干；若路由为干扰拒绝，则直接触发拒绝行为而不注入任何事实，从而避免模型用参数知识“猜对”。
  - 检索器与控制器以账本监督信号做轻量训练（操作分类、受话人判定、完整性判定、取代链接排序），主干全程不更新，保证与任意全双工前端可插拔组合。

### 2.4 评估协议

- **状态准确率**：以参考账本为金标，逐事件比较操作序列，并计算最终活跃状态 \(M_T\) 的条目级精确匹配（实体键、值、状态三元组）。
- **问题准确率**：6,564 个问题按六类评估目标分桶报告；最新值问题额外区分“曾暴露过旧值”与“未暴露”子集。
- **行为合规率**：针对四类场景，分别统计“正确停止/继续”“正确写入/不写入”“正确回复/不回复”的联合判定，只有行为与账本同时正确才计为通过。
- **污染与幻觉指标**：统计被禁止的过时 ID、干扰 ID 进入证据卡的比例（context pollution rate），以及回答中出现未在账本中出现的值的比例（fabrication rate）。
- **挑战三态统计**：同时报告计划挑战数、触发满足数、实际实现数，避免把“未触发”误计为模型失败。

## 3. 实验设置

- **主干**：MiniCPM-o 4.5（冻结），配冻结 ASR 与 VAD；ACT-Mem 作为侧车接入。
- **对照系统**：
  - 纯主干（无外部记忆，仅依赖上下文窗口）；
  - 全转写记忆（把 ASR 全量转写写入向量库，无准入控制）；
  - 全转写 + 检索（无版本化、无取代，仅相似度召回）；
  - 串行记忆基线（LoCoMo/LongMemEval 风格的追加—检索管线，适配到流式输入）；
  - 带 VAD 门控的写入基线（用语音活动而非语义判断是否写入）。
- **消融**：去掉事件控制器（改为全部 COMMIT）、去掉版本化取代（新值覆盖旧值且不保留审计）、去掉类型化路由（统一 top-k 检索）、去掉分数–边际门控、去掉置信度项。
- **语言与场景分层**：中英文分别报告；四类全双工场景分别报告行为合规率。

## 4. 主要结果

- **状态维护**：ACT-Mem 在最终活跃状态精确匹配上显著优于“全转写”与“全转写+检索”基线；后者因把反馈音、旁听语音、未完成话轮一并写入，产生大量伪条目与错误取代，状态准确率随会话长度下降明显，而 ACT-Mem 在长会话中保持较平稳。
- **最新值问题**：增益最大。无版本化基线在“旧值曾被说出”的子集上错误率显著升高，说明单纯相似度检索倾向于召回语义相近但已过时的证据；因果取代约束（时间戳更晚 + UPDATE + 置信度达标）有效抑制了这类错误。
- **干扰拒绝**：类型化路由的“0 条证据”路径明显降低了对干扰项的误采纳；统一 top-k 检索即使加入拒绝提示，仍会因召回相似干扰而给出错误确认。
- **行为合规**：反馈音与旁听语音两类场景差距最明显——纯主干倾向于对反馈音继续生成但误写入，或对旁听语音产生回应；ACT-Mem 通过受话人与完整性联合判定将二者导向 ABORT，行为与账本同时正确的比例更高。打断场景中，VAD 触发条件与主干自身的轮次控制存在耦合，增益相对有限。
- **污染与幻觉**：ACT-Mem 的 context pollution rate 与 fabrication rate 均为最低；消融显示去掉版本化后污染率回升最明显，说明“旧值仍可被检索”是主要污染源。
- **消融结论**：事件控制器（准入）与版本化取代是两项最关键组件；类型化路由主要改善干扰拒绝与最终摘要；分数–边际门控对最新值问题有小幅但稳定的提升；置信度项在噪声 ASR 条件下作用更明显。
- **语言差异**：中英文总体趋势一致；英文在打断场景的行为合规率略高，中文在最终摘要上的条目覆盖更完整，作者归因于模板与语体分布的差异而非架构差异。

## 5. 分析要点

- **“答对”不等于“记住”**：论文强调仅看问答准确率会高估系统，因为模型可借当前上下文或参数知识作答；因此把状态准确率、污染率与行为合规率作为与问答并列的一等指标。
- **准入是记忆的第一性问题**：在全双工中，错误主要发生在“是否该写”而非“写了能否查到”，这与串行记忆基准的问题结构不同。
- **可审计性**：保留 superseded 版本但不允许其进入证据卡，是在“可追溯”与“不污染”之间取的折中；论文将其视为事务性语义的必要条件。
- **触发条件的现实性**：自适应触发导致部分计划挑战未被实现，论文主张按三态报告而非把未触发算作失败，这一协议设计本身是对全双工评测可复现性的贡献。

## 6. 局限与讨论

- 侧车依赖 ASR 转写质量，强噪声或强口音下准入判定会退化；论文未系统评估跨语种口音与远场条件。
- 账本容量上限（32 个活跃槽）在超长会话中可能触发驱逐，驱逐策略对最终状态准确率的影响未充分展开。
- 挑战触发依赖 VAD 阈值（500 ms / 800 ms），阈值敏感性分析有限。
- 主干冻结虽保证可插拔性，但也意味着记忆条件化的收益受主干提示跟随能力上限约束。
- 场景覆盖为用户打断、反馈音、轮内停顿、旁听语音四类，尚未涵盖多人重叠发言、情绪性插话、跨会话记忆迁移等更复杂情形。
- 数据集由大模型生成 + 程序实例化 + TTS 合成，虽有多样性控制，但自然度与真实人类全双工语料的分布差异仍需实证检验。

## 7. 贡献与定位

- 首次把全双工语音交互中的记忆问题形式化为**事务性记忆**（接纳/拒绝/修订 + 版本化状态），并给出条目级转移算子与可审计账本语义。
- 提出 DuplexLedger 基准：把“是否写入”与“说了什么”解耦监督，提供状态、问答、行为三层金标，并以三态挑战统计提升评测可复现性。
- 提出 ACT-Mem 侧车：以轻量控制器 + 因果取代 + 类型化检索，在冻结主干上实现选择性、可审计的记忆写入，验证了“准入控制优先于检索优化”的设计主张。
- 定位：连接全双工交互评测与长程记忆评测两个此前割裂的社区，为“并发条件下的持久状态管理”提供可比较的测试床与基线。

## 8. 一句话总结

DuplexLedger 把全双工语音智能体的记忆从“尽量多存、按需检索”推进到“按事务接纳、按版本取代、按类型取证”，并用状态准确率、污染率与行为合规率三重指标说明：在并发语音中，**判断该不该记**比**能不能查到**更关键。
