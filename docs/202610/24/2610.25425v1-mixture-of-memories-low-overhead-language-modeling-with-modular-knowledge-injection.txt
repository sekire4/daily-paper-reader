Experiments across language modeling, factual QA, update analysis, and efficiency show that MoM improves both predictive accuracy and updateability while retaining low inference overhead.

## 1. Introduction 

Large language models (LLMs) encode a substantial amount of world knowledge in their parameters (Allen-Zhu and Li, 2025). This capability follows from large-scale next-token prediction and is one reason pretrained LMs generalize well. Parametric knowledge, however, is a poor interface for knowledge-intensive prediction. Parameters are optimized to capture broad statistical regularities, not to give explicit control over how individual facts are stored, accessed, or updated. The mechanism that handles common linguistic and factual patterns therefore becomes unreliable when a prediction depends on precise, infrequent, or newly introduced knowledge (Chang et al., 2024, Gekhman et al., 2024, Ovadia et al., 2024), which leaves a gap between what an LLM absorbs during pretraining and what it can reliably use at inference time. This gap has at least three sources. A fact may be weakly represented because it is under-supported in pretraining, difficult to recover because the context does not elicit it, or stale because it changed after training. Existing approaches address these failure modes only partially. Parameter-side methods internalize new information into model weights, but frequent or repeated updates remain difficult to support cleanly (Wang et al., 2024c). External retrieval and token-level memory make updates easier but add search and context-processing overhead at inference time (Cao et al., 2026). Latent-space memory compresses information into hidden representations and can improve retention, but it is tied to model-specific representations (Wang et al., 2024b, 2025). Plug-and-play parametric memories imitate non-parametric retrievers with lightweight auxiliary modules, which improves portability and inference efficiency, yet they still expose a single auxiliary path with fixed interpolation (Cao et al., 2026, Wei et al., 2025). Because all of these mechanisms ultimately act through next-token prediction at inference time, their differences matter only insofar as they change the local prediction problem during generation. The need for extra knowledge is not uniform across positions. At many steps, the base LM is already sufficient: the next token is governed mainly by local syntax, common lexical patterns, or highly reinforced knowledge, so auxiliary support brings little benefit. The challenging cases are concentrated on a much smaller subset of positions where prediction depends on precise factual content, such as entities, numbers, dates, and other knowledge-bearing slots (Yao et al., 2025). Even there, the relevant deficiency is not always the same. Some errors reflect weak parametric support and call for a lightweight correction to the base prediction; others reflect a need for more explicit token-level guidance or direct access to facts introduced after pretraining. This makes a single global augmentation rule difficult to justify. If the same auxiliary correction is applied uniformly throughout generation, the model is forced to treat easy and difficult positions alike, and to use the same form of support for qualitatively different failure modes. A more natural formulation is to let knowledge support vary with the local prediction state, invoking different auxiliary paths only where they are likely to reduce token-level error. To bridge the gap, we propose Mixture-of-Memories (MoM), a memory-augmented language modeling framework that separates memory for stable prediction from memory for post-hoc updates. MoM combines a frozen base LM with two routed neural memory experts: a latent memory (LatM) that provides low-latency, retrieval-like corrections in hidden space, and a lexical memory (LexM) that operates in token space and is therefore less coupled to the backbone’s representations. A lightweight Budget Router assigns token-wise mixture weights over these stable sources from uncertainty and disagreement features. Mutable knowledge goes to an explicit memory (ExpM), an external store that is kept outside the router; it retrieves a stored fact once per question and injects its answer only when an answer-level gate judges the fact reliable. Facts are added by appending entries, without retraining the backbone, the neural memories, or the router. Our contributions are as follows:

## 2. Related Work 

Retrieval-augmented generation. Retrieval-augmented generation grounds predictions in external knowl-edge. RAG (Lewis et al., 2020) retrieves documents or passages, RETRO (Borgeaud et al., 2022) retrieves corpus chunks, and kNN-LM (Khandelwal et al., 2020) retrieves nearest-neighbor continuations from a datastore of activations. Recent work post-trains the reader to make better use of retrieved evidence, through hierarchical-thought instruction tuning in HIRAG (Jiao et al., 2025) or reinforcement learning with a cur-riculum in RAG-RL (Huang et al., 2025). These methods keep knowledge explicit and easy to refresh, but they shift cost to inference: online search adds latency, retrieved evidence lengthens the context, and large indexes or datastores require storage. MoM amortizes retrieval-like corrections into neural memory experts that are invoked through token-wise routing, and it reserves explicit lookup for a small store of written facts. 

Parametric long-term memory. Parametric memory methods reduce the serving cost of retrieval by compressing corpus-level knowledge into learned auxiliary modules. MLP Memory (Wei et al., 2025) uses an external MLP to mimic non-parametric retrieval, and Memory Decoder (Cao et al., 2026) attaches a plug-and-play decoder memory to a frozen language model. Both make memory access fast and model-compatible, but compressing knowledge into parameters gives up direct writability, one of the main advantages of retrieval: adding or revising facts requires retraining, re-distillation, or rebuilding the memory. MoM keeps parametric memories for stable, low-latency modeling and delegates factual updates to a separate explicit memory. 

Conditional computation and knowledge editing. Sparse mixture-of-experts models route tokens to experts to scale capacity (Shazeer et al., 2017, Fedus et al., 2022, Du et al., 2022). MoM instead routes among heterogeneous knowledge sources, namely the base LM, a hidden-space memory, and a token-space memory, for conditional memory access. For editing, MEND (Mitchell et al., 2022a), ROME (Meng et al., 2022), and MEMIT (Meng et al., 2023) modify model weights, whereas SERAC (Mitchell et al., 2022b), GRACE (Hartvigsen et al., 2023), and WISE (Wang et al., 2024a) store edits in auxiliary modules. ExpM is closest to the second group, but it writes facts as raw key–value entries without per-edit optimization. 

## 3. Methodology 

MoM is built on a separation principle: stable neural memories are routed, while mutable explicit knowledge is injected externally. The two kinds of memory serve different purposes. Neural memories are trained once and reused across inputs, which makes them suitable for token-level routing. Explicit memory is sparse, user-or time-dependent, and may be empty during router training but populated at test time. Latent memory. LatM removes the online nearest-neighbor search of retrieval-augmented LMs. Instead of searching a datastore at every token, it learns a parametric approximation of retrieval-style corrections in the hidden space of the base model: 

pLatM (yt ∣ ht) = softmax (GLatM (ht)) yt . (6) 

GLatM is a lightweight MLP-style memory module. It is trained by distilling retrieval-augmented teacher distributions and frozen afterwards, and it provides low-latency corrections when the base representation already contains enough signal to predict the needed retrieval behavior. 

Lexical memory. LexM complements LatM by operating in token space rather than in the hidden space of the base model: 

pLexM (yt ∣ x≤t) = softmax (Dec LexM (x≤t)) yt . (7) Because LexM consumes token IDs rather than hidden states, it does not depend on the representation geometry of a particular base model. LatM is efficient but base-specific, whereas LexM can be attached to another backbone with a compatible vocabulary (Appendix B.1). After training, LexM is frozen and becomes a stable source of the routed core. 

3.3. Budget Router 

The Budget Router decides when each stable source should influence the next-token distribution. It outputs a distribution over the routed core: 

log π(t) = LogSoftmax (Rψ( ft)) , (8) where π(t) = [πBase (t), πLatM (t), πLexM (t)] , Rψ is an MLP, and ft contains inexpensive uncertainty and disagreement features: 

ft = [ HBase (t), margin Base (t), JSD (pBase , pLatM )( t), JSD (pBase , pLexM )( t) ] . (9)

HBase is the entropy of the base distribution, margin Base is the gap between its two largest token probabilities, and JSD measures disagreement between distributions. The core mixture is computed in log space with the log-sum-exp operator, LSE m(am) = log ∑m exp (am):

log pcore (yt ∣ x≤t) = LSE m∈𝒞 [ log πm(t) + log pm(yt ∣ x≤t)] . (10) ExpM is deliberately absent from Eq. 8 because it is mutable and may be empty while the router is trained, so routing it would teach the router to suppress explicit memory. 

3.4. External Explicit Memory 

ExpM stores facts as writable entries. A fact consists of a question or prompt xi and its answer token sequence 

ai = (ai,1 , . . . , ai,Mi ). Each entry keeps a dense key ki, a TF-IDF vector ˜ki of xi, the answer ai, and a source record. Adding knowledge appends entries to the store ∆ and changes no parameter of the base model, LatM, LexM, the router, or the ExpM encoders. 

Query and key encoders. ExpM reads the frozen backbone rather than raw text. At position t it forms the feature 

zt = [ ht ; ¯ht ], (11) where ht is the backbone hidden state of Eq. 5 and ¯ht is the mean hidden state of the most recent valid tokens. Two separate towers Eq and Ek map this feature to L2-normalized vectors. The query q = Eq(zT) is taken at the last position T of the question, where the answer starts, and the key of a fact, ki = Ek(z(xi)) , is taken at the last position of its own question prefix. 

Retrieval. ExpM retrieves once per question, before the answer is generated. Each entry is scored by a convex combination of dense and lexical similarity, 

si = (1 − β) q⊤ki + 12 + β cos ( ˜q, ˜ki), (12) where ˜q is the TF-IDF vector of the question and β ∈ [0, 1 ] weights the lexical term. Rescaling the dense cosine to [0, 1 ] puts both terms on the same range. ExpM takes the highest-scoring entry i⋆ over the whole store as its answer candidate. The top-k entries 𝒩 under the same score serve to compute gate features. 

Answer-level gate. Retrieval always returns a candidate, including for questions whose fact is not in the store, so ExpM must decide whether to trust it. A logistic-regression gate estimates the probability that the retrieved answer is correct: 

g(x) = σ(w⊤ϕ(x) + b), d = 1[g(x) ≥ η]. (13) The features ϕ(x) are the retrieval score si⋆ (x), its margin over the second-best candidate, the lexical overlap between x and xi⋆ , the agreement among the answers in 𝒩 , and the probability that the routed core assigns to the first retrieved answer token, pcore (ai⋆,1 ∣ x). The last feature lets the gate weigh the retrieval evidence against the core’s own prediction.

Answer injection. The gate decision holds for the whole answer, with dt = d at every answer position. If the gate accepts, ExpM proposes the stored answer token by token, followed by the end-of-sequence token. At the j-th answer position, 

pExpM (yt ∣ x≤t, ∆) = 1[yt = ai⋆,j], (14) and Eq. 3 is applied with λt = 0.8 . Because pExpM is a point mass and λt > 0.5 , the proposed token always receives the highest probability, so greedy decoding reproduces the retrieved answer exactly; the overlay then acts as gated answer copying. If the gate rejects, dt = 0 throughout and the routed core generates the answer alone.

## 4. Experiments 

We first report factual QA results, then attribute the gains to individual memory channels, analyze how ExpM absorbs updates, and finally measure efficiency. Appendix B.1 reports the transfer of LexM across backbones. 

4.1. Experimental Setup Datasets. For language modeling we use WikiText-103 (Merity et al., 2017). For factual QA we evaluate on the full evaluation splits of NQ (Kwiatkowski et al., 2019), WebQuestions (WebQ; Berant et al., 2013), TriviaQA (Joshi et al., 2017), TruthfulQA (Lin et al., 2022), and HotpotQA (Yang et al., 2018). Wikipedia-2021 (Izacard et al., 2023) is the corpus for memory training, continued pretraining, the kNN-LM datastore, and RAG retrieval. Appendix A.1 and Appendix A.3 give dataset and metric details. 

Baselines. We compare MoM with the frozen base LM and with two groups of methods. The parametric group comprises full continued pretraining (CPT), LoRA (Hu et al., 2022), and MLP Memory (Wei et al., 2025). The retrieval group comprises RAG with a BGE retriever (Xiao et al., 2024) that prepends the top-5 Wikipedia passages, kNN-LM with a 50M-key datastore, and a paper-guided reproduction of RAG-RL (Huang et al., 2025). MLP Memory is reported for Mistral only. Its official release provides Mistral checkpoints but no Llama-3.1-8B checkpoint, and rebuilding its backbone-specific hidden-state datastore over billions of Wikipedia tokens exceeded our storage budget. Appendix A.2 specifies all configurations. 

Implementation. We use Mistral-7B-v0.3 (Jiang et al., 2023) and Llama-3.1-8B (Grattafiori et al., 2024) as the main backbones and GPT2-large (Radford et al., 2019) for controlled language-modeling attribution. All base LMs and trained memory experts are frozen during evaluation. For the QA benchmarks, ExpM holds question–answer pairs from the training split, and its retrieval weight β, gate, and threshold η are selected on dev folds held out from that split. Training the full stack takes about 1,800 GPU-hours on 8 ×H200 GPUs, a one-time cost broken down by stage in Appendix A.6.

## 5. Conclusion 

We presented Mixture-of-Memories (MoM), a memory-augmented language modeling framework that routes stable neural memories token by token and handles factual updates through a writable explicit memory outside the router. MoM lowers WikiText-103 perplexity and obtains the best average factual QA score on Mistral-7B-v0.3 and Llama-3.1-8B, with a lower time to first token than retrieval-augmented baselines. The

same populated store helps far more as an external overlay than as a routed source, and written facts take effect immediately while previously correct answers are almost all preserved. Future work can extend MoM to other knowledge-intensive NLP tasks and to settings where knowledge changes continuously. 

## Limitations 

The proposed method has two main limitations. First, the explicit memory selects a single fact for each question from the whole store: as the store grows, more entries compete for each query, which raises the chance that a wrong fact is retrieved and accepted, making the current design more suitable for targeted factual updates than very large memory stores. Second, although our results are strong on QA benchmarks, the present evaluation is still concentrated on knowledge-intensive question answering. Further validation on a broader set of NLP tasks is needed to assess the generality of the approach.

## A. Experimental Details 

A.1. Datasets and Splits 

WikiText-103 is used for GPT2-large language modeling. Wikipedia-2021 is used for memory training, CPT, the kNN-LM datastore, and the RAG corpus. The QA evaluation uses the full evaluation splits of Natural Questions (3,610 questions), HotpotQA (7,405), WebQuestions (2,032), TriviaQA (17,944), and TruthfulQA. For the update experiments, Dnew and Dold each contain 200 questions from the NQ-open training split, selected separately for each backbone (Section 4.4). The facts of Dnew are written into an initially empty store, and Dold is never written. We report score after all 200 writes. 

A.2. Baselines Parametric baselines. CPT updates all parameters of the backbone by continued pretraining with the language-modeling objective. LoRA (Hu et al., 2022) keeps the backbone frozen and learns low-rank updates to its weight matrices. MLP Memory (Wei et al., 2025) is a pretrained MLP that imitates the next-token distribution of a nearest-neighbor retriever, and its output is interpolated with the distribution of the frozen backbone. 

Retrieval baselines. RAG retrieves the top-5 Wikipedia passages for each question with a BGE retriever (Xiao et al., 2024) and prepends them to the backbone’s prompt. kNN-LM (Khandelwal et al., 2020) interpolates the backbone’s next-token distribution with the next tokens of the nearest stored contexts, retrieved from a 50M-key datastore stored with product quantization. 

Post-trained RAG reproduction. RAG-RL (Huang et al., 2025) trains the reader with reinforcement learning and curriculum learning. We implemented a paper-guided reproduction with a bge-base-en-v1.5 retriever, exact inner-product FAISS search over 200,000 uniformly sampled Wikipedia-2021 chunks, question-only queries, top-5 retrieval, greedy bf16 decoding, and seed 42, with Mistral-7B-v0.3 as the reader backbone. 

A.3. Metrics 

For open-domain QA, EM is computed after answer normalization and measures whether the generated answer exactly matches any accepted answer alias. F1 is the token-level overlap after the same normalization. We report F1 for NQ. For TruthfulQA, we use the official multiple-choice suite: MC1 measures whether the single best answer is preferred, MC2 measures the total probability assigned to true answers relative to false answers, and MC3 measures the fraction of true answers ranked above false answers. We report their average when a single TruthfulQA score is needed.

A.6. Training Cost and Deployment Overhead 

Training takes about 1,800 H200 GPU-hours once: about 400 for the kNN teacher targets, 1,100 for LatM distillation, 150 for LexM, 50 for the router, and 100 for preprocessing and pipeline overhead. The stages run sequentially with the base LM frozen, and afterwards new facts enter only through ExpM writes. With a 7B backbone, LatM (1.0B parameters, 2.0 GB in bf16), LexM (0.77B, 1.55 GB), and the 580-parameter router raise resident weights from 14.0 GB to 17.6 GB. The ExpM store has no trainable parameters, occupies about 15 MB, and grows with the number of written facts, whereas our product-quantized kNN-LM datastore occupies 3.2 GB. Both neural memories are MLPs that add about 6 ⋅ nlayer ⋅ dmodel ⋅ dff FLOPs per token, and ExpM retrieves once per question rather than per token.

B.2. Router Gate Interpretability 

To test whether the router learns non-trivial token-wise allocation, we group generated tokens into semantic, numeric, and syntactic categories, represented by ENTITY, NUMBER, and PUNCT tokens, and compute the average gate weight of each memory channel. The allocation depends on both the token type and the backbone. On Mistral, punctuation tokens are routed mostly to the base LM (gate weight 0.908 on PUNCT), while NUMBER tokens receive a larger LatM weight of 0.286, so LatM is used selectively on factual or numeric positions. On Llama, LexM dominates, with gate weights of 0.614, 0.698, and 0.749 on ENTITY, NUMBER, and PUNCT, while LatM receives only 0.7–1.2% of the mass. The router therefore adapts its memory usage to token semantics and to the quality of each channel on a given backbone rather than following a static interpolation rule. 

B.3. Case Study 

Figure 8 shows a case study. For the question of who was originally cast as Indiana Jones, RAG retrieves passages that contain both “Indiana Jones” and the phrase “originally was cast.” The retrieved evidence, however, states that Paul Picerni was originally cast in a different role. RAG copies this entity and answers “Paul Picerni,” the base LM answers “Steve McQueen,” and CPT, LoRA, and MLP Memory also return plausible but incorrect actors. MoM returns the gold answer, “Tom Selleck,” showing that ExpM can recover a written fact even when lexical retrieval is misled by entity and phrase overlap.
