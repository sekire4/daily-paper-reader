## ABSTRACT 

Memory-augmented assistants retrieve evidence from stored conversations and documents to answer queries. Most embedding-based retrievers compare single-vector representations of queries and memories, even when relevance depends on a small part of the content. Such local evidence can be matched to queries using the contextual token representations already computed by the same embedding models. Our method uses sparse token matching to improve retrieval without additional training. Each query token retrieves a small set of matching tokens across candidate memories. The matching scores are aggregated for each memory and combined with whole-memory similarity to rank memories. An optional low-rank query adapter can be trained with supervision while keeping the encoder and stored mem-ory representations fixed. Our method improves retrieval across eight benchmarks and multiple model families without additional training. Query adaptation further increases the gains to 13.3 and 14.3 percentage points in average Recall@10 and NDCG@10 on Qwen3-Embedding-4B. These retrieval gains translate into higher question-answering accuracy on long-term memory benchmarks. 

## 1 INTRODUCTION 

Memory retrieval enables assistants to answer questions using information from past conversations and stored documents (Maharana et al., 2024; Wu et al., 2025; Zhao et al., 2026). Existing retrieval approaches range from lexical methods that rely on word overlap (Robertson & Zaragoza, 2009) to semantic methods that compare learned representations of queries and memories (Wang et al., 2022). Among these, single-vector retrieval encodes each query and memory into a single embedding and uses embedding similarity to rank memories, supporting efficient indexing and search over large memory banks (Karpukhin et al., 2020; Zhang et al., 2025). The expressive limitations of single-vector retrieval have attracted both theoretical and empirical study (Weller et al., 2026). In practice, the information needed to answer a question may occupy only a small part of a memory, and different questions may depend on different parts. Single-vector retrieval scores relevance through whole-memory similarity without explicitly matching queries to fine-grained information within each memory. However, the same encoder already computes contextual token representations that can be used to match queries to such local evidence. Figure 1 illustrates how combining the resulting local scores with whole-memory similarity improves retrieval. These local matches illustrate the use of richer matching signals, a direction that existing work has explored alongside representation learning to improve retrieval. Context-aware representation learning methods, such as InSeNT and EvoEmbedding, incorporate surrounding information when learning retrieval representations (Conti et al., 2025; Nie et al., 2026). Search-Adaptor instead adapts the final embeddings produced by existing models (Yoon et al., 2024). On the matching side, multi-vector methods such as ColBERT score relevance through token-level matching (Khattab & Zaharia, 2020). Recent work further shows that existing single-vector models can support such matching by reusing their internal token representations (Zhang et al., 2026a). We introduce a memory retrieval method that uses contextual token representations already computed by a frozen embedding model. ## 2 RELATED WORK 

Long-term memory and retrieval. Long-term memory systems organize past interactions to support question answering. A-Mem links structured notes, while MemoryOS manages memories hierarchically (Xu et al., 2025; Kang et al., 2025). LightMem reduces processing costs through compression, consolidation, and offline updates (Fang et al., 2026). For retrieval, AssoMem combines associative links with relevance and temporal signals (Zhang et al., 2026b), while EvoEmbedding incorporates evolving context into retrieval representations (Nie et al., 2026). We instead improve retrieval within a fixed memory bank using token representations from a frozen encoder. 

Single-vector representation learning. Single-vector models learn a shared embedding space for efficient comparison of queries and candidates. Sentence-BERT uses siamese networks to learn sentence embeddings (Reimers & Gurevych, 2019), while E5 scales contrastive pre-training with weakly supervised text pairs (Wang et al., 2022). Qwen3-Embedding builds on pretrained language models to support multilingual, instruction-aware retrieval (Zhang et al., 2025). These approaches improve the final embedding through representation learning. Our method instead uses the contextual token states of an existing encoder alongside its final embedding, without changing the encoder. 

Contextual and multi-vector retrieval. Context-aware chunk methods preserve surrounding infor-mation in local representations (Günther et al., 2024; Conti et al., 2025), while BERT-MaxP scores query–passage pairs and takes the maximum (Dai & Callan, 2019). ColBERT and ColBERTv2 use token-level late interaction (Khattab & Zaharia, 2020; Santhanam et al., 2022b). Other methods use compact multi-vector representations (MacAvaney et al., 2025; Yu et al., 2026; Xiao et al., 2026; Qin et al., 2026) or improve late-interaction search (Santhanam et al., 2022a; Scheerer et al., 2025). SMART reuses frozen hidden states with MaxSim and pooled-score fusion (Zhang et al., 2026a). XTR studies token retrieval and missing-score estimation (Lee et al., 2023). Retrieval adaptation. Adaptation can operate on final embeddings or on the token states used for matching. Search-Adaptor learns task-specific mappings on top of existing embeddings (Yoon et al., 2024). Query-only adaptation preserves the document index, as studied in enterprise retrieval (Jain et al., 2026); ERA further aligns query and document embedding spaces before supervised query-side adaptation (Maekawa et al., 2026). SMART explores lightweight adaptation of token representations for late interaction (Zhang et al., 2026a). Our optional low-rank adapter updates only the local query branch, leaving the whole-memory scoring branch and stored memory representations unchanged. 

## 3 METHOD 

Overview. Our retrieval method has three stages, as illustrated in Figure 2. First, each memory is encoded once by the frozen model, and its contextual token states are stored with their source-memory ID. Second, query states retrieve a sparse set of matching memory tokens, whose scores are aggregated by those IDs. Third, the resulting local evidence is fused with the frozen pooled score to rank the memories. An optional query adapter changes the second stage without modifying the encoder or stored bank. 3.1 PROBLEM FORMULATION AND THE FIXED MEMORY BANK

## 4 EXPERIMENTAL SETUP 

Benchmarks. We evaluate our method on retrieval and downstream question answering. For retrieval, LoCoMo, LongMemEval, and REALTALK cover conversational memory (Maharana et al., 2024; Wu et al., 2025; Lee et al., 2025). The other five benchmarks cover financial reports (ESG-Reports), scientific papers (QASPER and PeerQA), biomedical text (CovidQA), and long documents (MLDR) (Macé et al., 2025; Dasigi et al., 2021; Baumgärtner et al., 2025; Möller et al., 2020; Chen et al., 2024). For downstream question answering, we use LoCoMo and LongMemEval to assess whether retrieval improvements translate into better answers using past conversations. 

Baselines. Same-backbone baselines include Original embedding, Search-Adaptor (Yoon et al., 2024), Chunk-MaxP, and MaxSim. Chunk-MaxP uses MaxP aggregation (Dai & Callan, 2019) over independent chunk representations, taking the highest score per memory. MaxSim applies ColBERT’s late interaction to frozen token representations (Khattab & Zaharia, 2020). BM25 + Original combines BM25 and original embedding scores using our query-wise normalization and equal weighting. Standalone baselines include BM25, ColBERTv2, XTR, and ConstBERT (Robertson & Zaragoza, 2009; Santhanam et al., 2022b; Lee et al., 2023; MacAvaney et al., 2025). Multi-vector systems retain their native encoders and retrieval configurations. Ours (training-free) and Ours 

denote our method without and with query adaptation, respectively. The eight frozen backbones are Qwen3-Embedding (0.6B/4B/8B) (Zhang et al., 2025), NVIDIA Llama-based models (1B/3B/8B), EmbeddingGemma-300M, and Jina-Embeddings-v5-text-nano. Same-backbone comparisons use identical query and memory inputs. 

Implementation Details. We average capped Recall@10 and NDCG@10 equally across eight benchmarks. We use uncompressed token indexes and HNSW search (Malkov & Yashunin, 2020), with k = 64 and α = 0 .5. Trainable methods share the EvoTrain-derived source training and validation split (Nie et al., 2026). Model selection uses only source validation data, and trainable retrieval results average three training seeds. For downstream question answering, we compare Original embedding with our adapted method using Qwen3-30B-A3B-Instruct as the answering model and GPT-4o-mini as the fixed judge. The main comparison retrieves 10 memories; budget analysis varies K over {4, 8, 10 , 16 }. Appendices A, B, and F provide detailed protocols.

## 6 CONCLUSION 

Existing contextual token representations support local matching, but single-vector scoring does not directly use them. Therefore, we introduced a method that combines sparse token matching with whole-memory similarity using a frozen embedding model. Experiments across eight models and eight benchmarks showed gains in Recall@10 and NDCG@10 without additional training. Optional query adaptation kept the encoder and memory index fixed, and the adapted method also improved downstream question-answering accuracy. Compression reduced storage and latency relative to the uncompressed index while retaining most retrieval gains. Our method thus made fuller use of the fine-grained retrieval capabilities of existing embedding models. 9Beyond the Final Embedding: Retrieving Memories from Token-Level Evidence

Evaluation protocol. We use Qwen3-30B-A3B-Instruct-2507 as the answering model and GPT-4o-mini-2024-07-18 as the judge. The main comparison retrieves K = 10 memories; the budget analysis uses K ∈ { 4, 8, 10 , 16 }. Memory construction and task-specific prompts follow EvoEmbedding (Nie et al., 2026). One API-rejected input for Qwen-8B Ours on LongMemEval was answered locally with the same named reader’s BF16 weights and greedy decoding, then scored by the same API judge; all other answers used the API reader. 

Metrics. Native retrieval uses Recall and binary-relevance NDCG on 1,533 LoCoMo questions with resolved evidence labels and 470 non-abstention LongMemEval questions. Question answering retains all 1,540 and 500 questions, respectively, with question-weighted overall accuracy and F1. LoCoMo F1 follows its category-aware evaluation code. LongMemEval F1 is a supplemental lexical metric applying the same normalization and stemming to the full predicted and reference answers, including abstention questions. 16
