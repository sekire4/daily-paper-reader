Abstract 

Context-to-LoRA methods encode documents as low-rank parameter updates, allowing lan-guage models to answer without retaining the source text in their decoding context. How re-liably do these updates preserve facts and sup-port their use under different instructions? Con-trolled diagnosis of existing context-to-LoRA methods separates fact discrimination, target retention, and response adaptation. Competing sources influence answers, while target-only construction and memory-state optimization improve recovery at fixed update size. Re-covering facts also does not ensure that an-swers follow response instructions. We in-troduce Cache2LoRA, which uses each query to aggregate evidence from a reusable frozen document cache before generating LoRA up-dates. Trainable encoding operates only on the query and memory-token suffix, and multi-style supervision teaches both evidence preser-vation and answer expression. Across 17 tasks, Cache2LoRA improves on existing context-to-LoRA methods and achieves macro F1 of 0.663, approaching full-context in-context learning at 0.671. For 32K documents and 256-token out-puts at batch size 16, its decoding throughput is 5.9 × that of full-context ICL. At matched mem-ory size, generated LoRA preserves answer accuracy more reliably than the learned-KV variant under long, diverse intervening text and combines more effectively with retained docu-ment KV, yielding higher hybrid F1 and EM. 

1 Introduction 

Parameter memory represents document informa-tion as weight updates rather than additional tokens in the answering context. Recent writers gener-ate LoRA updates in a forward pass, avoiding per-document gradient optimization (Charakorn et al., 2026; Liu et al., 2026). This offers a way to carry document information into the model’s computa-

tion without attending to document positions dur-ing decoding. Can these generated updates pre-serve the right facts and support their use under different response instructions? We diagnose D2L and SHINE along three di-mensions: fact discrimination, target retention, and response adaptation. Our source-substitution exper-iments link borrowed answers to competing facts. When we restrict writing to the passage relevant to the question, factual recovery improves without increasing the update size. Optimizing the writer’s memory states also improves recovery at fixed out-put size. These controls suggest that the difficulty lies partly in determining which information to write, beyond how much the update can hold. We also find that D2L can recover reference content without adopting the requested answer form. Effec-tive internalization requires selecting relevant facts and learning to express them as instructed. For fact selection, the query supplies information that document-only writers lack: what the reader needs from the document. This motivates using the query during writing, but the resulting construction cost must be paid for every question. Within param-eter memory, Doc-to-Atom enables query routing but requires semantic decomposition and compila-tion into LoRA units beforehand (Diao et al., 2026). AAG first generates a synthetic document and uses it with the query to produce adapters, coupling parameter construction to an additional context-generation stage (Liao et al., 2025). Activation-based compressors instead produce compact em-beddings or KV states. OSCAR, QGC, and ATA-Compressor jointly encode document content with each query, repeating document encoding when another question concerns the same source (Louis et al., 2025; Cao et al., 2024; Li et al., 2025a). We propose Cache2LoRA , which generates query-specific LoRA directly from a reusable cache of the supplied document. A frozen backbone pre-fills the document once, without semantic atom-1arXiv:2610.24107v1 [cs.AI] 16 Oct 2026 ization or synthetic-context generation. For each question, trainable encoding acts only on the query and appended memory tokens, aggregating relevant information without re-encoding the document. A generation head converts these states into LoRA updates for the answerer. Multi-style teacher su-pervision supports both factual recovery and varied response instructions, while a retention objective limits interference on unrelated inputs. New docu-ments and queries require no gradient optimization. Across 17 tasks, Cache2LoRA reaches macro F1 of 0.663, approaching full-context ICL’s 0.671, and improves on released D2L, Cache2LoRA-TF, and further-trained D2L. Cached construction avoids repeated document encoding. For 32K documents and 256-token outputs at batch size 16, decoding throughput reaches 5.9 × that of full-context ICL. Generated LoRA also shows two advantages over directly using the learned memory tokens as KV states at matched memory size. First, it preserves answer accuracy more reliably under long, diverse intervening text, keeping query-specific document memory usable after construction. Second, it com-plements retained document KV more effectively, yielding higher hybrid F1 and EM across both se-lectors and all tested budgets. 

2 Related Work 

2.1 Context-to-LoRA Generation 

Context distillation transfers source-conditioned behavior into parameters (Snell et al., 2022; Cac-cia et al., 2025), while hypernetworks predict up-dates from task or input representations (Ha et al., 2016; Karimi Mahabadi et al., 2021; Ivison and Peters, 2022; Phang et al., 2022). Our writer com-bines generated adaptation with distillation. D2L maps document latents to LoRA, and SHINE maps memory-token states to updates (Charakorn et al., 2026; Liu et al., 2026). Both write before seeing the query. Our diagnoses of factual recovery and response adaptation motivate query-guided writing. Parametric RAG and Doc-to-Atom select pre-compiled parameter memories (Su et al., 2025; Diao et al., 2026), whereas we generate an update for each query. AAG constructs adapters from syn-thetic context (Liao et al., 2025), while we use the supplied document’s cache. Override adjusts gen-erated updates to resolve conflicts with pretrained knowledge (Cheng et al., 2026). We instead train the writer to select facts and express answers. 

2.2 Fast Weights and Test-Time Adaptation 

Fast-weight programmers write input-dependent weights, encompassing certain linear-attention up-dates (Schlag et al., 2021). Our writer likewise generates dynamic parameters, specifically LoRA updates for a pretrained answerer. Test-time train-ing optimizes parameters during inference (Sun et al., 2020; Hardt and Sun, 2024). TTT layers use a trainable model as recurrent state, and Titans up-dates neural memory at test time (Sun et al., 2024; Behrouz et al., 2025). Cache2LoRA instead gener-ates updates from cached document states without test-document gradients. Forward generation is also used in fast-weight systems. 

2.3 Context Compression 

Text selection and learned activation memories pro-vide alternatives to parameter storage (Jiang et al., 2024; Mu et al., 2023; Ge et al., 2023; Chevalier et al., 2023). We use CCM and 500xCompres-sor as KV controls (Kim et al., 2024; Li et al., 2025b). OSCAR, QGC, and ATACompressor con-dition compression on the query (Louis et al., 2025; Cao et al., 2024; Li et al., 2025a), but jointly en-code document content with each question. Our writer reuses document states. We also compare with released OSCAR on Mistral. KV eviction selects existing states (Zhang et al., 2023; Xiao et al., 2024; Li et al., 2024; Zhang et al., 2026; Kim et al., 2026), whereas our writer aggre-gates document information into new parameter updates. Cartridges and related studies compare KV and parameter memories optimized for a cor-pus or document (Eyuboglu et al., 2026; Rakotoni-rina et al., 2026). Our comparison instead uses forward-generated, query-specific memories.

4.1 Query-Guided Memory Construction 

A frozen copy of the answering backbone reads 

D once with encoding LoRA disabled, storing its layerwise keys and values as C(D). This cache is reused across queries about D. For each q, we process the query followed by M learned memory tokens as a suffix attending to C(D).An encoding LoRA , shared across documents and queries, adapts the attention and feed-forward projections for this suffix. Each memory token attends to the cached document, the query, and preceding memory tokens, combining document content according to the question. We denote its hidden state at layer ℓ and memory position m by 

hℓ,m . The default writer forms states per query without external relevance scores or attention bias. Document states remain fixed during this pro-cess. New token projections and feed-forward com-putation are confined to the suffix, although suffix attention still accesses the full cache. Its cost there-fore still grows with document length. 

Training-free variant. We also introduce Cache2LoRA-TF, a training-free variant that applies query guidance to a pretrained writer. A frozen matcher scores document positions for the query. These scores bias the writer’s extraction attention toward relevant content, and its existing generator converts the aggregated states into LoRA. Our main implementation uses released D2L with all writer parameters fixed. Appendix C.2 details this variant and its extension to SHINE. 44.2 Generating and Applying LoRA 

In the full model, we generate answering LoRA from the learned memory states at each layer ℓ:

zℓ,m = Pℓ LN( hℓ,m ),

(Aℓ, B ℓ) = Gℓ(zℓ, 1: M ),

∆Wℓ = BℓAℓ.

(1) Here Pℓ projects each state into the generator’s latent space. The generator Gℓ uses a residual MLP, normalization, and a linear head to produce scaled LoRA factors. Each memory state supplies one rank component. We apply ∆Wℓ to the answerer’s 

down_proj weights at layer ℓ.The encoding LoRA is learned during training and reused to construct memory. The answering LoRA is generated for each document–query pair to supply information to the answerer. 

Answering. The answerer receives the query and response instruction with the generated update ap-plied. In standalone use, its decoding context con-tains neither the document nor the writer’s memory tokens. The same update can also supplement doc-ument KV retained by SnapKV or DropKV (Sec-tion 5.5). New documents and queries require only forward passes through the trained writer. 

4.3 Multi-Style Supervision 

To train the full model, we use the same frozen backbone as a teacher conditioned on the full doc-ument and query. It generates answers under var-ied instructions, including short answers, complete sentences, and explanations. The student uses the generated LoRA and the corresponding answering prompt, without the document. At each teacher-answer prefix, we match the student’s next-token distribution to the teacher’s using forward KL (Hin-ton et al., 2015). These targets teach content and answer form without passage labels. 

Preserving base behavior. Generated LoRA changes the answerer’s computation wherever the update is applied. We therefore combine answer distillation with a retention objective, 

L = LKL + λretain Lretain . (2) Here LKL is the tokenwise distillation loss above. On unrelated text, Lretain matches predictions with the generated update to those of the unmodified backbone. It limits interference with base-model behavior, a concern also observed for document-trained LoRA (Eyuboglu et al., 2026). 

Training. We jointly train the memory embed-dings, encoding LoRA, projections, and parameter generator. Gradients pass through the answerer to the generated factors and writer, while backbone weights remain frozen. Our default uses rank-32 encoding LoRA and M = 8 memory tokens to gen-erate rank-eight answering updates. Training runs for 2,000 steps with λretain = 0 .3. Appendix A details data construction and training settings. 

5 Experiments 

5.1 Setup Tasks and metrics. We evaluate 17 tasks span-ning FactSet, Wikipedia, SQuAD (Rajpurkar et al., 2016), DROP (Dua et al., 2019), NewsQA (Trischler et al., 2017), TriviaQA (Joshi et al., 2017), Natural Questions (Kwiatkowski et al., 2019), and LongBench (Bai et al., 2024), including HotpotQA (Yang et al., 2018). We report token F1, exact match (EM), and ROUGE-L Recall (R-L) for reference coverage. Tasks receive equal weight. 

Baselines. The Qwen3-4B comparison in-cludes released D2L, further-trained D2L, and full-context ICL. We also evaluate Cache2LoRA-TF, our training-free variant using frozen D2L. The Mistral comparison adds OSCAR. Main results use the same short-answer instruction. SHINE is evaluated on its released Qwen3-8B backbone in the diagnoses and the Cache2LoRA-TF extension. Appendix A.4 details the baseline settings. 

KV baselines and state budgets. We compare with SnapKV, DropKV, Fast KVzip, and our re-productions of CCM and 500xCompressor (Ap-pendix A.4). Their budget equals 48 KV posi-tions, matching Cache2LoRA’s 6.75 MiB output. Selected-KV baselines recompute the instruction and query over compressed document KV before answering. Budgets exclude prompt states, model weights, and construction caches.

5.5 Hybrid Answering 

Prior work combines document-trained LoRA with compressed KV (Zuo et al., 2026). We test gener-ated updates with document positions selected by SnapKV or DropKV. Both selectors use the query. All conditions process the instruction and query again over the selected cache, including controls without LoRA. The writer and selectors are com-bined without joint training (Appendix A.6). 

LoRA combines better with selected KV on F1 and EM. We replace LoRA with Memory Tokens KV while keeping the selected document cache fixed. Both add 6.75 MiB. Across all tested budgets, LoRA gives higher F1 and EM with both SnapKV and DropKV (Figure 8). Memory Tokens KV has higher R-L at all three budgets. 

The update’s source and query matter. Hold-ing the selected cache and answering procedure fixed, enabling Cache2LoRA improves F1 with both selectors. Replacing it with an update from another document lowers performance below KV-only answering. An update for a different query about the same document also underperforms KV-only answering on the matched subset (Table 24). 5.6 Efficiency 

On one H200, we measure one-time document caching, time to the first answer token after caching, and batch-16 decoding with 256 output tokens. 

Caching benefits long documents. Relative to re-encoding on the same backbone, Cache2LoRA reaches the first answer token 2.1 × faster at 4K, 6.6 × at 16K, and 12.2 × at 32K (Figure 9a). The control re-encodes the document and suffix for each question. These ratios exclude one-time document caching, which costs 1,820.6 ms for Cache2LoRA at 32K and is shared across queries (Table 27b). At 32K, cached 16-token answering is 4.6 × faster than the re-encoding control (Table 27c). 

Compact memory benefits long-document batch decoding. As document length grows from 4K to 32K, Cache2LoRA throughput changes from 596 to 560 tokens/s, while full-context ICL drops from 512 to 95 tokens/s. The resulting speedup grows from 1.2 × to 5.9 × (Figure 9b). At 32K, per-request decoding state is 12.52 MiB versus ICL’s 4,613.91 MiB, excluding the separately retained document cache. SnapKV and DropKV remain faster at 606 and 601 tokens/s with the current inference infrastructure. Merging LoRA into the weights avoids memory-prefix attention, but our measurements execute adapter factors separately for each request. 6 Conclusion 

We diagnose fact discrimination, target retention, and response adaptation in document-to-LoRA writers. Source interventions and fixed-capacity controls motivate query-guided information aggre-gation, while instruction probes motivate supervi-sion of answer expression. Cache2LoRA combines these choices with reusable document caching, im-proving on released D2L, Cache2LoRA-TF, and further-trained D2L. Its generated updates also sup-plement selected document KV, with gains persist-ing at larger retained-context budgets. At matched memory size, generated LoRA shows two strengths relative to the learned-KV variant: it preserves answer accuracy more reliably under long, diverse intervening text and complements retained document KV more effectively, yielding higher hybrid F1 and EM across both selectors and all tested budgets. These results support generated parameter memory for interference-resistant recall and hybrid answering. 8Limitations 

Cache2LoRA constructs a new LoRA update for each query. The full document cache is needed during construction, while decoding uses the com-pact output. The cache can be stored on CPU be-tween construction calls, though our measurements use GPU-resident caches and do not include trans-fer latency. Per-query construction adds prepara-tion time and transient GPU memory. We report preparation latency, decoding-state size, and the document-prefill peak allocation increment (Ap-pendix D.6), rather than a total deployment peak including all resident models and caches. Our ex-periments assume fixed source documents. Main-taining caches and constructed memories as docu-ments are revised remains future work. The current evaluation considers individual queries. In multi-turn interactions, relevant context can change as a conversation develops, creating choices about when to retain, refresh, or replace a constructed memory. We leave the design and evaluation of these memory management policies for conversational use to future work. Finally, the writer constructs each update from the context available for a query. Our hybrids com-bine this output with selected document KV. Com-posing memories constructed independently from separate documents is a distinct setting that we have not evaluated. Such composition requires deciding which memories to combine and how to reconcile conflicting information across them. 

Ethical Considerations 

This work studies document memory using existing public benchmarks, synthetic facts, and pretrained language models. Their use remains subject to the original licences and access conditions. Com-pression into LoRA or KV states should not be treated as anonymization: either form may pre-serve sensitive source information and reproduce it in answers. Applications should use authorized documents, control access to derived memories, and account for source deletion or correction. Gen-erated answers may also retain errors or biases from the source text and backbone. Generative AI tools assisted with analysis code and manuscript editing. The authors remain respon-sible for the methods, results, and final text.

A.1.1 Sources and Input Construction 

Training uses the training splits of SQuAD, DROP, ROPES, and PwC, together with synthetic facts. Natural inputs group questions by document. Hot-potQA, 2WikiMultihopQA, and MuSiQue are ex-cluded from the training corpus. Table 4 re-ports source documents and queries before and after teacher-response filtering; multiple teacher re-sponses do not count as additional source records. 

Document construction and separation. We combine single passages with multi-passage inputs containing related facts or distractors. Synthetic documents include competing facts, shared subjects, biographies, and relational questions. Training inputs are limited to 3,072 tokens. Before teacher generation, overlap checks exclude matches to evaluation and calibration material using passage overlap and query similarity. Synthetic names and templates are also separated from held-out pools. Long natural documents combine four to six source units, with at most two questions per unit and up to eight questions per document, plus shuffled filler passages, targeting 1,500–3,072 tokens. Long synthetic documents contain 16–26 fictional people and four to eight one- or two-hop questions. Construction uses seed 1009. A separate calibration set monitors training, and all reported models use the final checkpoint. Appendix A.2 reports the overlap audit. 

Overlap thresholds. For overlap checks, text is lowercased and reduced to sequences of word char-acters. A passage is excluded if at least 10% of its word 13-grams, or at least 50 such occurrences, appear in the evaluation/calibration exclusion in-dex. Exact matches to indexed short passages or sentences of at least six words are also excluded, along with matched source titles where available. A question is excluded when its normalized text matches exactly, or its word-trigram Jaccard sim-ilarity is at least 0.6, and an accepted-answer pair has token F1 of at least 0.5. These checks are re-peated on the constructed documents. Synthetic question templates are additionally compared after replacing capitalized names by a placeholder and digit sequences by zero. Matching templates are removed, and synthetic documents with fewer than three remaining questions are discarded. Source passages may recur across training constructions, but long natural-document variants use previously unused normalized questions. The two style vari-ants of each document are retained intentionally. 

A.1.2 Teacher Responses and Sampling Teacher prompting. A frozen teacher produces responses in eight styles: evaluation short answer, original D2L, direct answer, explicit short answer, entity or number, complete sentence, extractive span, and brief explanation. Before compatibil-ity filtering, their sampling probabilities are 0.20, 0.15, 0.15, 0.10, 0.12, 0.12, 0.10, and 0.06, respec-12 tively. For each query, two compatible styles are sampled sequentially without replacement, renor-malizing these weights over the remaining eligi-ble styles. Extractive styles require a verbatim accepted-answer span, excluding the base DROP and ROPES sources and yes/no answers. Entity styles require an accepted answer of at most five words and exclude yes/no, why, and general how questions. Count questions additionally require an answer span in the document. PwC uses direct-answer and D2L styles. The single-style controls use either short-answer-only or original-D2L re-sponses, with the same sampled training data and training budget as the multi-style model. During distillation, the student answers without the docu-ment using the corresponding response style. 

Filtering and training mixture. Teacher genera-tion is greedy with a 256-token limit. We remove empty, truncated, or unsuitable responses and fil-ter short-answer targets against accepted answers; PwC is exempt from the short-answer correctness filter. After normalizing thousands separators and English number words from zero to twenty, a re-sponse is removed if it has zero token F1 against all accepted answers and contains none of them. Refusals without an accepted-answer match and queries shorter than three characters are also re-moved. Documents with no retained questions are discarded. Retained variants are pooled without additional source weighting and reused through-out training. The D2L-style control uses the same construction pool and filtering rules. Gemma gen-erates its own teacher responses from this pool and applies the input limit with its own tokenizer. Table 5 gives the teacher templates. Table 6 lists the 22 closed-QA wrappers used in the three legacy styles. For the three legacy styles, the student re-ceives the wrapped question alone. For the remain-ing styles, it receives the same instruction and raw question with the document prefix removed. 

A.2 Evaluation and Scoring Datasets and cohorts. The main benchmark con-tains 17 tasks. FactSet and Wikipedia tasks use 304 questions each, document QA and constructed multi-document tasks use 300, and LongBench tasks use 200 (150 for MultiFieldQA-en). The duplicate non-LongBench HotpotQA task is ex-cluded. Cross-writer comparisons use the common thirteen-task cohort without LongBench. Compar-isons align questions and accepted answers, and task averages receive equal weight even when re-lated tasks are grouped for display. Qwen evalua-tions use complete benchmark inputs. 

Concatenated inputs. SQuAD-4 combines an answer paragraph with three others from the same article, SQuAD-Mix groups shuffled paragraphs, and NQ-4 combines answer passages from different queries. Each question receives a separate update constructed from the concatenated input. 

Answering instructions. Unless varied ex-plicitly, comparisons use the D2L short-answer instruction: “Answer the following question. Output only the answer and do not output any other words.” Generation is greedy with a 256-token limit. Response-adaptation tests instead request an entity or number, one complete sentence, a brief explanation, or use the question alone. Documents, factual questions, and generated memory remain fixed while the answering instruction changes. The writer receives the raw question, without the varying response instruction. Qwen sweeps cover the main tasks. Cross-method averages cover thirteen shared tasks. Qwen/Gemma comparisons use three untruncated tasks. 

Metrics. We report normalized token F1, exact match (EM), and ROUGE-L Recall (R-L). R-L measures reference coverage, while containment credits an accepted answer appearing anywhere in the response. Scores take the best accepted refer-ence and are averaged equally across tasks. Short responses contain at most five words. Conditional brevity is measured among responses with full ref-erence coverage, excluding tasks without such re-sponses. Longer answers are scored against the same short-answer references, so their accuracy is interpreted alongside length and coverage. Response-length span is the difference between the longest and shortest task-average responses across instructions, divided by the correspond-ing ICL span. Normalization matches backbones, tasks, and instructions: four on Qwen, and short answer plus explanation on Gemma.

A.5 Diagnostic Protocols 

The probes hold target questions fixed while chang-ing source content, construction, or answering instructions. Target-only controls use annotated supporting evidence; directly optimized reference adapters preserve the size and structure of gener-ated updates. Internal probes use D2L on Qwen3-4B unless stated otherwise. 

Fact discrimination and repair. Wikipedia probes add competing people or replace their facts. Birth-year responses are classified by the first year as correct, borrowed from another person, or other, with correctness taking precedence when years co-incide. Source interventions alter the borrowed source or average its memory values, using another source as a control. The intervention cohort con-tains 192 questions; the repair cohort contains 304. Repair counts track the same baseline-borrowed cases, and gold labels are used only for evaluation. 

Target retention. Synthetic probes hold 64 target questions fixed while adding same-type facts, other-type facts, or empty content. Target amplification restores the target’s isolated attention share without renormalizing or directly suppressing distractors. Value averaging replaces distractor values by their mean while retaining their keys; gold-support bias 16 favors annotated evidence. A natural-text probe adds distractor passages or generic filler to 60 fixed SQuAD targets. Filler avoids names, dates, and numbers. Attention enrichment measures target attention relative to its share of input tokens. 

Query dependence and attention sharing. For a fixed adapter, the activation probe measures how much its direct contribution varies across questions, normalized by total activation energy. It uses eight documents with eight questions each and measures the direct document-dependent contribution, ex-cluding the shared bias from the measured vector. Appendix B.1 defines the statistic. Attention shar-ing is measured by the overlap between facts’ com-bined extraction and assembly weights, averaged across layers on sixteen FactSet-Homo documents. 

KV and capacity controls. Learned KV com-pressors undergo the same source-count, fixed-target expansion, and response-instruction probes, with matched questions within each comparison. Target-only controls use annotated evidence. Ca-pacity controls optimize the writer’s internal mem-ory states while freezing the backbone and down-stream parameter mapping. Each resulting adapter is shared across all questions about its document. D2L uses 200 distillation steps with retention; its learning rate is calibrated on the first document, which remains in the reported cohort. SHINE uses the analogous frozen-mapping intervention. 

A.6 KV Compression and Hybrid Protocols 

All methods use matched documents, queries, in-structions, and scoring. SnapKV and DropKV re-tain only document positions using their official selection procedures. The instruction and query are then processed again over the selected cache, and the first answer token is generated from this recomputation. No full-document query states or first-token prediction are reused. Selected keys retain their original positional encoding. 

Hybrid construction. Hybrid comparisons match unique document–query pairs across conditions, removing repeated records. Standalone benchmark tables retain the original evaluation records. We combine the selected cache with either gen-erated LoRA or Memory Tokens KV without joint training, sweeping 48, 128, and 512 retained doc-ument positions. Both additions use 6.75 MiB. Learned memory KV is appended after the selected document cache, with answering positions continu-ing after the document and memory prefixes. Se-lected positions and answering are identical with and without adapters. Fast KVzip uses default global allocation across layers and heads, with a matched total budget and the same answering procedure. 

Evidence interventions. Adapter substitutions use an update from another document or another question about the same document while holding the selected cache fixed. Answer-retention controls prioritize positions containing an accepted answer and their immediate neighbors, filling the remain-ing budget by the original selection scores. Inputs without an answer match use ordinary selection. Counterfactual tests combine caches and adapters from original and altered documents while keeping the question fixed; containment of the original and altered answers is scored separately.

Restoring positional proximity helps at 4K but is insufficient at 32K. The RoPE alignment con-trol restores the memory-to-question RoPE offsets of the no-insertion condition while retaining the full intervening sequence (Appendix A.8). At 4K, it substantially improves Memory Tokens KV on all six tasks and exceeds LoRA in F1 on SQuAD-4 and SQuAD-Mix. At 32K, its F1 remains be-tween 0.004 and 0.116, well below LoRA on every task (Table 17). Thus, correcting this positional mismatch addresses an important source of degra-dation at 4K but does not explain away the long-interference gap. Competition with intervening to-kens for attention remains a plausible explanation, rather than a directly measured mechanism. 

Memory access and parameter updates. Mem-ory Tokens KV requires attention to a fixed mem-ory prefix, so additional context may interfere with access to the stored information even though the memory itself is unchanged. Generated LoRA mod-ifies feed-forward computation at each subsequent position without requiring memory-prefix retrieval, which may support more stable recall. Two findings support the usefulness of this pa-rameter pathway. First, at 32K insertion, LoRA re-tains F1 of 0.611 and R-L of 0.771, compared with 0.050 and 0.144 for Memory Tokens KV. Second, with identical prompts on the first 200 GSM8K questions, loading LoRA generated from unrelated documents yields 92% accuracy versus 94% with-out LoRA (Appendix D.4). The first result mea-sures access to the constructed document memory. The second measures preservation of unrelated rea-soning performance after loading LoRA.
